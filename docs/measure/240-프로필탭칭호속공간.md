# 240 측정표 — 19 프로필 탭 라벨 「칭호」의 속공간(카운터)

대상: `.pf-tab`(index.html `:root` 토큰 + 규칙) · 라벨 `#pfw .pf-tab.t1>i`
게이트: `tools/verify240.js`(화면) · `tools/m126counter.js`(격리) · 스윕 도구 `tools/probe240.js`

> 이 표는 «레이아웃 재구성» 측정표가 아니다. 240 은 T1 버그(지시서 [3]-(가))이므로 비평가를 띄우지
> 않았고, 잰 것은 **한 글자의 속공간 면적**과 그것을 움직이는 두 변수(스트로크·드롭)뿐이다.

## §2. 문제 — 두 잣대가 서로 다른 값을 낸다

같은 자리를 두 방법으로 잰다. **둘 다 필요하다.**

| 잣대 | 무엇을 보는가 | 240 착수 전 | 하한 |
|---|---|---|---|
| 격리 렌더 (`m126counter.js`) | 계산된 타이포그래피만 — 글꼴·크기·자간·**스트로크**·paint-order | **4.6 px²** | 8.0 |
| 화면 (`verify240.js`) | 위 + **드롭 섀도**(= 사용자가 실제로 보는 것) | **3.4 px²** | 8.0 |

- 격리가 «이웃 글자·오버레이를 빼고» 재는 판단은 옳다(그 이유는 `m126counter.js` 서두).
  다만 그 대가로 **드롭 섀도가 구멍을 한 번 더 메우는 것**을 못 본다.
- 126 이 이 자리를 내내 초록으로 본 이유는 따로 있다: 재던 셀렉터가 `.pf-tab.t2`(**「초상화」**)였고
  그 ㅇ 는 **30.4 px²** 다. 201 이 t2·t3 를 폐기하면서 남은 「칭호」로 옮겨 재자 4.6 이 나왔다.
  즉 **6.6배 차이를 한 칸이 가려 주고 있었다.**

같은 잣대(화면)로 잰 «게이트가 초록이라고 부른» 다른 자리들 — 240 만 하한 아래였다:

| 자리 | fs | stroke | 드롭 | 화면 속공간 px² |
|---|---|---|---|---|
| 52 메뉴 «우편» | 29 | 3.77 | 없음 | 62.6 |
| 10 상점 «10회 소환» | 31 | 4.96 | 없음 | 23.8 |
| 10 상점 «1,000» | 30 | 4.80 | 없음 | 9.1 |
| 02 레일 «승급전» | 29 | 3.77 | **있음** | 11.8 |
| 19 프로필 «해금 미션» | 36.9 | 8.12 | 없음 | 8.3 |
| **19 프로필 탭 «칭호»** | 38 | 6.08 | **있음** | **3.4** ✗ |

## §3. 스윕 — 처방을 하나로 좁힌 세 줄

### 3-1. font-size 를 올리는 안(ⓑ)은 죽는다

격리 렌더, 스트로크는 크기대 비율(.16) 유지:

| fs | stroke | 격리 속공간 px² | 라벨 자연폭 | ref 54 대비 |
|---|---|---|---|---|
| 38 | 6.08 | 4.6 ✗ | 57.14 | +5.8% |
| 40 | 6.40 | 4.8 ✗ | 60.14 | +11.4% |
| 42 | 6.72 | 6.1 ✗ | 63.15 | +16.9% |
| 44 | 7.04 | 6.1 ✗ | 66.15 | **+22.5%** |

글자를 키우면 스트로크도 같이 커져 **카운터가 하한에 못 닿는다.** 폭만 +22% 망가진다 → 기각.

### 3-2. 스트로크 비율 스윕 (화면 잣대 · 드롭은 «sw/2 + 1.9/1.06» 공식 유지)

| 비율 | stroke | 바깥 두께 | 화면 속공간 px² |
|---|---|---|---|
| .16 (현행) | 6.08 | 3.04 | 3.4 ✗ |
| .15 | 5.70 | 2.85 | 3.4 ✗ |
| .14 | 5.32 | 2.66 | 4.4 ✗ |
| .13 (`--st-small`) | 4.94 | 2.47 | 6.4 ✗ |
| .125 | 4.75 | 2.38 | 7.4 ✗ |
| **.122** | 4.64 | 2.32 | **7.9** ← 절벽 |
| .120 | 4.56 | 2.28 | 8.5 ✔ |
| .118 | 4.48 | 2.24 | 8.8 ✔ |
| **.115 (채택)** | **4.37** | **2.19** | **9.6** ✔ |
| .112 | 4.26 | 2.13 | 11.0 ✔ |
| .110 | 4.18 | 2.09 | 11.3 ✔ |

**`--st-small`(.13)로는 안 된다** — 격리로는 11.9 로 통과처럼 보이지만 화면에서는 6.4 로 여전히 막힌다.

### 3-3. «드롭을 깎아 두께를 지키는» 안은 거래가 안 된다

| 비율 | stroke | 드롭 dy/dx | 화면 속공간 px² |
|---|---|---|---|
| .16 | 6.08 | 1.9/1.06 | 3.4 ✗ |
| .16 | 6.08 | 1.2/0.7 | 3.4 ✗ |
| .16 | 6.08 | **0/0 (드롭 제거)** | **4.5** ✗ |
| .14 | 5.32 | 0/0 | 9.0 ✔ |
| .13 | 4.94 | 1.9/1.06 | 6.4 ✗ |
| .13 | 4.94 | 0.8/0.45 | 8.9 ✔ |
| .13 | 4.94 | 0/0 | 12.9 ✔ |
| **.115** | **4.37** | **1.9/1.06** | **9.6** ✔ |

두 가지가 여기서 결정된다:
1. **드롭은 주범이 아니다.** 드롭을 통째로 빼도 .16 은 4.5 로 하한 아래다 → **스트로크를 내려야만 한다.**
2. 드롭을 −58%(0.8/0.45) 깎아서 버는 두께는 **+0.28px** 뿐이다. 그 대가로 126 20회차가
   **세 비평가·두 라운드**로 확정한 드롭(ref dy +1.9 · dx +1.06)을 버린다 → 기각.
   반면 바깥 두께 «~3px» 는 ref JPEG 한 장의 추정치이고 비활성 칸은 «2~3px» 로 폭이 있다.

## §4. 채택값과 그 대가

```
--st-pft:.115;   /* 19 프로필 탭 라벨(.pf-tab, fs 38) */
.pf-tab{ -webkit-text-stroke:calc(var(--st-pft) * 1em) #000;
         text-shadow:0 calc(var(--st-pft)/2*1em + 1.9px) 0 #000,
                       calc(var(--st-pft)/2*1em + 1.06px) 0 0 #000 }
```

| 항목 | 전 | 후 | 비고 |
|---|---|---|---|
| stroke | 6.08px | **4.37px** | fs 38 × .115 |
| 바깥 두께 | 3.04px | **2.19px** | ref «~3px» 대비 **−27%** ← 대가 |
| 드롭 보이는 몫 | dy 1.9 / dx 1.06 | **그대로** | 오프셋만 sw/2 를 따라 내려감(4.94→4.09 · 4.10→3.25) |
| 격리 속공간 | 4.6 | **17.8** | 하한 8.0 |
| 화면 속공간 | 3.4 | **9.6** | 하한 8.0 · 절벽(.122=7.9) 에서 +1.7 |
| 탭·라벨·패널 기하 | — | **불변** | `verify240` §4 로 고정 |

**대가는 126 서두가 이미 적어 둔 그 거래다** — «본문·작은 라벨은 비평가 목표(바깥 3.0px)까지 못 간다.
그 지점이 곧 옛 고정 px 값이고, 거기서는 카운터가 다시 0~2px² 다.»
절벽에 바짝 붙이지 않은 이유: .120 은 8.5(하한 +6%)라 폰트가 조금만 흔들려도 도로 빨개진다.
