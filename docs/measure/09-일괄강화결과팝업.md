# 09 일괄 강화 결과 팝업 측정표

> **출처**: `docs/ref/09-일괄-강화-결과-팝업.jpg` — 원본 **1080×2340**, 좌표는 전부 원본 절대 px(정수 반올림).
> **측정 방법**: python3 + PIL(+numpy) **픽셀 스캔만** 사용. 눈대중 수치 없음.
> - 행/열 색전이 런렝스(`|px[i]−px[st]|∞ > tol`)로 경계 검출
> - **배경 예측 이미지와의 차분 마스크**로 «팝업이 그린 것」과 «딤 먹은 뒤 화면」을 분리
>   (`pred = unlin(lin(07번) × k)`, `|09 − pred|₁ > 25`)
> - 모서리 반경은 코너 좌변 x(y) 를 원호 `r − √(r²−(r−d)²)` 에 최소자승 피팅
> - 텍스트는 **밝은 채움 마스크(lum>150 & 채도<45)** 와 **검정 스트로크 마스크** 를 따로 떠서
>   «잉크 = 채움», «스트로크 포함» 두 값을 각각 기록
> - 딤은 같은 장면의 `07-스킬-팝업.jpg` 와 **픽셀 대 픽셀 나눗셈**으로 산출 (아래 §1.1)
> **폰트 규칙**: `font-size = 잉크높이 ÷ 0.93` (`docs/PROGRESS.md` «01 에서 얻은 교훈». **0.75 로 나누지 않음**)
> **스트로크 규칙**: `-webkit-text-stroke` 는 글리프 윤곽 **중심**에 그려져 바깥으로 절반만 보인다.
> 실측 외곽선 N px 을 재현하려면 CSS 에는 **2N px** 을 준다. 표에 «실측 N / CSS 2N» 을 둘 다 적었다.
> **테두리 기준**: 이 문서의 «bbox/width/height» 는 **검정 외곽선을 포함한 바깥 기준**이다.
> 안쪽 값이 필요한 곳은 «안쪽 …» 행으로 따로 적었다. (05 에서 안/밖 불일치로 7건이 반대로 틀렸던 항목)

> - 08(딤 55%)·A5(**54%** — ⚠ 576 정오, 이 줄은 «65%» 였다)·05(55%) 와 **완전히 다른 값**이다. 09 는 «결과 연출」이라 훨씬 깊게 어둡다.

- 왼쪽/오른쪽 숫자 색도 **같다.** «강화 전은 회색» 같은 처리를 넣지 말 것.

### 터치하여 닫기

```css
.ur-close{position:absolute; left:0; right:0; text-align:center;
  bottom:-4px;                       /* 탭바 상단 기준. 2160 − 2164 = −4 */
  font-size:45px; color:#fff;}        /* 외곽선 없음 — text-stroke 금지 */
```

## 8. 구현 담당에게 넘기는 것

### 8.1 세로 좌표 변환 (레퍼런스 2340 → 기준 프레임 1920)

**가로 수치(x · width · font-size · gap · radius · 테두리 두께)는 변환 없이 1:1 그대로 쓴다.**

세로는 요소마다 기준이 다르다. 09 의 각 요소가 어느 기준인지 **판정 결과**:

| 요소 | 기준 판정 | 근거 | 변환 |
| --- | --- | --- | --- |
| 딤 오버레이 | **화면 전체** | y0–2339 균일 | `inset:0` — 변환 불필요 |
| **리본 + 카드 3칸 + 레벨 텍스트** | **화면 세로 중앙 정렬 그룹** | 그룹 bbox y **1012–1312**(h 301) → 중심 **1162**. 화면 중심 1170 대비 **−8px** = 사실상 정중앙. 상단 기준(y−84)으로 보면 위 여백 1012 인데 이는 어떤 고정 밴드와도 맞지 않는다 | **`y_new = y_ref − 202`** (그룹 중심 1162 → 프레임 중심 960) |

| 화면 위쪽 기준(`y − 84`) 요소 | **없음** | 09 팝업에 상단 앵커 요소 없음 | — |

### 8.2 다른 화면 담당에게도 쓰이는 주의사항

1. **이 게임의 딤은 선형광(linear-light)에서 합성된다.**
   sRGB 단일 배율로는 밝은 면과 중간 톤을 동시에 못 맞춘다(잔차 MAE 9.34 vs 1.98).
   딤을 07↔09 처럼 대조할 때는 **선형 변환 후 비율**을 봐야 정확하다.
   구현은 CSS 한계상 `rgba(0,0,0,α)` 로 근사하되, **α 는 화면 면적 대부분을 차지하는 밝은 면 기준**으로 정한다.
2. **«팝업» 이라고 전부 껍데기가 있는 건 아니다.** 09 는 A5 의 3분류 어디에도 없는 **«껍데기 없음» 4번째 유형**이다.
   결과 연출류(12 소환 결과, 17 스탯업 보너스)도 같은 유형일 가능성이 높으니 **먼저 차분 마스크로 판 유무부터 확인**할 것.
3. **«터치하여 닫기» 는 이 게임에서 유일하게 외곽선이 없는 텍스트다.**
   글리프 둘레 링 4,454px 중 lum<25 가 3px. 다른 화면 라벨에 쓰는 `-webkit-text-stroke` 를 여기에 복사하지 말 것.
4. **레벨 변화 텍스트의 좌우 숫자는 같은 흰색이다.** «전은 흐리게, 후는 강조」 같은 흔한 UI 관습이 여기엔 없다.
5. 카드 3칸의 등급색도 **전부 같다.** 09 레퍼런스만으로는 «등급별 카드색» 스케일을 알 수 없으므로
   등급색 팔레트는 **07 스킬 팝업 측정표(`docs/measure/07-스킬팝업.md`)의 값을 재사용**해야 한다.

## 정오표 — 661(2026-09-02, 저장소 주인 지시): 결과 묶음은 **프레임 세로 중앙**이다

## 정오표 ② — 726 (2026-09-02, sess-1658-18753 워커 D): 카드는 **3칸 고정이 아니다**
