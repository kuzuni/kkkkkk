# 174 측정표 — 펫 슬롯·카드 썸네일 (전투씬 스프라이트)

> 주인 지시(2026-08-27): «펫 이미지가 전투씬에 있을 때랑 똑같은 이미지로 슬롯 썸네일에 있어야 하는데 안 그렇게 됨».
> 레퍼런스 스크린샷 없음 — **레이아웃 작업이 아니다.** 잰 것은 «지금 그 자리를 차지하고 있는 이모지의 잉크 bbox» 이고,
> 그 자리를 스프라이트 캔버스가 그대로 물려받게 하는 것이 이 표의 용도다(72 «아트 자리 규칙»).
> 측정 도구: `node tools/measure174.js` (스크린샷 차분) · `node tools/verify174.js` (캔버스 픽셀)

---

## 0. 왜 «스크린샷 차분» 으로 쟀나

이모지는 텍스트라 `getBoundingClientRect` 가 **글리프 advance 상자**를 돌려주고 실제 잉크와 다르다
(A1 교훈 «글리프 advance 보다 좁은 박스», 94-① 캔버스 차분의 DOM 판).
그래서 같은 자리를 «글리프 보임 / `visibility:hidden`» 두 장 찍어 다른 픽셀만 모았다.

⚠ **차분은 카드 상시 연출(121·122)에 오염된다.** 보유 카드(`.sk-card:not(.lk)`)에서 잉크가
110×89 로 나온 것은 배경 애니메이션이 두 장 사이에 움직였기 때문이다 — 캔버스가 생긴 뒤의
«후» 측정은 전부 `getImageData`(verify174)로 다시 쟀다. 아래 «후» 열이 그 값이다.

> 늘려 채우는 것은 356 이 금지하므로 **이것은 결함이 아니다**. 게이트 `tools/verify411.js` [C] 가 그 사실을 적는다.

부속 CSS 값(안 건드린 것 포함):
- `.sk-si` `left:0;right:0;top:12px;height:70px;font-size:58px;line-height:70px` → **박스는 그대로**, `display` 만 `.pt` 로 flex.

- `.cdic` `left:23px;top:15px;width:66px;height:70px;font-size:65px;transform:scaleX(1.15)`
  → **박스 66×70 은 ref 아트 bbox 라 그대로**, `.pt` 에서 `transform:none`(캔버스를 가로로 늘리면 안 된다).
  차분이 잰 76px 폭은 `66 × 1.15 = 75.9` — 이모지가 박스 밖으로 넘치고 있었다는 뜻이다.
- `.sm-c` `--if-w:158px --if-ic:64px` (공용 `.ifr`) → 프레임 규격 불변.

## 2. 스프라이트 원본(전투 씬과 같은 소스)

| sp | 아틀라스 애니 | 프레임 수 | 0번 프레임 잉크 rect | 종횡(w/h) | 전투 씬 scale |
|---|---|---|---|---|---|
| bird | `anim` | 10 | 82×95 | 0.863 | 0.34 |
| robo | `Running` | 15 | 126×216 | 0.583 | 0.16 |
| dragon | `fly` | 12 | 96×64 | 1.500 | 0.62 |

세 종의 종횡이 0.583~1.500 으로 크게 벌어져 있다 — contain 이라 **캔버스가 곧 «그림이 차지해도 되는 자리»** 다.

- **칸 박스(115×70 · 156×96)를 그대로 쓰면 안 된다.** dragon(종횡 1.5)만 가로로 물려 96px·148px 이 되고
  슬롯의 12px 림·카드의 11px 림을 뚫는다.
- **정사각으로 잡아도 안 된다(1회차 회귀).** «이모지 잉크의 **최대변**» 만 보고 92×92 로 잡았더니
  세로가 물리는 bird(82×95)·robo(126×216)가 이모지보다 **18% 더 커져**(71 → 84)
  카드의 «Lv.n»(상단 14~46)·«장착 중»(63~107) 라벨을 밀고 들어갔다 — **캡처 검수에서 잡혔다.**
  게이트도 «최대변» 만 보고 있어서 못 걸렀다 → 3회차에 축을 **«박스 자체»**(w≤85 && h≤72)로 바꿨다.
- 그래서 캔버스 = **이모지 잉크 박스 + 여백**이다. 세로도 이모지 값을 그대로 물려받는다.

## 3. 대비(97-⑤) 실측 — **이번 작업에서 고치지 않은 것**

카드 면은 등급별 `SK_FILL` 8단(휘도 48~170)이다. 전 종 보유 상태에서 «잉크 픽셀 중 면 휘도 ±25 안에 드는 비율»:

| 묻힘 | 등급 면 휘도 | sp | 잉크 평균 휘도 | 카드 |
|---|---|---|---|---|
| 69.4% | 48 (g3) | robo | 64 | `robo2` |
| 61.5% | 48 (g3) | dragon | 32 | `pet3_3` |
| 59.2% | 66 (g5) | dragon | 53 | `drag2` · `pet5_3` |
| 51.2% | 141 (g4) | bird | 102 | `pet4_4` |
| 51.1% | 48 (g3) | robo | 76 | `pet3_4` |
| … | | | | 30% 이상 **9장**(전 종 보유) / **11장**(verify174 시드 = 3종 보유·장착) |
| 0.0% | 114·137·141·146 | dragon·bird | 38~67 | `pet2_2` `pet4_3` `pet6_0` `pet6_2` `pet7_0` |

72 는 던전 카드에서 스프라이트별 상수(`thbr` dragon 2.70 · robo 1.55 · bird 1.00)로 이걸 풀었지만
**여기 면은 8가지**라 상수 하나로 못 맞춘다 — 어두운 면에 맞춰 올리면 밝은 면에서 다시 묻힌다.
「면 휘도 + 45」 자동 보정을 실제로 붙여 봤더니 밝은 면 위의 밝은 종이 255 에 포화해
`pet4_4` 가 **51.2% → 66.5%** 로 **나빠졌다** → 되돌렸다(2회차). 상세는 `docs/review/174-펫스프라이트썸네일.md`.
그리고 주인 지시가 «전투씬과 **똑같은** 이미지» 라 픽셀을 밝히는 것 자체가 전제를 깬다.
→ 후속 등재: PROGRESS **224**.
