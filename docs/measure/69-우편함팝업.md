## 10. 우리 구현으로의 환산 (s = 898 / 988 = **0.9089**)

우리 A5 상자는 **폭 898 고정**이라 가로는 s 로 환산한다. 세로도 s 를 쓰면 상자 1408×s = 1280 인데
그러면 **5행이 리스트에 안 들어간다.** 레퍼런스 패널은 «3행만 차 있어도 5행 자리를 비워 두는» 고정
높이(§4·§10-6)이고 **우리 우편은 정확히 5통**이므로, 그 5행 자리를 실제로 채우는 쪽이 구성에 충실하다.
→ 상자 높이 **1310** 을 택했다(종횡비 1:1.459 vs ref 1:1.425, **+2.4%**). 이것이 유일한 의도적 이탈이다.

## 12. 정오표 — 하단 버튼 2개의 «정체» (작업 92, 2026-08-26 저장소 주인 지시)

§7 은 두 버튼의 **크기·좌표만** 실측했고 «무엇을 하는 버튼인가» 는 우리가 임의로 «닫기 / 전체 수령»
으로 채웠다. 레퍼런스(`docs/ref/69-우편함-팝업.jpg`)를 다시 보면 둘 다 **동작 버튼**이다.

| 자리 | 구 구현 (~작업 69) | **확정 (작업 92)** |
|---|---|---|
| 좌 (x112, 305×117) | `#mailClose` «닫기» · 갈색 | **`#mailDel` 「읽음 전체 삭제」 · 빨강** (ref 면 #F26B6B 계열) |
| 우 (x333, 305×117) | `#mailBtn` «전체 수령»/«수령 완료» · 초록 | **`#mailBtn` 「일괄 읽기&수령」 · 초록** (라벨 **고정**) |
| 닫기 경로 | 좌 버튼 + 바닥 ✕ 2가지 | **바닥 ✕(§8) 하나뿐** |

- **크기·좌표·간격은 §7·§10 그대로다**(305×117 · gap 27 · span 637 · 좌우 여백 112). 바뀐 것은 색·라벨·동작뿐.
- 라벨이 4자 → 7~8자로 길어져 잉크가 면(305 − 테두리 7×2 = **291**)을 넘을 뻔했다.
  `font-size` 는 §7 «라벨 잉크 h ÷ 버튼 h = .233» 을 지키려고 29px 그대로 두고,
  `transform:scaleX(.93)` + `letter-spacing:-1.5px` 로 가로만 죄었다 → 실측 잉크 **좌 166 · 우 178**.
- 두 버튼의 베벨 스톱은 **동일**(0–7 / 92–98)하고 색만 다르다 — 같은 부품이라는 뜻이다.
  - 빨강: `#FFB3B3 / #F58B8B / #E24E4E / #FFC0C0 / #A32C2C` (면 실측 rgb(226,78,78))
  - 초록: `#C9F07E / #7CD84B / #4EBB2F / #B9EC77 / #2F8F1E` (면 실측 rgb(124,216,75))
  - 비활성(둘 다): `#D3D3D3 / #A7A7A7 / #8C8C8C / #D1D1D1 / #757575`

### 12-1. 세이브 — `S.mail` 이 2상태에서 **3상태**가 됐다

| 값 | 뜻 | 목록 | `mailLeft()` |
|---|---|---|---|
| 없음 / 0 | 미수령 | 보임 (받기 활성) | 센다 |
| 1 | 수령 완료 | 보임 (완료·`.done`) | 안 셈 |
| **2** | **삭제됨** | **안 보임** | 안 셈 |

`MAILS` 원본은 불변이고 «삭제» 는 렌더 필터(`mailList()`)일 뿐이다. **미수령(0)은 절대 지워지지 않는다**
— `delReadMail()` 이 `S.mail[id] === 1` 인 것만 2 로 넘긴다. 구 세이브는 0/1 만 있으므로 마이그레이션 불필요
(KEY 버전 그대로).
