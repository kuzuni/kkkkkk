# 163 — 첫 접속 로딩 화면 측정표

> 레퍼런스 스크린샷이 **없는** 신설 화면이다(주인 지시만 있다). 따라서 이 표는 «레퍼런스에서 잰 값» 이
> 아니라 **구현이 실제로 쓰는 값과 그것이 나온 근거**다. 값을 바꿀 때는 근거 칸을 같이 고칠 것.
> 기준 프레임 1080×2280.

## 2. 시간 (ms)

| 상수 | 값 | 근거 |
|---|---|---|
| `LD_RUN` | **420** | 등장 길이. 1회차 300 은 «횡방향 등장 인지 하한 200ms 미달» · «이동의 93%가 앞 155ms 에 몰림» |
| `LD_RUNMS` | **52** | run **8프레임** × 52 = 416 ≈ `LD_RUN` → **스트라이드가 정확히 한 번 완결된다.** 게이트가 아틀라스에서 프레임 수를 다시 세서 대조 |
| `LD_IDMS` | 125 | 8fps — 전투 `setAnim(player,'knight','idle',8)` 과 같은 속도 |
| `LD_HOLD` | 90 | 착지 뒤 여운 |
| `LD_SQ` | 160 | 착지 스쿼시 길이(몸통 ±6% · 그림자 ±30%) |
| `LD_MIN` | 400 | 전부 캐시된 재방문에서도 한 박자는 보이게 |
| `LD_GRACE` | 90 | knight 가 늦게 와도 캐릭터를 최소 이만큼은(«연출 0프레임» 방지) |
| `LD_FADE` | 110 | 페이드아웃. **CSS `#loading{transition:opacity .11s}` 와 한 벌** — 게이트 §2 가 두 값을 대조한다 |
| `LD_HARD` | **620** | ★ «이 시각을 넘겨서까지 등장을 기다리지 않는다». 유도: load 이벤트 **550**(아틀라스까지 받은 시점) + 저장소 게이트 최단 대기 **300** = 가장 이른 캡처 **850**. 거기서 페이드 110 과 타이머 굶주림 여유(실측 70~85)를 뺀 값 |

**측정된 시간축**(`node tools/probe163.js`, file:// · 전부 로컬):
`#loading` DOM 90 → knight 도착·등장 시작 ≈**380~450** → 부팅(.thru) ≈**420~495** → 페이드 시작 ≈**660~740** → 안 보임 ≈**770~850**.
캐릭터가 400ms 에야 그려지는 이유는 **본 인라인 스크립트가 672KB** 라 파싱에 ~350ms 가 걸리고
그동안 메인 스레드가 막혀 이미지 `onload` 조차 못 돌기 때문이다. 연출 모듈을 `atlas-data.js` 바로 뒤로
옮겨 **로딩 시작**은 앞당겼지만(그래서 부팅도 빨라졌다), 자바스크립트 실행 자체는 파싱을 못 앞지른다.

## 3. 궤적

- 시작 오프셋 `LD_X0 = **−450**` — 정지 자세의 잉크 우변이 x=432 이므로 −450 이면 잉크 우변 −18,
  **딱 프레임 밖**이다. 1회차 −560 은 우변이 +100(몸의 39%가 화면 안에서 켜졌다),
  중간에 시도한 −760 은 반대로 앞 **72ms(17%)** 가 빈 무대였다. 게이트 §4 가 아틀라스에서 다시 계산해 대조.
- 이징 `easeOutCubic` — 순수 함수 `LD.at(t) = round(LD_X0 · (1−t/LD_RUN)³)`.
  프레임당(52ms) 최대 이동 **148px = 몸통 352px 의 42%**(«순간이동으로 읽히는» 상한 50% 이내).
- 상하 아치 `LD_ARC = 26px` — `−26·sin(π·p)`. 1회차는 세로 변위 0px 라 «슬라이딩» 으로 읽혔다.
- 그림자는 공중에서 작아지고(−18%) 옅어진다(−45%), 착지에서 가로로 퍼진다(+30%).
