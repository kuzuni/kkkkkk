# 163 — 첫 접속 로딩 화면 측정표

> 레퍼런스 스크린샷이 **없는** 신설 화면이다(주인 지시만 있다). 따라서 이 표는 «레퍼런스에서 잰 값» 이
> 아니라 **구현이 실제로 쓰는 값과 그것이 나온 근거**다. 값을 바꿀 때는 근거 칸을 같이 고칠 것.
> 기준 프레임 1080×2280.

## 2. 시간 (ms)

| 상수 | 값 | 근거 |
|---|---|---|
| `LD_RUN` | **640** | 등장 길이. 1회차 300 은 «횡방향 등장 인지 하한 200ms 미달» · «이동의 93%가 앞 155ms 에 몰림» |
| `LD_RUNMS` | **40** | run **8프레임** × 40 = 320 → 640 안에 **스트라이드 2회**. «주기로 인식하려면 최소 2회»(2회차 비평 D). 게이트가 아틀라스에서 프레임 수를 다시 세고 «정수 회, 2회 이상» 을 단언 |
| `LD_IDMS` | 125 | 8fps — 전투 `setAnim(player,'knight','idle',8)` 과 같은 속도 |
| `LD_HOLD` | 90 | 착지 뒤 여운 |
| `LD_SQ` · `LD_SQA` | 170 · **±10%** | 착지 스쿼시. 2회차 ±6% 는 실측 −1.8% 로 «160ms 를 쓰고 얻은 임팩트가 1.8%»(비평 D) |
| `LD_MIN` | 400 | 전부 캐시된 재방문에서도 한 박자는 보이게 |
| `LD_GRACE` | 90 | knight 가 늦게 와도 캐릭터를 최소 이만큼은(«연출 0프레임» 방지) |
| `LD_FADE` | **150** | 페이드아웃. **CSS `#loading{transition:opacity .11s}` 와 한 벌** — 게이트 §2 가 두 값을 대조한다 |
| `LD_HARD` | **530** | ★ «이 시각을 넘겨서까지 등장을 기다리지 않는다». 유도: load 이벤트 **550**(아틀라스까지 받은 시점) + 저장소 게이트 최단 대기 **300** = 가장 이른 캡처 **850**. 거기서 페이드 150 과 타이머 굶주림 여유를 뺀 값. 굶주림은 실행마다 **20~115ms** 흔들려서(실측) 여유를 넉넉히 잡아야 «뜨고 지는 FAIL» 이 안 된다 |

**측정된 시간축**(`node tools/probe163.js`, file:// · 전부 로컬 = «재방문» 경로):
`#loading` DOM 90 → knight 도착·등장 시작 ≈**380~450** → 부팅(.thru) ≈**420~495** → 페이드 시작 ≈**640~680** → 안 보임 ≈**790~830**.
이 경로에서는 등장 640ms 가 `LD_HARD` 에 **잘린다** — 의도된 동작이다(위 `LD_HARD` 칸).
주인 지시가 가리키는 **첫 접속**(1.8MB 를 네트워크로 받는 경우)에는 부팅이 훨씬 늦어 등장이 통째로 보인다.
캐릭터가 400ms 에야 그려지는 이유는 **본 인라인 스크립트가 672KB** 라 파싱에 ~350ms 가 걸리고
그동안 메인 스레드가 막혀 이미지 `onload` 조차 못 돌기 때문이다. 연출 모듈을 `atlas-data.js` 바로 뒤로
옮겨 **로딩 시작**은 앞당겼지만(그래서 부팅도 빨라졌다), 자바스크립트 실행 자체는 파싱을 못 앞지른다.

## 3. 궤적

- 시작 오프셋 `LD_X0 = **−850**` — 정지 자세의 잉크 우변이 x=**828**(캔버스 좌변 180 + 720/2 + 앵커 −324 + 51×12)
  이므로 −850 이면 우변 −22, **딱 프레임 밖**이다.
  1·2회차 값(−560 / −450)은 **게이트가 틀린 값을 줘서** 나온 숫자였다 — §4 가 `display:none` 인
  오버레이에서 `offsetLeft`(실제 180 → 0)를 읽었고 CSS 확대(1.5×)도 안 쳤다. 비평가가 픽셀로 잡았다.
  게이트는 이제 오버레이를 **보이는 상태로 되돌려 놓고** `getBoundingClientRect()` 로 잰다.
- 이징 — **등속 + 감속**. 순수 함수 `LD.at(t)`:
  시간의 앞 `LD_CRZ = .75` 를 등속으로 `LD_CRZD` 만큼 가고, 남은 25% 시간에 남은 거리를 2차 감속으로.
  ★ `LD_CRZD` 는 **손으로 적지 않는다** — `.80` 으로 적었더니 이음매에서 속도가 1.067 → 1.6(**+50%**)로
  튀어 감속해야 할 자리에서 가속했다(게이트가 잡았다). 속도 연속 조건을 풀면
  `LD_CRZD = 2·LD_CRZ / (1 + LD_CRZ)` = 0.857.
  2회차의 `easeOutCubic` 은 앞 21% 시간에 거리의 50%를 써서 뒤가 **트레드밀**이었다(비평 C·D 독립 확인).
  등속 구간의 프레임당(40ms) 이동은 **57px = 잉크폭 612px 의 9.3%** 로 고르다.
- 상하 아치 `LD_ARC = 20px` — `−20·|sin(π·t / (LD_RUNMS×4))|`. **주기를 걸음에 묶었다**:
  run 8프레임 = 접지 2회이므로 접지 간격은 4프레임 = 160ms → **딛는 순간 arc=0**, 정점은 그 사이.
  감속 구간(뒤 25%)은 아치 0 = 발이 붙은 채로 선다.
- 그림자는 공중에서 작아지고(−18%) 옅어진다(−45%), 착지에서 가로로 퍼진다(+30%).
