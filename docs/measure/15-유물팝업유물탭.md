## §0. 측정 방법 / 임계값 / 신뢰도

### 0.1 방법
- **python3 + PIL + numpy 픽셀 직접 스캔**. 눈대중 수치 0개. 이미지는 구조 파악용으로 1회 육안 확인 후, 모든 숫자는 스캔으로 확정.
- 가려진 도형(활성 알약 뒤의 비활성 알약, 서브탭 바 뒤의 «레어» 리본 등)은 **전체 bbox 로 재지 않고**, 가림 없는 행/열을 골라 스캔한 뒤 형태 매칭으로 원위치를 역산했다(§1.4, §2.3).
- «전폭 경계»로 보이는 y 는 반드시 **가로 전폭 스캔**으로 재확인했다(예: y=250 전폭 스캔 → dark 0개 / bright 0개 = 진짜 빈 배경).
- 14 와 15 의 **행 단위 픽셀 차분**으로 공통 껍데기 구간을 확정했다(§1.2).

### 0.2 임계값 (JPEG 번짐 처리 규칙)
| 용도 | 임계값 | 중간 톤 처리 |
|---|---|---|
| 검정 외곽선 검출 | `lum < 22` (일부 `< 20 / < 25` 병행) | **중간 톤은 «바깥»(비-검정) 쪽으로** 넣음 → 외곽선 두께는 실제보다 0~1px 작게 나옴 |
| 흰 글자 잉크 | `lum > 180~190` **+ 채널 편차 < 28** (중성색 조건) | 중간 톤은 «바깥» → 잉크 bbox 는 최소 추정값 |
| 크림색 글자(활성 탭) | `R > 190` **and** `R−B > 40` | 동일 |
| 노랑 채움(진행바) | `R − B > 50~60` | 동일 |
| 배경(페이지) 판정 | `|R−39|<14, |G−39|<14, |B−49|<14` | — |
- `lum = 0.299R + 0.587G + 0.114B`
- 좌표는 모두 **레퍼런스 1080×2340 절대 px, 정수**. bbox 는 **검정 외곽선 포함(바깥 기준)**, 끝점 포함(inclusive).

### 0.3 폰트 크기 환산
- 한글: `font-size ≈ 잉크높이 / 0.93`
- 라틴/숫자(캡하이트): `font-size ≈ 잉크높이 / 0.70`
- 두 값 모두 병기한다. 실제 지정값은 렌더러/폰트에 따라 ±2px 오차 가능.

## §1. 껍데기 판정 — **(ⓒ) 딤 · 헤더 · 테두리 없는 전체화면 페이지**

### 1.1 판정
> **ⓒ 전체화면 페이지.** 다이얼로그도 바닥 시트도 아니다. 딤 없음, 모달 카드 없음, 팝업 헤더/타이틀/닫기 ✕ 없음.
> 화면 = **고정 상단 HUD(공용) + 전체폭 스크롤 리스트 + 리스트 위에 떠 있는 서브탭 바(오버레이) + 고정 하단 앱 탭바(공용)**.

### 1.2 판정 근거 (픽셀)

| 근거 | 실측 | 결론 |
|---|---|---|
| 상단 HUD 보임? | y **86~191** 에 갈색 밴드 `#42362A`, 재화 2종 표시 | **보임(고정)** — A3 소속 |
| 하단 앱 탭바 보임? | y **2160~2339**, 상단 검정선 y2160~2163 | **보임(고정)** — A1 소속 |
| 딤 오버레이? | 페이지 배경 `#272731`, HUD 밴드 `#42362A` — **10/13 전체화면 페이지와 완전 동일 원색**. 어떤 α 딤도 적용되지 않음 | **딤 없음** |
| 모달 카드/테두리? | y=250 **전폭(x0~1079) 가로 스캔** → `lum<22` 0개, `lum>60` 0개 | **없음** (빈 배경) |
| 팝업 헤더/타이틀/✕ | y192~289 구간 전체가 배경색뿐 | **없음** |
| 콘텐츠(스크롤 뷰포트) 영역 | x **0 ~ 1079** (전폭), y **192 ~ 2159** (h **1968**) | 전폭 블리드 |
| 콘텐츠 배경 원색 | **`#272731`** (39,39,49) | 평탄부 (250,540) / (1150,900) |
| 배경 무늬 | 커다랗고 흐릿한 «유령» blob (`#2D2C3C` ~ `#2E2D3F` 밝은쪽 / `#262630` 어두운쪽). 14 와 동일 위치 = **정적 배경 애셋** | 아트 리소스 |

### 1.3 14(보물상자 탭)와의 공통 껍데기 대조
14 ↔ 15 **행 단위 최대 채널차 ≤ 12** 인 «완전 동일» 구간:

| 구간 | 의미 |
|---|---|
| y **0 ~ 101** | 상태바 + HUD 상단 (완전 동일) |
| y **173 ~ 191** | HUD 하단 + 검정 하단선 (완전 동일) |
| y **2242 ~ 2339** | 앱 탭바 하단 (완전 동일) |

> y102~172 가 «다름»으로 잡히는 이유는 **재화 숫자(43.70A vs 43.68A)** 와 **14 에만 있는 좌측 `?` 버튼** 때문. 밴드 자체는 동일.
> 15 의 HUD 좌측(x0~496)은 y=140 전폭 스캔에서 `#42362A` 단색 → **15 에는 `?` 버튼도 프로필 플레이트도 없다.**

**공통 껍데기의 경계 = 서브탭 바까지.** 14 와 15 는
- 서브탭 바 외곽 y **2021 ~ 2118** (h 98) — **두 화면 동일**
- 세그먼트 라벨 잉크 중심 **x=345 (보물상자) / x=734 (유물)** — **두 화면 픽셀 단위로 동일**
- 활성/비활성 알약의 «색과 크기»만 서로 뒤바뀜 (§2)

즉 **껍데기 = HUD(A3) + 서브탭 바 + 앱 탭바(A1)**, 그 안쪽 y192~2159 가 탭별 콘텐츠 영역이다.

### 1.4 서브탭 바는 «오버레이»다 (중요)
- 15 의 «레어» 리본은 서브탭 바 **아래쪽**(y2118~2159)에 다시 나타난다.
- 리본 좌측 꼬리의 x 프로파일을 «커먼» 리본과 형태 매칭한 결과 **레어 리본 상단 y ≈ 2093** (섹션 피치 902 기준 이론값 **2094**) → 즉 리본의 위쪽 **약 25px 가 서브탭 바에 가려져 있다**.
- 따라서 서브탭 바는 **스크롤 콘텐츠 위에 떠 있는 하단 고정 오버레이**이며, 스크롤 뷰포트는 그 뒤로 y2159 까지 이어진다.
- 바 아래에는 그림자가 없다(바 하단 y2118 바로 아래 픽셀 = 배경 `#272731`).

```
  ↓ gap 91
다음 리본   y 1192 ...
────────────────────────────────
섹션 피치 = 101 + 51 + 324 + 11 + 324 + 91 = 902
```
