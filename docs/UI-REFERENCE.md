# UI 레퍼런스 — 목표 레이아웃

레퍼런스 게임(햄지·매옹이 계열 방치형 RPG) 스크린샷 22장을 화면별로 정리한 문서입니다.
**이 문서의 레이아웃이 목표이며, 현재 `index.html`의 UI는 이 방향으로 교체합니다.**

- 화면 이름은 **기획에서 지정한 명칭**을 사용 (모달 안에 찍힌 제목과 다를 수 있음 — 목차 참고)
- **앱 프레임 `1080×1920` (9:16)로 확정** (2026-08-24 변경. 레퍼런스 캡처는 1080×2340 이지만 폭이 같으므로 가로 수치는 1:1, 세로 차이는 전투 캔버스가 흡수)
- 따라서 **스크린샷에서 잰 좌표·크기·폰트·여백을 변환 없이 그대로 사용**한다 (1:1 대응)
- `#app`은 고정 프레임을 `transform: scale()`로 화면에 맞추는 구조라 내부 좌표계를 키워도 표시 크기는 동일
- **스크린샷 원본은 `docs/ref/` 에 번호순으로 들어 있습니다** (`01-오프라인보상-팝업.jpg` …). 각 항목 제목 아래에 첨부되어 있으니 작업 세션에서 바로 열어 보면 됩니다
- 작업 지시는 **번호로** 하면 됩니다 — 예: “UI-REFERENCE.md 10번대로 상점 소환 탭 다시 만들어줘”

### 설계 확정 (2026-08-24) — 레퍼런스와 다르게 가는 것

레퍼런스 게임은 **캐릭터 2명(햄지·매옹이)을 한 번에 키우는** 구조지만, 우리 게임은 다음으로 확정한다.
아래 항목은 화면별 절과 24번 체크리스트에도 반영돼 있다.

1. **캐릭터는 «용사» 1명.** 햄지·매옹이 2명 구조를 따르지 않는다. 06 장비 팝업의 캐릭터 카드는
   **1개**(이름 리본 `용사`)로 하고, 훈련·스탯·퀘스트 등에서 «햄지 공격력 / 매옹이 공격력» 처럼
   캐릭터별로 갈라진 항목은 전부 **단일 «공격력»** 으로 합친다.
2. **장비 부위는 3종 — 무기 · 방패 · 목걸이.** 부위 슬롯은 2칸(무기/방어구)이 아니라 **3칸**이다.
   레퍼런스의 잠금 슬롯 행(반지·목걸이·탈것)은 폐기한다(목걸이는 정식 부위로 승격, 반지·탈것 없음).
3. **하단 탭 «모험» 은 없애고 그 자리를 «던전» 으로.** 탭 라벨을 `던전` 으로 바꾸고, 탭을 누르면
   중간 화면 없이 **03 던전 팝업(페이지)이 바로 열린다.**
4. **영웅 서브탭 «동료» 는 잠금이 아니라 정식 화면.** UI 는 **07 스킬 팝업과 같은 구조**를 그대로 쓰되
   **장착 슬롯만 8칸 → 3칸**이다. 스펙은 **26번** 참고.
5. **하단 탭 «성장» 은 «훈련» 으로.** 탭 라벨을 `훈련` 으로 바꾸고, 탭을 누르면 중간 화면 없이
   **23번 훈련 팝업이 바로 열린다** — 레퍼런스 23 이미지 나온 그대로 구현한다. **⚑ 최우선 순위 작업이다**(작업 단위 23).
6. **보스는 제한 시간 30초.** 보스 스테이지는 **30초 안에 클리어해야 한다.** 전투 중 스테이지 헤더에
   ⏱ 남은 시간을 표시(02 ② 의 도전 모드 타이머 규격 재사용)하고, 시간 초과 시 실패 처리(패배 → 스테이지 재도전.
   18번 패배 화면이 생기면 그리로 연결).
7. **룰렛은 «원판» 이다.** 지금의 8칸 그리드 하이라이트 방식이 아니라, **실제로 회전하는 원판 휠**
   (세그먼트 8칸 + 상단 고정 포인터, 돌리기 → 감속 → 포인터가 가리킨 칸 당첨)로 바꾼다.
   **인터넷의 오픈소스 스피너 휠 코드를 가져와도 된다** — 단 `index.html` 에 인라인으로 포함(외부 CDN 요청 금지)하고,
   세그먼트 아트·텍스트만 우리 보상 8종(`ROULETTE` 배열)으로 교체한다. 보상·확률·횟수(하루 5회)는 기존 로직 그대로.

## 0. 공통 프레임

모든 화면이 아래 프레임 위에 얹힙니다. 전투 화면은 항상 뒤에서 계속 돌아가고, 콘텐츠는 **패널 또는 모달**로 위에 덮입니다.

```
┌───────────────────────────────────────────┐
│ [초상화] 닉네임 / 칭호        💰 54.65A     │  ① 상단 HUD (고정)
│          🔥 1.33B            💎 4,600      │
├───────────────────────────────────────────┤
│ 🔒                STAGE 37           ▦    │  ② 스테이지 헤더 + 우상단 메뉴
│ 패스              ●───────●──💀           │     (진행바 + 보스 노드)
│ 퀘스트                              이벤트 │
│ 휴식보너스        [ 전 투 화 면 ]    특권  │  ③ 좌/우 사이드 아이콘
│ 도감                               [집 4] │
│ 길드                               1D 22H │
│ 💬                                        │
│ 마을                    [보상받기 미션]    │  ④ 좌하단 유틸 / 우하단 미션
```

### ① 상단 HUD
| 위치 | 요소 |

| 좌 | 정사각 **초상화**(테두리 프레임) + 우측에 닉네임(`U_1787501115822`), 그 아래 **칭호** 알약(`칭호 없음`) |

### ② 스테이지 헤더
- 중앙 상단 `STAGE 37` (외곽선 있는 굵은 폰트)
- 바로 아래 **진행바**: 좌측 시작 노드 ─ 중간 노드 ─ 우측 끝에 **보스 해골 아이콘**
- 전투 중이 아닐 때(클리어 상태)는 진행바 대신 해골 엠블럼 + 빨간 **[스테이지 재도전]** 버튼
- 도전/특수 모드에서는 헤더 위에 ⏱ **남은 시간**(`53.6`)과 빨간 **[포기하기]** 버튼이 추가됨

  > 규격으로 남은 시간을 표시하고, 30초 안에 못 잡으면 실패 처리(패배 → 재도전. 18번 패배 화면 생기면 연결).
- 우상단: ▦ 4분할 메뉴 버튼(레드닷)

### ③ 좌/우 사이드 아이콘 (세로 스택)
- **좌**: 🔒(잠금 슬롯) · 패스 · 퀘스트 · 휴식 보너스 · 도감 · 길드
- **우**: 이벤트 · 특권 · 시설 배너(집 아이콘 + `4` 뱃지 + `1D 22H` 타이머)
- 아이콘 = 정사각 일러스트 + 아래 라벨. 미해금은 자물쇠 오버레이
- 알림은 **좌상단 빨간 점(레드닷)**

### ④ 좌하단 / 우하단
- 좌하단: 💬 채팅 버튼, 🌳 **마을** 버튼
- 우하단: 진행형 미션 배너 — `[보상받기]` / `적 50마리 처치하기` / 보상 아이콘(상자 ×3)
- 우하단 구석: 배속 버튼(`×1.3`, 잠금 상태면 자물쇠)
- 전투 화면 아래쪽에 `[미션-124] 보물상자 1개 오픈 (0/1)` + 보상(💎1,000) 형태의 **가이드 미션 바**도 존재

### ⑤ 스킬 슬롯
- **원형** 슬롯 8개, 전투 화면 최하단에 가로 배치
- 장착 슬롯은 캐릭터/스킬 아이콘 + 컬러 링(노랑=활성, 파랑=대기), 미해금은 자물쇠
- 쿨타임은 슬롯 위에 오버레이

### ⑥ 하단 탭바 (5개 고정)
`영웅 · 성장 · 모험 · 보물상자 · 상점`
- 각 탭 = 큰 아이콘 + 라벨, 레드닷 지원, 신규는 **NEW** 리본
- 패널/모달이 열려 있으면 해당 탭 자리가 **✕(닫기)** 버튼으로 바뀜

> **설계 변경(2026-08-24)**: 우리 게임의 탭 구성은 `영웅 · 훈련 · 던전 · 보물상자 · 상점` 이다.
> - 2번째 탭 `성장` → **`훈련`** — 누르면 **23번 훈련 팝업이 바로** 열린다 (⚑ 최우선, 작업 단위 23)
> - 3번째 탭 `모험` → **`던전`** — 누르면 **03 던전 페이지가 바로** 열린다 (작업 단위 24)
> 둘 다 중간 화면을 만들지 않는다. 레이아웃(칸 크기·위치·측정값)은 A1 측정표 그대로,
> 라벨 문자열과 연결 동작만 다르다.

### 화면비 대응 — 폭 고정 · 세로 가변

**디자인 기준은 `1080×1920` (9:16) 입니다.** (2026-08-24 변경 — 이전 기준은 9:19.5 였음)
9:19.5 · 9:21 등 더 긴 화면에서도 깨지지 않아야 합니다.

> **레퍼런스 스크린샷은 1080×2340(9:19.5) 캡처지만, 기준 프레임은 1080×1920 입니다.**
> 폭이 둘 다 1080 이므로 **가로 수치(x · width · font-size · gap · radius)는 변환 없이 1:1** 로 씁니다.
> 세로도 **고정 요소(상단 HUD · 튜토리얼 배너 · 패널 · 탭바)는 측정값 그대로** 쓰고,
> 차이 420px 은 **전투 캔버스가 흡수**합니다. 절대 전체를 `1920/2340` 비율로 축소하지 마십시오.

**고정 프레임을 통째로 레터박스하면 안 됩니다.**
더 긴 기기에서 높이가 먼저 걸리면 좌우에 여백이 생기고 UI 전체가 작아집니다.

**규칙: 폭은 1080 고정, 높이는 기기 비율에 맞춰 가변.**

```js
const AW = wrap.clientWidth, AH = wrap.clientHeight;        // 안전영역 제외된 값
const frameH = clamp(Math.round(1080 * AH / AW), 1600, 2600); // 극단 비율 방어
app.style.width  = '1080px';
app.style.height = frameH + 'px';
app.style.transform = 'scale(' + (AW / 1080) + ')';          // 항상 폭에 꽉 맞음
```

| 화면비 | frameH | 1920 대비 |
|---|---|---|
| 9:21 | 2520 | +600 |
| 9:19.5 | 2340 | +420 |
| 9:18 | 2160 | +240 |
| **9:16 (기준)** | **1920** | **—** |
| 4:3 (태블릿) | 1600 (clamp) | 레터박스 |

**높이 배분 규칙**

| 구분 | 요소 | 높이 |
|---|---|---|
| 고정 | 상단 HUD, 튜토리얼 배너, 하단 탭바 | 레퍼런스 측정값 그대로 |
| **가변** | **전투 화면(캔버스)** | **남는 높이를 전부 흡수** |
| 가변 | 패널(탭 콘텐츠) | 내부 스크롤로 흡수 |

**현재 구현값** (프레임 1080×1920 기준, 기존 540×960 레이아웃을 2배한 잠정값 — 화면별 작업 시 레퍼런스 측정값으로 교체)

| 요소 | 높이 | 비고 |
|---|---|---|
| `#top` (상단 HUD) | 112 | 고정 |

| `#tuto` (튜토리얼 배너) | 103 | 고정, 내용에 따라 auto |

### 안전 영역 (Safe Area) · 실기기 대응

레퍼런스 스크린샷은 **1080×2340 전체 화면 캡처**(기준 프레임은 1080×1920)이고 상태바가 보이지 않는 **몰입형(immersive)** 상태입니다.
반면 웹 빌드는 노치 · 상태바 · 홈 인디케이터를 직접 피해야 합니다.

| 문제 | 현재 상태 | 대응 |
|---|---|---|
| 노치/상태바가 상단 HUD를 가림 | `#wrap{inset:0}` 로 화면 전체를 덮음 | `#wrap` 에 `env(safe-area-inset-*)` 패딩 |
| 홈 인디케이터가 하단 탭바를 가림 | 미처리 | 위와 동일 (bottom inset) |
| 스케일 계산이 안전영역을 무시 | `fit()` 이 `window.innerHeight` 사용 | `#wrap` 의 `clientWidth/clientHeight` 기준으로 계산 |
| 모바일 브라우저 주소창 표시/숨김 | `resize` 만 처리 | `visualViewport` 의 `resize`·`scroll` 도 처리 |
| 기기별 화면비 편차(19.5:9 ~ 21:9) | 레터박스(위아래 여백) | 의도된 동작. 여백은 앱 배경색으로 채움 |

```css
#wrap{ position:fixed; inset:0; display:flex; align-items:center; justify-content:center;
  padding: env(safe-area-inset-top)  env(safe-area-inset-right)
           env(safe-area-inset-bottom) env(safe-area-inset-left); }
```
```js
function fit(){
  const AW = wrap.clientWidth, AH = wrap.clientHeight;         // 안전영역 제외
  const frameH = clamp(Math.round(1080 * AH / AW), 1600, 2600);
  app.style.height = frameH + 'px';
  app.style.transform = 'scale(' + (AW / 1080) + ')';
  resizeCanvas();                                              // 캔버스 높이 재계산
}
addEventListener('resize', fit);
if(window.visualViewport){ visualViewport.addEventListener('resize', fit); }
```

> 좌표는 **1080×1920 프레임 안에서만** 다룹니다. 안전영역은 프레임 **바깥**에서 흡수되므로
> 각 화면의 측정값은 안전영역과 무관하게 레퍼런스 그대로 쓰면 됩니다.

## 21. 도감 보너스 팝업

![도감 보너스 팝업](ref/21-도감-보너스-팝업.jpg)

**진입**: 좌측 사이드 아이콘 → 도감

- 모달 헤더가 다른 화면과 다름: **파란 리본 배너**(둥근 깃발 모양)에 `도감`, 우측에 🔍 검색 버튼
- 본문은 **세트 단위 블록**의 세로 리스트. 블록 1개 구성:

```
┌─────────────────────────────────────────┐
│ ▨Lv.5 │ ✦ 따뜻한 처음                    │ ← 세트 헤더 (짙은 남색 바)
├─────────────────────────────────────────┤
│  [아이템]  [아이템]                       │ ← 세트 구성 아이템 그리드
│  Lv. 5/6   Lv. 6/6                      │
├─────────────────────────────────────────┤
│ 체력 5% 증가                    [ 강화 ] │ ← 효과 바 + 강화 버튼
└─────────────────────────────────────────┘
```

| 요소 | 규격 |
|---|---|
| 세트 레벨 뱃지 | 헤더 좌측에 **빨간 방패형 리본**, 안에 `Lv. 5` (2줄) |
| 세트 이름 | ✦ 아이콘 + 이름 (`따뜻한 처음`, `탐험가`, `부드러운 활동복`, `햇병아리 기사`) |
| 아이템 카드 | 등급색 배경(갈색 커먼 / 초록 언커먼 / 파랑 레어) + 하단 라벨 `Lv. 현재/필요` |
| 카드 라벨 색 | **미달 = 빨강**(`Lv. 5/6`), **충족 = 흰색**(`Lv. 6/6`) |
| 효과 바 | 연베이지 바, 좌측 효과 문구 — 수치만 **초록 강조**(`체력 5% 증가`, `매옹이 이동 속도 0.05% 증가`) |
| 강화 버튼 | 효과 바 우측, 조건 미충족 시 회색 비활성 |
| 서브탭 | 모달 **하단 바깥**에 **깃발형 탭 4개**: `무기 · 방어구 · 스킬 · 동료` (파란 배경 + 노란 테두리, 아래가 뾰족한 리본 모양, 레드닷 지원) |

> 포인트: 세트를 구성하는 아이템들을 **각각 요구 레벨까지 올려야** 세트 강화가 열리는 구조.
> 내 구현의 "컬렉션 보너스"를 이 형태로 바꾸면 됨 — 종수 수집이 아니라 **세트별 레벨 조건**.

  - **배수 탭**: `x1 / x10 / x30` (선택된 항목만 밝게, 각 구간에 레드닷)
- **스탯 카드 3열** (카드 우상단 레드닷)
  | 영역 | 내용 |
  |---|---|
  | 상단 노란 헤더 | `Lv. 380` (해당 스탯 훈련 횟수) |

  | 하단 갈색 바 | 골드 아이콘 + 비용 `741` |
- 하단 서브탭: `훈련` · 🔒 · 🔒 · `마법상판(🔒)`

### 우리 게임 설계 (레퍼런스와 다름)

**훈련 = 골드 강화**를 이 구조로 대체합니다.

- 강화 대상을 **공격력 / 체력 / 체력회복** **3종으로 단순화**
- 각 스탯의 상한 = **훈련 단계 × 100**
  - 1단계 → 각 100까지 / 2단계 → 각 200까지 / 3단계 → 각 300까지 …
- **3종 모두 상한까지** 찍으면 진행바 우측 **↑ 버튼 활성화**
- ↑ 버튼을 누르면 **[17. 스탯업 보너스 팝업 연출]** 이 재생되고 **훈련 단계 +1**
- **단계가 오를 때마다 훈련 보너스: 공격력 · 체력 · 체력회복 각 +10%** (누적)
- 상한이 다시 열리므로 계속 반복 — **무한 구조**
- 구매 단위 `x1 / x10 / x30` 지원

```
훈련 1단계:  공격력 0→100  체력 0→100  체력회복 0→100   (전부 100)
             ↓ ↑버튼 → 연출 → 2단계, 훈련 보너스 +10%
훈련 2단계:  상한 200으로 확장 → 전부 200
             ↓ ↑버튼 → 연출 → 3단계, 보너스 누적 +20%
...  무한 반복
```

### 스탯 훈련 (캐릭터 레벨 포인트)

- 캐릭터 레벨업으로 얻는 **스탯 포인트**도 이름을 **“스탯 훈련”**으로 바꾸고 **같은 구조**로 운영
- 동일하게 공격력 / 체력 / 체력회복 3종 · 단계별 상한 · ↑ 버튼 · 단계 보너스
- 차이는 **소모 재화**뿐 — 훈련은 **골드**, 스탯 훈련은 **스탯 포인트**

## 25. 세션 운영 규칙 (컨텍스트 · 토큰 한도 대비)

작업량이 커서 **한 세션 안에 끝나지 않는다.** 컨텍스트가 압축되거나 토큰 한도로 중단돼도
다음 세션이 이어받을 수 있도록 아래 규칙을 지킨다.

### 상태는 항상 파일에 남긴다

| 파일 | 역할 |
|---|---|
| `docs/PROGRESS.md` | **단일 진실 공급원.** 단계·화면별 상태·점수·루프 횟수·미결 사항 |
| `docs/UI-REFERENCE.md` 24번 | 구현 체크리스트 `[ ] / [x]` |
| `docs/measure/NN-이름.md` | 화면별 **측정표** (재측정 방지) |
| `docs/review-log.md` | 비평가 점수와 지적사항 이력 |
| `git log` | 실제로 무엇이 반영됐는지의 최종 근거 |

- **화면 하나가 통과할 때마다** 위 파일을 갱신하고 **반드시 커밋**한다
- 커밋 메시지에 화면 번호와 점수를 남긴다 — 예: `feat(ui): 03 던전 팝업 (9.2/10)`

### 컨텍스트 절약

- **이미지는 메인 세션에서 직접 Read 하지 않는다.** 측정과 채점은 **서브에이전트**에게 시키고
  결과 텍스트(측정표 · 점수 · 지적사항)만 받는다. 이미지가 메인 컨텍스트를 먹지 않게 한다
- 캡처본은 저장소 밖 임시 경로에 저장하고, 통과한 화면의 캡처는 지운다
- `index.html` 전체를 반복해서 읽지 말고 필요한 구간만 grep 후 부분 편집한다
- 한 세션에서 **A~C 전체를 시도하지 않는다.** 화면 2~3개 단위로 끊는다

### 중단 · 재개

- 컨텍스트가 70% 이상 찼거나 토큰 한도가 임박하면 **즉시 작업을 멈추고**
  `PROGRESS.md` 를 갱신 → 커밋 → 현재 상태를 한 줄로 보고한 뒤 종료한다
  (**작업 도중에 끊기지 않도록, 화면 하나가 통과한 직후에 끊는다**)
- 재개는 항상 동일한 절차다
  1. `docs/PROGRESS.md` 를 읽는다
  2. 화면별 상태 표에서 **구현이 비어 있는 가장 앞 번호**를 찾는다
  3. `docs/measure/NN-*.md` 가 있으면 재측정하지 않고 그대로 쓴다
  4. 검증 루프를 이어서 돌린다
- **직전 세션의 대화 내용을 안다고 가정하지 않는다.** 필요한 정보는 전부 위 파일에 있어야 한다

### 병렬 워커 — 작업 단위 선점 (2026-08-24 개정)

> **옛 «전역 락(docs/.session-lock)» 방식은 폐기됐다.** 그 방식은 한 번에 한 세션만 돌게 하므로
> 병렬 진행이 불가능하다. `.session-lock` 파일을 만들지도, 보고 종료하지도 마라.

클라우드 워커가 매시간 돌아 동시에 여러 세션이 작업한다 (계정당 A~D 4개, 두 계정 동시 가동 시 최대 8세션 —
cron 은 `docs/ROUTINE-OPS.md` §1). 전부 `index.html` 한 파일이므로 **작업 단위(ID)로 선점**해서 구간을 나눈다.

**시작할 때**
1. `git checkout main || git checkout -B main origin/main` → `git pull --rebase origin main`
2. `SID=sess-$(date -u +%H%M)-$RANDOM` 으로 세션 식별자를 만든다
3. `docs/PROGRESS.md` 의 «작업 단위» 표 순서(A1→A5→01→…표의 마지막 번호)대로 훑어
   **미완료이면서 `docs/claims/<ID>.lock` 이 없는** 첫 작업을 고른다
   - lock 이 있어도 안의 UTC 시각이 **90분 초과**면 죽은 것으로 보고 뺏는다
4. lock 파일에 `<UTC시각> <SID>` 한 줄을 쓰고 커밋 후 push
5. **push 가 거부되면** `git pull --rebase` 후 다시 본다
   - 남이 같은 ID 를 먼저 잡았으면 **그 작업만 포기하고 다음 미선점 작업**으로 간다 (세션을 끝내지 않는다)
   - 잡을 게 하나도 없을 때만 종료한다

**끝낼 때 (성공·중단·에러 무관)**
- `docs/claims/<ID>.lock` 을 삭제하고 커밋 + push 한다
- 빼먹으면 90분 동안 그 작업이 막히므로 반드시 지운다

```bash
# 시작
git checkout main 2>/dev/null || git checkout -B main origin/main
git pull --rebase origin main
SID=sess-$(date -u +%H%M)-$RANDOM
ls docs/claims/                                   # 선점 현황 확인
echo "$(date -u +%Y-%m-%dT%H:%M:%SZ) $SID" > docs/claims/A1.lock
git add docs/claims/A1.lock && git commit -m "chore: A1 선점 ($SID)"
git push origin main    # 거부되면 pull --rebase 후 재확인 → 남의 것이면 다음 작업으로

# 종료
git rm docs/claims/A1.lock && git commit -m "chore: A1 선점 해제" && git push origin main
```

**충돌 처리**
- push 전 항상 `git pull --rebase origin main`
- `index.html` 충돌 시 **양쪽 변경을 모두 살린다** (서로 다른 구간이라 대개 자동 병합됨).
  내 작업 구간이 아닌 곳은 남의 버전을 그대로 둔다. 병합 후 문법 검사 + 헤드리스로 에러 0건 확인
- `PROGRESS.md` 충돌 시 **양쪽 행을 모두 살린다**
- 비평 기록은 `docs/review/<ID>-이름.md` 에 **자기 파일로만** 쓴다 (공용 `review-log.md` 추가 금지)

**전체 지시서는 `docs/ROUTINE.md`** 에 있다. 루틴 4개는 그 파일을 읽고 그대로 수행하므로,
지시를 바꾸려면 `ROUTINE.md` 하나만 고치면 된다.

## 26. 동료 팝업 (신규 설계 — 레퍼런스 스크린샷 없음)

레퍼런스에서는 `동료` 서브탭이 잠금이라 스크린샷이 없다. **우리 게임은 이 화면을 정식으로 만든다**

**진입**: 영웅 탭 → 서브탭 `동료` (잠금 해제)

### 구조 — 07 스킬 팝업을 그대로 복제하되 장착 슬롯만 3칸

**07 스킬 팝업과 완전히 같은 UI 구조·규격을 재사용한다.** 측정값은 `docs/measure/07-스킬팝업.md` 를
그대로 쓰고, 새로 측정하지 않는다. 다른 점은 아래뿐이다:

| 항목 | 07 스킬 | 26 동료 |
|---|---|---|
| 상단 장착 슬롯 | **8칸** 가로 배치 | **3칸** 가로 배치 (슬롯 1칸 규격·간격은 07 과 동일, 패널 안에서 가로 중앙 정렬) |
| 헤더 제목 | `스킬` | `동료` |
| 그리드 내용 | 보유 스킬 | 보유 동료 |
| 소환 버튼 | `[스킬 소환]` | `[동료 소환]` |

- 장착 슬롯: 장착된 동료는 `Lv.n` + `─` 해제 버튼 (07 과 동일)
- 보유 동료 그리드 **5×3**: 카드 좌상단 `Lv.n`, 우상단 **[+] 장착 / [─] 해제**, 하단 재료 진행바,
  장착 카드는 중앙 `장착 중` — 전부 07 카드 규격 그대로
- 하단 `총 보유 효과` 라벨 + 버튼 2개(`[동료 소환]` / `[일괄 강화]`) — 07 규격 그대로.
  `[동료 소환]` 은 그 자리 소환이 아니라 **10번 상점 소환 탭으로 이동**(07 의 «설계 변경» 과 같은 규칙)
- 동료 카드 선택 시 세부 팝업은 **08 스킬 세부 팝업 껍데기 재사용** (내용 문자열만 동료)

### 데이터 (미정 항목)

- 동료 획득 경로(소환 배너 신설 여부)·효과 종류·밸런스 수치는 **미정** — UI 를 먼저 만들고
  임시 데이터로 연결한다. 저장 구조를 바꾸면 세이브 마이그레이션 또는 KEY 버전을 올릴 것.
