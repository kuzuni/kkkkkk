> **01 에서 얻은 교훈 2개 (다른 화면에서도 그대로 재발한다)**
> - **측정표의 `font-size (추정)` 을 그대로 쓰면 안 된다.** 측정표는 `잉크높이 ÷ 0.75` 로 추정하는데
>   이 프로젝트 폰트의 실제 잉크비는 **0.93** 이다. 그대로 쓰면 글자가 15~25% 커지고, 폭을 맞추려
>   음수 `letter-spacing` 을 넣으면 **어절 공백과 소수점이 통째로 사라진다**(`1.5배 받기`→`15배받기`).
>   → `font-size = 실측 잉크높이 / 0.93`, 폭은 글자를 감싼 `<i>` 의 **`transform:scaleX()`** 로 맞출 것.
> - **`background-clip:text` 와 `-webkit-text-stroke` 는 같이 못 쓴다**(스트로크가 그라데이션을 덮어
>   글자가 통째로 검정이 된다). 외곽선 레이어를 따로 깔고, 그라데이션은 **글자를 직접 담은 요소**에 걸 것.

> **15 에서 얻은 교훈 (CSS 변수 — 다른 화면에서도 그대로 재발한다)**
> - **`var(--x, var(--y))` 폴백은 `--x` 가 «어디에도» 정의되지 않았을 때만 걸린다.** 베이스 규칙에
>   파생 변수를 정의해 두면, 등급·상태 규칙이 원본 변수만 덮어써도 폴백이 안 걸려 **틴트가 통째로 죽는다.**
>   15 에서 이 한 줄 때문에 등급별 색이 한 회차 내내 무시됐고 ⑤ 점수가 7~8 → 4~5 로 떨어졌다.
> - **수정 후에는 그 변수를 쓰는 «다른 상태»(등급·보유 여부)도 한 번씩 재실측할 것.**

> **A5 에서 얻은 교훈 3개**

>   화면 작업 전에 그 화면이 셋 중 어느 껍데기인지부터 확인할 것.
> - **비평가는 반드시 PIL 픽셀 스캔을 시켜라.** 눈대중 비평가는 우리가 값을 아는 항목(테두리 7px)을
>   4px 로, 모달 폭 898 을 878 로 읽었다. 그 회차 지적을 그대로 반영했으면 오히려 멀어졌다.

> - **`letter-spacing` 은 마지막 글자 뒤에도 붙어** 가운데 정렬을 그만큼 왼쪽으로 민다.

#### A1 비고 (통과 기준 9 미달 — 남은 문제)

1. **아이콘이 이모지다.** 레퍼런스는 칸마다 폭이 다른 일러스트(영웅121·성장150·모험109·보물상자125·상점165)라
   칸별 font-size 로 근사했지만, 이모지는 가로세로가 같이 커져 **가로로 넓은 아트(상점 165×115)를 재현할 수 없다.**
   → 아트 리소스가 들어와야 ② 상대 크기 비율이 9점에 도달한다.
2. **라벨 2글자 폭이 +9%** (61 vs 56). 4글자('보물상자')는 120 vs 121 로 일치해서, 자간을 더 줄이면 4글자가 어긋난다.
   레퍼런스의 **좁고 높은 게임용 한글 서체**를 웹폰트로 넣기 전에는 트레이드오프다.
3. 탭바 **바로 위 보라색 튜토리얼 배너**(`#tuto` 의 `border:3px solid #6d54ad`)는 레퍼런스에 없다.
   **A1 구간이 아니라 손대지 않았다** — 별도 작업 단위에서 처리할 것.
4. NEW 리본 기울기는 측정(−22°)과 비평가 실측(−8° / −20.6°)이 엇갈려 **−20°** 로 정했다.

> 참고 — 이번에 잡은 CSS 함정 2개 (다른 화면에서도 그대로 재발한다):
> - **글리프 advance 보다 좁은 박스**에 `text-align:center` 를 쓰면 넘친 글리프가 가운데가 아니라 **좌측 정렬**돼
>   잉크가 우측으로 밀린다. 아이콘 박스는 advance 보다 넓게 잡을 것.
> - `*{box-sizing:border-box}` 리셋은 **의사요소(::before/::after)를 잡지 못한다.** 테두리를 준 의사요소는
>   `box-sizing` 을 직접 써 주지 않으면 테두리 두께만큼 커지고 중심이 밀린다.

**주의 — 이전 세션의 `#legacy{transform:scale(2)}` 스캐폴드 방식은 저장소 주인이 revert 했다.**
(래퍼를 통째로 scale(2) 하는 방식은 프레임 아래쪽에 검은 띠가 남는다)
이번에는 스캐폴드 없이 **CSS px 값을 실제로 2배**하고 **캔버스가 남는 높이를 흡수**하도록 했다. 되돌리지 말 것.

## 병렬 세션 규칙 (2026-08-24 도입)

여러 세션이 **동시에** 돈다. 전부 `index.html` 한 파일이므로 **작업 단위로 선점**해서 나눈다.

1. 작업 선택은 **티어 순**: **T1** 【⚑ 우선】 → **T2 주인 지시 TODO(24~36 — 설계 변경·신규 기능. 일반
   화면 루프보다 먼저)** → **T3** 한 번도 구현 안 된 일반 화면(`docs/review/<ID>-*.md` 없음 — 이게 남아
   있으면 재폴리시 금지) → **T4** 2차 폴리시 라운드(점수 낮은 순). 같은 티어 안은 표 순서, 대상은 항상
   미완료 + lock 없음. **통과·최종 목표는 전 화면 8점(2026-08-25 통과 기준 9→8 하향)**이되, 화면당 라운드
   상한 10회(세션 합산)를 채우면 «⏸ 보류» 하고 다음 화면으로 — 전 화면 커버 후 T4 에서 8점을 채운다. 아트/서체 한계 화면은
   «보류(아트 대기)». 상세: `ROUTINE.md` [-1]·[3] (골고루 규칙).
2. `docs/claims/<ID>.lock` 에 `<UTC시각> <세션식별자>` 한 줄을 쓰고 **커밋 + push**.
   - push 가 거부되면 `git pull --rebase` 후 다시 본다. 내 lock 이 아닌 남의 lock 이 생겼으면 **그 작업은 포기하고 다음 것**을 잡는다.
3. 잡은 작업의 코드 구간만 건드린다. **다른 작업 구간은 절대 손대지 않는다.**
4. 끝나거나 중단하면 성공·실패 무관하게 lock 을 **삭제**하고 push.
5. **90분 넘은 lock 은 죽은 것으로 보고 뺏는다.**
6. 비평 기록은 `docs/review/<ID>-이름.md` 에 **자기 파일로만** 쓴다 (공용 `review-log.md` 에 추가 금지).
7. push 전 항상 `git pull --rebase origin main`. `index.html` 이 충돌하면 **양쪽 변경을 모두 살린다**
   (서로 다른 구간이라 대부분 자동 병합됨). 병합 후 반드시 문법 검사 + 헤드리스 실행으로 확인.
8. `PROGRESS.md` 는 유일한 공용 파일이다. 충돌하면 **양쪽 행을 모두 살린다.**

### 04 비고 (던전 세부 팝업) — **비평 루프를 낭비하지 않기 위한 교훈 3개**

1. **캡처 상태가 레퍼런스와 다르면 그 회차 비평은 통째로 무효다.** 04 는 첫 캡처를 엉뚱한 던전
   (황금 동굴 8층)으로 떠서 비평가 2명에게 보냈고, 레퍼런스는 보석 던전 3층이었다.
   돌아온 지적이 **전부 내용 차이**였다 — 리본 텍스트 «+26px 과대»(문자열이 달랐다. 맞추니 Δ1),
   타이틀 폭 불일치(던전 이름이 달랐다), «우 화살표 없음»(8층=최고층이라 next 가 비활성이었다).
   → **비평가에게 보내기 전에 캡처가 레퍼런스와 같은 상태(같은 대상·같은 층/탭)인지 먼저 확인할 것.**
2. **가려진 도형은 전체 bbox 로 재지 마라.** 04 입장권 알약은 좌측을 티켓 아이콘이 덮고 있어
   전체 bbox 를 잡으면 아이콘의 안티에일리어싱 행까지 물려 **높이가 45 → 51 로 읽힌다**.

   **가림이 없는 열/행을 골라 스캔**하면 ref 는 일관되게 44 다.
3. **반투명 요소의 형상은 뒤 레이어를 평탄화한 프로브 캡처로 재라.** 04 상태 리본은 반투명이라
   뒤 배너 아트가 비친다. 그대로 스캔하면 **뒤 아트의 어두운 픽셀이 리본 윤곽으로 잡혀**

### 02 비고 (기본 메인 화면)

1. **좌표계 정정 — 다른 세션도 이걸 써야 한다.**

   - 하단 고정 요소 → `stagearea 기준 bottom = 2160 − ref_bottom`
   229 를 쓰면 상단 요소가 전부 **41px 아래로** 내려간다.

3. **레퍼런스에 없어서 끈 것** — 진행바 안 숫자, 미션 배너 진행바, 헤더의 `최고 N`,

   (켜 두면 좌하단 마을 라벨·우하단 미션 배너와 세로로 겹친다). **정식 제거 여부는 A4/battlefoot 담당이 판단할 것.**
4. **레드닷 지름 정정** — A2 측정표는 메뉴 레드닷을 «채움 Ø31 / 외곽 Ø42» 로 적었으나

   배너 레드닷도 **Ø24** 다. 레드닷은 화면 전체에서 **Ø24~25 로 통일**돼 있다.
5. **우측 컬럼 1행 = 메뉴 버튼 (A2 와 협의 완료)** — 레퍼런스 우측 컬럼 1행은 이벤트 아이콘이 아니라
   4분할 메뉴 버튼이다(A2 측정표 §2 와 같은 결론). 02 가 메뉴 버튼을 넣자 `#sideR` 1행과
   **100×99px 완전히 겹쳐**, 02 쪽에서 `#sideR{transform:translateY(한 행 pitch)}` 임시 보정을 넣었었다.
   **이후 A2 가 1행을 정식으로 비워 해결했고, 임시 보정 줄은 제거했다.**
   현재 메뉴 버튼 `y176..276` / `#sideR` 1행 `y337~` 로 겹침 0건.
