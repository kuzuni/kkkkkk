# 화면 클레임 (병렬 세션용)

여러 세션이 동시에 돌기 때문에 **화면 단위로 선점**한다.

- 파일명: `NN.lock` (NN = PROGRESS.md 화면 번호, 2자리)
- **번호는 한 작업만 가리켜야 한다.** 새 작업을 등재할 때는 «화면별 상태» 표에 **이미 쓰인 번호 중 가장 큰 것 + 1**
  을 쓰고, 이미 쓰인 번호는 재사용하지 않는다. 선점이 번호로만 걸리므로 한 번호가 두 작업을 가리키면 두 워커가
  같은 lock 을 놓고 «다른 작업» 을 하거나, 한 워커의 lock 이 남의 작업까지 막는다(2026-08-28, 작업 281).
  - **«마지막 행» 이 아니라 «가장 큰 번호» 다**(2026-08-28, 작업 286). 표는 대체로 번호순이지만 아니어도 되고,
    번호가 옮겨진 행은 표 끝으로 이동시켜 두 읽기가 어긋나지 않게 한다. 한 줄로 확인:
    `awk '/^\| [0-9A-Z]/{split($0,a,"|");gsub(/^ +| +$/,"",a[2]);print a[2]}' docs/PROGRESS.md | sort -n | tail -1`
  - **push 가 rebase 로 붙은 뒤 한 번 더 본다** — 같은 시각에 두 워커가 같은 «표 끝 번호» 를 읽으면 같은 번호가 나온다.
    중복 0 확인: 위 awk 결과에 `| sort | uniq -d` (출력이 비어야 한다).
- 내용 1줄: `<UTC ISO8601> <세션식별자>` 예) `2026-08-24T07:05:11Z sess-a1b2`
- **90분이 지난 클레임은 죽은 것으로 보고 뺏는다.**
- 작업이 끝나거나 중단되면 성공·실패 무관하게 **반드시 삭제**한다.

세션마다 다른 파일을 만들므로 클레임 자체는 충돌하지 않는다.
같은 화면을 두 세션이 동시에 집으면 **push 가 먼저 성공한 쪽이 이긴다**
(진 쪽은 pull 후 자기 lock 파일이 사라졌거나 남의 것이 있으면 포기하고 다음 화면으로).
