  회차 기록(`docs/review/<ID>-*.md`)도 회차마다 같이 커밋한다 — 다음 세션이 이어받는 유일한 근거다.
- 끝나면 PROGRESS.md 해당 행 + UI-REFERENCE.md 체크리스트 + docs/review/<ID>-이름.md 를 갱신하고 lock 삭제 후 커밋 · push.

[2] 작업 규칙 (상세는 문서 0·24·25번)
- **기준 해상도는 1080x2280 (9:19) 이다.** (2026-08-25 확정. 08-24 의 9:16 기준은 폐기 — 레퍼런스 게임의 실제 콘텐츠 영역이 1080×2256≈9:19 다)
- 레퍼런스 스크린샷(docs/ref/*.jpg)은 1080x2340 캡처이고 **최상단 84px 이 상태바(안전영역)** 다. 따라서 변환은 **단 하나: 프레임 y = 레퍼런스 y − 84** (가로는 1:1).
  남는 24px(2280 − 2256) 은 전투 캔버스가 흡수한다. 옛 «y−419/−420/−210» 식 화면별 변환은 **전부 폐기** — 새로 쓰지 마라.
  9:16 등 짧은 기기에서는 전투 캔버스만 줄어든다(UI 고정 요소는 절대값 그대로). **절대 전체를 비율로 축소하지 마라.** 눈대중도 금지.
- **기존 UI를 래퍼로 감싸 scale() 로 확대·축소하는 꾸수는 금지한다.** 각 요소의 CSS 값을 레퍼런스 측정치대로 직접 다시 적는다.
- 폭 1080 고정 · 세로 가변(#app 높이 = 1080 x 안전영역높이/폭, clamp 1600~2600). 남는 높이는 전투 캔버스가 흡수.
- 안전영역은 프레임 바깥에서 흡수(#wrap 에 env(safe-area-inset-*), fit()은 wrap.clientWidth/clientHeight 기준).
- 구현 전에 측정한다: docs/measure/NN-이름.md 에 요소별 x/y/width/height/gap/font-size/border/radius 를 절대 px로 기록. 이미 있으면 재측정 금지.

[3] 검증 — 작업 종류에 따라 다르게 한다 (중요)

(가) **기계적 작업**(단위 변환, 상수 일괄 치환, 리네이밍, 값 스케일링 등 레퍼런스 대조가 필요 없는 작업)
  → **비평가를 절대 띄우지 마라.** grep 으로 미변환분이 남았는지 세고, 헤드리스로 한 번 띄워 콘솔 에러 0건과 요소 겹침·잘림 0건만 확인하면 통과다.
  → 이런 작업에 비평 루프를 돌리면 회차 예산을 다 태우고 정작 레이아웃을 못 바꾼다. 실제로 이전 회차가 그렇게 날아갔다.

(나) **레이아웃 재구성**(레퍼런스와 배치·비율을 맞춰야 하는 작업) → 아래 루프를 최대 5회 돈다.
  1. 헤드리스 브라우저로 그 화면을 **1080x2280** 으로 캡처한다(playwright. 2026-08-25 부터 — 1920 캡처는 폐기). 상태가 필요하면 임시 주입 스크립트로 상태를 만든 뒤 캡처.
  2. Task 도구로 서로 독립적인 비평가 2명을 띄운다. 각자에게 레퍼런스(docs/ref/NN-*.jpg)와 캡처본을 둘 다 Read 시키고 채점하게 한다.
     비평가에게 **레퍼런스는 1080x2340(상단 84px 상태바), 캡처는 1080x2280 이며 가로는 1:1, 세로는 «레퍼런스 y − 84 = 캡처 y» 로 비교하고 전투 캔버스 높이 24px 차이는 감점하지 말 것**이라고 반드시 알려준다.
     항목은 ①요소 배치 ②상대 크기 비율 ③여백·간격 ④정렬·그리드 ⑤색·명암 ⑥폰트 크기 비율. 각 10점이며 최저 항목 점수를 그 비평가의 점수로 삼는다.
     지적은 '몇 px 어긋남 / 몇 % 큼'처럼 수치로만. 두루뭉술한 총평 금지. 후하게 주지 말라고 명시한다.
     **통과 판정은 ①②③④(배치·상대 크기 비율·여백·정렬) 만으로 한다(2026-08-25).** ⑤ 색·명암 ⑥ 폰트는 채점해서
     기록은 남기되 **통과를 막지 않는다** — 아트·서체는 나중에 GPT 로 만들어 넣을 예정이라, 지금은 **레이아웃의
     비율·비례**가 전부다. 단 ⑤⑥ 지적 중 크기·bbox·비율에 관한 것(아이콘 박스 w×h, 글자 잉크 높이·폭, 두께)은
     ②·⑥ 비율 항목이므로 반영한다. 비평가에게 «색·아트 내용·서체 모양은 감점 사유로 쓰지 말고 크기·위치만 보라» 고 명시.
  3. 2명 중 ①~④ 최저 점수가 8 미만이면 수정 후 1번부터 반복.
  4. ①~④ 최저 8 이상이면 통과 → 문서 갱신 + 커밋. (⑤⑥ 점수는 비고에 «아트 대기: …» 로 기록)
  - **아트 자리 규칙**: 이모지·CSS 작화로 대체한 요소는 **레퍼런스 bbox(w×h·중심)를 정확히 차지**하게 만든다 —
    나중에 이미지로 교체만 하면 되게. 그리고 측정표(`docs/measure/<ID>-*.md`) 끝에 **«아트 필요» 표**(요소명 · w×h · 용도 · 현재 대체물)를
    남긴다. 이 표가 모여서 GPT 아트 발주서가 된다.
  5회 안에 8이 안 나오면 남은 문제를 PROGRESS.md 비고에 적고 lock 을 풀고 종료한다.
  - **최종 목표는 전 화면 8점이다(2026-08-25 통과 기준 9→8 하향). 다만 «한 화면 몰아치기»가 아니라 «전 화면 라운드»로 돈다.**
  - **라운드당 회차 상한(2026-08-25): 화면당 누적 10회 — 세션을 넘어 합산한다.** 시작 전에
    `docs/review/<ID>-*.md` 로 앞 세션들의 회차를 확인하고, 이미 10회를 채운 화면은 **«보류»** 처리한다
    (구현 칸에 `⏸ 보류(n회, 최고 m점)` 로 적고 남은 문제를 비고에 기록. 완료가 아니다).
  - **2차 폴리시 라운드**: 미구현 화면이 하나도 안 남으면(전부 구현 or 보류), 보류 화면을 **점수 낮은 순**으로
    다시 잡아 8점까지 올린다. 이때 회차 상한이 +10회 리셋된다. 8점 도달 화면만 완료다.
  - 두 비평가가 남은 감점을 **«아트 리소스/게임 서체 없이는 회수 불가»** 로 분류한 화면은 CSS 로 더 밀어도
    소용없으므로 **«보류(아트 대기)»** 로 적고 넘어간다 — 아트 리소스가 들어오면 일괄 재검해서 8점을 채운다.

(다) **연출 작업**(UI-REFERENCE 58번: 재화 획득·보상·강화·퀘스트 등 피드백 이펙트) → (나) 와 같이 최대 5회 루프.
  단 캡처는 정지 1장이 아니라 **연속 프레임 6~8장**(playwright 로 트리거 직후 80~100ms 간격)을 비평가 2명에게 준다.
  채점 축은 ①타이밍(길이·이징) ②크기 비율 ③위치·경로(재화는 HUD 알약에 정확히 도착) ④가독성·일관성 — 최저 8 통과.
  «연출 없음» 은 무조건 0점이다. 09·12·17 의 기존 연출 톤과 어긋나면 ④ 감점.
  - **골고루 원칙은 연출·쥬시(58·60)에도 그대로 적용된다.** 58·60 은 «공용 모듈 1회 제작 + 전역 부착» 이 작업 범위다 —
    한 화면의 연출만 파고들어 회차를 태우지 마라. 공용 모듈이 올라간 뒤로는 **각 화면 비평에 ⑦ 인터랙션 손맛(쥬시) 축을
    추가**해 8 기준으로 같이 채점하되, 화면당 회차 상한(10회)은 그대로다. 쥬시 때문에 특정 화면만 계속 잡히면 안 된다.

[4] 병렬 충돌 처리
- push 전 항상 `git pull --rebase origin main`.
- `index.html` 이 충돌하면 **양쪽 변경을 모두 살린다**(서로 다른 구간이라 대부분 자동 병합된다). 내 작업 구간이 아닌 곳은 남의 버전을 그대로 둔다.
- 병합 후 반드시 문법 검사 + **`node tools/smoke.js` 통과** 확인. 깨졌으면 고쳐서 push 한다.
- `PROGRESS.md` 가 충돌하면 **양쪽 행을 모두 살린다.**
- `docs/claims/*.lock` 이 충돌하면: **내 <ID>.lock 이 아닌 lock 파일은 절대 건드리지 않는다** — 남의 lock 은
  남의 버전 그대로 살린다(생성이든 삭제든). 내 <ID>.lock 자체의 충돌은 [-1] 4 규칙(경쟁 패배 = 포기)을 따른다.
- 비평 기록은 `docs/review/<ID>-이름.md` 에 자기 파일로만 쓴다. 공용 `docs/review-log.md` 에는 추가하지 마라.

- 이미지는 절대 메인 세션에서 직접 Read 하지 마라. 측정·채점은 Task 서브에이전트에게만 시키고 텍스트 결과만 받는다.

- 컨텍스트가 70%를 넘으면 하던 작업을 마무리 짓고 PROGRESS.md 갱신 → lock 삭제 → 커밋 → 종료한다.
