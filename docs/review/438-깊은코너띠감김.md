## 3. 진짜 결손 — **384 의 게이트가 자기 자리를 안 본다**

등재문: «자리는 384 의 소유이므로 `verify384` 에 호스트 축을 세우는 것이 처방의 절반이다.»

착수 시점의 `verify384` 는 이미 5호스트를 다 돌고 있었다(409 4회차 이관). 그래서 «호스트» 는 구멍이 아니었다.
구멍은 **깊이(각도)** 였다. 수리 전 트리에 `verify384` 를 직접 돌려 못박았다:

```
V384_SRC=.v438-pre.html node tools/verify384.js   →  VERIFY384 95/96  FAIL 1
  PASS [2]  03 던전«던전» 좌 rel 68 — D 4px
  PASS [2]  03 던전«던전» 좌 rel 74 — D 5px
  PASS [2b] …  PASS [5] …  PASS [3] …  PASS [4] …
  FAIL 어느 쪽이든 «가로 인셋 + 반경 = 30»          ← 유일한 빨강 = 409 가 넣은 **선언** 항
```

**찍힌 픽셀 항은 한 개도 안 빨개졌다.** 이 파일 서두가 스스로 적어 둔
«⚑ 찍힌 픽셀로 본다(350 처방) — 선언만 물면 «의사요소는 있는데 안 보인다» 를 놓친다» 의
바로 그 함정에 자기가 빠져 있었다.

### 3-1. 왜 못 보나 — 기하 (`tools/probe438.js` 신설)

알약 반경 30 · 높이 85 ⇒ 좌하 코너 원 중심은 rel 55, 법선 각 α 의 바깥 점은 `rel = 55 + 30·sin α`:

| α | 30° | 45° | 60° | 75° |
|---|---|---|---|---|
| rel | 70.0 | 76.2 | 81.0 | **84.0** |

`verify384` 의 `ROWS` 는 **rel 68 · 74** 뿐이다 — **45° 언저리에서 멈춘다.**
행을 더 내려도 안 된다는 것을 `probe438` 이 값으로 못박았다(03 던전 좌):

| rel | 수리 후 | 수리 전 | 갈리나 |
|---|---|---|---|
| 68 | D 8px | D 4px | ○ |
| 74 | D 10px | D 5px | ○ |
| **76** | D 6px | D 5px | **× (1px)** |
| 78 | `R13 K16` D 0 | `R13 K16` D 0 | **× (행이 호 밖)** |
| 80·82·84 | D 0 | D 0 | **×** |

rel 78 부터 가로 행은 호 바깥으로 나가 **알약을 아예 안 지난다**.
⇒ **이 자리는 행이 아니라 법선(각도)으로만 물 수 있다.**

## 6. 교훈

1. **«호스트 축이 없다» 와 «깊이 축이 없다» 는 다른 말이다.** 438 등재문은 전자로 적혀 있었고
   착수 시점엔 이미 5호스트가 다 돌고 있었다 — 그대로 «이미 됐다» 로 닫았으면 진짜 구멍은 남았다.
   **등재문의 낱말이 아니라 등재문이 가리킨 픽셀을 재라.**
2. **코너를 가로 행으로 재는 자는 45° 에서 눈이 먼다.** `rel = cy + r·sin α` 라 행을 아무리 내려도
   60° 위는 못 가고(호 밖) 그 전은 1px 로 뭉갠다. 코너의 성질은 **법선**으로만 물어진다.
3. **«한 호스트만 이상하다» 는 대개 «한 호스트에서만 판독이 색을 바꿨다» 다.** 던전 BL 만 `B` 로 읽힌 것은
   거기만 정확히 0 이었기 때문이고, 결손 자체는 4면이 똑같이 얇았다.
4. **0항으로 증발하는 축에는 «몇 면을 쟀나» 를 같이 걸어라.** 조건부(r23)로 도는 축은 조건이 사라지면
   빨개지지 않고 **사라진다** — 수리 전 트리가 정확히 그 모양이었다(0면).
