## 2. 원인 — «가운데 정렬» 이 **걸려 있지도 않았다**

```
.rw-c>i{position:absolute;inset:0;display:flex;align-items:center;justify-content:center;
  font-size:126px;line-height:1}
```

* 이모지 advance = 126px × 1.248 = **157.2px**
* 상자 안폭 = 슬롯 151 − 테두리 4×2 = **143px**

**여백이 −14.2px 이다.** 그런데 `justify-content:center` 도 `text-align:center` 도 «남는 여백을
나눠 주는» 규칙이라 여백이 음수면 할 일이 없어 **start 로 떨어진다.** 그래서 advance 좌변이 상자
좌변에 물리고 초과분 14.2 가 **전부 오른쪽으로만** 흘러 정확히 절반인 +7.11 이 나온다.

세로도 같은 계열이다 — `align-items:center` + `line-height:1` 은 «126px 줄상자» 를 143 안에
넣을 뿐이라 폰트 ascent/descent 비대칭이 그대로 남아 advance 중심이 8.5px 위였다.

**등재문이 후보로 적어 둔 셋은 전부 아니었다**(반증해 두니 다음에 같은 자리를 다시 파지 않는다):
`RW_POS` 슬롯 좌표는 행 중심 539 로 정상 · 슬롯 `border`/`box-sizing` 은 자식 절대좌표를 안 민다
(`Δibox` 가 10칸 전부 **0.00** — 상자 자체는 처음부터 정확히 가운데였다) · `--rws` 스케일도 무관
(1600·1920·2280·2600 네 화면비 전부 같은 +7.11).

### ★ 이 회차에서 두 번 틀렸고, 둘 다 «자를 잘못 대서» 였다

**ⓐ 처방을 «정렬 속성 추가» 로 잡은 것 — 두 번 헛짚었다.**
`text-align:center` 를 넣어도 Δ는 **+7.11 그대로**였고, `display:block` + `line-height:143px`
로 바꿔도 가로는 **여전히 +7.11**(세로만 −0.50 으로 닫혔다). 속성이 문제가 아니라 **여백의 부호**가
문제였기 때문이다. 정답은 정렬 속성이 아니라 **상자를 글리프보다 넓히는 것**이었다.

**ⓑ 음성항을 «CSS 주입» 으로 짰다가 게이트가 스스로 거짓말을 했다.**
옛 규칙을 `document.head` 에 얹어 재니 **Δx 0.00 · Δy 0.00** 이 나와 «옛 CSS 도 멀쩡» 이라는 결론이
나올 뻔했다. 같은 CSS 를 index.html 에 넣고 **새로 열면 +7.11** 이다(A/B 로 확인). 레이아웃이 끝난 뒤
넣은 규칙은 익명 flex 항목의 정렬을 다시 풀지 않아 **새로 연 문서와 다른 배치**가 된다.
→ 게이트의 음성항은 **옛 규칙으로 갈아 끼운 사본(`.v191-neg.html`)을 새로 열어서** 잰다
(59·74·58 게이트 선례. 사본은 `assets/*` 가 상대 경로라 **저장소 루트**여야 하고, 게이트가 끝나면 지운다).
LESSONS «마스크가 다르면 다른 것을 잰다» 의 변주 — **«언제 재느냐» 도 자의 일부다.**

## 3. 고친 것 — 한 규칙, 세 줄

```
.rw-c>i{position:absolute;left:-40px;right:-40px;top:0;bottom:0;pointer-events:none;
  display:block;text-align:center;font-size:126px;line-height:143px}
```

| 바꾼 값 | 왜 |
|---|---|
| `inset:0` → 좌우 **−40px** | 상자 223 > advance 157.2 로 여백을 **+65.8** 로 만들어야 `text-align:center` 가 비로소 걸린다. −40 은 `.rw-c>u`(Lv 라벨)가 이미 쓰는 폭이라 새 상수가 아니다. padding box 기준 **좌우 대칭** 확장이라 중심은 슬롯 중심 그대로. |
| flex → `display:block` + `text-align:center` | 여백이 양수가 된 뒤로는 줄상자 정렬로 충분하다. |
| `line-height:1` → **143px** | 반줄간격을 상자 높이에 맞춰 세로 비대칭을 없앤다(Δy −8.50 → **−0.50**). |
| `pointer-events:none` 신설 | 상자를 넓혔으니 **클릭 판정까지 넓어지면 안 된다.** 부모 `.rw-c` 가 그대로 받는다(게이트 E1·E2 가 양·음 양쪽으로 확인). |

**font-size 126px 는 안 건드렸다** — 측정표 §「유물 아이콘 ×10」이 «~130×130» 을 못 박는다.
슬롯 151×151 · 행 피치 176 · `RW_POS` 도 한 줄도 안 바뀌었다(게이트 F1·verify100 이 지킨다).

### 픽셀 잉크로도 확인 (`tools/cap191.js` + `tools/scan191.py`)

DOM 이 아니라 **캡처 화소**로 잉크 중심을 다시 쟀다(자를 두 개 대라 — LESSONS).

| | 평균 Δink | 부호가 +인 칸 |
|---|---|---|
| 수정 전 `191-r1.png` | **+3.55px** | **9/10** |
| 수정 후 `191-r2.png` | **−0.75px** | 1/10 |

DOM(+7.11)과 잉크(+3.55)의 값이 다른 것은 **이모지마다 잉크가 advance 안에서 제각각**이기
때문이고, 부호가 10칸 중 9칸 같다는 점이 «일괄 밀림» 의 화소 증거다.
수정 후에는 8칸이 **±0.5px 안**이고, 남은 두 칸은 아래 «아트» 항목이다.

**곁가지 관찰**: 수정 전 캡처에서 잉크 폭이 슬롯 안쪽 창에 **잘려 있었다**(rl2 131 → 137 로 회복).
+7px 밀린 상태에서 폭 137 짜리 잉크는 오른쪽 안쪽 테두리를 ~4px 넘어간다 — 주인 눈에 «밀렸다» 가
확실히 보인 이유다.
