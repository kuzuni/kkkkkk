## 설계 — «화면별로 만들지 않는다»

지시(UI-REFERENCE 60)의 핵심은 **한 번 만들어 전역 부착**이다. 그래서 호출부를 한 곳도 고치지 않고
«모든 경로가 지나는 한 지점»에 붙였다(46 교훈 3 의 입력 판, 58 `fxWatch` 의 자매품).

|---|---|

## 이번 작업에서 잡은 함정 — `transform` 을 쓰면 안 된다

이 저장소는 글자 폭 보정(LESSONS 05 «폰트»)에 `transform:scaleX()` 를 **대량으로** 쓰고,
모달 중앙 정렬에도 `translate(-50%,-50%)` 를 쓴다. 쥬시 애니메이션이 `transform` 을 덮으면
그 보정이 **화면 전체에서 통째로 날아간다**(글자 폭이 12~27% 튀고 모달이 우하단으로 밀린다).
→ 60 은 **독립 변형 속성 `scale:` / `translate:` 만** 쓴다. 이 둘은 `transform` 과 합성되므로
(적용 순서 translate → rotate → scale → transform) 기존 값이 살아 있다.

### 2회차 (2026-08-25, sess-0058-25815, 워커 D) — 자가 반증으로 버그 3개

비평가에게 보내기 전에 **기하 검증 스크립트**(`docs/review/60-verify60.js`)를 먼저 만들어 돌렸다.
«이미지를 눈대중하기 전에 값으로 반증한다»(LESSONS 04-① · 05-③)를 연출 작업에 적용한 것이다.
Web Animations 를 `pause()` 하고 `currentTime` 을 직접 세워 **정확한 t(ms) 의 렌더 값**을 읽는다 —
헤드리스 스크린샷 간격(40~90ms)으로는 60~250ms 애니메이션을 못 따라간다.

1회차 코드에서 **버그 3개**가 나왔다(전부 캡처만 봤으면 «좀 약하네» 로 지나갔을 것들):

1. **`cursor` 는 상속된다 — 안쪽부터 찾으면 버튼이 아니라 글리프가 잡힌다.**
   `.tab` 을 눌렀는데 `.jz-dn` 이 그 안의 `<span class="ti">`(이모지 하나)에 붙어서
   **아이콘만 쪼그라들고 버튼은 가만히 있었다.** `getComputedStyle(el).cursor === 'pointer'` 로
   대상을 찾을 때 «가장 안쪽» 을 잡으면 항상 이렇게 된다 — `cursor` 는 자식에게 내려가기 때문이다.
   → «연속으로 pointer 인 조상 중 **가장 바깥**» 이 `cursor:pointer` 를 실제로 선언한 요소 = 버튼 본체다.
   검증: 누름 t60 `.tab` scale 이 **1** 로 나왔다(기대 .94).

2. **열기 애니메이션이 실패 흔들림을 특이도로 이겨서 통째로 삼켰다.**
   `.jz-o.jz-dlg>*`(0-2-0) 가 `.jz-bad`(0-1-0) 를 이겨 «재화 부족» 팝업이 **안 흔들렸다.**
   `.cDia` 알약(오버레이 자식이 아님)은 멀쩡히 빨개져서 «반은 되는» 상태라 더 안 보였다.
   → `.jz-bad` 의 `animation` 에 `!important`. **같은 요소에 두 애니메이션을 «상태별로» 걸 때는
   항상 특이도를 확인할 것** — 15 교훈(«폴백이 안 걸려 틴트가 통째로 죽는다»)의 애니메이션 판이다.

3. (검증 스크립트 자체의 오독 2건) `translate` 의 computed 값은 **퍼센트를 px 로 안 바꾼다**(`0px 100%`).
   `parseFloat` 하면 `100` 이 나와 «2100 이어야 하는데 100 이다» 라는 오진이 된다.
   그리고 seek 를 되돌리지 않고 다음 항목을 재면 앞 항목의 t 가 그대로 남는다.
   → **LESSONS 43-① «내가 쓴 assert 도 기준을 먼저 의심하라» 가 또 재현됐다.**

#### 코드 버그 (고침)

1. **바닥 시트 오버슈트가 8px 이 아니라 212px 이었다.** ⚑ 가장 큰 감점 원인.
   `translate:0 100% → -8px` 구간 **전체**에 오버슈트 베지어 `cubic-bezier(.34,1.56,.64,1)` 를 걸었는데,
   이동거리가 시트 높이(≈2100px)라 **베지어 최대치 1.098 × 2100 = 205px** 가 그대로 물리 오버슈트가 됐다.
   t=100ms 프레임에서 화면 바닥에 212px 짜리 구멍이 뚫려 배경·스킬슬롯·탭바가 드러났다.
   → **구간별 이징**(`@keyframes` 안 `animation-timing-function`)으로 나눠 이동 구간은 비오버슈트,
   8px 바운스는 마지막 26% 구간에만. 실측 **-8.0px**.
   **교훈: 오버슈트 이징은 «이동거리에 비례해 커진다». 긴 이동에 그대로 걸면 안 된다.**
2. **`!important` 로 흔들림을 살렸더니 이번엔 열기 팝이 죽었다**(1회차의 정확한 반대 사고).
   «부족» 팝업만 박스 폭이 882±1px 로 고정 — 정상 팝업은 860→886→860 인데 혼자 뚝 떴다.
   → `!important` 를 빼고 **특이도 0-3-0(`.jz-o.jz-dlg>.jz-bad`)으로 이기면서 세 애니메이션을 함께 선언**.
   **교훈: `!important` 로 특이도 싸움을 이기면 «진 쪽» 이 통째로 사라진다. 둘 다 살려야 하면 같이 선언해라.**
3. **재화 알약의 «부족» 틴트가 사실상 안 보였다.** 알약은 `#top`(z6) 안이고 딤은 z30 이라
   알약 영역 평균휘도가 **20~27/255(8~10%)** — 색만 바뀌고 «번쩍» 이 없었다.
   → 58 과 같은 방식으로 **`#fxl`(z60) 위에 같은 bbox 의 빨간 오버레이**(`.jz-badov`)를 겹쳐 그린다.

#### 캡처 절차 오염 (그 회차 비평을 통째로 무효화한 것 — LESSONS 04-①의 재현)

4. **`pause()` 한 애니메이션은 영원히 멈춰 있다.** 장면을 넘어가도 살아 있어서 다음 장면의 `GRAB` 에
   같이 잡히고, `SEEK` 하면 **앞 장면 연출이 같이 재생된다.** 그래서 탭 장면에서 누름 스프링(1.04)이
   되살아나 «탭 아이콘 팝이 1.12 가 아니라 1.04» 로 읽혔다 — **코드는 멀쩡했다**(verify60 은 계속 1.120 PASS).
   → 장면 사이에 `finish()`/`cancel()` + 클래스 제거(`CLEAR`).
5. **누름 장면의 «제자리에서 떼기» 가 클릭이 되어 영웅 패널을 열어 뒀다.** 그 뒤 모든 장면이
   패널 위에 겹쳐 찍혔고, 던전 그리드는 장비 시트 아래로 열려 **카드가 1장만 보였다**
   → «stagger 25ms 를 확인할 수 있는 프레임 0개». → 누른 뒤 **프레임 구석으로 옮겨서** 뗀다(LESSONS 42-③),
   그리고 장면마다 `RESET`(전 오버레이·패널 닫기)을 먼저 돈다.
6. **흔들림 극점을 비껴 샘플링했다.** `.34s` 흔들림의 극점은 54/112/170/224/282ms 인데
   0/40/80/130/180/240/320/420ms 로 떠서 «스윙 4.5px»(실제 12px)로 읽혔다.
   → 캡처 t 를 **애니메이션의 키프레임 시각에 맞춰** 다시 잡았다.
