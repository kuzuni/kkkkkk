⇒ **등재문이 «세 경로» 로 센 이유는 `probe464` 가 오프너를 셋만 굴렸기 때문**이다. `sk8` 을 켜는 세 자리
(`showSkillDetail`·`showItem`·`showCosDetail`)는 목록이 «비대칭» 인 게 아니라 **아예 없다** —
`classList.add('on','sk8')` 한 줄이 전부라 남의 껍데기를 하나도 안 뗀다. 그래서 우편·퀘스트·출석에서
08 세부로 갈아타는 여섯 경로가 통째로 겹친다.

⇒ **[4-b] 640px 가 «잠복이지만 고칠 값어치» 의 근거다.** 겹쳤을 때 어느 치수가 이길지는 «나중에 붙인 쪽»
이 아니라 **CSS 선언 순서**가 정한다 — 22 퀘스트 → 08 유물 세부에서는 **먼저 붙은 `q22` 가 이겨**
08 세부가 퀘스트 크기(본문 739 → **1379**)로 열리고, 우편 → 출석처럼 Δ0 인 쌍도 있다.
즉 겹침의 값은 **쌍마다 다르고 예측이 안 된다**. 지금 밟을 수 없는 이유는 딤 하나뿐이고,
그 딤은 이 결함과 아무 상관이 없는 부품이다.

⚠ **재현 1회차 함정 — 기준선이 «닫힘 연출 한복판» 이었다.** `closeModal()` 뒤 90ms 에 다음 화면을 열면
345 `jzShellBack()` 이 연출을 위해 **되살려 둔** 껍데기가 그대로 남는다(`done()` 은 «연 쪽» 의 것이라
안 뗀다). 그래서 «하나만 열었는데 껍데기가 둘» 이라는 **거짓 표본**이 [3] 에 6곳 중 4곳으로 찍혔다.
⇒ 기준선의 대기를 **320ms**(연출 0.12s + 여유)로 올렸고, 그 함정 자체는 버리지 않고
**[2-c] «닫는 중 전환» 축**으로 세웠다 — 그쪽이 오히려 사람이 밟기 더 쉬운 경로다.

## 3. 처방 — ⓐ (상수 하나) · 제품 8자리

```js
const MODAL_SHELLS = ['sk8', 'q22', 'ml69', 'at70'];
function modalShell(cls){
  const m = $('modal');
  m.classList.remove(...MODAL_SHELLS);      /* 남의 껍데기는 예외 없이 전부 뗀다 */
  if(cls) m.classList.add(cls);
  return m;                                  /* 호출부가 이어서 'on' 을 켠다 */
}
```

| 자리 | 수리 전 | 수리 후 |
|---|---|---|
| `closeModal()` | `remove('on','sk8','q22','ml69','at70')` | `remove('on')` + `modalShell(null)` |
| `showModal()` | `remove('sk8','q22','ml69','at70')` | `modalShell(null)` |
| `openAttend()` | `remove('sk8','q22')` + `add('at70','on')` | `modalShell('at70')` + `add('on')` |
| `openMail()` | `remove('sk8','q22')` + `add('ml69','on')` | `modalShell('ml69')` + `add('on')` |
| `openQuest()` | `remove('sk8','ml69')` + `add('q22','on')` | `modalShell('q22')` + `add('on')` |
| `showSkillDetail()`·`showItem()`·`showCosDetail()` | `add('on','sk8')` — **아무것도 안 뗌** | `modalShell('sk8').classList.add('on')` |

**ⓑ(제품에게 물어 뗀다)를 안 고른 이유**: `jzShellBack()` 의 축(«그 클래스만 붙였을 때 `display:none` 인가»)은
껍데기를 **찾아내는** 데는 맞지만 이 자리에서는 오프너마다 **전 클래스를 순회하며 computed style 을 두 번씩**
읽어야 한다 — 열 때마다 강제 리플로우가 껍데기 수만큼 붙는다. 여기서 필요한 것은 판별이 아니라 **목록 한 벌**이고,
목록이 낡을 자리를 없애는 데는 선언 한 줄이면 충분하다. 새 껍데기를 만드는 세션은 배열에 한 칸을 더하면 된다.
