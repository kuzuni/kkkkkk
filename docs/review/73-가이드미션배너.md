## 1. 무엇이 문제였나

`#tuto` 배너는 `[보상받기]`(`#tutoBtn`) 한 곳만 클릭을 받았고, **미완이면 `disabled` 라 눌러도 아무 일도 없었다.**
그래서 “스킬 1회 소환하기” 를 보고도 어디로 가야 하는지 알 수 없었다. 여기에 주인 지시 3개가 더 붙었다.

| # | 지시 | 처리 |
|---|---|---|
| ① | 미완 미션 클릭 → 해당 콘텐츠로 이동 | 미션마다 `go()` — 20개 전수 |
| ② | 직전 미션 보상 = 다음 소환 미션의 10연 1회 | `dia` 를 **함수**로 허용 → `() => summonCost(b,10)` |
| ③ | 소환 미션 중 다른 배너 소환 차단 | `ban` + `gmBlocked()` — **무료 횟수 차감 전**에 막는다 |
| ④ | 소환 가격 통일 10회 1,000 / 30회 3,000 | `cost:100` + `flat:1`(10연 할인 제외) |

## 2. ④ 가격 통일 — «할인 플래그» 로 풀었다

지시서는 «`cost=100` 으로 맞추고 10연 할인(0.9)을 없애거나 `summonCost` 를 n×100 으로 단순화» 라고 했지만,
같은 문단이 **«펫·유물 가격은 현행 유지»** 다. 0.9 를 전역으로 빼거나 n×100 으로 단순화하면
**펫 10연 2,250 → 2,500 · 유물 10연 3,600 → 4,000 으로 같이 움직인다.** 그래서 배너별 플래그로 갈랐다.

```js
skill/weapon/shield/amulet : { cost:100, flat:1 }   // 10회 1,000 · 30회 3,000 (30 = 10×3)
pet   : cost 250            // 10연 2,250 · 30연 6,750  (불변)
relic : cost 400 (유물석)    // 10연 3,600 · 30연 10,800 (불변)
summonCost = round(cost × n × ((n>=10 && !flat) ? 0.9 : 1))
```

표시처 3곳은 전부 같은 함수를 지나므로 함수만 고치면 됐고, **하드코딩된 «1,000/3,000» 문자열은 없었다.**
다만 **10 상점 카드만 표기가 `fmt()` 라 «1.00K» 로 나왔다.** 측정표 `10-상점팝업소환탭.md` §21·§26 의
레퍼런스 실측이 `1,000` / `3,000` 쉼표 표기이므로, 12 결과 팝업이 이미 쓰던 쉼표 표기(`won()`)로 맞췄다
— **레퍼런스에 더 가까워지는 방향이고 글자 수도 5자로 같다**(버튼 기하 불변).

부수 효과: 1회 소환 값이 스킬 150 → 100 · 무기류 160 → 100 이 된다. 같은 `cost` 를 쓰므로 불가피하고,
지시(10/30회 통일)와 모순되지 않는다.

## 3. ② 보상 체인 — 하드코딩 대신 계산

소환 미션은 0(스킬)·2(무기)·5(방어구) 세 개다. 그 **직전** 미션의 보상을 10연 값으로 못박았다.

| i | 미션 | 보상 | 근거 |
|---|---|---|---|
| — | (게임 시작) | `DEF().dia` **300 → 1,000** | i0 «스킬 1회 소환» 이 첫 미션이라 앞 미션이 없다 |
| 1 | 스킬 장착하기 | `() => summonCost('weapon',10)` = **1,000** | 다음 i2 = 무기 소환 |
| 4 | 훈련 10회 하기 | `() => summonCost('shield',10)` = **1,000** | 다음 i5 = 방어구 소환 |

하드코딩하지 않았으므로 ④ 가격을 나중에 또 바꿔도 체인이 저절로 따라온다.
나머지 미션 보상은 지시대로 **현행 유지**(300~3,000). 그 결과 i1·i4 가 뒤 미션들보다 높은
«계단 역전» 이 생기지만, «나머지 보상은 현행 유지» 가 명시 지시라 그대로 뒀다.

`m.dia` 가 함수일 수 있으므로 읽는 곳을 **`gmDia(m)` 한 군데로 모았다**(배너 수량·수령 지급·완주 모달·52 메뉴 «길라잡이» 팝업 4곳).

## 4. ⑤ 담당 결정 — 5번 미션은 «동료 소환» 이 아니라 «방어구 소환»

지시서 73 ①은 «펫 상자를 `SHOP_BOXES` 에 추가하거나 미션을 «방어구 1회 소환» 으로 바꿀 것,
담당이 결정해 기록» 이었다. **후자를 택했다.**

- 상점(10)의 레퍼런스는 **상자 3칸**(무기·방어구·스킬)이다. 펫 카드를 넣으면 **다른 작업 단위의
  비평 점수(7/10)를 가진 화면의 카드 목록**을 건드리게 된다.
- 방어구(`shield`) 상자는 **이미 `SHOP_BOXES` 에 있다.** ①의 «누르면 그 화면으로» 가 그대로 실동작하고,
  화면 기하는 한 픽셀도 안 바뀐다.
- 미션 **순서·개수는 그대로**(20개) 두고 5번의 이름·`get`·`ban` 만 바꿨다 → `S.guide.idx` 세이브 호환 유지.

> **남은 문제(73 범위 밖, 다음 담당에게)** — 이 결정으로 **펫 소환 경로는 여전히 막다른 길**이다.
> 26 동료 시트의 `[동료 소환]`(`data-ptsum`)은 작업 27 대로 `goTab('shop')` 으로 가는데
> **상점에 펫 카드가 없다.** 현재 펫을 얻는 유일한 경로는 룰렛 «펫 소환권» 보상뿐이다.
> 10 상점에 «동료 상자» 를 넣든 26 에서 직접 소환하든, **그 화면 담당이 정해야 한다.**

## 6. ③ 소환 차단 — «차감 전» 이 전부다

```js
gmBan()      // 현재 미션이 소환 미션이고 «아직 목표 미달» 이면 그 상자 키, 아니면 null
gmBlocked(b) // relic 은 항상 통과 · ban 과 다르면 안내 팝업 + true
```

호출 지점 4곳 — **무료 횟수(`S.daily.freeSum`) 차감은 «호출부» 가 먼저 하므로 거기에도 넣어야 한다.**

1. `doSummon(b, times)` 진입부 (유료 · 12 결과 팝업 재소환 `#sumB10`/`#sumB30` 포함)
2. `doSummonFree(b, times, viaReward)` 진입부
3. `#shopList [data-shfree]` 핸들러 — `S.daily.freeSum[b] = freeLeft(b) - 1` **바로 위**
4. `#sumBF`(12 결과 팝업 무료 10연) — 같은 위치

`viaReward` 예외가 필요했다: 룰렛 보상 «펫 소환권» 은 `doSummonFree('pet', n)` 으로 들어오는데,
가이드가 `skill` 을 강제하는 중이면 **이미 소모한 룰렛 보상이 통째로 증발한다.** 보상 지급 경로만
`doSummonFree('pet', n, 1)` 로 통과시킨다.

## 8. 이번에 발견한 것 (LESSONS 로 승격)

1. **`localStorage.clear()` + `reload()` 로는 게임 상태가 초기화되지 않는다.** 지우는 순간에도
   **옛 페이지가 살아 있어 자동 `save()` 가 곧바로 다시 쓴다.** verify73 §5 가 이것 때문에
   «장비 장착»·«유물 장착» 미션을 **이미 완료 상태**로 잡아 3항목이 계속 실패했다(코드는 멀쩡했다).
   → 검증에서는 **메모리 상태를 `Object.assign(S, DEF())` 로 직접 되돌린다.** 리로드보다 빠르고 확실하다.
2. **새 세이브에서도 이미 완료인 미션이 있다.** i1 «스킬 장착하기» 는 시작 시 스타터 스킬이 자동 장착돼
   `S.eqSkill.length === 1` 이라 **첫 화면부터 `[보상받기]`** 다(61 설계, 73 범위 밖). 검증에서
   «미완 상태의 이동» 을 보려면 그 미션은 상태를 **직접 비워** 놓아야 한다.
3. **«이동» 기능은 «닫기» 를 빠뜨리면 다음 미션에서 터진다.** 목적지를 여는 코드는 다 맞았는데
   `gmCloseAll()` 이 21 도감(`#collw`)·공용 모달을 안 걷어서, 그 뒤 «메인 복귀» 미션 2개가 실패했다.
   → **새 오버레이를 만든 작업은 «전역 닫기» 목록(여기서는 `gmCloseAll`, smoke 의 오프너 목록)에
   자기 id 를 넣는 것까지가 범위다.**

## 9. 캡처 검수 — 겹침·잘림 (서브에이전트 픽셀 확인, 최대 14배 크롭)

세 캡처를 전수 확인했다. **73 구간에서 생긴 결함은 0건**이고, 나온 지적은 전부 다른 작업 단위의 기존 상태다.

| 지적 | 판정 | 근거 |
|---|---|---|
| 배너 라벨 `[미션-1]` 의 `1` 과 `]` 가 겹쳐 읽기 어렵다 | **32 구간(기존)** | `#tuto.todo .tbtn u{transform:scaleX(.5);margin:0 -3.5px}` — 32 가 «레퍼런스 서체의 `1` 은 `0` 의 절반 폭» 을 맞추려고 넣은 값이다. 73 은 이 CSS 를 건드리지 않았다(32 는 🔧 픽셀 마감 대기 중) |
| 상점 가격 인셋에서 💎 가 첫 자리 숫자를 덮는다(3카드 6버튼 전부) | **10 구간(기존) · 73 이 오히려 2px 완화** | 실측: 인셋 561..699, 💎 575..620. 옛 표기 `1.44K` = 폭 58 @601 → 겹침 **19px**, 새 표기 `1,000` = 폭 54.1 @603 → 겹침 **17px**. 표기 교체가 원인이 아니고 값이 좁아져 조금 나아졌다 |
| 배너 우측 라운드 모서리가 화면 밖으로 잘린다 | **02/61 구간(기존·의도)** | `#tuto{right:0}` — 레퍼런스도 우측 변에 붙어 있다 |
| 상점 진입 시 상단 HUD 전투력 숫자가 절반 잘린다 | **10 구간(기존)** | `#shopw` 가 HUD~탭바를 덮는 전체화면 페이지라 그렇다(41 팝업 내장 재화 바와 별개) |
| 하단 탭 라벨-아이콘 겹침 · 닫기 버튼 위 NEW 리본 | **A1 구간(기존)** | A1 비고 1·2 «이모지·서체 한계» 로 이미 기록된 감점 |

73 이 만든 세 화면 요소는 전부 정상이었다 — 배너 문구 `[미션-1] / 스킬 1회 소환하기 / (0/1) / 💎300`,
상점 카드 3장 `1,000` · `3,000`(30회는 보유 다이아 부족이라 빨강 = 정상), 안내 팝업
«가이드 진행 / 원활한 가이드 진행을 위해 **스킬 소환**을 먼저 해주세요!» 모두 상자 안에 들어가고 잘림 0건.
