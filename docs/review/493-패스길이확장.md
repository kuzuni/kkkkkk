## 3. ⚑ 가상화를 **안 넣었다** — 후보 둘이 «찍힌 픽셀» 로 기각됐다

등재문 ⑤ 의 처방(«현재 단계 ±30행 창» 가상화)은 이번 회차에 **안 골랐다.** 이유는 취향이 아니라 측정이다.

### ⓐ `content-visibility:auto` — 층이 무너진다 (기각)

DOM 을 한 칸도 안 버리고 오프스크린 렌더만 건너뛰는 한 줄짜리 처방이라 먼저 쟀다.
속도는 **317ms → 70.9ms** 로 좋았고 DOM·rect 도 그대로였다(`probe493b` [3]). 그런데 **그림이 바뀐다** —
`probe493c` 가 탭 3 × 스크롤 3 자리에서 **다른 픽셀 37,576~71,872개**(A/A 잡음 0)를 찍었다.

뿌리는 **스태킹 컨텍스트**다. `content-visibility` 는 `contain: layout style paint` 를 같이 걸어
`.ps-r` 을 스태킹 컨텍스트로 만드는데, 이 화면은 **행 경계를 넘나드는 z 층 넷**으로 그려져 있다:

```
.ps-spine    z2   (트랙 직속)
.ps-eg       z3   (트랙 직속 — 좌우 가장자리 하이라이트)
.ps-tk::before z4 (헤더 그림자 띠)
.ps-hex      z5   ← **행의 자식**인데 위 셋보다 위에 그려져야 한다
```

행이 스태킹 컨텍스트가 되는 순간 `.ps-hex` 의 z5 가 **행 안에 갇혀** 스파인(z2) 아래로 내려간다.
`probe493d` 의 표본이 그것을 색으로 말한다 — (526,777) 이 육각 금색 `253,211,26` → 스파인 초록
`160,243,45` 로 바뀐다.

### ⓑ 껍데기 하나(`.ps-cv`)로 컬럼·칸만 담고 육각은 행 직속으로 남기기 (기각)

ⓐ 의 뿌리가 «육각 하나» 라면 그것만 껍데기 밖에 두면 될 것 같았다(`probe493h`). 결과는 둘 다 아니다 —
**속도 −7%**(교차 12회 중앙값 300.9 → 322.3ms)이고 **픽셀은 여전히 22,363~60,431개** 다르다.
행 안에 껍데기를 세워도 CV 가 **보이는 행까지** 건너뛰는 자리가 남는다.

### ⓒ 아이콘 `loading="lazy" decoding="async"` (기각 — 4%)

칸마다 `<img class="cic">` 가 하나씩 1,800개라 이것이 본체인가 물었다. 교차 12회 중앙값
**310.9 → 297.8ms (4%)**. 같은 SVG 한 장이라 이미 캐시돼 있어 로딩이 비용이 아니다.

⇒ **남은 정답은 «DOM 을 실제로 줄이는» 창 가상화 하나**인데, 그건 `verify301`(레드닷 칸 수)·
`verify428`(해금 육각 수)처럼 **DOM 을 전수로 세는 게이트 여럿을 같이 이관**해야 하는 별개의 작업이다.
이번 작업 단위(길이 확장)에 얹으면 «남의 구간» 이 되므로 **526 로 등재**하고 여기서는
