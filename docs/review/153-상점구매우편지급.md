# 153 — 상점 구매품은 전부 우편함으로 지급 · 상점발 우편은 보관 기간 무한

> 저장소 주인 지시(2026-08-27): **«상점에서 구매한 것들은 전부 우편함으로 지급, 상점 구매분은 우편함 기간 무한».**
> 워커 C · sess-2345-23236 · T2 기능(주인 지시 설계 변경) · 1~2회차 · 지시서 [3]-**(가)** 계열

## 1. 무엇이 문제였나

상점의 지급 경로가 **네 곳에 흩어져 각자 재화를 직접 더하고** 있었다.

| 경로 | 위치 | 옛 동작 |
|---|---|---|
| 다이아 상품 5종 | `grantDiaPack()` | `S.dia += p.dia` · `S.mileage += p.cp` |
| 마일리지 교환 | `mileageExchange()` | `S.dia += MILE_DIA` |
| 유물조각 교환 | `[data-ex]` 핸들러 | `S.relic += ex.rel` |
| 이용권(151) 부가 지급 | `grantPass()` · `passDailyTick()` | `S.dia += p.once` · `S.mileage += p.cp` · `S.dia += n * p.daily` |

주인이 원한 것은 «구매 → 우편함 → 수령» 한 흐름이다.

## 2. 어떻게 고쳤나 — `sendMail()` 한 곳으로 모았다

- **동적 우편** 신설: `S.mailx[]`(세이브에 들어간다) + `S.mailSeq`(id 카운터).
  고정 우편 `MAILS`(5통, 상수)는 그대로 두고 **`allMails() = MAILS.concat(S.mailx)`** 로 합친다.
  목록·수령·삭제·연출·레드닷이 전부 이 한 함수를 지나므로 두 출처가 같은 규칙으로 돈다.
- `sendMail({t,b,g,c,r,m})` — 보상 키는 `MAIL_RW` 와 같다. **id 는 `x<seq>`** 라 `m1~m5` 와 절대 안 겹친다.
  우편함을 **열어 둔 채** 사면 그 자리에서 목록이 늘어난다(`fxStillOpen('ml69')` → `openMail()`).
- `MAIL_RW` 에 **마일리지 쿠폰(`m`)** 키를 추가했다(프레임 색 `SUM_CARD[4]` 금색, 썸네일은 125 `curIc('mile')`).
  기존 3키(골드·다이아·유물조각)는 그대로다.
- `claimMail` / `claimAllMail` 이 쿠폰까지 지급하고, **모든 수량을 `|| 0` 으로 받는다**
  (동적 우편은 키가 빠져 있을 수 있어 `undefined` 를 더하면 NaN 이 된다).

### «기간 무한» 은 왜 코드 한 줄도 안 늘었나

우리 우편엔 **애초에 만료가 없다**(69 «기한 없음», 행 라벨도 그 글자다). 우편이 사라지는 유일한 경로는
[읽음 전체 삭제]이고 그것은 `S.mail[id] === 1`(**수령 완료**)만 고른다 — 미수령(0)은 구조적으로 안 지워진다.
그래서 «무한 보관» 은 새 플래그가 아니라 **기존 불변식이 상점 우편에도 그대로 적용되는지**를
게이트로 못 박는 문제였다(VERIFY153 [C]).

다만 동적 우편은 **삭제 시 세이브에서 빼야 한다** — 안 그러면 `S.mailx` 가 구매 횟수만큼 무한히 자란다.
`delReadMail()` 이 상태 2 로 넘긴 뒤 `x*` 항목만 배열과 `S.mail` 에서 제거한다(고정 우편은 상태만 남긴다).

## 3. 스코프 판단 — 무엇을 우편으로 보내고 무엇을 안 보냈나

| 대상 | 처리 | 근거 |
|---|---|---|
| 다이아 상품 5종 · 마일리지 교환 · 유물조각 교환 | **우편** | 지시 그대로의 «상점 구매품» |
| 이용권 쿠폰·즉시 보석·매일 보석(151) | **우편** | 상점에서 산 것의 «지급분» 이다. 지시서 [-1] 이 명시한 대상 |
| 이용권 **권한** 자체(`noAds`·`autoBlessUntil`·`offPlus`) | 즉시 | 물건이 아니라 계정 권한이다. 우편에 담으면 «수령 전에는 광고가 그대로 뜨는» 상태가 생긴다 |
| 소환(가챠) 결과 | 즉시(12 결과 팝업) | 관례. 지시서 [-1] 의 스코프 주석이 «기본은 소환 제외» 로 못 박았다 |
| 광고 상품 6칸(`COIN_ADS`) | 즉시 | «구매» 가 아니라 무료/광고 수령이다(버튼 라벨도 «받기»·«무료 수령»). 13 §3 리본이 «광고 상품» 으로 갈라 놨다 |
| 결제 카운터 `S.cnt.paid` | 즉시 | 수령 여부와 무관한 **결제 이력**이다 |

«매일 보석» 은 오프라인 정산이 며칠치를 한 번에 밀어 넣으므로 **한 통으로 모아** 보낸다
(30일치가 30통이 되면 우편함이 그것만으로 찬다).

## 6. 함정 (LESSONS 등재)

1. **`load()` 는 값을 돌려주지 않는다 — 전역 `S` 를 갈아 끼우고 `d.time` 을 반환한다.**
   게이트 [C] 를 `const back = load(); back.mailx` 로 짰다가 «저장이 안 됐다» 로 3항목 오판했다.
2. **세이브 라운드트립을 `page.reload()` 로 재면 안 된다** — 게이트 자신의 `addInitScript` 가
   매 로드마다 초기 세이브를 다시 써 넣어 방금 저장한 것을 덮는다. `save()` → `load()` 를 **직접** 태워라.
3. **문자열을 바꾸면 남의 «앵커 게이트» 가 조용히 깨진다.** `verify149` 는 소스 조각에서 뒤로 훑어
   가장 가까운 `notify(`/`popup(` 을 보는데, ⓐ 내가 문구를 바꾼 것(«획득 · 남은 쿠폰») ⓑ 내가 같은 조각을
   **더 앞줄에 새로 만든 것**(`diaPackName(p)` · `p.n + ' 이용권'`)에 둘 다 걸렸다. `indexOf` 는 **첫 출현**만 본다.
   → 새 코드에서 남의 앵커 문자열을 재사용하지 말고, 어쩔 수 없으면 앵커를 더 좁은 조각으로 옮겨라.
4. **화폐 이모지는 우편 «제목» 에도 못 쓴다.** 🎟️·💠 를 제목에 넣었다가 `verify125` A1/A2 가 걸렸다
   (125 는 주석 제외 전 소스를 훑는다). 📦·🛒 로 갈았다 — `mailRowHtml` 이 어차피 선행 이모지를 떼고 그린다.
5. **`m` 이라는 키 이름은 `MAIL_RW` 안에서 두 번 산다** — 보상 키(`m.m`)이면서 매퍼의 인자 이름(`m`)이다.
   `.map(m => ({ ..., m: m.m|0 }))` 는 맞지만 읽기 어렵다. 새 키를 더 붙일 때 주의.
