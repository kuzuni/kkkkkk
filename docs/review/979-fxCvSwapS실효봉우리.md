## 1. 재현 — 등재문이 그대로 맞았고, **실물이 산수와 오차 0.00000** 이다

`tools/probe979.js` 신설(338 규칙 — 처방 전에 제품에게 묻는다. 등재문의 수치를 옮겨 적지 않는다).

```
── fxCvSwapS  (340ms · 약칭 `cubic-bezier(.34,1.56,.64,1)` · scale 정지점 3)
   키프레임 값: 0% 0.84 → 55% 1.18 → 100% 1
   선언 봉우리 1.1800 @187.0ms   ↔ 실효 봉우리 **1.2133** @107.1ms   (초과 +2.82%)
   정지값 1.0000   ↔ 봉우리 뒤 최소 **0.9824** @274.7ms   (정지보다 −1.76%)
   [894 축] 재가속 13.79배 (같은 값·linear 2.01배)
```

**기계**: `cubic-bezier(.34,1.56,.64,1)` 는 y 가 1 을 넘는(최대 **1.0978**) 오버슛 곡선이고,
CSS 는 timing-function 을 **구간마다 다시** 건다 ⇒ 정지점이 셋이면 그 오버슛이 **두 번** 돈다.
① 올라가는 구간이 선언한 봉우리를 넘고 ② 내려오는 구간이 정지값 밑으로 파고든다.
«커졌다 돌아온다» 가 **«커졌다 → 정지보다 작아졌다 → 돌아온다»** 로 끝난다.

실물 대조(`Animation.currentTime` + `getComputedStyle`) 12표본 **최대 오차 0.00000** —
`t=107ms 1.21325` · `t=187ms 1.18000` · `t=274.5ms 0.98240`. **산수 = 렌더**다.

### ⚑ 등재문의 ③ 여백도 재현됐다 — 다만 **부호가 더 아슬아슬했다**

| scale | «Lv. n» 상자 좌단(카드기준) | [+] 뱃지 우변(카드+45.0) 대비 |
|---|---|---|
| 1.0000 (정지) | +52.00 | 여백 **7.00px** |
| 1.1800 (선언 봉우리) | +45.99 | 여백 **0.99px** |
| **1.2133 (실효 봉우리)** | **+44.88** | **−0.12px — 밟는다** |

등재문은 잉크 기준 «46.4 ↔ 45 = 0.6px 파고듦» 으로 적었고, 이 자는 **상자** 기준이라 값이 1px 남짓 다르다
(상자가 잉크보다 넓다). **부호와 결론은 같다** — 840 이 «팝 상한에서도 겹침 0» 을 **s=1.18 로** 계산해 둔
keep-out 이 실효 1.2133 에서 음수가 된다. 14회차 채점 2인 독립 일치(EE 여백 6px → **0px** @160ms ·
EF 6px → 1px)가 가리키던 그 자리다.

## 3. 처방 — 토큰 **하나**(890 · 93 29회차 · 894 와 같은 처방)

```
  .sk-clv.fx-cvswap{animation:fxCvSwapS .34s cubic-bezier(.34,1.56,.64,1) both, fxCvLit .34s linear}
                                        ↓
  .sk-clv.fx-cvswap{animation:fxCvSwapS .34s linear both, fxCvLit .34s linear}
```

* **키프레임 값 셋(.84 / 1.18 / 1)·정지점 자리(0/55/100%)·수명 340ms·채움 `both` 는 Δ0** —
  814 3회차가 «정보 잉크 : 앰비언트» 로 정한 진폭 1.18 은 **한 글자도 안 건드렸다.**
  완화를 «진폭을 줄여서» 얻지 않았다는 것을 자의 **[A1]** 이 못박는다.
* 짝인 `fxCvLit` 이 이미 `.34s linear` 라, 두 채널이 **같은 시간 눈금**을 쓰게 됐다 —
  814 3회차 주석의 «두 축이 한 사건으로 읽힌다» 를 값이 아니라 **곡선에서** 지킨다.
* 894 [v] 축도 같이 좋아진다: 재가속 **13.79배 → 2.01배**(894 래칫 3.0 아래).
  ⚠ 2.01 은 «정점에서 방향이 꺾이는 프레임» 의 표본 아티팩트라 정지점 3개 팝에서는 못 내린다.

### 왜 `ease-out` 이 아니라 `linear` 인가

`ease-out` 을 걸면 봉우리 값은 지켜지지만 **구간 경계에서 속도가 0 → 최대로 튄다**(890 이 이름 붙인
«급락 → 정체»). 890 이 `fxFlash` 에서, 93 29회차가 `.fx-plus` 에서, 894 가 `.fx-pay` 에서 고른 답이
셋 다 `linear` 였다 — **정지점이 곡선을 이미 표본하고 있으면 이징은 곡선이 아니라 왜곡이다**(894 §6 ②).

## 7. 교훈

1. **오버슛 이징은 «상수를 선언하는 키프레임» 과 같이 못 쓴다.** y 가 1 을 넘는 곡선은 구간마다
   다시 걸리면서 **적어 둔 값을 넘고 정지값을 파고든다** — 890·894 가 잰 «계단(속도)» 자로는
   한 항도 안 잡히는 결함이다(재가속만 보면 `fxCvSwapS` 도 «그냥 큰 값» 이다).
   자를 «값의 항등» 으로 새로 세워야 보인다.
2. **다른 자의 «시각 상수» 는 결함이 옮겨 놓은 자리일 수 있다.** `verify814` [B9] 는 정점을 100ms 에서
   찾고 있었는데, 그 시각은 **오버슛이 봉우리를 당겨 놓은** 자리였다. 수리하면 그런 항이 빨개지는데,
   이때 **문턱을 넓혀 초록으로 되돌리면 «결함이 있어야 통과하는 자»** 가 된다 — 물음을 고쳐야 한다.
3. **선언된 딥과 이징이 만든 딥을 나누는 것은 894 의 산수 한 줄이다**(같은 값·linear 와 나누기).
   안 나누면 이 스윕은 `fxPunch`·`fxHandTap` 의 **설계된 움푹**까지 7건으로 세어 넘겼을 것이다
   (실제로 첫 판이 그렇게 셌다 — 표를 고친 것이 이 회차의 두 번째 산출이다).
