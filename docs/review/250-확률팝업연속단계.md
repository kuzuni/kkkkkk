## 1. 등재문의 «확인 필요(주인)» 3지선다 — ⓐ 로 결정한 근거

등재문은 «1 2 3 4 5 6» 이 ⓐ 전 레벨 나열인지 ⓑ 단계 번호만 1..N 연속 표기(내용은 이정표 유지)인지
ⓒ 등급 6개를 세로로 한 번에(페이저 폐기)인지 확인이 필요하다고 적어 두었다. **ⓐ 로 갔다.**

- 주인 문구가 **«띄엄띄엄»** 을 문제로 짚는다. ⓑ 는 번호만 1..6 으로 바꾸고 **내용은 그대로 건너뛴다** —
  «Lv5 다음이 Lv8» 이라는 사실은 안 변하므로 지적이 해소되지 않는다(라벨만 속이는 셈).
- ⓒ 는 페이저 폐기 = 11 화면 레이아웃 재구성이다. 지시는 «단계» 에 대한 것이지 화면 개편이 아니고,
  11 은 이미 통과(①~④ 8)한 화면이라 T4 폴리시 라운드를 새로 여는 셈이 된다 — 지시 범위를 넘는다.
- **등재문 자신이 «연동» 절에서 길을 지목한다**: «등재 196(소환 레벨 총 25 로 축소)이 먼저 들어가면
  ⓐ 가 25쪽이 되어 현실적이 된다 — 순서를 같이 볼 것.» **196 은 이미 완료돼 main 에 있다**(`SUM_MAXLV = 25`).
  즉 ⓐ 를 막고 있던 유일한 이유(만렙 100 → 100쪽)가 이미 사라졌다.

→ **단계 = 소환 레벨 1..SUM_MAXLV 전부(25쪽).**

## 2. 원인 — 왜 띄엄띄엄이었나

`PRB_STEPS` 는 **«각 등급 해금 레벨 + 만렙» 이정표**였다.

```js
const prbStepsOf = roll => roll.map(g => g.unlock)…concat(SUM_MAXLV)…sort();
```

- 6행 배너(스킬): `1, 5, 8, 12, 16, 25`
- 8행 배너(장비·동료): `1, 5, 8, 12, 16, 20, 24, 25`

그런데 확률표는 **원래부터 임의 레벨을 계산할 수 있었다** — `gradeProbsAt(b, L)` 은 `L` 을 명시적으로 받고
`t = (L − unlock) / (SUM_MAXLV − unlock)` 을 `t^0.9` 로 굴린다. 즉 **해금 레벨 사이에서도 확률은 계속 움직이는데**
이정표만 보여 주느라 그 구간(2·3·4·6·7·9·10·11 …)을 볼 방법이 없었다. 이정표는 «전용 코드» 가 아니라
**단순히 골라 담은 목록**이었으므로, 목록만 바꾸면 나머지는 그대로 동작한다.

## 3. 고친 것

### ① `index.html` — 단계 목록 (한 줄)

```js
const prbStepsOf = () => Array.from({ length: SUM_MAXLV }, (_, i) => i + 1);
const PRB_STEPS    = prbStepsOf();   /* 250 — 소환 레벨 1..만렙 연속 */
const PRB_STEPS_EQ = prbStepsOf();   /* 250 — 8행 배너도 같은 연속 단계 */
```

- **배너별로 단계가 다를 이유가 사라졌다.** 6행/8행 차이는 «그 레벨에 해금된 등급이 몇 개냐» 로
  **저절로** 드러난다(장비는 21단계부터 초월 행이, 25단계에서 불멸 행이 는다).
- 두 상수 이름을 남긴 이유는 `prbSteps()` 와 게이트 3종(verify85 B5 · verify106 C5 · verify196 E1·E2)이
  **배너별 이름으로 묻기 때문**이다. 값은 같다.
- **만렙을 리터럴로 적지 않았다** — 196 이 세운 원칙(LESSONS 106-1: «해금 사다리·만렙이 바뀌면 이 줄이
  따라가야 한다»)을 그대로 지킨다. `SUM_MAXLV` 가 또 바뀌면 이 한 줄이 자동으로 따라간다.
- 손대지 **않은** 것: `renderProbInfo()`(표 그리기) · `gradeProbsAt()`(확률 공식) · `openProbInfo()`(진입) ·
  `prbPrev/prbNext` 핸들러 · 마크업 · CSS. `$('prbLv')` 의 «만렙이면 MAX» 표기 규칙도 종전 그대로다
  (`fnchk115` [3]·`func196` [5] 가 «MAX» 문자열을 묻는다).

### ② 게이트 3종 — 옛 이정표를 단언하던 줄 갱신

이 셋은 «이정표 문자열» 을 통째로 박아 두고 있어서 그대로 두면 **설계 변경 직후 빨간 채 방치**된다
(등재문이 미리 «게이트를 같이 갱신해야 한다» 고 적어 둔 그 자리다).

세 곳 모두 **리터럴을 새 리터럴로 갈아 끼우지 않았다** — `SUM_MAXLV` 로 세게 만들어서

- `tools/fnchk115.js` [2] 는 `openProbInfo('weapon', 75)` 가 «단계 75» 로 열리기를 기대한다 —
