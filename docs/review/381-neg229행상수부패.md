## 2. ⚑ 본체는 «FAIL 4줄» 이 아니라 «조용히 사라진 단언 47항» 이다

이 작업의 핵심 관측이다. `neg229` 의 루프는 갈아 끼울 자리를 못 찾으면 **`continue`** 한다:

```js
if (bad) { ok(t.id + ' 갈아 끼울 자리가 전부 정확히 1곳', false, …); continue; }
```

⇒ 그 블록의 `want`/`not` 이 **아예 안 세진다**. 화면에는 FAIL 이 **4줄**만 뜨는데
실제로 사라진 단언은 **47항**이다(93 − 46). 319(«§5 후반·§6 이 한 번도 안 돌았다»)와 같은 모양 —
**빨간 줄 수는 구멍의 크기를 안 말해 준다.** `probe381` [4]·[R] 이 그 수를 못박는다.

즉 N1(83 되돌림)·N2(71 되돌림 = 이 게이트의 **원래 물음**)·N3(360 «출석 단독 규격» 되돌림)·

## 3. 처방 — 368 그대로 «자리를 상수에서 빼고 제품에게 묻는다»

등재문이 제시한 두 갈래 중 **후자(더 나은 처방)** 를 골랐다.

- ⓐ 세 상수를 «현재 소스 문자열» 로 갱신 → **기각.** 다음 `--sf`·글리프 변경에 **또 죽는다**.
  356·371 이 두 번 연속 죽인 자리를 세 번째로 굳히는 것일 뿐이다.
- ⓑ **채택** — `data-pop` 으로 행을 **뽑는다**(`row(pop)`). 368 의 «상수를 박아 둔 쪽이 게이트다» 와 같은 처방.

```js
const row = pop => { …  `^[ \t]*<div class="ibtn"[^\n]*?data-pop="${pop}"[^\n]*?</div>$` … };
const COLL_ROW = row('coll'); const BLESS_ROW = row('bless'); const ATTEND_ROW = row('attend');
```

**허용 오차는 한 칸도 안 넓혔다** — 뽑기는 `verify71` 의 단언을 하나도 안 건드린다.
바뀐 것은 «되돌림을 어디에 꽂을지 찾는 방법» 뿐이고, **무엇이 빨개져야 하는가**(want/not 47항)는 그대로다.

«뽑기» 는 자칫 «무엇이든 뽑아 와서 늘 초록» 이 될 수 있는 처방이라, 가드를 같이 세웠다.
