## 0. 왜 (가) 인가 — 비평가를 안 띄운 이유

레퍼런스와 «배치·비율» 을 맞추는 작업이 아니다. 배너의 몬스터 자리는 이미 04 측정표 §2 로 확정돼
있고(배너 750×351 @ 본문 로컬 6,24), 그 안의 실루엣 자리(300×214 · 가운데 · bottom 14)도
CSS 에 이미 적혀 있었다. 169 가 하는 일은 **그 자리를 채우는 대체물을 CSS 실루엣 → 실스프라이트로
바꾸는 것**과 **빈 함수였던 버튼을 실동작에 잇는 것**이다. 기하는 한 값도 안 움직인다(게이트 A4·A5·A6).
따라서 회차 예산을 비평 루프에 태우지 않고, **수치 게이트 + 실동작 확인**으로 닫았다.

기능 완성 규칙(2026-08-25 주인 지시) 대로 §4 에 **기능 체크 표**를 남긴다.

## 1. 고친 것 — ① 배너 몬스터 썸네일

### 무엇이 문제였나

세부 팝업 배너 `.dgd-bn` 은 **장식 그라디언트 + CSS 로 그린 슬라임 실루엣**(`b` — radial-gradient 덩어리에
`::before/::after` 눈 2개)뿐이었다. 03 행 카드는 이미 작업 72(2026-08-26 주인 재지시)로 이모지를 버리고
`drawSpriteTo()` 실스프라이트 캔버스가 됐는데, 그 카드를 눌러서 열리는 세부 팝업에는 **같은 몬스터가
없다.** 「황금 동굴」 행에서 용을 보고 들어갔는데 세부에서는 초록 슬라임이 나오는 상태였다.

### 처방 — 같은 데이터, 같은 페인터

새 규격을 만들지 않았다. 행 카드가 쓰는 것을 **그대로** 가져다 쓴다.

| 무엇 | 행 카드(03) | 세부 배너(04, 169) |
|---|---|---|
| 데이터 | `DUN_UI[id]` 의 `thk/thf/thi/thbr` | **같음** |
| 그리기 | `raidDraw(cv)` → `drawSpriteTo` | **같은 함수** |
| 담는 방식 | `fit: TH_PAD`(contain, 사방 16) | **같음**(`.dnc.rd` 가 아니라 자동으로 contain 가지) |
| 아이들 순환 | `raidIdleTick` 125ms 폴링 · 8fps | **같은 타이머**에 편입 |

바꾼 곳은 4군데다.

1. **마크업** — `.dgd-bn` 에 `<canvas class="dgd-th" id="dgdTh" width="300" height="214">` 를 넣고
   배너에 `id="dgdBn"` 을 달았다. 캔버스 픽셀 = CSS px 라 배율 1 에서 1:1(안 흐려진다).
2. **CSS** — 캔버스를 **종전 실루엣 `b` 와 완전히 같은 규칙값**으로 앉힌다
   (`left:50%; bottom:14px; 300×214; margin-left:-150px`). 그려진 회차에는 `.dgd-bn.th-on` 이 붙어
   실루엣이 `display:none` 이 되고 캔버스가 대신 보인다. **어느 쪽이든 bbox 는 같다.**
3. **JS `dgdPaintTh()`** — `dgdDun` → `DUN_UI[id]`, `dgdRaid` → `RAIDS[].ui`, `dgdArena` → `null`.
   `raidDraw` 가 **성공했을 때만** `th-on` 을 붙인다(아틀라스가 늦게 올라오면 200ms 간격 25회 재시도.
   03 의 `raidPaint` 와 같은 규칙). `renderDunDetail`·`renderRaidDetail`·`renderArenaDetail` 셋 다에서 부른다.
4. **`raidIdleTick`** — 폴링 대상에 `#dgdw canvas.dgd-th` 를 더하고, 살아 있는 조건을
   «`#dunw` 가 열림» → «`#dunw` **또는** `#dgdw` 가 열림» 으로 넓혔다. 세부 팝업은 03 목록을 안 거치고도
   열리기 때문이다(구버전 `#bDun` [도전] · 113 가이드 손가락). 대신 `offsetParent` 가 null 인 캔버스는
   건너뛴다 — 닫힌 페이지의 캔버스와 아레나(숨긴 캔버스)를 그리지 않기 위한 값싼 가드다.

### 123 분기 — 이 팝업은 레이드·아레나와 공유된다

## 2. 고친 것 — ② 소탕 버튼

### 무엇이 문제였나

```js
$('dgdSweep').onclick = () => {};   /* 레퍼런스의 잠긴 유료 버튼 — 아직 미구현 */
```

버튼은 `.dgd-lk`(자물쇠 아트)만 달고 **빈 함수**였다. 그런데 `sweepDungeon(d)` 는 이미 완동이다 —
구버전 목록 행의 `[⚡ 소탕]` 이 쓰는 바로 그 함수다. 즉 «기능이 없어서» 가 아니라 **선이 안 이어져 있었다.**

### 처방

- 한 버튼이 두 얼굴을 갖게 했다. `.dgd-b.lk` = 레퍼런스의 «잠긴 유료 버튼»(소탕 개념이 없는 레이드·아레나),
  `.lk` 없음 = 「소탕」 글자 버튼(던전 모드). 서로를 CSS 로 끈다.
- 활성 조건은 **목록 행과 글자 그대로 같다**: `left > 0 && f > 1`.
  (1층까지밖에 못 깼으면 소탕할 이전 층이 없고, 오늘 입장 횟수를 다 썼으면 못 들어간다.)
  비활성 표시는 `dgdGo` 와 같은 `grayscale(.75) brightness(.8)`.
- 핸들러는 `closeDunDetail(); sweepDungeon(d);` 뒤에 03 목록·89 유물 페이지 갱신을 붙였다
  ([도전] 버튼과 **같은 뒷정리**).
- **밸런스는 한 줄도 안 바꿨다.** `sweepDungeon` 안(층 선택 `S.dun[id]-1` · 횟수 소모 · `giveReward`)은
  그대로다. 세부 팝업이 ◀▶ 로 고른 층(`dgdFloor`)은 종전 [도전] 이 소탕으로 떨어질 때도 안 쓰던 값이라
  여기서도 안 쓴다 — 두 버튼이 같은 층을 소탕한다.

## 7. 아트 필요 / 남은 것

- 배너 몬스터는 이제 **실스프라이트**라 «아트 대체물» 이 아니다. 다만 레퍼런스 배너는
  «초록 크리스탈 동굴 씬 + 그 안의 몬스터» 인데 우리 배경은 아직 CSS 그라디언트 + 결정 기둥 2개다
  (04 측정표 §2-1 «아트» 표기 그대로). **배경 씬 아트**는 여전히 발주 대상이다.
- 아레나 세부 배너는 종전 슬라임 실루엣이 그대로다. 카드가 «마주 본 기사 2명» 이라 한 칸 배너로
  옮기려면 «두 칸 배너» 규격이 새로 필요하다 — 123 이나 아레나 전용 작업의 몫으로 남긴다.
