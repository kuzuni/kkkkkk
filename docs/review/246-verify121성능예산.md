## 2. 왜 «비율» 인데도 빨간가 — 양자화 (`tools/probe246.js` 신설)

이 러너의 크로미움은 소프트웨어 합성(SwiftShader)이라 프레임 시간이 **16.7ms 배수로 양자화**된다.
중앙 프레임은 33.4 / 50.0 / 66.7 / 83.3ms 넷 중 하나로만 떨어진다. 그래서 ON 이 **한 칸** 밀리는 순간
비가 곧바로 `50.0 / 33.4 = 1.50` 이고, **그 1.50 은 239 가 «회귀 주입 값» 으로 자에 적어 둔 바로 그 수다.**
1.15 와 1.50 사이에는 이 러너가 만들 수 있는 값이 하나도 없다 — 자에 **눈금이 없다.**

같은 스크롤(왕복 120프레임)에서 축 4개를 한꺼번에 재고, 239 가 쓰던 회귀 2종에 2종을 더해 주입했다.

- **[T] 시간은 자로 못 쓴다.** ① 무회귀 행이 이미 1.50 을 찍어 회귀대와 **같은 칸**에 있다.
  ② 더 나쁜 것은 **진짜 회귀를 놓친다**는 것 — 레이어 면적을 4배로 부풀린 마지막 행에서 중앙 프레임 비는
  **1.00(초록)** 이다. ③ `>40ms 비율` 은 무회귀에서 이미 99~100% 로 **머리끝까지 포화**돼 회귀를 얹어도 안 움직인다.
- **[W] 작업량(recalc·layout 카운트)도 못 쓴다.** 스크롤 자체가 매 프레임 레이아웃을 부르므로 배경 몫이
  묻힌다 — 레이아웃 유발 애니메이션을 넣어도 3.07 → 3.11 로 잡음 안에서 안 움직였다. **폐기.**
- **[G] 기하와 [S] 구조는 폭이 0** 이고(3쌍 내내 같은 값) 주입 4종을 **전부** 잡는다.

## 3. 고친 것 (`tools/verify121.js` §7 한 절만)

`index.html` 은 **한 줄도 건드리지 않았다**(제품이 아니라 자의 문제 — 등재문의 판단대로다).
237 이 `verify114 [8]` 에서 간 길을 그대로 옮겼다: **시간을 버리고 작업량·구조를 잰다.**

1. **주 판정 ① 비싼 상태 0건** — `.bgm` 과 그 의사요소 2겹의 computed `filter`·`backdrop-filter`·`box-shadow`
   가 전부 `none`. (LESSONS 121-③ «filter 는 매 프레임 그 요소를 다시 래스터한다»)
2. **주 판정 ② 합성 전용 속성** — `.bgm` 계열에서 도는 애니메이션이 건드리는 속성 집합이
   `{transform, opacity}` 의 부분집합. `getAnimations({subtree:true})` → `getKeyframes()` 의 키를 모은다.
   레이아웃·페인트를 유발하는 속성이 끼면 매 프레임 메인 스레드가 돈다 —
   측정표 주석의 «JS rAF·캔버스 금지, 움직이는 것은 translate 와 opacity 뿐» 조항을 자로 옮긴 것이다.
3. **주 판정 ③ 래스터 면적 예산** — **카드당** 애니메이션 레이어 면적 ≤ 카드 면적 × 6배.
   실측 던전 3.76 · 레이드 4.78(`--bgh2` 만큼 `::after` 가 더 높다) · 폭 0. **카드 장수와 무관한 양**으로
   잡았다 — 던전은 194·203 처럼 계속 늘어나므로 «리스트 면적 대비 총합» 으로 재면 카드가 붙을 때마다
   자가 저절로 좁아진다(그때 3.76 → 5.32 → … 로 올라가는 것은 회귀가 아니다).
4. **시간 판정은 옵트인** — `V121_PERF=1` 을 준 전용 러너에서만 239 의 두 줄을 켠다.
   기본 실행에서는 fps 표와 쌍별 유지율을 **그대로 출력**하되 «(판정 아님)» 으로 값만 찍는다
   (237 의 `V114_PERF=1` 관례 그대로). GPU 합성이 있는 기기에서는 그 두 줄이 여전히 뜻을 갖는다.
