## 1회차 (2026-09-02, sess-0742-27872 루틴 워커 C)

### ① 자를 먼저 세웠다 — «어긋난 그림» 이 아니라 **앵커 계수 k** 를 잰다

등재문의 증상(«요소가 제각각의 높이에 흩어지고 겹친다»)은 **결과**이고, 등재문 자신이 뿌리를
이미 지목하고 있다 — «요소별로 앵커 기준이 다르다». 그래서 재현기 `tools/probe754.js` 는
겹침이 아니라 그 뿌리를 직접 잰다:

```
k = Δ(요소의 y) / Δ(프레임 높이)      k 0 = 상단 앵커 · 0.5 = 중앙 · 1 = 하단
```

한 그릇 안의 요소가 서로 다른 k 를 가지면 프레임이 변할 때 상대 거리가 벌어진다.
**판정은 «k 의 종류 수»** 이고, 겹침은 같이 찍되 판정 축이 아니다.

**화면비 5종 = 프레임 5종이다.** `fit()` 이 frameH 를 **1600..2600 으로 clamp** 하므로
9:13.3 보다 «넓은» 화면은 전부 1600 으로 눌린다 — 레이아웃이 갈리는 축은 frameH **하나**다:
`1600`(9:13.3 및 그보다 넓은 전부) · `1841`(`.shortf` 경계 1842 바로 아래) · `1920`(9:16) ·
`2280`(기준) · `2600`(clamp 상한).

첫 판은 k 를 **프레임** 기준으로 쟀고, 그래서 다음 셋을 결함으로 찍었다:

### ④ 처방 — 426·661 과 **같은 한 줄**(제품 `index.html` 4자리)

규약 ②(«한 오버레이 = 한 그릇, 요소별 개별 앵커 금지»)를 그대로 적용했다.
앵커는 **상자가 아니라 좌표계 원점**이다(426 의 «높이 0» 꼴):

```css
.st-grp{position:absolute;left:0;right:0;top:calc(50% - 1104px);height:0}   /* 17 */
.df-grp{position:absolute;left:0;right:0;top:calc(50% - 907.5px);height:0}  /* 18 */
```

* 상수는 값이 아니라 **묶음 bbox 의 중심**이다 — 17 은 793..1415 ⇒ 1104, 18 은 458..1357 ⇒ 907.5.
  자식 top `T` 는 `(VH/2 − C) + T` 에 그려지고 묶음 중심은 **어떤 프레임에서도 정확히 VH/2** 다.
* **묶음 «안» 의 좌표는 한 칸도 안 건드렸다** — `#statw .upr-grp{top:793px}` · `.st-icon{top:1004px}` ·
  `.st-desc{top:1345px}` · `.df-emb{top:458px}` 전부 측정표 값 그대로다(게이트 §4 가 소스로 못박는다).
* ⚠ **높이·z-index·transform 을 주지 마라** — 높이를 주면 «빈 면을 누르면 닫힘» 이 그 상자에 먹히고(426 ⑥),
  z-index 는 새 쌓임 맥락을 만들어 자식 z 를 가두며(426 ⚠), transform 은 60 쥬시 등장 연출과 자리를 다툰다(661 ⚠).
