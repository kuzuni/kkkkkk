## 1. 무엇이 문제였나

61 이 만든 가이드 미션은 기본이 **델타형**이다 — 진행 = `카운터 − 기준선`이고,
기준선(`S.guide.prog`)은 그 미션이 «현재» 로 올라온 순간 찍힌다. 그래서 미션이 열리기 **전**에
이미 그 행동을 해 둔 플레이어는 카운터가 0 부터 다시 시작해 **한 번 더** 해야 한다.

강화는 08 세부 팝업에서 게임 초반부터 되는데 «아이템 1회 강화하기» 는 **idx 12**(20개 중 13번째)다.
거기까지 온 플레이어가 한 번도 강화를 안 했을 리 없으므로 **사실상 전원이 겪는다** — 주인이 본 그대로다.

## 2. 처방 — ⓐ `abs:1`

등재문의 두 후보 중 **ⓐ**(누적 절대값으로 판정)를 택했다.

- ⓑ(«델타는 두되 시작 시 이미 만족하면 즉시 달성»)는 **판정 경로가 둘**이 된다 — 시작 순간에만
  보는 특례라, 미션이 열린 뒤 세이브가 이관되거나 `prog` 가 재확정되면 다시 옛 동작으로 샌다.
- ⓐ 는 `gmBase()` 의 **기존 분기**(`if(m.abs) return 0;`)를 그대로 탄다. 형제 미션
  «스킬 장착하기»·«스테이지 N 도달»·«유물 Lv 3 모으기» 가 이미 쓰는 길이라 새 코드가 0줄이다.

### ★ 함정 1 — «전용 카운터» 가 조건인 이유: 소환 3종은 카운터를 **나눠 쓴다**

무기·방패·목걸이 미션은 셋 다 `S.cnt.sumEquip` 하나를 본다. **abs 로 돌리면 무기를 한 번 뽑는
순간 방패·목걸이 미션이 동시에 자동 달성**돼 체인 두 칸이 공짜로 사라진다(다이아 ~1,500 도 같이).
지금은 **델타 + `ban`** 조합이 «그 상자만» 뽑게 강제해서 정확히 돈다 — 델타가 여기서는 버그가
아니라 **부위별 카운터가 없는 것을 메우는 장치**다. 부위별 카운터를 새로 두는 것은 세이브 구조
변경이라 이 단위 밖이다. 게이트 §6 이 이 셋을 «공짜 달성 아님» 으로 못 박는다.

## 6. 남의 게이트 1건 정정 — `verify154` §6

`verify154` §6 이 미션 11 을 완료 상태로 만들 때 이렇게 썼다:

```js
S.guide.prog = -1; gmBase(GUIDE[11]);
S.cnt.sumRelic = S.guide.prog + GUIDE[11].goal;   /* 델타형 — 기준선 + goal */
```

`gmBase()` 의 **부작용**(prog 에 기준선이 찍힌다)에 기대 목표치를 계산한다. abs 미션에서 gmBase 는
prog 를 건드리지 않고 0 을 돌려주므로 prog 가 `-1` 그대로 남아 목표치가 **0** 이 됐다(5건 FAIL).
**반환값**을 쓰도록 한 줄 고쳤다 — 두 형태 모두에서 맞는다.

> 교훈: **부작용으로 값을 받아 오지 말고 반환값을 써라.** 그 한 줄이 «판정 방식이 바뀌면 조용히
> 어긋나는» 결합을 만들었다. 154 의 주제(«출석» 삭제·순서·이관)와는 무관한 헬퍼이고,
