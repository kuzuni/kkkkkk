## 1. 재현 — 등재문이 가르라고 한 갈래를 먼저 갈랐다

등재문의 질문은 **«표시만 잘리는가, 결과 «데이터» 도 6개만 남는가»** 하나였다(723 과 같은 질문).
`tools/probe726.js` 를 신설해 **한 번의 일괄 강화에서 세 수를 동시에** 찍었다 —

| | 뜻 | 어떻게 재는가 |
|---|---|---|
| ⓐ | 세이브가 실제로 올린 종 수 | `S.own[id].l` 을 강화 **전후로 대조** (제품의 진실) |
| ⓑ | 팝업에 넘어간 데이터 | `openUpAll` 을 감싸 `ups.length` 를 그 자리에서 받는다 |
| ⓒ | 그려진 카드 수 | `#upCards .upr-cel` 개수 — 주인이 센 그 숫자 |

**수리 전 실측(24종씩 심어 실제 버튼 클릭 경로로):**

| 시트 | ⓐ 세이브 | ⓑ ups | ⓒ 그린 카드 |
|---|---|---|---|
| 장비(05 무기) | **24** | **24** | **6** |
| 스킬(07) | **24** | **24** | **6** |
| 펫(26) | **24** | **24** | **6** |

⇒ **표시만 잘린다.** 데이터 경로(`levelUpAll` → `ups`)는 처음부터 온전했고 강화 자체도 20개+ 전부
적용돼 있었다. 고칠 곳은 **한 자리**다 — `index.html` 의

```
const UPR_MAX = 6;
$('upCards').innerHTML = ups.slice(0, UPR_MAX).map(…)
```

주석이 이유까지 적어 두고 있었다: «레퍼런스는 카드 3칸이지만 실제 강화 결과는 개수가 가변이라
한 줄에 들어가는 6칸(151·6−14 = 892 < 1080)까지만 보여 준다.»
**6은 «한 줄에 들어가는 칸 수» 였는데 그 값이 «보여 줄 최대 개수» 로 쓰이고 있었다.**

⚠ 1회차 하네스 함정 하나 — `goTab('hero')` 는 **이미 열린 탭을 다시 누르면 패널을 닫는다**(A1 규약).
시트를 연속으로 오가며 재현할 때 조건 없이 부르면 **두 번째 시트가 통째로 안 열린다**(펫 절이 실제로
그렇게 빨갰다). `if(!(panelOpen && curTab === 'hero')) goTab('hero')` 로 갈랐다 — 자 두 개 다 같은 가드다.

## 2. 처방 — 상한을 없앤 게 아니라 **6의 뜻을 되돌렸다**

`UPR_MAX`(보여 줄 최대) → **`UPR_COLS`(한 줄 칸 수)**. 넘치면 줄바꿈, 프레임에 안 들어가는 행은
그 격자만 스크롤한다.

| | 값 | 근거 |
|---|---|---|
| `UPR_COLS` | 6 | 137·6 + 14·5 = **892 < 1080** (측정표 09 §3 칸 규격 그대로) |
| `UPR_ROW_H` | 166 | 카드 138 + `.upr-lv` margin 5 + 23 |
| `UPR_GAP` | 14 | 칸 사이 — 가로·세로 같은 값(측정표 §3) |
| `UPR_SLACK` | 8 | `.upr-lv` 검정 스트로크가 칸 밖으로 **7px** 넘친다(`probe726` [5] 실측 — 이걸 안 넣으면 «다 보이는데 스크롤이 생긴» 상태가 된다) |
| `UPR_TOP_1` | 131 | ≤6칸 — 레퍼런스 카드 상변(ref y1143 − 리본 상변 1012) |
| `UPR_TOP_N` | 183 | 7칸 이상 — «총 N건 강화» 줄(top 106 · h 44)이 끼어 52px 내려간다 |
| `UPR_BOT_KEEP` | 240 | 아래로 비워 둘 띠 — «터치하여 닫기»(bottom 175 + 잉크 45) + 여유 20 |

**보이는 행수**는 프레임에서 역산한다. 묶음이 **세로 중앙**(661)이라 높이 H 는 아래로 **H/2** 만
자라므로 여유는 2배로 잡는다:

```
room = frameH − 2·UPR_BOT_KEEP − top
vis  = clamp(1, rows, ⌊(room − SLACK + GAP) / (ROW_H + GAP)⌋)
gh   = vis·ROW_H + (vis−1)·GAP + SLACK
높이 = many ? top + gh : 300
```

실측: 9:19(2280) **9행** · 9:13.3(1600) **5행**(= 30칸)까지 보이고 그 위는 스크롤.

⚑ **661 이 만든 성질을 그대로 썼다** — 묶음은 `top: calc(50% − 높이/2)` 라 **높이만 정하면 자리는
따라온다.** 그래서 «높이 300 상수» 를 `--upr-gh`(폴백 **300px**)로 바꾼 CSS 한 줄이 세로 배치의 전부다.
폴백이 옛 상수라 같은 부품을 쓰는 **17(`#statw`)·31(`#dclw`)은 한 픽셀도 안 움직인다**(변수는 `#upw` 에만 건다).

### 2-1. «6칸 이하는 레퍼런스 그대로 Δ0px»

`many` 클래스는 **7칸부터** 붙는다. 6칸 이하에서는 묶음 높이 300 · 카드 top 131 · 칸 좌변
**x 320.5 / 471.5 / 622.5**(측정표 §3 의 ref x321/471/623) 가 전부 그대로다 — `verify726` [C] 가
그 다섯 값을 직접 잰다. **레퍼런스 화면(3칸)은 이 작업 전후로 한 픽셀도 안 다르다.**

### 2-2. 327 «스크롤조차 안 쓴다» 는 여기로 안 옮겼다 (위임 규약 채택)

| 안 | 대가 |
|---|---|
| ⓐ 327 처럼 **고정 N배 확대**로 스크롤 0 | 12 소환은 최대 30연이라 상한이 있지만 **일괄 강화 건수는 보유 종수만큼 가변**이다(장비 36 · 스킬 27 · 펫 36, 앞으로 더 는다). 고정 배수를 정할 근거가 없고, 짧은 프레임에서는 어차피 안 들어간다 |
| **ⓑ 줄바꿈 + 그 격자만 스크롤 + «총 N건» 헤더** ← **채택** | 스크롤바를 숨기는 저장소 규약(`.shsc`·`.shp-list`·`.dns-list`) 때문에 «더 있다» 는 신호가 없다 → **헤더 글자가 그 몫을 한다** |

주인 지시문 자체가 «스크롤 허용 · 헤더에 총 N건» 이라 ⓑ 가 문면이다. 되돌리려면 `UPR_TOP_N` 줄과
`#upw.many` 규칙 3개를 지우고 `UPR_COLS` 를 다시 상한으로 쓰면 된다.

### 2-3. 곁다리 둘 — 안 하면 수리가 반쪽이 되는 것들

- **합침(187 규약)** — `uprMerge()` 신설. 같은 아이템이 여러 줄로 오면 한 칸 «Lv min→max» 로 접는다.
  `levelUpAll` 은 종당 한 줄만 만들지만(«a→b» 가 이미 합본) 호출부가 목록을 겹쳐 넘길 수 있어
  **표시층에서 한 번 더** 접는다. 게이트가 세는 «기대 건수» 는 이 합침 **뒤** 값이다.
- **«밀어서 스크롤» 이 팝업을 닫는 문제** — `#upw` 는 «화면 아무 데나 탭하면 닫힘» 이라 격자를
  드래그해 스크롤하면 **끝에서 click 이 도착해 그대로 닫힌다**(마우스 드래그·스크롤바 포함).
  ⇒ `pointerdown` 자리를 기억해 **10px 넘게 움직인 클릭은 닫기가 아니다**. 제자리 탭은 종전 그대로.
  이걸 안 하면 «스크롤 허용» 이 말만 남는다(`verify726` [F1] 이 120px 끈 손짓으로 못박는다).
