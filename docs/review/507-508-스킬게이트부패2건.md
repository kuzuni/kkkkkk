## §1 507ⓐ — «185 넉백 0» 8건: 스킬이 민 것이 아니라 **적 자신이 걸었다**

### 찍힌 값 (`probe507` [A]·[B])

```
drone   변위 79.733px · 돌진 프레임 32 · 예고 프레임 52
curve   변위 79.733px · 돌진 프레임 32 · 예고 프레임 52
…(8종 전부 같은 값, 폭 0.0000px)
(스킬 없음) 변위 79.733px · 돌진 프레임 32 · 예고 프레임 52   ← 대조군
```

- **[A2]** 8종의 변위가 **소수점 넷째 자리까지 같다**(폭 0.0000px) = 스킬이 만든 값일 수 없다.
- **[A3]** **스킬을 하나도 안 낀 대조군**이 같은 79.733px 를 낸다 = 넉백이 아니다.
- **[B2]** 움직인 프레임은 전부 `dashD > 0`(돌진 중)이다 — 한 프레임 4.983px 씩 f148~f153.
- **[B3]** `DASH.mob.spd 2.6 × PLAYER_SPEED 115 × dur 0.26 = 77.740px` 로 **5% 안에서 같다.**

### 뿌리

**359**(«보스·일반 적 대시 공격 신설»)가 잡몹에게도 대시를 줬고, 돌진 중에는 속도가

```js
else if(dashing) spd = stat.speed * DK.spd * (e.slow > 0 ? 0.55 : 1);   /* index.html 21584 */
```

로 **`e.sp` 를 통째로 우회한다.** 193 시절의 하네스는 `e.sp = 0` 한 줄로 «추격을 껐다» 고 믿었고,
그 전제가 359 와 함께 조용히 무너졌다. **제품은 내내 옳았다** — 288 이 걷어낸 넉백은 지금도 0 이다.

### 처방 — «적 자신의 이동» 을 전부 끈다

```js
if (!chase) enemies.forEach(e => { e.sp = 0; e.dashT = 0; e.dashD = 0; e.dashCd = 1e9; });
```

⚠ **무르게 푼 수리가 아님을 게이트 «안» 에서 두 겹으로 못박았다** — 허용치(0.5px)는 한 칸도 안 넓혔다.

- **[전제 p1]** 스킬을 하나도 안 낀 대조군이 **0.000px** 여야 한다 → 하네스가 적 자신의 이동을 확실히 껐다.
- **[전제 p2]** 같은 하네스에서 적 0번을 **2.5px 밀면 자가 2.500px 로 본다** → 껐다고 눈이 먼 것이 아니다.

이 둘이 없으면 «변위 0» 은 «아무것도 안 움직인다» 와 «자가 못 본다» 를 구별하지 못한다.
(`probe507` [C]·[D] 가 같은 것을 재현기 쪽에서도 찍는다.)

### 왜 «대시를 세는 축» 을 새로 안 만들었나

359 의 대시는 **`verify359`·`verify172`·`verify66` 이 이미 자기 축으로 재고 있다.**
193 이 묻는 것은 «185 넉백이 되살아났는가» 하나이므로, 여기서 대시를 같이 재면 두 자가 서로를 대신하게 된다
(505 가 «자리를 비우지 말라» 와 짝으로 남긴 교훈의 반대쪽 — 남의 축을 가져오지도 말라).

## §2 507ⓑ — 피해 밴드 1건: 축이 «총 피해» 라 등급 안에서 **8배** 갈린다

### 찍힌 값 (`probe507` [E])

| 등급 | **선언 DPS** 최대÷최소 | **총 피해**(링 6기 10초) 최대÷최소 |
|---|---|---|
| 일반 | 1.0000 | 1.93 |
| 고급 | 1.0001 | 3.11 |
| 희귀 | 1.0000 | 4.84 |
| 영웅 | 1.0001 | 3.76 |
| 전설 | 1.0001 | **8.62** (flask 45,852 ↔ boomer 395,327) |
| 신화 | 1.0000 | 6.78 (laser 43,910 ↔ lance 297,749) |

**484**(«같은 등급 DPS 동일 + 등급 ×3»)와 **504**(발수 실측 재정박) 이후 «같은 것» 은 **DPS 6.49 하나**다.
반면 이 하네스의 총 피해는 «적 몇 기를 덮는가» 로 갈린다 — 링 6기 배치는 광역기에 유리하고
단일 표적 지속형(레이저)에 불리하다. 그 편향이 그대로 **«신화 laser 43,910 ∈ [75,885, …] 밖»** 이라는
거짓 빨강으로 나왔다. 자리를 옮겨 가며 실패하는 것도 확인된다 — 504 **전**에는 whirl 이,
504 **후**에는 laser 가 같은 자리에서 걸렸다(등재문).

⚑ 총 피해 축은 **실행마다도 흔들린다**(전설 8.20 → 8.62). 밴드를 이 축에 세우면 플레이키까지 얹힌다.

### 처방 — 축을 «선언 DPS» 로 갈아 끼운다 (333 «자리를 비우지 말고 살아 있는 표본으로»)

```js
const D = s => s.cd > 0 ? s.m * skillHits(s) / s.cd : s.m * skillHits(s);
```

식을 새로 짜지 않고 `verify484` [B] · `verify260` [C] 와 **같은 문장**을 쓴다. 발수는 제품의 입구
`skillHits()`(504) 를 그대로 부른다 — 사슬을 베껴 적지 않는다.

- 대조군은 그대로 **같은 등급 기존 스킬**(`PEER`) 이고, 밴드는 그 실측 평균의 **±5%** 다.
- ±5% 를 고른 근거: 실측 편차가 **0.01%**([E1] 등급 안 최대÷최소 1.0001) 라 **500배 여유**이고,
  «절반으로 조였다 / 두 배로 키웠다» 급 이탈은 그대로 빨개진다.
- **§R 되돌림 시험 신설** — `laser` 의 `m` 을 절반으로 되돌리면 선언 DPS 3.2449 가 하한 6.1655 아래로
  떨어져 빨개진다(그 자리에서 원복하고, 원복됐는지까지 단언한다). «±5% 로 넓혔더니 무엇이든 통과» 가
  아님을 게이트 안에서 증명한다.

### 소유권을 주석에 못박았다

`m` 축의 주인은 `tools/verify484.js`(`SK_DPS_REF 6.49`) · 발수 축의 주인은 `tools/verify504.js` 다.
193 [5] 가 묻는 것은 그 둘이 아니라 **«193 이 신설한 8종이 자기 등급 밖으로 새지 않는가»** 하나다.

## §3 508 — `m` 기대표 셋이 484 를 안 따라왔다

### ① `verify193` [1-b] `M_MOVED` — 4건 → **19건 전부**

193 기준선(`KEEP`)은 그대로 두고, 이동분만 «누가·왜» 와 함께 등재하는 구조 자체는 손대지 않았다.
바뀐 것은 **표가 19종으로 다 찼다**는 것이고, 근거가 셋인 자리(260 → 484 → 504)와 둘인 자리(484 → 504)를


⚠ **표가 다 차도 게이트는 무르지 않는다** — 세이브 호환이 걸린 축(id·등급·cd)은 **[1-a] 가 따로** 지키고,
제품이 이 등재값에서 다시 움직이면 [1-b] 의 `wrongVal` 이 곧바로 빨개진다. 두 자가 서로를 대신하지 않는다.

### ② `verify114` [7] «폭발 계열 피해 계수·쿨 불변» — **한 단언을 둘로 갈랐다**

부패의 뿌리는 값이 아니라 **두 축을 한 단언에 묶어 둔 것**이었다. `m` 이 움직이면 «쿨이 밀렸다» 까지
같이 빨개져 어느 쪽이 깨졌는지 알 수 없었다.

- **`폭발 계열 쿨타임 불변`** — 114 가 실제로 지키는 축이다(연출 길이가 쿨을 밀면 즉시 빨강). **어긋남 0건.**
- **`폭발 계열 피해 계수 = 484·504 등재값`** — 밸런스 값이라 움직일 수 있는 축. 5종 재정박
  (slash 5.5165 · boom 3.2049 · meteor 2.5476 · holy 2.0495 · nova 1.6465). **cd 는 한 칸도 안 움직였다.**

### ③ `sim197` — 세 줄 전부 NaN

**뿌리는 481** 이다(«펫 피해 = 플레이어 공격력 그대로 · 등급은 공격 주기만»). `PETS` 에서 `m` 을

`cpOld` NaN 으로 번졌다. 제품 셰이프를 직접 찍어 확인했다 — `PETS[0]` 의 키는
`id·n·g·j·sp·tint·v·cd` 뿐이고 `m` 은 없다.

⇒ **펫에는 197 축이 더 이상 걸리지 않는다.** 197 이 바꾼 것은 «착용값 mul→wear · 착용 레벨 기울기
