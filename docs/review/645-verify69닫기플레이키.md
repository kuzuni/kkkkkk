## §2 실재 — 껍데기는 «남은 것» 이 아니라 **되붙인 것**이다

`tools/probe645.js` 를 신설해 `#modal` 의 `classList.add/remove` 를 감싸 **변경자 스택까지** 채집했다.

```
 292.9ms remove on                  index.html:27256 ← (자, mailX 클릭)
 293.1ms remove sk8 q22 ml69 at70   index.html:27249 ← index.html:27257   ← closeModal 이 다 뗐다
 294.6ms add    ml69                index.html:39200 ← index.html:39235   ← 345 jzShellBack 이 되붙인다
 298.0ms add    ml69                index.html:39206 ← index.html:39235
 491.1ms remove ml69                index.html:39255 ← index.html:39260   ← done() = 퇴장 연출 끝
```

⇒ 자가 본 `ml69` 는 «닫기가 실패해서 남은 것» 이 **아니다**. `closeModal()`(27253)은 동기라
클릭과 **같은 tick** 에 `on`·`ml69` 를 둘 다 뗀다(표본 전부). 그 직후 **345**(«닫힘 연출 중 팝업이
제 치수를 잃는다»)가 만든 `jzShellBack`(39196)이 **일부러** 껍데기를 되살리고 `done()`(39251)에서 뗀다.
즉 자가 200ms 에 읽은 것은 **주인이 승인한 퇴장 연출의 한복판**이다.

**제품은 한 줄도 틀리지 않았다.**

## §3 옛 상수 200 은 연출 길이 **바로 위**에 얹혀 있었다

|---|---|---|---|
| 단독 | 7.8ms | **169ms** | 초록 |
| 3병렬 6표본 | 9.7~20.6ms | **196.6 · 197.1 · 199.3 · 232.1 · 249.7 · 255.8ms** | **6개 중 3개 빨강** |

세 표본이 196.6·197.1·199.3 — **3.4ms 차이로 초록**이었다. 상수가 분포 한복판에 박혀 있으니
«2회 중 1회» 는 우연이 아니라 그 자리의 정상 동작이다.

⚠ **그래서 상수를 200 → 600 으로 올리는 처방은 안 썼다**(334·638-③ 규약).
어떤 상수를 골라도 다음 부하에서 다시 깨지고, 그때도 «연출이 길어졌다» 와 «안 닫힌다» 를 못 가른다.
실측이 그 말을 그대로 확인한다 — 수리 뒤 5병렬의 실제 해제 시각은 **229~367ms** 로 여덟 표본 전부가
옛 상수를 넘겼다(단독은 169~176ms).

## §4 처방 — 한 항이 두 사실을 물고 있었다. 갈랐다

| | 옛 자 | 새 자 |
|---|---|---|
| | `click()` → **고정 200ms** → `!on && !ml69` 한 항 | |
| **[4-a]** | — | **클릭과 같은 tick** 에 `on`·`ml69` 가 떨어지는가 (`closeModal` 은 동기다 — **시간 축이 아예 없다**) |
| **[4-b]** | — | 제품의 «연출 중» 신호 `#modal.__jzBusy`(39237·39258)를 **읽기만 하며** 기다린 뒤 `!on && !ml69` |

- **[4-a] 는 옛 자보다 좁다.** 옛 자는 200ms 안의 어떤 지연도 봐줬지만 이 항은 한 tick도 안 봐준다.
- **[4-b] 의 폴링 시작점은 상수가 아니다.** 되붙이는 쪽(`jzClose`)은 `#modal` class 를 보는
  **MutationObserver**(39537)라 그 콜백은 이 tick 의 마이크로태스크에서 돌고 `requestAnimationFrame` 은
  그 뒤다 ⇒ «되붙기 전에 훔쳐보는» 창이 **구조적으로** 없다. `probe645` [D] 가 값으로 확인한다
  (같은 tick 에는 `__jzBusy=0`, **첫 rAF 에는 이미 1** — 7.8~20.6ms).
- 상한 4000ms 는 제품 자신의 폴백 2500ms(39265)보다 크게 잡았다.
