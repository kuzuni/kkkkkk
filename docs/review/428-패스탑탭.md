## 1. «자물쇠 풀기» 는 «준비 중 토스트» 로는 푼 것이 아니다

주인이 «자물쇠 풀기 / 잠금 풀기» 를 **두 번** 말했다. 수리 전 두 칸은 `.lk` + `<s class="lk">🔒</s>` 였고
눌러도 `notify('🔒 아직 해금되지 않은 패스입니다')` 뿐이었는데, **자물쇠 클래스만 떼면 그 다음이
«🔒 이 패스는 아직 준비 중입니다»** 다(`PASS_TABS` 에 없는 탭의 폴백). 즉 «푼 척» 하는 상태가 둘이나
줄지어 있었고, 지시서 «기능 완성 규칙»(T2 는 실동작이 완료 조건)대로 **둘 다** 넘어야 완료다.

## 3. ⚑ 진행도를 `S.tower` 그대로 쓰면 «깨기도 전에 1단계를 받는다»

`S.tower`/`S.tower2` 는 209·210 이 정의한 대로 **«지금 도전 가능한 레벨»** 이라 아무것도 안 깬
세이브에서도 **1** 이다. 그대로 `prog` 로 쓰면 `passOpen(0) = prog >= 1` 이 참이 되어 부팅 직후
1단계 보상이 열린다. 스테이지 패스의 `S.best`(= **달성한** 값)와 뜻을 맞춰

```js
const passTowerLv = id => Math.max(0, towerFloor(towerById(id)) - 1);
```

로 읽는다. 키를 여기서 다시 고르지 않는 것이 중요하다 — `towerFloor` 한 곳이 `TOWERS[].fk` 를 본다
(209·210 «어느 키를 쓰는지는 `fk` 한 곳에만 적는다»). `verify428` [D] 가 «한 레벨도 안 깼으면 0단계» ·
«`S.tower` 6 → 5단계» · **«시련을 올려도 절망은 안 열린다»** 셋을 각각 잰다.

## 4. ⚑ 등재문과 갈린 자리 둘 — 보상 재화와 라벨 scaleX

**ⓐ 보상은 다이아다.** 등재문은 «그 탑의 산출 재화(시련 = 유물조각 · 절망 = 단련석)» 를 적었지만,
**398·399(주인 원문 «패스 보상 출석보상 전부 다이아로 줘라», 2026-08-29)가 더 나중이고 더 넓은 지시**다.
그리고 그 결정은 이미 **게이트로 굳어 있다** — `verify398` §1 은 `Object.keys(PASS_TABS)` 를 돌며
«전 칸 보상 키가 dia 하나» 를 재므로, 유물조각·단련석을 넣으면 새 탭을 넣는 그 순간 빨개진다.
(등재문의 «398 «보상은 재화 하나» 규약» 은 «한 탭에 한 재화» 로 읽었지만, 398 이 실제로 못박은 것은
**«그 하나가 dia»** 다.) 곡선도 새로 만들지 않고 `PASS_CUR` 공용을 쓴다.

**ⓑ 라벨 `scaleX` 두 줄을 걷어냈다.** 9회차가 ref 전용 서체 폭(«보물상자 114 / 시련의탑 130»)에 맞춰
`scaleX(1.07)` · `scaleX(1.228)` 을 걸어 뒀는데 **맞출 대상이 사라졌다** — 새 두 라벨은 레퍼런스에 없는
주인 지시 신설 콘텐츠다. 1.228 을 5글자(«시련의 탑», 공백 포함)에 그대로 얹으면 잉크가 비활성 칸
190px 을 넘는다. 공용 1.15 로 두고 실측: **111.0 / 113.1px, 넘침 0**(측정표 35 §3-1 정오표).
