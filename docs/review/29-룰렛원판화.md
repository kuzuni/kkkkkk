### 2.1 각도 규약 (다른 원형 UI에도 그대로 쓴다)

`conic-gradient` 은 **0deg = 북 · 시계방향**이므로 세그먼트 `i` 는 `[i*45, (i+1)*45]`, 중심각은 **`i*45+22.5`** 다.
포인터는 북(0deg)에 고정이므로 **원판 회전각이 `−(중심각)` (mod 360)** 이면 그 칸이 포인터 아래 «중심» 에 선다.

```
c      = idx*45 + 22.5
base   = rouRot + 360*6              /* 최소 6바퀴 */
target = base + (((-c - base) % 360) + 360) % 360
```

감속은 **easeOutQuart** `1-(1-p)⁴` · 3600ms · `requestAnimationFrame`.
정지 시 `rouRot` 을 `mod 360` 으로 정규화한다(회전 변환은 360의 배수 차이가 시각적으로 동일하므로 튐 없음.
연속 5회를 돌려도 누적 각도가 커지지 않는다).

세그먼트 색·라벨은 **전부 `ROULETTE` 배열에서 생성**한다(`roulSegColor`/`roulLabel`) — 보상 8종을 고치면 원판이 따라간다.
칸 라벨은 `아이콘 / 이름 / 값` 3줄이며, 값은 `goldMul → ×25`, `dia → 400`, `rel → 150`, 둘 다면 `💎6.00K` `🔮1.50K` 2줄이다.

## 7. 교훈 (다른 화면에서도 재발한다)

1. **`conic-gradient` 각도 규약을 UI 로직과 같은 식으로 적어 둬라.** 25 교훈 1(«중심점이 꼭짓점»)의
   회전판 버전이다 — `0deg = 북 · 시계방향`이라 세그먼트 `i` 의 중심은 `i*45+22.5` 이고,
   그 칸을 북에 세우려면 원판을 **`−중심각`** 만큼 돌린다. 부호를 한 번 뒤집으면 «항상 옆 칸이 당첨» 인
   버그가 되는데, 하이라이트를 같이 칠하면 **화면상으로는 멀쩡해 보여서 아무도 못 잡는다.**
   → 검증은 «하이라이트가 켜졌나» 가 아니라 **회전각으로 포인터 아래 칸을 역산해** 대조해야 한다(§3 절 6).
2. **회전각을 `mod 360` 으로 정규화하면 자체 검증 스크립트가 깨진다.** 정규화 프레임에서 각도가
   2498 → 38 로 «점프» 해서 «감속 안 함» 오판이 났다(시각적으로는 완전히 동일하다).
   rAF 애니메이션을 샘플링해 속도를 재는 스크립트는 **«애니메이션 중» 플래그로 마지막 프레임을 걸러라.**
3. **원형 배치에서 라벨이 옆 칸을 침범하는지는 캡처를 보지 말고 계산해라.** 중심에서 거리 `r` 인
   지점의 반현은 `r·tan(180°/2n)` 이다. 라벨 줄의 **바깥이 아니라 «안쪽(중심에 가까운) 모서리»** 가
   가장 빡빡하므로 거기서 판정한다. 세그먼트 회전을 잠시 `none` 으로 돌리고 `Range.getBoundingClientRect()`
   로 **글자 실폭**을 재면 박스 폭(186)이 아니라 잉크 폭(칸 7 = 102)으로 판정돼 과잉 축소를 피한다.
4. **«팝업을 다시 그려서 결과를 보여주는» 구조는 애니메이션과 양립하지 않는다.** 기존 `openRoulette(hit,txt)`
   는 당첨 칸을 인자로 받아 `showModal()` 로 통째로 재렌더했다. 원판은 회전 중 DOM 이 살아 있어야 하므로
   **«렌더» 와 «갱신» 을 분리**해야 한다(`openRoulette()` = 렌더 1회, `roulSpinTo`/`roulFinish` = 제자리 갱신).
   같은 구조가 09·12·17 결과 연출과 58 공용 모듈에도 그대로 필요하다.
