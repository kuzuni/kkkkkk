«커졌다 돌아온다» 가 **«커졌다 → 정지보다 작아졌다 → 돌아온다»** 로 끝난다.

### ⚑ 눈에 보이는 대가를 한 자리 찾았다 — 12 소환 결과 좌단 칸이 **9.27px 더 잘린다**

`fxPop` 이 붙는 가장 넓은 자리(12 소환 결과 카드 `.sm-c`)의 그릇은 `.sm-grid{overflow-x:hidden}` 이고

클립량 = `w(s−1)/2` 이고 카드 폭은 158 이다:

| scale | 좌단 칸 클립량 | |
|---|---|---|
| 1.2000 (선언 봉우리) | **15.80px** | 산수와 일치 |
| **1.3174 (실효 봉우리)** | **25.07px** | 선언보다 **+9.27px (+58.7%)** |

즉 «1.2배까지 커졌다 돌아온다» 로 적어 둔 연출이 실제로는 **1.32배까지 커지면서 왼쪽 칸의 림을 25px 먹고**
있었다. 이 자리는 `verify983` [C2]·[C3] 이 지킨다(되돌리면 [R-e] 가 25.07 을 다시 찍는다).

⚠ **첫 판은 이 표를 잘못 찍었다** — 좌단 칸을 `getBoundingClientRect()` 로 골랐더니 그 순간 팝이 걸려 있던
**6열 칸**이 (스케일 때문에 위·왼쪽으로 번져) «가장 위·가장 왼쪽» 을 가로챘다. 칸 고르기는 **레이아웃
좌표**(`offsetTop`/`offsetLeft`)로 해야 한다. 같은 자리에서 두 번째 함정도 나왔다 — 60 쥬시 스태거가
카드마다 `animation-delay` 를 주는데 `Animation.currentTime` 은 **지연을 포함**하므로 그냥 `t` 를 넣으면
전부 «아직 시작 전»(scale 0)이 찍힌다.

## 2. 처방 — 토큰 **셋**(979 · 890 · 93 29회차 · 894 와 같은 처방)

```
  .fx-cvswap{animation:fxCvSwap .34s cubic-bezier(.34,1.56,.64,1) both}   → … .34s linear both}
  .fx-pop   {animation:fxPop    .34s cubic-bezier(.34,1.56,.64,1) both}   → … .34s linear both}
  .fx-hit   {animation:fxHit    .26s cubic-bezier(.34,1.56,.64,1) both}   → … .26s linear both}
```

* **키프레임 값(.84/1.07/1 · 0/1.2/1 · 1/1.05/1)·정지점 자리·수명·채움 `both` 는 Δ0** —
  `fxPop` 의 **opacity 채널까지** 한 글자도 안 건드렸다([A5]). 완화를 «진폭을 줄여서» 얻지 않았다는 것을
  [A1a]~[A1c] 가 못박는다. 이 값들의 소유자는 이 행이 아니다(58·93·12·683 계열 라운드).
* **왜 `ease-out` 이 아니라 `linear` 인가** — 979 §3 그대로다. `ease-out` 은 봉우리 값은 지키지만
  구간 경계에서 속도가 0 → 최대로 튄다(890 «급락 → 정체»). **정지점이 곡선을 이미 표본하고 있으면
  이징은 곡선이 아니라 왜곡이다**(894 §6 ②).
* 셋을 **같이** 갈아야 `verify979` [B5] 래칫이 «남은 자리 = `fxToastIn` 하나» 로 닫힌다.

## 6. 교훈

1. **같은 기계는 같은 처방으로 닫되, 자의 «허용치» 는 부품마다 다시 정한다.** 979 → 983 은 처방을
   그대로 옮겨 쓸 수 있었지만 **문턱은 못 옮겼다** — 진폭이 가장 작은 판(`fxHit` +0.0049)이 선례의
   0.01 안에 통째로 숨었다. 옮겨 적은 문턱은 «있어 보이는 자» 를 만든다.
2. **894 의 «재가속» 절대값은 이 셋에 문턱으로 못 쓴다.** `linear` 로 갈아도 3.69·5.96·7.30 인데
   같은 값·linear 와 **정확히 같다**(이징 몫 ×1.00) — 정지점 셋인 팝의 그 값은 **값의 성질**이지 이징의
   죄가 아니다. 979 가 `fxCvSwapS` 에서 ≤3.0 을 쓸 수 있었던 것은 그 부품의 값이 완만해서였을 뿐이다.
   ⇒ 남의 자를 빌릴 때는 **그 자의 문턱이 무엇의 성질인지**부터 갈라라.
3. **연출을 «실물 기하» 로 잰다면 칸 고르기는 레이아웃 좌표로 해라.** `getBoundingClientRect()` 는
   그 순간 걸린 transform 이 곱해진 뒤라, 팝이 걸린 칸이 «가장 위·가장 왼쪽» 을 가로챈다
   (첫 판이 6열 칸을 좌단으로 집었다). 그리고 **스태거 지연이 있으면 `Animation.currentTime` 은
   지연을 포함**한다 — `delay + t` 로 넣지 않으면 전부 «시작 전» 이 찍힌다.
4. **가장 큰 오차가 가장 넓게 붙은 부품에 있었다.** `fxPop`(+9.78%)은 12 소환 결과·보상 팝 등
   붙는 자리가 가장 많은 부품인데, 979 가 셋을 안 고친 이유가 바로 그 «값 소유자와 부딪힐까» 였다.
   실제로 부딪히는 것은 **값이 아니라 이징**이었고(값 Δ0), 그래서 소유자 라운드를 기다릴 필요가 없었다.
