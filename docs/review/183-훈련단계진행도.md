## 고친 것 (1곳, `index.html` ~14182)

```js
const trainBase  = () => (trainStage() - 1) * TRAIN_CAP_STEP;   /* 이전 단계까지의 스탯당 몫 */
const trainLvRel = id => Math.max(0, Math.min(lv(id), trainCap()) - trainBase());
const trainProg  = () => TRAIN_STATS.reduce((s, id) => s + trainLvRel(id), 0);
const trainMax   = () => TRAIN_STATS.length * TRAIN_CAP_STEP;   /* 300 고정 */
```

- 분자는 **스탯별로** 이전 단계 몫을 빼고 `[0, 100]` 으로 물린다(`Math.max(0, …)`).
  합을 통째로 빼면 «한 스탯이 이전 단계 몫에 못 미치는» 비정상 세이브에서 다른 스탯의 몫과 상쇄돼 숫자가 흐려진다.
- **표시만 상대화한 것이다.** `S.lv.*` 저장값 · `trainCap()`(= 단계×100) · `trainReady()`(전 스탯 ≥ cap) ·
  `trainBuyInfo()` 의 `room` 계산은 전부 절대값 그대로다 → 저장 구조 불변, 마이그레이션·KEY 버전 불필요.
- `trainProg`/`trainMax` 는 `trSyncHead()` 한 곳에서만 쓰인다(전수 grep). 진행바 폭이 같은 값을 쓰므로 바도 자동으로 같이 리셋된다.
- 168(스탯 «효과값» 선형화)은 `val` 곡선 작업이라 이 구간과 겹치지 않는다 — 병행 무방.
