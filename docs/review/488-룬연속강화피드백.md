## §1 재현 먼저 (338 규칙) — 등재문이 **그대로 확인**됐고, 범위는 등재문보다 넓었다

`tools/probe488.js` 신설. 세는 것은 지시 ④ 의 눈금 그대로 «**시도 한 번당 보이는 사건**» 이고,
셋을 독립으로 잰다: ⓐ `#fxl` 에 붙은 노드(MutationObserver childList) ·
ⓑ **홀드 호스트 안에서** 일어난 애니메이션 클래스(`jz-*`/`fx-*`) 토글 ·
ⓒ 각 자리가 실제로 부르는 «1회» 함수 호출 수(`runeBuy`·`temperUpBtn`·`levelUp`·`summonRelic`·`trainBuy`).

같은 하네스·같은 손(터치 ±2px 떨림 · 게임 루프 ON · 실제 확률)으로 **수리 전 트리와 수리 후 트리**를

### ⚠ 1회차 계측 함정 — «전수로 세면 초록이 나온다»
처음엔 클래스 토글을 `document.body` 전수로 셌다. 그러자 룬이 «시도당 **1.36**» 으로 나와
**결함이 없는 것처럼 읽혔다.** 그 34건은 전부 팝업 뒤 02 메인 화면 스킬 슬롯의 쿨타임 글로우
(`jz-cdok`/`jz-cast`)와 전투 골드의 HUD 반응이라 룬 강화와 아무 상관이 없다.
스코프를 «홀드 호스트 안» 으로 좁히자 **0.00~0.04** 가 됐다.
→ LESSONS 488-① (A3-ⓔ «마스크가 다르면 다른 것을 잰다» 의 재판).

### ⚠ 2회차 계측 함정 — 조상 결합자를 쓴 호스트 셀렉터는 항상 null
수리 뒤 `jz-hb@tr-rn` 이 분명히 찍혀 있는데 «호스트 사건 0» 이 나왔다. 홀드가 끝나면
`end` 의 `renderTrain()` 이 카드를 `innerHTML` 로 갈아 끼우므로, 기록해 둔 노드는 그때
**떨어져 나간다** — 떨어진 노드에서 `closest('#trRunes .tr-rn[…]')` 는 `#trRunes` 조상이 없어
영원히 null 이다. 호스트 판정 셀렉터는 **자기 자신만으로 매치되는 것**이어야 한다.
→ LESSONS 488-②.

### 안 한 것과 그 이유
- **토스트를 회당 쌓지 않았다.** 60ms 주기로 쌓으면 206 규약(스택 4장 드롭)이 즉시 깨지고
  `#fxl` 이 FXMAX(120)로 막힌다. 정산 요약 토스트 한 장은 `end` 에 **그대로 뒀다**(지시 ②).
- **`−n` 을 HUD 알약(`fxPay`)에 안 붙였다.** 이유 셋 — ⓐ `fxPay` 는 `FX_PAY_GAP` **320ms** 스로틀이라
  홀드 주기(60~160ms)에서 시도의 1/3 만 찍는다 ⓑ 룬 재료 `S.rstone`·단련 포인트는 **HUD 알약이
  아예 없다**(`FXCUR` = gold·dia 둘뿐) ⓒ 꾹 누르는 동안 눈은 카드에 있다.
  HUD 쪽 `fxPay` 는 **한 줄도 안 건드렸다** — 골드·다이아 결제의 «알약 움푹» 은 종전 그대로 같이 뜬다.
- **`dunRunProg` 식 판정·밸런스 0줄.** 확률·비용·레벨 계산은 한 글자도 안 바뀌었다.
- **64 의 «정지 시 정산»(`trHoldStop` 의 `fxUpOk`)은 그대로 뒀다.** 64 가 «반복분은 정지할 때 한 번»

  `#fxl` 이 막힌다). 여기서 얹은 것은 그보다 훨씬 가벼운 «맥박 + 플로터 두 장» 이다.

## §4 게이트 — `tools/verify488.js` **46/46 PASS**

지시 ④ 가 «시도마다 보이는 사건 ≥ 1» 로 완료 조건을 못 박았으므로 «≥1» 이 아니라 **«= 시도 수»** 를 센다.
두 자를 맞대는 것이 요점이다 — ⓐ 부품 호출 수(`hbPulse`/`hbFloat` 래핑 · 반환 false = 유실)
ⓑ 실제 DOM(`#fxl` 의 `.fx-plus.hb` 노드 · 호스트의 `jz-hb`/`jz-hbx` 토글).
둘이 어긋나면 «불렀는데 안 보인다» 이므로 그 자체가 결함이다.

- **[A] 1~4** 부품 3개 선언 · CSS 두 갈래 · 플로터 CSS 와 `.dn` · 키프레임 4종
- **[B] 1~18** 룬 — `runeRate` 를 1/0 으로 고정해 **성공 축·실패 축을 갈라** 단언.
  맥박 = 시도(16/16 · 19/19) · «+1 Lv» = 시도 · «실패» = 시도 · «−n» = 시도(실패해도 나간다) ·
  비용만 `.dn` · 색 3종(초록 `rgb(46,125,20)` · 빨강 `rgb(176,27,46)` · 갈색 `rgb(122,58,16)`) ·
  **정산 토스트 한 장**
- **[C] 1~4** 단련 — 확정 처리라 흔들림 0 · 맥박 = 시도 = 19
- **[D] 1~4** 08 세부 — beat = **시도 − 1**(첫 발은 `fxUpOk`). 두루뭉술한 «≥» 로 덮지 않고 규약을 상수로 박았다
- **[E] 1~4** 유물 — 맥박·비용 = 시도 − 1 · **결과 문구는 0건**(격자 칸의 «이름 Lv.n» 델타와 두 벌이 되면 안 된다)
- **[F] 1~3** 훈련 — 맥박·«−n» = 시도 − 1
- **[G] 1~5** 진폭 §3 을 실측 rect 로 재검
- **[R] 1~3 되돌림 시험** — `hbBeat` 를 no-op 으로 바꾼 사본에서 **맥박 0 · 플로터 0**,
  그런데 **요약 토스트 한 장은 그대로 남는다**(488 이 206 을 안 건드렸다는 음성항)

수리 전 트리(`V488_FILE`)에 걸면 **[A]4건·[B]~[F] 전부 빨강**. 3회 연속 실행 46/46 로 안정.

### ⚠ 게이트 계측 함정 — `jzOn` 의 «remove → 리플로우 → add» 왕복
`jzOn`(35184)은 같은 애니메이션을 재시작하려고 클래스를 뗐다 다시 붙인다. 그 왕복이 한
MutationObserver 배치에 **두 레코드**로 들어오고, 콜백 시점의 `className` 은 둘 다 «붙은 뒤» 라
제 눈에는 «두 번 걸린 것» 으로 보인다(부품 호출 19 인데 이 자만 21 을 셌다).
한 배치·한 노드·한 클래스는 **한 번의 걸림**으로 접었다 — 비트 간격이 최소 60ms(`TR_HOLD_IVMIN`)라
두 비트가 같은 배치에 들어올 수 없으므로 이 접기는 참 사건을 지우지 않는다. → LESSONS 488-③.

### ⚠ 토스트는 «전체 개수» 로 세면 안 된다
[R3] 이 1회차에 2~3 을 오갔다. 훈련 단계 상승·가이드 미션 등 **다른 계통의 토스트**가 같은 창에
섞이기 때문이다. 정산 토스트는 «전체 개수» 가 아니라 **문구로** 골라 센다(`/회 시도 · 성공/`).
→ LESSONS 488-④.
