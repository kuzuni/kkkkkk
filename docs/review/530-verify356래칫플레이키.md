## 2. ⚑ 이 작업의 본체 — **뿌리가 하나가 아니라 셋이었다**

### ⓐ 찰나의 연출 노드가 판정에 섞인다 — «상시» 가 아니다

356 [A] 가 지키려는 성질은 자기 문구 그대로 «**상시** 크롬 아이콘의 종횡» 이다.
그런데 스윕은 재화 비행(`#fxlc > .fx-fly > img.cic`)·알약 펀치(`.cbox.cGold.fx-punch > i > img.cic`)를
같이 쟀다. ⇒ **재기 전에 페이지를 «상시» 상태로 되돌린다**(연출 레이어 `#fxlc`·`#fxl` 비우기 +
`fx-*` 클래스 걷기).

⚠ **«판정에서만 뺀다»(등재문 후보 ①)를 안 고른 이유**: 무엇을 뺐는지가 결과에 안 남아 스코프가
조용히 줄고(397 «무음 실패» 사고), 이웃 아이콘은 **여전히 그 연출에 가려진** 채 판정된다.
걷어 내면 둘 다 사라진다. 그리고 걷은 수(`fx`·`fxCls`)를 **결과에 실어 돌려준다**.

### ⓑ **비우기만으로는 모자랐다** — 정지 뒤에도 연출 노드가 «또» 태어난다

레이어를 비우고 180ms 뒤에 재니 5화면 25회에서 **12건**이 도로 잡혔다.
`clearInterval/clearTimeout(1..20000)` 은 **그 순간** 걸려 있던 타이머만 지우므로, 게임 틱이
그 뒤에 새로 잡은 타이머는 계속 돈다. ⇒ 레이어를 **`display:none` 으로 내린다** — 그 뒤에 무엇이
생겨도 rect 가 0 이라 COLLECT 의 «8px 미만은 건너뛴다» 에 걸려 판정에 절대 안 섞인다.

### ⓒ ⚑ **정지 절차 자신이 «무한 반복» 을 한 번도 못 세우고 있었다**

8회차가 놓은 정지는 `for (const a of document.getAnimations()) { try { a.finish(); } catch (e) {} }` 다.
**무한 반복 애니에서 `finish()` 는 던진다**(`Cannot finish Animation with an infinite target effect`) —
그 예외를 `try/catch` 가 삼켰고, `clearInterval`·rAF 무력화는 **CSS 애니를 안 멈춘다**(합성기에서 돈다).
⇒ 122 가 넣은 «가만히 있어도 살아 있는» 상시 쥬시가 **차분 두 장 사이에도 계속 돌고 있었다.**

실측(13 재화 탭 · 정지·정규화를 다 마친 뒤):

```
DIV.gem  animation-name = jz122Float      top = 360.736 / 360.212 / 360.654 …
document.getAnimations() → 183~186개 중 jz122Float·jzDotPulse·jzUpN 이 running
같은 페이지에서 500ms 더 기다리면 top 이 또 달라진다 (360.736 → 360.6719)
```

`pause()+currentTime=0` 으로는 **안 닫혔다** — 재렌더가 **새 CSSAnimation 을 계속 만든다.**
⇒ 판정 직전에 «애니는 없는 것» 이라고 **선언**한다:
`*,*::before,*::after{animation:none!important;transition:none!important}`.
그러면 요소가 자기 **기본 자리**에 선다 — 그것이 356 이 재려는 «상시» 기하다.

⚠ **선언이 스코프를 줄일 수 있다**(`fill:forwards` 로만 보이던 노드). 그래서 선언 **전후로**
«잴 수 있는 노드» 수를 세어(`COUNT_VIS`) 줄었으면 `stillLost` 로 신고한다 — 게이트가 0 을 단언한다.
**조용히 줄지 않는다.**
