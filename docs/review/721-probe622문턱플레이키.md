## 2. 뿌리 — 자가 «잡음 폭 안»에서 부호를 묻고 있었다

### [3-d] — «조금이라도 가까우면 뿌리» 라는 자
옛 판정식은 `closer(k) = |m/decl − 1| < |base/decl − 1|` 였다. 즉 되돌림 값이 base 보다
**0.01 이라도** 선언 쪽이면 «그 손잡이가 뿌리다» 로 읽는다.

그런데 용의자 되돌림 셋은 base 와 **잡음 안에서 겹친다**:

| 축 | 5회 실측 | 현행 대비 변화율 |
|---|---|---|
| base(현행) | 15.83 ~ 16.67 (평균 16.23 · 폭 **±2.7%**) | — |
| `c541`(잡몹 반경) | 15.75 ~ 16.82 | **+2%** |
| `ply`(플레이어 이속) | 15.75 ~ 15.88 | **−0%** |
| `pr15`(플레이어 반경) | 15.88 ~ 16.30 | **0%** |
| `a580` / `mob` / `ac` | 8.7 ~ 10.3 | −36 ~ −43% |

셋의 «변화» 는 전부 측정 잡음보다 작다 — 어느 쪽이 위로 가느냐는 **동전 던지기**다.
[3-c] 는 같은 사실을 이미 «±15% 안에서 안 움직인다» 로 옳게 적고 있었다(그래서 초록이었다).
**같은 사실을 [3-d] 만 «부호» 로 물었고, 그래서 혼자 빨갰다.**

⚑ **곁다리로 잠복 하나를 같이 걷어냈다** — `[3-a]`·`[3-b]` 도 같은 `closer()` 를 쓴다.
`[3-b]` 의 `ply` 는 base 와 0.04 차이까지 붙은 실행이 있었다(5회차 base 15.83 ↔ ply 15.79).
**아직 안 터졌을 뿐 같은 함정 위**였고, 자를 바꾸면서 셋이 같이 나았다.

### [3b-c] — 옛 문턱 0.85 가 분포 한복판을 지난다
불사 축은 판별 sd 4.6 짜리 **가장 넓은 축**이다(한 실행 안 6판이 17 ~ 36.6 까지 벌어진다).
16회 풀에서 **선언 대비 74 ~ 95%**(평균 82.4 · sd 5.8%p)인데 문턱이 **0.85** 였다 —
**16회 중 9회가 그 아래**다. 문턱이 분포 밖이 아니라 **한복판**에 있었다.

## 3. 처방 — 문턱을 «잰 값» 에서 다시 뽑았다(504-④)

등재문의 후보 ⓐ(문턱 재산출)를 골랐다. ⓑ(하네스를 `rul504.js` 로 이관)는 **자 하나를
통째로 옮기는 일**이라 이 행의 범위(자 플레이키)를 넘고, `[3b-c]` 의 불사 축은 어차피 따로
선언해야 해서 옮겨도 이 두 항의 흔들림은 안 없어진다.

**⑴ «뿌리» 의 정의를 바꿨다** — 부호가 아니라 **간극을 얼마나 메웠나**:

```js
const REACH = 0.50;                                   /* 현행↔선언 간극의 절반 */
const reachBar = () => base.m + REACH * (decl - base.m);
const nearsDecl = m => m >= reachBar();               /* 옛 closer() 자리 */
```

문턱 **22.6 ~ 23.0** · 용의자 최댓값 **16.82** ⇒ 여유 **6.0(잡음 폭의 13배)**.
개체수 40(27~28.4)·불사(21.8~27.8)는 이 자로도 그대로 «뿌리» 로 읽힌다 — **결론은 안 바뀐다.**

**⑵ 불사 항은 문턱을 분포 밖으로 내리고 축을 하나 더 세웠다**:

```js
const HPINF_DECL = 0.65;   /* 선언 대비 — 평균 82.4%에서 3.0σ 아래(실측 최저 74%) */
const HPINF_OVER = 1.15;   /* 현행 대비 — 평균 1.51배에서 3.3σ 아래(실측 최저 1.33배) */
hpOk = (m, ki) => m >= decl * HPINF_DECL && m >= base.m * HPINF_OVER && ki === 0;
```

«현행 대비» 축을 더한 것이 핵심이다 — 선언 대비 하나만 낮추면 «문턱을 내렸다» 로 끝나지만,
**용의자 되돌림은 전부 현행의 1.03배 안**이라 이 축은 잡음과 구조적으로 안 겹친다.

⚑ **표본을 늘리는 길은 막혀 있다(실측으로 확인)** — `K` 를 6 → 18(3배)로 올려 5회 다시 재 봤다.
실행 간 폭이 **안 줄었다**: K=6 은 23.23~26.09 · K=18 은 **22.04~27.22 로 오히려 넓다.**
⇒ 이 축의 흔들림은 «판» 이 아니라 **«실행» 단위**다(판마다 플레이어 자리를 안 되돌리므로
한 실행 안 6판이 서로 독립이 아니다). K 는 6 으로 되돌렸다 — **시간만 쓰고 값을 못 산다.**

## 4. 무르게 푼 수리가 아님 — §R 되돌림 시험 4항 신설

문턱을 내린 수리는 «헛초록» 의문을 남기므로, 바뀐 두 판정식에 **거짓인 사본**을 먹여
빨개지는지 산술로 못박았다(368 §R 규약 · 브라우저 재실행 없이 판정식만 잰다).

| 항 | 무엇을 못박나 | 실측 |
|---|---|---|
| **[R-a]** | 잡음 폭(현행 ×1.05)·용의자 최댓값은 «뿌리» 로 **안** 읽힌다 | 16.7~17.3 · 16.8 < 문턱 22.6~23.0 |
| **[R-b]** | **진짜로** 선언에 닿는 손잡이(선언 자신 · 개체수 40)는 새 자로도 «뿌리» | 29.36 · 27.0~28.4 ≥ 문턱 |
| **[R-c]** | 불사가 «안 부푸는» 사본(현행값 · 문턱 바로 아래 18.50)은 [3b-c] **빨강** | 둘 다 빨강 |
| **[R-d]** | «장판 안 사망 0» 전제가 깨지면 [3b-c] **빨강** | 같은 발수라도 1건이면 빨강 |

⚠ **[R-b] 에 `hpinf` 는 안 썼다** — 그 축은 문턱에서 3σ 안이라 넣었으면 **새 헛빨강**이 된다.
«자가 무르지 않다» 는 것은 **안 흔들리는 축**(선언 자신 · 개체수 40)으로 보인다.
