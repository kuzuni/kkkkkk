## 1. 무엇이 바뀌었나 — 한 줄

던전 입장 횟수는 **«오늘 남은 횟수»(일일 리셋) 가 아니라 «보유 입장권»(영구)** 이 됐다.
저장 위치 `S.daily.dun` → **`S.dunTk`**, 리필 경로 `dailyCheck()` → **`claimAttend()` + 상점 교환**.

## 2. ① 적립식

| 항목 | 종전 | 204 |
|---|---|---|
| 저장 | `S.daily.dun[id]` (일일) | **`S.dunTk[id]` (영구)** |
| 충전 | `dailyCheck()` 가 매일 `DUN_TRY(3)` 로 **리셋** | **출석 수령마다 던전별 `+DUN_TRY(2)`** · 상점 교환 |
| 상한 | 3 (리셋이 곧 상한) | **없음** — 안 쓰면 `3/2 · 5/2` 로 쌓인다 |
| 표기 | `N/3` | `N/2` (분모 = `DUN_TRY`, **N > 분모가 정상**) |

- `DUN_TRY = 2` 는 이제 **두 뜻을 겸한다**: ⓐ 출석 1회 적립량 ⓑ 표기 분모.
  하나로 묶은 이유는 «출석 1회분이 곧 기준» 이라 값이 갈리면 «2장 받는데 분모는 3» 같은 어긋남이
  생기기 때문이다. 던전이 늘어도(194 강화석 · 203 룬) 값은 그대로 — 적립은 «던전마다» 다.
- `DUN_TRY_OLD = 3` 은 **구 세이브 승계에만** 쓰는 상수다(아래 §4).
- 소비처는 종전 그대로 두 곳이다 — `challengeDungeon()`(도전) · `sweepDungeon()`(소탕).
  둘 다 1장씩 쓰고, 0장이면 막힌다.

### 교환가 — **199 의 평가 대상**(주인 명시)

여기 값은 «굴러가는 잠정치» 다. 199(최종 밸런스 비평 라운드)가 수급 총량표를 세울 때 정하며,
그때 고칠 곳은 **`DUN_EX_BASE` · `DUN_EX_K` 두 상수뿐**이다.

잠정치의 근거(눈대중 아님): `기준가 300 × 던전 난이도 계수 k`, 십의 자리 절사.
`k` 는 던전 `req` 곡선의 배수를 그대로 쓴다 — relic1 을 1 로 두고 REL_DUN 의 `k` 가 2.5/6/15,
골드·다이아·강화석·룬은 각 `req` 계수 ÷ relic1(2500·4000·4200·4600 / 5000)를 반올림.
15배를 그대로 곱하면 4,500 다이아라 «다이아로는 사실상 못 산다» 가 되므로 **상위 단은 √k 로 눌렀다** —
«상위 던전일수록 출석 적립이 주 수급처» 라는 성질은 남기면서 막차는 열어 둔다.
