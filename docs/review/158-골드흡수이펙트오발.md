## 1. 원인 (실측으로 확정)

`fxSrc()`(index.html ~22406)는 발원을 **«명시 힌트 `fxAt`(600ms) vs 마지막 탭 `fxTapEl`(1200ms)» 중
더 최근 것**으로 고른다. 문제는 이 판정이 **발사 시점**에 일어난다는 것이다.

전투 킬 골드의 경로는 이렇다:

```
killEnemy → fxAt(fxWorld(...), 'combat')   ← 발원: 적이 죽은 자리
          → S.gold += g
fxWatch()  → fxAcc.gold 에 누적 (quiet 45ms, 최대 900ms 까지 묶는다)
          → 나중에  fxFly(fxSrc(now), 'gold', fxAcc.gold)   ← 여기서 발원을 «지금» 다시 묻는다
```

즉 **골드는 최대 900ms 동안 묶여 있다가 뒤늦게 발사**되는데, 그 사이에 사용자가 하단 네비·팝업·✕ 를
누르면 `fxTapT` 가 `fxOrigT` 보다 최근이 되어 **탭 좌표가 이긴다.** 그러면

1. 전투에서 번 골드가 **방금 누른 버튼에서 튀어나오고**(= 주인이 본 그림),
2. 그렇게 뺏긴 출발점에는 `combat` 태그가 없으므로 레이어가 `#fxlc`(z7, 팝업 아래)가 아니라
   **`#fxl`(z60, 팝업 위)** 로 가서 **작업 77(⚑ «전투 발은 팝업 아래»)까지 같이 깨진다.**

게이트로 재현한 수치(수정 전 코드):

| 상황 | 결과 |
|---|---|
| 킬(300,1500) 누적 → 발사 전에 하단 네비 탭 → 발사 | 발원 = **탭 지점(오차 0px)**, 킬 자리에서 **716px** |
| 같은 묶음의 레이어 | `#fxl` 에 **16개** (팝업 위) · `#fxlc` **0개** |
| 자동 전투 중 네비 5칸 8초 연타 | `#fxl` 에 **52~93건** 이 튄다 |

## 2. 처방

**발원을 «발사 시점» 이 아니라 «누적 시점» 에 스냅샷한다.** 발사 시점 판정이 버그의 뿌리이므로
그 자리를 없앤다 — 재화가 실제로 늘어난 그 프레임의 출처를 적어 두면, 이후 어떤 탭도 묶음을
가로챌 수 없다.

수정 3곳 (`index.html`, 전부 `fxWatch()` 구간):

1. `const fxAccSrc = { gold:null, dia:null }` 신설 — 묶음별 발원 스냅샷.
2. 누적 지점(`fxAcc[k] += d` 옆)에서 `fxAccSrc[k] = fxSrc(now) || fxAccSrc[k]`.
   **매 증가마다 갱신**하므로 연속 킬에서는 마지막 킬 자리가 남는다(종전 동작 유지). 획득이 멈춘
   뒤에 들어온 탭은 더 이상 끼어들지 못한다.
3. 발사 지점에서 `fxFly(fxSrc(now), …)` → **`fxFly(fxAccSrc[k], …)`**. 여기서 `fxSrc(now)` 로
   **되묻지 않는다** — 되물으면 «누적 뒤에 누른 탭» 이 다시 끼어들 틈이 생긴다.
   스냅샷이 `null` 인 묶음(발원 불명)은 종전대로 `fxFly` 의 기본값(화면 중앙)으로 간다.
4. 덤 — 묶음 디바운스 `quiet` 도 전역 `fxOrigSrc` 가 아니라 **그 묶음의 스냅샷**으로 정한다.
   종전 전역 판정은 다이아(UI 발)와 골드(전투 발)가 같이 떠 있을 때 서로의 디바운스를 바꿨다.

**건드리지 않은 것**: `fxSrc()`·`fxAt()`·`fxTapEl` 리스너 자체는 그대로다(93·77 구간). 탭 힌트는
UI 발 획득에서 여전히 «누른 자리에서 날아가는» 그림을 만든다 — 아래 [D] 회귀 참조.
