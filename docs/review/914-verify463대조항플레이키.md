## §3 뿌리 — [0] 의 200ms 창은 «주입한 스타일만 그림을 바꾼다» 를 전제한다

`[0]` 이 하는 일은 이것이다.

```
shoot(N)                     ← 지금 그림
setStyle(injBefore(23))      ← 같은 값(23)을 덮는다 + waitForTimeout(200)
shoot(F0)                    ← 200ms 뒤
setStyle(null)               ← 걷는다 + waitForTimeout(200)
shoot(Z0)                    ← 다시 200ms 뒤
noise = max(diff(N,F0), diff(N,Z0))   ← 0 이어야 한다
```

전제는 **«두 장 사이에 흐른 200ms 동안 그림을 바꿀 수 있는 것은 내가 주입한 스타일뿐»** 이다.
그런데 **이 자는 게임 루프를 세우지 않는다** — 부팅하고 기다릴 뿐이라 자동 전투가 그대로 돈다.

`probe914` [P2] 는 **스타일을 한 번도 안 건드리고** 알약 상자만 200ms 간격으로 찍었다.
그러자 07 스킬 자리에서 **t = 7.2s** 에 알약의 **87.0%(19,083px)** 가 저 혼자 바뀌었고,
그 순간 알약 중심에 서 있던 것이 **`div#defw`** 였다.

```
#defw{position:absolute;inset:0;display:none;z-index:39;cursor:pointer;background:rgba(0,0,0,.62)}
#defw.on{display:block}
function openDefeat(){ if(arena) return; $('defw').classList.add('on'); }
```

**18 패배 화면의 전면 딤**이다. 자동 전투가 스테이지 보스에게 지면 `playerDied()` → `openDefeat()`
(index.html ~24881)로 켜지고, `inset:0 · z39` 라 **알약을 제자리에 둔 채** 통째로 덮는다.
그리고 «아무 데나 눌러야 닫히는» 계열이라 한 번 켜지면 클릭 전에는 안 꺼진다.

⇒ 플레이키의 기계는 이렇다 — **그 순간이 [0] 의 200ms 창 안에 드는가**.
들면 `N` 은 밝고 `F0` 은 딤이라 알약의 90% 가까이가 «달라졌다» 로 세어진다.
안 들면 세 장이 다 밝거나 다 어두워 **0px** 이다. 자동 전투가 언제 지느냐는 실행마다 다르므로
**«4회 중 1회»** 라는 모양으로 새어 나온다.

⚑ **자리마다 값이 갈린 이유도 여기서 나온다** — 21,375px 은 «딤이 창 한복판에 든 판»,
112px 은 «딤이 창의 **가장자리**에 걸친 판»(정착 대기 200ms 의 끝에서 프레임이 반만 갈린 자리)이다.
둘은 다른 결함이 아니라 **같은 사건의 다른 위상**이다.
