## 1. 무엇이 깨져 있었나

`auMode === 'el'`(= `file://` 이거나 AudioContext 생성 실패) 폴백에서 `sfx()` 는 겹침 재생을 위해
**호출마다** `base.cloneNode()` 로 `<audio>` 엘리먼트를 새로 만들고 **한 번도 회수하지 않았다.**
크로미움은 **문서당** WebMediaPlayer 를 ~75개로 제한한다(crbug.com/1144736). 상한을 넘는 순간부터

```
Blocked attempt to create a WebMediaPlayer as there are too many WebMediaPlayers already in existence.
```

가 쏟아지고 **그 뒤로 효과음이 하나도 안 난다.** 되돌아오지 않는다 — 새 엘리먼트를 만들 수 없으니
탭을 새로고침할 때까지 게임이 영구히 조용해진다.

**같이 발견한 두 번째 누수(같은 절, 이 작업 범위)** — `bgmApply()` 의 el 분기는 트랙이 바뀔 때마다
`new Audio()` 를 만들었다. 보스전 진입·이탈마다 2개씩 쌓인다. 게다가 `bgmStopCur()` 의 페이드아웃과
`bgmApply()` 의 페이드인이 **`bgmElFade` 라는 타이머 id 하나를 나눠 써서**, 페이드인을 걸 때의
`clearInterval(bgmElFade)` 가 **직전 트랙의 페이드아웃까지 지웠다.** 결과: 옛 트랙이 볼륨을 문 채
`pause()` 되지 않고 영원히 재생 → **BGM 이 2겹·3겹으로 겹쳐 울리면서 엘리먼트도 회수 안 됨.**
누수는 이 쪽이 더 조용히 진행된다(전투마다 2개씩).

## 2. 재현 (수정 «전» 빌드)

```
$ node tools/repro128.js
auMode = el
폭주 1200회 → «WebMediaPlayer 막힘» 경고 192건
  예: Blocked attempt to create a WebMediaPlayer as there are too many WebMediaPlayers already in existence…
폭주 뒤 새 효과음 재생 = X (t=0.000s)

REPRO128 CRASH — 효과음이 죽는다(누수 재현됨)
```

`repro128.js` 는 **새 심볼(`auVo`/`auMade`)에 의존하지 않는다** — 옛 빌드에 그대로 돌려 대조하기
위해서다(LESSONS 110-③). 재생 확인은 `document.querySelectorAll('audio')` 와 풀을 **둘 다** 훑는다.

## 3. 고친 방법 — «목소리 풀»(처방 후보 ②)

행의 처방 후보 ①(`ended` 에서 놓아주기)은 **놓아주기 전에 겹치면 여전히 상한에 닿는다**(전투의
`hit` 은 30ms 간격까지 허용된다). ③(`ctx` 로 밀기)은 `file://` 배포를 포기하는 것이라 못 쓴다.
그래서 권장안인 ② **고정 개수 풀**로 갔다.

```js
const AU_VOICE_MAX = 8;      /* 동시 발음 수 상한 */
const auVo = [];             /* {el, name, t} */
function auVoice(name){ … }  /* ① 같은 이름의 쉬는 목소리 → ② 남는 목소리 → ③ 가장 오래된 것을 뺏는다 */
```

- 같은 이름이 쉬고 있으면 **`src` 재할당 없이** 즉시 재생(재로드 0).
- 8개가 전부 재생 중이면 **가장 오래 전에 발화한 목소리를 뺏는다**(표준 voice stealing).
  방치형 게임에서 8겹을 넘는 동시 발음은 어차피 서로를 가린다.
- 프리로드 캐시 `auEl`(AU_SFX 27종)은 **종전 그대로** — 첫 재생 지연을 없애는 역할이라 손대지 않았다.
  이건 고정 개수라 누수가 아니다(verify78 §C 가 27 을 계속 센다).
- BGM 은 «울리는 트랙 1 + 페이드아웃 중인 트랙 1» 뿐이므로 **핑퐁 2개**(`auBgmEl`)로 돌린다.
  페이드아웃 타이머를 `bgmElFadeOut` 으로 **갈라서** 페이드인이 남의 페이드아웃을 지우지 않게 했고,
  앞 페이드아웃이 안 끝난 채 또 전환되면 그 엘리먼트를 **즉시 `pause()`** 한다.

**미디어 엘리먼트 총수 = 프리로드 27 + 목소리 8 + BGM 2 = 37** — 상한 75의 절반이다.
`auMade`(만든 총수)를 노출해 게이트가 «상한 안에 머무는가» 를 직접 잰다.

## 4. 기능 체크 표 (헤드리스 실측)

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| sfx() 1200회 폭주 → «WebMediaPlayer 막힘» 경고 | **192건** | **0건** |
| 폭주 «뒤» 에 낸 새 효과음 재생 | **X** (t=0.000s) | **O** (t=0.562s) |
| 만든 미디어 엘리먼트 총수(`auMade`) | 무한 증가 | **36 ≤ 37** |
| 목소리 풀 크기(`auVo`) | — | **8 ≤ 8** |
| BGM 트랙 24회 전환이 만든 엘리먼트 | 24개 | **1개 ≤ 2** |
| 24회 전환 뒤 동시에 울리는 BGM | 여러 겹 | **1개** |
| 60s 자동 전투 — 엘리먼트 총수 최대 | 계속 증가 | **31 ≤ 37** |
| 180s 자동 전투 — 엘리먼트 총수 최대 | 계속 증가 | **32 ≤ 37** (`--long`) |
| 장시간 뒤에도 효과음이 나는가 | X | **O** (60s 런 t=0.469s · 180s 런 t=0.705s) |

`verify128.js` 는 **`file://` 로 연다** — 그래야 `auMode` 가 'el' 폴백으로 떨어진다. `http` 로 열면
`ctx`(WebAudio) 경로라 이 버그가 아예 안 나온다. §A~§E 는 상단 주석 참고.
상수 `SFX_N`·`AU_VOICE_MAX` 는 **`index.html` 에서 읽어 온다**(LESSONS 99 — «N 을 세는 게이트는
N 을 소스에서 뽑아라»). SFX 가 늘거나 풀 크기를 조정해도 게이트가 따라간다.

## 6. 남은 것 / 다음 사람에게

- **`ctx`(WebAudio) 경로는 무관하다** — `createBufferSource()` 는 미디어 플레이어를 안 쓴다.
  이 버그는 `file://` 배포판과 AudioContext 를 못 만드는 기기에서만 난다. 다만 GitHub Pages(https)는
  `ctx` 경로라 **주인이 웹에서 플레이하면 이 버그를 못 본다** — 그래서 오래 남아 있었다.
- 작업 110 이 «게이트에서 오디오를 껐다»(`verify74`)고 적어 둔 것은 **이 누수 때문**이었다.
  이제 원인이 사라졌으니, 74 를 다시 잡는 세션은 오디오를 켠 채 돌려 볼 수 있다
  (다만 LESSONS 99 대로 «정확히 N» 게이트는 여전히 비결정적이다 — 오디오는 꺼 두는 편이 안전하다).
- `AU_VOICE_MAX = 8` 은 «동시 발음 수» 다. 소리가 얇게 느껴지면 올려도 되지만, 프리로드 27 + BGM 2 와
  합쳐 **75 아래**를 지켜야 한다(게이트 §0 이 이 관계를 센다 — 상수가 아니라 관계로 적었다, LESSONS 101-②).
