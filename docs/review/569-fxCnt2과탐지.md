## §1 재현 (처방보다 먼저 — 338)

`tools/probe569.js` **신설**. 이 자는 **판정식을 베끼지 않는다** — `fxFly` 전역 바인딩을 감싸
«호출 순간의 `fxAcc`» 와 «그 호출이 정한 `fxCnt2`», «그 호출이 실제로 스폰한 개수» 를 그대로 적는다
(제품 0줄 수정 · `probe564` 와 같은 방식). 씬은 셋 다 **실제 게임 경로**다 — 상태를 손으로 밀어 넣지 않는다.

| 씬 | 경로 | 수리 전 | 수리 후 |
|---|---|---|---|
| A | 다이아 팩 우편 수령(153·497 — `devBuyDia('d4')` → 우편 «다이아 90만 + 마일리지 1») | dia **3** · mile 0 · `fxCnt2` **true** | dia **6** · mile 0 · `fxCnt2` **false** |
| B | 다이아만 든 우편(m2, 40,000) — 단독 기준선 | dia 6 · false | dia 6 · false |
| C | 골드+다이아 우편(m1) — 진짜 «두 재화 동시» | gold 3 · dia 3 · relic 0 · true | **그대로** gold 3 · dia 3 · true |

계측 원문(수리 전):

```
fxFly(dia, 900000) — 그 순간 fxAcc {dia:900000, mile:1} → 스폰 3개 · fxCnt2 true
fxFly(mile, 1)     — 그 순간 fxAcc {mile:1}            → 스폰 0개 · fxCnt2 true
[알약 유무] gold O · dia O · relic X · stone X · rstone X · tstone X · mile X
```

⚑ **A 가 C 와 값이 같았다** — «상대가 실제로 나는가» 를 아무도 안 물었으므로, 마일리지 쿠폰 **1개**가
다이아 90만의 연출을 «두 재화 동시» 로 만들어 개수를 절반으로 깎았다. 마일리지 자신은
`FXCUR.mile.pill === null` 이라 512 ③ 대로 **한 개도 안 난다**(버스트 + `+n` 만) — 즉 화면에는
**상대가 없는데** 자리만 비워 두고 개수를 줄인 그림이다.

## §2 뿌리 — 512 가 표를 넓혔는데 판정 하나가 «표의 길이» 를 따라오지 않았다

93 3회차가 세운 규칙은 «골드·다이아가 **같이 날면** 두 묶음이 겹치니 각자 절반» 이고, 그때
`FXCUR` 는 gold·dia **두 항**뿐이었다 — 그 시절에는 «`fxAcc` 에 값이 있다 = 상대가 난다» 가 참이었다.
512 가 표를 **7종**으로 넓히면서 그 등식이 깨졌다: 새로 들어온 다섯(유물조각은 41 바가 닫혔을 때 ·
강화석 · 룬강화석 · 단련석 · 마일리지)은 도착 알약이 없어 `fxFly` 입구에서 되돌아간다.
**부패의 자리는 512 가 새로 쓴 코드가 아니라, 512 이전부터 있던 «두 항 시절의 전제»** 다.

## §3 처방 — 판정을 «날 수 있는가» 로 바꾼다 (제품 1자리)

`index.html` `fxFly()`:

```js
const other = fxFlies.some(f => f.ui && f.cur !== cur)
  || Object.keys(FXCUR).some(k2 => k2 !== cur && fxAcc[k2] > 0 && !!fxPill(FXCUR[k2]));
```

⚑ **재화 이름으로 빼지 않았다.** «마일리지·강화석은 제외» 식의 목록은 402 가 잡은 «표 두 벌» 이
되고, 표에 재화가 하나 더 들어오는 순간 같은 자리에서 또 샌다. 물어야 할 것은 처음부터 하나 —
**도착지가 있는가**(`fxPill`) — 이고, 그것은 바로 위 `if(!pill) … return` 이 이미 쓰는 자다.
같은 자를 쓰므로 «판정과 거동이 어긋날» 수가 없다.

⚑ **좁히지 않았다.** 유물조각은 **41 재화 바가 열린 화면(89 유물 페이지)** 에서는 알약이 생겨
실제로 난다 — 그때는 종전대로 «상대» 로 세어진다(`verify569` [D] 실측: relic 알약 O · 비행 3개 ·
dia 묶음 `fxCnt2` true). 판정 축이 «재화 종류» 가 아니라 «그 순간 알약이 있는가» 임을 이 항이 못박는다.

⚠ 호출 비용 — `fxPill` 은 `fxAcc[k2] > 0` 이 참인 재화에만 물어본다(단락 평가). 묶음 하나에 최대
6번이고, 그 자체가 `querySelectorAll('.pcb-x')` 한 번이라 종전 경로(`fxFly` 입구에서 이미 한 번 부른다)와
같은 급이다.

## §7 교훈

1. **표를 넓힌 작업은 «표를 읽는 자리» 만 고치면 끝이 아니다.** 512 는 아홉 개의 상태 사전을
   `fxMap` 으로 표에 묶었지만, «두 항 시절에만 참이던 전제» 를 쓰는 판정은 표 밖에 있었다.
   부패는 새 코드가 아니라 **옛 전제**에 생긴다.
2. **«상대가 있는가» 를 묻는 자리는 «상대가 보이는가» 로 물어야 한다.** 화면에 안 나는 것을
   상대로 세면 사용자는 «왜 반만 나오지» 만 본다 — 상태로 묻지 말고 **그리는 조건**으로 물어라.
3. **무른 수리의 유혹은 이름 목록이다.** 다섯을 이름으로 빼는 수리는 오늘은 초록이고 내일 표에
   여덟 번째가 들어오면 조용히 샌다. [D] 항은 그 유혹을 막으려고 넣었다.
