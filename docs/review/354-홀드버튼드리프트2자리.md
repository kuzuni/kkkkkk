## 1. 338 규칙대로 «처방 전에 재현» — 이번엔 등재문 가설이 **확인**됐다

338 은 등재문 가설을 재현으로 **기각**했고 341 은 «누락» 이 유령이었음을 밝혔다. 그래서 이번에도
처방을 손대기 전에 `tools/probe354.js` 를 신설해 두 호스트를 349 와 **같은 축**(CDP 터치 ·
게임 루프 ON · 손가락 드리프트)으로 굴렸다. 결과는 350 과 같은 쪽 — **가설 그대로**다.

수리 «전» (1.5초 홀드 · 제품 함수 호출을 직접 셈):

| drift | `#modal #mLv` 시도 / 취소 | `#relw #rwBasin` 시도 / 취소 |
|---|---|---|
| ±0px | 11 / 0 | 4 / 0 |
| ±6px | 12 / 0 | 3 / 0 |
| ±14px | 13 / 0 | 8 / 0 |
| **±30px** | **1 / 1** | **1 / 1** |
| **±45px** | **1 / 1** | **1 / 1** |

⇒ 349 의 표(±30px → 1회 · `pointercancel` 1)와 **같은 값**이다. 버튼 크기는 다르다
(`#mLv` 250×120 · `#rwBasin` 400×216) — 즉 «버튼이 작아서 밖으로 나간 것» 이 아니다.
±30px 는 두 자리 모두 **버튼 안**이고, 브라우저가 그 터치를 스크롤 제스처로 채간 것이다.

`probe354` [C] 는 그 자리에서 349 의 한 줄을 **주입**해 대조군을 뜬다 —
`#mLv` 11회 · `#rwBasin` 4회, 취소 0. **처방이 원인을 정확히 겨눈다는 증거는 재현 단계에서 이미 나왔다.**

### #rwBasin 의 시도 횟수가 낮은 이유 (게이트 임계를 조이지 않은 근거)

`#rwBasin` 은 1.5초에 3~8회로 `#mLv`(11~13회)보다 낮고 편차도 크다. 원인은 홀드가 아니라
`summonRelic` 이 매회 `renderRelw()`(캔버스 10칸 재도색) + `fxUpOk` 를 도는 **렌더 비용**이다.
그래서 게이트는 **절대 횟수를 조이지 않고** «연속이 도는가(≥3) · `pointercancel` 0» 만 묻는다 —
355(플레이키 게이트)가 남긴 교훈대로, 타이밍에 민감한 임계는 게이트를 부패시킨다.

## 2. 자리 — 클래스가 아니라 JS 가 무는 훅

349 규약을 그대로 따랐다. `bindUpHold` 는 세 호출부(08 스킬 세부 · 08 아이템 세부 · 50 코스튬 세부)가
전부 **`$('mLv')`** 를 넘기고, `rwHold` 는 **`$('rwBasin')`** 에 직접 붙는다. 그래서 선택자는
`#modal #mLv, #relw #rwBasin` 이다 — 마크업 클래스가 바뀌어도 새어 나가지 않는다.

⚠ `#relw` 쪽은 `pointerleave` 도 정지 사유로 걸려 있다(89 원설계). 그 축은 **건드리지 않았다** —
처방은 «제스처를 안 뺏긴다» 이지 «정지 조건을 무르게 한다» 가 아니다. 게이트 [C] 가 그 사실을
직접 잰다(이탈·팝업 닫힘·손 뗌 전부 여전히 즉시 정지).

### 스크롤을 죽이지 않는가

349 [B] 의 마지막 항을 두 호스트로 이관했다 — 조상 사슬에 `overflow:auto|scroll` 인 스크롤 영역이
하나도 없다. ⚠ **넘침(`scrollHeight > clientHeight`)이 아니라 «스크롤 가능성»** 을 묻는다
(`overflow:hidden` 이면 내용이 넘쳐도 스크롤은 못 한다 — 349 가 여기서 자체 오측을 한 번 했다).
언젠가 이 두 팝업에 스크롤 영역이 생기면 그 항이 빨개져 처방을 다시 보게 만든다.

## 5. 하네스 함정 3개 (게이트를 세우며 잡은 것 — 셋 다 제품이 아니라 게이트가 거짓말을 한 것이다)

1. **«정확히 n회» 는 성공으로 세야 한다.** 홀드는 소진되면 «한 번 더 시도 → 실패 → 정지» 라
   호출 수는 항상 **n+1** 이다. 처음에 시도로 세서 [D] 두 항이 빨갰다(제품은 멀쩡했다).
   `__n`(시도)과 `__ok`(성공)를 갈랐다.
2. **«닫기 직전 값» 과 «닫기» 는 같은 순간에 잡아야 한다.** 둘로 나누면 그 사이에 홀드 틱
   (100~160ms)이 한 번 더 돌아 **하네스가 «+1» 을 만든다** — 3회 중 2회 빨갰다.
   `p.evaluate(() => { const v = __n; closeModal(); return v; })` 로 한 태스크에 묶어 4/4 안정.
   (350 이 «rect 와 캡처를 같은 순간에 잡아라» 로 남긴 것과 같은 함정이다.)
3. **결함의 서명은 «횟수» 가 아니라 `pointercancel` 이다.** `#rwBasin ±45px` 이 20여 회 중 한 번
   «1회 · **취소 0**» 으로 빨갰다 — 이벤트 로그를 찍어 보니 홀드를 끊은 사건이 **없었고**(누름→뗌
   사이에 leave·cancel 0건), 같은 조건을 12회 반복하면 3~6회로 전부 초록이다. 즉 머신이 1.5초 안에
   통째로 정체한 표본이다. 그래서 «취소 0 인데 횟수만 낮은» 표본에 한해 **한 번만** 다시 잰다 —
   결함이 살아 있으면 재시도해도 매번 취소가 뜨므로 이 완충은 결함을 가리지 못하고, 그 사실을
   [R] 이 매 실행 «되돌리면 1회 · 취소 ≥1» 로 못 박는다. (355 를 하나 더 만들지 않기 위한 것이다.)
   **5회 연속 29/29** 로 안정을 확인했다.
