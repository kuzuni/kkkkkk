## 1. 등재문 ① «먼저 확인» — 진입 버튼 배지는 **멀쩡했다**

등재문은 «안 보이면 166 ⓔ 특이성 계열 의심(`.ibtn .bdg` 는 299 에서 right 기준으로 재기술됨)» 이라고
적어 뒀다. 착수 전에 `tools/probe318.js` 로 먼저 쟀다(LESSONS 264 — 「미착수」 등재문도 코드로 재확인).

| 재는 것 | 실측 (att `{n:3, date:''}` = 오늘 미출석) |
|---|---|
| `S.att.date !== today()` | `true` |
| `.ibtn[data-pop="attend"]` 의 `.on` | **붙는다** |
| `.ibtn.on .bdg` computed display | **`block`** · rect 42×42 @ (125.3, 170) |
| 그 자리의 실제 화소 | **빨강 1438화소 / 42×42** (`verify318` [1]) |
| `elementFromPoint(배지 중심)` | **배지 자신** — 가리는 것이 없다 |

**특이성 함정은 없었다.** 299 가 `right` 기준으로 다시 적은 뒤에도 좌측 사이드 배지는 논리·화소 둘 다 정상이다.

## 2. 그럼 무엇이 결손인가 — **293(우편)과 똑같이 «경로가 한 칸 짧다»**

출석으로 가는 길은 좌측 사이드 «출석» 아이콘 **하나뿐**이다(`openAttend()` 호출부는 `data-pop` 위임 한 곳,
▦ 메뉴에는 출석 칸이 없다). 그런데 그 버튼을 누르면:

| 순간 | 실측 |
|---|---|
| 70 팝업이 열린다 | `#modal` 이 `at70 on` · **z-index 30** |
| 좌측 사이드는 | `.side` **z-index 3** |
| 배지 자리를 hit-test 하면 | **`#modal`** (배지는 딤 **아래**) |
| 팝업 안 배지 노드 수 | **0개** (`#mbox .updot, .bdg, .dot` 전수) |

⇒ «출석 보상을 받을 수 있다» 는 신호가 **확인하려고 손을 대는 순간 화면에서 완전히 사라진다.**
293 이 우편에서 잡은 것과 **같은 형태**다(그쪽은 `#menub.mnon .bdg{display:none}`, 이쪽은 딤의 z-order).
292 가 «열렸는가 ≠ 보이는가» 로 적어 둔 것의 반대 방향 사례이기도 하다 — 여기서는 **켜져 있는데 안 보인다.**

## 3. 고친 것 — 경로의 다음 칸(«오늘 카드»)까지 잇는다

**제품 코드는 두 곳, 순증 함수 0개다.** 판정식을 새로 만들지 않았다 —
70 팝업은 이미 `now = (idx === day && can)` 으로 «받을 수 있는 칸» 을 정확히 가르고 있고
(`can = S.att.date !== today()`), 그 칸에만 `data-att="1"` 를 찍는다. 그 조건을 그대로 쓴다.

| 자리 | 변경 |
|---|---|
| `openAttend()` 카드 템플릿 | `now` 일 때 `class` 에 **` alert`** 추가 · 카드 끝에 **`<s class="updot"></s>`** 1개 |
| CSS `.updot` 위치 목록 | **`.at-c>.updot,.at-c7>.updot{right:-9px;top:-9px}`** 신설 |

- **부품은 공용 `<s class="updot">`** — 283·276·294·301 이 쓰는 것 그대로. 등장·맥박 연출(`jzDotIn`/`jzDotPulse`)도
  `.alert>.updot` 선택자에 이미 걸려 있어 CSS 한 줄도 안 늘었다(④ 일관성).
- **노드는 조건부**(301 `.ps-bx` 꼴). 수령하면 `claimAttend()` 직후 `openAttend()` 가 팝업을 재렌더하므로
  «켜진 채 굳는» 사고가 없다 — 294 가 «렌더 밖에서 재고가 변하는 화면» 에 쓴 «노드는 늘 두고 토글» 방식은
  여기서는 필요 없다(재고가 바뀌는 경로 = 수령 하나이고 그 경로가 곧 재렌더다).
- **자리 선정(299 «우상단 사분면»)**: 카드 우상단 **바깥** 코너가 비어 있다 —
  `.at-bd`(N일 차 밴드)는 카드 **안쪽** `top:1`, `.at-ck`(✔)는 **수령 완료 칸에만**, `.at-cr`(👑)은 하단이다.
  `.at-in`(`overflow:hidden`)의 **형제**라 잘리지 않고, 카드 바깥 9px 은 그리드 gap(33/44.5) 안,
  7일차(`.at-c7`, 폭 767 = 크림 폭)는 `.at70 .mbody` padding(65) 안이라 `overflow:hidden` 에도 안 걸린다.
  실측 중심 — 그리드 칸 **cx 216.5/226 · cy 9.5/268** · 7일차 **cx 757.5/767 · cy 9.5/268**.

## 6. 곁가지 — `tools/verify204.js` 가 **즉사**한다 (내가 깬 것이 아니다 → 작업 319 로 등재)

이 작업의 회귀 범위(출석 수령 = `claimAttend` → 던전 입장권 +2)라 돌렸더니
`page.evaluate: ReferenceError: **bagUse is not defined**` 로 **19번째 항목에서 통째로 죽는다**(tools/verify204.js:155~161).
`bagUse()` 는 **292(가방 «화폐만»)가 소모품 탭을 폐기하면서 지운 함수**이고, 지금 `index.html` 에는
주석 한 줄(26094)만 남아 있다. **착수 전 기준선(`fc8d245` 의 `index.html`)으로 되돌려 돌려도 같은 줄에서 같은 예외로 죽는다** —
내가 깬 것이 아님을 가름했다(292 의 곁가지 «착수 전 기준선에서 먼저 확인» 과 같은 절차).
185-② «부패는 그 자리에서 등재» 대로 **작업 319** 로 올렸다(제품 결함이 아니라 게이트 부패이고,
278·279·289·305 와 같은 계열 — «즉사» 라 앞 19건이 초록이어도 뒤 절은 **한 번도 안 돈다**).
