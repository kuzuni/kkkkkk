## 3. 고친 것 — `tools/verify112.js` ④ HUD 단언 1블록

```js
const hud = await p.evaluate(() => { fxDisp.gold = S.gold; drawHud();
  return { txt: $('goldN').textContent, want: fmtG(S.gold),
           plain: fmt(S.gold), gold: S.gold }; });
eq('④ HUD 골드 = fmtG(S.gold)', hud.txt, hud.want);
yes('④ HUD 골드가 fmt 원시 표기와 갈린다(150 표기층 회귀 감지)',
    hud.gold >= 1000 && hud.txt !== hud.plain);
```

두 가지를 의도적으로 다르게 했다.

**ⓐ 값의 출처를 `fxVal('gold')` 가 아니라 `S.gold` 로 잡았다.**
등재문은 `fmtG(fxVal('gold'))` 를 처방했지만, 그러면 **HUD 가 방금 쓴 식을 그대로 다시 계산해
비교하는 항등식**이 된다 — `fxVal` 경로가 망가져 HUD 가 엉뚱한 값을 그려도 단언이 같이 틀려서 통과한다.
바로 윗줄이 `fxDisp.gold = S.gold` 로 58 롤링 캐시를 밀어 두므로 이 시점에
`fxVal('gold') === S.gold` 가 보장된다(`fxVal` = `fxDisp[k]` 가 유한하면 그것, 아니면 `S[k]`,
index.html:25310). 즉 **같은 것을 재면서 항등식만 피한** 선택이고, 표기 함수 교정이라는
등재문의 처방은 그대로 지킨다.

**ⓑ 회귀 감지 한 줄을 더 달았다.** 같은 부패가 다시 나면 ⓐ 만으로도 잡히지만,
**두 표기가 애초에 같은 크기**(골드 < 1000 이면 `fmtG` 와 `fmt` 가 같은 문자열)에서 재면
빨간 게 아니라 초록으로 지나간다. 이 지점의 골드는 테스트 셋업상 999,955 라 안전하지만,
곡선이 바뀌어 액수가 작아지면 게이트가 조용히 무력해진다 — 그래서 «잴 수 있는 크기인지»를 못 박았다.
