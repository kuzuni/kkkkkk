# 752 — 스킬 투사체가 위로 발사될 때 사각 경계에서 하드 컷 «버그»

- **세션**: sess-1839-19595 (루틴 워커 B) · 2026-09-01 · 1회차
- **주인 원문**: «스킬중에서 위로 갔더니 랜더링 잘리는거 있던데 해결하라해. 이 발사스킬같은거나 뭐나 위로 발사할때 저렇게 짤림» (스크린샷 — STAGE 560, 청록 투사체가 위·좌로 퍼지다 직선 절단면)
- **제품 변경**: `index.html` — 상수 1자리(`EDGE_TOP` 130 → **0**) + 램프 2줄 삭제 + 주석 정오표. 판정·밸런스 **0줄** · 레이아웃 **Δ0px** · DOM/z **0줄**.

## §1 재현 (probe752 — 처방 전에, 338 규칙)

«있음/없음 diff» 로 잰다: 같은 프레임을 투사체 있음/없음으로 두 번 `draw()` 해 달라진 픽셀만
투사체 잉크로 센다(바닥 타일·플레이어·비네트가 전부 상쇄된다 — 배경 오염 0).

위로 나는 발(k:'ice', vy −430) 4발 + 대각 1발을 화면 y210 에서 쏘아 16프레임 굴린 결과(수리 전):

| 프레임 | 발 머리(화면 게임y) | 클립선(130) 위 잉크 | 선 위 7px 띠 | 선 아래 7px 띠 |
|---|---|---|---|---|
| 9:19 | 100·100·100·100 (생존, life>0) | **0** | **0** | 2,590 |
| 9:13.3 | 100·100·100·100 | **0** | **0** | 2,590 |

발이 화면 게임 y100 에 **실재하고 살아 있는데 잉크가 0** — 절단면이 정확히 y130 직선이다.
등재문 가설(«이펙트 레이어 경계가 플레이 영역보다 작다»)이 그대로 확인됐다.

## §2 뿌리 — 경계는 하나의 상수다 (`EDGE_TOP = 130`)

`draw()` 의 투사체·잔상 구간(트레일·운석 예고·드론·몸통·접촉 잔상 전부)이
`ctx.rect(-ox, EDGE_TOP - oy, VW, VH); ctx.clip()` 로 **화면 게임 y 130 위를 하드 클립**하고,
같은 상수를 `edgeDist()`(가장자리 페이드)와 운석 램프(`scrY<180` 알파 0→1)가 본다.
⇒ 캔버스 상단 **0..130 게임px = 프레임 260px**(좌측 사이드 아이콘 첫 줄 옆 높이)가
투사체가 실재해도 잉크 0 인 «죽은 띠» 였다. 주인이 본 «좌측 사이드 아이콘 열 근처와 상단의
직선 절단면» 은 이 한 줄이다(가로 위치가 달라도 같은 수평선).

**이 130 은 새 결함이 아니라 114 비평 12·13회차가 세운 가드다** — 운석 꼬리가 상단 STAGE
패널(DOM, 게임 y 62..112)을 «관통해 보인다» 는 지적을 클립으로 막았다(112 → 13회차에 130).
그 가드가 6주 뒤 주인 결함이 됐다: 위로 나는 스킬 전부가 그 선에서 잘린다.
좌·우·하변은 처음부터 «클립 없이 edgeFade 만»(16회차 — «날아가 멀어진다») 인데 상변만 이중이었다.

## §3 처방 — 경계를 캔버스 전체로, 겹침은 z 층이 흡수 (등재문 처방 그대로)

1. `EDGE_TOP` **130 → 0** — 클립 rect·edgeDist 가 같은 상수를 보므로 한 자리로 페이드·클립이
   같이 열린다. 상변 소멸은 좌·우변과 같은 edgeFade 문법(속도 비례 34~90px)이 흘린다.
2. 운석 램프(`scrY<180` 알파) **삭제** — 남기면 경계를 열어도 y130 아래 알파 0 = 죽은 띠 그대로다.
3. **z 층은 한 글자도 안 만졌다** — 상단 STAGE 패널·HUD·팝업은 DOM 이라 캔버스 위에 있고,
   꼬리는 그 «뒤» 로 지나간다(«팝업·HUD 위로 새는 것 금지» 짝 항 = verify752 [D]).
   12회차가 걱정한 «관통해 보임» 은 패널이 가리는 부분이 늘어나는 방향이라 재발 형태가 다르며,
   주인 지시(잘림 해소)가 비평 회차 판정보다 우선한다(425 선례 — 의도적 이탈, 주석 정오표).
4. **클립 rect 는 남겼다**(EDGE_TOP=0 이면 캔버스 전체 = 무동작) — 경계 손잡이. **되돌리려면
   상수 하나(130)** 이고 probe752/verify752 §R 이 그 사본으로 «수리 전» 을 재현한다(위임 규약의
   되돌림 경로).
5. **안 건드린 것**: 반사탄(rico) 튕김 경계 `T = -camOy + 150` — 그것은 그리기가 아니라
   **판정**(탄 궤적·명중)이라 밸런스다. 주인 결함은 «렌더링 잘림» 이고 rico 는 튕겨서 경계 밖에
   그려질 일이 없다. `edgeW` 상한·`EDGE_FADE` 도 불변(16회차 설계 그대로).
