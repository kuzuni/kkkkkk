## 1회차 — 진단

### ⓐ 결손은 «판정» 이전에 **부품** 이었다

```html
<div class="stab dns-t off" data-dsub="raid"><i class="ol3">컨텐츠</i></div>       ← 배지 노드 없음
<div class="stab dns-t on"  data-dsub="dun"><i class="ol4">던전</i><s class="bdg"></s></div>
<div class="stab dns-t off" data-dsub="tower"><i class="ol3">탑</i></div>          ← 배지 노드 없음
```

`.stab.alert>.bdg{display:block}` 은 멀쩡하고 `.alert` 를 거는 코드도 멀쩡했다 — **켤 대상이
없었다.** 등재문의 진단 그대로다. 293 이 «경로가 한 칸 짧다» 로 만난 것과 같은 계열이고,
«토글이 틀렸나» 를 먼저 의심하면 아무것도 안 나오는 자리다(LESSONS 293-①).

### ⓑ 그 김에 드러난 것 — «던전» 칸 판정이 카드와 **이미 갈라져 있었다**

같은 식이 두 곳에 손으로 적혀 있었다.

| 자리 | 종전 식 | `!dunLocked(d)` |
|---|---|---|
| 던전 **카드** dot (`renderDunPage`) | `!lock && left > 0 && cp() >= d.req(f)` | **본다** |
| 탭바·서브탭 (`renderUI` 의 `dunAlert`) | `S.dunTk[d.id] > 0 && cp() >= d.req(…)` | **안 본다** |

⇒ **잠긴 던전에 입장권이 남아 있으면 «탭은 켜지는데 카드는 한 장도 안 켜지는»** 상태가 된다.
166 이 «탭·카드가 함께 켜지고 함께 꺼진다» 고 주석에 적어 둔 바로 그 자리인데, 식을 **두 번 적어서**
한쪽만 조건이 늘었다(LESSONS 58-① «같은 값을 두 곳에 적으면 반드시 어긋난다»).

## 처방 — 값을 새로 정하지 않았다. **자를 하나로 모았다.**

카드가 dot 을 켜는 조건을 함수 넷으로 뽑고, **카드·서브탭·탭바가 전부 그것을 본다**
(`index.html` — `renderDunPage()` 바로 위).

```js
const dunCardOk   = d => !dunLocked(d) && S.dunTk[d.id] > 0 && cp() >= d.req(S.dun[d.id]);
const raidCardOk  = r => !raidLocked(r) && raidLeft() > 0 && !(raidBest(r.id).dps > 0);
const arenaCardOk = () => { const rec = S.arena || { w:0, l:0 };
                            return !arenaLocked() && arenaCanEnter() && rec.w + rec.l === 0; };
const towerCardOk = t => cp() >= t.req(towerFloor(t));
const dunSubAlert = k => k === 'raid'  ? (RAIDS.some(raidCardOk) || arenaCardOk())
                       : k === 'tower' ? TOWERS.some(towerCardOk)
                       : k === 'dun'   ? DUNGEONS.some(dunCardOk) : false;
const advAlert = () => dunSubAlert('dun') || dunSubAlert('raid') || dunSubAlert('tower');
```

바꾼 곳은 여섯 자리뿐이다(값 변경 0 — 네 식 모두 카드 렌더에 **이미 적혀 있던 것을 옮긴 것**이다).

1. 마크업 — «컨텐츠»·«탑» 칸에 `<s class="bdg"></s>` 신설
2. `renderDunPage()` 던전 카드 dot → `dunCardOk(d)`
3. `renderRaidPage()` 측정장 카드 dot → `raidCardOk(r)`
4. `arenaCardHTML()` 아레나 카드 dot → `arenaCardOk()`
5. `renderTowerPage()` `ready` → `towerCardOk(t)`
6. `renderUI()` — 서브탭 토글 `dunSubAlert(t.dataset.dsub)` · 탭바 «모험» 칸 `advAlert()`
   (옛 지역 상수 `dunAlert` 삭제. 토글이 칸 이름을 **다시 판단하지 않는다** — 칸이 늘어도 이 줄은 안 고친다)

### 166 규약 — «무엇이 이걸 끄는가» 를 칸마다 한 문장으로

| 칸 | 켜는 조건 | **끄는 사건** |
|---|---|---|
| 던전 | 잠금 아님 + 입장권 남음 + 요구 전투력 충족 | 입장권을 다 썼다 / 층이 올라 요구를 못 넘는다 (자정 리셋) |
| 컨텐츠 | 측정장 기록 없음 **또는** 아레나 전적 0-0 | 한 번 재봤다 / 한 판 했다 |
| 탑 | 지금 층 요구 전투력 충족 | **그 층을 깼다**(층 +1 → 요구 ×1.65). 성장하면 다시 켜진다 |

셋 다 자기소멸 조건이 있다(166 ③ «말할 수 없으면 알림이 아니라 장식이다»).
탑은 «무제한 도전» 이라 조건 없이 켜면 영영 안 꺼지는데, 209 가 이미 카드에 «요구 전투력» 을
걸어 둬서 그대로 물려받으면 된다 — 등재문의 ⚠ 가 걱정한 상시 점등은 생기지 않는다.

### ③ 상위(탭바) — 붙였다

293 이 «우편» 에서 세운 «신호는 진입 경로의 칸마다» 규약대로, 탭바 «모험» 칸을
`dunAlert` → **`advAlert()`**(서브탭 3칸의 OR)로 넓혔다. 종전에는 «던전» 조건만 올라와서,
컨텐츠·탑에 할 것이 있어도 **팝업을 열기 전에는 알 방법이 없었다.**

## 게이트 — `tools/verify166.js` (47 → **65/65**)

166 의 규약(«새 배지를 만들면 감사에 그 호스트를 추가한다»)대로 넓혔다.

**소스 4항** — ⓐ `#dunSub` 칸 수와 배지 수가 같다(리터럴이 아니라 마크업에서 센다)

ⓓ 탭바 «모험» = `advAlert()`.

**[4b] 거동 6항** — 3칸 노드 존재 · 셋 다 거짓이면 3칸 다 꺼짐 · **한 칸씩만 참으로 만들어
그 칸만 켜지는지**(격리) 3항 · 탭바 «모험» 이 OR 로 따라오는지.
[8] 호스트 전수 감사 `#dunSub .stab` 은 **1개 → 3개**로 자동 확대됐다(필터가 «배지가 있는 호스트» 라서).

**음성 대조 2건** — 규칙이 실제로 무는지 되돌려서 확인했다.

| 되돌린 것 | 결과 |
|---|---|
| «컨텐츠»·«탑» 의 `<s class="bdg">` 제거 (버그 상태 재현) | **FAIL 5건** — 논리는 켜지는데 `노드없음` 으로 갈라진다 |
| 토글을 옛 «던전 칸만» 으로 · 탭바를 `dunSubAlert('dun')` 으로 | **FAIL 5건** — 격리 2항 + 경로 1항 + 소스 2항 |

> ⚠ 첫 음성 대조에서 **게이트가 FAIL 도 못 찍고 죽었다** — `getComputedStyle(null)`.
> 없는 노드는 «없음» 이라고 적고 계속 가게 고쳤다. **결함을 재현했을 때 죽는 게이트는
> 그 결함을 못 잡는 게이트다.**

옛 단언 하나를 **삭제**했다 — `«컨텐츠» 칸에는 안 번진다`. 그것은 «컨텐츠 칸은 항상 꺼짐» 을
정답으로 굳혀 두고 있었고, 즉 **결함을 지키는 단언**이었다. 격리 3항이 그 자리를 대신한다.
