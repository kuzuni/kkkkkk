## 3. ★ 회수 보존 — 이 작업의 핵심 불변식

주인 추가 지시가 «반환액이 소모액과 **1pt 도 어긋나면 안 됨**» 이라 여기가 이 작업의 심장이다.

**누적 소모액을 따로 저장하지 않았다.** 저장하면 표기층이 두 벌이 되어 조용히 갈라진다
(203 «표기층» 교훈과 같은 자리). 대신 **닫힌 식으로 역산**한다:

```
temperSpent(L) = TEMPER_SEG · f(f+1)(f+2)/6  +  rem · (f+1)(f+2)/2      (f = ⌊L/100⌋, rem = L − 100f)
```

투자 1회가 빼는 값과 **같은 표**를 지나므로 왕복 보존이 구조적으로 보장된다.
게이트가 두 각도에서 잰다:

- **[D] 무작위 왕복 40회** — 재현 가능한 의사난수(`Date.now`/`Math.random` 없이)로 예산 50~60050 을
  세 축에 무작위 배분 → 회수 → **총 포인트가 처음 예산과 정확히 같다**. 40/40 오차 0pt.
  «시험이 계단을 실제로 넘었는가»(>Lv100 · 3축 분산)도 같이 재서 단언이 공허하지 않음을 확인.
- **[D] 닫힌 식 대조** — L = 0·1·99·100·101·250·1000 에서 «한 레벨씩 실제로 낸 합» 과 `temperSpent(L)`
  이 정확히 같다(0 · 1 · 99 · 100 · 103 · 700 · 22000).

## 4. 절망의 탑 — 209 를 «준용» 했지 다시 쓰지 않았다

209 가 탑을 **싱글턴**(`TOWER` 하나 · `S.tower` 하나 · 카드 1장)으로 만들어 뒀다.
210 ② 는 «나란히» 를 요구하므로 목록으로 일반화했는데, **209 의 규칙은 한 줄도 안 바꿨다** —
바뀐 것은 «어느 탑인가» 를 고르는 자리뿐이다:

- `TOWERS = [TOWER, TOWER_D]` · `towerById(id)` · `towerFloor(t)` / `towerSetFloor(t,f)`
- 진행 키를 탑마다 갈랐다(`fk`: `tower` / `tower2`). **한 탑을 깨도 다른 탑 층이 안 오른다**(게이트 [I]).
- `isTower(d)` 를 목록 판정으로 넓혀 209 의 ①③④(입장권 없음·소탕 없음·층 선택 없음)가
  절망의 탑에도 **그대로 딸려 온다** — 규칙을 두 번 적지 않는다.
- `data-tcard` 가 «1» 이 아니라 **탑 id** 를 들고 있어 클릭이 어느 탑인지 스스로 안다.
- `load()` 정화도 `TOWERS.forEach(t => …t.fk…)` 로 돈다 — 탑이 더 늘어도 이 블록은 안 바뀐다.

## 6. 저장 구조 (KEY 안 올림)

`S.tstone`(수) · `S.temper{pts, alloc:{atk,hp,regen}}` · `S.tower2`(수) 셋을 신설했다.
203·194 와 같은 «없으면 기본값» 마이그레이션이라 **KEY 를 안 올렸다**(44 교훈 2) —
구 세이브는 전부 0 / 1층에서 시작하고 손댄 값은 `load()` 한 곳에서만 정화한다.
`alloc` 은 **상한이 없다**(주인 ⓑ) — 그래서 «클램프» 가 아니라 «음수·NaN·비정수 방어» 만 한다.
정수 구간 밖으로 나가면 `temperSpent()` 의 닫힌 식이 깨져 §3 보존이 무너지기 때문이다.

## 7. 일부러 안 한 것

- **꾹 누르기(64) 없음.** 훈련 카드는 골드 확정 구매라 홀드가 맞지만, 단련은 «자유 배분» 이라
  한 번에 훅 들어가면 되돌리는 값이 1000 다이아다. 한 번 누르면 한 레벨.
  (그 대신 [전환] 은 보유분을 **한 번에** 바꾼다 — 되돌릴 것이 없는 조작이라 마찰을 둘 이유가 없다.)
- **부분 회수 없음.** 주인이 «전액이 기본» 이라고 못 박았다. 축별 회수를 넣으면 1000 다이아를
  세 번 나눠 내는 우회가 생겨 가격 자체가 무의미해진다.
- **밸런스 확정 안 함.** 계수 +2%/pt · 전환비 1:1 · 절망의 탑 곡선(900 · 1.65 · 60+45f)은
  전부 **199 의 몫**이다. 여기서 만든 것은 «구조와 불변식» 이다.
- **88 «스탯 훈련» 의 부활이 아니다.** 88 이 폐기한 것은 «캐릭터 레벨·경험치에 연동된 포인트»
  이고 이번은 «재료 수급형 포인트» 다 — 레벨·경험치 개념이 아예 없다. 코드 주석에도 적어 뒀다.

   한 번 띄워야 잡힌다. **상수는 «쓰는 쪽» 이 아니라 «가장 먼저 읽는 쪽» 앞에 둔다.**
2. **화이트리스트 게이트는 «그때 N개» 라는 기록이다.** `verify209`·`verify90` 둘 다
   «던전 아닌 DUN_UI 키는 `tower` 뿐» 을 **문자열로** 박아 둬서 탑이 하나 늘자 같이 빨개졌다
   (194-4 가 이미 등재한 병인데 화이트리스트 형태로 재발했다). 손으로 늘리지 않고 **모델(`TOWERS`)을
   읽게** 고쳤다 — 탑이 또 늘어도 안 빨개지고, 지키려던 규칙(«던전 아닌 키는 탑뿐»)은 그대로 참이다.
   같은 이유로 `verify203` 의 «탭 2칸 · `sp2`» 도 «앞 두 칸이 훈련·룬 · `spN`» 으로 느슨하게 했다
   (칸 수 자체는 `verify210` [B] 가 못 박으므로 단언이 사라지지 않는다).
3. **탭 상태를 켜는 곳은 한 곳뿐이다.** 게이트 초안이 `renderTemper()` 뒤에 레드닷을 확인했다가
   FAIL 했는데, 탭의 `on`/`alert` 를 켜고 끄는 것은 **203 이 정한 대로 `renderRunes()` 한 곳**이고
   `renderTemper()` 는 본문만 그린다. 게이트를 고쳤다(제품이 옳았다) — 이 규약을 주석에 명시.
4. **«한 재화 = 한 계열» 이 아니다.** 단련석은 재화지만 **던전 계열이 아니다**(수급처가 탑이라
   입장권이 없다). 그래서 `dunTk`·`cur-ticket-*.svg` 를 안 만들었고 `verify125` [H] 의 «입장권 5종»
   은 그대로 5종이다. 게이트 [A] 가 «입장권을 안 만들었다» 를 **양성 단언**으로 잰다.
