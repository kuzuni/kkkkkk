## 2. 고친 것

### 2-1. 단위표 (`index.html` ~7750)

```js
const SUF_CC = 65;                     /* 65 = 'A'(대문자, 기본) · 97 = 'a'(소문자) */
const SUF = [''];
for(let i=0;i<26;i++) SUF.push(String.fromCharCode(SUF_CC+i));
for(let i=0;i<26;i++) for(let j=0;j<26;j++) SUF.push(String.fromCharCode(SUF_CC+i)+String.fromCharCode(SUF_CC+j));
```

| | 구 | 신 |
|---|---|---|
| 10³ | `K` | **`A`** |
| 10⁶ | `M` | **`B`** |
| 10⁹ | `B` | **`C`** |
| 10¹² | `T` | **`D`** |
| 10¹⁵ | `aa` | **`E`** |
| 10⁷⁸ | (없음, `bz` 대) | **`Z`** |
| 10⁸¹ | | **`AA`** |
| 길이 | 5 + 676 = 681 | **703** (1 + 26 + 676, 10²¹⁰⁶ 까지) |

`fmt()` 의 자릿수 규칙(<10 소수 2자리 · <100 소수 1자리 · 그 이상 정수, 1000 미만 접미사 없음)과
58 롤링의 «반올림 승격» 보정은 **한 글자도 건드리지 않았다** — 지시 ③ 이 «지금 fmt 그대로» 다.
`fmtShort()`(아이템 수량 배지)는 같은 `SUF` 를 읽으므로 자동으로 따라온다.

## 4. 이번에 걸린 함정 2개 (LESSONS 후보)

### ⓐ 대문자를 고르면 «화면 텍스트에서 K/M/B/T 찾기» 검증이 죽는다

PROGRESS 111 행이 지정한 검증 항목에 «헤드리스 HUD/전투 데미지 텍스트에 `[KMBT]$` 패턴 0» 이
있었다. 그런데 **새 표에서도 B=10⁶ · K=10³⁶ · M=10³⁹ · T=10⁶⁰ 이 전부 정상 접미사**라
글자만으로는 옛것과 새것을 구별할 수 없다. 실제로 스윕에서 유물조각 3.3e6 이 **«3.30B»** 로
잡혀 «옛 M 접미사» 오탐이 났다(옛 표라면 «3.30M»).
→ **«옛 접미사 0건» 은 소스 스캔으로**, 런타임은 **«알려진 값의 표시 결과가 새 표와 일치하는가»**
로 본다. 게이트는 `S.gold = 4.2e15` 를 넣고 **«4.20E»**(옛 표라면 «4.20aa»)를 19개 화면에서 확인한다.
소문자를 골랐다면 이 문제는 없었다 — **대소문자 결정이 검증 방법까지 바꾼다.**

### ⓑ HUD 알약을 그리는 것은 `renderUI()` 가 아니라 `drawHud()` 다

게이트 1차 작성에서 `renderUI()` 만 부르고 `#goldN` 을 읽어 «0» 을 받았다.
`renderUI()` 는 열린 패널·시트 본문을 갱신하고, HUD 알약(`#goldN`/`#diaN`/`#cpN`)은 `drawHud()` 가
그린다. 게다가 표시값은 58 롤링 캐시 `fxDisp` 를 거치므로 **`fxDisp.gold` 를 목표값으로 밀어
놓지 않으면 몇 프레임 뒤에야 도달**한다. 헤드리스에서 HUD 를 읽는 게이트는 이 둘을 같이 해야 한다.

## 5. 기능 체크 표 (T2 «실제로 동작해야 완료» 규칙)

| 확인 | 방법 | 결과 |
|---|---|---|
| 단위표가 10³=A … 10⁷⁸=Z → AA 로 이어진다 | `SUF[1/2/3/26/27/28]` · 길이 · 중복 | A/B/C/Z/AA/AB · 703 · 0 ✔ |
| 지시가 명시한 값들이 그대로 나온다 | `fmt(1234)`·`fmt(5.07e3)`·`fmt(2.36e9)`·`fmt(999)` | `1.23A`·`5.07A`·`2.36C`·`999` ✔ |
| 10⁷⁸ 계열이 Z, 그 다음이 AA | `fmt(2e78)`·`fmt(2e81)` | `2.00Z`·`2.00AA` ✔ |
| 58 롤링 승격 보정 유지 | `fmt(9999.9)` | `10.0A`(«10.00A» 아님) ✔ |
| HUD 골드·다이아가 실제 게임 값으로 갱신된다 | `S.gold=5.07e3`·`S.dia=2.36e9` → `drawHud()` | `5.07A` · `2.36C` ✔ |
| 전투 캔버스 데미지 숫자 | `dmgNum(…, 1.234e7)` | `12.3B` ✔ |
| 탭 5개·사이드·▦메뉴 8칸 **19개 화면**에서 표기가 유지된다 | 오프너 스윕, `S.gold=4.2e15` | 전부 `4.20E` ✔ |
| 아이템 수량 배지(`fmtShort`) | `1500`·`12345`·`3e6` | `1.5A`·`12A`·`3B` ✔ |
| 소환 가격 쉼표 예외가 3곳 그대로 | 소스 카운트 | 3 ✔ |
| 시간 표기 회귀 없음 | `hhmm(3h25m)` | `3시간 25분` ✔ |
| 콘솔·런타임 에러 | 페이지 로드 + 스윕 | 0 ✔ |

`fmt(1e78)` 은 정확히 1000²⁶ 이라 double 나눗셈이 999.99…9 로 떨어져 **`999Y`** 로 나온다.
전환 전 K/M/B/T 시절에도 같았던 부동소수 경계이고 표시 오차는 1e-7% 라 그대로 뒀다 —
게이트는 그 자리에서 «접미사 계열» 만 본다.

## 6. 잔여 — 주인 판단 필요 (111 범위 밖)

레퍼런스는 **만 미만을 쉼표로, 그 이상을 알파벳으로** 쓴다(쉼표: HUD 젬 `1,300` · 33 «보유: 3,210» /
알파벳: 골드 `39.20A` · `32.68A` · `538A` · `2.36C` — 6개 데이터 전부 부합).
즉 «다이아만 쉼표» 가 아니라 **자릿수 규칙**이다. 그러나 주인 지시 ③ 이 «1,000 미만은 접미사 없음»
으로 임계를 못박았고, 임계를 10,000 으로 올리면 `fmt` 를 거치는 **126곳의 글자 수**가 바뀌어
폴리시 완료 화면들의 숫자 잉크 폭 측정치가 전부 재검 대상이 된다.
지시 ② 의 «확실치 않으면 통일해서 a 표기» 를 따라 이번에는 **알파벳으로 통일**했다.
채택 여부는 별도 작업 단위로 — 상세 표는 `docs/measure/02-기본-메인-화면.md` §8-2.
