### 처방 — 등재문 ①②③ 을 그대로 이행

**① 53 가방 단언을 292 이후의 실제 구조로 다시 적었다.**
«가방 소모품 탭에 입장권 5장» 은 **폐기**했다. 여기서 재야 할 «다른 화면 반영» 은

**② 왜 없앴는지를 게이트 주석에 남겼다**(285-② 관례). 위 블록 머리에 8줄로 적었다 —

**③ `page.evaluate` 예외가 게이트를 통째로 죽이지 않게 감쌌다**(278 처방).

```js
const ev = async (fn, arg) => {                     /* p 를 닫아야 해서 IIFE 안에서 만든다 */
  try { return await p.evaluate(fn, arg); }
  catch (e) { return { __err: String((e && e.message) || e).split('\n')[0] }; }

const blk = (r, m) => { if (r && r.__err) { ok(false, m + ' — 평가가 죽었다: ' + r.__err); return false; } return true; };
```

`p.evaluate(` 호출 11곳을 전부 `ev(` 로 돌리고, 블록마다 `if (blk(x, '이름')) { …ok… }` 로 감쌌다.
죽은 블록은 **FAIL 1건으로 세고 건너뛰며, 뒤 블록은 계속 돈다.**
§1(상수·저장 구조)만 예외로 **죽으면 즉시 중단**한다 — `st` 는 뒤 블록 전부가 참조하는 기준값이라
그게 없으면 뒤 항목이 «전부 빨강» 이 되어 원인이 묻힌다.

**④ 292 가 폐기한 다른 이름 전수**는 등재 때 이미 돌렸고(`verify204`·`verify53` 둘뿐), `verify53` 은 안전하다.

### `tools/probe319.js` 신설 — 「안 죽는다」를 말이 아니라 시험으로

처방 ③ 은 고쳐 놓고 «이제 안 죽는다» 고 **적기만 하면 다음 회귀 때 똑같이 죽는다.**
그래서 **일부러 죽는 참조**(`bagUse()` — 319 를 낸 바로 그 호출)를 같은 `ev`/`blk` 짝에 먹이고 센다:

- [A] 미정의 참조가 `__err` 로 잡힌다 · `blk()` 이 false 를 돌린다 · **FAIL 을 1건만** 센다
- [B] 죽은 블록 **뒤에도** 평가가 계속 살아 정상 값을 읽는다(즉사였다면 여기까지 못 온다)
- [C] 정상 결과에는 `__err` 키가 없다(감싸기가 성공 결과를 오염시키지 않는다)

[A] 의 blk() 은 일부러 FAIL 을 1건 찍으므로 **프로브 자신의 점수에서는 되돌려 놓고 센다** —
안 그러면 프로브가 늘 빨갛게 끝나서 진짜 실패와 구별이 안 된다.
