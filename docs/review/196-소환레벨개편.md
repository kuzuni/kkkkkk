`sumNeedExp` 는 표 길이를 넘는 lv 를 **마지막 값(5000)으로 유지**한다 —
지시의 «그 뒤(Lv17~24)는 5000 유지» 를 «16칸 뒤는 마지막 칸» 이라는 한 줄로 적어서,
표가 늘거나 줄어도 이 줄이 따로 굳지 않게 했다.

```
const SUM_EXP_TABLE = [50, 200, 500, 800, 1200, 1500, 1800, 2100, 2300, 2600,
                       3000, 3300, 3600, 4000, 4500, 5000];
const sumNeedExp = lv => SUM_EXP_TABLE[Math.min(Math.max(lv | 0, 1), SUM_EXP_TABLE.length) - 1];
```

**만렙까지 총 소환 횟수 = 76,450 회**(표 합 36,450 + 5,000 × 8). 경험치 1 = 소환 1회다
(`sumAddExp(b, times)` — 이 배선은 안 건드렸다). 구 곡선은 1,224 회였으니 **62.5배**다.

### ③ 해금 사다리 — 이 작업의 «진짜» 위험

지시가 못 박은 그대로다. 만렙만 25 로 줄이고 사다리를 두면 **전설(30)·신화(40)·초월(55)·불멸(75)의
해금 레벨이 전부 만렙을 넘어 영원히 안 나온다.** 지시의 예시 사다리 **5 / 8 / 12 / 16 / 20 / 24** 를
그대로 썼다(재량 범위지만 애매한 구석이 없어 되묻지 않았다).

되돌림 시험으로 이 증상을 **실제 확률로** 재현했다 — 만렙 25 + 구 사다리에서 8등급 확률이
`6.667 / 20.000 / 40.000 / 33.333 / 0.000 / 0.000 / 0.000 / 0.000 %` 로,
**전설 이상 4등급이 전부 0.000%** 다. 새 사다리에서는
`4.712 / 14.137 / 28.274 / 23.561 / 14.137 / 9.425 / 5.655 / 0.100 %` 로 8등급 전부 > 0.

`IMMORTAL_P1` 은 **손대지 않았다.** 115 가 «목표 실효 확률» 에서 역산하도록 적어 둔 식이라
(`p1 = T × Σ다른행 / (1 − T)`) 레벨을 전혀 안 쓴다 → 만렙이 100 이든 25 든 **만렙 실효 0.10% 는 그대로**다
(게이트 C4·B 로 실측 확인). LESSONS 106-1 «값이 식을 따라야 한다» 가 여기서 값을 벌었다.

다만 불멸 램프가 **75→100(25레벨) → 24→25(1레벨)** 로 짧아졌다. `t^0.9` 곡선 자체는 그대로고
해금 시점 0 · 만렙 0.10% 도 그대로다. 램프 길이는 «총 25레벨» 이라는 지시의 산술적 귀결이다.

### ④ 이정표를 리터럴로 안 적은 이유

`PRB_STEPS`/`PRB_STEPS_EQ` 는 85 → 106 → 196 세 번 바뀌는 동안 **손으로 적은 리터럴**이라
«표는 옮겼는데 팝업 이정표는 옛 레벨» 이 되기 딱 좋은 자리였다(이번에도 그럴 뻔했다).
`prbStepsOf(roll)` = «해금 레벨(중복 제거) + 만렙» 으로 바꿔 표 하나만 고치면 따라오게 했다.
