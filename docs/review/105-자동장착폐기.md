## 2. 수정

- **주기 호출 삭제** — `autoEquipTick`·`autoEqT` 제거, `step()` 의 호출 줄 삭제.
- **`autoEquipAll()` 삭제** — 소환·합성·부팅의 전체 재계산 4곳 전부 제거.
- **대체 = `equipFillNew(ids)`** (지시 ② «빈 슬롯 자동 채움은 첫 획득 시 1회만»):
  - 후보는 **그 호출에서 «처음» 얻은 id 뿐**(`summonOne().isNew` · `craft()` 의 `isNew`). 중복 획득(n++)은 후보가 아니다.
  - 스킬은 8칸이 **남을 때만** push, 펫은 3칸, 장비는 **해당 부위 칸이 `null` 일 때만**.
  - 이미 끼워져 있는 것은 더 강한 신규가 나와도 **밀어내지 않는다**.
  - ⇒ «해제한 것이 되돌아오는» 경로가 구조적으로 없다: 되돌아오려면 그 아이템을 **다시 처음 얻어야** 하는데 이미 보유 중이라 `isNew` 가 아니다.
- **부팅은 채우지 않는다** — 여기서 빈 칸을 채우면 «해제하고 나간 칸» 이 재시작마다 되살아난다. 세이브의 장착 상태를 그대로 쓴다. (새 게임의 `slash` 1개 지급은 기존대로.)
- **`S.autoEquip` 키 폐기** · **`S.autoBuy` 기본 `false`** · 로드에서 `delete b.autoEquip`, 구 세이브는 `a105` 표식으로 **딱 한 번** autoBuy 를 꺼 준다(그 뒤 플레이어가 켜면 유지). KEY 는 올리지 않는다(44 교훈 2 — 진행도 보존).
- 지시 ③ «04/06/07 의 자동 장착(최강) 버튼» — 실제로 **그런 버튼은 없었다**(전 소스 grep 0건). 주기 실행만 있었으므로 남길 버튼도 없다.

## 5. 이 화면을 다시 만질 때 지켜야 할 것

1. **«장착을 계산해서 통째로 쓰는» 함수를 다시 만들지 마라.** 장착 배열·부위 칸을 쓰는 곳은 `toggleEquip()`(플레이어 탭) 과 `equipFillNew()`(신규 획득 + 빈 칸) **둘뿐**이어야 한다. `verify105.js` [A] 가 `autoEquipAll`/`autoEquipTick`/`S.autoEquip` 를 소스에서 0건으로 잡는다.
2. **새 획득 경로(우편 보상·퀘스트 지급 등)를 만들면 `equipFillNew([새 id])` 를 부를지 «신규 여부»부터 판단하라.** 후보에 중복 획득분을 넣는 순간 해제한 장비가 되돌아온다.
3. **주기 호출(`step()` 안의 `if(S.xxx) xxxTick(dt)`)은 «플레이어가 켠 것» 만 허용.** 지금 남은 것은 `autoBuy` 하나이고 기본 OFF 다.
4. 셋업용으로 «강한 순 8칸» 이 필요한 하네스는 페이지 안에서 직접 배열을 만들어라(`tools/verify86.js` [4] 가 그렇게 바뀌었다).
