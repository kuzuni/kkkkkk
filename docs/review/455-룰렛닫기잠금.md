## 1. 무엇이 결손이었나

닫는 길은 267 이후 **딤 탭 하나**(`$('modal').onclick` → `closeModal()`)인데 그 경로에
**회전 가드가 없었다.** 회전 3.6초 + 되감기 260ms(실측 창 **4173ms**) 동안 딤을 누르면 팝업이 닫히고,
181 의 `gone()` 이 그것을 «더 볼 사람이 없다» 로 읽어 **즉시 결판내고 지급**한다.

보상은 증발하지 않는다 — 그래서 이 결손은 «손해» 가 아니라 **«플레이어가 자기 결과를 못 본다»** 다.
`#rouRes` 의 «획득! 300» 은 **이미 닫힌 팝업 안**에 쓰이고, 재화 비행의 출발점 `.rlt-hub` 는
문서엔 남아 있으나 **그려지지 않는 노드**(width 0)라 다이아가 엉뚱한 자리에서 난다.

## 4. 처방 — 제품 3자리

### ① 판정식 하나 (`index.html`, `rouGen`/`rouPend` 선언 바로 아래)

```js
let rouPayT = -1e9;                          /* 지급이 끝난 시각 = 재화가 날기 시작하는 창의 0점 */
const ROUL_PAY_MIN = 300, ROUL_PAY_MAX = 2000;
function rouLocked(){
  if(rouSpinning) return true;               /* 회전 3.6s + 되감기 260ms (실측 창 4173ms) */
  if(rouPend >= 0) return true;              /* 당첨 칸이 정해졌는데 아직 지급 전 */
  const dt = performance.now() - rouPayT;
  if(dt >= ROUL_PAY_MAX) return false;
  return dt < ROUL_PAY_MIN || fxFlies.some(f => f.ui);   /* 허브 → HUD 알약 비행이 아직 공중 */
}
```

**꼬리를 상수로 안 박은 이유**(368 처방 — 자리를 상수에서 빼고 제품에게 묻는다):
비행 길이는 재화 개수·동시 묶음·프레임에 따라 변한다. 그래서 «끝났나» 는 `fxFlies` 에게 묻고,
상수 둘은 **그 질문의 앞뒤 울타리**로만 쓴다.

* **MIN 300** — 지급 직후 비행이 **아직 안 뜬 공백**(실측 첫 비행 **+130ms**, `fxWatch` 디바운스).
  이 울타리가 없으면 지급과 첫 비행 사이 ~130ms 에 잠금이 잠깐 풀려 그 틈으로 닫힌다.
* **MAX 2000** — 비행이 **어떤 이유로든 안 끝나도** 팝업이 영영 안 닫히는 일은 없어야 한다
  (실측 1193ms 의 1.7배). `verify455` **[G2]** 가 «착지하지 않는 유령 비행» 을 박아 두고
  상한 뒤에 풀리는 것을 단언한다 — **소프트락이 구조적으로 불가능**하다.

⚑ **`fxFlies.some(f => f.ui)` 를 고른 것은 취향이 아니다** — 전투 드랍은 `ui` 플래그가 **없다**
(`fxFly` 의 combat 분기가 그것을 안 붙인다). 팝업이 열려 있는 동안에도 자동 전투는 계속 도는데,
`fxFlies.length > 0` 로 물었으면 **전투 중에는 룰렛이 영영 안 닫혔을 것**이다.
같은 질문을 `fx3LitBusy()`(index.html)가 이미 `f.ui` 로 하고 있다 — **집안 처방을 그대로 썼다.**

### ② 문 하나에만 가드 (`closeModal()`)

```js
function closeModal(){
  const m = $('modal');
  if(m.classList.contains('on') && m.querySelector('#rouDisc') && rouLocked()) return false;
  m.classList.remove('on', 'sk8', 'rl16', 'q22', 'ml69', 'at70');
  return true;
}
```

입구마다 가드를 흩뿌리지 않는다 — **딤 탭·`gmCloseAll()`·`gmPage()`·직접 호출이 전부 이 함수를 지난다**
(318 «경로가 한 칸 짧다» 의 역방향: 경로를 늘리는 게 아니라 **모은다**).
`verify455` **[E1a]·[E1b]** 가 «모달의 `on` 을 떼는 자리가 이 한 곳뿐» 을 소스 스캔으로 못박아,
나중에 우회로가 생기면 [B] 가 못 보는 대신 **[E] 가 빨개진다.**

⚠ **[E1] 은 1회차에 «`remove('on'` 이 30건» 으로 빨갰다** — 팝업·페이지 스물아홉 개가 각자 자기 `on` 을
뗀다(`$('upw')`·`$('relw')`·…). 자를 **모달 스코프로 좁힌 것**이지 허용치를 넓힌 것이 아니다.

돌려주는 값(`true`/`false` = «실제로 닫았는가»)은 호출부가 안 쓰지만 게이트가 이 자리를 직접 묻는다.

### ③ 창의 0점 (`roulFinish` 맨 끝)

```js
rouPayT = performance.now();
```

`giveReward` **뒤**에 찍는다(비행은 이 시점부터 뜬다). **맨 끝**에 둔 이유는 위 어느 줄이 던져도
잠금이 켜진 채 남지 않게 하기 위해서다 — 잠금은 «닫기» 를 막는 물건이라 켜진 채 남는 쪽이 더 나쁘다.

## 5. 일부러 **안** 넣은 것 — 거부 피드백

등재문 ② 는 «토스트는 띄우지 않는다(필요하면 60 계열 «거부» 흔들림만)» 이라고 열어 뒀다.
**흔들림도 안 넣었다**, 두 가지 이유가 서로를 받친다:

1. **65·181 이 금지한다.** 주인 지시가 «회전 중에는 원판만 돌고 **모달 박스·딤·버튼은 완전히 정지**» 다.
   CSS 도 실제로 그것을 강제한다 — `#modal.rou-spin,… .mbox *{animation-name:none;scale:none;…}`.
   회전 중 `jz-sh` 를 걸어도 **그 규칙이 죽인다**(넣어도 안 흔들린다).
2. **꼬리 구간에서만 흔들면 «같은 거부인데 반만 반응» 이 된다.** 회전 4.2초는 무반응, 그 뒤 1.2초만
   흔들리는 것은 일관성이 아니라 고장으로 읽힌다(166 «신호는 한 곳»).

⇒ **돌고 있는 원판 자체가 이유를 말한다.** 신호를 새로 두지 않는 것이 이 화면에서는 정답이다.

## 6. 게이트 이관 — **이 작업에서 두 번째로 중요한 부분**

455 는 «닫힌다» 를 «안 닫힌다» 로 뒤집으므로, **그 자리를 이미 재고 있던 게이트 둘이 빨개졌다.**
LESSONS 329 규약대로 **항을 눌러 초록으로 되돌리지 않고, 살아 있는 표본으로 갈아 끼운 뒤
«누른 항을 묻는 항» 을 한 줄씩 더 넣었다.**

### `verify181` [F] — 갈아 끼움 + [F2] 신설

* [F] 는 «회전 중 팝업이 사라져도 지급된다»(65 «강제 닫힘» 성질)를 `closeModal()` 로 만들었다.
  455 가 그 길을 막아 **표본이 성립하지 않게 됐다**(3/3 어긋남 · dia 0 · 여전히 회전 중).
* ⇒ **살아 있는 «사라짐» 경로로 갈았다** — `showModal()` 이 본문을 가져가면 `#rouDisc` 가 모달에서
  빠지고 `gone()` 이 결판낸다. 성질(«사라져도 지급된다»)은 **한 글자도 안 약해졌다.**
* ⇒ **[F2] 신설** — «회전 중 `closeModal()` 은 안 닫고 `false` 를 돌려준다 · 끝나면 지급된다».
  이 줄이 없으면 **455 가 통째로 사라져도 `verify181` 은 초록**이다(329 가 잡은 바로 그 함정).
* [H](pagehide 안전망)는 **[F] 의 회전이 아직 돌고 있어서** 오염된 것이었다(«회전 중 이미 지급됐다 (300)»).
  `rouSpinning || rouPend >= 0` 이 비워질 때까지 기다렸다 시작하게 고쳤다 — 기대값은 안 건드렸다.

### `verify321` [9-455] 신설

[8] 이 `rouSpinning === false` 뒤 **900ms** 만 기다리고 닫는데, 455 의 꼬리(실측 +1193ms)가 아직 살아 있어
닫기가 거부됐고 **다음 줄의 사이드 클릭이 딤에 막혀 TimeoutError** 로 즉사했다.
시간을 더 박지 않고 **잠금이 풀릴 때까지 제품에게 물어** 기다린 뒤 닫는다(368 처방).
그리고 **[9-455]** 로 «정지 직후엔 잠겨 있고(닫기 거부) 비행이 끝나면 닫힌다» 를 단언한다 —
편집이 조용히 지나가지 않게 한다.
