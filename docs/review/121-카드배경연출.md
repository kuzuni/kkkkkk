### 1.2 썸네일 «들썩» (지시 ⑥)

슬롯(`.th`)의 기하 `--thw/--tht/--thcx/--thcy` 는 **1px도 안 건드렸다.** 움직이는 것은 슬롯 안의 잉크뿐이고,
`overflow:hidden` 이 슬롯 밖 유출을 막는다.

- `transform` 은 이미 **폭 정규화(`scaleX(--tsx)`, 작업 72)** 가 쓰고 있으므로 건드리지 않았다.
  대신 **개별 변환 속성** `translate`(들썩)·`scale`(스쿼시)로 움직인다 — 다른 속성이라 충돌이 없고,
  개별 속성은 `transform` 보다 먼저 적용돼 72 의 정규화가 그대로 산다
  (`verify72` 의 «`matrix(` 적용» 항목 102/102 유지).
- **⚠ 움직임은 «위» 가 아니라 «아래» 로 뻗는다(2회차 정정).** 72 가 잉크를 슬롯 천장에 붙여 앉혔기 때문에
  지시문대로 `translateY 0 → −8` 을 걸면 **올라가는 매 프레임 머리가 잘린다**(`probe121` [1] 실측:
  상단 여유 0px, 7개 위상 중 5개 잘림). 지시 ⑥ 의 «움직임은 슬롯 안에서만» 이 이기므로
  **기준 자세 = 가장 높은 포즈**로 두고 아래로 웅크렸다 편다. 진폭·스쿼시 값은 지시 그대로, 부호만 반대다.
- 애니메이션은 **1개**다(`thBob`). 들썩과 스쿼시를 따로 걸면 주기가 어긋나 웅크림과 점프가 엇박이 된다.
  한 루프(`--thb` 3.9~5.0s) 안에 **짧은 들썩 4번(8px)** + **큰 점프 1번(14px, 84% 웅크림 → 90% 정점)**.
  짧은 들썩 주기는 그 1/5 = **0.78~1.00s**(지시 «0.7~1.0s»), 큰 점프는 **3.9~5.0s 마다**(지시 «3~5s»).
- 스쿼시 `scale: 1 .96`(착지) ↔ `1 1`(정점), 큰 점프 직전만 `1 .94`. `transform-origin` 은 **발밑(50% 100%)**.
- 위상 `--thd` = −0.37s × 카드 인덱스 — 6장이 한 몸처럼 움직이지 않는다.

## 2. 이번에 잡은 함정 4개 (다음 세션도 그대로 밟는다)

### ① `animation:` 단축 속성은 `animation-play-state` 를 **running 으로 되돌린다**

처음에 이렇게 썼다:

```css
.dnc>.bgm::before,.dnc>.bgm::after{ … ; animation-play-state:paused}   /* 기본은 정지 */
.dnc>.bgm::before{ … ; animation:bgmA var(--bgt1) linear infinite var(--bgd1)}  /* ← 여기서 running 으로 리셋 */
```

**페이지를 닫아도 배경이 계속 도는 상태**가 됐다. `animation-play-state` 는 반드시 **단축 속성 뒤**에 적어야 한다.
같은 함정이 레이드 전용 `::after` 오버라이드(2개 애니메이션 지정)에도 있었다.

### ② 그 회귀를 **게이트가 못 잡았다** — `[].every()` 는 true 다

`#dunw` 는 닫히면 `display:none` 이라 **의사요소가 상자를 못 만들고**, `getAnimations({subtree:true})` 가
**빈 배열**을 돌려준다. 그래서 «전부 paused 인가» 를 `every()` 로 물으면 **무엇을 넣어도 통과**한다.
실제로 기저 규칙을 `running` 으로 되돌리는 회귀를 주입했더니 그대로 PASS 했다.
→ 게이트를 둘로 갈랐다: ⓐ 닫히면 «살아 있는 애니메이션 0개»(렌더 자체가 없다) ⓑ **렌더만 강제로 살리고
`.on` 은 뺀 상태**에서 12개 전부 paused 인지. ⓑ 가 «규칙» 을 지키는 쪽이고, 회귀 주입이 여기서 걸린다.
(LESSONS 132 «고친 게이트에는 회귀를 주입해 봐라» 의 재현)

### ③ `filter:brightness()` 로 어둡게 하면 **스크롤이 17% 느려진다**

잠금 카드 4장을 `filter:brightness(.58) saturate(.72)` 로 어둡게 했더니 03 리스트 왕복 스크롤 평균이
**31.9 → 26.4fps**. 필터는 매 프레임 그 카드를 다시 래스터한다. 같은 «어둡게» 를 `opacity:.45` 로 내면
합성만으로 끝나고 fps 가 기준선으로 돌아온다. 레이어 높이도 130% → 100% 로 줄였다(합성 텍스처만 커진다).

### ④ `transform-origin` 을 **id 리셋이 이긴다** (LESSONS 21-①·90-④ 세 번째 재발)

`#dunw i,#dunw em,#dunw b{transform-origin:50% 50%}`(1-0-1)이 `.dnc>.th>em`(0-3-1)을 이겨,
스쿼시 축이 «발밑» 이 아니라 «잉크 한가운데» 로 남아 있었다. `#dunw` 로 되받아 고쳤고 게이트에 항목을 넣었다.

넘겼던 그 값을 **서로 다른 방법으로 각각 실측해서 같은 수를 냈다** — 그래서 이번엔 넘기지 않고 고쳤다.

#### ⓐ 3회차의 «정점 여유 4px / 2px» 는 **명목 상자 기준이었고, 실제 잉크는 계속 잘리고 있었다**

- **E**: bob-1(착지)·bob-6(깊은 웅크림) 두 표본에서 잉크 상단↔슬롯 바닥 거리를 풀어 `h0 = 315.3 / 315.5`
  (Δ0.2px) → translate 0·scale 1 자세의 잉크 상단이 슬롯 천장보다 **10.5px 위**.
  따라서 «여유 4px» = 실제 **−6.4px**, «여유 2px» = 실제 **−8.5px**. 한 바퀴 3.9s 중 **49.4%** 가 절단 상태.
- **F**: CSS 모델 역산으로 같은 값 **10.3px**(골드) · **12.0px**(다이아). 8표본 중 5장이 잘린다.
- **자체 검산**(`node tools/probe121.js cut` — 신설): 슬롯 최상단 3행의 «잉크 접촉 폭» 을 6카드 × 14위상.
  `골드 19 · 다이아 79 · 유물1 33 · 유물2 178 · 유물4 20`(접촉 4~9/14 위상). 다이아·골드는 **F 의
  이미지 실측(80/75/62 · 19/19/15/16)과 오차 1~4px 로 일치** — 서로 독립인 두 측정이 맞물렸다.

> **왜 [1] 의 잉크 bbox 는 이걸 못 봤나** — [1] 은 글리프의 **글로우까지** 잡는다. 4회차에 scale 을
> 0.8 까지 줄여 봐도 bbox 가 `0/1` 로 안 변하는 것으로 확인했다(글로우가 슬롯을 꽉 채운다).
> 비평가가 보는 것은 잉크가 천장에 눌려 만든 **직선의 길이**지 bbox 가 아니다 → [0-2] 를 새로 만들었다.

#### ⓑ 그래서 진짜 손해는 «잘림» 보다 **«큰 점프가 큰 점프로 안 보이는 것»** 이었다

두 정점(짧은 들썩 4px · 큰 점프 2px)이 **둘 다 y=천장 직선에 눌려** 화면상 정점 차가 **0px** 이 됐다.
E 가 몸통 중앙(y=200)으로 재니 지시 ⑥ 의 «8 대 14 = +75%» 가 실제로는 **+28%** 로만 읽힌다.
F 도 독립적으로 «정점 차 2.0px = 지시 6px 의 33%», «총 진폭 22px 중 20px(91%)를 더 깊게 웅크려서 벌었다»
로 같은 결론에 도달했다. **위로 갈 공간이 없어서 웅크림으로 진폭을 벌던 것**이다.
