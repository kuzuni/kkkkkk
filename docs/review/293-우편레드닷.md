## 2. 그럼 «안 뜬다» 는 무엇이었나 — **경로가 한 칸 짧았다**

우편으로 가는 길은 ▦ 메뉴 **하나뿐**이다(71 이 좌측 📬 를 없앴다). 그런데

- 레드닷이 붙어 있는 자리는 **▦ 버튼 하나**이고,
- 그 배지는 **버튼을 누르는 순간 사라진다** — `#menub.mnon .bdg{display:none}`.
  이 규칙 자체는 옳다(레퍼런스 52 열림 상태에 붉은 화소가 0개다. 52 5회차 실측).
- 그리고 열린 메뉴의 **7칸에는 배지 노드가 한 개도 없었다**(프로브: «배지 달린 칸 0개»).

즉 «받을 우편이 있다» 는 신호는 **사용자가 그것을 확인하려고 손을 대는 순간 화면에서 완전히 사라진다.**
294 가 «소환 가능이면 탭 → 탭 안 카드까지 레드닷» 으로 적어 둔 것과 **정확히 같은 형태의 결손**이고,
처방도 같다 — **경로의 다음 칸까지 잇는다.**

## 3. 고친 것 (index.html 3곳)

1. **마크업** — ▦ 메뉴 «우편» 칸에 `<s class="bdg"></s>` 한 개.
2. **CSS** — `#mnw .mn-b>.bdg{…display:none}` + `#mnw .mn-b.alert>.bdg{display:block}`.
   ⚠ **두 줄 모두 `#mnw` 스코프로 적었다.** 바로 위 `#mnw i,#mnw s,#mnw b,#mnw em{display:block}` 이
   **ID 급**이라, 클래스 급으로 적으면 숨김이 지고 배지가 **조건 없이 상시 점등**이 된다 —
   166 ⓔ(도감 탭)·202(07·26·50 시트)가 두 번 밟은 그 함정이 `#mnw` 에도 그대로 있었다(등재문 ⓓ).
3. **JS** — `sideAlert()` 안에서 갈라 준다. **호출부는 한 줄도 안 고쳤다**(71 이 세운 규약 그대로):
   ```js
   const MENUCELL = {};
   document.querySelectorAll('#mnw .mn-b[data-mn]').forEach(c => MENUCELL[c.dataset.mn] = c);
   function sideAlert(k, on){
     const b = SIDEB[k]; if(b) b.classList.toggle('on', !!on);
     if(k === 'mail') MENUB.classList.toggle('alert', !!on);
     const c = MENUCELL[k]; if(c) c.classList.toggle('alert', !!on);
   }
   ```
   `data-mn` 이 키라서, 나중에 «랭킹·가방» 같은 다른 칸에 알림이 생겨도 **`sideAlert` 키 이름만 맞추면
   자동으로 연결**된다(새 분기를 안 쓴다).
4. **쥬시(60)** — `#mnw .mn-b.alert>.bdg` 를 `jzDotIn`/`jzDotPulse` 선택자 목록에 더했다(④ 일관성).

### 자리는 눈대중이 아니라 잉크 실측으로 정했다

칸은 100×100 · radius 37 이라 시각적 코너가 칸 로컬 (89,11) 쯤이다. `right/top: -4px` 로 두면
빨간 코어가 ✉️ 글리프 우상단을 **2×9px** 물었다 — 글리프 잉크를 «배지를 숨긴 캡처 / 표시한 캡처»
두 장으로 재서 확인했다(잉크 칸 로컬 **x20..79 · y14..89**).

| 오프셋 | 코어 bbox(칸 로컬) | 글리프(x≤79)와 겹침 | 패널 잘림 |
|---|---|---|---|
| −4px | x77..104 · y−4..23 | **2×9px 물림** | 없음 |
| **−6px (채택)** | x79..106 · y−6..21 | 코어 0(검정 링만 한 열 스침) | 링 우변 107.5 < 패널 우변 119 · 링 상변 절대 135.5 > 패널 상변 128.5 |

화면마다 다른 배지를 만들지 않는다.

## 4. ★ 이 작업의 교훈 — **레드닷을 켜고 끄는 것은 `renderUI()` 가 아니라 `drawHud()` 다**

게이트를 처음 쓸 때 `renderUI()` 로 상태를 밀고 쟀더니
**«다 받았는데 안 꺼진다»(left 0 · btn true)** 로 빨개졌다. 제품 버그처럼 보였지만 아니다 —
`sideAlert('attend'/'roul'/'mail'/'quest'/'promo'/'coll')` **여섯 줄이 전부 `drawHud()` 안**에 있고
`renderUI()` 는 그 줄을 한 번도 안 지난다. `loop()` 가 매 프레임 `drawHud()` 를 돌리므로 실제 화면에서는
즉시 꺼지고, **게이트만 «한 프레임도 안 돌린 채» 재서 가짜 FAIL** 이 났다.

> 레드닷 상태를 게이트에서 만들 때는 **`drawHud()` 를 부르거나 한 프레임 이상 기다려라.**
> `renderUI()` 는 탭·서브탭·카드 배지(`.tab.alert`·`.stab.alert`·`.updot`)를 맡고,
> 사이드/▦ 계열(`sideAlert`)은 `drawHud()` 가 맡는다 — **두 갈래다.**
> (유일한 예외: 절전 모드(56)는 `drawHud()` 를 통째로 건너뛴다.)
