> «모든 축복 받기 저거는 자동으로 모든 축복 받기로 바꾸고 버튼을 '이동' 으로, 클릭 시 해당 상점 페이지로»

| | 이전 | 이후 |
|---|---|---|
| 헤드라인 | `모든 축복 받기!` | **`자동으로 모든 축복 받기`** |
| 버튼 라벨 | `받기` | **`이동`** |
| 버튼 동작 | `BLESS` 3종을 한 번에 `activateBless` | **축복 팝업을 닫고 10 상점을 «이용권» 탭으로 연다** |
| 버튼 `.off` | `blessAny()` 기준으로 비활성 표시 | **항상 활성** (이동은 축복 상태와 무관) |

### 왜 이제 «이동» 이 성립하는가

측정표 34 §10 은 원래 «유료 상품이 없으므로 «이동» 할 곳이 없다» 며 레퍼런스의 크로스 프로모를
**실제 일괄 활성화 버튼**으로 바꿔 놨었다. 그 사이 **124(이용권 탭 신설)** · **151(이용권 카드 3장)** 이
«자동 축복 ₩22,900» 판매처를 만들었으므로, 이제 레퍼런스와 **같은 역할**의 크로스 프로모가 된다.
측정표 §10 의 해당 행을 취소선 + 157 갱신으로 고쳐 적었다.

### 이동 경로는 새로 만들지 않았다

164 가 이미 «홍보 배너의 [이동] 계열이 전부 쓰는» 공용 헬퍼를 만들어 두었고, 주석에 **«157 축복 프로모 → 이용권»**
이라고 자리까지 적어 두었다:

```js
function openShopTab(cat){ openShopPage(null, cat); }   /* 164 */
$('blsAll').onclick = () => { closeBless(); openShopTab('pass'); };   /* 157 */
```

`openShopPage` 가 `closeDungeon/closeTrain/closeRelw` · `setShopCatTabs` · `renderShopPage` · `syncShopNav`
를 전부 처리하므로 157 이 따로 정리할 상태가 없다. 축복 팝업만 `closeBless()` 로 걷는다.

### 잃은 기능 — 전제를 남긴다

**«비활성 축복 3종 일괄 활성화» 기능 자체가 사라진다.** 주인 지시대로다. 전제:

- **자동 축복 이용권(124/151) 보유자** — 어차피 자동 갱신이라 일괄 버튼이 필요 없다.
- **미보유자** — 축복 카드 3장을 개별 클릭한다(카드 클릭 = `activateBless`, 종전 그대로 동작).

`activateBless` 자체는 카드 클릭 경로가 계속 쓰므로 **함수는 그대로 두었다**(죽은 코드 아님).

## 2. 레이아웃 — 문구가 1.56배 길어져 **두 줄로 접히고 버튼을 덮었다**

이게 이번 작업의 실질적인 내용이다. (가) 기계적 작업이라 비평 루프는 안 돌렸지만, «요소 겹침·잘림 0건»
확인이 (가) 의 통과 조건이고 **여기서 실제로 걸렸다.**

| 문구 | 글자수 | advance @ fs70 (GameKR) | 상자 470 |
|---|---|---|---|
| `모든 축복 받기!` (구) | 한글 7 + `!` + 공백 2 | **402.5** | 들어감 |
| `자동으로 모든 축복 받기` (신) | 한글 **10** + 공백 3 | **627.7** | **+33.6% 초과** |

`getClientRects()` 로 잡은 실제 파손:

```
line1  y1559  w436.4
line2  y1639  w191.3      ← [이동] 버튼 상단이 1640. 1px 차로 겹친다
```

### 처방 — 높이는 지키고 가로만 조인다

```css
.bls-promo .tx{ right:52px; width:636px; white-space:nowrap;
                transform:scaleX(.739); transform-origin:100% 50%; font-size:70px }
```

- **`font-size` 는 안 내렸다.** 34 의 13·17회차가 «잉크 높이 ref 74» 에 맞추려고 fs 를 56→62→65→**70** 으로
  두 번 올려 잡은 값이다. fs 를 내리면 그 결과가 통째로 무너진다 → fs 70 유지 + `scaleX(.739)`
  (627.7 × .739 = **463.9 ≤ 470**, 여유 6px 은 폰트 폴백으로 advance 가 흔들려도 안 접히게 둔 몫).
- `transform-origin:100% 50%` — LESSONS 의 **A3 ⓓ**(«fs 를 내리고 scaleX 를 걸면 잉크가 옆으로 밀린다,
  `transform-origin` 을 박아라»)를 그대로 따랐다. 우변이 고정점이라 13회차의 우측 정렬(우끝 **959**)이 그대로 남는다.

### ★ 함정 — 상자를 470 에 둔 채 scaleX 만 걸면 **우측 정렬이 통째로 뒤집힌다**

첫 시도는 `left:420;right:52`(=470) 를 그대로 두고 `nowrap + scaleX(.739)` 만 걸었다. 결과:

```
FAIL [F] 헤드라인 우끝 1075.54 ≤ 스트립 우끝 1016
```

`text-align:right` + `nowrap` 인데 **advance 가 상자보다 넓으면** Chrome 은 우측 정렬을 버리고
줄을 **상자 좌측 시작점에 붙인 뒤 우측으로 흘린다.** 잉크 우끝이 959 가 아니라 **1075** — 스트립(x1016) 밖으로 나갔다.

LESSONS 의 «글리프 advance 보다 좁은 박스 + `text-align:center` → 잉크가 우측으로 밀린다» 와 **같은 함정**이고,
**center 뿐 아니라 right 에도 걸린다**(A1 비고가 center 사례만 적어 둬서 안 걸릴 줄 알았다).

→ 상자를 **advance 보다 넓은 636** 으로 잡는다(`left` 를 버리고 `right:52 + width:636`).
`right` 와 `transform-origin:100% 50%` 이 둘 다 우변 고정이라 **화면에 보이는 상자는 여전히 x420..890(=470)** 이고,
넓힌 176px 은 전부 «변환 전 좌표계» 에만 있다.
