## 1. 왜 비평 루프를 돌리지 않았나

- **레이아웃이 신규가 아니다.** 지시가 «디자인은 03 던전 페이지와 완전히 동일 — 카드 리스트 껍데기·카드 규격·
  서브탭 바·04 세부 팝업 규격 재사용, 내용만 레이드» 다. 실제로 새로 그린 CSS 는
  ① 서브탭의 «선택 상태를 좌우로 옮길 수 있게» 기하와 상태를 분리한 것,
  ② 레이드 카드의 알약 폭을 내용에 맞춘 것 두 가지뿐이고, 좌표·크기·색은 03 측정표
  (`docs/measure/03-던전팝업.md`) 값을 그대로 쓴다.
- **레퍼런스 이미지가 없다.** `docs/ref/` 에 레이드 화면 캡처가 없으므로 대조할 원본이 없다.
  결과 화면도 «신규» 이지만 A5 공용 모달(`popup()`)을 그대로 써서 새 껍데기를 만들지 않았다.
  (29 룰렛·43·44 와 같은 처리 — 레퍼런스 없는 지시 작업은 (가))
- 대신 **기능 체크(§4)** 와 **기하 감사(§5)** 로 «깨졌나» 를 본다.

## 2. 확정한 가정 (주인 확인 필요)

지시서가 «미정» 으로 남긴 것들. 바꾸려면 `RAIDS` 배열 한 곳만 고치면 된다.

| 항목 | 확정값 | 근거 |
|---|---|---|
| 제한 시간 | **30 / 60 / 120초 3종** | 지시서 가정이 «60초» 였다. 60을 기본(첫 카드)으로 두고, 03 던전이 카드 5장 리스트인 것에 맞춰 측정장을 3장으로 늘렸다 |
| 보스 | 무한 체력 샌드백 · **공격력 0** | 지시서 «죽지 않는 보스 · 보스 공격 없음» |
| 입장 횟수 | **무제한** (`∞`) | 지시서 «입장 횟수 미정» — 측정용이라 제한할 이유가 없다고 보고 무제한 |
| 보상 | **없음** (기록만) | 지시서 «보상표 미정» |
| 해금 | 최고 스테이지 1 / 15 / 30 | 03 던전의 해금 규칙(`DUN_UI.open`)과 같은 방식 |
| 기록 | `S.raidBest[id] = {dmg, dps}` · **DPS 기준 갱신** | 지시서 «최고 기록 저장 `S.raidBest`» |
| 중단(포기하기) | 기록 저장 안 함 | 짧게 끊어 DPS 를 유리하게 만드는 것을 막는다 |

## 7. 다음 세션에 넘기는 것

- **레이드 보상·입장 제한이 붙으면** `RAIDS` 항목에 필드를 추가하고 `renderRaidDetail` 의 «최고 기록» 칸을
  던전처럼 보상 아이콘+수량으로 되돌리면 된다. `.dgd-fr`/`.dgd-amt` 는 그대로 살아 있다.
- **58 연출 모듈**이 올라오면 결과 팝업(신기록)과 누적 피해 HUD 에 붙일 자리다 — 지금은 A5 기본 모달이다.
- 레이드는 `raidOn` 이 켜져 있는 동안 스테이지 진행을 멈춘다. **전투 로직을 건드리는 작업
  (59 플레이어 AI · 66 보스 AI · 67 맵 2배)** 은 `step()` 의 `if(raidOn)` 가드를 함께 확인할 것.
- 회귀: 이 구간을 다시 손대는 세션은 **손대기 전/후로 `node tools/verify46.js`** 를 돌려 60/60 을 확인한다.
