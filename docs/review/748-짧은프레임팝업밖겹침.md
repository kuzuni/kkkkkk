## 1. 뿌리 — 사슬의 뿌리가 «화면 하단» 이고, 올라간 자리에 무엇이 있는지 아무도 안 본다

짧은 프레임 보호항 셋은 서로를 되푼 **같은 값의 사본**이었다(위 327·84 주석이 그 유래를 적어 뒀다):

```
.sm-btns  bottom: min(426px, 100% − 1416px)      1416 = 패널 하변 1248 + 버튼 148 + 간격 20
.sm-close bottom: min(170px, 100% − 1475px)      1475 = 1416 + 간격 15 + 잉크 44
#sumw     --sm-bot: max(100% − 594px, 1248px)    1248 = 1416 − 168   ← 서로를 되푼다
```

프레임이 짧아지면 이 사슬이 통째로 위로 올라오는데 **올라간 자리에 탭바(180px)가 있다는 것을
아무도 안 본다.** 1600 에서 실효값은 `.sm-btns` 184 · `.sm-close` 125 였고, 닫기 상자 하변이
1477 = 탭바 상변 1420 + 57 이다.

**세로 예산을 다 적으면 이렇다(1600):**

```
리본 돌출 68 + 패널 1080 + 간격 20 + 버튼 148 + 간격 15 + 닫기 44 + 탭바 180 = 1555   (여유 45)
여기에 토스트 띠(8 + 80 + 8 = 96)까지 세면                                  = 1651   (초과 51)
```

⇒ **탭바를 비키는 것과 토스트 띠를 남기는 것은 1600 에서 동시에 못 산다.** 이 표가 이 작업의
모든 결정을 설명한다.

## 2. 처방 — 사슬의 뿌리를 한 곳으로 모으고, 그 값을 «가장 짧은 프레임» 이 정하게 한다

`--sm-floor`(패널 하변의 하한) **한 곳**을 세우고 나머지 둘을 파생시킨다(402 «표가 아니라 파생으로»).
값은 산수로 나온다 — «clamp 하한 1600 에서 닫기가 제 자연 앵커 170 에 정확히 앉는» 자리:

```
floor = 1600 − (20 + 148 + 15 + 44 + 170) = 1203
```

| 자리 | 수리 전 | 수리 후 |
|---|---|---|
| `#sumw --sm-floor` | (없음 — 값이 세 곳에 흩어져 있었다) | `1203px` |
| `#sumw --sm-bot` | `max(calc(100% - 594px),1248px)` | `max(calc(100% - 594px),var(--sm-floor))` |
| `.sm-btns bottom` | `min(426px,calc(100% - 1416px))` | `min(426px,calc(100% - var(--sm-floor) - 168px))` |
| `.sm-close bottom` | `min(170px,calc(100% - 1475px))` | `min(170px,calc(100% - var(--sm-floor) - 227px))` |

**1600 실측(수리 후)** — 패널 **123..1203** · 리본 55..142 · 버튼 **1223..1371**(간격 20) ·
닫기 잉크 **1386..1430**(간격 15) · 탭바 상변 1420 ⇒ **침범 10px = 2280 과 같은 값**.
즉 짧은 프레임에서 **레퍼런스의 세로 관계가 그대로 선다**(간격 20·15 가 산수대로 나온다).

**패널은 줄지 않았다 — 자리만 옮겼다.** 1600 에서도 패널 1080 · 그리드 868 · 30 고유 판
**가려짐 0**(`verify748` [D-1600]·[D-1600b]) — 327 무손실.

**긴 프레임은 Δ0px.** 2280·1920 은 `max()`/`min()` 의 다른 항이 이겨 `.sm-btns` 426 · `.sm-close` 170 ·
리본 538/178 이 **수리 전과 같은 값**이다(`probe748` [4-d]·[4-e] · `verify748` [C1]~[C3]).

## 4. ③ 은 여기서 안 닫는다 — 구조 한계이고 **811** 의 축이다

버튼 줄이 스킬 슬롯 원형(1275..1393)을 완전히 비키려면 버튼 하변 ≤ 1275 ⇒ `floor ≤ 1107` 인데,
리본 상변 = `floor − 1148` 이라 그 순간 **리본이 프레임 밖으로 나간다**. 즉 1600 에서는
«리본을 화면에 두면서 버튼을 슬롯 위에서 치우는» 자리가 **없다**.

수리로 겹침은 **118 → 96px** 로 줄었다(`probe748` [4-c]). 남은 96px 은 «팝업 요소가 배경 HUD 를
덮는다» 인데, 배경은 딤(z37 · 탭바 z10) **아래**라 이것은 «가려짐» 이 아니라 «딤 너머로 비침» 이고
그 축은 이미 **811**(«팝업이 떠 있는데 그 밖의 HUD 가 딤 너머로 읽힌다»)로 등재돼 있다.
⚠ 그래서 `verify748` 은 ③ 에 문턱을 안 세운다 — 세우면 811 이 그 자리를 다른 방법(HUD 억제)으로
닫았을 때 이 자가 **거짓으로** 빨개진다.
