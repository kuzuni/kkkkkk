## 2. 만든 것 — 공용 아이템 프레임 `.ifr` (지시 ①)

CSS `<style>` 안, **22 절 바로 앞**에 «104» 절을 신설했다(그 아래 화면 규칙들이 위치를 덮어써야 하므로

토큰 3개는 지시대로 **05 `.wgc` · 53 `.bg53-c` 에서 뽑았다**:

## 5. 게이트가 무엇을 보는가 (`tools/verify104.js`, 68항목)

선언을 읽으면 순환 논증이 되므로(LESSONS 60 11회차) **전부 실렌더 computed style** 이다.

1. ① 일곱 칸이 전부 `.ifr` 부착 — 2. ② 검정선 두께가 **단일값**이고 5 — 3. ③ 림 두께가 **단일값**이고 6
4. ④ 코너/폭이 전부 .233±.004 이고 **산포 ≤ .004** — 5. ⑤ 면 합성(그라데이션 + 등급면)
6. ⑥ 배지 글자·스트로크가 폭 대비 단일 비율, 바닥 걸침 > 0 — 7. ⑦ **bbox 가 측정표 값 그대로**
8. ⑧ 버튼 4종이 `.ifbtn` 이고 «색을 지운 베벨 골격» 이 **1종**으로 수렴 — 9. ⑨ 69 껍데기가 `.mbox`
10. ⑩ 렌더 경로 예외 0 · 콘솔 에러 0

게이트를 만들며 잡은 함정 2개(다음 세션도 밟는다):

* **`box-shadow` computed 형식은 «색 0px 0px 0px Npx inset»** 이다 — `inset` 이 뒤에 온다. 앞에 있다고 보고
  regex 를 짜면 인셋 두께가 전부 0 으로 읽혀 «림 단일값 0px PASS» 라는 **거짓 통과**가 난다(실제로 한 번 났다).
* **`fx-pop` 이 붙은 카드는 애니메이션 중 rect 가 0×0** 이다(`0%{transform:scale(0)}`). 12 `.sm-c` 의 bbox 가
  0×0 으로 나온 것은 CSS 가 아니라 캡처 아티팩트였다(LESSONS 92-1 과 같은 종류). 재기 전에 팝을 걷어낸다.
* `font-size`·`-webkit-text-stroke-width` 는 **프레임 좌표계 값 그대로**다(#app 의 transform 은 rect 만 바꾼다).
  둘을 같이 `/sc` 하면 비율이 정확히 2배로 나온다.
