## 1. 등재문보다 한 칸 더 나빴다 — 축은 «이 자리에서» 가 아니라 «모든 자리에서» 무음이었다

등재문은 «443 수리 전 트리에서 `35 패스(보물상자)` 가 `35 패스(스테이지)` 와 같은 화면을 열었는데
자는 0묶음이라고 찍었다» 였고, 가설은 «흔들리는 조각 하나(레드닷·뱃지·쥬시) 때문» 이었다.
338 규칙대로 처방 전에 **직접 물었다** — 두 화면의 서명 문자열을 그대로 떠서 차분을 찍었다.

가설은 **맞았지만 범위가 틀렸다.** 노드 **1250개 중 딱 둘**이 흔들린다:

| 노드 | A(스테이지) | B(box=무음실패) | 무엇 |
|---|---|---|---|
| `nickN` | 194,12,**183**,32 | 193,12,**184**,32 | 닉네임 글자 폭 — 매 로드 달라진다 |
| `cdv` | 43,**1981**,88,**77** | 43,**2002**,88,**56** | 시간이 흐르면 자란다 |

그런데 **같은 화면을 두 번 연 것(A ↔ A2)도 `nickN` 하나로 갈렸다**(194,12,183 ↔ 198,12,175).
서명이 **해시**라 1비트만 달라도 완전히 다른 값이 나오므로 —

> **이 축은 «패스 화면에서 한 번» 실패한 게 아니라, 어떤 자리에서도 한 번도 울릴 수 없었다.**

**같은 뿌리로 두 번째 축도 죽어 있었다**: 단계별 `moved` 도 해시 정확 비교라, 아무 일도 안 일어나고
420ms 만 흘러도(`cdv` 가 자란다) «움직였다» 고 찍혔다 ⇒ «눌렀는데 안 바뀐 단계» 는 **언제나 «없음»** 이었다.
등재문이 «두 축 중 하나만 실효» 라고 적은 것은 정확했지만, 실효인 쪽은 «무음 실패» **하나뿐**이고
나머지 **둘**이 죽어 있었다.

## 2. 등재문의 처방 후보 ⓐⓑⓒ 를 **셋 다 재서 셋 다 기각**했다

44화면 전수 · 각 2회 실행으로 «참-같은 쌍» 과 «참-다른 쌍» 을 갈라 봤다.

| 후보 | 결과 | 판정 |

| ⓐ 선택자만(rect 제거) | 참-다른 **5쌍**이 **정확히 일치**(`A1 탭바 열림`↔`06 장비` · `21 도감(스킬)`↔`21 도감(무기)` · `33 재화 정보` 3쌍) | ✗ 반대 방향 헛빨강 |

`103 채팅` **0.745** · `89 유물` 0.855 인데 «참-다른» 최고는 **0.9721**(형제 패스 탭)이다.
⇒ **같은 화면이 다른 화면보다 덜 닮을 수 있다.** 절대 임계값 하나로 전 화면을 가르는 자는 원리적으로 없다.

## 3. 처방 — 잰 임계값 + **파생한** 흔들림 목록 + 매 실행 자기 증명

1. **해시를 버리고 다중집합 자카드**로 «얼마나 닮았나» 를 잰다.
2. **`SIM_T = 0.985`** — 손으로 고른 값이 아니라 **틈의 한복판**이다:
   참-다른 최고 **0.9721** < `SIM_T` ≤ 참-같은 최저 **0.9968** (여유 +1.3pp / −1.2pp).
3. **흔들리는 노드는 «표» 가 아니라 파생한다**(402 규약) — 2차 통과가 준 «같은 화면 두 장» 의
   대칭차에 든 키가 곧 흔들리는 노드다. 그 키만 **자리를 안 세고 존재만** 센다(지우지 않는다 —
   지우면 그 노드가 통째로 사라져도 서명이 같아진다). 손 목록이 아니라 UI 가 바뀌면 따라온다.
4. ⚠ **희소 가드 `RARE_MAX = 4` 가 없으면 이 파생은 ⓐ 로 되돌아간다 — 만들어 보고 알았다.**
   가드 없이 뭉갰더니 잡음 바닥은 42/42 로 올라갔지만 **참-다른 4묶음이 중복으로 잡혔다**
   (`A1 탭바 열림`==`06 장비` **1.0000** · `21 도감(스킬)`==`21 도감(무기)` **1.0000** · `33 재화 정보` 3쌍 0.9878).
   뿌리는 **키의 굵기**다 — `nickN`·`cdv` 는 화면에 한둘이라 뭉개도 잃는 게 없지만
   `I`(민 `<i>` 아이콘)는 수백 개짜리 **덩어리**라 그것을 뭉개면 «아이콘 격자만 다른 화면들» 이 통째로 같아진다.
5. **`moved` 도 같은 자로** 판다(`sim < SIM_T`) — 둘째 축이 여기서 되살아난다.

## 4. 무르게 풀지 않았음을 **세 겹**으로 못박았다

- **되돌림 시험(주입구 `P397_EXTRA`)** — 448 사고를 **다시 만들어** 축이 잡는지 묻는다.
  `P397_EXTRA='[["35 패스(box=무음실패)",["#menub","#psGo","#psBar [data-ptab=\"box\"]"]]]'`
  ⇒ **무음 실패 1건 + 서명 중복 1묶음 · sim 1.0000** (수리 전 자는 여기서 «0묶음» 이었다).
- **양성 대조(매 실행)** — 가장 조용한 화면을 **다른 이름으로 한 번 더** 열어 중복으로 잡히는지 본다.
  못 잡으면 축이 죽은 것이므로 `✗` 를 찍고 **종료 코드 3**. 448 의 사고(«축이 죽었는데 0묶음이라 초록으로 읽힘»)가
  다시 조용히 지나가지 못한다. 실측 **sim 1.0000 ≥ 0.985 ✓**.
- **음성 여유(매 실행)** — 중복 아닌 쌍 중 가장 닮은 것과 임계값의 거리. 실측 **0.9741 → 여유 0.0109**.
  이 여유가 0 에 붙으면 다음 UI 변경 한 번에 헛빨강이 나므로 매 실행 눈에 보이게 찍는다.

## 5. **«못 봤다» 를 «없다» 로 안 적는다 — 남는 사각을 숫자로 고지한다**

잡음이 `SIM_T` 보다 큰 화면은 이 축이 **원리적으로** 못 본다(2절의 `103 채팅` 0.745 계열).
고친 뒤에도 **중복 축이 실효인 화면은 24~29/42**(실행마다 흔들린다)이고, 나머지는 자가 이렇게 찍는다:

```
  ⚠ 아래 화면은 **자기 자신과도** SIM_T 만큼 안 닮는다 = 이 축이 못 본다(수치는 자기 유사도):
      0.8600  13 재화 탭
      0.8793  89 유물
      ...
    → 이 화면들의 «중복 없음» 은 «확인했다» 가 아니라 «못 봤다» 다.
```

⚑ **이것이 448 의 핵심이다.** 예전 자의 죄는 «못 본 것» 이 아니라 **«못 본 것을 0 으로 찍은 것»** 이다.
남은 사각을 지우지 못했으므로 **고지**로 바꿨다 — 다음 세션이 «중복 0» 을 완료 근거로 쓰지 않게.
