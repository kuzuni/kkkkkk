## 1. 무엇이 깨져 있었나 (재현)

### ①-a `verify74` 가 첫 줄에서 즉사 — 74 회귀 게이트가 죽어 있었다

```
$ node tools/verify74.js
ReferenceError: closeRelicPage is not defined
```

`setup` 마다 `closeRelicPage(); closeRelicTab();` 을 **이름으로 직접** 부르는데,
**89 유물 개편이 두 함수를 `closeRelw()` 하나로 갈아치웠다.** 게이트는 그 뒤로 한 번도 못 돌았다.
74 는 «탭이 유실되는» **전역 입력 경로**라, 게이트가 죽어 있는 동안 그 경로의 회귀는 아무도 못 잡는 상태였다.

> **LESSONS 52-⑤ 의 재발이다** — «남이 내 구간을 지시대로 고치면 내 게이트가 먼저 깨진다».
> 이번엔 «내 구간» 이 아니라 **게이트가 부르는 API 이름** 이 갈렸다.

### ①-b 번들 브라우저가 없는 환경에서는 `chromium.launch()` 가 즉사

```
browserType.launch: Executable doesn't exist at
  /opt/pw-browsers/chromium_headless_shell-1234/chrome-headless-shell-linux64/chrome-headless-shell
```

`npm i --no-save playwright` 는 **드라이버만** 넣는다. 클라우드 컨테이너에는 크로미움이
`PLAYWRIGHT_BROWSERS_PATH`(`/opt/pw-browsers`) 에 이미 있지만 **빌드 번호가 다르면** 드라이버가 못 찾는다.
`smoke.js`·`verify100.js` 등에는 `launchOpts()` 폴백이 복붙돼 있고, `verify74` 를 포함한

### ② 스테이지 점프 시 전투 루프 크래시 — 원인 규명

```
TypeError: Cannot read properties of undefined (reading 'born')
    at step (index.html:9505)
```

`step()` 의 «적» 구간은 이렇게 돈다:

```js
for(let i=enemies.length-1;i>=0;i--){
  const e = enemies[i];
  e.born += dt;              // ← 여기서 터진다
```

그 **루프 안에서**(약 60줄 아래) 적의 접촉 공격에 플레이어가 죽으면 `failBoss('패배')` 가 불리고,
`failBoss()` 안이 **`enemies.length = 0`** 이다. 배열이 통째로 비므로 다음 반복의 `enemies[i]` 가 `undefined`.

**왜 «스테이지 점프» 가 조건인가:** `failBoss()` 는 맨 앞에서
`if(!inBossFight()) return;` 로 빠져나간다(`inBossFight = S.stage % 10 === 0 && !S.bossFarm`).
정상 진행에서 보스 스테이지는 `spawnStage()` 가 **보스 1마리 단독 스폰**이라 루프에 `i=0` 하나뿐 →
«다음 반복» 자체가 없어서 드러나지 않는다.
반면 일반 몹 50마리가 깔린 채 `S.stage` 를 ×10 으로 점프시키면
**«몹 50 + 보스전 판정»** 이라는 정상 진행에 없는 조합이 만들어져 바로 터진다.
하네스·치트·손상된 세이브 어느 쪽으로도 들어올 수 있는 상태였다.

`loop()` 은 맨 첫 줄에서 `requestAnimationFrame(loop)` 을 이미 예약하므로 게임이 완전히 멈추진 않지만,
**그 프레임의 적·투사체·장판 처리가 통째로 날아가고 매 프레임 예외가 쏟아진다.**

## 4. 다음 세션이 알아야 할 것 (교훈)

1. **게이트가 부르는 «남의 API 이름» 은 언젠가 갈린다 — 이름 하나에 게이트 전체를 걸지 마라.**
   `closeRelicPage()` 한 줄이 74 게이트 전체를 몇 세션 동안 죽여 놨다. 셋업의 «치우기» 단계는
   **있는 것만 부르고 없어진 것은 경고**하는 형태로 짜라. 죽은 게이트는 없는 게이트보다 나쁘다 —
   «PASS 를 안 본 지 오래됐다» 는 사실 자체가 안 보인다.
2. **«순회 중에 배열이 비워질 수 있는가» 는 인덱스 루프의 기본 점검 항목이다.**
   `enemies` 는 `killEnemy()` 가 **자기 인덱스 하나만** 빼므로 역방향 순회로 안전하다고 믿기 쉽지만,
   `failBoss()`·`spawnStage()`·던전/레이드 진입은 **`length = 0`** 으로 통째로 비운다.
   루프 몸통에서 «플레이어가 죽을 수 있는가 / 스테이지가 바뀔 수 있는가» 를 보면 바로 걸린다.
3. **정상 진행에서 안 터진다고 안전한 게 아니다 — «수가 1이라 다음 반복이 없었을» 뿐일 수 있다.**
   보스 단독 스폰이 이 버그를 4개월 가려 줬다. 몹 수·스테이지처럼 **바깥에서 주입 가능한 값**이
   루프 길이를 정한다면, 그 값을 비정상 조합으로 밀어 보는 게 재현의 지름길이다.
4. **`npm i --no-save playwright` 는 브라우저를 안 받는다.** 게이트가 «환경 탓» 으로 안 도는 것처럼
   보이면 코드를 의심하기 전에 실행 파일 경로부터 봐라. 이제 `tools/pwlaunch.js` 의
   `launch(chromium)` 을 쓰면 된다 — 새 게이트는 처음부터 이걸로 짜라.

### 남은 것 (110 범위 밖으로 넘김)

- `tools/verify22·30·52·65·69·72·81·84·87·A2.js` 는 아직 `chromium.launch()` 직접 호출이라
  **번들 브라우저가 없는 환경에서 못 돈다.** 고치는 법은 2줄이다:
  `const { pw, launch } = require('./pwlaunch'); const { chromium } = pw();` → `await launch(chromium)`.
  이번에 손대지 않은 이유는 **각각 다른 작업 단위의 게이트**이고 그 번호를 잡은 세션이 동시에 돌 수 있어서다
  (지시서 [1] «잡은 작업 단위 딱 1개»). 그 번호를 잡는 세션이 자기 게이트를 돌릴 때 같이 고치면 된다.
