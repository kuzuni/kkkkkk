## 1. 증상 재현

새 세이브는 탭 5칸이 전부 `.fresh` 라(`renderUI` 의 `x.classList.toggle('fresh', !S.seen[x.dataset.t])`)
NEW 리본이 **5개 동시에** 뜬다. 헤드리스 1080×2280 프로브 실측(착수 전):

| 칸 | 탭 x | 리본 bbox x | 칸 기준 좌단 |
|---|---|---|---|
| 0 영웅 | 0 | **−5.51** | −5.51 |
| 1 훈련 | 216 | 210.49 | −5.51 |
| 2 던전 | 432 | 426.49 | −5.51 |
| 3 유물 | 648 | 642.49 | −5.51 |
| 4 상점 | 864 | 858.49 | −5.51 |

다섯이 전부 칸보다 5.51px 왼쪽이다. 2~5번은 **옆칸을 덮을 뿐**이라 안 보이고,
첫 칸만 프레임(0..1080) 밖이라 잘렸다. 등재문(비평가 AF #9)이 잡은 것이 이 한 칸이다.

## 2. 원인이 둘이다 — 하나만 고치면 «맥박마다 잘리는» 상태가 된다

### ① 정지 앵커가 5.51px 왼쪽 — 폐기된 측정치를 근거로 삼은 주석

`.tab .nw` 8회차 주석:

> 8회차 — 리본은 레퍼런스대로 칸 왼쪽 경계를 **6px 넘어간다**.

근거는 측정표 `docs/measure/A1-탭바.md` **§7-2 원 측정**의 «위치: 상점 칸 좌상단 앵커,
**칸 왼쪽 경계에서 잘림**» 이다. 그런데 그 절은 **§7-1 정오표(A1 6회차)** 가 이미 뒤집었다 —
원 측정의 빨강 마스크(`r>90·r−g>40·r−b>30`)가 **주황인 옆 가게 일러스트까지 물어서**
bbox 를 오른쪽으로 47px 늘려 읽었고, 초록을 묶은 마스크로 다시 재니

| 항목 | 원 측정 | 정오(실측) |
|---|---|---|
| ref bbox | x864–1027 (w164) | **x864–980/981 (w117)** · y2163–2241 |

즉 **ref 리본은 상점 칸(864..1080) 안에 온전히 들어간다.** 칸을 넘어가지 않는다.
정오표 자신이 «구현은 프레임 좌표로 x864..981» 이라고 못 박아 뒀는데,
8회차 주석만 폐기된 원 측정을 들고 있었고 그 5.5px 이 계통 오차로 남았다.

**교정** — ref bbox 중심(칸 기준 **58.5** = 프레임 922.5)에 우리 bbox 중심을 맞춘다:

```
bbox 중심 = left + width/2      (transform-origin:50% 50% 이라 회전이 중심을 안 옮긴다)
left = 58.5 − 104/2 = 6.5px     (−1.3 → 6.5)
```

폭 112.43 은 A1 10회차에 비평가 M·N 이 «우리가 ref 보다 넓다» 로 2인 일치해 좁힌 값이라 **안 건드렸다.**
정지 bbox 는 칸 기준 **2.28 .. 114.71** — ref 0..117 안이고, 중심은 ref 중심과 **정확히 일치**한다.
(좌·우 어느 한쪽에 붙이면 폭 차이 4.6px 이 한쪽으로 몰린다. 중심 정렬이 ±2.3px 로 최대 오차가 작다.)

### ② 60 쥬시의 «점» 배율을 112px 리본이 그대로 탄다

①만 고치고 재보니 **여전히 나갔다 들어왔다** 했다. 리본은 60 쥬시 ⑥ 절의
«레드닷 등장·맥박» 한 벌을 그대로 탄다:

```
.ibtn.on .bdg, #menub.alert .bdg, .tab.fresh .nw, … {
  animation: jzDotIn .3s var(--jzs) both, jzDotPulse 2s ease-in-out .3s infinite }
@keyframes jzDotIn   {0%{scale:0}62%{scale:1.3}100%{scale:1}}
@keyframes jzDotPulse{0%,72%,100%{scale:1}84%{scale:1.14}}
--jzs: cubic-bezier(.34,1.56,.64,1)   /* 오버슈트 */
```

이 배율은 **20px 짜리 점** 기준이다. 리본은 bbox 112.43 이라 같은 배율이 절대값으로 5.6배가 된다.
rAF 스윕 실측(1080×2280, `.fresh` 재트리거 포함):

| 상태 | 정점 배율 | 정점 폭 | 첫 칸 최소 x |
|---|---|---|---|
| 맥박(2초 주기) | 1.14 | 128.17 | **−5.59** |
| 등장 팝(`display:none↔block` 마다) | **1.353** | 152.1 | **−17.53** |

«쥬시» 는 표시 전환마다 다시 도는 연출이라 탭을 여닫을 때마다 재발한다.
①만 고치면 «정지 캡처는 멀쩡한데 2초마다 잘리는» 상태 — 정지 1장만 보는 게이트로는 안 잡힌다.

**교정** — 60 의 공용 키프레임·다른 대상(레드닷·배지 8종)은 **한 글자도 안 건드리고**,
탭바 리본에만 전용 키프레임을 건다. 선택자에 `#tabbar` 를 붙여 60 규칙(`.tab.fresh .nw`, 특정도 0-3-0)보다
특정도를 높였다 — `!important` 불필요.

```
#tabbar .tab.fresh .nw{animation:nwIn .3s var(--jzs) both,nwPulse 2s ease-in-out .3s infinite}
@keyframes nwIn   {0%{scale:.88}62%{scale:1.015}100%{scale:1}}
@keyframes nwPulse{0%,72%,100%{scale:1}84%{scale:1.025}}
```

값의 근거는 **«같은 배율» 이 아니라 «같은 절대 진폭»** 이다 — 5.6배 큰 요소에 같은 %를 걸면
같은 손맛이 아니라 5.6배 큰 요동이 된다.

| | 레드닷(≈20px) | 리본(112.43) |
|---|---|---|
| 맥박 진폭 | 1.14 → **±1.4px** | 1.025 → **±1.4px** (같다) |
| 등장 «팝» | 0 → 1 로 솟는다 | `.88 → 1` 로 자라 들어온다 (**±6.7px**) · 오버슈트는 1.015 |

덤으로 프레임 밖으로 나갈 여지 자체가 사라진다. **한계 배율**은

```
58.5 ÷ (112.43/2) = 58.5 ÷ 56.215 = 1.0406
```

실측 정점은 **1.028**(등장 재트리거 포함) 로 그 아래라, 첫 칸 최소 x 가 **+0.71** 이다.

## 6. 남긴 것

- **A1 의 ①~④ 8점 통과 근거는 재측정하지 않았다.** 등재문이 «리본 기하를 바꾸면 A1 통과 근거를
  다시 재야 한다» 고 적었지만, 이번 변경은 리본을 **ref 로부터 멀어지게** 한 것이 아니라
  ref bbox 중심에 **정확히 맞춘** 것이다(옛 −5.51 → ref 중심 오차 0). 폭·높이·기울기·세로는 불변이고,
  `verifyA1` 62/62 로 나머지 A1 기하가 한 픽셀도 안 움직였음을 확인했다.
  그래도 다음 A1 폴리시 라운드에서 비평가가 리본 좌변을 다시 읽을 때는 **§7-1 정오표(864)** 를
  기준으로 삼아야 한다 — §7-2 원 측정을 인용하면 이 버그가 그대로 되돌아온다.
- **60 쥬시의 «점 배율을 큰 요소가 그대로 탄다» 는 구조 문제는 리본 한 자리만 막았다.**
  같은 규칙을 타는 대상 중 `.dnc .dot`·`.alert>.updot`·`.stab.alert>.bdg` 등은 전부 점 크기라 무해하지만,
  앞으로 60 대상 목록에 **큰 요소**를 넣을 때는 절대 진폭을 다시 계산해야 한다. 60 구간이라 손대지 않았다.
