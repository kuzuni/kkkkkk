## 1. 무엇을 뺐나

`GUIDE[]`(index.html) 의 **idx 11**

```
{ n:'출석 보상 받기', goal:1, dia:800, get:() => S.att.n,
  go:() => { gmCloseAll(); openAttend(); }, hint:'#mbox [data-att]' }
```

미션표가 **21개 → 20개**가 되고 idx 12~20 이 전부 **11~19** 로 당겨진다.

**빠진 것은 «미션» 뿐이다.** 70 출석 보상 팝업(`openAttend`)·좌측 사이드 «출석» 아이콘·`S.att` 는
그대로다 — 주인 지시는 «출석 보상 받는 **미션**» 이지 출석 기능이 아니다(§7 로 못 박았다).

## 2. 같이 움직여야 했던 3곳 (삭제 한 줄로 안 끝나는 이유)

| # | 자리 | 무엇을 | 왜 |
|---|---|---|---|
| ① | `GUIDE_V` 4 → **5** + load 이관 | `gv ≤ 4` 세이브는 **idx ≥ 12 이면 −1** | 안 하면 진행 중인 플레이어의 배너가 **한 칸 앞선 미션**을 가리킨다(=미션 하나를 건너뛴다) |
| ② | `DUN_UI.relic1.gm` 15 → **14** | 03 유물조각 던전 1단 해금 번호 | 게이트 미션은 **여전히 «스테이지 15 도달하기»** 다. 그 미션의 idx 가 14→13 이라 «수령 후 idx» 가 15→14 로 당겨진 것뿐 — 안 고치면 해금이 **한 미션 늦어진다** |
| ③ | `verify73` · `verify76` · `verify113` | 하드코딩된 미션 인덱스·개수 | 세 게이트가 «21개 · idx 13/16/18» 을 그대로 물고 있었다 |

**★ 이관 방향이 v3 의 정확한 반대다.** 76 이 idx 6 에 «목걸이» 를 **삽입**하며 `gv ≤ 2 · idx ≥ 6 → +1`
을 넣었으므로, 154 는 `gv ≤ 4 · idx ≥ 12 → −1` 이다. **두 이관은 같은 블록에서 연쇄한다** —
v3 을 먼저 적용한 뒤의 idx 로 v5 를 판정해야 gv ≤ 2 세이브가 어긋나지 않는다.
그 결과 v2 의 idx 11 은 `+1 → 12 → −1 → 11` 로 **제자리처럼 보이는데 우연이 아니다**:
v2 의 11번 미션이 곧 v5 의 11번(«유물 1회 소환하기»)이다(삽입 1칸과 삭제 1칸이 상쇄).

**구 idx 11(출석을 진행 중이던 세이브)은 이관하지 않는다.** 그 자리가 이미 다음 미션
(«유물 1회 소환하기»)이라 자연히 넘어간다 — v3 의 «지난 구간으로 되돌리지 않는다» 원칙 그대로다.

## 3. 보상 사다리 — 안 깨졌다

지시서가 «앞뒤 미션 dia 연쇄(73 ②)가 깨지지 않는지 확인» 을 걸어 뒀다. 실측 결론:

- 빠진 칸은 `dia 800` 이고 앞뒤가 `700 → [800] → 800` 이라, 삭제 후 **`700 → 800`** 으로 그대로 이어진다.
- 73 ② 의 «이전 미션 보상 = 다음 소환 미션 10연 비용» 은 `ban` 이 붙은 소환 미션 4개(idx 0·2·5·6)
  앞자리에만 걸리는데, 그 넷은 **전부 삭제점(11) 앞**이라 한 칸도 움직이지 않았다.
- 다음 미션 «유물 1회 소환하기» 는 다이아가 아니라 **유물조각(`relicCost()`)** 을 쓴다 —
  다이아 사다리와 무관하다. 그래서 앞자리 보상이 800 → 700 으로 낮아져도 막히는 것이 없다.
- 게이트로 못 박았다: 고정값 보상 17칸이 **단조 비감소**(§5) · 소환 미션 직전 보상 **≥ 1,000**(§5).
  ⚠ 「전체 dia 가 단조」로 재면 안 된다 — 소환 직전 칸은 `() => summonCost(b,10)` = 1,000 이라
  원래부터 뒤 칸(400·500)보다 크다. **고정값 부분수열**만 사다리다(1회차에 이걸로 자체 게이트가 한 번 헛불렀다).
