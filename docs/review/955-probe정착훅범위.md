## §2 처방 — 조건 ⓐ 를 넓히고, **빼는 쪽을 선언으로** 받는다

등재문의 후보 셋 중 **ⓐ 를 골랐다**. 고른 이유와 나머지를 버린 이유:

| 후보 | 판정 | 이유 |
|---|---|---|
| ⓐ 조건을 «`verify*` 또는 `probe*`» 로 넓힌다 | **채택** | 제품 **1줄**. 훅 본체·필터·상한을 한 글자도 안 건드린다. |
| ⓑ 356자에 `PW_SETTLE=1` 한 줄씩 심는다 | 기각 | 위험군만 **337자**다 — 402 가 지운 병(사본)을 337벌 새로 만든다. |
| ⓒ «정착이 필요한 자» 판별기를 세운다 | 기각 | 판별기가 곧 **또 하나의 자**다. 판별기가 틀리면 조용히 다시 거짓말한다. |

⚑ **ⓐ 를 고르면서 «빼는 쪽» 을 어떻게 받느냐가 이 작업의 실제 설계다.**
연출을 **일부러** 한복판에서 재는 자는 정착하면 안 된다(291 조건 ⓐ 가 `cap*` 을 뺀 그 이유).
그 목록을 `settle291.js` 안에 이름으로 적으면 **자가 늘 때마다 뒤처지는 사본**이 하나 더 생긴다.
⇒ 빼는 쪽도 **그 파일 안의 한 줄**로 선언한다 — 이미 있는 옵트인 관례
(`if (!process.env.PW_SETTLE) process.env.PW_SETTLE = '1';` · `probe353`·`probe941`·`probe950`)
의 대칭이고, 사유가 **그 자를 읽는 사람 눈앞에** 남는다.

### 제품 — `tools/settle291.js` 1줄

```
-  return /^verify.*\.js$/.test(entry);
+  return /^(verify|probe).*\.js$/.test(entry);
```

`index.html` **0줄** · 레이아웃 Δ0px · 밸런스 0줄 — 게이트 장치만 고쳤다.

⚑ **옵트인 선언 3자는 남겼다(no-op 이 됐는데도).** 훅은 **이름 규칙**이라 파일 이름이 바뀌거나
조건이 다시 좁아지면 그 자들은 조용히 0% 프레임으로 되돌아간다. 그 한 줄은 «이 자는 정착이
**필요하다**» 는 선언이지 스위치가 아니다(`verify955` [4b] 가 그 셋을 센다).
