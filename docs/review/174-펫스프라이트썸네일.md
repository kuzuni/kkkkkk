## 3. ★ 이번 회차의 함정 — «규칙은 있는데 안 먹는다»

캔버스를 넣고 flex 로 가운데 정렬했는데 **칸 좌단에 붙었다.** 규칙은 스타일시트에 있고(`document.styleSheets` 로 확인),
`el.matches('.sk-si.pt')` 도 true 이고, `display` 를 선언하는 **다른 매칭 규칙이 하나도 없는데** computed 는 `block` 이었다.

범인은 시트 공용 리셋이다:

```css
:is(#bSk,#bPet,#bCos) i, :is(#bSk,#bPet,#bCos) b, … {display:block; …}
```

**`:is()` 의 특정도 = 인자 중 가장 센 것** — 여기서는 ID 라 `(1,0,1)` 이다.
내 `.sk-si.pt` 는 클래스 두 개 `(0,2,0)` 이라 **자릿수 자체가 진다.**
`:is(#bSk,#bPet) b.sk-si.pt`(1,2,1) 로 되받아 풀었다.

> 배운 것: **«매칭되는 다른 규칙이 없는데 안 먹는다» 면 `:is()`/`:where()` 를 의심하라.**
> `:where()` 는 특정도 0, `:is()` 는 «가장 센 인자» 다 — 둘이 정반대인데 생김새가 같다.
> 그리고 이걸 자백시킨 도구는 `document.styleSheets` 순회가 **아니라** CDP `CSS.getMatchedStylesForNode` 였다.
> 순회는 «누가 매칭되는가» 만 알려 주고 **«누가 이겼는가» 는 안 알려 준다.**

## 4. ★ 되돌린 것 — 자동 밝기 보정(2회차)

게이트에 §5b «잉크가 등급 면에 묻히는가»(97-⑤)를 넣고 36칸을 재니
**30% 이상 묻힌 카드가 9장**, 최악 `robo2` 가 **69.4%**(면 휘도 48 위의 잉크 64)였다.
72 가 던전 카드에서 쓴 `bright` 를 그대로 빌려, 면 색을 칸이 알려 주고(`data-ubg`)
«면 휘도 + 45» 를 목표로 계수를 내는 자동 보정을 붙였다.

**결과가 더 나빴다.** 평균 잉크 휘도로 계수를 내면 밝은 면 위의 밝은 종이 255 에 포화한다 —
`pet4_4`(bird, 면 141)가 **51.2% → 66.5%** 로 악화했다. 밝기는 분포를 «옮기는» 게 아니라 «압축» 한다.

되돌린 진짜 이유는 그 위에 하나 더 있다: **주인 지시가 «전투씬과 똑같은 이미지» 다.**
보기 좋으라고 픽셀을 밝히면 이 작업의 전제 자체가 깨진다. 그래서
- 제품은 **보정 없음**으로 두고,
- 게이트 §5 에 «밝기 보정을 걸면 지문이 갈린다» 단언을 넣어 **되돌림이 굳게** 했고,
- §5b 는 **재서 기록**하고 «아예 안 보임(≥80%)» 과 «악화» 만 막는다,
- 대비 자체는 **PROGRESS 224 로 등재**했다(면 색을 바꿀지, 외곽선을 넣을지, 펫 전용 아트를 넣을지는 주인 판단).

> 배운 것: **«고칠 수 있다» 와 «고쳐도 되는가» 는 다른 질문이다.** 지시가 «똑같은 이미지» 인 작업에서
> 대비 보정은 개선이 아니라 **지시 위반**이다. 재서 기록하고 넘기는 것이 맞다.

## 4b. ★ 캡처 검수가 잡은 것 — «최대변만 보면 세로가 새어 나간다»(3회차)

게이트가 71/71 초록인 채로 캡처를 사람 눈에 보였더니 **게이트가 못 본 회귀**가 나왔다:
카드의 **«Lv.n»·«장착 중» 라벨을 스프라이트가 밀고 들어간다.**

원인은 1회차의 크기 산정이다. 이모지 잉크는 **84×71**(가로가 최대변)인데
«최대변 84» 만 보고 캔버스를 **정사각 92×92** 로 잡았다. contain 이라
세로가 물리는 bird(82×95)·robo(126×216)는 **세로 71 → 84 로 18% 커진다.**
가로만 맞고 세로가 새어 나간 것이다.

| | 이모지 | 1회차(92×92) | 3회차(92×79) |
|---|---|---|---|
| 카드 잉크 세로 | 71 | **84** | 71 |
| 잉크가 차지하는 card y | 33~104 | **26~110** | 32~103 |
| «장착 중»(y 63~107)과 겹침 | 41px | **44px** | **40px** |

3회차에 캔버스를 **이모지 잉크 박스 + 여백**(슬롯 69×59 · 카드 92×79 · 소환 75×64)으로 다시 잡아
이모지 시절 기하로 되돌렸다. 재검수 결과: **잘림 0 · 세 화면 어디에도 프레임 침범 없음 ·
같은 dragon 의 종횡이 r1/r2/r3 에서 1% 안(1.510~1.519)** · 새·로봇·용이 다 알아볼 크기(60×69·42×71·83×57).

> 배운 것: **«최대변» 은 종횡이 다른 것들을 한 자로 재려다 세로를 놓친다.**
> 아트 자리 규칙은 «최대변» 이 아니라 **bbox** 다. 게이트 축도 그래서 `max(w,h)` → `w≤85 && h≤72` 로 바꿨다 —
> 최대변만 보는 자였으면 1회차의 18% 초과를 **초록으로 통과시켰고 실제로 그랬다.**

⚠ **«장착 중» 겹침 자체는 174 가 만든 것이 아니다** — 이모지 시절에도 41px 겹쳤고(라벨이 아이콘 위에
도장처럼 찍히는 07/26 공용 레이아웃. 04 스킬·50 코스튬도 같다) 174 는 41 → 40 으로 **1px 줄였다.**
라벨을 옮기는 것은 07/26 카드 레이아웃 변경이라 내 작업 구간이 아니다 → **224** 에 같이 적었다.
