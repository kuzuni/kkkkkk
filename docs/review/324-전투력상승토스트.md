## 1. 무엇이 없었나

`cp()`(index.html «전투력» 절)는 HUD 알약(`#cpN`)에 **현재값**만 굴러 나온다(60 롤링).
플레이어가 강화·장착으로 그 값을 올려도 «얼마나 올랐는지» 는 어디에도 안 남는다 —
알약이 롤링으로 새 값에 도달할 뿐이라 **직전 값이 화면에서 지워진다.** 주인이 요구한 것은
그 차이(Δ)를 그 자리에서 말해 주는 것이다.

## 2. 왜 «호출부 계측» 이 아니라 «감시자» 인가

`cp()` 를 올리는 경로를 전부 세면 **15곳**이다:

| 계열 | 함수 | markDirty |
|---|---|---|
| 강화(장비·스킬·펫) | `levelUp` · `levelUpMax` · `levelUpAll` | ✅ |
| 장착·해제 | `toggleEquip`(스킬·펫·부위) | ✅ |
| 무기 장착 | `$('wpnBtnEq').onclick` | ✅ |
| 도감 단계 | `claimColl`(개별 · 266 일괄) | ✅ |
| 훈련 | `trainBuy` · `trainUp` | ✅ |
| 단련 | `temperUp` · `temperReset` | ✅ |
| 룬 | `runeTry` | ✅ |
| 코스튬 | `cosUpgrade` | ✅ |
| 합성 | `craft` | ✅ |
| 소환 | `doSummon` · `doSummonFree` · `summonRelic` | ✅ |
| 축복 | `activateBless` | ✅ |
| 승급 성공 | 승급 결과 처리 | ✅ |
| **강화 탭 구매** | **`$('bUp')` 클릭 → `applyBuy`** | **❌** |

자리마다 «전 / 후» 스냅샷을 심으면 **새 경로가 생길 때 조용히 빠지는** 계측이 된다.
58 이 재화 획득 연출을 호출부가 아니라 `fxWatch` 하나로 모은 것과 같은 이유로, 여기서도
**감시자 하나**로 모았다. 위 표에서 보듯 15곳 중 14곳이 이미 `markDirty()` 를 지난다
(파생 스탯 캐시를 깨야 하니까) — 그 한 줄을 «묶음 열림» 신호로 쓴다.

### ⚠ 함정 — 표의 마지막 줄

**강화 탭(`$('bUp')`)만 `markDirty()` 를 안 부른다.** `S.lv` 는 `bonus()` 캐시 밖이라
(`stat` 게터가 매번 `lv()` 를 새로 읽는다) 캐시를 깰 이유가 없기 때문이다.
감시자만 달고 끝냈으면 **주인 지시의 한복판인 «강화했을때» 가 통째로 빠졌다.**
그 한 곳만 `cpFxArm()` 을 직접 부른다.
`applyBuy` 안이 아니라 **클릭 핸들러 쪽**이어야 한다 — 자동 구매(`autoBuyTick`)가 같은
`applyBuy` 를 0.4초마다 부르므로, 안에서 열면 토스트 폭탄이 된다.

## 3. 구현 (제품 3곳 + 게이트 1개)

| 자리 | 내용 |
|---|---|
| `cp()` 바로 아래 | `CP_FX_MS` · `cpPrev/cpOpen/cpAt/cpReady` · `cpFxInit` · `cpFxArm` · `cpTick` (주석 포함 40줄) |
| `markDirty` | `const markDirty = () => { bonusDirty = true; cpFxArm(); };` |
| `$('bUp')` 클릭 | `applyBuy(...); cpFxArm(); …` (markDirty 를 안 지나는 유일한 계열) |
| 루프 | `fxClockTick` 옆에 `cpTick(performance.now())` — **절전 모드에서도** 돈다 |
| 부팅 끝 | `requestAnimationFrame(loop)` 직전 `cpFxInit()` |

### 3-1. 기준값이 «직전 프레임» 인 이유

호출부는 예외 없이 **«변이 → markDirty()»** 순서다(`o.n -= …; o.l++; markDirty();`).
그래서 markDirty 시점의 `cp()` 는 **이미 오른 값**이고, «액션 직전» 값은 묶음이 열리기 전
마지막 프레임에만 남아 있다. `cpTick` 은 묶음이 **닫혀 있는 동안에만** 기준선을 따라 올린다.

### 3-2. 묶음 창 420ms — 홀드가 한 장이 되는 근거

64/262/297 «꾹 누르면 연속 강화» 의 반복 간격은 `TR_HOLD_IV0` **160ms** 에서
`TR_HOLD_ACCEL`(0.86)로 가속해 `TR_HOLD_IVMIN` **60ms** 까지 내려간다. 첫 발과 반복 시작
사이의 최대 공백은 `TR_HOLD_DELAY` **350ms**. 셋 다 420ms 창보다 짧으므로 창은
**홀드가 멎은 뒤에만** 닫힌다 = 틱마다 1장이 아니라 **합계 1장**(fxWatch 묶음 선례).
게이트 [3] 은 그보다 **느린 100ms** 간격 12회로 민다 — 느린 쪽이 창을 닫기 쉬우므로,
이쪽이 통과하면 실제 홀드는 더 확실히 1장이다.

### 3-3. 침묵 규칙 넷

1. **Δ ≤ 0 은 안 띄운다.** 주인 지시가 «올랐는지» 다. 해제·축복 만료로 내려간 값을 «+» 로
   쓰지 않고 기준선만 새로 잡는다 — 그래서 «해제 → 재장착» 이 «+0» 노이즈를 안 낸다.
2. **자동 구매는 침묵.** `autoBuyTick` 은 `applyBuy` 를 직접 부르고 `markDirty` 도
   `cpFxArm` 도 안 지난다 → 묶음이 안 열리고 기준선이 프레임마다 따라 올라간다.
   (0.4초마다 토스트가 나면 그 자체가 149/206 이 없앤 «안내 팝업» 의 재발이다.)
3. **부팅은 침묵.** `load()`·`dailyCheck()`·시작 지급의 cp 점프는 `cpReady` 가 막는다.
4. **Δ=0 도 침묵.** 전투력에 영향이 없는 액션(재화 소비·탭 전환 등)은 markDirty 를 지나도
   Δ 가 0이라 아무 일도 안 난다.

### 3-4. 156 «표기·지급·이펙트 삼자 일치»

토스트의 수는 **`cp()` 실측차를 `fmtB` 로 찍은 것 그 자체**다(어림수·자체 계산 없음).
게이트가 매 항목에서 문자 그대로 대조한다.
