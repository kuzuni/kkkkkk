## 1. 원인 실측

`jzInit()` ⑧ 보스 등장·처치 블록(`index.html` ~25755)이 `#stinfo` 의 `.bfight` 클래스 전환을
MutationObserver 로 보고 세 연출을 띄운다. 셋 다 `jzFx()` → **`#fxl`(z-index 60)** 에 얹혔다.

| 연출 | 클래스 | 실체 | 종전 레이어 | 문제 |
|---|---|---|---|---|
| 보스 등장 비네트 | `.jz-vig` | `inset:0` 붉은 radial-gradient, 0.6s | `#fxl` **z60** | `#modal`(z28)·`#panel`(z9)·`#tabbar`(z10) **전부보다 위** → 팝업 열어 놓고 보스가 뜨면 팝업 위로 붉게 덮임 |
| 「BOSS」 슬램 리본 | `.jz-slam` | `top:300px` · font-size **132px** · 0.9s | `#fxl` **z60** | 같은 이유로 팝업을 뚫고 글자가 얹힘 |
| 처치 흰 플래시 | `.jz-wf` | `inset:0` **순백** opacity `.86 → 0` (0.15s) | `#fxl` **z60** | «화면 전체가 팍» — 주인이 폐지 지시한 바로 그것 |

`#fxl` 의 z60 은 «현재 최상위 오버레이(`#ciw` 41 · `#loading` 40)보다 위» 로 잡힌 값이라
**모달·패널·탭바를 전부 덮는 것이 설계상 당연한 자리**였다. 즉 이건 «가끔 새는» 버그가 아니라
연출을 잘못된 레이어에 얹은 구조적 위반이었다 — 작업 **77**(⚑ «전투 킬 골드 코인이 모든 팝업을 뚫고
위에 그려짐»)·**158** 이 이미 «전투씬 발(發) = 팝업 아래 / UI 발 = 팝업 위» 로 못 박은 규칙을
보스 연출만 따르지 않고 있었다.

## 3. 처방

### ① 레이어 — 보스 등장 연출을 `#fxlc`(z7 · 팝업 아래)로

`jzFx()` 에 네 번째 인자 `combat` 을 추가했다. 참이면 `fxLC()`(= `#fxlc`)를 고른다.

```js
function jzFx(cls, ms, txt, combat){
  const L = combat
    ? ((typeof fxLC === 'function') ? fxLC() : $('fxlc'))
    : ((typeof fxL  === 'function') ? fxL()  : $('fxl'));
  …
}
…
if(n){ jzFx('jz-vig', 700, '', true); jzFx('jz-slam', 1000, 'BOSS', true); }
```

`#fxlc` 는 **z7** — 스테이지 오버레이(z3)·사이드(z5)·HUD(z6) 위, `#panel`(z9)·`#tabbar`(z10)·
모든 모달(z28+) **아래**. 77 이 코인 비행을 위해 이미 만들어 둔 레이어를 그대로 썼다(새 레이어 신설 없음).
팝업이 열려 있으면 딤·시트가 연출을 자연히 덮는다 — «억제» 분기를 따로 두지 않았으므로
팝업을 닫으면 남은 연출이 그대로 이어 보인다(끊김 없음).

### ② 폐지 — 처치 흰 플래시 `.jz-wf`

CSS 규칙 · `@keyframes jzWf` · 호출부 세 곳을 **전부 삭제**했다. 레이어 이동이 아니라 제거다.
`.bfight` 해제 시 아무것도 띄우지 않는다(시간초과 `bfarm` 예외 분기도 함께 사라졌다 — 이제 무의미).

되돌림 방지용으로 `index.html` ⑧ 블록 주석(~10090)에 «다시 넣지 마라» 를 근거와 함께 박아 두었다.
