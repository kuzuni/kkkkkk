## §3 뿌리 — 291 정착 훅이 **못 보는 자리**가 있다

291 은 «고정 대기 뒤 rect» 함정을 게이트 44개에서 한꺼번에 닫았다. 붙는 자리는 하나다 —
`page.waitForTimeout()` 을 감싼다. 그런데 `verify96` [6] 은 대기를 **페이지 안에서** 한다:

```js
page.evaluate(() => new Promise(res => {
  goTab('hero'); openDungeon();
  setTimeout(() => { …getBoundingClientRect()… }, 700);   // ← 훅이 못 본다
}))
```

`probe353` ① 이 그것을 계수기로 못박았다: **훅 호출 0회.** 대기를 밖으로 두면 1회다.
291 이 심어져 있는데도 이 자리만 샌 이유가 이것이다.

**전수 조사**: 이 모양(«evaluate 안 대기 → rect»)을 쓰는 게이트는 5개다 — `96·22·46·125·299`.
그 중 **같은 블록에서 페이지 입장 연출을 여는** 것은 96 과 77 뿐이고, 77 은 rect 가 아니라
fly 노드 **개수·스태킹**을 세므로 이 흔들림에 안 걸린다. ⇒ 지금 새는 자리는 **96 하나**다.

## §4 처방 — ⓐ(근본) 를 골랐다. ⓑ 는 안 골랐다

- **ⓐ 채택**: 291 의 **같은 본체**를 페이지 안에서도 부를 수 있게 심는다(`addInitScript` 로
  `window.settle291()`). 게이트는 재기 직전 한 줄만 얹는다:
  `setTimeout(() => settle291().then(() => res(잰다())), 700)`.
  훅과 다른 점 하나 — **2 rAF 를 준 뒤 다시 본다.** 고정 대기가 «연출이 붙기 직전» 에 끝나면
  그 순간 pending 은 0 이라 그냥 지나가는데, 바로 다음 프레임에 연출이 붙으면 잰 값이 0% 프레임이 된다.
  다시 보면 그 창이 닫힌다. 상한은 훅과 같은 **1500ms** — `finished` 가 안 와도 게이트를 안 멈춘다.
- **ⓑ 기각**: 폭으로 배율을 역산해 나누는 방법(`verify337` [1]·[3])은 **96 한 자리만** 낫는다.
  같은 함정을 쓰는 다른 자리는 그대로 남고, 무엇보다 «연출 한복판의 값을 보정해서 쓴다» 는 뜻이
  이 절의 뜻(«정착한 프레임에서 ref 자리를 잰다»)과 다르다.
- **허용 오차는 한 칸도 안 넓혔다** — 좌 151 / 우 135 / Δ≤1px 그대로다(등재문의 ⚠).

⚠ `enabled()`(entry 가 `verify*.js` 인가)를 **페이지 안 본체에는 안 건다.** 이것은 부르는 게이트만
지나가므로 연출 캡처 하네스(`cap*.js`)에는 애초에 영향이 없다. 끄는 것은 되돌림 스위치
`PW_SETTLE=0`(→ `window.__settle291off`)뿐이다.

## §7 교훈 (LESSONS 353)

1. **«공용 장치가 있다» 와 «그 자리를 지난다» 는 다르다.** 291 은 44개를 닫았지만 붙는 자리가
   `page.waitForTimeout` 하나뿐이라, 대기를 페이지 **안에서** 하는 게이트는 한 번도 안 지난다.
   장치를 믿기 전에 **계수기로 «몇 번 돌았나» 를 재라** — 0 이면 그 장치는 그 자리에 없는 것과 같다.
2. **플레이키를 «확률» 로만 다루지 마라 — 위상을 스윕하면 대개 결정적이다.** 부하 재현은 1/10 이라
   같은 실행을 스무 번 돌려야 한 번 보이지만, 트리거 뒤 40·60·90·120ms 에 재면 **항상** 빨갛다.
   그 표가 «무엇의 어느 위상인가» 까지 한 번에 말해 준다.
3. **정착은 «한 번 기다리고 끝» 이 아니라 «기다린 뒤 다시 본다» 여야 한다.** 대기가 연출이 붙기
   직전에 끝나면 그 순간의 pending 은 0 이다. 2 rAF 뒤 재검사가 그 창을 닫는다.
4. **처방 팔이 공허한지 재라.** «고친 쪽이 초록» 은 기다릴 게 없어도 나온다. 정착이 실제로 기다린
   개수(n)를 같이 찍어야 그 초록이 처방 덕분임을 말할 수 있다.
