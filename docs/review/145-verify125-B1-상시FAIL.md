버그의 전부다.

## 3. 수정 — 두 검사가 «같은 소스» 를 보게 한다

등재 문서가 권장한 방향(둘이 같은 전처리를 쓰게 한다)을 택했다. 최소 수정(«주석 안 히트만 뺀다»)은
같은 함정을 한 번 더 남긴다 — 다음에 검사가 하나 더 붙으면 또 원본을 훑을 것이다.

```js
const BARE = stripComments(SRC);   /* 주석을 «같은 길이의 공백» 으로 지운 소스 */
const lines = BARE.split('\n');    /* [A] 가 쓰던 것 — 이제 한 번만 만든다 */
…
const decl = BARE.indexOf('const CUR_ICON = {');   /* [B] 도 같은 것을 본다 */
```

> **핵심 성질**: `stripComments()` 는 주석을 지우는 게 아니라 **같은 길이의 공백으로 덮는다**
> (`m.replace(/[^\n]/g, ' ')`). 그래서 문자 오프셋도 줄 번호도 원본과 1:1 이라,
> 오프셋으로 «블록 안/밖» 을 가르는 B1 의 판정 로직을 **한 줄도 안 고치고** 소스만 갈아 끼울 수 있었다.

덤으로 FAIL 메시지에 **블록 밖 히트의 줄 번호**를 붙였다(`… 블록 밖 1건 @ L1673`). 이번 건이
«어디가 문제인지 알아내는 데» 조사를 한 번 더 요구했기 때문이다.

**플래시는 «한 시점» 이 아니라 «구간» 이다** — 클릭 +100ms 쯤 붙어 700ms 쯤 걷힌다.
게이트는 `await sleep(90)` 한 장으로 찍고 있었다. **시작 모서리 바로 앞**이라 머신 속도에 따라 갈린다.
연출(`jzOn(el,'jz-bad',480)` · `jzBadPill`)은 멀쩡하다 — 게이트가 잘못 찍은 것이다.

고친 방식은 «시점» 대신 «구간 폴링»:

```js
let bad = false;
for (let i = 0; i < 30 && !bad; i++) {
  bad = !!document.querySelector('.cDia.jz-bad, #fxl .jz-badp');
  if (!bad) await sleep(20);
}
```

수명 480ms 안에서 뜰 때까지 기다렸다가 판정하고, 뜨면 즉시 빠져나온다. **4회 연속 15/15.**

## 8. 교훈 (LESSONS 에 옮김)

1. **한 게이트 파일 안에서 검사끼리 전처리가 갈리면, 갈린 쪽이 언젠가 거짓 빨강을 낸다.**
   A1 은 주석을 걷고 B1 은 안 걷었다 — 그 차이가 드러나는 데 «누군가 주석에 경로를 인용하는» 사건 하나면 됐다.
   전처리는 파일 맨 위에서 한 번 만들어 **모든 검사가 같은 것을 보게** 한다.
2. **연출을 «한 시점» 으로 찍는 게이트는 반드시 뜨고 진다.** 애니메이션은 구간이고, 그 구간의 시작은
   rAF·리플로우·모달 열림 순서에 밀린다. 고정 `sleep(n)` 이 아니라 **«뜰 때까지, 수명 안에서» 폴링**해야 한다.
   («상시 FAIL» 로 등재된 것이 실제로는 간헐 FAIL 인 경우가 이번까지 136·135 에 이어 세 번째다.)
3. **판정을 느슨한 쪽으로 고쳤으면 음성 테스트를 같이 낸다.** «빨간색이 사라졌다» 는 성공의 증거가 아니다 —
   위반을 심어도 초록이면 그 게이트는 죽은 것이다. `tools/neg145.js` 가 그 역할이다.
