## 3. 처방 — 리터럴을 갱신하지 않았다. 자리를 제품에게 물었다

**«`bottom:40px` → `bottom:42px` 로 고친다» 는 수리가 아니다.** 같은 죽음을 다음 폴리시까지 미룰 뿐이고,
그 사이에 다섯 항은 또 조용히 아무것도 안 검사한다. 368 처방(«자리를 상수에서 빼고 제품에게 묻는다»)대로
**정체로만 지목하고 줄 내용은 그때그때 읽는다**:

```js
const at = (name, re, why) => { … 정확히 한 줄일 때만 값을 돌려준다 … };
const TR_CSS    = at('TR_CSS',    /^\s*\.tr-subs\s*\{/,                       …);
const DUN_TOWER = at('DUN_TOWER', /^\s*<div\b[^>]*\bdata-dsub="tower"[^>]*>/, …);
```

파생물도 전부 읽은 줄에서 만든다 — **새 상수 0개**:

- 들여쓰기: `ind(DUN_TOWER)` (박아 둔 6칸·10칸 공백을 전부 걷어냈다)
- `N3` 의 «`.tr-sub` 규칙 부활»: `TR_CSS.replace('.tr-subs', '.tr-sub')` — **규칙 본문을 제품에서 물려받는다.**
  이 시험의 본질은 «한 글자만 다른 줄» 이지 «그 픽셀 값» 이 아니었다.
- `N6` 의 «규칙 이름 망가뜨리기»: `TR_CSS.replace('.tr-subs', '.tr-subsX')`
- `SP4_CSS` 의 줄 앞 공백: `ind(SP3_CSS)`

### 조용히 죽는 길을 셋 다 막았다
1. **§[A] 절 신설** — 앵커 6개를 시험 전에 해석해 `index.html:9556` 처럼 **줄 번호와 함께 찍는다.**
   0줄(사라졌다)이나 2줄 이상(지목이 모호하다)이면 그 자리에서 빨개진다.
   등재문의 ⚠ 그대로다 — **«초록 항의 수» 가 아니라 «자리를 찾았나» 를 먼저 보라.** 이제 그 절이 맨 위에 있다.
2. **no-op 치환 가드** — `DUN_BAR.replace(/\bsp3\b/,'sp4')` 는 바가 `.sp3` 을 안 쓰게 되면 **아무것도 안 바꾼
   같은 문자열**을 돌려준다. 옛 코드는 `indexOf(from) >= 0` 만 봐서 그것을 **초록으로 통과**시켰다
   (= `N8`·`N9` 가 «사본 그대로» 를 검사하는 빈 껍데기가 된다). `from === to` 를 «자리 없음» 으로 읽는다.
3. **앵커 null 전파** — `cat()` 이 부분 하나만 없어도 통째로 `null` 을 만들고, 편집 루프가 그것을
   «앵커 해석 실패 — §[A] 를 보라» 로 읽는다.
