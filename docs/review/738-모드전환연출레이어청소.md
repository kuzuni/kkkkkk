## 1. 순서를 지켰다 — 재현이 먼저(338 규칙)

`tools/probe738.js` 를 먼저 신설했다. 자는 «남은 것» 과 «새 모드가 스스로 만든 것» 을 섞지 않는다:

이 장치가 없으면 표가 못 쓴다 — 승급전은 입장하면서 수호자·등장 국면(457)·`jzFx` 를 **스스로**

## 2. 뿌리 — 목록이 네 곳에 복붙돼 있었고 하나는 그 목록조차 없었다

전장 정리 목록은 진입점마다 **손으로 복붙**돼 있었다.

```js
/* 수리 전 — 네 곳에 각각 */
enemies.length = 0; spawnQ.length = 0; shots.length = 0; nums.length = 0;
zones.length = 0; booms.length = 0; bolts.length = 0; corpses.length = 0; drones.length = 0; killed = 0;
rings.length = 0; ghosts.length = 0;
```

- ⚑ **`parts`(파티클)가 `spawnStage` 한 곳에만 있었다.** 던전·탑·레이드·아레나 셋은 처음부터
  파티클을 안 지우고 있었고, 그것이 표의 «parts 한 종만 남는» 칸들의 정체다.
- ⚑ **승급전은 목록 자체가 없었다** — `enemies.length = 0; spawnQ.length = 0;` **두 줄뿐**이다.
  주인이 본 그림이 정확히 여기다. 665 가 승급전의 **판정**을 런 소속으로 격리할 때 이 자리를
  지났지만, 그때 축은 «오판정» 이었고 **연출은 축이 아니었다.**

즉 결손은 «청소를 빠뜨렸다» 하나가 아니라 **«같은 목록을 네 벌 손으로 관리하고 있었다»** 다.
종이 하나 늘 때마다(114 `rings`·`ghosts` · 193 `drones` 가 실제로 그랬다) 네 자리가 따로 뒤처진다.

## 3. 처방 — 목록을 한 곳에 두고 다섯이 읽는다

```js
function clearFieldFx(){
  shots.length = 0; parts.length = 0; nums.length = 0; corpses.length = 0;
  zones.length = 0; booms.length = 0; bolts.length = 0; drones.length = 0;
  rings.length = 0; ghosts.length = 0;
  const L = fxLC(); if(L) while(L.firstChild) L.removeChild(L.firstChild);
}
```

진입점 다섯이 이것을 부른다 — `spawnStage` · `startDunRun`(던전·탑) · **`startPromo`** ·
`startRaid` · `startArena`. 665 가 판정을 런 소속으로 격리한 것의 **연출판**이다.

**경계 셋을 명시적으로 그었다.**

- ⚠ **판정 축은 안 넣는다**(`enemies`·`spawnQ`·`killed`). 진입점마다 시점이 다르고(승급전은 비운
  **뒤** 수호자를 세운다) 그것은 연출이 아니다. 그래서 호출부는 여전히 그 세 줄을 자기 자리에서 쓴다.
- ⚠ **DOM 은 전투 발 층(`#fxlc`)만** 비운다. `#fxl`(UI 발 · z60)은 660/666 의 강화·소환 버스트가
  사는 층이라 같이 비우면 **살아 있는 연출을 죽인다**. 77 이 세운 «발원으로 층을 가른다» 를 그대로 썼다.
  노드를 떼면 `fxTick` 의 `!f.el.isConnected` 분기가 `fxFlies` 항목을 스스로 걷는다(공짜 청소).
- ⚠ **660 «캔슬 금지» 와 충돌하지 않는다.** 그 규약은 **같은 모드 안**(연속 강화 틱마다 독립 스폰)의
  것이고 모드 전환은 «문맥이 끝난 것» 이라 예외다. 자에 그 경계를 항으로 세웠다 — `[K]` 가
  스테이지 안의 국면 전환(`startBoss`, 몹 구간 → 보스전)에서 연출이 **안 지워지는 것**을 단언한다.
