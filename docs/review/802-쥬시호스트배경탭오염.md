## §1 재현 — 등재문의 가설 둘이 **둘 다 그대로 맞았다**

338 규칙대로 처방 전에 `tools/probe802.js` 로 수리 전 트리를 직접 쟀다.

| 자리 | 누른 칸 | `jzTarget()` 호스트 |
|---|---|---|
| **12 결과 팝업(713) `#sumMulBar`** | `div.stab` **181px** | **`#sumMulBar` 724px** ← 네 칸이 통째로 |
| 89 유물 소환(700) `#rwMulBar` | `div.stab` 178.3px | `div.stab` 178.3px |
| 23 단련(701) `#tpMulBar` | `div.stab` 198.5px | `div.stab` 198.5px |
| 23 룬(701) `#rnMulBar` | `div.stab` 158px | `div.stab` 158px |

같은 부품(`.stabs.sp4 > .stab`)인데 **상점만** 어긋난다 ⇒ 부품이 아니라 **자리**의 병이다.
`.jz-dn` 이 실제로 붙는 노드도 `#sumMulBar` 하나였다(`probe802` [3]).

**뿌리 — `cursor` 상속 사슬**(`probe802` [2] 실측):

```
div.stab      cursor=pointer  부모=pointer   181×84
#sumMulBar    cursor=pointer  부모=pointer   724×98
div.sm-panel  cursor=pointer  부모=pointer  1080×1080   ← 크기 가드에 걸려 걸음이 멈춘다
#sumw         cursor=pointer  부모=auto     1080×2280   [JZ_NOPRESS]  ← 여기가 선언자
```

`#sumw{cursor:pointer}` 는 «터치하여 닫기» 배경 탭의 표시인데, `cursor` 는 **상속**되므로
팝업 **안쪽까지** 흘러내린다. 그러면 `jzTarget` 의 «pointer 인 동안 바깥으로 계속 나간다» 걸음이
«pointer 가 아닌 조상» 을 **영영 못 만나고**, `.sm-panel` 의 크기 가드에서야 멈춘다 —
멈춘 자리 바로 안쪽(`#sumMulBar`)은 아무것도 «선언한» 적 없는 **중간 그릇**이다.
대조군 셋이 멀쩡한 이유도 같은 한 줄로 설명된다: 그 셋의 팝업 배경은 `cursor:auto` 라
걸음이 바에 닿기 전에 끊긴다.

## §2 처방 — 등재문의 ⓐ·ⓑ 를 **둘 다 안 골랐다**

등재문의 후보는 ⓐ «`JZ_NOPRESS`/호스트 목록에 바를 넣는다» · ⓑ «배경 탭 판정을 `cursor` 가 아니라
명시 표시로 옮긴다» 였다. 둘 다 안 고른 이유:

* **ⓐ 는 자리 하나를 막는 목록**이다. 배경이 pointer 인 오버레이는 `#sumw` 하나가 아니라
  **다섯**이고(§3), 그 안에 컨트롤이 새로 생길 때마다 목록에 한 줄씩 적어야 한다 —
  402 가 «손으로 적은 목록은 던전이 늘면 그대로 뒤처진다» 로 폐기한 그 꼴이다.
* **ⓑ 는 배경 탭 쪽이 옳다는 전제**인데, 이 팝업에서 «닫기 영역» 은 실제로 `#sumw` **전체**다
  (`index.html` 의 `#sumw` 클릭 핸들러 — `.sm-b`·`.sm-sk`·`#sumMulBar` 를 뺀 나머지가 전부 닫는다.
  주석도 «12 는 `#sumw` 전체가 닫기 영역이라 달랐다» 고 적어 두고 있다). 즉 `cursor:pointer` 는
  **거짓말이 아니다** — 거짓인 것은 «pointer 면 컨트롤이다» 라는 걸음의 전제 쪽이다.

⇒ 걸음 자체를 고쳤다. `jzTarget` 을 `jzWalk`(옛 걸음 그대로 + 멈춘 자리를 같이 돌려준다)와
그 위의 얇은 판정으로 갈랐다:

1. 걸음이 «cursor 가 끊겨서» 멈췄으면 **종전 그대로** — 그 자리가 선언한 요소 = 버튼 본체다.
2. `JZ_NOPRESS`·크기 가드에서 멈췄고 **그 조상마저 `cursor:pointer`** 면, 달고 온 값이 배경 탭의
   선언일 수 있다 ⇒ **그 조상의 선언만 인라인으로 잠깐 끄고 다시 걷는다.**
   물려받기만 하던 그릇은 `auto` 로 떨어지고 **스스로 선언한 칸만** pointer 로 남는다.
3. 다시 걸어도 아무것도 안 나오면 **옛 답을 그대로 쓴다.**

**손은 새로 짜지 않았다** — 567 `jzRestRect` 가 이미 쓰는 «인라인으로 덮고 **같은 태스크 안에서**
되돌린다»(화면에는 한 프레임도 안 나간다) 그대로다. 인라인은 같은 요소의 저자 규칙을 이기고
자손의 규칙은 못 이기므로 **딱 «상속» 만** 끊는다. 재걸음은 오염된 자리에서만 돈다 —
평상시 pointerdown 은 종전대로 걸음 한 번뿐이다.

⚠ **3번(폴백)이 이 수리에서 가장 중요한 줄이다.** 팝업 안에는 «`cursor` 를 스스로 선언하지 않고
배경에서 물려받기만 하는» 노드도 있고(그 자리는 종전에도 자기 자신이 호스트였다), 폴백이 없으면
**멀쩡하던 누름이 `null` 로 사라진다.** 이 손은 **호스트를 좁히기만 하고 없애지 않는다** —
자의 [D1]·[D2] 가 그것을 못박는다.

## §3 스코프 — 이 병이 사는 자리는 **다섯**이었다

등재문이 «가족일 수 있다» 고 적어 둔 것이 사실이었다. `JZ_OVID` 22개 중 배경이 `cursor:pointer` 인
오버레이는 **`upw`·`sumw`·`statw`·`defw`·`dclw`** 다(`verify802` [A1] 이 이 목록을 **래칫**으로 잡는다 —
새 팝업이 배경 pointer 로 늘면 그 팝업의 컨트롤이 아니라 **이 항이 먼저** 빨개진다).

다섯을 전부 열어 안의 컨트롤을 전수 스윕한 결과(`verify802` [C]):

| 오버레이 | 컨트롤 | 좁혀진 자리 | 남은 어긋남 |
|---|---|---|---|
| 12 소환 결과 `sumw` | 9 | **4**(배수 칸 넷) | 0 |
| 09 일괄 강화 결과 `upw` | 0 | 0 | 0 |
| 17 스탯업 보너스 `statw` | 0 | 0 | 0 |
| 18 패배 `defw` | 3 | 0 | 0 |
| 31 던전 클리어 `dclw` | 4 | 0 | 0 |

수리가 실제로 좁힌 자리는 **배수 칸 넷뿐**이고, 나머지 자리의 답은 한 자리도 안 바뀌었다.
배경이 pointer 가 **아닌** 화면 셋(89 유물·23 훈련·05 장비 · 컨트롤 16개)은 옛 답과 새 답이
**완전히 같다**(`verify802` [E]) = 제품이 그쪽을 안 건드렸다.
