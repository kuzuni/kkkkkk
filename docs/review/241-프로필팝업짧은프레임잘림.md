## 4. 처방 — 값이 아니라 **상한**을 씌운다 (CSS 1줄)

```css
.pf{ … top:clamp(104px, 431px, calc(100% - 1404px)); … }
```

- 최대값 `100% − 1404`(= 패널 1396 + 여유 8): frameH **2280 → 876** · **1920 → 516** 이라
  둘 다 431 보다 커서 **431 이 그대로 이긴다.** frameH **1600 → 196** 이라 **이때만** 235px 위로 붙는다.
- 최소값 **104px** = 상단 HUD(0..104) 가드. 프레임 최솟값이 1600 이라 지금은 안 걸리지만,
  더 짧아져도 HUD 밑으로는 안 들어간다.

**기준 프레임(2280) 기하는 한 픽셀도 안 바뀐다** — 19 는 ①~④ 8점 통과 화면이라 이것이 제약이었다.
수정 전/후 트리를 같은 자로 나란히 재서 2280 의 `.pf`·`.pf-btn`·`.pf-tgl`·`.pf-grid`·`.pf-tab`·
`.pf-por`·`.pf-msn` **7개 좌표가 JSON 문자열까지 동일**함을 확인했다(431/1536/1692/901/833/511/1457).

### 등재문의 처방 후보 ⓐ 를 안 쓴 이유

ⓐ 는 작업 51 이 바닥 시트에 쓴 «`max-height` + 본문 내부 스크롤» 이다. 여기서는 틀린 처방이다 —
`.pf` 의 자식 좌표는 전부 **«패널 local»**(측정표 19 서두)이라 `.pf` 상자만 눌러도 자식은 따라오지 않고
그대로 상자 밖으로 흘러나온다(51 의 시트는 `.shsc` 뷰포트를 «헤더의 형제» 로 새로 판 것이라 사정이 다르다).
게다가 여기는 **패널 전체 1396 이 1600 안에 들어간다** — 접을 이유 자체가 없고, 통째로 올리는 것이 옳다.
등재문 ⓑ(«짧은 프레임에서 top 을 위로») 를 택하되, 화면비마다 값을 새로 적는 대신
**한 줄짜리 상한**으로 써서 기준 프레임을 건드리지 않았다.
