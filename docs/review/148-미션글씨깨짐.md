## 2. 원인 — 두 가지가 겹쳐 있었다

### ① 「글리프별 `transform:scaleX()`」가 **한 번도 적용된 적이 없다** (죽은 손잡이)

`@32-GLYPH-TUNE` 블록은 글리프 종류마다 `<b>[ ]` `<i>한글</i>` `<s>-/</s>` `<em>숫자</em>` 로 감싸
`font-size` · `top` · `transform:scaleX()` · `margin` 을 준다. 그런데 이 요소들은 **`display:inline` 이고
`position:static`** 이다 — CSS 상 **비치환 인라인 박스에는 `transform` 도 `top` 도 적용되지 않는다.**
헤드리스로 확인:

```
#tuto .tbtn b  display=inline transform=matrix(1.44,0,0,1,0,0)  ← 계산값엔 있지만 렌더에 반영 안 됨
```

실제로 `.tbtn b` 의 `scaleX` 를 1.15 → 1.44 로 바꿔 캡처해도 **잉크 폭이 w8 그대로**였다(그래서 되돌렸다).
`<u>` 만 자기 규칙에 `display:inline-block` 이 있어 유일하게 살아 있다.

**이것이 버그의 뿌리다.** 주석은 «`transform` 은 레이아웃 폭을 안 바꾸므로 줄어든 만큼 `margin` 으로 상쇄한다»
고 적어 두었는데, **줄어드는 쪽(`transform`)만 죽고 당기는 쪽(`margin`)은 살아서** 음수 margin 이 순수한
음수 자간이 됐다. `미`(−4/−4) · `숫자`(−3/−3) · `[ ]`(−1/−1) 이 이웃을 그대로 파먹었다.

### ② `<s>` 의 기본 `text-decoration:line-through` 를 아무도 끈 적이 없다

`<s>` 는 여기서 «슬래시·하이픈이라는 글리프 종류» 를 뜻하는 태그일 뿐인데, HTML 기본 스타일은 취소선이다.
`<u>` 는 바로 위 규칙에서 `text-decoration:none` 으로 껐는데 **`<s>` 는 빠져 있었다.**
취소선은 글자색으로 그려지지만 그 위에 `-webkit-text-stroke`(L3 3.68px · L1 4.48px)가 얹혀
**검정 가로 막대**가 되고, 하필 슬래시 한가운데를 지나 `/` 를 위·아래 두 토막으로 잘랐다
(비평가 2명이 서로 독립으로 «슬래시가 잘려 `A` 처럼 보인다» 로 지적).
L1 의 하이픈 `-` 은 글리프 자체가 같은 높이라 막대에 덮여 «하이픈이 사라진» 것처럼 보였다.

### ③ 왜 지금까지 «총폭은 맞는데» 안 잡혔나

부모 `scaleX(1.31)`(L1) · `scaleX(1.4)`(L3) 이 **줄 전체 폭만** ref 에 맞추고 있었다.
잉크는 ref 보다 넓고(L3 89 vs ref 70) 어간은 음수라, **둘이 상쇄돼 총폭만 우연히 맞았다.**
총폭을 재는 기존 게이트(`verify32`)로는 원리적으로 안 잡힌다 — 그래서 새 게이트는 **글리프별**로 잰다.
