| B | `openWeapon(id, part)` — 카드를 눌러 들어온 경로 | 지정한 카드 그대로 | **원래 옳았다**(건드리면 안 되는 쪽) |

## 2. 척도를 먼저 정해 적었다 (394 교훈 — «무엇을 눈금으로 삼는가»)

**«제일 좋은 것» = 장착 효과 `equipVal` 최대(보유한 것 중에서)**. 근거:

- 이 팝업의 [장착] 이 실제로 바꾸는 값이 `equipVal` 이다. **보유 효과 `ownVal` 을 척도로 쓰면
  «장착 버튼이 바꾸지 않는 값» 으로 줄을 세우게 된다** — 주인 문장의 뒷부분(«장착버튼을 누르면
  바로 그거로 장착») 과 어긋난다.
- `equipVal` 은 **등급 · 등급 안 티어(260 자리) · 강화 레벨**을 이미 전부 품는다(472 의 `EQ_BASE`).
  따로 가중치를 새로 만들 필요가 없다 — **새 상수 0개**.
- 동률은 260 이 정한 축 순서로만 가른다: **등급 → 강화 레벨 → 티어**.
- **보유한 것 중에서만** 고른다. 미보유 칸은 자물쇠라 [장착] 이 애초에 안 먹는다.

⚠ **등급 경계는 레벨로 못 넘는다**(260 «등급 경계 비역전» — 등급비 15.19 > `lvWear` 상한 2.2).
그래서 «낮은 등급이 최고» 표본은 만들 수 없고, 척도가 «표 자리» 가 아님을 못박는 표본은
**같은 등급, 티어 한 칸**이다(`verify482` A4 — j3 Lv44 117.54 > j4 Lv1 116.77).

## 3. 제품 (5자리)

| 자리 | 무엇 |
|---|---|
| `wpnCmp` · `wpnBest(part)` 신설 | 척도 한 벌. `wpnBest` 는 보유 0 이면 `null` 을 돌려준다 |
| `openWeapon()` | `id` 가 **명시된** 경로는 그대로, 인자 없이 열린 경로만 `wpnBest()` |
| `$('wpnBtnUp').onclick` | `levelUpAll` 뒤 `renderWpn()` **앞**에서 재선정(한 번만 그린다) |
| `cosBest()` 신설 + `renderCos()` 기본값 | 코스튬은 197 로 효율이 같아 축이 **강화 레벨**뿐 |
| `heroSubGo()` · `goTab()` | 코스튬 시트를 «여는» 두 자리에서 `cosSel = null`(→ 다음 렌더가 `cosBest()`) |

**[장착] 은 한 줄도 안 건드렸다** — 이 팝업은 처음부터 «선택 = 장착 대상» 구조라(`wpnCur()` →
`S.eqSlot[wpnPart]`) 선택만 옳아지면 주인 문장의 ③ 이 저절로 성립한다(`verify482` [D]).

⚑ **263/105 «자동 장착 폐기» 는 그대로다.** 바뀐 것은 **선택**뿐이고 `S.eqSlot`·`S.avatar` 는
버튼을 누를 때만 움직인다 — `verify482` [E]·[H2] 가 «열고·강화하고·닫아도 장착 불변» 을 단언한다.

⚠ **`cosSel` 은 모듈 수명 변수라 «열 때 초기화» 가 따로 필요했다.** `renderCos()` 안의 폴백만
고쳤으면 **처음 한 번만** 최고가 열리고 그 뒤로는 지난번 고른 것이 남는다(05 는 `openWeapon()`
이 곧 여는 자리라 이 문제가 없다). `goTab('hero')` 는 **토글**이라(이미 열려 있으면 닫는다)
두 자리 모두에 걸어야 한다 — 게이트 1회차가 여기서 빨갛게 나왔다.

## 4. 등재문 ⑤ 는 절반이 기각됐다 — 07 스킬 · 26 펫에는 «선택» 이 없다

등재문은 «같은 규칙을 07·26·50 에도 … **선택만** 바꾼다» 고 적었지만, `probe482` [F] 가
그 전제를 재 봤더니 **07·26 에는 선택 상태가 아예 없다**:

- 전역 선택 변수 — `skSel` **없음** · `petSel` **없음** (`cosSel` 만 있다)
- 그려진 `.sel` 노드 — 07 **0개** · 26 **0개** · 50 **1개**
- 하단 버튼 — 07 `[스킬 소환][일괄 강화]` · 26 `[펫 소환][일괄 강화]` · 50 `[착용][강화]`
  → **50 만** 버튼이 «선택 카드» 를 대상으로 한다. 07·26 은 카드가 곧바로 08 상세를 열고,
  장착은 카드의 `[+]/[─]` 뱃지가 한다(272) — «선택 → 장착 버튼» 이라는 모양 자체가 없다.

⇒ 여기에 «최고 자동 선택» 을 넣으려면 **선택 UI 를 새로 만들어야** 하고, 그건 «선택만 바꾼다»
가 아니라 시트 구조 변경(레이아웃 비평 루프 대상)이다. **주인이 확정하지 않은 신규 UI 를
이 작업 단위에서 만들지 않았다.** 대신 자에 못을 박아 뒀다 — `verify482` **[I]** 가
«07·26 에 선택 축이 없다» 를 단언하므로, 나중에 누가 선택을 신설하면 **그 항이 빨개져
«482 규칙(최고 자동 선택)을 같이 정하라» 고 말한다.**

⚑ **주인 판단이 필요한 한 줄**: 07·26 에도 «선택» 을 만들지(= 시트 구조 변경) 아니면
07·26 은 지금처럼 «카드 → 08 상세 → [장착]» 으로 둘지. 지금은 후자다.

## 5. 등재문 ④(레드닷)·③(08 상세 [최대 강화] 뒤 재선정)에 대해

- **④ [장착] 레드닷은 안 만들었다.** 지금 **471(레드닷 위치 전면 통일)이 돌고 있고**
  (`docs/claims/471.lock`) 그 작업이 «호스트 우상단 코너에 점 중심» 규약과 `--dot-r` 변수를
  새로 세우는 중이다. 그 위에 새 닷을 하나 더 얹으면 **471 이 훑어야 할 호스트가 하나 늘고,
  규약이 굳기 전 좌표로 박힌다.** 기능은 이미 라벨이 말해 준다(최고가 장착 중이면 버튼이
  «장착 중» 으로 꺼져 있다 — `verify482` [D] 가 그 라벨을 같이 찍는다).
- **③ 08 상세에서 한 개를 [최대 강화] 한 뒤의 재선정은 «안 함» 이 정답이라고 봤다.**
  그 경로는 플레이어가 **특정 카드를 손에 들고 있는** 상태다(카드 → 08 상세). 거기서 선택을
  다른 아이템으로 옮기면 «플레이어가 고른 것을 게임이 도로 뺏는» 모양이 되고, 263 이 세운
  «플레이어가 한 것만» 과 정면으로 부딪힌다. 주인이 이름을 댄 재선정 자리는 **[일괄 강화]**
  하나이고 그건 [C] 로 닫혔다. 카드 지정 진입을 존중하는 [B] 와 같은 원칙이다.
