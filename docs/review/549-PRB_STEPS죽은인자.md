# 549 — `verify86`·`verify193` 이 `PRB_STEPS[i].unlock` 을 넘긴다 (2026-08-31, sess-0050-17834 워커 H · 1회차)

**제품 `index.html` 0줄 · 레이아웃 Δ0px · 판정·밸런스·세이브 0줄.**
고친 것은 `tools/verify86.js` · `tools/verify193.js` **두 파일의 한 절씩**이다.
지시서 [3]-**(가)** — 레퍼런스 대조가 아니라 «자가 무엇을 보고 있나» 라 **비평가를 안 띄웠다**.

---

## §1 무엇이 문제였나 — «지금 빨강» 이 아니라 «잠복»

두 자의 «11 확률 팝업이 전 단계에 걸쳐 27종을 본다» 절은 이렇게 생겨 있었다:

```js
PRB_STEPS.forEach((_, i) => {
  openProbInfo('skill', PRB_STEPS[i].unlock);   // ← 인자
  prbStep = i; renderProbInfo();                 // ← 덮어쓰기
  ...
});
```

- **250**(주인 지시 «단계를 1·2·3 … 연속으로»)이 `PRB_STEPS` 를 «이정표 객체 배열» →
  **«소환 레벨 숫자 배열»**(`prbStepsOf() = 1..SUM_MAXLV`, index.html 30237~30239)로 바꿨다.
  그 뒤로 `PRB_STEPS[i].unlock` 은 **전 칸 `undefined`** 다.
- `openProbInfo(bank, lv)`(30310)는 `lv != null` 이 거짓이면 **예외 없이** «현재 소환 레벨»
  (`sumLv(prbBank)`)로 떨어진다 — 522-② «숫자가 틀렸는데 에러가 안 나면 가장 오래 사는 부패».
- **지금 초록인 이유는 바로 다음 줄**이다. `prbStep = i; renderProbInfo();` 가 단계를 덮어쓴다.
  ⇒ **인자는 죽었고 결과만 우연히 맞다.** 그 한 줄을 누가 «군더더기» 로 정리하는 순간
  두 자는 **조용히 좁아진 채 계속 초록**이 된다.

## §2 재현 (338 규칙 — 처방 전에 먼저 물었다)

`tools/probe549.js` **12/12 신설**. 자를 «지금 빨간가» 가 아니라
**«두 줄 중 어느 줄이 단계를 정하는가»** 에 세웠다 — 인자/덮어쓰기를 **네 조합**으로 갈라 각각
확률 팝업이 몇 종을 보는지 직접 셌다.

| 조합 | 인자 | 덮어쓰기 줄 | 본 종 수 |
|---|---|---|---|
| ⓐ 등재문이 말한 «조용히 좁아진» 자 | `.unlock`(`undefined`) | 없음 | **8 / 27** |
| ⓑ **현행 두 자** | `.unlock`(`undefined`) | 있음 | 27 / 27 (우연히 초록) |
| ⓒ **처방** (= `verify75` 246행 꼴) | 값 (`lv`) | 없음 | **27 / 27** |
| ⓓ 처방 + 덮어쓰기 | 값 (`lv`) | 있음 | 27 / 27 (ⓒ 와 같다) |

부수 실측 — 같은 `i = 3` 인데 인자에 따라 단계가 **다르다**:
`.unlock` → `prbStep 0`(현재 소환 Lv 1) · 값 → `prbStep 3`. 예외는 **안 난다**.
`PRB_STEPS` 는 1..**50**(`SUM_MAXLV`) 연속 숫자 배열이고 `PRB_STEPS_EQ` 도 같은 표라
`prbSteps()` 가 어느 쪽을 골라도 결과가 같다.

⚑ **등재문을 한 칸 정정한다** — 좁아졌을 때 보이는 것은 «일반·희귀 10행» 이 아니라 **8종**이다
(부팅 세이브의 소환 Lv 1 에서 확률이 0 이 아닌 등급만 그려진다). 방향은 등재문 그대로다.

## §3 처방 — 단계를 정하는 곳을 하나로

등재문의 두 갈래(«덮어쓰기 줄은 남겨도 된다» / «인자를 지우는 쪽이 더 정직하다») 중
**둘 다 살리지 않고 인자 하나로 모았다**. 근거는 §2 ⓓ 다 — 값을 넘기면 덮어쓰기 줄은
결과를 **한 종도 안 바꾸는 군더더기**이고, 두 곳이 단계를 정하는 한 «어느 쪽이 진짜인가» 는
다음 세션에게 다시 같은 질문이 된다.

```js
PRB_STEPS.forEach(lv => {
  openProbInfo('skill', lv);
  ...
});
```

`verify75.js` 246행이 이미 그 꼴이다(538 이 같은 함정을 밟고 고친 자리 — 거기엔 경위 주석도 있다).
두 자에도 같은 경위 주석을 남겼다: 값이 왜 아니라 인자여야 하는지, 그리고 8/27 이라는 수치.

**바꾼 곳 2자리**
- `tools/verify86.js` [5] 도감·확률 절 (246~251행 → 인자형 + 경위 주석)
- `tools/verify193.js` [6] 파급 절 (523~527행 → 같은 꼴)

## §6 다음 세션이 볼 것

- **«덮어쓰기 줄» 은 그 자체로 냄새다.** `f(x)` 를 부른 **바로 다음 줄**이 `f` 가 정한 상태를
  다시 적고 있으면, 둘 중 하나는 죽었고 어느 쪽이 죽었는지는 아무도 안 보고 있다.
  이 자리는 그 죽은 쪽이 **인자**였고, 살아 있는 쪽을 «군더더기» 로 지우는 정리 한 번이면
  게이트가 **8/27 만 보면서 계속 초록**이 되는 모양이었다(524 «가드 없는 이름을 삼킨다» 와 같은 꼴).

  `.field` 접근을 **전부 `undefined` 로 바꾸는데 예외를 한 번도 안 던진다**.
  같은 병이 538(`COLL` → `COLL_SETS`)·402(«표 두 벌»)·522(만렙 리터럴)에 이미 있었다.
