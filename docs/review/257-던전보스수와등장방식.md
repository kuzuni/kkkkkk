## 5. 함정 3건 (다른 화면에서도 재발한다 — LESSONS 등재)

**① «단독 개체» 예외는 «둘 이상» 을 가정하지 않고 쓰였다.**
66/172 가 만든 `SOLO_CHASER` 는 접선 스월과 **적 간 분리를 둘 다 끈다** — 보스가 언제나 하나였기
때문에 문제가 없었다. 3마리를 동시에 세우니 셋이 같은 점(플레이어)으로 직진해 **중심 거리가 반지름
합의 17%**(실측)까지 겹쳐 한 마리처럼 보였다. 조향력(`BOSS_SEP`)만으로는 안 풀린다 — 사거리에 들면
공격 모션 중 `spd = 0` 으로 **얼어붙은 채** 겹치기 때문이다. 그래서 조향 + **위치 해소(depenetration)**
두 겹으로 갈랐고 98% 로 올라갔다.
→ 규칙: **미는 대상을 «단독 개체끼리» 로 한정한다.** 무리 몹과는 여전히 안 밀므로(66 의 병이 안 돈다),
그리고 필드에 단독 개체가 하나뿐이면 힘이 **정확히 0** 이라 스테이지 보스·승급 수호자·아레나·
보스 1마리 던전의 좌표가 한 px 도 안 움직인다(verify66·172·257 [7] 로 못박음).

**② 게이트 2개가 «보스는 언제나 1마리» 를 상수로 굳혀 두고 있었다.**
`verify255` [B]·[C] 30건과 `verify178` ⑤ 3건이 **한 번에 빨개졌다** — 제품이 틀린 것이 아니라
게이트의 전제가 낡은 것이다(237·239·242 와 같은 계열). 고친 방향은 «값을 느슨하게» 가 아니라
**«무엇을 재는지» 를 다시 적는 것**이다: 「1마리 체력 = 0.3」 → 「1마리 = 0.3/bn **이고 동시 등장 합 =
0.3**」. 후자가 결정 ②를 직접 잰다 = 느슨해진 것이 아니라 **더 조여졌다**(verify255 100 → **124건**).

**③ «몇 마리 남았나» 표기는 남은 쪽을 앞에 둬야 읽힌다.**
처음에 잡은 쪽을 앞에 채워 «○●●» 로 그렸더니 3마리 중 몇이 남았는지가 한눈에 안 들어왔다.
등재문 ③ 이 예로 든 표기가 «●●○» 인 이유가 그것이다 — 남은 놈이 앞이다.

## 6. 남은 것 / 인계

- **탑(209·210)은 1마리 그대로다.** 등재문이 «209 는 264 의 몫» 이라고 적어 둔 그대로 손대지 않았다.
  `dunBossN`/`dunBossMd` 는 탑에도 그냥 붙으므로, 264 가 탑을 «보스 전투» 로 바꿀 때 `DUN_UI.tower`·
  `DUN_UI.despair` 에 `bn`/`bm` 한 줄만 적으면 이 층이 그대로 얹힌다.
- **03 던전 목록 카드**는 아직 보스 수를 말하지 않는다(04 세부 리본만 말한다). 목록 행은 레퍼런스
  기하가 빡빡해 글자를 더 넣을 자리가 없다 — 아이콘(●●○ 뱃지)이 필요하고 그것은 **아트 대기**다
  (측정표 30 §11 에 등재).
- **동시 등장 스폰 링**: `makeEnemy` 는 각도를 매번 무작위로 뽑는다. 3마리가 우연히 붙어 서는 판이
  있어 첫 몇 프레임은 해소 중이다(프로브의 «최소 간격» 이 0.70~0.99 로 흔들리는 이유 — 게이트는
  해소 프레임 12틱을 뺀 뒤 재서 98% 다). 링 각도를 균등 분할하면 더 깔끔해지지만 `makeEnemy` 는
  전 종이 쓰는 공용 경로라 이 작업 구간이 아니다.
- **난이도 자체는 199 의 몫이다.** 이 작업은 «수·방식» 축만 넣었고 총 체력·총 공격력·보상·제한
