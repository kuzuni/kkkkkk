### 1-2 도착 envelope 을 «분배» 로 잡은 이유

주인 지시의 세 숫자 — 퍼짐 0.22 + 머묾 0.12~0.20 + 흡수 0.55~0.75 — 를 **그대로 더하면**
첫 도착이 0.89s 가 되어 같은 지시의 검증 항목 «첫 도착 0.5~0.6s» 와 어긋난다(마지막 도착도
스태거 0.525 를 더하면 1.70s 로 «1.2~1.4s» 를 넘는다). 두 진술이 충돌하므로 **검증 항목 쪽을
지켰다** — 그것이 완료 판정에 실제로 쓰이는 수치이기 때문이다.

구현은 «흡수 길이» 를 상수로 두지 않고 **도착 시각을 균등 분배**한 뒤 역산한다:

```
u          = i/(cnt−1)
퍼짐 끝    = 0.22
흡수 시작  = 0.22 + (0.12 + u·0.08) + u·min(0.50, (cnt−1)·0.035)
도착       = 0.50 + u·0.72
흡수 길이  = clamp(도착 − 흡수 시작, 0.15, 0.80)
```

이렇게 두면 **아이콘 수(8~16)가 달라져도 envelope(첫 0.50 · 마지막 1.22 · 총 1.22s)이 고정**된다.
아이콘 수에 따라 «보상 수령은 1.2초인데 미션 하나는 0.9초» 로 갈리는 것을 막는 것이 목적이다.
cnt=16 실측 분배: 흡수 길이는 i=0 에서 0.28s → i=15 에서 0.30s(중간 0.28s) — 지시의 0.55~0.75s
보다 짧다. **이 한 항목만 지시 수치를 못 지켰다**(위 충돌의 결과). 남은 문제로 아래 §5 에 적는다.

### 1-3 벽시계 기준 타임라인

3박자는 `f.t += dt` 가 아니라 **`f.st`(시작 시각) 기준**으로 돈다. `dt` 는 loop 에서 0.1s 로
클램프되므로 프레임이 길어지면 연출이 벽시계보다 늘어진다 — 실제로 dt 누적판에서 1.22s 설계가
**1.40s** 로 찍혔다(58 14회차가 숫자 롤링에서 겪은 것과 같은 함정, 그 교훈의 3박자 판).

### 1-4 알약 «톡톡» 펄스와 그 버그

도착이 0.5~1.22s 에 걸쳐 5~6번 오므로 펄스는 **짧고 작게 여러 번**(`.fx-punch2`, .16s, ×1.09)이다.
구현 중에 잡은 버그: 재시작 간격(160ms)보다 **지우기 타이머(190ms)가 길면 앞 펄스의 타이머가
다음 펄스의 클래스를 떼어** 5번 도착에 펄스가 2번만 보인다. 420ms 짜리 전투 발에서는 간격 == 길이라
드러나지 않던 잠복 버그다 → `clearTimeout` 으로 앞 타이머를 끈다.
봉우리도 18~46% 고원으로 폈다 — .16s 짜리에서 «한 점 봉우리» 는 ≥1.085 구간이 12ms 라 캡처에
한 프레임도 안 걸린다(58 6회차가 .42s 에서 이미 겪은 것).

### 1-5 소리

`sfx(name, opt)` 에 `{rate, gap}` 선택 인자를 더했다(안 주면 종전과 완전히 동일 — 98 의 이름별
게인·최소 간격 그대로). 퍼짐은 `rate 0.82`(촤르륵 대용) 1회, 도착은 실제로 튄 펄스에만
`rate 1.00 → 1.14 → 1.28` 3단계 «팅». **전용 촤르륵/팅 파일은 없다** — `coin` 을 피치로 나눠 쓰는
임시 처리이고, 78 규칙대로 소스가 들어오면 교체한다(§5 «사운드 대기»).

## 3. «퀘스트 행 위 관통 0» 을 어떻게 쟀나

리스트 하단 → 우상단 HUD 라 형제 행 위를 지나는 것은 **기하학적으로 불가피**하고, 58 11회차가
«경로·제어점을 아무리 손봐도 회수되지 않는다» 고 결론 내고 **지나가는 동안 형제 행을 딤 처리**하는
것으로 처방을 확정했다. 93 이 지켜야 할 것은 «3박자로 길어진 연출 내내 그 딤이 유지되는가» 이므로
게이트는 **딤이 안 걸린(`.fx-dim` 없는) 형제 행 위의 통과 횟수**를 센다 → 0회.
(딤을 무시하고 세면 151회다. `FXSOLO` 를 380 에 두면 0.38s 뒤 딤이 풀린 채 코인이 1.22s 까지
지나가므로 **58 오독이 그대로 회귀**한다 — 이것이 `FXSOLO/FXHOLD` 를 1360 으로 올린 이유다.)
