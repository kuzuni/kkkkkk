## 1. 결손 — 「판정은 있는데 입구가 제각각이었다」

「전투 중인가」의 단일 판정은 **이미 있었다**(`bossMode()`, index.html ~22539 — 284 가 HUD 잔존 사고를
막으려고 세운 그 함수다). 그런데 **입구는 그 함수를 한 곳도 안 봤다.** 입구마다 `dunRun || raidOn || arena`
를 손으로 다시 적고 있었고, 그 3항에는 **승급전(`promo`)과 스테이지 보스전(`bossOn`)이 빠져 있었다.**

이것이 LESSONS 58-① 이 말하는 그 모양이다 — 「같은 값을 두 곳에 적으면 반드시 어긋난다」.

## 2. 처방 — 새 상태를 만들지 않는다

```js
const battleBusy = () => bossMode() !== '';
function battleBlock(msg){ if(!battleBusy()) return false; if(msg) notify(msg); return true; }
```

- **새 전역 상태 0개.** 켜고 끄는 곳이 늘면 「전투는 끝났는데 잠긴 채로 남는」 자리가 생긴다.
  판정은 `bossMode()` **재사용**이고, 그래서 던전·탑이 따로 등장하지 않는다 —
  탑은 별도 상태 없이 `startDunRun` 하나로 돌아 `'dun'` 에 이미 들어 있다(209).
- **조용히 막지 않는다.** 문구 없이 return 하면 「눌러도 아무 일도 안 일어나는 버튼」이 되고,
  그건 423·74 가 결함으로 잡은 바로 그 모양이다. 문구는 두 벌 한 쌍이다 —
  열기 `⚔️ 전투 중에는 열 수 없습니다` · 입장 `⚔️ 전투 중에는 입장할 수 없습니다`.
  (94 「12자 이내」는 **캔버스 `showMsg`** 규약이고 이건 206 계열 notify 토스트다.)

## 3. 막히면 안 되는 자리 — 「순서」가 근거다

주인 지시의 반대쪽이다. **339 연속 도전과 31 클리어 [다음]·[재도전] 은 막히면 안 된다.**
근거는 새 예외 분기가 아니라 **호출 순서**다:

```
endDunRun()  →  dunRun = null  →  spawnStage()  (bossOn = false)  →  finishDunRun()  →  openDunClear()
                                                                                          ↑ 여기서부터 battleBusy() === false
```

`verify453` [D] 가 이것을 **실제 클리어 경로로** 못박는다 — 던전에 들어가 `endDunRun(true, false)` 를
태운 뒤 `bossMode()` 가 `''` 인 것, `dclAutoCan()` 이 `true` 인 것, `challengeDungeon` 이 실제로 **다시 입장**하고
**입장권이 정상 차감**(8 → 7)되는 것까지 잰다.

같은 절이 **스테이지 파밍 흐름**도 지킨다 — 50킬 자동 보스 진입(`startBoss`)과 파밍 [재도전](`retryBoss`)은
비전투 상태에서 그대로 산다(D6·D7). 「막는 것은 «다른 모드에서 스테이지 보스로» 이지 «잡몹 → 보스» 가 아니다」는
등재문 예외 ⓑ 그대로다.

## 4. 신호 — 「켜지는데 못 누르는 닷」을 안 만든다

321 이 세운 규약은 **「레드닷 = 지금 누를 수 있다」** 다. 입장을 전면 차단해 놓고 닷을 그대로 켜 두면
그 규약이 깨진다. 그래서 네 개의 `*CardOk` 판정 앞에 `!battleBusy()` 를 붙였고, 그 하나로

- 03 카드 dot(341 `.dot`) — ⚠ **필요하다.** 던전 페이지가 전투 중에 *열리는* 일은 없어도,
  **열어 둔 채 스테이지 보스전이 시작되는** 경로가 있다(`#dunw` 는 전체화면 페이지이고 그 아래에서 스테이지가 계속 돈다).
- 서브탭 3칸 배지(`dunSubAlert`) · 탭바 「모험」 배지(`advAlert`) — 298 이 세운 「한 자를 같이 본다」 구조 덕에 **자동으로** 따라온다.

가 한꺼번에 따라온다. 사이드 「승급전」 닷은 `sideAlert('promo', promoReady() && !battleBusy())`.

그리고 **왜 꺼졌는지를 자리에서 말한다** — 탭 「모험」과 사이드 「승급전」에 `.busy` 딤:

```css
.ibtn.busy .si,.tab.busy .ti{opacity:.5}
```

- ⚠ **값을 새로 정하지 않았다** — 바로 위 `.ibtn.lock .si{opacity:.5}` 와 **같은 .5** 다(같은 뜻: 지금은 못 누른다).
- ⚠ **기하는 한 값도 안 건드린다**(width/height/font-size/margin 0줄) ⇒ **레이아웃 Δ0px**.
  `verify453` E9·E10 이 전투 전/중 `getBoundingClientRect` 를 대조해 못박는다
  (탭 `[432,2100,216,180]` · 사이드 `[45,578,100,114]` — 두 상태가 **바이트 단위로 같다**).
- ⚠ `.lock` 처럼 자물쇠를 얹지는 **않는다** — 잠금(영구)과 전투 중(한때)은 다른 사건이다.
