## 2. 처방 — 이름을 프로세스마다 유일하게, 정리는 `finally` 로

세 줄이 전부다(`tools/verify169.js` `[E]`).

1. `const negPath = n => path.join(ROOT, `.v169-neg${n}-${process.pid}.html`)` — **pid 를 섞는다.**
   사본을 저장소 루트에 두는 이유(`assets/*` 가 상대 경로 · 59·74·58·191 선례)는 **그대로 지켰다.**

   `ENOENT` 는 조용히 넘기고 나머지 실패만 `WARN` 으로 찍는다.
3. 사본을 쓰는 블록을 **`try { … } finally { rmNeg(NEGn) }`** 로 바꿨다 —
   가운데서 던져도(브라우저 실패·판정 예외) 사본이 남지 않는다. 수리 전에는 `unlinkSync` 가
   블록 **뒤에** 맨몸으로 있어서 도중에 던지면 1.3MB 사본이 그대로 남았다.

**곁다리 수리 1건 — `.gitignore` 에 규칙이 아예 없었다.** `.v169-neg*.html` 은 `index.html` 통째
사본(1.3MB)인데 무시 규칙이 없어, **즉사가 남긴 사본이 `git add -A` 에 딸려 갈 수 있었다**
(저장소는 2026-08-30 에 이력 정리로 대용량 커밋을 걷어낸 적이 있다). 고정 이름 시절까지 덮도록

## 6. 교훈 (LESSONS 646)

1. **«루트에 사본을 둔다» 는 규약과 «고정 이름» 은 다른 결정이다.** 루트에 두는 이유
   (`assets/*` 상대 경로)는 지켜야 하지만, 이름까지 고정할 이유는 한 번도 없었다 — pid 한 조각이면 된다.
2. **되돌림 시험은 «죽는 이유» 까지 물어야 한다.** 종료 코드만 보면 SyntaxError 로 죽은 사본도
   «성공적으로 재현» 으로 읽힌다. 죽는 **문자열**을 단언하라.
3. **자를 고치는 자는 자기 자신에게 같은 질문을 해야 한다** — `verify646` 도 처음엔 고정 이름이었다.
4. **무시 규칙이 없는 임시 사본은 즉사할 때만 문제가 된다** — 정상 종료 경로만 보면 영원히 안 보인다.
   `.v169-neg*.html` 은 3년치 이력을 부풀릴 수 있는 1.3MB 사본이었는데 규칙이 없었다.
