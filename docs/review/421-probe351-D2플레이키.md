# 421 — `probe351.js` D2 가 `.cn-cd.dia>.pn` 에서 내는 «회차마다 흔들리는» 넘침

> **완료 (2026-08-29, sess-1849-812 워커 C · 1회차)**
> **제품 `index.html` 0줄 · 레이아웃 Δ0px · 밸런스·판정 0줄.** 고친 것은 `tools/probe351lib.js` 의
> `settle()` **한 곳(순서 한 줄)** 이다.

## 1. 등재문과 무엇이 달랐나

등재문(351 10회차 곁다리 관측)은 이렇게 적혀 있었다 —
`shopcat:coin` 에서 `.cn-cd.dia>.pn` 의 `ovfX` 가 **3~4px** 로 7회 중 3회만 나온다. 가설은 둘:

- **ⓐ** `.pn` 안 숫자·아이콘이 폰트 로드·`fitNum` 류 되맞춤 **전에** 재져 넘친다
- **ⓑ** 광고 상품 상태가 실행마다 달라 문자열 길이가 바뀐다(노드 총수 46/47/48 흔들림이 이쪽을 가리킨다)

338 규칙대로 처방 전에 `tools/probe421.js` 를 신설해 재현했고 **가설 둘 다 기각**됐다.

| 물음 | 찍힌 값 | 판정 |
|---|---|---|
| 재현되는가 | 8회 실행 중 5회에서 `ovfX 2~5` | ✅ 등재문대로 흔들린다 |
| ⓐ 폰트·되맞춤인가 | `document.fonts.status` 가 세 시점(진입 직후·settle 후·+600ms) **전부 `loaded`** | ❌ 기각 |
| ⓑ 상품 상태인가 | 카드 클래스 서명이 실행마다 **한 종류**(`…dia.top│rel×3│dtk×6…`) | ❌ 기각 |
| 누가 넘치는가 | `.cn-cd.dia.top>.pn` 의 자식 **`s.ray`** — `left −2 … right 258`, **w 260** ↔ 판 `clientW 256` | ⚑ 실재 |

⚠ **첫 판만 보면 «재현 안 됨» 이 된다** — `querySelector('.cn-cd.dia>.pn')` 은 첫 다이아 카드를 집는데
넘치는 것은 **다섯째**(`.cn-cd.dia.top`, 광선을 가진 칸)다. `probe351` 의 `pathOf()` 가 클래스를 앞 둘만
적어(`cn-cd.dia`) 두 카드가 같은 이름으로 보인 것이다. 1회차 첫 실행이 `[0]` 을 재고 «값이 안 흔들린다»
로 닫힐 뻔했다.

## 2. 실재하는 뿌리 — «세운다» 는 맞았는데 «0 에» 가 아니었다

351 10회차가 `settle()` 에 넣은 것은 «무한 반복 연출을 **위상 0 으로 세운다**» 였다(그 자체는 옳았고,
카드 광택 스윕 유령을 실제로 지웠다). 그런데 적힌 순서가

```js
a.currentTime = 0; a.pause();      // ← 10회차 판
```

였고, 이 순서는 웹애니메이션 규약상 **0 에 안 선다**:

- **도는** 애니메이션에 `currentTime` 을 대입하면 hold time 이 아니라 **start time** 이 옮겨진다
  («지금을 0 으로 본다» 는 뜻일 뿐 시계는 계속 간다).
- `pause()` 는 그 자리에서 멈추는 게 아니라 **보류 작업(pending pause task)** 을 걸고, hold time 은
  그 작업이 **실제로 도는 프레임의 시각**으로 정해진다.

⇒ 세워진 자리는 «0 + 보류 작업이 늦은 만큼» 이고 그 지연은 실행마다 다르다. **실측 50 · 67 · 83ms
(3~5프레임)** 이다.

그 위에 122 재화 탭의 20초 회전 광선(`.cn-cd.dia.top>.pn>.ray` — 판 256 안의 **260px** 상자)이 얹힌다.

| 위상 | rotate | 판의 `ovfX` | D2(문턱 `clientW+2`) |
|---|---|---|---|
| 0ms | `0deg` | **2** | 조용 |
| 50ms | `0.90deg` | **4** | ⚠ 켜짐 |
| 67ms | `1.20deg` | **5** | ⚠ 켜짐 |
| 83ms | `1.50deg` | **5** | ⚠ 켜짐 |

회전한 상자는 bbox 가 `260·(cosθ+sinθ)` 로 넓어지므로 **1° 만 돌아도** 판을 3px 더 넘는다.
그리고 `probe351` 의 판정은 «2280 결함 집합 ↔ 1600 결함 집합» 의 **차분**이라, 두 판이 서로 다른
위상에 굳으면 그 순간 «1600 전용 결함» 이 태어난다 — 등재문이 본 **3/7** 이 정확히 이것이다.

**대조(같은 트리, 순서만 바꿔 5회씩)**

```
OLD(currentTime→pause)  cur = 67·50·50·50·83  rotate = 1.20°·0.90°·0.90°·0.90°·1.50°  ovfX = 5·4·4·4·5
NEW(pause→currentTime)  cur = 0·0·0·0·0       rotate = 0deg (전부)                     ovfX = 2·2·2·2·2
```

## 3. 처방 — 순서를 뒤집는다(문턱도 기대값도 안 건드린다)

```js
a.pause(); a.currentTime = 0;      // ← 규약: 보류 작업을 취소하고 hold time 을 그 값으로 확정
```

에 더해, **한 프레임 뒤 한 번 더** 세운다(그 사이 재렌더·지연 시작으로 새로 붙은 무한 연출까지).

- ⚠ **D2 의 문턱(`clientW + 2`)도 기대값도 한 칸 안 건드렸다**(334·등재문 명시). 등재문이 경고한
  «임계값을 2 → 5 로 올려 끄기» 는 실재하는 넘침의 하한을 같이 올리므로 쓰지 않았다.
- 위상이 0 으로 굳으면 광선의 잔여 넘침은 **2px** 이고 이는 문턱 이하라 **두 해상도 모두** 조용하다.
  즉 D2 가 조용해진 이유는 «자를 풀어서» 가 아니라 **«두 판이 같은 그림을 보게 돼서»** 다.
- 그 2px 은 애초에 «내용» 이 아니다 — `.ray` 는 `pointer-events:none` 장식이고 판은 **설계상**
  `overflow:hidden` 으로 그것을 자른다(122 2회차 주석: «판은 `overflow:hidden` 이라 잘라 줄 것도 이미 있다»).

## 4. 무르게 풀지 않았음 — 되돌림 시험과 음성항

`tools/verify421.js` **13/13 신설**.

- **§3 되돌림 시험** — 옛 순서로 세운 사본을 같은 트리에서 돌린다. 지금도 위상이 0 이 아니고
  (`4/4판`), `ovfX` 가 `5·2·5·2` 로 흔들리며 **D2 가 실제로 켜진다**(2/4판). ⇒ 뿌리가 그것이었음이
  못박히고, 이 항이 초록이면 «자를 무르게 푼 것» 이 아니다.
- **§4 음성항** — 같은 판에 «그릇 폭 +400px» 자식을 심으면 D2 가 **그대로 400px 를 잡는다**(4/4판).
  축이 죽지 않았다.
- **§2-d** — 넘치던 것이 장식임을 자로 적어 둔다(광선 260 > 판 256 · `overflow-x:hidden` ·
  `pointer-events:none`). 다음 세션이 «2px 을 왜 봐주나» 로 되짚지 않도록.
- `probe351.js` 의 `--selftest`(주입 되돌림 시험)는 **수리 전후가 같다** — `shopcat:summon` 에서
  둘 다 **4건**(D2 2 · D3 2). 내 변경이 그 시험을 건드리지 않았다는 대조다.

## 7. 남은 것 · 다음 세션에게

- ⚑ **«세웠다» 를 믿지 말고 «섰는지» 를 물어라.** `playState === 'paused'` 는 **0 에 섰다는 뜻이 아니다** —
  실측에서 `paused` 인데 `currentTime` 이 50~83ms 였다. 위상을 봉인하는 자는 **`currentTime` 값 자체**를
  단언해야 한다(`verify421` [1-b]).
- ⚑ **회전·스케일 장식이 `overflow:hidden` 그릇 안에 있으면 «넘침» 축은 위상의 함수다.** 그런 그릇을
  재는 새 자를 만들 때는 위상 고정을 먼저 하고, 고정이 됐는지 각도로 확인하라.
- 이 자리의 잔여 2px 은 **결함이 아니다**(설계상 잘리는 장식). 되짚지 마라.
