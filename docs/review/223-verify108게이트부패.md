## 2. 원인 — **162** 가 «보스 스테이지» 개념을 없앴다

게이트의 런타임 하네스는 이 한 줄로 보스를 불렀다:

```js
/* 보스 스테이지(10 의 배수)로 올려 «보스 단독 스폰 + 30초 제한» 흐름을 그대로 태운다 */
S.stage = 10; S.best = Math.max(S.best || 1, 10); S.bossFarm = false;
spawnStage();
```

`S.stage = 10` 은 **구 `isBossStage`(= `S.stage % 10 === 0`)** 를 노린 값이다. 그런데 그 규칙은
**162(2026-08-27 주인 지시)가 폐기**했다 — `index.html` ~14468~14499 가 직접 적어 두고 있다:

> 162 — 보스는 «10 의 배수 스테이지» 가 아니라 **모든 스테이지**에 있다.
> 스테이지 = 일반 몹 ENEMY_COUNT(50) 마리 처치 → 보스 도전 → **보스 격파가 스테이지 클리어**.
> 그래서 «이 스테이지에 보스가 있나»(구 `isBossStage`) 는 항상 참이 되어 폐기했고 …

즉 지금 `spawnStage()` 는 **언제나 잡몹 50마리를 깐다**(`queueMobs()`). 보스로 가는 길은
`startBoss()` 하나뿐이고, 그 문은 `step()` 의 «③ 몹을 다 채웠다 → 보스 도전» 분기(`killed >= ENEMY_COUNT`)
와 [재도전](`retryBoss`) 둘뿐이다. 60초(가상 3600 프레임) 안에 스테이지 10 잡몹 50마리를
기본 스탯으로 잡을 수는 없으므로 **보스는 원리적으로 한 번도 안 나온다** — 게이트는 «뜨고 지는» 것이
아니라 **결정적으로** 빨갛다(4회 연속 재현).

카메라(108 의 대상)는 한 줄도 잘못되지 않았다.

## 3. ★ 진짜 손해는 FAIL 1건이 아니라 **초록 21건 중 2건이 거짓이었다는 것**

`✗ 보스 등장 0회` 는 **증상**일 뿐이다. 보스가 안 나오면 그 뒤 «보스 등장/처치 직후 카메라» 를 보는

| | `cam.z 가 1 이 아닌 프레임` | 판정 |
|---|---|---|
| **옛 게이트** | `0` → **✓ 초록** | **거짓 초록** — 회귀를 그냥 통과시킨다 |
| **새 게이트** | `3426` → ✗ | **잡는다** (22/23 FAIL) |

옛 게이트는 «보스 등장 0회» 로 빨갛긴 했지만, **정작 108 이 막으라고 만든 회귀(처치 줌)에는
✓ 를 찍었다.** 게이트 부패가 «한 줄이 빨갛다» 가 아니라 «그 한 줄 뒤의 검사가 통째로 비었다» 인

덧붙여 파일 헤더 ④ 는 처음부터 이렇게 약속하고 있었다:

> ④ … **보스 등장/처치**를 1회 이상 지나도 그 값이 흔들리지 않는다

**처치 프레임은 한 번도 지나간 적이 없다.** 162 이전에도 스테이지 10 보스는 체력 ×22 라

## 4. 고친 것 — `tools/verify108.js` 만 (`index.html` 0줄)

기대값을 «화면이 쓴 식»(`stage % 10`)이 아니라 **«근거 데이터»(제품이 실제로 보스를 세우는 경로)**

**`step()` 의 ③ 분기가 스스로 `startBoss()` 를 부르게** 했다. 하네스가 `startBoss()` 를 직접
부르지 않은 이유는, 그러면 «50킬 → 보스 도전» 분기 자체가 검사 밖으로 빠지기 때문이다.

```js

spawnStage();
player.dead = 0; player.hp = stat.maxHp;
enemies.length = 0; spawnQ.length = 0; killed = ENEMY_COUNT;   /* 다음 step 이 startBoss() 를 부른다 */
```

**② 처치하는 길**: 보스가 전장에 선 뒤 `KILL_AFTER = 90` 프레임(1.5초)을 지나 보내고 제품의

순서대로 표본에 들어간다. 스탯을 부풀려 «진짜로 때려잡게» 하지 않은 이유는 그러면 전투 밸런스
