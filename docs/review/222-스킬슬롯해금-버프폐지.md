# 222 — 스킬 슬롯 해금 표시 · «누르지도 않았는데 해제» · 버프 스킬 폐지

> 저장소 주인 보고(2026-08-27, 원문)
> 1. «스킬 장착부분이 Lock 표시가 되있는게 문제고»
> 2. «해당 꺼 "-" 표시 누른게 아닌데 장착해제 되는거도 문제임.»
> 3. «자물쇠표시는 아직 해금안됐을떄 되있던지 해야함. 스테이지 몇 되면 해금 된다는 그런거 넣는다던지 해야함. 그거 스킬슬롯들.»
> 4. «그리고 버프류 스킬은 없었으면 함»

## 1. 무엇이 문제였나 (원인 실측)

| # | 증상 | 원인 (구 코드) |
|---|---|---|
| ① | 스킬 슬롯이 **전부 자물쇠** | `buildSlots()`·`renderSkill()` 이 «비어 있는 칸 = 자물쇠» 로 그렸다. 해금 개념 자체가 없어 **빈 칸과 미해금 칸을 구별할 수단이 없었다.** |
| ② | `-` 를 누르지 않았는데 장착 해제 | 07 스킬 시트 슬롯이 `<div class="sk-slot" data-skun="…">` — **슬롯 «전체» 가 해제 버튼**이었다. 아이콘·`Lv.n`·배경 어디를 눌러도 `toggleEquip` 이 돌았다(`[─]` 뱃지는 그 안의 장식일 뿐). 26 동료 슬롯도 같은 구조. |
| ③ | 해금 조건이 없다 | 장착 상한이 `8` 상수 하나였다. |
| ④ | 버프류 스킬 | 작업 86 이 24종을 채우며 넣은 보조 5종(`vigor`·`mend`·`haste`·`ward`·`rage` = `t:'buff'` + `sup:1`). |

## 2. 고친 내용

### ① 자물쇠는 «미해금» 칸에만 · 해금은 최고 스테이지

```js
const SK_SLOT_ST = [1, 1, 5, 10, 18, 30, 50, 80];   // 칸 i 가 열리는 최소 S.best
const skSlotMax  = () => …;                          // 지금 열린 칸 수(앞에서부터 연속)
```

- 칸 상태 3종: **장착** / **해금된 빈 칸 `[+]`**(`.sk-slot.free` · `.slot2.free`) / **미해금 자물쇠**(`.sk-slot.lock`).
- 미해금 칸에는 `St.n`(해금 스테이지)을 적고, 슬롯 줄 아래 한 줄(`.sk-slnote`)로
  «슬롯 2/8 · 다음 칸은 **스테이지 5** 도달 시 해금» 을 알린다.
- 장착 상한은 «8» 이 아니라 `skSlotMax()` 다 — 수동 장착(`toggleEquip`)·신규 획득 자동 채움(`equipFillNew`) 모두.
- 스테이지 클리어로 칸이 열리면 그 자리에서 토스트로 알린다(시트를 열어 봐야 아는 해금은 없는 것과 같다).
- **구 세이브 보호**: 해금 칸 수보다 많이 장착한 세이브에서도 **빼앗지 않는다**. 판정은 «칸 번호» 로 하므로
  그 칸은 그대로 장착 칸으로 그려지고, 상한은 «새로 넣을 때만» 본다. (①·②를 고치자고 강제 해제를 만들면
  주인이 보고한 바로 그 증상을 코드가 스스로 재현하는 꼴이 된다.)

### ② 해제는 `[─]` 뱃지에서만

- 슬롯 본체: `data-skun` → **`data-skslot`**(탭하면 **상세 보기**), `[─]` 뱃지(`.sk-eq.m`)에만 `data-skun`.
- `[─]` 는 잉크(49×20)를 1px도 안 건드리고 `::before` 로 **누르는 범위만** 바깥으로 넓혔다
  (49×20 은 실기기에서 약 18×7px — 겨눌 수 없는 크기다).
- 26 동료 슬롯(`data-ptun` → `data-ptslot`)도 같이 고쳤다. 동료 3칸은 스테이지 해금이 없으므로
  빈 칸은 자물쇠가 아니라 `[+]` 다.

### ③ 버프·회복 전용 스킬 폐지

id·등급·자리를 그대로 두고(구 세이브 보유·장착·도감·확률표 무손상) **직접 피해 스킬로 교체**했다.

| 등급 | id | 구(86) | 신(222) |
|---|---|---|---|
| 일반 | `vigor` | 기합 — `buff` 공격 +18%/5s | **기합 파동** — 범위 폭발 r150 · cd 2.0 · m 1.30 |
| 고급 | `mend` | 치유의 빛 — 체력 12% + 재생 버프 | **덩굴 가시** — 관통 투사체 3발 · cd 1.7 · m 0.95 |
| 희귀 | `haste` | 신속의 축복 — 발동속도 +30%/6s | **질풍참** — 부채꼴 검기 3발 · cd 1.4 · m 0.85 |
| 전설 | `ward` | 수호의 결계 — 피해 −35% + 회복 | **수호의 반격** — 범위 폭발 r210 · cd 3.0 · m 3.20 |
| 신화 | `rage` | 광란 — 2축 버프 8s | **광란의 살기** — 연쇄 5명 · cd 2.6 · m 1.80 |

- `sup:1`(DPS 합산 제외)·`heal` 을 쓰는 스킬은 **0종**이 됐다 → 24종 전부가 `stat.dps` 에 들어간다.
- 시전음 매핑(`SK_CAST_SFX`)도 버프음(`skchime`)에서 계열음(`skcast`/`skthrow`/`skwhoosh`/`skzap`)으로 옮겼다.
- `t:'buff'` 분기와 `sbuf*` 기계는 **남겨 뒀다**(다른 계통이 쓸 수 있게). 쓰는 스킬이 0종일 뿐이다.

## 5. 남는 것 / 다음 세션에 넘기는 것

- **밸런스 재측정 대상이 하나 늘었다.** 슬롯이 스테이지로 열리므로 초반 DPS 가 구 버전(처음부터 8칸)보다 낮다.
  `SK_SLOT_ST = [1,1,5,10,18,30,50,80]` 는 «랭크 사다리(실버 20 · 골드 45 · 플래티넘 80)» 를 참고한 첫 곡선이다 —
  README 밸런스 표 재측정(112·131 과 함께) 때 같이 잰다.
- 버프 5종을 피해 스킬로 바꾸면서 총 DPS 가 올랐다(보조 5종이 `stat.dps` 합산에 들어온다). 같은 재측정에 포함.
- 스킬 카드 격자의 `[+]`/`[─]` 뱃지는 07·26 공용이라 이번에 넓힌 «누르는 범위» 는 **슬롯의 `[─]` 에만** 걸었다.
  카드 쪽도 같은 문제를 겪으면 `.sk-card>.sk-eq` 에 같은 방식으로 넓히면 된다(잉크는 건드리지 말 것).
