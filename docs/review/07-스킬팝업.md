## 캡처 상태를 레퍼런스에 맞춘 방법 (04 비고 1의 교훈)

레퍼런스와 **같은 칸 상태**가 아니면 그 회차 비평은 통째로 무효다. 그래서 캡처 전에

- `S.autoEquip = false` — 안 끄면 `autoEquipTick()` 이 `eqSkill` 을 전투력순으로 덮어쓴다.
- 재현 스크립트: 세션 스크래치패드 `cap.js` (상태 주입 + 정식 진입점 클릭 + 캡처)

| 항목 | 수정 전 | 수정 후 | ref |

### 여기서 드러난 측정표의 오류 1건 — **카드 하단 radius**

측정표 5-3 은 radius 42 를 **좌상단 코너에서만** 재고 네 모서리가 같다고 가정했다.
레퍼런스 카드는 **위 38 · 아래 16** 인 «트레이» 모양이다.
카드 5장의 하단 코너를 행별로 스캔하니 전부 `dy0 inset 12 → dy4 inset 4 → dy10 inset 1` 로
일치했고, 이는 `inset(dy) = r − sqrt(r² − (r−dy−0.5)²)` 의 **r=16** 곡선과 dy 0/2/4/6/8/10 에서
전부 0~1px 이내로 맞는다. (42 라면 dy0 에서 inset 30 이 나와야 한다)

> **교훈**: 원호는 **한 코너만 재고 나머지를 같다고 가정하면 안 된다.** 상·하가 다른 도형이 있다.

## 1회차 — 비평가 A / B (최저 **5**)

- A: ①8 ②7 ③8 ④9 ⑤6 ⑥8 → **6**
- B: ①9 ②8 ③8 ④9 ⑤5 ⑥7 → **5**

### 채택 (자가 스캔으로 전부 재확인 후)

1. **버튼·서브탭 라벨에 검정 외곽선이 아예 없었다** — 이번 회차 최대 결함.
   측정표 §8·§9 가 글자 «색» 만 적고 스트로크를 언급하지 않아 통째로 빠져 있었다.
   라벨 박스 안 near-black(합<150) 픽셀 수:

   | 라벨 | ref | 수정 전 | 수정 후 |
   |---|---|---|---|
   | 스킬 소환 | 2475 | **0** | 2085 |
   | 일괄 강화 | 2441 | **0** | 2273 |
   | 탭 스킬(활성) | 1383 | **0** | 1440 |
   | 탭 장비 | 1329 | **0** | 1351 |

   특히 «일괄 강화» 는 회색 면(146) 위 회색 글자(210) 라 외곽선이 없으면 대비가 거의 사라진다.
2. **카드 상단 radius 42 → 38.** 카드 5장 좌상단 원호를 피팅하니 37.2 / 38.0 / 38.1 / 38.4 / 38.7
   (평균 38.1). 우리는 42.1 (RMSE 0.31) 이라 «정확히 42» 였다 — **측정표 5-3 의 42 가 과대추정**이다.
3. **맨 오른쪽 탭 구분선은 «함몰선»** 이지 활성 알약의 검정 7px 테두리가 아니다.
   실측 x775~779 (5px) · **y2044~2097 (h54)** · 색 **#483B2B** (바 배경 #61503C 대비 Δ26).
   우리는 `#000` 을 바 높이 전체(h85)에 그려 Δ97 · 높이 +57% 였다. 수정 후 구간·색 모두 일치.
4. **잠금 서브탭은 «라벨 + 그 위에 겹친 자물쇠»** 다. 레퍼런스 동료·기타 둘 다 회색 라벨 픽셀이
   자물쇠 좌우로 남아 있다(기타 x824~968, 자물쇠 872~920). 우리 «기타» 는 자물쇠만 있고
   라벨이 없었다 → 라벨 복원.
5. 버튼 상단 하이라이트 10px → **8px** (측정표 §8 y1850~1857).

### 외곽선 두께 — ref 검정 픽셀 «질량» 에 맞춰 요소별로 튜닝

## 2회차 — 비평가 C / D (최저 **4**)

- C: ①9 ②7 ③8 ④9 ⑤4 ⑥7 → **4**  (D 는 캘리브레이션에서 시트 radius 38.1·장착중 bbox·라벨 외곽선을 독립 복원 — 신뢰 가능)
- D: ①8 ②6 ③7 ④9 ⑤6 ⑥9 → **6**

> 두 비평가 모두 «면 색은 정확한데 **입체 구조(베벨)** 가 통째로 빠졌다» 로 수렴했다.
> 1회차가 «외곽선» 을 살렸다면 2회차는 «베벨» 을 살리는 회차였다.

### 채택 (전부 자가 단면 스캔으로 재확인)

1. **자물쇠 = 검정 외곽선 + 흰 면 + 검정 열쇠구멍.** 우리는 흰 실루엣만 그렸다(near-black 1618 vs ref 3104).
   열쇠구멍은 «원+슬롯» 이 아니라 **표주박**(검정 런 폭 3/13/8/13). 원 2개를 세로로 겹쳐 복원.
   외곽선은 두 의사요소의 합집합을 감싸야 해서 부모 `filter` 에 drop-shadow 4방향(4px). → 슬롯 3489/기타탭 1414 로 ref(3507/1404) 와 1% 이내.
2. **버튼 좌우 안쪽 라이트 림 신설** (`inset ±7px var(--hl)`). ref y1900: 검정 249~255 → 라이트 256~262.
3. **버튼 하단 라이트 밴드 13px → 6px** + 언더립 #3EBC2A 복원. 면 스톱을 옮겨 라이트 1951~1957 로.
4. **서브탭 바 하단이 «어두운 띠» 가 아니라 «밝은 베벨»** (#706049, y2101~2109). 측정표 §9 의
   «하단 하이라이트 #5E4E37 y2098~2104» 는 **색·위치 둘 다 오독**이었다.
5. **활성 알약이 완전 평면** → 위·아래 밝은 베벨 + 바닥 어두운 인셋(그라디언트 4단 + inset ±14px).
6. **장착 슬롯 패널 6px 좁음** → x21·w1037·테두리 8. 비평가 4인(A 1038·B 1036·C 1038·D 1039)이
   독립 지적했고 자가 raw 덤프도 일치. 측정표 4-1 의 «x24·w1032·테두리 7» 은 JPEG 램프를 테두리
   시작으로 오독한 값. 슬롯 좌단 +3 보정으로 절대좌표 45/170/... 유지(확인 완료).
7. 카드 `Lv.n` 좌단 카드+22 → **+20**.
8. (후속) 진행바 트랙 세로 그라디언트 + 채움 상단 밴드 5px → 9px (D#5·D#6).
