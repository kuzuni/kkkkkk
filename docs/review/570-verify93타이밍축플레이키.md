## 1. 재현이 먼저 (338 규칙) — 등재문의 «역행» 은 역행이 아니었다

```

R1-b  (없음)                                                            → 21/21

```

⚑ **실패문을 그대로 읽으면 «역행 0» 인데 빨갛다.** 한 줄에 둘이 들어 있었기 때문이다:


`moved > 40` 은 **표본 수**(= 러너 속도)이고 `backs === 0` 이 본체다. 프레임이 성기면

«비트 다음 틱» **한 장**이고 그 틱의 **dt** 가 고원보다 짧아야 하는데, 시각차(t−beat)는 dt 보다

## 6. 다음 세션이 볼 것

* ⚑ **«표본 n개 이상» 을 `ok()` 본체와 한 줄에 넣지 마라.** 그 줄은 러너가 느려지는 순간
  **본체 이름을 달고** 빨개진다 — 실패문만 보면 영원히 엉뚱한 것을 고치게 된다(이 작업의 등재문이 그랬다).

  값은 흔들리는 게 아니라 **계단으로 떨어진다**. 제품이 남긴 상태(`fxPz` 의 `a`·`h`)를 읽어라 —
  93 12·13회차가 `fxBeatLog` 를 만든 이유가 정확히 이것인데, 정작 피크 축이 그걸 안 쓰고 있었다.
* ⚑ **자가 부하의 일부다.** 프레임마다 `getBoundingClientRect`/`getComputedStyle` 을 부르면
  제품 프레임이 같이 늘어난다. 인라인 `style.transform` 은 같은 값을 레이아웃 0회로 준다(Δ 0.00px).
