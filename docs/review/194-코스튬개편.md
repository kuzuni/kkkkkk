### ③ 강화 — 곡선과 결합 방식

```
레벨      S.cosLv[id] : 0 ~ COS_MAXLV(500)     — 코스튬마다 따로
비용      cosCost(l)  = ceil(2 × 1.012^l)      — 전 코스튬 동일 곡선
보유 효과  COS_OWN     — 코스튬마다 «곱»
강화 효과  COS_LV      — 보유분 레벨을 **전부 더한 뒤 한 번만 곱**
```

**결합 방식이 다른 것이 이 작업의 핵심 판단이다**(LESSONS 91-1 «세트마다 곱하기 vs 축별로 더한 뒤 한 번 곱하기»).
코스튬마다 곱했다면 만렙 상한이 `(1+2.0)^50 ≈ 7.2e23` 으로 밸런스가 통째로 터진다.
더한 뒤 한 번 곱하면 `1 + 50×500×0.004 = ×101` 로 선다. `tools/verify194.js` [4] 가
«100Lv + 100Lv» 와 «200Lv» 가 **같은 값**인지로 이 성질을 직접 잰다(다르면 코스튬마다 곱한 것이다).

| 지표 | 값 |
|---|---|
| 1레벨 비용 | 2 · 100레벨 7 · 250레벨 40 · 499레벨 770 |
| 한 코스튬 만렙 누적 | **64,958 강화석** |
| 50종 전부 만렙 | ≈ 3.25M 강화석 |
| 보유 축 상한(50종) | 공격 ×117.4 · 체력 ×46.9 · 골드 ×11.5 (등급 있던 옛 값 ×159.8/×52.0/×17.1 과 같은 자릿수) |
| 강화 축 상한(25,000Lv) | 공격 ×101 · 체력 ×76 · 골드 ×51 |

### ⑤ 182 매핑 충돌 해소 — «순번 기반»

182 의 `PROMO_COS` 는 **등급으로** 묶음을 잘랐다(`cosOfGrade(g)`). 등급이 폐기됐으므로
등재문대로 **순번 컷**으로 재설계했다: `PROMO_CUT = [21, 10, 8, 6, 2, 1, 1]` 을 `COS_LIST` 순서
(av0 제외)에 그대로 적용한다. `COS_LIST` 가 옛 등급 순서 그대로라 **지급표는 한 칸도 바뀌지 않는다** —
구 계급 조건 앵커 2점(**av41 → rank 3** · **av48 → rank 6**)도 그대로 지난다(verify194 [6]·verify182 §1 검산).
마지막 칸은 «남는 것 전부» 라 코스튬이 늘어도 이 표를 안 고친다(LESSONS 91-4).

### 되돌림 시험(verify194 [7] — LESSONS 43-①)

내가 쓴 단언이 정말 무언가를 지키는지 확인한 것:

- ⓐ 강화 효과를 «코스튬마다 곱» 으로 되돌리면 «100+100 = 200» 이 깨진다 → 그래서 그 단언이 의미가 있다.
  (실제로 두 식의 값이 `(1+0.4)^2 = 1.96` vs `1.8` 로 다름을 같이 계산해 확인)
- ⓑ 강화석 0 에서 레벨이 오르지 않는다.
- ⓒ 등급 필드가 되살아나지 않았다.

### 121 — 카드가 7장이 되며 드러난 두 가지

`--thb` 5.22s(조항 3~5) · 짧은 들썩 1.044s(조항 0.7~1.0)가 동시에 조항 밖으로 나갔다.
그 주석이 이미 적어 둔 원칙을 **나머지 두 곳에도 그대로** 적용했다(`Math.min` 상한 2개).
그리고 `bgm-stone` 테마가 없어 `.bgm` 레이어의 이동거리 실측이 `NaN` 이었다 →
