## §2 처방 — 장부 하나(`catSum`/`catApply`)

주인 확정 모델:

```
총배율 = (1+Σ장비)×(1+Σ스킬)×(1+Σ코스튬)×(1+Σ펫)×(1+Σ훈련)×(1+Σ룬)×(1+Σ단련)×(1+Σ유물)
⇒ 카테고리 «안» 은 합 · 카테고리 «간» 은 곱
```

`bonus()` 를 **카테고리마다 장부 하나**로 다시 짰다 — `catSum()` 으로 열고 축별로 더한 뒤
`catApply(b, c)` 가 축마다 **한 번만** 곱한다. 장부는 11개다(주인의 8 + 도감·계급·축복 —
셋은 목록 밖이지만 성격이 같은 별도 카테고리라 같은 규칙으로 뒀다. 도감·룬·단련은 이미
그 규칙이었고 «장부를 지나게» 만 했다).

⚠ **«카테고리» 는 화면 이름이 아니라 «곱이 한 번 걸리는 단위» 다.** 그래서
**장비 = 보유 + 장착**, **펫 = 보유 + 485 장착**, **코스튬 = 보유 + 강화**가 각각 한 장부다
(194·197 은 코스튬 보유와 강화를 따로 곱했는데, 주인 모델에서 코스튬은 카테고리 하나다).

⚠ `crit`·`cdmg` 는 배율이 아니라 **덧셈 축**이라 이 모델 밖이다 — 그대로 `b` 에 더한다.

**제품 편집 5자리**(`index.html`)
1. `cosOwnMul()`(계단 **곱**) → `cosOwnSum()`(계단 **합** · 단위도 «배수» → «배수 −1» 로,
   강화 축 `cosLvVal` 과 같은 단위라 그냥 더할 수 있다). 옛 이름은 **선언째 삭제**(333·399).
2. `bonus()` 전면 — 11 장부.
3. 07 스킬 시트 «총 보유 효과» `Π−1` → `Σ`.
4. 26 펫 시트 «총 보유 효과» `Π−1` → `Σ`.
5. 50 코스튬 시트 «총효과» `cosOwnMul × (1+강화) − 1` → `cosOwnSum + cosLvVal`.

**세이브 이관 «없음» 이 정답이다** — 바뀐 것은 **읽는 식**뿐이고 저장되는 값(`S.own`·
`S.avatars`·`S.cosLv`·`S.rune`·`S.temper`)은 한 칸도 안 건드렸다. KEY 도 안 올렸다.

## §6 ⚑ 199 통지 (필수 · 큰 통지)

1. **모델이 확정됐다** — 199 는 이제 «카테고리 안은 합 · 간은 곱» 위에서 계수를 잡는다.
   손잡이의 성질이 바뀌었다: 한 카테고리 안에서 항을 늘리는 것은 **선형**이고, 지수는
   카테고리 수(11)로만 걸린다.
2. **cp 가 통째로 내려갔다** — 전 카테고리 만렙 표본에서 **1.7114e+45 → 5.5960e+9**
   (÷3.06e+35). 스킬 축만 봐도 Lv100 전 보유에서 ×1.79e+8 이 사라졌다.
   ⇒ **적 곡선·수급·비용 역산의 입력이 전부 바뀐다.** `bot199`·`sim112`·`sim177`·`sim249` 는
   지금 전부 초록이지만 그것은 **훈련만 축**(sim112 주석)이나 구조 항을 보기 때문이고,
   «장비·스킬·펫·코스튬을 갖춘 플레이어» 의 곡선은 199 가 다시 재야 한다.
3. **472·484·485 의 «등급 ×3 · 티어 ×1.5» 는 그대로다** — 바뀐 것은 그 값들이 **어떻게
   합쳐지는가** 뿐이다. 199 가 계수를 만질 때 이 둘을 헷갈리지 마라.
4. 703(공속 목걸이 전속)·704(방패 골드)·719(합성)·725(«×N배» 표기)가 이 모델 **위에** 얹힌다.
