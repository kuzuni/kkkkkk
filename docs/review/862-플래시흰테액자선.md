## 1. 등재문이 남긴 것과, 재현이 뒤집은 것

683 9회차(`probe683c`)가 남긴 것은 **사실 둘과 막다른 손잡이 하나**였다.

| | 등재문(683 9회차) | `probe862` 재현 |
|---|---|---|
| ⓐ 액자선 잔존(t0) | 3.1% (56/1812) | **3.1%** — 자릿수까지 같다 |
| ⓑ `inset` 을 켜면 | 38.3% 로 살지만 라벨이 15.26 → 3.77:1 | **38.3% · 3.77:1** — 그대로 |
| ⓒ 처방 ①(«흰 테를 링에서 파생» = `min(9, ring)`) | 유력 후보 | **기각** — 액자선 38.3% 에 멈추고 라벨은 여전히 3.77:1 |

**등재문의 1순위 처방이 재현에서 죽었다.** 흰 테를 2px 로 눌러도 그림이 안 바뀐 이유는
그 처방이 전제한 «링 2px» 자체가 **틀린 값**이었기 때문이다.

### 뿌리는 «액자가 두 겹» 이다

`.rw-c`(유물 카드)는 액자를 **두 겹**으로 그린다:

```css
.rw-c{ border:4px solid #A67B50;
       box-shadow:inset 0 0 0 2px #8A6732, 0 0 0 1px #35210F; }
```

즉 액자선은 카드 rect 안쪽 **0~6px** 띠(테두리 4 + 안쪽 링 2)다. 그런데 `fxRingIn()` 은
**inset 그림자의 spread 하나만** 읽어 **2** 를 답했다. 619 18회차가 이 함수를 만들 때 본
호스트 셋(훈련 카드·룬 행·단련 행)은 `border` 가 **0/0/0/0** 이라 그 답이 곧 띠 전부였고
(측정표 619 ⓐ), 그 우연이 «액자 = inset spread» 라는 문장을 굳혔다.

⇒ 안쪽 링(2)만큼 들이면 흰 테는 [2, 11] 에 앉는다. **액자선의 바깥 4px 을 여전히 먹고**
(잔존 38.3%), 동시에 카드 «안» 으로 9px 을 파고들어 라벨을 잃는다(4.5:1 미만 **64~66%**).
683 이 이 손잡이를 기각한 것은 옳았다 — 다만 기각한 이유가 «흰 테가 두껍다» 가 아니라
**«들이는 양이 애초에 모자랐다»** 였다.

## 2. 실측표 (`probe862` · 1080×2280 · t0 봉우리 · 알 숨김)

| 판 | 들이기 | 흰 테 | 액자선 잔존 | 라벨 중앙값 | **4.5:1 미만** |
|---|---|---|---|---|---|
| ⓐ 수리 전 | 0 | 9 | **3.1%** | 15.26:1 | 7% |
| ⓑ 안쪽 링만(683 기각) | 2 | 9 | 38.3% | 3.77:1 | **64%** |
| ⓒ 등재문 처방 ① | 2 | 2 | 38.3% | 3.77:1 | **66%** |
| **ⓔ 띠 전부 + 흰 테 상한 — 채택** | **6** | **6** | **100%** | 5.16:1 | **6%** |
| ⓕ 띠 전부 · 상한 없음 | 6 | 9 | 100% | 5.16:1 | 11% |
| ⓓ 대조(흰 테만 파생) | 0 | 2 | 3.1% | 13.32:1 | 9% |
| — 정착(연출 0) | — | — | — | 17.71:1 | 14% |

⚑ **라벨 축의 자는 «중앙값» 이 아니라 «읽을 수 있는가»(4.5:1 미만 비율)다.** 플래시가 하는 일이
곧 워시라 어느 판이든 중앙값은 내려간다. 683 이 ⓑ 를 기각한 축도, 채택안이 이기는 축도 같은
자리다 — ⓔ 는 **6%** 로 수리 전(7%)보다도, 연출이 없는 정착(14%)보다도 낫다.

⚠ **재현 harness 의 전제 하나** — 카드는 소환마다 «팝» 으로 크기가 오간다(실측 139.8 ↔ 151).
단발 호출은 추적(rAF)을 안 켜므로 상자가 **발화 시각의 rect 로 굳는다** ⇒ 판마다 다른 상자가
나와 «들이기 2px» 보다 큰 9.3px 잡음이 섞인다. `probe862`·`verify862` 는 팝을 끝낸 **뒤**
같은 자리에 다시 띄워 여섯 판이 같은 상자에서 출발하게 한다.

## 3. 처방 — 세 자리 (전부 파생 · 새 손 상수 0개)

1. **`fxRingIn()` 이 «테두리 + 안쪽 링» 을 답한다.** `border` 겹을 같이 센다.
   619 의 호스트 셋은 `border` 가 0 이라 **한 값도 안 바뀐다**(0 + 8 = 8).
   안쪽 링 없이 테두리만으로 액자를 그리는 호스트도 이제 제 값을 답한다.
2. **들이기는 `inset` 인자가 아니라 «액자가 있는가» 가 정한다** (`const ring = fxRingIn(el)`).
   «흰 판이 액자선을 먹는다» 는 기하이지 619 회당 발화의 성질이 아니다 — 유물 카드는 **단발**
   호출(`rwGainFx`)이라 18회차의 문이 안 열렸고, 그것이 잔존 3.1% 의 직접 원인이다.
   액자가 없는 호스트(`fxRingIn` = 0)는 **한 픽셀도 안 바뀐다**(09·12·17·코스튬·장비).
3. **흰 테는 액자 띠를 안 넘는다** — `min(CSS border-width, 띠)`. 기준값은 `.fx-flash` 자신의
   CSS 에서 **읽어서** 누른다(795 «그림은 자신에게서 읽는다»). 이 상한이 «읽을 수 있는가» 축에서
   **5%p**(11% → 6%)를 번다.

⚠ **`inset` 인자는 여전히 산다** — 추적(rAF)과 배지 keep-out 은 그대로 그 문 뒤다
(`verify619` [K6] 가 그것을 묶는다 · 65/65 무수정 통과).

## 6. 왜 비평 루프를 안 돌았는가

이 행은 등재 당시 «T4 폴리시 · 지시서 [3]-(다) 연출» 로 적혀 있었지만, 실제로 닫아야 하는 것은
**«두 부품의 두께 관계»** 하나였고 통과·기각 판정이 전부 화소 수치로 갈렸다(액자선 잔존 % ·
4.5:1 미만 %). 지시서 [3]-(가)의 «레퍼런스 대조가 필요 없는 작업에 비평 루프를 돌리면 회차
예산만 태운다» 에 해당한다고 보고 **자 두 벌로 닫았다**(위임 규약 2026-09-01 — 판단을 상신하지
않고 그 회차에서 채택하고 기록으로 남긴다). 그림으로 다시 확인하고 싶으면 683 의 남은 1회차가
같은 화면을 2인 채점으로 다시 본다 — 그때 이 판정이 뒤집히면 되돌림은 §3 의 세 자리를 각각
지우면 된다(각 자리에 되돌리는 법을 주석으로 적어 두었다).
