## 1. 무엇이 깨져 있었나 (재현)

이 러너에는 미리 깔린 브라우저가 `/opt/pw-browsers/chromium-1194` 뿐인데,
`npm i --no-save playwright` 로 들어오는 드라이버는 **다른 빌드**를 기대한다:

```
$ node -e "const{chromium}=require('playwright');console.log(chromium.executablePath())"
/opt/pw-browsers/chromium-1234/chrome-linux64/chrome     ← 없는 경로
```

그래서 `chromium.launch()` 를 직접 부르는 게이트는 첫 줄에서 죽는다:

```
Executable doesn't exist at /opt/pw-browsers/chromium_headless_shell-1234/...
```

**이관 전 12종 전수 실행 결과 — 11종 즉사, 1종만 실행:**

## 2. 무엇을 고쳤나

### ① 런처 2줄 치환 (11종)

```js
- const { chromium } = require('playwright');
+ const { pw, launch } = require('./pwlaunch');
+ const { chromium } = pw();
...
- const b = await chromium.launch();
+ const b = await launch(chromium);
```

`verify84` 는 브라우저를 3번 띄운다(`b`·`b2`·`b3`) — 3곳 모두 교체.

### ② `verify87` — 자체 «모듈만» 해석 블록 폐기

87 은 `require('playwright')` 실패 시 npx 캐시를 뒤지는 블록을 복붙해 갖고 있었는데,
**«모듈» 만 찾고 «브라우저 바이너리» 는 안 찾아서** 결국 같은 이유로 죽었다. 통째로 `pwlaunch` 로 교체.
캔버스 픽셀을 읽는 게이트라 `--allow-file-access-from-files` 는 그대로 유지(`launch(chromium, {args:[…]})`).

### ③ `aud98.js`(= `verify98` 의 런처) — 자체 폴백 폐기

후보가 `PW_CHROMIUM` 과 `/opt/pw-browsers/chromium` **둘뿐**이라,
그 심링크가 없고 `chromium-<빌드>/` 디렉터리만 있는 러너에서는 못 찾는다.
호출부(`verify98`·`measure`)가 쓰는 `launch(args)` 시그니처는 그대로 두고 속만 `pwLaunch(chromium,{args})` 로 위임.

### ④ `verify87` §7 — «FAIL 도 못 내고 TypeError 로 즉사» 하던 구간

이관해서 실제로 돌려 보니 §7 에서 이렇게 죽었다:

```
page.evaluate: TypeError: Cannot read properties of null (reading 'getBoundingClientRect')
```

§7 은 §6 의 `page.reload()` **직후**다. 리로드 후 탭 핸들러가 붙기 전에 고정 300/500ms 로 클릭이 떨어지면
패널이 **아예 안 열리고** → `#bCos` 가 빈 채로 남아 → `#bCos .sk-gp` 가 null 이 된다.
재현(프로브): 리로드 후 900ms 대기면 실패, 1200ms 면 성공 — **경합**이다.

시간이 아니라 **«격자가 떴는가»** 를 기준으로 최대 ~10초 재시도하도록 바꿨다.
탭 재클릭은 패널을 닫으므로(A1 계약) **패널이 닫혀 있을 때만** 누른다.

```js
for (let i = 0; i < 20 && !(await page.$('#bCos .sk-gp')); i++) {
  await page.evaluate(() => {
    const pn = document.querySelector('#panel');
    if (!pn || getComputedStyle(pn).display === 'none') document.querySelector('.tab[data-t="hero"]')?.click();
    document.querySelector('#eqTabs [data-eqtab="cos"]')?.click();
  });
  await page.waitForTimeout(500);
}
```

## 5. 곁가지 — 게이트가 «런처 말고» 또 안 도는 이유 2가지

`Executable doesn't exist` 를 걷어내자 그다음 벽이 나왔다. 둘 다 **저장소가 아니라 러너에 없는 것**이다.

| 게이트 | 없으면 나는 에러 | 준비 |
|---|---|---|
| `verify81` | `Error: Cannot find module 'pngjs'` | `npm i --no-save pngjs` |
| `verify84` | `ModuleNotFoundError: No module named 'PIL'` (→ `tools/scan12.py`) | `pip install pillow` |

`npm i --no-save playwright` 만 한 세션은 이 둘에서 또 «게이트가 죽었다» 를 보게 된다.
**한 줄로 끝내려면:** `npm i --no-save playwright pngjs && pip install -q pillow`
(⚠ `npm i --no-save` 를 **따로 두 번** 부르면 뒤 호출이 앞 패키지를 지운다 — 이번에 실제로 playwright 가 날아갔다. 한 번에 나열할 것.)
