## 1회차 (완료)

### 무엇을 바꿨나

1. **`EQ_NAMES` 구조 변경** — «부위 → 이름 6개» → **«부위 → 등급 → 항목 배열»**.
   종수 배분: 일반·고급 **4** / 희귀·영웅 **3** / 전설·신화 **2** → 부위당 18종, **총 54종**(기존 18의 정확히 3배).
   - id: j=0 은 기존 `slot+g`(`weapon0`~`weapon5` 등) **그대로 보존**, j≥1 은 `slot+g+'_'+j`.
     → 구 세이브 `S.own`·`S.eqSlot` 마이그레이션 불필요, **KEY 유지**(LESSONS 44-2).
   - 항목별 `v`(개체차 배율 0.9~1.15)와 `ic`(임시 이모지 아트). **j=0 은 v=1.00 고정**이라 구 세이브의 수치가 1도 안 변한다.
2. **`eqv()` 신설 + `ownVal`/`equipVal`/`power`(equip 분기)에 v 반영** — 같은 등급·레벨이라도 종류별 효과가 다르다.
   `eqv = it => (it.slot && it.v) ? it.v : 1` — **slot 이 있는 것(장비)만** 곱한다. 유물도 `v` 필드를 갖지만
   (relicVal 전용) slot 이 없어 안 걸린다. 스킬·펫·유물 값 불변을 verify75 ③이 확인.
3. **`nextGradeItem` — 같은 계열(j) 유지** — 다음 등급에 같은 j 가 없으면 `j % pool.length` 로 감아 **결정적**으로.
   (랜덤으로 하면 `canCraft` 판정과 `craft` 지급이 서로 다른 아이템을 볼 수 있다.)
4. **`COLL.equip` need 3배 스케일** — 4/8/11/14/16/18 → **12/24/33/42/48/54** (마지막 단계 = 전 종 수집 유지).
   `S.coll.equip` 은 «받은 단계 수» 카운터라 구 세이브가 이미 받은 보너스는 그대로 유효하다.
5. **05 부위별 아이템 팝업 그리드** — 행=등급 유지, 칸을 «1번만 실물» → **그 등급의 실제 아이템 2~4개**로.
   남는 칸은 종전과 같은 잠금 더미. (11 확률 팝업·도감 그리드·21 세트 도감·06 시트는 전부 list 를 일반 순회라 **무수정 자동 편입** — 21 세트는 구 id 만 참조하므로 안전.)
6. **README** — 도감 표 «각 6종 (18종)» → «각 18종 (54종) — 등급당 2~4종, 개체차 0.9~1.15», 합성 «같은 계열 우선».
