## 1. 고친 것 — 한 줄이다

```js
/* before (131) — 구간별 지수 */
const TRAIN_VAL_KNEE = 33;
const TRAIN_VAL_R = { atk:1.0599, hp:1.0348, regen:1.0348 };
const trainVal = (id, b, r) => l =>
  b * Math.pow(r, Math.min(l, TRAIN_VAL_KNEE)) * Math.pow(TRAIN_VAL_R[id], Math.max(0, l - TRAIN_VAL_KNEE));

/* after (168) — 선형 */
const TRAIN_VAL_K = { atk:20, hp:100, regen:15 };   /* 레벨당 증가분 — 주인 확정 */
const trainVal = (id, b) => l => b + TRAIN_VAL_K[id] * l;
```

호출부 3곳도 인자 하나가 빠졌다: `trainVal('atk',18)` · `trainVal('hp',160)` · `trainVal('regen',4)`.

- **기울기는 «역산» 이 아니라 «받아쓰기» 다.** 112·131 은 자유도(배율·무릎)를 등식으로 풀었지만
  168 의 k 는 주인이 숫자로 확정해 줬다. 여기서 도구가 할 일은 «값 고르기» 가 아니라 **«결과 재기»** 다.
- **기저 b 는 현행 Lv0 값 유지**(18·160·4) → **Lv 0 은 세 스탯 다 완전히 동일**(게이트 ①).
- **무릎 구조는 흔적도 안 남겼다** — `TRAIN_VAL_KNEE`·`TRAIN_VAL_R` 은 index.html 에서 **0회 출현**
  (게이트가 주석 안 언급까지 0 으로 센다. 그래서 새 주석에서도 그 식별자를 안 쓰고 «무릎 Lv 33» 이라고 적었다).

**안 건드린 축**: `TRAIN_BONUS`(단계당 +10%) · 112 비용 곡선(`trainCost`/`TRAIN_KNEE`/`TRAIN_COST_R`) ·
상한 `trainCap`/`TRAIN_CAP_STEP` · 세이브 구조(마이그레이션 없음 — 저장하는 것은 `S.lv.*` 레벨값뿐이고
곡선은 표시·계산 시점에 적용된다) · UPG 나머지 7종 · **적 스케일(`eHp`/`eDmg`)**.

## 4. ⚠ 본체 — 적 스케일과의 정합 (177 의 입력)

등재문이 «⚠ 적 스케일과의 정합이 본체» 라고 못 박은 대목이다. 결론부터:

> **선형 스탯이 지수 적 곡선을 이기는 방법은 없다. 벽은 버그가 아니라 이 지시의 필연적 귀결이고, 설계다.**

적 HP ×1.25/스테이지 · 적 공격 ×1.14/스테이지인 한, `b + k×l` 은 어떤 k 를 줘도 유한 스테이지에서 뒤처진다.
그러므로 판정할 것은 «벽이 있느냐» 가 아니라 **«벽이 어디 서는가»** 이며, sim168 [D] 가 그것을 매 실행 실측한다:

| 기준 | before(131) | **after(168)** |
|---|---|---|
| 몹 1마리 처치 > 1초 | s1 | **s17** |
| 몹 1마리 처치 > 5초 | 없음 | **s27** |
| 보스 소요 > 제한 30초 | s1 | **s19** |
| 체력/적공격 < 1 (한 방 사망) | 없음 | **s67** |

→ **훈련 축 단독 사거리 = 스테이지 18.** 그 위는 **장비·유물·소환·펫(지수 축)** 이 메워야 한다 —
이것이 주인이 지시한 구조다(훈련은 «바닥», 지수 성장은 «획득물»).

**적 곡선을 완화할지는 작업 177 의 몫이고 168 은 손대지 않았다**(등재문 «곁가지 금지, 효과값 곡선만»).
177 이 쓸 입력 한 줄: 레벨당 +20 은 s40 부근 접선 기준 **스테이지당 ×1.0238** 에 해당한다 —
적 HP 배율 1.25 를 이 근방까지 내리면 훈련 축만으로도 비가 평탄해지지만, 그것은 **적 곡선 재설계**이므로
던전 요구 전투력·계급·도감이 전부 따라 움직인다(131 이 «내 구간 밖» 이라고 기각했던 바로 그 선택지다).

**±10% 류 «변화량» 게이트는 이 건에 부적용**이다(등재문 명시 — 곡선 교체 자체가 목적).

## 6. 이번에 잡은 것 — 게이트를 내 손으로 틀리게 쓸 뻔했다

**처음 쓴 sim168 게이트 ⑦ 은 «첫 보스가 before 보다 어려워지면 FAIL» 이었고, 실제로 FAIL 이 났다**
(s10 몹 처치 0.389 → 0.434초, +11.7%). 여기서 곡선을 만지고 싶어지는데, **틀린 것은 곡선이 아니라 게이트다** —
기울기는 주인 확정값이라 협상 대상이 아니고, 「before 보다 착해야 한다」는 **내가 발명한 수용 기준**이었다.
131 은 «어느 스테이지도 오늘보다 어려워지지 않는다» 를 만족할 수 있었지만(무릎으로 초반을 통째로 보존),
선형은 구조상 **어딘가에서 반드시 구곡선과 교차**한다. 교차를 금지하면 «선형으로 하라» 와 모순이다.

→ ⑦ 을 **«게임이 초반에 실제로 되는가»** 로 바꿨다: 훈련만으로 첫 보스가 제한시간 안에 나고
몹 처치가 1초를 안 넘으면 통과(9.22초 < 30초 · 0.434초 ≤ 1초). 그리고 교차점(Lv 32)과 s10 의 +11.7% 는
**감추지 않고 게이트 출력에 «결과» 로 찍는다** — 주인이 그 값을 보고 기울기를 다시 정할 수 있게.
