## §2 처방 — 사본을 안 심는다(955 교훈), **감사자를 한 자리에 놓는다**

등재문 ⓒ 는 «자에 [D0] 를 심는다» 였다. 그대로 하면 31벌 사본이고, 402 가 지운 병을 다시 만든다.
게다가 [D0] 원형은 **잉크 마스크**(그 줄만 `visibility:hidden` 으로 지운 차분)를 필요로 해서
호스트마다 지우는 법이 다르다 — 일반화가 안 된다.

⇒ **[D0] 의 일반형을 찾았다.** [D0] 가 묻는 것은 결국 «그 창이 찍힌 판을 가리키는가» 이고,
그것은 잉크 없이도 물을 수 있다 — **건네준 rect 를 찍는 순간 다시 재서 값이 갈리는지** 보면 된다.
갈리면 그 창은 찍힌 판이 아니다. 잉크 마스크보다 싸고, 호스트를 안 가리고, **한 자리**에 놓인다.

|---|---|---|
| ⓐ 자 31벌에 [D0] 사본 | 기각 | 402·955 가 지운 병(사본). 게다가 잉크 마스크는 호스트마다 다르다 |
| ⓑ `page.screenshot` 직전에 **건네준 rect 를 다시 재는** 공용 감사자 | **채택** | 한 자리(`pwlaunch` 사슬 1줄) · 잉크 없이 같은 것을 묻는다 |

### ⚑ 이 작업의 실제 설계는 «무엇을 안 세는가» 였다

첫 사본은 자마다 «낡은 읽기» 를 **수백 건** 냈고 **그중 자가 창으로 쓴 것은 하나도 없었다.**
두 번을 걷어내고서야 축이 섰다:

| 걷어낸 것 | 왜 | 실측(`probe814d`) |
|---|---|---|
| **제품이 부른 rect** | `drawHud`→`cpRoom` · `fitNum`→`fitRoom` 이 **매 프레임** 부른다 | 134 → 4건 |
| **부팅 중에 읽은 rect** | 로딩 막이 걷히고 HUD 숫자가 오르는 사이 것은 «창» 이 아니라 **준비**다 | 나이 창(1,500ms)으로 가른다 |
| **사라진 노드** | Range 는 DOM 이 바뀌면 스스로 접히며 컨테이너를 산 조상으로 올려 잡는다 — `isConnected` 가 못 거르고 0×0 으로 나온다 | 4 → **2건**(= 실물 둘) |

제품과 자를 가르는 것은 **호출 스택**이다(실측):

```
제품  … at cpRoom (file:///…/index.html:29979)          ← `index.html` 이 있다
자    … at eval (eval at evaluate) / UtilityScript.evaluate  ← 없다
```

⚠ 스택을 뜨는 값이 싸지 않아 `Error.stackTraceLimit` 을 4 로 줄인다 — **감사자를 켰을 때만**이다.
