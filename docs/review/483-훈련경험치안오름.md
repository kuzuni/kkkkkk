**배율 ×5.836e56.** 326 자신의 review 가 이미 «4단계 Lv 1000 = 2.5e25 골드로 sim112 지평 밖»
이라고 적어 둔 곡선이다. 즉 기본안은 진행바를 0 에서 풀어 주는 대신 **한 레벨도 못 사게** 만들어,
주인이 본 그림(«사도 안 오른다»)이 «살 수가 없어서 안 움직인다» 로 이름만 바꿔 그대로 남는다 —
**등재문 자신의 완료 조건(«구매 → 진행바 즉시 반영»)을 못 넘는다.**

⇒ 등재문 본문의 처방으로 간다: **단계를 «레벨이 실제로 산 만큼» 으로 내린다.**
326 규칙에서 단계 k 에 올라 있으려면 전 스탯이 `lv ≥ trainCapAt(k−1)` 이어야 하므로,
그 조건을 만족하는 **가장 큰 k** 가 그 세이브의 진짜 단계다.

```js
/* index.html — load() 안, `S = b;` 바로 앞 */
b.trainStage = (Number.isFinite(b.trainStage) && b.trainStage >= 1) ? Math.floor(b.trainStage) : 1;
TRAIN_STATS.forEach(id => { const v = b.lv[id];
  b.lv[id] = Number.isFinite(v) && v > 0 ? Math.floor(v) : 0; });
const lo = Math.min.apply(null, TRAIN_STATS.map(id => b.lv[id]));
let k = 1;
while(k < b.trainStage && trainCapAt(k) <= lo) k++;
b.trainStage = Math.min(b.trainStage, k);
```

- **레벨·골드는 한 톨도 안 건드린다**(`verify483` [H]).
- **`Math.min` — 올리는 방향으로는 절대 안 간다.** 이관이 단계를 선물하면 안 된다([F] 승급 금지 항).
- **정상 세이브에는 한 글자도 안 닿는다** — 단계 n 에 오르려면 `trainReady()` 가 전 스탯
  `lv ≥ trainCapAt(n−1)` 을 요구하므로 그런 세이브는 `k ≥ n` 이고 `min(n,k) = n` 이 항등이다.
  두 번 돌아도 결과가 같다(멱등 — [F]).
- **KEY 는 안 올린다**(44 교훈 2) — 저장 «구조» 는 그대로고 값 하나가 정정될 뿐이다.

수리 후 주인 세이브: **4단계 · 진행 `1030/1200`** = (921−600)+(983−600)+(926−600).
등재문이 손으로 계산해 둔 값과 **정확히 일치**한다.

### 3-1. 이관이 이 작업의 절반이다 — `verify326` [F]

원래 [F] 는 «**세이브 이관이 «없음» 이 맞다** — 구 세이브를 넣어도 레벨이 깎이거나 단계가

- ① **레벨 축은 여전히 맞다** — 구 상한 100n ≤ 신 상한이라 레벨이 깎이는 일은 없다(그대로 둔다).

⚑ **그리고 [F] 는 로드 경로를 한 번도 안 지나고 있었다.** `setup()` 이 `S` 를 **직접** 세팅하고
`save()` 만 부르므로 `load()` 의 이관 블록이 돌 일이 없었다 — 이관이 있든 없든 초록인
**헛초록**이었다. 이제 실제로 `load()` 를 불러 묻는다(**+6 항**: 정정된 단계 · 기저 ≤ lv ·

⚠ **`page.reload()` 로는 못 잰다**(LESSONS 363 재확인) — `beforeunload → save()` 가 방금 심은

## 6. 교훈 (LESSONS 483)

1. **«넘침» 만 보고 «모자람» 을 안 본 이관 판정.** 326 은 `구 상한 ≤ 신 상한` 을 확인하고 이관을
   «없음» 으로 닫았는데, 깨진 것은 **하한(기저)** 이었다. 상한을 바꾸는 작업은 **같은 식이 쓰는
   다른 끝**(base·분모·room)을 전부 세어 봐야 한다.
2. **«플레이어가 손해 안 보는 쪽» 이 늘 옳지는 않다.** 레벨을 선물하는 안은 곡선이 지수라
   **다음 한 레벨을 ×5.8e56 로** 만들어 화면을 더 죽인다. 처방 후보도 «찍힌 값» 으로 고른다(338).
3. **세이브 이관 게이트가 `save()`+직접 세팅으로 돌면 이관을 한 번도 안 지난다.** `verify326` [F]
   가 그 상태로 초록이었다. 이관을 묻는 항은 **`load()` 를 실제로 부르는지**부터 확인한다.
4. **`page.reload()` 는 세이브 주입을 지운다**(`beforeunload → save()`). 새 컨텍스트 +
   `addInitScript` 로 심거나, 같은 페이지에서 `load()` 를 직접 부른다(LESSONS 363 재확인).
