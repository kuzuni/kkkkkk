## 1. 증상 재현

등재문의 «간헐 FAIL» 은 인계 시점 3회 연속 PASS 였다(`VERIFY72 215/215`). 판정선이 아니라 **시간**에
걸린 자라 «몇 번 돌려 본다» 로는 못 잡는다 → 표본을 세는 프로브를 따로 만들었다.

**`node tools/probe245.js [표본수=120] [간격ms=50]` 신설** — 던전 카드 8장의 «지금 그려진 프레임» 키를 표본해
충돌률을 찍는다(설계값 쪽 충돌은 종료 코드로도 알린다):

```
[2] «지금 그려진 프레임» 충돌률 — 120표본 × 50ms
  «지금 프레임» 충돌 41/120 (34.2%)
     gold+stone → dragon/f3 — 41회
  «설계값(thk/thi/thf)» 충돌 0/120 (0.0%)  ← verify72 가 재는 자리
```

- **34.2% ≈ 1/3.** 등재문의 «3/3 재현 · 내 트리는 3회 중 1회 PASS» 와 같은 자리다.
- 같은 표본에서 **설계값**(`thk/thi/thf`) 쪽은 **충돌 0회**.
- **«3회 돌려 봤다» 는 근거가 못 된다** — 3회 연속 PASS 는 `0.658³ = 28.5%` 로 그냥 일어난다.

## 2. 원인 — 등재문의 «위상이 맞는 순간» 이 아니라 **«한쪽이 아예 안 돈다»**

등재문은 「골드(dragon/fly/`f3`)와 194 강화석(dragon/fly/`f1`)이 같은 애니를 돌다 위상이 겹친다」로
읽었다. 실제로 재 보면 다르다 — `node tools/probe245.js` [1] 절(카드별 `lkd`·`thn`·`at`·지금/설계 프레임):

```
  gold     lkd=false thn= 0 at=  8.78  지금 dragon/f4          설계 dragon/fly/f3
  stone    lkd=true  thn= 6 at=   4.2  지금 dragon/f3          설계 dragon/fly/f1
```

`gold` 의 `at` 은 표본마다 계속 커지고(8.78 → 18.63 …), `stone` 의 `at` 은 **4.20 에서 한 번도 안 움직인다.**
(같은 표에서 **8장 중 6장이 잠금·정지**이고, **6장 다 자기 `thf` 가 아닌 프레임에 굳어 있다**.)

세 가지가 한꺼번에 보인다.

1. **`stone` 은 잠금 카드다**(`gm:14`, 기본 세이브에서 `.dnc.lkd`). `raidIdleTick` 은 지시 ④ 대로
   잠금 카드를 건너뛰므로 `at` 이 **4.20 에서 영원히 멈춘다.**
2. 그런데 멈추기 전 **한 번은 `raidDraw` 로 그려졌고**, 그때 프레임은 설계값 `thf='f1'` 이 아니라
   아이들 창이 고른 `TH_IDLE['dragon/fly'][floor(4.20) % 3] = ['f2','f3','f4'][1] = **'f3'**` 이었다.
   → 잠금 카드가 **자기 설계값이 아닌 프레임**에 굳는다.
3. `gold` 는 살아서 `f2→f3→f4` 를 8fps 로 돈다. **3프레임 중 1장이 `f3`** 이라 충돌률이 1/3 = 34.2%.

즉 옛 단언이 재던 것은 «두 카드의 그림이 같은가» 가 아니라
**«살아 있는 카드가 지금 몇 번째 프레임인가 × 죽은 카드가 어느 프레임에서 굳었는가»** 였고,
후자를 정하는 것은 설계가 아니라 **카드의 목록 순서**(`data-thn` → 초기 위상 `thn × 0.7`)다.
던전이 한 장 늘어 `stone` 의 `ci` 가 바뀌면 굳는 프레임도 같이 바뀐다 — 90·194·203 이 이 게이트를
세 번 깨뜨린 것과 **같은 자리에서 나는 네 번째 병**이다.

## 3. 처방 — 재는 자리를 «그려진 프레임» → «설계값» 으로 (등재문 ⓐ)

`tools/verify72.js` [1-2] 마지막 단언:

```diff
-    seen.add(a.k + '/' + a.f);          /* a.f = cv._fr || dataset.thf — «지금 그려진 프레임» */
+    seen.add(a.k + '/' + a.i + '/' + a.f0);   /* dataset.thk / thi / thf — 설계값 */
```

- 72 가 지키려는 물음(«카드마다 다른 그림이다»)은 **그대로 두고**, 그것을 정하는 자리로 자를 옮겼다
  (LESSONS 185-④ «재는 자리만 이사» 와 같은 처방).
- 그리기 타이밍·잠금 여부·카드 순서 어느 것과도 무관해졌다.
- ⓑ(다른 아틀라스)는 안 갔다 — 등재문대로 97 «없는 몬스터를 그리지 않는다» 와 충돌하고 남는
  아틀라스가 없다. **아트 빚이지 게이트 결함이 아니다**(§5).

**동봉 단언 1건** — 같은 «아틀라스+애니» 를 쓰는 카드 쌍은 시작 프레임이 서로 갈려 있어야 한다:

```
  · 아틀라스+애니 재사용 1쌍 — dragon/fly = gold:f3 vs stone:f1 (아트 대기 등재분)
  ✓ 재사용 «dragon/fly» 는 시작 프레임이 서로 다르다 (gold:f3 vs stone:f1)
```

위 단언의 부분집합이지만 **겹친 쌍을 이름으로 찍는다** — 아트 빚이 조용히 늘면 로그에 바로 뜬다.
카드 수·던전 목록을 상수로 들고 있지 않으므로 던전이 늘어도 안 죽는다(242-③ 계열 부패 방지).

## 5. 남긴 것 (아트 대기 · 게이트 밖)

`gold` 와 `stone` 은 **같은 dragon 아틀라스의 같은 `fly` 애니**를 시작 프레임만 달리해 쓴다 —
순환 중 실제로 같은 포즈를 지난다. 97 «없는 몬스터를 그리지 않는다» 를 지키는 한 남는 아틀라스가

갈아 끼우면 된다 — 측정표 `docs/measure/03-던전팝업.md` 부록 D 에 등재했다(210 이 `despair` 를
같은 형식으로 등재해 둔 것과 나란히).

**손대지 않은 것** — `stone` 이 잠금 상태에서 «설계값이 아닌 프레임» 에 굳는 거동 자체는
`raidIdleTick` 의 지시 ④(잠금 카드 정지)와 121 아이들 창의 조합이라 **72 구간 밖**이다.

그것은 121·72 양쪽의 설계 판단이 필요하다 — 병렬 세션 규칙 3 대로 등재만 하고 두었다(PROGRESS 비고).
