### ① 신규 지급 — 소급 없음
`DEF()` 는 **신규 세이브에만** 도는 함수라 기존 유저에게 소급되지 않는다(등재문이 명시한 기본값).
`load()` 는 `Object.assign(b, d)` 로 세이브의 `dia` 가 기본값을 덮으므로 구조적으로 그렇게 된다 —
게이트 [G] 가 «구 세이브 dia 1,000 그대로 · gold·stage 불변» 으로 못박았다. 소급을 원하면 주인 되물음.

**73 ② 하한은 그대로 만족한다.** 「첫 가이드 미션이 스킬 10연(1,000 다이아)이라 시작 다이아가
그 아래면 첫 미션부터 막힌다」가 그 하한의 근거인데, 100만은 당연히 그 위다.
`verify73` 의 해당 항목도 `dia0 >= 1000` 부등식이라 손댈 것이 없었다(실제로 회귀 확인 시 무변경).

### ② 월별 지급 — 153 «지급품은 우편함» 규약을 그대로 탄다
```js
function monthlyCheck(){
  const mk = monthKey();
  if(S.lastMonthly === mk) return null;
  S.lastMonthly = mk;                       // ← 보내기 «전» 에 적는다
  const m = sendMail({ t:'📅 월별 다이아', c:MONTHLY_DIA, src:'monthly', b:'…' });
  uiDirty = true; save();
  return m;
}
```
세 가지가 설계다.

- **ⓐ `S.dia` 를 직접 더하지 않는다.** 153 이 «상점 지급품은 전부 우편함» 으로 목적지를 옮겼고,
  월별 다이아도 «지급품» 이다. 직접 더하면 그 규약이 깨지고 58 재화 비행 연출도 출처를 잃는다.
  게이트 [A] 가 `monthlyCheck` 본문에 `S.dia +=` 가 되살아나는 것을 정적으로 막는다.
- **ⓑ 달 열쇠를 «먼저» 적는다.** `sendMail()` 이 어떤 이유로든 null 을 돌려줘도(보상 0통 가드 등)
  같은 달에 두 번 시도하지 않는다. 「보내고 나서 적기」였다면 실패한 달에 매 tick 재시도가 된다.
- **ⓒ 밀린 달은 세지 않는다.** 달 열쇠 **하나**만 비교하므로 석 달을 비웠어도 우편은 **1통**이다
  (등재문 기본값 «최근 1통만»). 게이트 [E] 가 `lastMonthly:'2025-05'` 세이브로 실측한다.

### ③ 호출 자리 — «날짜 바뀜» if 블록 **밖**
`dailyCheck()` 안의 날짜 분기는 `S.daily.date !== today()` 일 때만 돈다. `monthlyCheck()` 를 그
**안**에 넣으면 첫 부팅에서는 한 통이 오지만(날짜가 «바뀐» 것이라) **그 뒤로 달이 바뀌는 순간을 놓친다** —
달이 바뀌는 날은 반드시 날짜도 바뀌므로 실전에서는 대부분 맞아떨어져서, 통수만 세는 자로는 안 잡히는
함정이다. 그래서 호출을 블록 밖에 두고, **게이트 [A] 에 «호출이 if 블록 밖인가» 를 정적으로 한 항목**
세웠다. NEG180 **N4** 가 이 함정을 그대로 재현한다 — 「첫 통은 초록, 달 바뀜만 빨감」.
