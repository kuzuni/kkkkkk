- **작업 종류**: T2 기능(저장소 주인 지시 2026-08-28) · **331 과 한 벌 · 같은 구간 한 세션 처리**

## 1. 현행 — 완료 화면이 사망 연출을 통째로 덮고 있었다

```
killEnemy(dunboss) → dunRun.bossDown = true
   ↓ 같은/다음 프레임
step() 던전 분기: if(dunRun.bossDown) endDunRun(true) → openDunClear()
```

`bossDown` 이 서는 **바로 다음 틱**에 완료 화면이 떴다. `killEnemy` 는 그 직전에 시체
(`corpses.push`, die 애니 · `life:1.6`)와 폭발(`burst`)을 세워 두는데, **아무도 그것을 보지 못했다**
— 딤이 깔린 클리어 화면이 그 위를 즉시 덮었기 때문이다. 주인이 «보스 터지고 나서» 라고 한 것이 이 자리다.

## 2. 처방 — 타이머 체인이 아니라 **런에 얹은 상태 하나**

지시가 «1초 뒤» 라 `setTimeout` 체인이 제일 먼저 떠오르지만, 그러면 **포기·시간 초과·부활과 경합**한다
(나가고 나서 1초 뒤에 완료 화면이 튀어나오는 사고). 등재문 ③ 이 «상태 기계로» 라고 못박은 이유다.

`dunRun` 에 필드 셋을 얹었다(런과 **함께 태어나고 함께 사라진다** — 포기하면 `dunRun = null` 로
시퀀스도 같이 없어진다. 잔존이 원천적으로 불가능하다):

| 필드 | 뜻 | 정하는 곳 |
|---|---|---|
| `clrT` | 격파 후 경과(초) | `step()` 이 `dt` 를 더한다 |
| `clrDie` | 이 던전 보스의 **사망 애니 길이** | `startDunRun` 에서 **한 번** 재 둔다 |
| `clrMsg` | «클리어» 를 이미 띄웠나 | 한 번만 띄우게 |

`step()` 던전 분기 — 두 갈래가 **배타적**인 것이 핵심이다:

```js
if(dunRun.bossDown){
  dunRun.clrT += dt;
  if(!dunRun.clrMsg && dunRun.clrT >= dunRun.clrDie){ dunRun.clrMsg = true; showMsg(DUN_CLR_TXT); }
  if(dunRun.clrT >= dunRun.clrDie + DUN_CLR_HOLD) endDunRun(true);
}else{
  dunRun.t -= dt;                       /* ← 시퀀스 중에는 제한 시간이 아예 안 흐른다 */
  if(dunRun.t <= 0){ dunRun.t = 0; endDunRun(false); }
}
```

**시퀀스에 들어간 런은 제한 시간을 더 깎지 않는다** → «연출 도중 시간이 다 돼 실패로 뒤집힌다» 가
**구조적으로 불가능**하다. 타이머 체인이었다면 정확히 그 경합이 생긴다(`verify332` §E 가 이것을 잰다:
남은 시간 0.005초에서 격파해도 클리어로 끝난다).

### «터지는 시간» 을 손으로 안 적은 이유
`DUN_CLR_HOLD = 1.0` 은 주인이 말한 «1초» 라 상수로 적었다. 그런데 **die 애니 길이는 던전마다 다르다**
(보스 아틀라스가 카드마다 다르다). 숫자를 적어 두면 아틀라스가 바뀌는 순간 갈라지므로
(LESSONS 90-① · 바로 옆 `bossDrawnH()` 와 같은 원칙) **아틀라스에서 센다**:

```js
const CORPSE_FPS = 10, CORPSE_LIFE = 1.6;      /* killEnemy 의 시체 리터럴을 상수로 올렸다 */
function dunBossDieSec(d){                      /* die 애니 프레임 수 ÷ 10fps, [0.3, 1.6] 로 가둠 */
  const u = DUN_UI[(d && d.id)] || DUN_UI.gold;
  const A = ATLAS[u.thk], nm = dunBossAnims(u).die;
  const n = (A && A.a && A.a[nm] && A.a[nm].length) || 0;
  return clamp(n / CORPSE_FPS, 0.3, CORPSE_LIFE);
}
```

`killEnemy` 의 시체 리터럴 `afps:10` · `life:1.6` 도 **같은 상수를 보게** 바꿨다 — 사본이 둘이면
반드시 갈라진다. 상한이 시체 수명인 이유는 그 뒤로는 **이미 사라진 시체를 기다리는 것**이기 때문이고,
하한 0.3 은 die 애니가 따로 없어 walk 로 대체되는 아틀라스(dragon/bird/robo)에도 «터지는 틈» 을 남긴다.

실측된 `clrDie`(던전 8종): 0.5s(relic4) ~ 1.5s(relic3) · gold 1.2s.

### 문구
`showMsg('클리어')` — 94 규약의 그 경로 그대로다(폭 클램프·짧은 문구·캔버스 중앙, 그리기는
`draw()` 끝의 `msgT` 블록이라 **UI DOM 을 뚫지 않는다** = 184 규약). 완료 화면이 뜰 때
`endDunRun → spawnStage()` 의 «STAGE n» 이 자연히 문구를 걷어 가므로 **따로 지우는 코드가 없다**.

## 3. 게이트 — 신설 `tools/verify332.js` **80/80 PASS**

- **§A·B 길이와 표시** (던전 8종 전부) — 격파부터 완료 화면까지 = `clrDie + 1.0` **± 2틱**,
  그 사이 «클리어» 가 실제로 `msgTxt` 에 뜨고 그 시각이 **`clrDie` 직후**, «클리어» → 완료 화면이
  **정확히 1초**, 그리고 완료 화면(`#dclw`)이 실제로 떠 있다.
- **§C 길이의 출처** — `dunBossDieSec` 이 던전 8종 전부에서 «die 애니 프레임 수 ÷ 10fps» 와
  **정확히 일치**(1e-9). 상한 1.6s·하한 0.3s. **94 규약** — `showMsg('클리어')` 가 폭 클램프를
  안 타서 문자열이 안 잘리고 폰트도 안 줄었다.
- **§D 포기** — 시퀀스 한복판에서 **`#dunOut` 을 실제로 클릭** → 런·`.dunrun` 즉시 해제,
  완료 화면 안 뜸, 그리고 **5초를 더 돌려도 뒤늦게 안 뜬다**(타이머 체인이면 여기서 뜬다). 층 불변.
- **§E 경합** — 남은 시간 0.005초에서 격파 → 시간 초과로 안 뒤집히고 클리어로 끝난다. 실패 통보(💀) 없음.
- **§F 페이즈(257)** — 보스 2~3마리 던전에서 **1마리째 격파로는 시퀀스가 안 시작**한다
  (`clrT = 0` · «클리어» 안 뜸 · 런 계속). 지시 ④ «마지막 보스에만».
- **§G 자기 검진** — `clrT` 를 크게 밀어 «격파 다음 틱에 끝나는» 옛 거동을 만들고 §A 와 **같은 자로**
  잰다. 그때 0.017s 로 끝나 §A(≥ 2.2s)가 빨개지는 것을 보인다(LESSONS 307-④ — 가짜 초록 방지).

### 게이트가 자기 함정 둘에 먼저 걸렸다 (1차 실측)
1. **rAF 를 안 얼려 시퀀스가 1~2틱 먼저 끝난 것으로 보였다.** `enter → killAll → 측정` 세 번의
   `page.evaluate` **왕복 사이에** 실시간 루프가 제 마음대로 틱을 더 흘리고 있었다(LESSONS 161).
   `window.requestAnimationFrame = () => 0` 으로 얼려 **`step()` 호출만이 유일한 시계**가 되게 했다.
2. **`cleanup()` 이 `#dclw` 를 안 걷어 §D 가 «완료 화면이 떠 있다» 로 빨갰다.** 31 클리어 화면은
   `.modal`/`.mw` 가 아니라 제 클래스로 뜬다 — 앞 절이 띄운 화면이 다음 절의 판정을 통째로 오염시킨다.
