## 1. 증상과 원인

**저장소 주인 보고(2026-08-26)**: «스킬 팝업을 아래로 드래그했는데 자꾸 자동으로 위로 올라간다.»

`loop()` 은 `uiT > 0.35` 에서 **`uiDirty` 와 무관하게** `renderUI()` 를 돌린다(index.html ~14987).
`uiDirty` 는 `renderUI()` 끝에서 false 로 꺼질 뿐 **진입 조건이 아니다** — 즉 시트를 열어 두면
전투를 하든 안 하든 **초당 약 3회** 본문이 `setBody()` 로 통째로 다시 그려진다.

옛 `setBody()` (작업 51) 는 스크롤 위치를 두 군데만 복원했다.

```js
const el = $(id), st = el.scrollTop;
const vp = el.querySelector('.shsc'), vs = vp ? vp.scrollTop : 0;   /* ← 본문 뷰포트 하나뿐 */
```

07 스킬 격자는 **그 «안»의 두 번째 스크롤러**다 — 86 이 스킬을 24종으로 늘리면서
패널 기하(1000×680)를 지키려고 `.sk-gp{overflow-y:auto}` 로 «상자 안» 스크롤을 만들었다.
`.shsc` 만 복원하니 `.sk-gp` 는 **매 틱 새 노드로 태어나 scrollTop 0** 이 됐다.

### 실측 (수정 전 / 수정 후)

시트를 열고 스크롤을 준 뒤 **3초** 방치. `idle` = 본문 `childList` 변이 횟수(= 실제 재생성).

|---|---|---|---|---|---|---|
| **07 스킬 격자** | `#bSk .sk-gp` | 455 | 455 | **0** ← 버그 | **455** | 8 → **0** |
| 50 코스튬 격자 | `#bCos .sk-gp` | 2352 | 500 | 500 | 500 | 8 → **0** |
| 26 동료 본문 | `#bPet .shsc` | 0 | — | — | — | 8 → **0** |

| 모험(던전) 패널 | `#bDun` | 731 | 500 | 500 | 500 | 8 → **0** |

**깨져 있던 것은 07 하나뿐이었고, 그게 정확히 주인이 본 화면이다.**
나머지가 무사했던 이유는 두 가지다 — 성장·모험은 **껍데기 자신이 스크롤러**라 옛 `el.scrollTop`
복원에 걸렸고, 50 코스튬은 87 이 `cosScroll` 모듈 변수로 **그 화면만** 따로 이어 놨었다.
즉 «`.sk-gp` 를 쓰는 화면이 두 개인데 한 쪽만 손으로 기워져 있던» 상태였다.

## 2. 수정 — `setBody()` 한 곳 (index.html «107» 절)

지시 ① 은 «`renderSkill/renderPet/renderCos/renderUp` 을 64 방식(값만 갱신)으로» 였는데,
**그 넷을 라이브 갱신으로 다시 짜면 8점 받은 레이아웃 4개의 마크업을 전부 건드려야 한다.**
같은 결과를 «값만 갱신» 이 아니라 **«바뀐 게 없으면 아예 안 그린다»** 로 낸다 —
64 의 `renderTrainLive()` 가 «구조가 다르면 통째로» 로 위임하는 것과 같은 판정을 문자열 하나로 한다.

1. **① 내용이 같으면 DOM 을 갈아끼우지 않는다.** 직전에 쓴 HTML 문자열을 `el.__bh` 에 들고
   있다가 같으면 그대로 반환. 전투 중 스킬 시트 HTML 은 «조각·레벨·장착» 이 바뀔 때만 달라지므로
   **유휴 틱의 재생성이 0회**가 된다(위 표). 스크롤이 튈 기회 자체가 없어진다.
2. **② 갈아끼울 때는 본문 안 «모든» 스크롤러를 복원한다.** 셀렉터가 아니라 **자식 인덱스 경로**
   (`[0,2,1]`) 로 뜬다 — `.sk-gp` 처럼 같은 클래스의 스크롤러가 여러 개인 화면에서 셀렉터로 뜨면
   첫 개만 복원된다. 구조가 바뀐 자리는 조용히 건너뛴다.
3. **③ 포인터를 쥔 «동안» 은 재생성을 미룬다.** 64 교훈 1 과 같은 규칙 — 드래그·꾹 누르기 중에
   노드가 날아가면 포인터 캡처가 끊긴다. `pointerdown` 캡처 리스너로 대상만 기억해 두고,
   그 대상이 이 본문 안이면 이번 틱을 건너뛴다. 뗀 뒤 다음 틱(≤0.35초)에 자동으로 반영된다.
   `pointerup` 을 놓쳐도 UI 가 영영 안 갱신되지 않게 **8초 안전망**을 뒀다.
4. **`setBody()` 의 반환값이 «갈아끼웠으면 요소 / 건너뛰었으면 null»** 로 바뀌었다.
   재렌더 뒤에만 해야 하는 후처리를 호출부가 가리게 하려는 것이고, 지금 그 후처리가 있는 곳은
   `renderCos()` 하나다(87 `cosPaint` + «선택 카드로 이동» 판정 + `scroll` 리스너 부착).
   **건너뛴 틱에 그것들을 그냥 돌리면 «선택 카드로 이동» 이 매 틱 재판정되고 `scroll` 리스너가 쌓인다.**
   같은 이유로 리스너에는 `gp.__csl` 표식을 붙였다 — 재생성이 드물어진 뒤로 노드가 오래 살기 때문이다.

**CSS 0줄 · 렌더 함수의 마크업 0줄 변경.** 8점 받은 화면들의 기하는 손대지 않았다.
