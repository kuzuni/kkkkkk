## 2. 처방 — 646 과 **같은 한 줄**을 105번 (새 규약 0개)

646 이 `verify169` 에서 쓴 처방을 그대로 넓혔다. 새 결정은 하나도 없다.

1. **이름에 `process.pid` 를 섞는다.** `'.v180-neg.html'` → `` `.v180-neg-${process.pid}.html` ``.
   확장자 **앞**에 넣어 «무엇을 여는 파일인가» 는 안 바뀐다(`.html` 사본은 계속 `.html`).
   ⚑ **사본을 저장소 안에 두는 이유는 그대로 지켰다** — `index.html` 이 `assets/**` 를 상대 경로로
   물어서 `/tmp` 에 두면 리소스가 통째로 404 다(59·74·58·191·360·367·439 선례). 옮긴 것은 **이름뿐**이다.
2. **맨몸 정리를 감쌌다** — `fs.unlinkSync(x);` → `try { fs.unlinkSync(x); } catch (e) {}` (278 처방:
   즉사 대신 그 항만 빨개지게). 이미 `try/catch` 나 `if (fs.existsSync(…))` 안에 있던 자리는 안 건드렸다.
   **`tools/claim.js` 는 일부러 뺐다** — lock 해제 실패는 **보여야** 하는 실패다(90분 규칙이 그 위에 산다).
3. **`.gitignore` 를 «이름» 이 아니라 «자리» 로 다시 걸었다.**

## 3. `.gitignore` — 이 작업이 규칙을 **깨뜨리는** 쪽이라 같이 고쳐야 했다

`.gitignore` 에는 `.v191-neg.html` 처럼 **정확한 이름**으로 걸린 규칙이 20줄 넘게 있었다.
이름에 pid 를 섞는 순간 그 규칙들이 **전부 안 맞는다** — 즉, 646 이 «규칙이 아예 없어서» 겪은 위험
(강제 종료가 남긴 `index.html` 통째 사본 1MB+ 가 `git add -A` 에 딸려 간다)이 **106자리로 번질 뻔했다.**
648 을 «이름만 바꾸고 끝» 냈으면 그것이 이 작업의 실패였을 것이다.

⇒ 자리째 덮는 규칙으로 갈았다:

```
/.*.html   /.*.js   /.*.json   /__*.html   /index.*.html   !/index.html
tools/.*.html   tools/.*.js   tools/.*.json
```

**넓혀도 안전하다는 근거를 재고 넣었다** — `git ls-files` 로 저장소가 추적하는 루트 dotfile 은
`.gitignore`·`.nojekyll` **둘뿐**이고 `tools/` 에는 **하나도 없다**. `index.html` 은 `!/index.html` 로
되살렸고(`index.*.html` 은 `index.html` 을 안 무는 꼴이지만 못을 박아 뒀다), `git check-ignore` 로
셋 다 안 걸리는 것을 확인했다. 기존 정확한 이름 규칙은 **안 지웠다** — 그 줄들이 «왜 이 사본이
저장소 안에 사는가» 를 적어 둔 유일한 기록이라, 지우면 다음 세션이 `/tmp` 로 옮겼다가 404 를 만난다.

## 8. 교훈 (LESSONS 648)

1. **«고정 이름» 은 리터럴만이 아니다.** `` `…-${sha.slice(0,7)}.html` `` 은 보간이 있어 유일해
   보이지만 **같은 트리를 도는 워커 넷에서는 전부 같은 값**이다. 판정은 «리터럴인가» 가 아니라
   «**두 프로세스에서 다른가**» 여야 하고, 그 축을 만족시키는 조각은 실질적으로 `process.pid` 하나다.
2. **이름을 바꾸는 작업은 `.gitignore` 를 깨뜨리는 작업이다.** 정확한 이름으로 걸린 무시 규칙은
   이름을 바꾸는 순간 전부 무효가 된다 — 646 이 «규칙이 없어서» 겪을 뻔한 사고가, 규칙을
   **가진 채로** 106자리에 번질 수 있었다. 이름을 옮기면 규칙은 **자리로** 다시 걸어라.
3. **사본을 «만드는 줄» 과 «여는 줄» 은 다른 곳에 있다.** `verify633` 은 자식 프로세스 명령줄에
   이름을 문자열로 다시 적고 있었다. 치환 뒤 **«옛 이름이 더 남았는가» 를 반드시 세라** —
   안 세면 «이름은 바꿨는데 안 여는» 자가 되고, 그건 조용히 빨간 게이트다.
4. **소스를 읽는 자는 주석·문자열·정규식 셋을 다 걷어야 한다.** 646 은 주석 하나로 족했지만,
   전수로 넓히자 «문자열로 자기 이름을 단언하는 자»(`verify571`)와 «문자 클래스 안에 백틱을 둔
   정규식»(`verify646`)이 차례로 나왔다. 둘 다 **자기 자신을 검사하는 자**에서 나온 것이 우연이 아니다.
