## 1. 무엇이 결손이었나

199 의 입력표를 만드는 봇(`tools/bot199.js` 1240)이 오프라인 보상을 **버튼이 아니라 API 로** 받고 있었다.

```js
try { offlineReward(lastLogout); claimOffline(a.offlineMul); } catch (_) {}
```

650 은 «결손A» 가드(실효 이득이 0 인 ×1.5 는 안 준다)를 **API 쪽 난간으로 일부러 남겨 두고**
버튼만 `claimOffline(offNoGain() ? 1 : 1.5)` 로 고쳤다(`index.html` 39631). 그래서 실제 유저는
광고 버튼만 눌러도 하루 예산을 다 받지만, 봇은 그 난간에 그대로 막혀 네 번째 수령을 통째로 버린다.

⚑ **계수가 아니라 계측기 결함이다.** 손잡이(적·수급·비용·확률)를 돌려 이 몫을 메우면
실제 플레이어에게 이중으로 얹힌다 — 그래서 199 의 손잡이는 **한 칸도 안 건드렸다**.

유저의 버튼은 이때 ×1 로 부르므로 남은 337.5분을 정확히 받아 예산을 채우고, 봇은 ×1.5 로 불러 거절당한다.

## 3. 처방 — 새 문턱을 적지 않고 **650 이 세운 판정을 그대로 읽는다**

```js
try { offlineReward(lastLogout); claimOffline(offNoGain() ? 1 : a.offlineMul); } catch (_) {}
```

등재문의 처방 그대로다. `offNoGain()` 은 650 이 «한 곳에서만 묻기» 위해 신설한 판정이고
라벨·클릭·가드 셋이 이미 그것을 읽는다. 봇이 넷째 독자가 되는 것뿐이라 **문턱 사본이 안 생긴다**.
