## 4. 3회차 (2026-08-26, sess-2319-7181) — 비평가 O·P 채점 반영

**2회차 채점: O ①5 ②6 ③4 ④4 (최저 4) · P ①4 ②3 ③2 ④3 (최저 2).**

### 4-1. 이번 회차 최대 결함 — «clip-path 로 가뒀다» 는 착각

O: «coin-5 카드 왼쪽 바깥 배경 42.33 → **50.38**, coin-10 오른쪽 → 51.43, dia-1 왼쪽 → 49.82».
P: 같은 현상을 «골드 광선이 카드 밖으로 다 새어나온다(전이광의 84~91%가 카드 밖, x0~1079·y330~1945)» 로 읽었다.
둘이 **같은 회색 사선 막대**를 서로 다른 연출로 지목한 것이고, 정체는 **재화 카드 광택 스윕**이다.

원인은 한 줄이다 — **의사요소의 `clip-path` 는 «그 의사요소 자신의 상자» 기준이라 띠와 함께 움직인다.**
띠를 카드 안에 가두는 일은 `clip-path` 가 아니라 **부모의 `overflow:hidden`** 이 한다
(소환 카드에서 `.chd{overflow:hidden}` 이 이미 그렇게 하고 있었는데 재화 카드에만 그 규칙을 안 옮겼다).
→ `.cn-cd{overflow:hidden;border-radius:35px}`. 게이트 §11 신설 — **카드 왼쪽 바깥 52px 띠가 세 위상에서 픽셀 동일**.

### 4-2. 두 번째 발견 — `rotate:0` 은 **무효 선언**이다 (들썩이 «이따금» 이 아니었다)

O 는 «들썩의 회전이 사실상 0(bbox 팽창 없음)» 이라고 읽었다. 확인해 보니 **정반대**였다:

```
카드2, 들썩 구간 밖(진행률 51.4%) 의 computed rotate = 1.74deg
```

`translate:0` 은 길이라 단위 없는 0 이 유효하지만, **`rotate` 는 `<angle>` 이라 단위 없는 0 을 안 받는다**
— 선언이 통째로 버려진다. 그래서 `0%`·`92%`·`100%` 에서 rotate 가 사라지고, Chrome 이
«94% 의 3deg» 와 «바탕값 0deg» 사이를 **주기 내내 선형 보간**했다. 즉 «이따금 한 번 툭» 이
**«항상 조금 기울어 서서히 도는»** 것이 돼 있었다. 회전이 없어서가 아니라 **늘 있어서** 프레임 간 차가 안 났다.
→ `rotate:0deg`. 게이트 §10 신설 — «쉬는 시각의 회전 0° · 들썩 구간에서만 ±3°».
(게이트를 만들면서 한 번 더 헛짚었다: computed 값이 **`4.9e-29deg` 같은 지수 표기**로 와서
정규식이 지수부 «29» 를 각도로 읽었다. 각도 파싱은 `parseFloat` 하나면 된다.)

**두 신설 게이트는 회귀를 주입해 실제로 FAIL 하는 것을 확인했다** —
`overflow` 제거 → §11 FAIL(38/39) · `rotate:0deg`→`rotate:0` → §10 FAIL(38/39), 원복 후 39/39.
