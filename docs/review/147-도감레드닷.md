## 2. JS 는 무죄다 — 판정도 토글도 처음부터 맞았다

`renderColl21()` 의 마지막 줄은 정확히 지시대로다.

```js
t.classList.toggle('alert', collTabReady(t.dataset.ct));   /* 레드닷 = 그 탭에 강화 가능한 세트가 있다 */
```

`collTabReady(tab)` → `COLL_SETS.some(st => st.tab === tab && collReady(st.key))`,
`collReady(key)` → `collStep(key) < collCap(st)` = «받은 단계 < 가능 단계». 전부 맞다.
실제로 위 실측에서도 `ready=0` 인데 `dot=1` 이다 — **판정은 0 인데 점이 떠 있다.**

## 3. 원인 — CSS 특이성

```css
#collw i,#collw s,#collw b,#collw em{display:inline-block}   /* 5488줄 — (1,0,1) ID */
.cltab>s.dot{display:none}                                   /* 5731줄 — (0,2,1) 클래스 2 */
.cltab.alert>s.dot{display:block}                            /* 5733줄 — (0,3,1) 클래스 3 */
```

ID 셀렉터 하나가 클래스 셋을 이긴다. 그래서

* `display:none` 이 무력화돼 **점이 상시 노출**되고,
* `.alert` 를 붙이는 쪽(`display:block`)도 **똑같이 져서** 토글 자체가 화면에 아무 영향이 없었다.

즉 «켜는 규칙도 지고 끄는 규칙도 져서, 항상 켜진 것처럼 보인다» 는 형태다.
이 함정은 **같은 파일 안에 이미 두 번 주석으로 박제돼 있었다**(`.clb-bdg>i`(5585) · 카드 라벨 상자(5632) —
둘 다 `#collw .클래스` 로 올려서 되찾았다). 레드닷만 그 처방이 빠져 있었다.
