## 1. 재현 (수정 전)

`tools/probe192.js` 로 펫 3종(`bird`/`robo`/`dragon`)을 보유시키고 **영웅 탭 → 동료 서브탭 →
[일괄 강화] 를 진짜 포인터로 클릭**했다.

```
카드: [{"text":"❔"},{"text":"❔"},{"text":"❔"}]   ← 3칸 전부
에러: 0
```

콘솔은 깨끗하다 — **크래시가 아니라 «없는 필드를 폴백으로 덮은» 조용한 버그**다.

## 2. 원인

09 결과 팝업이 카드 아이콘을 한 줄로 그린다:

```js
'<div class="upr-card"><b>' + (u.it.ic || '❔') + '</b></div>'      /* index.html ~17663 */
```

`u.it` 은 `levelUpAll(list)` 이 받은 목록의 원소이고, 호출부는 **3곳**이다:

| 호출부 | 목록 | `ic` |
|---|---|---|
| `wpnBtnUp`(05 무기) | `wpnList()` ⊂ `EQUIPS` | 있음 (`ic:x.ic \|\| s.ic`, ~13634) |
| `data-skup`(07 스킬) | `SKILLS` | 있음 (표에 직접) |
| `data-ptup`(07 펫) | `PETS` | **없음** |

`PETS` 는 **36종 전부** `ic` 가 없다 — 펫 그림은 이모지가 아니라 `sp:'bird'\|'robo'\|'dragon'` +
`tint` 스프라이트이기 때문이다(~13698 · `PET_SP` ~13704). 그래서 폴백 `'❔'` 이 통째로 걸렸다.

**`ic` 를 채워 넣는 것은 오답이다.** 174(펫 슬롯·카드 썸네일 = 전투 스프라이트)가 주인 지시로
확정돼 있어 이모지를 새로 심으면 174 에 역행한다 — 등재문도 «스프라이트 캔버스가 정답» 으로 못 박았다.

## 3. 고친 것 (index.html 2곳)

### ① 마크업 — `uprIcon(it)` (~17660)

```js
const UPR_ART = 13;                                   /* 90x90 칸의 사방 여백 */
const UPR_FB  = { dragon:'🐉', bird:'🐦', robo:'🤖' }; /* 아틀라스가 없을 때만 */
function uprIcon(it){
  if(!(it && it.sp && PET_SP[it.sp])) return it && it.ic || '❔';
  return '<canvas width="90" height="90" data-usp="' + it.sp + '"'
       + (it.tint ? ' data-utc="' + it.tint + '"' : '') + '></canvas>';
}
```

**분기 기준을 «펫이냐» 가 아니라 «`sp` 가 `PET_SP` 에 있느냐» 로 잡았다.** `PETS` 배열을 뒤지지
않으므로 나중에 다른 스프라이트 항목이 이 팝업을 타도 같은 규칙으로 그려지고, `ic` 를 가진
장비·스킬은 **한 글자도 안 바뀐다**(§6 과교정 잠금).

### ② 그리기 — `uprPaint(root)`, `openUpAll` 이 삽입 직후 1회 호출

```js
drawSpriteTo(cv, { k, frame:list[0], tint:cv.dataset.utc || null, fit:UPR_ART });
```

- **`drawHeroTo` 가 아니라 `drawSpriteTo`** — LESSONS 97-② 그대로다. 전투용 헬퍼는 앵커가
  «발밑» 이라 논리 프레임(`fr[4..7]`)을 쓰고, 그러면 잉크가 칸 한쪽으로 몰린다. 카드 썸네일은
  «씬에 세우기» 가 아니라 «액자에 담기» 라 잉크 rect(`fr[0..3]`)만 봐야 한다.
- **`fit:13`(contain)** — 72 의 «액자» 규칙. 늘려 채우면 로봇(종횡 0.58)·용(1.47)이 찌그러진다.
- 프레임은 `A.a[PET_SP[sp].anim][0]` **고정 0번**이다. 애니메이션을 돌리지 않는다 —
  09 는 «탭하면 닫히는» 순간 연출이고, 프레임이 흔들리면 게이트가 비결정적이 된다(LESSONS 121-⑤ 계열).
- 실패하면 **캔버스를 이모지로 되돌린다.** 빈 캔버스를 남기면 ❔ 보다 나쁜 «빈 칸» 이 된다.

### ③ CSS 1줄 (~9279)

```css
.upr-card>b>canvas{display:block;width:90px;height:90px;image-rendering:pixelated}
```

칸 규격(`b` 90x90)은 그대로다 — **레퍼런스 bbox 를 한 px 도 안 건드렸다.**

## 4. 실측 — 잉크가 이모지와 같은 급인가

측정표 09 는 «아이콘 잉크 51~65 → 90x90 안에 contain» 이라 적혀 있고, 이모지 칸은 `font-size:57`
로 그 대역을 맞춰 놓았다. 스프라이트도 **같은 대역**에 들어와야 한 팝업 안에서 크기가 안 튄다.

| sp | 틴트 | 잉크 w×h | 최대변 | 잉크 중심 (칸 중앙 45) | 잉크 px |
|---|---|---|---|---|---|
| bird | – | 53×62 | **62** | 45.5 / 45.0 | 1838 |
| robo | `#b9c2d0` | 37×64 | **64** | 45.5 / 45.0 | 1512 |
| dragon | `#9ad6a0` | 63×43 | **63** | 45.5 / 45.5 | 1113 |

`fit` 을 13 으로 잡은 근거가 이 표다(90 − 13×2 = 64 = 최대변 상한). 중심은 3종 모두 칸 중앙에서
**0.5px 이내** — 97-② 의 «한쪽으로 몰림» 이 없다는 실측이다.

## 5. 대비 (LESSONS 97-⑤)

`multiply` 틴트는 **색을 입히는 게 아니라 어둡게 하는 것**이라, 밝은 카드 위에서 잉크가
묻히는지 «곱한 뒤» 재야 한다. 카드 중심색 `#9DC838` = 휘도 **180.5**.

| sp | 잉크 휘도 평균 | 최저~최고 | 배경±25 에 묻힌 잉크 |
|---|---|---|---|
| bird | 149.8 | 16~251 | **15.9 %** |
| robo | 74.6 | 26~187 | **9.7 %** |
| dragon | 49.4 | 0~187 | **2.6 %** |

세 종 다 배경보다 확실히 어둡고 검정 외곽선(최저 0~26)이 실루엣을 잡아 준다 →
**밝기 보정(`bright`) 불필요**. 게이트가 «묻힘 < 30%» 로 이 결론을 고정한다.
