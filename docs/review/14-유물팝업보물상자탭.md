## 남은 문제 (아트 리소스 없이는 회수 불가)

1. **중앙 나무상자·활성화버튼 상자·5칸 아이콘 모두 이모지 대체.** 레퍼런스는 각 상자별 다른 실루엣(나무·강철·보석·황금·전설)의 픽셀 아트인데 이모지는 형태·비율·명암이 다 다르다. A1·A3·A4·03·06 과 동일한 천장. ⑤ 색·명암과 ⑥ 폰트를 이 이상 회수하려면 아트 리소스가 필요하다.
2. **획득 가능 목록 2줄 텍스트의 «✦» 글리프.** 유니코드 별표를 쓰지만 레퍼는 두 줄의 별이 서로 색만 다른 것이 아니라 **다른 픽셀 아트**(1줄 노란색 마름모 반사, 2줄 보라 스파클). 이모지·유니코드 단일 문자로는 재현 불가.
3. **활성화버튼 라벨의 «필요» 대신 collReady 시 «보너스 받기»** 노출 로직은 유지했으나, 레퍼는 상태에 따라 라벨/색이 바뀌는지 확인 불가. 현재는 collReady 시 «보너스 받기» 로 자동 전환.

## 다른 화면에도 쓰이는 교훈

- **눈대중 비평의 «전체가 X% 어긋남» 판정은 세로 종횡비 차이(1:1.78 vs 1:2.17)에서 오는 착시로 원인이다.** 두 이미지 폭이 같아도 이 비율 차이가 가로 지각을 왜곡시켜, 두 비평가가 **독립적으로 같은 방향·같은 크기의 오독**을 낸다. 반드시 PIL 스캔으로 반증 후 반영.
- **버튼 border-box 는 fill-only 스캔으로 재지 마라.** ref 오픈버튼을 «fill 회색 벽 안쪽» 으로 스캔하면 h=115(라벨/베벨 제외), border 포함 h=148. 두 값을 섞으면 «22% 과대» 같은 반대 결론이 나온다. text-free 열을 골라 검정 border 를 포함하는 y 범위로 재라.
- **`localStorage` 주입은 `page.reload()` 로는 안 되고 `addInitScript()` 로만 된다.** Playwright 의 `file://` 컨텍스트는 reload 시 storage 를 비운다. 첫 goto 전에 addInitScript 로 setItem 해야 첫 load() 가 값을 읽는다. 06/07 등에서 disabled 상태로 캡처돼 색 채점이 왜곡됐던 문제도 이 방식으로 해결 가능.
- **그라디언트 fill 의 «상단 색» 이 중앙 픽셀까지 새어든다.** `linear-gradient(#FEC820 0 34%, #FFB514)` 는 y=34% 까지 상단 색을 유지하는데 (255,194,29) 가 진행바 중앙(y=50%) 근처까지 지배해 «G+16 노랑» 지적이 나왔다. 목표 색이 하나면 solid, 그라디언트라면 목표 색을 **하단이 아니라 y=50% 근처**에 두어야 중앙 스캔이 목표와 맞는다.
- **CSS `top` 오차 8px 는 «HUD 106px + 상태바 84px» 매핑 규칙의 미묘한 차이에서 온다.** 규칙상 −87 이지만 실제 값은 −86~−90 사이에서 흔들린다(요소마다). 요소별로 실측한 뒤 어긋난 것만 개별 조정하는 게 안전.
