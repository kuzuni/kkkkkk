## 1. 등재문과 실제

등재문은 두 갈래를 남겼다.

* ⓐ **자 쪽** — `+n` 은 «첫 도착» 때 뜨는데 [B] 는 `fxFly` 를 직접 부르고 700ms 만 기다린다. 발원
  `{x:540,y:1200,combat:true}` 이 알약까지 못 닿으면 `.fx-plus` 자체가 안 난다.
* ⓑ **제품 쪽** — `fxPlus` 의 층 선택이 `combat` 을 안 읽어 `+n` 이 `#fxl`(팝업 **위**)로 샌다.
  그렇다면 77 규약 자체의 결손이고 518 과 같은 축이다.

등재문은 «**결정적으로** 빨갛다(3회 연속 FAIL 1)» 고 적었지만, 착수 시점(`a9db968` 이후)에서
같은 자를 5회 돌리니 **PASS 4 / FAIL 1** 이었다 — **플레이키다.** 등재 이후 512·518 3회차가
같은 구간을 지나갔으므로 «결정적» 이라는 관측 자체는 그때는 맞았을 수 있으나, 판정 축이
확률적이라 «3회 연속» 이 성립하는 창이 존재한다(아래 §2 가 그 확률을 설명한다).

**338 규칙대로 처방 전에 재현부터 했다** — `tools/probe552.js` 신설.

## 2. 재현이 갈래를 확정했다 — **둘 다 아니다. 뿌리는 «자의 판정 방식» 이다**

`probe552` 는 [B] 와 **같은 호출**을 반복하되 셋을 더 본다.

1. 두 묶음에 **다른 금액**을 준다(combat 1,010 → `+1.01A` · UI 2,020 → `+2.02A`) — 542 의
   «금액으로 묶음 고르기». 배경 자동 전투의 금액과도 겹치지 않으므로 «내 +n» 을 글자로 집는다.
2. `MutationObserver` 로 **어느 층에 무엇이 언제 붙었는지**를 적는다(잔존 수가 아니라 **생성**).
3. 같은 시나리오를 **배경 전투를 막고**(`killEnemy` 무력화 — [E] 선례) 한 번 더 돌린다.

### 실측 (각 10회)

| 조건 | [B] 델타 판정이 빨간 회차 | 내 combat `+n` 이 **#fxlc** 에 붙은 회차 | **#fxl** 로 샌 회차 | 붙은 시각 |
|---|---|---|---|---|
| ① 자와 같은 조건(배경 전투 도는 채로) | **8 / 10** | **10 / 10** | **0 / 10** | 중앙 270ms (218~299) |
| ② 씬 격리(`killEnemy` 무력화) | **0 / 10** | **10 / 10** | **0 / 10** | 중앙 276ms (228~297) |

**⇒ ⓑ 는 기각된다.** 제품의 `fxPlus(cur, n, combat, at)` 는 `L = combat ? fxLC() : fxL()` 로
층을 옳게 고르고, `fxTick` 의 첫 도착 자리도 `fxPlus(f.cur, f.n, f.batch.combat)` 로 묶음의
`combat` 을 그대로 넘긴다. 실제로 **20회 중 20회**가 `#fxlc` 에 붙었고 `#fxl` 로는 **0회** 샜다.

**⇒ ⓐ 도 «도착 실패» 는 아니다.** `+n` 은 **예외 없이** 218~299ms 에 붙는다 — 자의 창 700ms 의
2.3~3.2배 여유다.

### 진짜 뿌리 — **840ms 짜리 남의 `+n` 이 700ms 창 안에서 죽는다**

종전 [B] 는 층별 `.fx-plus` 를 **개수 델타**로 쟀다.

```js
const b0 = cnt(L), c0 = cnt(LC);          // 호출 «직전» 재고
… fxFly(…) …
await sleep(700);
combatPlus: cnt(LC).plus - c0.plus        // 700ms 뒤 재고 − 직전 재고
```

이 자는 **배경 자동 전투가 도는 채로** 잰다. 전투 `+n` 의 수명은 `fxBye(el, 840)` 이므로,
호출 직전 `#fxlc` 에 남아 있던 «남의» `+n` 이 700ms 창 안에 사라지면

> 들어온 내 것 1 − 나간 남의 것 1 = **0** → `✗ combat 묶음의 +n 이 #fxlc 에 없다`

가 된다. **내 +n 이 제 층에 정확히 들어와 있는데도** 빨갛다. 실측 ①에서 호출 직전 재고는
중앙 **1건**이었고, 그 1건이 창 안에서 죽는 비율이 그대로 실패율(8/10)이다.

UI 쪽(`#fxl`)이 한 번도 안 빨갰던 이유도 같은 식으로 설명된다 — 배경 전투는 **전부 combat 발**
이라 `#fxl` 에는 남의 `+n` 이 아예 안 쌓인다. 등재문이 «자매 항이 초록이라 갈래를 못 가른다»
고 적은 그 비대칭이 바로 이 오염의 지문이었다.

## 3. 처방 — 씬 격리 + 금액으로 묶음 고르기 (542 처방 그대로)

`tools/verify77.js` [B] 를 다시 적었다. **허용 오차는 한 칸도 안 넓혔다 — 자를 좁혔다.**

* **씬 격리** — `killEnemy` 를 무력화하고(`[E]` 가 이미 쓰는 방식) 앞 비행이 착지하도록 1초 기다린다.
* **금액으로 고르기** — 두 묶음에 다른 금액(1,010 / 2,020)을 주고, `MutationObserver` 로
  «어느 층에 무엇이 붙었나» 를 적는다. 판정이 «개수» 가 아니라 **«층»** 이 되면서 재고와 무관해진다.
* **음성항 2개 신설** — combat `+n` 이 `#fxl` 로 **안 샌다** · UI `+n` 이 `#fxlc` 로 **안 샌다**.
  등재문이 «77 규약 자체의 결손» 이라 부른 갈래 ⓑ 를 이제 **자가 직접 감시한다**(종전에는
  «#fxlc 에 있나» 만 물어서 양쪽에 다 있어도 초록이었다).
* **전제 2개 신설** — ⓐ 두 금액이 실제로 다른 글자로 렌더된다(안 그러면 묶음을 못 고른다)
  ⓑ 격리 창에 «남의» `+n` 0건(격리가 깨지면 조용히 헛초록이 되는 것을 막는다).

**항 수: 4 → 8.**

## 4. 무르게 풀지 않았음 — `[B-R]` 되돌림 시험 신설

지시서와 등재문이 함께 못박은 금지(«항을 지우거나 `>0` 을 `>=0` 으로 바꾸지 마라»)를
지켰다는 것을 **자 자신이 증명**하게 했다. `[E]` 가 `killEnemy` 를 바꿔 끼우는 것과 같은 방식으로
**제품 파일은 안 건드리고** 페이지 안에서 사본만 갈아 끼운다.

```js
const orig = fxPlus;
fxPlus = (cur, n, combat, at) => orig(cur, n, false, at);   // 「층이 안 따라가는」 사본
```

* **R1** — 그 사본에서 combat `+n` 이 `#fxl` 로 **새고** `#fxlc` 에는 **없어야** 한다(= [B] 가 빨개진다). ✓
* **R2** — 원복한 뒤 다시 `#fxlc` 로 돌아와야 한다(되돌림 시험이 상태를 안 더럽혔다). ✓

즉 **갈래 ⓑ 가 실제로 일어나면 이 게이트는 반드시 빨개진다.** 종전 자는 그것을 증명한 적이 없다.
