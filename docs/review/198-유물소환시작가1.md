## 1. 무엇을 바꿨나 — 절편 하나

119(2026-08-26)가 «800 + 22 × ΣLv» 를 «100 + 1 × 누적 소환 횟수» 로 갈아 놓은 구조가 이미 있었다.
198 은 **그 구조를 한 줄도 안 건드리고 절편만 100 → 1** 로 내린다.

| | 119 (전) | 198 (후) |
|---|---|---|
| `RELIC_COST_BASE` | 100 | **1** |
| `RELIC_COST_PER` | 1 | 1 (유지) |
| 축 | `S.cnt.sumRelic` | 그대로 |
| 사다리 | 100 → 101 → 102 → … | **1 → 2 → 3 → …** |

편집은 **2곳뿐**이다.

1. `index.html` ~21462 — `const RELIC_COST_BASE = 1, RELIC_COST_PER = 1;`
2. `index.html` ~12249 — `#rwCost` 정적 기본 표기 `<b>100</b>` → `<b>1</b>`

②는 런타임에 `renderRelw()` 가 즉시 덮지만, **유물 페이지가 처음 열리기 전 한 프레임 «100» 이 보이는
자리**다. 119 도 같은 이유로 «822» 를 여기서 갈았고 `verify119 A5` 가 그것을 못박고 있다 —
상수만 고치고 이 자리를 빼먹으면 게이트가 빨개진다(실제로 A5 가 잡는다).

머리주석에는 198 절을 넣고, 119 가 적어 둔 «비용 = 100 + …» 문장을 «BASE + …» 로 고쳤다.
값보다 주석이 오래 살아서, 남겨 두면 다음 세션이 «100 이 설계다» 로 읽고 되돌린다(LESSONS 반복 항목).

**표시·차감·부족 판정 코드는 0줄**이다. 119 가 세 소비처(`#rwCost b` 표시 · `lack` 토글 ·
`summonRelic()` 차감 · 홀드 매회 재계산)를 `relicCost()` 한 함수로 모아 놨기 때문에 상수 하나로 전부
같이 움직인다. 소스 전체에 하드코딩된 «100» 유물 가격 문자열은 **0건**(실측).
