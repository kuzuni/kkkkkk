## 1. 재현부터 (338 규칙)

등재문은 «제품이 앞서간 부패» 로 읽었지만, 제품 쪽이 틀렸을 가능성을 먼저 갈랐다.
수리 전 실행 로그(`node verify41.js`):

```
[1] 기능 체크
  FAIL [dun] 초기 골드 표기 = fmt(S.gold): 0 ≠ 1
  FAIL [dun] 골드 미반영: 바 35.0A ≠ 35,012
  FAIL [dun] 감소 미반영 17.5A ≠ 17,510
  OK   [dun] 바 표기 = 메인 HUD 표기(같은 소스)      ← ⚑
  ...
page.evaluate: ReferenceError: openRelicPage is not defined   ← [2] 직전 즉사
```

**⚑ 줄이 판정을 끝냈다** — 바와 메인 HUD 가 **같은 문자열**이다. 즉 «팝업 바만 이상하다» 가 아니라
**게임 전체의 골드 표기가 접힌 꼴**이고, 자 혼자 콤마를 기대하고 있었다. 소스가 그것을 확인해 준다:

| 자리 | 코드 | 규약 |
|---|---|---|
| 메인 HUD | `$('goldN').textContent = fmtG(fxVal('gold'))` (index.html 23761) | 150 |
| 팝업 바 | `const g = fmtG(fxVal('gold')), d = fmt(fxVal('dia'));` (`renderPcb` 23718) | 150 |
| 디스패처 | `const fmtCur = (k, n) => k === 'gold' ? fmtG(n) : fmt(n);` (16549) | 150·188 |

150(«골드만 접는다»)·188(주인 정정 «데미지·체력도 a b c 식»)이 표기를 재화 종류별로 갈라 놓았고,
`verify41` 은 그 **이전(2026-08-24)** 에 쓰여 `fmt()` 한 벌만 알고 있었다. ⇒ **자가 뒤처진 것이 맞다.**
이관 실행으로 못박았다 — `verify150` 43/43 · `verify188` 83/83 (둘 다 무수정 초록).

## 2. 고친 것 — 자 다섯 자리

### ⓐ 표기 축 3항 — 숫자도 함수 이름도 박지 않고 **제품 디스패처에게 묻는다**
`fmt(S.gold)` → **`fmtCur('gold', S.gold)`**. 402 «표 두 벌» 부패를 만들지 않으려면 자가 규약을
복제하면 안 된다. 대신 규약이 조용히 뒤집히는 것을 막으려고 **«지금 규약이 무엇인가» 항을 따로 신설**했다
(골드 `/^\d+(\.\d+)?[A-Z]+$/` · 다이아 `/^\d{1,3}(,\d{3})+$/`). 셋이 «같이» 초록으로 남는 길을 막는 항이다.

### ⓑ 옛 이름 — `openRelicPage()` → `openRelw()` · `#relicw` → `#relw`
130(`verify77`)·133(`verify73`·`aspect63`)이 이미 같은 이름을 걷어냈는데 이 자만 남아 있었다.
`cap41.js` 22행에도 같은 이름이 있어 같이 고쳤다(같은 작업 단위의 캡처 도구).

### ⓒ **[2] rel 이 헛초록이었다** — 이번 작업의 본체
`GEO_SEL.rel = ['#relicw', '.rlx-strip', '.rlx-sub', '#relicBody']` 는 **네 개 다 문서에 0건**이다.
`querySelectorAll` 이 빈 집합을 돌려주므로 회귀 대조가 «0종 Δ0» 으로 **언제나 초록**이었다.
즉시 죽는 55행을 고치기만 했으면 그 헛초록이 그대로 남았을 것이다. ⇒ 이름을 옮기는 데서 멈추지 않고
**그 페이지가 실제로 그리는 블록**을 적었다: `#relw` `.rw-panel` `#rwGrid` `.rw-mid` `#rwBasin` `.rw-cost` `.rw-cap`
(수리 후 **7종 Δ0** — 처음으로 무언가를 재고 있다).
