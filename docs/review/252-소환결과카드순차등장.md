## 1. 등재문의 의심 3곳은 **전부 빗나갔다** (오등재 정정)

등재문(PROGRESS 252)은 원인을 60 쥬시의 `jzStagger` 로 좁히고 세 갈래를 지목했다 —
① 그리드 탐지가 className 완전 일치라 등급색 때문에 못 알아본다 · ② `Math.min(kids.length, 20)`
상한 · ③ `kids` 를 DOM 순으로 도는데 배열을 정렬해 꽂는다.

**셋 다 아니다.**

- ① **그리드 탐지는 정상 작동한다.** 12 결과 카드의 `className` 은 등급과 무관하게 전부
  `"sm-c ifr fx-pop"` 이다 — 등급색은 `class` 가 아니라 **인라인 CSS 변수**(`--face`/`--rim`)로 들어간다
  (`showSummonResult()` ~19594). 실측: `jzStagger` 가 이 그리드를 **찾아내서** `--jzd` 를
  `60ms,85ms,…,285ms` 로 전 칸에 박는다(probe252 [A], 수정 전).
- ② 상한 20 은 도달하지 않는다. 같은 아이템은 개수로 합쳐지므로(`agg`) 30연이어도 칸 수는 종 수만큼이다.
- ③ `jzStagGo` 는 DOM 순으로 돈다. 어긋난 것은 그쪽이 아니라 **12 자신의 인라인 delay** 였다.

> **★ 첫 probe 가 «`--jzd` 전 칸 공백» 을 찍어 ①②③ 을 한 번에 반증한 줄 알았다 — 그게 틀렸다.**
> 선언값을 `showSummonResult()` **직후**에 읽었기 때문이다. `jzStagger` 는 `#sumw` 의 `.on` 을
> MutationObserver 가 본 **뒤**에 도는 비동기라, 그 시점엔 아직 아무것도 안 붙어 있다.
> 표본을 창 전체로 넓히자 `--jzd` 가 나타났다. → 게이트 [D2] 는 **한 시점이 아니라 60표본 전부**에서
> `.jz-st` 부착 프레임 수를 센다. (LESSONS 221-① «게이트가 빨간 이유는 재는 법이 틀렸다도 있다» 의
> 반대 방향 사고 — **초록인 이유가 «너무 일찍 재서» 일 수 있다.**)

## 2. 진짜 원인은 두 겹이고, 둘 다 «순서» 가 아니라 «누가 그 칸의 등장을 소유하는가» 다

### 갈래 A — 지연이 **DOM 순이 아니라 등급 순**으로 매겨져 있었다 (58 의 설계)

`showSummonResult()` 옛 코드:

```js
/* 58 — «카드가 등급 순으로 순차 팝». DOM 순서(=레이아웃)는 12 규격 그대로 두고
   animation-delay 만 등급 오름차순으로 매겨 낮은 등급부터 터지게 한다. */
const dly = new Array(agg.length).fill(0);
agg.map((a, i) => ({ i, g:a.it.g })).sort((x, y) => x.g - y.g || x.i - y.i)
   .forEach((o, k) => { dly[o.i] = k * 0.055; });
```

DOM 순서(=그리드에서의 자리)는 뽑은 순서 그대로 두고 **지연만** 등급으로 매기면, 화면에서는
칸이 제자리를 건너뛰며 튄다. 실측(probe252 [C], 수정 전):

| | 값 |
|---|---|
| delay(DOM 순) | `0.000 0.055 0.110 0.275 0.165 0.330 0.385 0.220 0.440 0.495` |
| 등장 순서(i) | `0,1,2,4,7,3,5,6,8,9` |
| **등급 오름차순 i** | `0,1,2,4,7,3,5,6,8,9` ← **정확히 일치** |
| DOM 순서와 일치? | **아니오** |

주인이 본 «랜덤처럼» 의 절반이 이것이다. 58 의 의도(«좋은 게 마지막에») 자체는 말이 되지만,
**주인 보고가 그 설계를 뒤집는다** — «첫 장부터 … 순차 등장해야».

### 갈래 B — `jzStagger` 가 카드의 등장 연출을 **중간에 빼앗았다가 돌려줘서, 같은 카드가 두 번 등장했다**

이게 더 큰 결함이고 등재문에 없던 것이다. 한 요소에 등장 애니메이션이 **둘** 걸려 있었다:

- `.fx-pop{animation:fxPop .34s cubic-bezier(.34,1.56,.64,1) both}` (line 3327, 12 자신의 연출)
- `.jz-st{animation:jzSt .2s linear both;animation-delay:var(--jzd,0ms)}` (line 10479, 60 공용 스태거)

둘 다 `animation` 단축 속성이고 특이도가 같으므로 **문서 뒤에 있는 `.jz-st` 가 이긴다.**
`jzStagLife` 가 수명이 다해 클래스를 떼면 **다시 `fxPop` 이 이기는데, 그때 애니메이션이 처음부터 새로 시작된다.**

카드 0 의 실측 시간축(수정 전):

| t(ms) | animation-name | transform | scale | className |
|---|---|---|---|---|
| 0 | `fxPop` | `matrix(0,0,0,0,0,0)` (=scale 0) | none | `sm-c ifr fx-pop` |
| 133 | **`jzSt`** | **`none`** | 0.94 | `sm-c ifr fx-pop jz-st` |
| 301 | `jzSt` | `none` | 0.962 | … |
| 474 | `jzSt` | `none` | 1.005 | … |
| **551** | **`fxPop`** | **`matrix(0,0,0,0,0,0)` (=scale 0 — 다시 사라진다)** | none | `sm-c ifr fx-pop` |

즉 화면에 실제로 보인 곡선은 12 가 의도한 `fxPop`(0 → 1.2 → 1, «작았다가 커진다»)이 **아니라**
`jzSt`(0.94 → 1.02 → 1, 거의 안 움직인다)였고, 그 뒤에 카드가 **한 번 더** 0 에서 튀어나왔다.
게이트 [D2b] 로 세니 수정 전 트리에서 **10칸 전부**가 «나타났다 사라졌다 다시 나타난다».
주인 보고의 «첫 장부터 작았다가 커지며» 가 안 보였던 이유가 이것이다.

## 3. 고친 것 (`index.html` 3곳)

① **상수 분리** — `const SUM_POP_STEP = 0.055;` (58 이 리터럴로 박아 둔 값을 **값 변경 없이** 이름만 붙였다).

② **지연을 DOM 순서 = 뽑은 순서로** (`showSummonResult`):

```js
const dly = agg.map((_, i) => i * SUM_POP_STEP);
```

곡선(`fxPop`)도 칸당 간격(0.055s)도 58 것을 그대로 쓴다. **10칸 마지막 카드 지연은 0.495s 로 수정 전과
정확히 같다** — 총 길이가 안 변하므로 `verify12`·`verify84` 의 픽셀 회귀가 보존된다(게이트 [E1]).

③ **`jzStagger` 가 «자기 등장 연출을 이미 가진 그리드» 를 건너뛴다** (공용 모듈, 한 줄):

```js
if(!kids[0].classList.contains('fx-pop')) jzStagGo(kids, Math.min(kids.length, 20));
continue;
```

`fx-pop` 은 이 저장소에서 «내 등장은 내가 건다» 는 표시다. **파급 범위는 12 하나**로 확인했다 —
`fx-pop` 을 마크업에 박는 그리드는 `#sumGridIn`(19594) 뿐이고, 나머지 쓰임(`fxPop(el)` ~27174)은
전부 «동작에 반응해 단일 요소를 튀긴다» 라서 팝업이 열리는 시점에는 클래스가 붙어 있지 않다.
`.jz-st` 를 **탐지 단계에서** 막았으므로 «붙였다 떼는» 왕복 자체가 사라진다(게이트 [D2]: `jz-st` 프레임 0/60).

> **손대지 않은 것**: 58 이 «낮은 등급부터 터지게» 하려던 의도는 되살리지 않았다. 되살리려면
> DOM 순서 자체를 등급순으로 꽂아야 하는데, 그건 12 그리드의 **칸 색 배치**를 바꿔
> `verify12`·`verify84` 픽셀 회귀와 12 측정표 §4 를 정면으로 깬다 — 그리고 주인 지시가
> «첫 장부터 순차» 이므로 애초에 되살릴 대상이 아니다.

## 6. 교훈 (LESSONS 반영분)

1. **«한 요소에 등장 애니메이션 2개» 는 «둘이 섞인다» 가 아니라 «하나가 이겼다가, 놓는 순간 다른 하나가
   처음부터 다시 시작한다» 로 나타난다.** 둘 다 `animation` 단축 속성이면 문서 뒤가 이기고,
   이긴 쪽이 클래스 수명으로 떨어질 때 진 쪽이 **새 애니메이션으로 등록**된다 — 그래서 증상이
   «느낌이 이상하다» 가 아니라 **«같은 카드가 두 번 등장한다»** 라는 눈에 띄는 형태가 된다.
   공용 등장 모듈은 «이 요소가 이미 자기 등장을 갖고 있나» 를 **부착 전에** 물어야 한다.
2. **게이트가 초록인 이유가 «너무 일찍 재서» 일 수 있다.** 비동기로 붙는 클래스는 한 시점 스냅샷으로
   재면 영원히 «없음» 이다. 부착·탈착이 있는 것은 **창 전체의 프레임 수**로 세라.
   같은 함정이 [C3] 에도 있었다 — 선언값 수집(`petPaint` 캔버스 10장)이 380ms 를 먹어 첫 표본이
   그만큼 늦게 찍혔고, 그 사이 이미 등장한 앞 칸 4개가 «같은 t» 로 뭉쳐 간격이 335ms 로 **잘려 보였다.**
   판정선을 늘리는 대신 **표본 채취를 맨 앞으로 옮기고**, 그 사실을 [C0] 이 상시 감시하게 했다.
3. **«순서» 버그는 지연값이 아니라 «지연 순서 ≟ DOM 순서» 로 재라.** 값만 보면 `0.055` 간격이
   가지런해서 정상으로 읽힌다 — 어긋난 것은 그 값이 **어느 칸에** 갔느냐다.
   그래서 게이트 [B2] 가 «등급순과 DOM순이 서로 다른 표본인가» 를 먼저 확인한다(구분력 확보).
