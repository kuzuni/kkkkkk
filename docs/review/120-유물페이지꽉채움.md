## 1. 문제 — 100 이 남겨 둔 «검은 띠»

100 은 «패널이 탭바를 덮어 탭이 안 눌리는» 버그를 **균일 축소**(`scale(--rws)`)로 막았다. 그건 맞는 처방이었지만
패널 자체는 여전히 **레퍼런스 크롭 그대로의 절대 1080×1527** 이었고, `#relw` 영역은 `frameH − 284` 로 가변이다.
기준 해상도 2280 에서 실측:

| 구간 | 프레임 y | 높이 | 내용 |
|---|---|---|---|
| 재화 바 | 0 ~ 108 | 108 | 41 `.pcb` (정상) |
| **검정** | **108 ~ 370** | **262** | `#relw{background:#0A0F14}` 노출 |
| 패널 | 370 ~ 1897 | 1527 | `.rw-panel` |
| **검정** | **1897 ~ 2100** | **203** | `#relw` 노출 |
| 탭바 | 2100 ~ 2280 | 180 | (정상) |

→ 영역 1992px 중 **465px(23.3%)이 검정**. 짧은 프레임에서는 축소까지 겹쳐 좌우에도 여백이 생겼다.

## 2. 수정 — 패널을 «영역» 에 앵커한다

### 2-1. 껍데기

```
.rw-panel{position:absolute;left:0;right:0;top:4px;bottom:0;overflow:hidden}
```

`#relw` 는 `top:104/bottom:180` 이고 41 재화 바 `.pcb` 가 프레임 y0~108 을 덮으므로 **`top:4` = 프레임 y108** 이다
(바 바로 아래). `bottom:0` = 탭바 상변. 9:19 에서 **1080×1992**, 다른 화면비에서는 가용 높이 전부.
`.rw-bg`(inset 0) · `.rw-frame`(inset 2) · `.rw-fc`(bottom 3) 는 손댈 필요가 없었다 — 패널이 커지면 따라 커진다.

`#relw` 자체 배경도 `#0A0F14` → `#0D100D`(석벽 톤)로 바꿨다. 패널이 100% 덮으므로 원래 안 보이지만,
전환 프레임에서도 «검정» 이 안 보이게 한다.

### 2-2. 배경 — px 정지점을 % 로 환산

패널이 1527 → 1992 로 늘어나는데 바닥 그라디언트가 px 로 박혀 있으면 **바닥선이 수반보다 훨씬 위에 남는다**.
1527 대비 %로 환산했다:

| 레이어 | 구 | 신 |
|---|---|---|
| 바닥 그라디언트 정지점 | 980 / 1120 / 1400 / 1491 px | 64.178% / 73.347% / 91.683% / 97.642% |
| 석벽 질감 `.rw-bg::before` | `height:1050px` | `height:68.762%` |
| 중앙 아치 `.rw-bg::after` | `top:133px · height:889px` | `top:8.709% · height:58.219%` (가로 589 는 1:1 고정) |

**수반 난색 글로우**(구 `.rw-bg` 1번 레이어 `radial 40%×18% at 50% 88%`)만은 %로 두면 수반과 어긋난다 —
수반의 세로 위치가 «% 고정» 이 아니라 «여백 배분» 으로 정해지기 때문이다. 그래서 **`.rw-mid::before` 로 이관**했다
(864×550 = 구 rx432·ry275, 수반 기준 중심 200,171 = 구 540,1344 − 수반 340,1173). 이제 글로우가 수반을 따라간다.

### 2-3. 내용 — 세로 3구획 + 여백 비율 배분

| 구획 | 요소 | 고정 높이 |
|---|---|---|
| 상 `.rw-grid` | 슬롯 10칸 (3·4·3) | **516** = 3행(피치 176/175, 슬롯 151 → 502) + Lv 라벨 하단 돌출 14 |
| 중 `.rw-mid` | 돌 수반 + 코스트 알약 | **216** (수반 캔버스. 알약 하변 202 < 216) |
| 하 `.rw-cap` | 안내문 2줄 | **88** (line-height 44 × 2) |
| | | **합 820** |

남는 높이 `--rw-sp = 100% − 820px × --rwc` 를 **레퍼런스의 여백 비율 그대로** 네 곳에 나눈다
(ref 1527 기준: 상 320 : 격자↔수반 337 : 수반↔안내문 23 : 하 27 = **707**):

```
.rw-grid{top:calc(var(--rw-sp) * .452617)}
.rw-mid {top:calc(var(--rw-sp) * .929279 + 516px * var(--rwc,1))}
.rw-cap {top:calc(var(--rw-sp) * .961811 + 732px * var(--rwc,1))}
```

실측 여백(상 / 격자↔수반 / 수반↔안내문 / 하):

| frameH | 패널 | 여백 | `--rwc` |
|---|---|---|---|
| 1600 | 1080×1312 | 223 / 234 / 16 / 19 | 1 |
| 1920 | 1080×1632 | 368 / 387 / 26 / 31 | 1 |
| **2280** | **1080×1992** | **530 / 559 / 38 / 45** | 1 |
| 2600 | 1080×2312 | 675 / 711 / 49 / 57 | 1 |

→ **가용이 짧아지면 여백부터, 그것도 네 곳이 같은 비율로 줄어든다.** 내용 픽셀은 안 줄어든다.
내용 총합 820 보다도 가용이 짧아지는 극단에서만 `rwFit()` 이 `--rwc` < 1 로 내용을 균일 축소한다.
지원 범위(frameH 1600~2600 → 가용 1312~2312)에서는 **항상 정확히 1** 이라 ROUTINE [2] 의 «scale 래퍼 금지» 에
걸리지 않는다 — 100 이 남긴 것과 같은 성격의 최후 안전망이다.

### 2-4. 좌표 재기준 (89 규격은 불변)

| 값 | 구 (패널 기준) | 신 |
|---|---|---|
| `RW_POS` 행 y | 320 / 496 / 671 | **0 / 176 / 351** (`.rw-grid` 기준. 피치 176/175 그대로) |

| `.rw-cost` | `401,1322` | `.rw-mid` 기준 `61,149` (상대 위치 불변) |

슬롯 151×151 · 수반 400×216 · 코스트 278×53 · 가로 중심 540 은 **전 프레임 높이에서 Δ0** (게이트 ⑦).

### 2-5. 폐기

`RW_PANEL_TOP`·`RW_PANEL_H`·`--rws` 는 사라졌다. `rwFit()` 은 `--rwc`(내용 축소) 하나만 갱신한다.
`#relw{overflow:visible}` 은 **그대로 둔다** — 41 재화 바 `.pcb` 가 `top:-104px` 로 `#relw` 밖에 얹혀 있어
`hidden` 이면 통째로 잘린다(100 의 교훈 3).

## 3. 게이트

### `tools/verify120.js` — 신설 (68 항목, 4개 프레임 높이)

① 패널 = 영역 전체 · ② 배경/프레임/코너가 가장자리 앵커 · **③ «패널이 못 덮은 픽셀» 0** ·
④ 3구획 상호 겹침 0(코스트는 수반 구획 안) · ⑤ 잘림 0 · ⑥ 여백 4곳 양수 + 레퍼런스 비율 ·
⑦ 89 규격 불변 · ⑧ 탭바 25점 히트테스트.

> **③ 을 «`#0A0F14` ±4 픽셀 세기» 로 하면 안 된다.** 지시서 검증절이 그렇게 적혀 있지만, 석벽 최상단이
> `#090C10` 이라 (1,3,4) 차이로 **±4 안에 들어온다** — 멀쩡한 배경이 «검은 띠» 로 잡힌다.
> 대신 `#relw` **배경만** 센티넬 `#FF00FF` 로 바꾸고 «영역 안에 그 색이 한 픽셀이라도 보이면 FAIL» 로 했다.
> «패널이 못 덮은 자리» 를 색으로 직접 잡는 것이라 오탐·미탐이 둘 다 없다.

**음성 대조**: `.rw-panel` 을 `top:266px;bottom:200px` 로 되돌려 주입 → ①③ 이 4개 높이 전부 FAIL
(`60/68`, 노출 픽셀 486,000~498,960). 원복 확인.

### `tools/verify100.js` — ③ 교체

«스케일 = min(1, avail/1527)» · «패널 1080×1527 @y370» 회귀 검사는 120 이후 참이 아니라 폐기하고,
**«패널 = 영역 전체» + «--rwc = 1» + «수반 400×216 · 슬롯 151²·피치 176/175 불변»** 으로 갈아끼웠다.
탭바 비가림(①②④⑤⑥)은 그대로다. 높이 목록에 **2600**(clamp 상한)을 추가했다.

> 이때 «행 피치 176» 으로 게이트를 걸었더니 FAIL 이 났다 — 원본 `RW_POS` 가 320/496/671 이라
> 실제 피치는 **176/175** 다(측정표의 «176» 은 79×2.2222=175.55 의 반올림). 코드가 아니라

«같은 아치가 긴 화면에서 16% 더 홀쭉해진다.» 이건 1회차 % 환산의 진짜 설계 결함이었다.

### 2회차 — 캡처 `120-r2-{1600,1920,2280,2600}.png`

**고친 것 4건**

1. **아치를 «패널의 %» 에서 «슬롯 격자 ± 186» 으로 재정의.**
   레퍼런스가 아치 133~1022 · 격자 320~836 이라 **아치 = 격자 상하 186** 이다. 이 관계로 바꾸면
   아치는 어느 프레임에서도 **589×888(ref 종횡비 1:1.51 그대로)** 이고 격자를 따라 움직인다.
   ```
   top:calc(var(--rw-sp) * .452617 - 186px * var(--rwc,1));  height:calc(888px * var(--rwc,1))
   ```
   → 아치 세로는 프레임 높이와 **무관**해졌다(2280·2600·1600 전부 888).
2. **아치 내부 단색 → 세로 명암 5단 + 얼룩 3개 + 하단 8% 알파 소멸.**
3. **아치 하변 수평 절단선 제거** — 아래 §5 참조(box-shadow → drop-shadow).
4. **바닥 68~99% 대역에 결 9겹.** 석벽 얼룩(`.rw-bg::before`)이 상단 68.762% 만 덮어 바닥에는
   결이 하나도 없었다. 최하단 청흑 띠까지 포함해 깔았다.

| 지표 | 1회차 | **3회차(정지 캡처)** |

| 아치 행별 고유색 (최소) | 1 | **23~25** |
| 아치 행평균 휘도 진폭 | 0 | **75.4** (14.3 → 89.7) |

> 2회차 캡처의 스캐너 수치(아치 최소 3 · 바닥 최소 34 · 하변 0.3)는 **믿을 수 없다** — 아래 §4-3 의
> 애니메이션 중간 프레임에서 잰 값이다. 위 표는 3회차의 «정지 확인된» 캡처로 다시 잰 것이다.

**반증해 미채택한 지적**

- **G ③ «하단 블록 내부 간격만 배율이 튄다»(수반↔안내문 47px, 안내문↔하단 50px)** — 잉크 기준으로 잰 것이다.
  안내문은 `line-height:44` 라 잉크(≈30)와 라인박스 사이에 상하 7px 씩 half-leading 이 있다.
  **라인박스 기준 여백은 네 곳이 정확히 같은 배수**다(게이트 ⑥ 실측 Δ0.01: 530.5/558.7/38.1/44.8 vs 기대 530.5/558.6/38.1/44.8).
  ref 잉크 기준으로 환산해도 «안내문 잉크 하변 → 패널 하변» 은 ref 34 ×1.658 = 56 인데 우리는 50 으로
  오히려 **더 좁다.** G 가 쓴 «환산 24px» 은 배율을 안 곱한 값이다.
- **H ① «아치 폭이 ref 487 인데 우리는 589 (+21%)»** — 측정표 §측정 표가 ref 265 ×2.2222 = **589** 로 확정한 값이고,
  G 는 아치 폭을 감점 사유로 들지 않았다. 저해상(486×687) 레퍼런스의 아치 에지는 비평가 실측으로 수렴하지 않는다
  (LESSONS 89-①). **3회차 비평 프롬프트에 «선확정 — 재측정 금지» 로 박았다.**
- **G ② / H ②-3 «코스트 알약이 8~11% 납작하다»** — 두 비평가의 ref 실측이 269×49 / 269×52 로 서로 다르고,
  측정표 확정치는 **262×51** 이다. 우리는 278×53 으로 종횡비 차 **2%** 다(89 가 이 값으로 ①~④ 8 을 통과했다).
  같은 이유로 선확정에 박았다.
- **H ③·④ «슬롯 간극 95/98 비대칭 → 97/97 로»** — `RW_POS` x 는 ref 97·208·320 ×2.2222 를 반올림한 값이라
  **간극 95.5/97.8 은 레퍼런스 자체의 성질**이다. 97/97 로 만들면 ref 에서 멀어진다. 선확정에 박았다.
- **H ⑤-4 «금테 안쪽 2px 검은 틈»** — 89 설계의 «검정 + 갈색 2겹 프레임»(`.rw-frame` 의 `inset 0 0 0 2px`)이다.
  120 구간이 아니고 의도된 림이다. 선확정에 박았다.

### 3회차 — ★ 2회차 비평(I 2 / J 2)은 **캡처 결함**이었다

I·J 는 독립적으로 **같은 것을 같은 방향으로** 보고했다. 보통은 «둘이 몰리면 움직인다»(LESSONS 52-④)가
맞지만, 이번 보고는 **DOM 게이트와 정면으로 충돌**했다:
