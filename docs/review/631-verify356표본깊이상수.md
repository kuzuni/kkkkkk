## 4. 잰 값·함정 넷

① **비용은 문제가 아니었다** — 표본을 파는 데 `.git` +6MB · 2.2~3.6s(240s 예산의 1.2%). 26회차가 잰 +7MB 와 같은 급이다.

② **⚠ `--shallow-since` 의 비용은 «표본의 나이» 에 비례한다.** 판 것은 **날짜 이후 전부**라
   실측 약 40KB/커밋 · 24ms/커밋(depth 1 → 149커밋에서 6MB · 3.6s)이다. 이 속도(시간당 26커밋)면
   240s 예산에 닿는 것은 표본이 **약 2주** 나이일 때다. ⇒ 그때 할 일은 **깊이를 줄이는 것이 아니라
   표본을 옮기는 것**이다(`PRE_REV` 와 `PRE_DATE` 를 **같이**). 어느 축으로 재도 «K커밋 뒤의 커밋을
   가져오려면 K커밋을 받아야» 하므로 ⓐ·ⓒ 도 같은 값을 치른다 — ⓑ 만의 값이 아니다.

③ **⚠ 부모가 표본보다 «나중» 이다** — `319277e` 01:09:45Z · 그 부모 `25c21c2` 01:31:49Z.
   리베이스가 도는 저장소라 커밋 날짜가 이력 방향으로 단조롭지 않다. ⇒ `PRE_DATE` 는
   **표본과 부모 둘 다보다 앞서야** 하고(여유 2시간), `verify631` B6 이 그 두 값을 실제로 읽어 단언한다.

④ **⚠ 일회용 클론에는 `node_modules` 가 없다** — `probe356r23` 는 모듈 머리에서 playwright 를 문다
   (`digPre` 자신은 git 만 쓴다). `verify631` 은 자식 프로세스에 이 저장소의 `node_modules` 를 `NODE_PATH` 로
   빌려 준다. 1회차에 이걸 안 줘서 6건이 «playwright 없음» 으로 빨갰다 — **자의 편의일 뿐 축이 아니다.**

⑤ **⚠ `git show` 를 파이프로 받으면 잘린다** — `spawnSync` 기본 `maxBuffer` 가 1MiB 라 3.2MiB 짜리
   `index.html` 이 0.7MiB 로 읽혀 B4 가 거짓 빨강이었다. 크기는 `git cat-file -s` 로 묻고
   실행은 출력을 버리고 **종료 코드만** 본다.
