## 1. 실측 — 무엇이 결손이었나

착수 전 현행을 그대로 읽었다.

| 칸 | 코드 | 상태 |
|---|---|---|
| ① 사이드 «룰렛» 아이콘 | `sideAlert('roul', S.daily.spins > 0)` (drawHud ~20618) | **정상** — `.ibtn[data-pop="roul"].on > .bdg` 점등 |

즉 **318(출석)·293(우편)과 똑같은 «경로가 한 칸 짧다»** 다. 판정식은 이미 맞는데
경로가 진입 버튼에서 끊긴다 — 그리고 팝업을 여는 순간 딤(`#modal` z30)이 사이드(z3)를 덮으므로
**정확히 «돌리려고 팝업을 연 순간» 신호가 화면에서 사라진다.**

게이트로 이 전제를 화면 좌표로 못 박았다(`verify321` [2]): 팝업을 연 뒤 사이드 배지 중심에서
`elementFromPoint` → **`#modal`**. 배지는 살아 있지만 보이지 않는다는 이진 사실이다.

## 2. 처방 — 판정식은 새로 만들지 않는다

166 규약 그대로 **부품은 `<s class="updot">` 하나 · 점등은 호스트 `.alert`**.
판정은 이미 있는 `S.daily.spins > 0` 을 그대로 쓴다(새 조건 함수를 만들지 않았다).

### ⓐ 마크업 (`openRoulette`)
```
+ '<button class="ifbtn pbtn" id="rouBtn"' + (…disabled) + '><b>' + 라벨 + '</b>'
+ '<s class="updot"></s></button>';
```
**`<b>` 뒤(형제)** 에 붙인 것이 요점이다 — 267 규약이 «라벨은 `<b>` 안» 이라
라벨 안에 넣으면 규격이 통째로 깨진다. 게이트 [4] 가 `b .updot` **부재**를 단언한다.

### ⓑ 위치 CSS — 새 좌표를 발명하지 않았다
```
.ifbtn.pbtn>.updot{right:12px;top:12px}
```
`.pbtn` 은 h130·border 7px 로 **`.sk-btn`(275×131, border 7)과 규격이 사실상 같고**,
그 자리는 283 이 이미 `right:12/top:12` 로 정해 뒀다 — 같은 모양의 호스트에는 같은 좌표를 쓴다.
라벨 `<b>` 는 flex 로 가운데 한 줄이라 안쪽 우상단이 통째로 비어 있다.
절대배치 기준은 **padding box** 이므로 12px 은 검정 테두리 «안쪽» 12px 이고,
외곽 링(±7.5)까지 4.5px 여유로 안 잘린다(`.ifbtn` 에 `overflow` 없음).
실측: 버튼 820×130 · 중심 **(787.5, 32.5)** → 299 «우상단 사분면» 충족 · 4변 전부 상자 안.

### ⓒ 켜고 끄는 곳은 한 곳뿐
```
function rouBtnDot(){ const b = $('rouBtn');
  if(b) b.classList.toggle('alert', S.daily.spins > 0 && !rouSpinning); }
```
부르는 곳 3개 — `openRoulette`(열자마자) · `roulSpinTo`(회전 시작 = 소등) ·
`roulFinish`(라벨이 «내일 다시 충전됩니다» 로 바뀌는 그 경로).

**회전 중 소등을 넣은 이유**는 두 가지다. ⓘ 그 동안 버튼은 `disabled` + `#modal.rou-spin .ifbtn
{pointer-events:none}`(267) 라 **누를 수 없다** — 레드닷은 «지금 누를 수 있다» 는 신호이므로
그때 켜 두면 거짓말이 된다. ⓘⓘ 60 쥬시 등장·맥박 애니(`.alert>.updot`, ~11000)가
`#modal.rou-spin … *{animation-name:none}`(65) 에 걸려 반쪽으로 죽는다.

### ⓓ 곁다리 1줄 — `rouBtnTx` 를 `querySelector('b')` 로
```
- const b = btn.firstElementChild;
+ const b = btn.querySelector('b') || btn.firstElementChild;
```
지금은 `<b>` 가 여전히 첫 자식이라 **동작상 차이가 없다**. 다음 사람이 배지 노드를
앞에 끼우는 순간 267 [F] 가 조용히 깨지는 것을 막는 가드다(첫 자식 = 라벨이라는 암묵 전제 제거).

## 3. 게이트 — `tools/verify321.js` 신설 (32/32 PASS)

`verify318` 과 같은 골격이다. 판정은 **«논리(class·computed display)» 와 «화소(배지 bbox 안
빨강 수)» 를 같이** 본다(292 «열렸는가 ≠ 보이는가» · 189-③ 헛초록 처방). 클릭은 전부 진짜 포인터.

| [2] | 팝업을 열면 사이드 배지가 딤 아래로 사라진다 (결손의 근거) | `elementFromPoint` = **#modal** |
| [3] | 버튼 `.alert` · 닷 1개 · **실제로 누를 수 있다** · 화소 | 빨강 **668**화소 |
| [4] | 267 회귀 — 배지는 `<b>` 의 **형제** · 라벨 46.6px 유지 | 첫자식 B · `b .updot` 0 · fs **46.6** |
| [5] | 299 규약 — 우상단 사분면 · 4변 안 잘림 | cx **787.5**/820 · cy **32.5**/130 |
| [6] | 166 호스트 감사 — `.alert` 떼면 `none`, 붙이면 `block` | none → block |
| [7] | **회전 중 소등** (논리·화소 둘 다) + 라벨 46.6px 유지 | `display:none` · 빨강 **0** |

## 5. 남기는 것

- **«경로가 한 칸 짧다» 는 이제 계열이다** — 293(우편) · 294(상점) · 301(패스) · 318(출석) · 321(룰렛).
  전부 «판정은 맞는데 진입 버튼에서 끊기고, 팝업 딤이 그 진입 버튼을 덮는다» 는 같은 모양이다.
  남은 같은 계열(322·323·325·328·329·330)도 **판정식을 새로 만들지 말고 경로만 이으면 된다.**
- **레드닷은 «지금 누를 수 있다» 는 약속이다.** 버튼이 `disabled`·`pointer-events:none` 인 구간
  (여기서는 회전 중)에는 반드시 같이 꺼라 — 안 그러면 배지가 거짓말을 한다.
  게이트에 «켜짐» 만 넣으면 이 거짓말이 초록으로 통과한다([7] 이 그 축이다).
- **호스트 규격이 같으면 좌표도 같은 것을 쓴다.** `.pbtn`(h130/bw7) ↔ `.sk-btn`(h131/bw7) —
  새 좌표를 발명할수록 299 «우상단» 규약을 어길 자리가 늘어난다.
- ⚠ **이 버튼에 배지를 더 달거나 라벨 구조를 바꾸면** `tools/verify321.js` ·
  `verify267.js` [F] · `verify299.js` 호스트 목록을 같이 고칠 것.
