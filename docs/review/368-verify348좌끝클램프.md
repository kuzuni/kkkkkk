## 1. 착수 전에 재현했다 (338·341·350 규칙)

## 2. 처방 — 자리를 상수에서 빼고 **제품에게 묻는다**

LESSONS 328·343 대로 **묻는 것은 그대로 두고 자리만** 옮겼다. [3-b] 가 묻는 것은 여전히
«좌측 끝 적의 바가 사이드 아이콘 열 밖으로 밀려 있는가»(13회차 규약)이고, 바뀐 것은 그 «좌측 끝» 을
**`sideBox` 에서 만든다**는 것뿐이다. 바 상변은 발밑에서 `e.r*3.1 + 6` 위 — **그리기와 같은 식**을 쓴다.

새 도우미 `shotBand(ev, sx, mode, pad, tk, rgb)`:
- `mode:'mid'` — 띠 «안» 자리(양성항)
- `mode:'below'` — 띠 아래 `pad`px(음성항)

이제 360 같은 레이아웃 변경이 또 와도 게이트가 **따라간다.**

### ⚠ 두 번째 함정 — 비네트가 «찍힌 픽셀» 자의 눈을 멀게 한다

처음엔 표본 행을 «띠 세로 한복판»(232)으로 잡았는데, **되돌림 시험 §R2 가 «바가 아예 없다»(0px)** 로 나왔다.
클램프를 뺐으니 바는 x 11.5 에 그려져 있어야 하는데 표본이 0 이었다 — 재현으로 갈랐다:

- draw() 맨 끝의 **비네트**(`createRadialGradient(VW/2, VH/2, VH*0.34, …)`, index.html ~21012)가 화면 전체를 덮는다.
- 캔버스 중심에서 **VH·0.34 ≈ 339px 밖**의 바는 색이 살짝 어두워진다 — `#ff6b8a` → **249,104,135**.
- 350 의 «찍힌 픽셀» 자는 **정확한 색**을 세므로, 어두워진 바는 **0개**로 읽힌다.
- 띠 한복판(232)은 클램프 **뒤** 자리(x 78.5, 거리 328)는 안쪽인데 클램프 **전** 자리(x 22, 거리 **364**)는 **바깥**이다.
  = 양성항은 보이는데 음성항만 안 보이는, 가장 헷갈리는 모양이었다.

⇒ 표본 행을 **«띠 안에서 캔버스 세로 중심에 가장 가까운 행»** 으로 바꿨다
(`Math.max(sb.y1+8, Math.min(sb.y2-8, VH/2))` = 지금 **420** · 중심거리 260 < 339 = 비네트 안쪽).
상수를 새로 안 만들었고, 띠가 또 움직여도 «가장 옅은 자리» 라는 뜻이 그대로 따라간다.
이 대조는 `probe368` §4 에 표로 남겼다 — **다음에 캔버스 픽셀을 읽는 게이트가 같은 자리에서 걸린다.**

## 3. 무르게 푼 수리가 아니라는 증명 (334·361 규칙)

자리를 옮겨 초록을 만든 수리는 «자리를 옮겨 **아무것도 안 묻게**» 되기 쉽다. 세 겹으로 못박았다.

| 항 | 무엇을 막는가 | 실측 |
|---|---|---|
| **[전제 3-b]** 신설 | 표본이 띠 **밖**이면 [3-b] 는 아무것도 안 묻는다 → 그 상태를 **빨갛게** | 바 상변 **420.0** ∈ 36.0..428.0 ✓ |
| **[3-d]** 음성항 신설 | 클램프가 «상수 24» 가 아니라 **띠**를 재는지 | 띠 아래(488)에서 좌변 **24.0** ✓ |
| **§R2** 되돌림 시험 신설 | [3-b] 가 **클램프에 매여 있는지** | 클램프 뺀 사본 좌변 **11.5 < 72.5** = 열 위를 덮는다 ✓ |

§R2 는 `const bx = fxClampX(e.x, w/2, by) - w/2;` 를 `const bx = e.x - w/2;` 로 바꾼 사본을 띄운다

**허용 오차는 한 칸도 안 넓혔다** — [3-b] 의 술어(`x0 >= sideBox.x2`)는 글자 그대로 그대로다.
