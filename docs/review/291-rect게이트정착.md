## 1회차 — 재현 → 처방 → 회귀

### 1. 먼저 «부하를 걸고 재현» 했다 (등재문이 못 박은 순서)

등재문(PROGRESS 291)이 «재현 없이 44개를 일괄 수정하면 되돌림 불가능한 변경이 된다» 고 적어 두었다.
그래서 **게이트가 빨개지나** 를 보지 않았다 — 그건 단언 허용오차에 가려진다(실제로 1순위 `verify22` 는
CPU 버너 6개를 걸고 3회를 돌려도 **65/65 로 요지부동**이었다). 대신 **병 자체**를 직접 쟀다:

> 고정 대기(`waitForTimeout`)가 끝난 **그 프레임**에서
> ① `jzPg…`·`jzSheet…` 가 아직 돌고 있나 ② 그래서 rect 가 얼마나 밀려 있나

를 재는 도구를 새로 만들었다 — **`tools/repro291.js`**. 44개 게이트의 공통 지문
(`goto → 부트 대기 → 여는 동작 → 고정 대기 → rect`)을 그대로 흉내내고, 마지막 고정 대기 뒤에 probe 를 넣는다.

| 조건 | 연출 한복판에서 잰 횟수 |
|---|---|
| 한가한 러너 (`--runs 3`) | **1 / 12** |
| 부하 (`--runs 3 --parallel 3 --load 6`) | **24 / 36** |

그리고 그때 잡히는 오차는 **47 §221 이 적어 둔 것과 글자 그대로 같은 지문**이었다 —

```
⚠ 연출 중 r1-1 adv  진행중 1 0%   · scale 0.9850 · x 8.1 w 1063.8  → 좌변 오차 8.22px
⚠ 연출 중 r2-2 adv  진행중 1 42%  · scale 0.9939 · x 3.3 w 1073.4  → 좌변 오차 3.34px
```

`jzPgIn` 0% 프레임의 scale 은 **.985**, rect.x 는 화면 절대 좌표라
`x' = 540 + (x−540)·s` → 좌변이 `540·(1/s−1)` = **8.22px** 밀리고 폭은 1080 → **1063.8**(−1.5%).
122 §17 의 «실행마다 3.8/4.0/6.1/6.2 로 흔들리던 자» 가 바로 이 값이다.

**★ 이 회차의 첫 교훈: «게이트가 초록이다» 는 «계측이 옳다» 가 아니다.**
`verify22` 는 부하에서도 65/65 였지만, 같은 부하에서 같은 지문의 계측 오차는 **24/36 회** 실재했다.
허용오차가 넓은 단언은 8.22px 을 그냥 삼킨다 — 그러다 122 §17 처럼 **좁은 단언 하나가 생기는 순간**
«실행마다 흔들리는 게이트» 로 얼굴을 내민다. 그래서 판정 도구를 «PASS/FAIL» 이 아니라
«잰 순간이 연출 도중이었나» 로 만든 것이다.

### 2. 처방 — 새로 설계하지 않았다. 47 의 것을 **한 곳**으로 올렸다

등재문이 «처방은 이미 있다(새로 설계하지 마라)» 고 못 박았다. 그대로 했다.

- **`tools/settle291.js` 신설** — 47 `verify47.js` 가 쓰던 SETTLE 을 공용 모듈로 뽑았다.
  `jzPg…`·`jzSheet…` 의 `finished` 를 기다리고 rAF 2프레임을 더 준다.
  무한 루프 연출(`jzDotPulse`·`jz122*`·`bgm*`)은 `finished` 가 영영 안 오므로 **이름으로 걸러낸다**.
- **`tools/pwlaunch.js` 의 `launch()` 가 브라우저에 그 장치를 심는다**(`armBrowser`).
  심는 자리는 **`page.waitForTimeout()` 직후 한 곳뿐**이다 — 44개 게이트의 «고정 대기» 가 전부
  그 함수를 지나가므로, **게이트 파일을 한 줄도 안 고치고 44개가 동시에 낫는다.**

**왜 «전부» 가 아니라 조건을 다나** (셋 다 실측으로 강제된 조건이다):

- ⓐ **entry 가 `verify*.js` 일 때만.** `cap*.js` 계열은 연출을 **일부러 한복판에서** 80~100ms 간격으로
  연속 캡처하는 하네스다(지시서 [3]-(다)). 거기에 정착을 걸면 찍으려던 프레임이 사라진다.
- ⓑ **250ms 이상 기다린 뒤에만.** 그보다 짧은 대기는 «프레임 하나 넘기기» 라 정착 대상이 아니다.
- ⓒ **기다릴 연출이 하나도 없으면 본체를 아예 안 돈다**(값싼 선검사). ← **이 회차의 두 번째 교훈**,
  아래 §3.
- 되돌림 스위치 **`PW_SETTLE=0`** (강제 on 은 `PW_SETTLE=1`).

미이관 게이트 6개(`verify100`·`104`·`107`·`64`·`262`·`158`)는 `chromium.launch()` 직결이라 이 장치가
안 닿았다 — `pwlaunch.launch()` 를 지나가게 **한 줄씩** 옮겼다(각자의 `launchOpts()` 는 그대로 둔다).

### 3. ★ 함정 — «정착을 걸었더니 시간을 재는 게이트가 깨졌다»

첫 판(선검사 없이 무조건 rAF 2프레임)에서 **세 게이트가 빨개졌다**:

| 게이트 | 증상 | 무엇을 재는 게이트인가 |
|---|---|---|
| `verify64` | `300ms 유지 → 1회` **Δ2** | 훈련 꾹 누르기 — «350ms 전에는 반복 없음» |
| `verify262` | 같은 Δ2 + 홀드 중 표기 불일치 | 룬 버튼 홀드 |
| `verify107` | (아래 §4 — 이건 내 탓이 아니었다) | |

원인은 단순하다. 이 게이트들의 `waitForTimeout(300)` 은 **«정착을 기다리는 대기» 가 아니라 «재고 있는 시간
그 자체»** 다. 거기에 rAF 2프레임(≈32ms, 부하에선 더)이 얹히면 300ms 홀드가 **350ms 문턱을 넘어** 반복이
한 번 더 돈다. 즉 **같은 함수(`waitForTimeout`)가 두 가지 다른 뜻으로 쓰이고 있었다.**

처방: **값싼 선검사**를 앞에 뒀다 — 기다릴 `jzPg…`·`jzSheet…` 가 **하나도 없으면 그대로 반환**한다
(evaluate 왕복 1회, rAF 0프레임). 정착이 필요한 순간은 어차피 «연출이 돌고 있을 때» 뿐이라
병은 그대로 닫히고, 시간을 재는 게이트는 원래 시간을 되찾는다. → `verify64` **41/41** · `verify262` **38/38** 복귀.

> **교훈으로 남긴다**: 공용 지점에 무언가를 얹을 때는 «그 지점이 **한 가지 뜻**으로만 쓰이는지» 를 먼저 봐라.
> `waitForTimeout` 은 이 저장소에서 «정착 대기» 이기도 하고 «측정 구간» 이기도 했다.
