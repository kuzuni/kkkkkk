> **처방**: ① `renderDunPage()` 카드 마크업에 `<s class="updot">` 형제 추가 + 호스트 `.alert` 토글 …

338 이 남긴 규칙대로 **처방을 따르기 전에 재현부터 했다**(`tools/probe341.js` 신설). 결과:

| 등재문이 주장한 것 | 실측 |
|---|---|

## §2 그러면 왜 캡처에 하나도 안 찍혔나 — 축이 하나 빠진 캡처 상태

166 이 세운 조건은 셋이다: `dunCardOk = !dunLocked(d) && S.dunTk[d.id] > 0 && cp() >= d.req(층)`.
`tools/cap72.js` 는 **해금 축과 입장권 축만** 레퍼런스와 맞춰 놓고 **전투력 축을 안 세웠다**.
부팅 직후 세이브의 `cp()` 는 **505** 이고, 해금돼 있는 두 던전의 요구는 2500·4000 이다:

| 카드 | 잠금 | 남은 횟수 | 요구 전투력 | `cp()=505` 로 점등? |
|---|---|---|---|---|
| 황금 동굴 | – | 2 | 2500 | ✗ |
| 수정 광산 | – | 2 | 4000 | ✗ |
| 고대 유적 … 룬의 제단 (6장) | 🔒 | 2 | 89345 … 536070 | ✗ (잠금) |

⇒ **8장 전부 소등이 정상인 화면**이었고, 비평가 AP·AQ 는 «켤 수 없는 상태의 화면» 을 레퍼런스와
맞대 놓고 **2인 독립으로 같은 유령**을 봤다. 이 파일 머리에 이미 답이 적혀 있었다 —
`cap72.js` 첫 주석의 **LESSONS 04-①: «캡처 상태가 레퍼런스와 같아야 그 회차 비평이 유효하다»** 를
해금 축에만 적용하고 있었던 것이다.

## §3 처방 — 상수를 박지 않고 제품에게 묻는다(336 처방)

`tools/cap72.js` 에 전투력 축을 세운다. 지갑·레벨을 큰 상수로 박으면 **326 이 훈련 상한식을 바꿨을 때
`verify324` 하네스가 통째로 부패한 것과 같은 사고**를 한 번 더 심는 것이라, 값을 역산한다:

```js
const need = DUNGEONS.filter(d => !dunLocked(d))
  .reduce((m, d) => Math.max(m, d.req(S.dun[d.id])), 0);   /* «지금 해금된 던전이 요구하는 것» */
const cap = trainCap();                                     /* 세이브로서 합법인 자리까지만 */

```

실행 결과 — **레퍼런스와 같은 그림**(카드 1·2 만 점등):


`--unlock` 에서 유물 계열이 안 켜지는 것은 **정상**이다(요구가 89345~536070 이라 훈련 상한만으로는
못 넘는다). 루프가 상한에서 멈추므로 도달 불가능한 요구치에서도 안 매달린다.
