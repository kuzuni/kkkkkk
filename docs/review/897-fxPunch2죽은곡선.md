## §1 등재문이 준 것

894 §7 이 곁다리로 넘겼다:

> `fxPunch2` 의 한 프레임 최대 이동이 진폭의 **90.4%** — `.16s` 안에
> «팝(22ms) → 고원(70ms) → 복귀(35ms) → 안착(32ms)» 을 넣어 **복귀가 두 프레임**이라
> 93 39회차가 형(`fxPunch`)에서 고친 «복귀가 한 프레임에 끝난다» 와 **같은 얼굴**인데

> ⚠ 값·수명은 93 이 소유한다 — 되돌리지 말고 **복귀에 방을 주는 쪽**으로 풀 것.

한 문장에 **셋**이 섞여 있다. ① 90.4% 라는 수치 ② «복귀가 두 프레임» 이라는 진단

## §2 재현 — 셋 중 **하나만** 참이었고, 넷째가 나왔다

### ① «90.4%» 는 **복귀가 아니라 «팝»** 이다 — `probe897` [P1]

프레임 격자는 애니 시작에 안 맞으므로 위상을 0.02ms 씩 쓸어 최악 창을 찾았다.

| 부품 | 구간 | **최악 프레임** | 그 프레임의 자리 |
|---|---|---|---|
| `fxPunch2` | 팝 22.4 → 고원 70.4 → 복귀 35.2 → 안착 32.0ms | **90.2%** | **@0.0→16.7ms = 팝** |
| `fxPunch`(형) | 팝 58.8 → 고원 117.6 → 복귀 201.6 → 안착 42.0ms | 38.9% | @0.0→16.7ms = 팝 |

**두 부품 다 최악 프레임은 «팝» 이다.** 형이 38.9% 인 것은 복귀를 고쳐서가 아니라 **팝이 58.8ms**
(3.5프레임)라서다. 동생의 팝은 **22.4ms = 1.34프레임**이라 한 프레임이 진폭의 대부분을 먹는다.

⚑ **그리고 그 축은 이징으로 못 내린다.** 22.4ms 짜리 구간의 한 프레임 최악은 **linear 일 때 74.4%**
가 하한이고(등재문 자신이 괄호로 «linear 로 굴려도 74.6%» 라고 적어 두었다), 그보다 내리려면
**«고원 시작 14%» 를 옮겨야** 한다 — 그 값은 93 3회차 것이고 등재문이 「되돌리지 마라」고 못박은 값이다.
⇒ **등재문의 처방(«복귀에 방을 준다»)으로는 애초에 한 칸도 안 움직였을 축**이다(`verify897` [R3]).

### ② «복귀가 두 프레임» 은 **참이다** — `probe897` [P2]

| | 하강 구간 한 프레임 최악 | 실효 복귀(95%→5%) |
|---|---|---|
| `fxPunch2` | **48.3%** | 66.1ms = **3.97프레임** (복귀 구간 자체는 35.2ms = 2.11프레임) |
| `fxPunch`(형, 39회차 수리본) | **8.8%** | 276.1ms = 16.57프레임 |

동생의 하강이 형의 **5.5배** 나쁘다. 등재문의 «형만 처방을 받았다» 는 사실이었다.

### ③ ⚑⚑ **그런데 그 곡선은 화면에 없다** — `probe897` [P3]

`.fx-punch2` 를 거는 곳은 `fxPunch(el, soft, beat)` 한 곳뿐인데, **그 함수의 첫 줄이**

```js
if(soft) return fxPzHit(el, beat);      /* 93 4회차 — UI 발은 JS 진폭 경로 */
```

다. 93 **4회차**가 «160ms 마다 애니를 재시작하면 봉우리가 잘린다»(≥1.05 가 표본 80장 중 **6장**)를
실측하고 UI 발 펄스를 통째로 **JS 진폭**(`fxPzHit` → `fxPzTick` 이 매 프레임 인라인 `transform` 을 쓴다)
으로 옮긴 그 자리다. 그 뒤로 `soft` 는 이 아래에서 **예외 없이 거짓**이고,

```js
const gap = soft ? FX3_PUNCH : 420;
const cls = soft ? 'fx-punch2' : 'fx-punch';
el.classList.remove('fx-punch'); el.classList.remove('fx-punch2');
```

세 줄의 «참» 가지는 **닿을 수 없었다.** 브라우저 실물로도 UI 발 도착에 `add('fx-punch2')`
**0회**(전투 발 `add('fx-punch')` 는 1회 — 자가 «아무것도 안 붙는 것» 을 보고 있는 게 아니다).

⇒ **894 가 «한 프레임 최대 이동 90.4%» 로 잰 것은 3년 묵은 그림이 아니라 아예 안 그려지는 그림이다.**
곡선을 다듬었으면 **화면은 한 픽셀도 안 바뀌고** 회차만 탔다.

### ④ 그 죽은 가지가 **지뢰**였다 — `probe897` [P3-b]

`FX3_PUNCH` 는 **어디에도 선언돼 있지 않다**(제품 전체에서 참조 1건 · 선언 0건).
삼항의 «참» 가지가 평가되지 않아서 조용했던 것뿐이고, 누가 조기 반환을 걷어내 그 곡선을
«되살리는» 순간 **첫 UI 발 도착에서 `ReferenceError: FX3_PUNCH is not defined`** 다.
브라우저에서 그 한 줄만 그대로 평가해 **폭발을 실제로 찍었다**([P3-e] · 319 `bagUse is not defined` 와 같은 얼굴).

## §8 교훈 (LESSONS 897)

1. **«어느 프레임인가» 를 안 물으면 최악값이 거짓말을 한다.** 90.4% 는 «복귀» 의 값처럼 적혀 있었지만
   실제로는 «팝» 의 값이었고, 두 부품의 차(90.4 ↔ 38.9)도 복귀가 아니라 **팝 길이의 차**였다.
   위상을 쓸어 **최악 창의 시각**을 같이 찍으면 한 줄로 갈린다.
2. **수명이 프레임 몇 장인지부터 보라.** 22.4ms 짜리 구간은 60fps 에서 1.34프레임이라
   **어떤 이징으로도** 한 프레임이 진폭의 74.4% 아래로 못 내려간다. 이징을 손대기 전에
   «이 축에 손잡이가 있기는 한가» 를 산수로 확인할 것.
3. **곡선을 재기 전에 «그 클래스가 붙는가» 를 먼저 물어라.** 890 → 894 → 897 로 두 번 이관되는 동안
   아무도 그것을 안 물었고, 셋 다 **안 붙는 클래스**의 값을 재고 있었다. 자를 세우는 첫 항은
   「이 부품이 화면에 나오는가」여야 한다(341·338 계열).
4. **닿을 수 없는 가지는 조용한 지뢰다.** `soft ? FX3_PUNCH : 420` 은 선언되지도 않은 이름을 3주 동안
   들고 있었다 — 삼항이 그 가지를 평가하지 않아서 `smoke` 도 페이지 에러 0건이었다. 조기 반환을 넣어
   경로를 갈아탈 때는 **그 아래의 반대편 가지를 같은 회차에 접을 것**(319 와 같은 얼굴).
5. **템플릿 리터럴 안의 주석에 백틱을 쓰지 마라.** 페이지에 주입하는 스크립트 문자열 안이라
   백틱 한 글자가 파일을 통째로 못 읽게 만든다(`probe609` 즉사). 자를 고쳤으면 `node --check`.
