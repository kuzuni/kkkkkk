## 1. 왜 713 이 못 닫았나 — 자가 못 따라온 것이지 처방이 없던 것이 아니다

713 은 처방을 이미 알고 있었고 **한 번 해 보고 되돌렸다**(index.html `#sumw` 주석에 값째 적혀 있다):

```
padding 85/127 · #sumMulBar{bottom:29} · #sumSkip{bottom:50} · verify12 DY −25 · scan12r 창 −25
```

막은 것은 `tools/scan12r.py` 다. 이 스캐너는 카드·배지를 **고정 창**에서 찾는데, 카드가 14px 더 뜨면
창이 잉크의 윗동을 잘라 `10×26 → 5×11` 로 읽는다. 713 은 «자를 같이 고치는 것» 을 한 벌로 보고
잔여(747)로 넘겼다 — 그 한 벌이 이 회차다.

## 2. 산수 — 여유 14 가 어디서 오고 어디로 갔나

| | 713 | 747 |
|---|---|---|
| `.sm-panel` padding | 99 / 113 | **85 / 127** |
| 패딩 합(= 패널 1080 을 지키는 상수) | 212 | **212 (불변)** |
| `--sm-gh`(그리드) | 868 | **868 (불변)** |
| 띠 = padding-bottom − 크롬 15 | 98 | **112** |
| `#sumMulBar{bottom}` | 15 | **29** (= 크롬 15 + 여유 14) |
| `#sumSkip{bottom}` | 36 | **50** |
| 바·토글 세로 중심 | 64 (같음) | **78 (같음)** |
| 카드 이탈(ref 축) | −11 | **−25** |

- **여유는 전부 아래로 준다.** 지적이 «바 **하변**이 테두리에 붙었다» 였고, 위쪽은 그리드 *상자*
  하변이라 잉크가 닿지 않는다(줄은 `align-content:safe center` 로 가운데 모이고 배지 돌출 8px 은
  그리드 안 `padding-bottom` 이 이미 먹는다). 그래서 바 상변은 여전히 그리드 하변에 **정확히** 붙고
  (`29 + 98 = 127`), `verify668` [A8] 의 «그리드 하변 = 셸 상변» 항등이 그대로 산다.
- **토글은 «띠 한가운데» 가 아니라 «바와 같은 중심»** 이다. 713 에서는 둘이 같은 값이었고
  (15 + 21 = 36), 747 에서 갈린다(띠 한가운데면 43 · 바와 같은 중심이면 50). 363 이 실제로 지키던
  약속은 `verify713` [B1] 이 재는 **«바와 세로 중심이 같다»** 쪽이라 그것을 따랐다.
- **패널·버튼·닫기·리본은 한 칸도 안 움직인다**(84·327 앵커 Δ0px). 움직인 것은 패딩을 위아래로
  나누는 자리뿐이고, 그 대가가 카드 −14px 이다.

## 3. 자 — «창» 과 «환산» 을 갈랐다(이 회차의 핵심)

`scan12r.py` 는 cap 좌표를 ref 축으로 되돌려 두 이미지를 같은 숫자로 비교한다. 여기에 이탈을 섞으면
**어긋난 만큼 창이 따라가** 표류가 영영 안 보인다. 그래서 둘로 갈랐다:

- **환산 오프셋 `SM_CARD`(−83)** = 327 모델 그대로. 손대지 않는다.
- **창 이탈 `SM_DY`(−25)** = 창이 «어디를 보는가» 일 뿐. 잉크가 잘려 읽히는 것만 막는다.

⇒ 이탈은 `verify12` 의 `DY` **한 상수**에만 살고, 그 이상 표류하면 그대로 빨개진다.
실제로 창을 편 효과가 숫자로 보인다 — 배지 잉크 높이가 **25 → 26**(= ref 26)으로 돌아왔다
(713 때는 창에 2px 물려 있었고 ±3 허용치 안이라 초록으로 지나갔다).
