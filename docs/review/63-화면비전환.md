### 남은 문제 — 중앙 정렬 다이얼로그가 일제히 **+54px** 아래 (다음 세션 인계)

A5 공용 모달(`#modal`)과 전용 다이얼로그(`#wpnw`·`#dgdw`·`#prbw`·`#pfw` 계열)는 절대 top 이 아니라
**«패딩 안에서 세로 중앙 정렬»** 이다. 이 방식은 `padding:126px 91px 42px` 로 짜여 있어
**프레임을 레퍼런스와 같은 2340 으로 키우면 ref 절대 y 를 정확히 재현**하도록 맞춰져 있다.

그래서 프레임이 **2280** 이면 상자 top 은 이렇게 된다:

```
top(frameH) = (frameH + pt − pb − h) / 2          ← h = 상자 높이
top(2340) = ref_top            (설계상)
top(2280) = top(2340) − 30
목표      = ref_top − 84 = top(2340) − 84
편차      = −30 − (−84) = **+54px  (상자 높이 h 와 무관하게 일정)**
```

실측이 정확히 그렇다 — `.wm` h1469 → y448(목표 394) · `.mbox` h1497 → y434(목표 380) ·
`.dgd-box` h1197 → y584(목표 529.5) · `.spc` h1395 → y485(목표 430.5). **전부 +54.**

**처방은 한 줄이다: 컨테이너 패딩의 `pt − pb` 를 108 줄인다** (예 `126px/42px` → **`42px 91px 66px`**).
그러면 `top = 1128 − h/2 = ref_top − 84` 가 되어 단일 변환과 정확히 일치한다.

**이번 세션은 일부러 안 건드렸다.** 이유 2개:
1. 대상이 04·05·08·11·16·20·21·22·29·33 **10화면**이고 전부 이미 7~9점으로 통과한 화면이라,
   껍데기 위치를 54px 옮기면 **재채점이 필요하다**(기계적 작업 (가)의 범위를 넘는다).
2. `padding-top:126` 은 짧은 기기(4:3 → frameH 1600)에서 다이얼로그가 상단 HUD(0..104) 를
   파고들지 않게 막아 주는 가드이기도 하다. 42 로 낮추면 **1600 프레임에서 상자 top 이 42** 가 되어
   HUD 와 62px 겹친다. 짧은 기기 가드를 어떻게 유지할지(`max()` 클램프 등)를 같이 정해야 한다.

→ **2차 폴리시 라운드에서 «10화면 일괄 −54px + 짧은 기기 가드» 로 한 번에 처리할 것.**
