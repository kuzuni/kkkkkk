## §3 뿌리 — 자가 **입장 연출 한복판**에서 재고 있었다

팝업을 연 직후의 애니메이션을 세어 보니 `jzPgIn`(`.12s` · `scale:.985→1`)이
캡처 시점에 **`playState: 'running'`** 이었다. 291 이 적어 둔 지문 그대로다 —
0% 프레임의 `scale` 이 `.985` 라 화면 절대 좌표가 통째로 밀린다.

**왜 공용 정착이 이 자를 못 도왔나** — 291 의 정착은 `page.waitForTimeout(ms)` 에 훅으로
붙는데 **`ms >= 250`**(`settle291.MIN_WAIT`) 일 때만 돈다. 그 문턱은 «시간 자체를 재는»
게이트(64·262 홀드 · 107 관성)에 rAF 2프레임을 얹지 않으려고 291 이 일부러 둔 것이다.
그런데 `verify886` 의 `openAt()` 은 이렇게 생겼다:

```
await page.waitForTimeout(560);                 // ≥250 → 정착이 돈다. 그런데 팝업을 열기 **전**이다(정착할 연출 0)
await page.evaluate(() => { S.relic = 1e9; openRelw(); });
await page.waitForTimeout(220);                 // <250 → 정착이 **안 돈다**. 그런데 여기가 jzPgIn 한복판이다
```

⇒ **훅이 한 번도 이 자를 도운 적이 없다.** 353 이 «훅이 못 보는 자리»(페이지 안에서 기다리는 모양)를
찾아 §in-page 를 만들었는데, **문턱 아래로 기다리는 모양**이라는 자리가 하나 더 있었다.

그 위에서 플레이키의 기계가 하나 더 겹친다. `[3]` 은 판을 **셋** 찍는다(`base`·`base2`·`noBar`) —
세 판이 각자 다른 위상에서 찍히므로,
* 두 `base` 가 우연히 **같은** 위상이면 잡음 마스크가 비고(잡음 0) → 그다음 `base↔noBar` 차분이
  통째로 «바가 덮은 화소» 로 세어진다 = **빨강**(판 2·6),
* 두 `base` 가 **다른** 위상이면 마스크가 그 자리를 먹어 치워 → **초록**(판 5, 잡음 1222).

즉 잡음 축(`base↔base2`)은 «렌더가 흔들리나» 를 묻는 자였는데 **표본이 한 쌍뿐**이라
같은 흔들림을 어떤 판에서는 마스크로, 어떤 판에서는 결함으로 셌다.

⚠ **증상은 `[3]` 에서만 보였지만 재던 것 전부가 0% 프레임 위에 있었다.** 정착을 넣으면 같은 트리에서
`panelY` **117.81 → 108.00** · `--rw-fl` **874.86 → 888.19** 로 바뀐다. `[1]·[2]·[4]·[5]·[6]` 이
초록이었던 것은 그 항들이 전부 **조상 배율 `sc` 로 나눠 보는** 상대 자였기 때문이다
(`sc` 가 입장 연출의 배율까지 같이 흡수하고 있었다). 정착 뒤 얹힘·간극이 `3.94`·`Δ3.94` 에서

## §4 처방 — 문턱을 만지지 않고 **부르는 쪽**에서 정착한다
