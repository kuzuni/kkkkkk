## 3. 처방 — 제품 4자리

### ⓐ 축 (`trainCardData`)

```js
const mul = TRAIN_NOW[k]() / u.val(l);            /* 알약이 쓰는 자에서 꺼낸 배수 */
const gain = bi.n ? (u.val(l + bi.n) - u.val(l)) * mul : 0;
```

⚑ **배수 표를 두 번째로 안 적었다**(402 «표 두 벌» 부패). `mulAtk`/`mulHp`/`mulRegen` 을 여기서
다시 부르면 «훈련 카드가 읽는 배수 표» 가 한 벌 더 생겨, 다음에 축이 하나 늘면 조용히 갈린다.
배수는 **알약이 쓰는 바로 그 함수**(`TRAIN_NOW`)에서 나눗셈으로 꺼낸다.
`u.val` 은 `b + K·l`(b = 18/160/4 · K > 0 · l ≥ 0 — 19577 `trainVal`)이라 0 이 될 수 없어 안전하다.

### ⓑ 시점 (`trHoldGainTxt` 신설 · `trHoldStop` · `trHoldStart`)

```js
function trHoldGainTxt(h){
  if(!h || h.now0 == null || !TRAIN_NOW[h.key]) return '';
  const g = TRAIN_NOW[h.key]() - h.now0;
  return g > 0 ? '+' + fmtB(g) : '';
}
```

`trHold` 에 `now0`(= **첫 발을 산 뒤**의 최종값)를 박고 정산은 그 차이를 말한다.
`now0` 을 첫 발 «앞» 이 아니라 «뒤» 에 잡은 이유는 64 규약 그대로 이 한 장이 맡은 것이
**반복분**(`h.n > 1`)이기 때문이다 — 첫 발은 자기 플로터가 이미 말했다.
⚠ 계산식을 새로 안 적었다. `TRAIN_NOW` 를 **두 시점에 읽을 뿐**이라 자가 여전히 하나다.

## 5. ⚠ 다음 세션이 볼 것 — **단계는 세이브로 못 정한다**

## 6. ⚠ 알약에는 해상도가 있다

`.cv` 는 유효숫자 3자리(«32.4A»)다. 고레벨에서 x1 은 값의 0.1% 라 **글자가 안 움직이는 것이 정상**

**그건 제품이 아니라 자의 결함**이다. ⇒ x30(눈에 보이는 크기)은 «반드시 움직인다» 를 묻고,
안 움직인 칸은 «해상도 아래였다» 를 **양성으로** 묻는다.

## 7. ⚠ `fmtG` 는 `Math.floor` 다

«전·후를 재서 뺀» 실측은 부동소수 누적이 붙어 180 이 179.99999999 로 내려앉고, floor 가 그 한 칸을
통째로 깎는다(regen x10 이 그랬다). 제품 쪽은 **곱셈 한 번**이라 180.0 이 정확하다 —
**제품이 아니라 뺄셈이 흔들린 것**이므로 게이트는 한 자리 nudge(`×(1+1e-9)`)만 허용한다.
무르게 푸는 것이 아니다: 같은 표본에서 [B] 가 기저 축과의 **16~22%** 차이를 계속 막는다.
