## 1. 재현이 먼저 (338 규칙)

등재문의 처방(ⓐ «claim 이 열린 화면을 다시 그린다»)을 따르기 **전에** `tools/probe547.js` 로 제품에게 직접 물었다.
**등재문 그대로 확인됐다** — 그리고 «넓이» 질문(ⓑ)의 답도 같이 나왔다.

수리 **전** 트리(`406819b` 기준 · `git checkout -- index.html` 로 되돌려 같은 자를 돌린 대조 실행):

| 1-e 수령 **직후** 화면 | `off=true` · `#cnExch` **없음** · ct **«0 / 10»** · bar **0px** | `off=false` · `#cnExch` **있음** · ct «11 / 10» · bar **410px** |

### 재현하면서 잡은 함정 둘 (다음 세션이 그대로 밟는다)

- **세이브는 `goto`·`reload` 로 못 지운다.** 떠나는 페이지의 `beforeunload → save()` 가 방금 지운 키를 되살린다
  (LESSONS 363-①). 1회차에 절 [1] 의 쿠폰 11개가 절 [2] 에서 **22** 로 읽혀 «두 번 수령» 이라는 헛다리를 짚을 뻔했다.
  ⇒ 절마다 **새 컨텍스트**(`browser.newContext()`)를 연다. `probe547`·`verify547` 둘 다 그렇게 돌린다.
- **`getAnimations()` 는 카드 자신에게 안 붙어 있다.** 122 쥬시는 자손(`.bg`·`.hd`·`em` …)에 걸리므로
  `card.getAnimations()` 는 **0개**를 돌려준다(1회차에 «진행 시각 0 → 0 = 대가 없음» 이라는 오답이 나왔다).
  `document.getAnimations()` 를 걷어 `card.contains(a.effect.target)` 으로 걸러야 카드당 **9개**가 잡힌다.

## 2. 뿌리와 처방

뿌리는 «누가 잘못 그렸나» 가 아니라 **«그릴 사람을 아무도 안 불렀다»** 다.

- `claimMail`(24843)·`claimAllMail`(24854) 은 `uiDirty = true; save()` 만 한다.
- `renderUI()`(0.35초 주기)는 **상점 리스트를 안 그린다** — `renderCoinPage()` 를 부르는 곳은 구매·교환·광고 경로뿐이다.
- 우편함(`ml69`)은 **상점 시트 «위» 에 뜨는 모달**이라, 수령이 끝나도 아래 시트는 열린 채 옛 그림으로 남는다.

**처방은 등재문 ⓐ** — 그리고 **선례가 저장소 안에 이미 있었다**: 153 의 `sendMail()` 이
`fxStillOpen('ml69') → openMail()` 로 «열려 있으면 그 자리에서 다시 그린다» 를 하고 있다(24818).
다만 상점은 모달이 아니라 **시트**(`#shopw`)라 `fxStillOpen` 이 못 본다 ⇒ 시트용 판정을 **한 곳에만** 둔다.

```js
/* 28907 부근 — SHOP_CATS 선언 바로 위 */
const shopStillOpen = () => { const sw = $('shopw'); return !!(sw && sw.classList.contains('on')); };
function reShopIfOpen(){ if(shopStillOpen()) renderShopPage(); }
```

호출은 **재화가 실제로 오간 자리**에서만 — `claimMail` 끝(24851) · `claimAllMail` 끝(24864).

### ⚑ 이 작업의 핵심은 «조건을 두 벌로 두지 않은 것» 이다

`grantDiaPack`(29238)에 **이미 같은 판정이 손으로 적혀 있었다**:

```js
const sw = $('shopw');
if(sw && sw.classList.contains('on') && shopCat === 'coin') renderCoinPage($('shopList'));
```

claim 쪽에 이 줄을 **복사했으면** 판정이 세 벌이 된다 — 재화 탭 말고 다른 탭이 재화를 보이게 되는 날
(등재문 ⓑ 가 걱정한 바로 그 재발) 한쪽만 따라온다. 402 의 «표 두 벌»(`dunTk()` 를 고쳐도 `DUN_UI[].tk`
사본이 옛 그림을 그렸다) 과 같은 꼴이다. ⇒ **그 줄을 `reShopIfOpen()` 으로 갈아 끼워** 판정을 한 곳으로 모았다.
`verify547` [D-b] 가 «옛 이중 판정이 제품에 0건» 을 지킨다.

### 왜 «부분 갱신» 이 아니라 재렌더인가

마일리지 패널만 손으로 고치는 길(노드 4개를 직접 만지기)은 **두 번째 렌더 경로**를 만드는 것이라
같은 402 병을 새로 심는다. 재렌더는 `renderCoinPage()` 한 벌만 남긴다. 대가(아래 §4)는 잰 뒤 받아들였다.

## 3. 넓이 — 등재문 ⓑ 에 답한다

등재문은 «다른 탭에도 같은 병이 있는지 먼저 세라(마일리지만 고치면 다음 재화에서 재발)» 고 했다.
`probe547` [3] 이 상점 3탭 각각에서 **«수령 직후 DOM» ↔ «강제 재렌더 뒤 DOM»** 을 문자열로 대조했다:

| 탭 | 수리 전 | 비고 |
|---|---|---|
| 소환(`summon`) | 같다 = 안 낡는다 | 카드 상태가 소환 레벨·무료 횟수라 우편과 무관 |
| **재화(`coin`)** | **다르다 = 낡는다**(len 12,849 → 12,860) | 마일리지 패널 |
| 이용권(`pass`) | 같다 = 안 낡는다 | 보유 이용권은 구매로만 바뀐다 |

⇒ 지금 낡는 자리는 **하나뿐**이다. 그런데 고친 자리는 «마일리지 패널» 이 아니라 **«상점 시트»** 다 —
`reShopIfOpen()` 은 열려 있는 탭이 무엇이든 그 탭을 그린다. 그래서 §9 유물조각 교환이 잔고로 상태를 갈리게
바뀌든, 이용권 탭이 재화를 보이게 되든 **자리가 늘어나도 따라온다.** `verify547` [E] 가 세 탭을 전부 센다.

## 4. 대가 — 재렌더는 122 쥬시 위상을 되감는다

`probe547` [4] 실측: 재렌더 직전 카드 3장의 애니 진행 시각이 **1,600~1,650ms** 였는데 재렌더 직후 **0ms** 다
(카드당 애니 9개). 칸별 위상 오프셋 `--jz-k`(0.0000 / −0.3333 / −0.5000)는 렌더가 다시 계산하므로 **불변**이라,
122 가 15·21회차에 푼 «이웃 칸이 동위상으로 겹치지 않는다» 는 성질은 그대로 산다.

받아들인 이유 셋:
1. 이 재렌더가 도는 순간 화면은 **우편함 모달과 딤에 덮여 있다**(사용자 경로에서 유일한 발생 지점).
2. 같은 대가를 **`grantDiaPack` 이 이미 치르고 있었다**(구매 시 재화 탭 재렌더) — 새로 생긴 비용이 아니다.
3. 자리를 «재화가 실제로 오간 순간» 으로 좁혔다. `verify547` [D-c] 가 **시트가 닫혀 있으면 렌더 0회**를 못박는다.
