## §2 뿌리 — ⓓ 는 **양자화된 두 값을 빼면서** 판정선을 잡음 바닥에 붙여 놨다

ⓓ 의 셈은 이렇다.

```
expect = (오프스크린 1× 래스터의 잉크 bbox 중심 − 펜) × sx        // sx = .si3 의 scaleX(.842)
actual = (화면 캡처 차분의 잉크 bbox 중심) − 슬롯 중심
resid  = actual − expect                                          // 판정: |resid| ≤ 1px
```

두 항 모두 **정수 픽셀 열**에서 뽑은 bbox 다. `(x0 + x1) / 2` 는 정수 두 개의 평균이라 **0.5 격자에만 앉고**,
참값 대비 오차가 각각 최대 ±0.5px 다. 그래서 `resid` 가 짊어지는 **순수 측정 잡음**은

```
±(0.5 + 0.5 × sx) = ±(0.5 + 0.421) ≈ ±0.92px
```

판정선이 **±1px** 이다. 잡음 바닥(0.92)과 판정선(1.00)의 간격이 0.08px 밖에 없다 —
래스터가 반 픽셀만 달라져도 뒤집히는 것이 **정상 동작**인 자였다.

실제로 드라이버가 바뀌자 두 항이 **같은 방향으로 어긋나 서로 상쇄되던 것이 서로 더해지는 쪽으로** 돌아섰다:

| 칸 | 🗡️ | ✴️ | 🪨 | 🌙 | 🔱 | 💫 | ❄️ | 🌀 |
|---|---|---|---|---|---|---|---|---|
| 1× `dxRaw` (1.62.1) | 0 | 0 | −2 | 0 | −0.5 | −0.5 | −0.5 | −0.5 |
| 1× `dxRaw` (1.56.0) | −1 | −1 | −2 | −1 | −0.5 | −0.5 | −0.5 | −1 |
| 화면 `actual` (1.62.1) | +0 | −0.5 | −1.5 | −0.5 | −0.5 | +0 | −0.5 | +0 |
| 화면 `actual` (1.56.0) | **+0.5** | **+0.5** | **−1** | **+0.5** | +0 | **+0.5** | +0 | +0 |

화면 쪽은 8칸이 **통째로 +0.5px** 옮겨 앉았다(개별 칸이 제각각 움직인 것이 아니다 — 배치라면 이런 모양이 안 나온다).
오프스크린 쪽은 네 칸이 −0.5 → −1.0 으로 **한 픽셀** 옮겨 앉았다. 둘이 더해져 1.34px.

## §3 처방 — 판정선을 넓히지 않고 **자를 가늘게 간다**(8× 수퍼샘플)

`expect` 를 1× 래스터에서 읽는 한 그 항은 «글리프의 기하» 가 아니라 «그 드라이버의 래스터» 다.
같은 글리프를 **K배 크기로 그려 K로 나누면** 분해능이 1/K 로 떨어지고, 값은 래스터가 아니라 **아웃라인의 기하**로 수렴한다.

```js
const BEAR_K = 8;                          // 분해능 0.125px
const SZ = 300 * K;                        // 캔버스 2400×2400
g.font = (fs * K) + 'px ' + fam;           // 78.3 → 626.4px
…
dxRaw = (((x0 + x1) / 2) - SZ / 2) / K     // 1 CSS px 단위로 되돌린다
```

수렴 실측 (드라이버 1.56.0):

| 칸 | K=1 | K=2 | K=4 | **K=8** |
|---|---|---|---|---|
| 🗡️ | −1 | +0.25 | +0.125 | **+0.125** |
| ✴️ | −1 | +0.25 | 0 | **−0.063** |
| 🪨 | −2 | −1.25 | −1.375 | **−1.5** |
| 🌙 | −1 | +0.25 | 0 | **−0.063** |
| 🔱 | −0.5 | 0 | 0 | **−0.063** |
| 💫 | −0.5 | 0 | 0 | **−0.063** |
| ❄️ | −0.5 | 0 | 0 | **−0.063** |
| 🌀 | −1 | 0 | 0 | **−0.063** |

K=4 와 K=8 이 사실상 같은 값이다(≤0.13px). 1× 가 읽던 −1·−2 는 **글리프가 아니라 격자**였다.
K=8 의 `dxRaw` 는 **두 드라이버에서 동일**하다 — 자가 드라이버를 안 탄다는 뜻이고, 그것이 이 수리의 전부다.

남는 잡음은 **화면 쪽 ±0.5px 한 겹뿐**이라 ±1px 이 비로소 «배치» 를 재는 선이 된다(여유 0.45px).
**판정선은 한 칸도 안 넓혔다.**

### 안 고른 길

- ⓐ **±1px 을 ±1.5 로 넓힌다** — 361 이 방금 되돌린 그 실수(«글리프별 ±12%» 로 부푼 게이트)다. 잡음을 판정선으로 인정하는 것이라 기각.
- ⓑ **화면 캡처를 `deviceScaleFactor: 4` 로 찍는다** — 화면 쪽 양자화까지 지울 수 있지만 ⓒ 절의 창·좌표가 전부 device px 로 바뀌어
  357 이 남긴 측정 기록(잉크 68×85 · 창 ±60/±48)과 연속성이 끊긴다. 잡음의 큰 쪽(오프스크린)만 지워도 판정선이 서므로 기각.
- ⓒ **칸마다 어긋난 만큼 CSS 로 밀어 넣는다** — 357 지시가 금지한 «비균등 보정» 이고, 애초에 어긋난 것이 화면이 아니라 자였다. 기각.

## §4 §R 되돌림 시험 — «무르게 푼 수리» 가 아님을 못박는다

자를 갈았으니 «그래서 이제 아무것도 못 잡는 항 아니냐» 에 답해야 한다. 프로브에 §R 절 **3항 신설**:

1. `html.p357shift #slots .si3{left:3px}` 로 **일부러 3px 밀고** 다시 찍는다 → ⓓ 최악 잔차 **3.55px**(1.56.0) / **3.05px**(1.62.1) = 빨강.
2. 밀린 3px 이 **8칸 전부** 잔차로 그대로 올라온다(각 칸 `resid − base_resid` 가 3 ± 0.6px).
3. 클래스를 떼면 **다시 0.55 / 0.45px 로 초록**.

규칙은 기존 스타일시트에 **한 번만 심고 클래스로 토글**한다 — 장마다 `addStyleTag` 를 덧붙이면 재래스터가 섞인다(이 프로브 5회차 사고).

> `tools/verify243.js:71` — «실전 배율(0.15~4.8)로 재면 잉크가 수십 px 이라 **1px 양자화가 허용치를 먹어 버린다.**
