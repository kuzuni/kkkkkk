## 3. 처방 — ⓐ(파생) 채택, ⓑ(숫자만 내리기) 기각

등재문의 두 후보 중 **ⓐ** 를 골랐다. 두 자에 같은 파생 한 벌을 넣었다(페이지 안에서 제품에게 묻는다):

```js
const specOf = b => { const tab = rollOf(b), gs = new Set(BANNERS[b].list.map(x => x.g));
  return { heads: [...gs].filter(g => g < tab.length).length,
           rows:  BANNERS[b].list.filter(x => x.g < tab.length).length,
           gated: tab.some(g => g.unlock > lit) }; };
```

- `heads` 를 **`rollOf(b).length` 로 두지 않았다** — 렌더는 «종이 한 마리도 없는 등급» 을 건너뛰므로
  (`renderProbInfo` 의 `if(gp[g] <= 1e-9 || !items.length) continue;`), 표 길이가 아니라 **표 안에 실제로
  종이 있는 등급 수**가 화면의 헤더 수다. 표만 늘리고 종은 안 늘리는 날 표 길이로 잡으면 자가 거짓말을 한다.
- `gated` = «그 표에 옛 리터럴(100)보다 늦게 열리는 행이 있나». 되돌림 항의 **갈래 축**이다(아래 §4).

**ⓑ 를 기각한 이유는 `probe773` `[2-c]` 가 못박는다** — 숫자만 7·35 로 내렸으면 펫 종이 다시 느는 날
같은 네 항이 **또** 빨개진다(그것이 지금 내가 고치고 있는 바로 그 사고의 재발이다).

## 4. 죽은 단언을 비우지 않고 방향을 뒤집었다 (333 처방)

`[B3]`·`[R3]` 은 상수만이 아니라 **주장 자체**가 낡아 있었다: 「106 [E7] 이 세는 36행도 옛 형태에선 줄어든다」.
757 이후 펫 표에는 **만렙 문턱에 걸린 행이 없다**(불멸 `unlock: SUM_MAXLV − 1` 이 잘려 나갔고, 남은 최고 행은
초월 `unlock: 40`). 그래서 만렙 150 사본에서 Lv100 을 열어도 펫은 **35행 그대로**다 — 옛 주장은 지금 거짓이다.

자리를 비우지 않고 **살아 있는 사실**로 갈아 끼웠다:

> 「106 [E7] 이 세는 행은 **«만렙 문턱 행» 이 있는 표에서만** 옛 형태에서 줄어든다 —
>  757 이 펫에서 불멸을 걷어내 지금 줄어드는 쪽은 **무기**다(대조군).」

세 겹으로 잰다: ① 펫 행·등급 = 파생값 ② `gated` 갈래대로 «줄어든다/그대로다» ③ **무기는 실제로 줄어든다**
(사본에서 35행 → 36행). ③ 이 없으면 이 항은 «펫이 안 줄었다» 만 말하는 **헛초록**이 된다 — 자가 화면을
못 읽고 있어도 «안 줄었다» 는 성립하기 때문이다.
