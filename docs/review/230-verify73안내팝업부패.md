## 1. 원인 — 두 군데가 동시에 죽어 있었다

```js
/* 옛 단언 (tools/verify73.js §4) */
const modalOn  = $('modal').classList.contains('on');
const modalTxt = $('mtitle').textContent + ' ' + $('mbox').textContent;
ok(blk.modalOn && /가이드 진행/.test(blk.modalTxt) && /무기|방패|스킬/.test(blk.modalTxt),
   '차단 시 안내 팝업 노출');
```

세 조건 중 **두 개**가 이미 죽어 있었다.

| 조건 | 상태 | 왜 |
|---|---|---|
| `modalOn` | **항상 false** | 149 가 `notify()` = `fxToast` 로 뒤집었다. `gmBlocked` 는 모달 경로를 안 탄다 |
| `/가이드 진행/` | **항상 false** | 그 시절 팝업 **제목**의 스냅샷. 지금 문안에 그런 말은 없다 |
| `/무기\|방패\|스킬/` | 살아 있었다 | 상자 이름은 지금도 문구에 들어간다 |

현행 안내(index.html 18452 `gmBlocked`)는 이것 하나다:

```js
notify('📌 <b>' + BANNERS[need].n + ' 소환</b>을 먼저 해주세요');
```

실측 문구 — **`📌 스킬 소환을 먼저 해주세요`** (`#fxl .fx-toast` 의 `textContent`).

**중요 — 「제품이 안내를 안 낸다」 가 아니다.** 안내는 유료(`doSummon`)·무료(`[data-shfree]`) 두 경로에서
**둘 다 정상으로 뜬다.** 죽은 것은 재는 자리뿐이다.

## 2. 처방 — 이사 + 항목 신설 (65 → 67)

`§4` 의 측정만 `#fxl .fx-toast` 로 옮기고, 한 항목이던 것을 **셋**으로 쪼갰다.

| 항목 | 무엇을 지키나 |
|---|---|
| **차단 시 안내 토스트 노출 — «{이름} 소환»** | «막았으면 **왜** 막혔는지 말하는가» (옛 단언의 물음 그대로) |
| **차단 안내는 팝업이 아니다 — 149 토스트화 유지** | 149(주인 지시)로의 **되돌림을 그 자리에서** 잡는다 |
| **무료 10연 차단도 같은 안내를 낸다** | 유료·무료 **두 경로**가 같은 안내를 내는가 (옛 단언은 유료만 봤다) |

세부 규약 3가지:

- **기대 문구는 리터럴 금지 (185-①).** 페이지 안에서 `BANNERS[gmBan()].n` 으로 **런타임 계산**한 뒤
  `wantName + ' 소환'` 을 찾는다. 옛 단언의 「가이드 진행」 이 바로 «그때의 문안» 을 박아 굳힌 결과다.
  ⚠ 다만 **`BANNERS` 는 게임 데이터이고 `gmBan()` 은 제품 함수**다 — 이 자는 «어느 상자를 지목하는가» 는
  제품에 맡기고 «지목한 이름이 안내에 들어 있는가» 만 잰다. 지목 자체는 `§3` 의 `ban` 부착 항목이 따로 지킨다.
- **대기 없음 — 185-⑥ 의 예외.** `doSummon → gmBlocked → notify → fxToast → appendChild` 가
  **한 동기 흐름**이라 같은 `evaluate` 안에서 읽으면 토스트 수명(760ms 퇴장 · 1060ms 제거)과 **무관**하다.
  기다리는 것보다 **엄격**하다 — 300ms 를 기다렸다면 여유 460ms 에 걸린 자가 된다.
- **재기 «전» 에 비운다.** `fxToast` 는 `stack > 3` 이면 **조용히 드롭**한다(index.html 25155).
  §4 는 한 `evaluate` 안에서 차단 2번 + 정상 소환 1번을 연달아 하므로, 비우지 않으면
  뒤쪽 안내가 «없는» 것으로 보일 수 있다. 측정 후에도 비운다(**뒷정리** — 다음 절에 토스트를 흘리지 않는다).
