## 1. 뿌리 — «남는 자리를 가운데로» 가 만든 전폭 상자

699(주인 지시 2026-09-02 «보스 도전할 때 설정 가능하고 설정 팝업에도 있게 해줘»)가 28 보스전 HUD 에
공용 부품 `.sm-sk` 를 얹으면서 **정렬 손잡이**로 이것을 골랐다:

```css
#bossSkip{position:absolute;left:0;right:0;top:396px;justify-content:center;z-index:5;display:none}
```

`left:0;right:0` 은 **상자를 프레임 전폭으로 늘리고**, `justify-content:center` 는 그 안에서
**내용만** 가운데로 민다. 즉 보이는 것과 상자가 다르다:

| | x | 폭 |
|---|---|---|
| 상자 | 0.0 .. 1080.0 | **1080.0** |
| 잉크(라벨 + 노브) | 421.3 .. 660.8 | 239.4 |
| **투명 여백** | 좌 **421.3** · 우 **419.3** | 상자의 **77.8%** |

그런데 이 토글은 **표시 전용 HUD(`#stinfo`·`#bossHp`)와 달리 «누르는 것»** 이라
`pointer-events` 가 살아 있다(699 가 주석에 명시). ⇒ **여백 77.8% 가 그 y 띠의 탭을 통째로 먹는다.**

`z-index:5` 이고 `#sideL` 은 `z-index:3` 이라 같은 쌓임 맥락에서 토글이 위다.

## 3. 처방 — 상자를 잉크만큼

등재문의 후보 셋 중 **ⓐ(히트 영역을 잉크로)** 를 골랐고, 그 구현을 **정렬 손잡이 교체 한 줄**로 했다:

```css
#bossSkip{position:absolute;left:0;right:0;top:396px;width:fit-content;margin-inline:auto;z-index:5;display:none}
```

`left:0;right:0` + `width:fit-content` + auto 마진 = 절대배치의 표준 중앙정렬이고,
상자가 **잉크만큼**이라 여백이 애초에 안 생긴다. **선례가 저장소 안에 있다** — 같은 부품의 다른 호스트
`#rouSkip{width:fit-content;margin:14px 0 0 auto}` 가 이미 그 꼴이다(514 «부품 한 벌 · 호스트 여럿»).

### 기각한 길 셋 (되돌리려는 다음 세션이 읽을 것)

| 후보 | 왜 아닌가 |
|---|---|
| ⓑ z 층을 갈라 사이드를 위로 | 가려짐이 «어느 칸이 위냐» 로 바뀔 뿐 **투명 여백은 그대로 남는다** — 그 띠의 **빈 곳** 탭이 계속 설정을 뒤집는다. 결함의 절반만 고친다. |
| ⓒ 보스 연출 중에만 히트 | 결함이 나는 상태가 바로 그 «연출 중»(`bf`)과 «재도전 대기»(`fm`)다. 조건을 좁혀도 그 두 상태에서 그대로 난다. |
| `left:50%` + `translateX(-50%)` | **오답이다** — `.sm-sk:active{transform:scale(.96)}` 가 **같은 속성**을 덮어써 누르는 순간 토글이 오른쪽으로 튄다(손잡이 둘이 한 속성을 다툰다). |

### 자리는 한 칸도 안 움직였다

`probe959` 판정 마지막 줄 — **잉크 중심 Δ0.00px · 상변 Δ0.00px · 폭 Δ0.00px.**
699 가 세운 «버튼 두 개의 중심 x540 축 · 396..452 띠» 는 그대로다. 보이는 그림은 **한 픽셀도** 안 바뀐다.

⚑ 그래서 이 결함이 오래 남았다 — `verify959` [E] 되돌림 시험이 그것을 못박는다:
옛 손잡이를 도로 먹여도 **잉크 중심은 같은 값**이고, 달라지는 것은 오직 «탭이 어디에 떨어지는가» 다.
