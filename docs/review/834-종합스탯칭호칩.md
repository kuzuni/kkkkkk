## §1. 재현 먼저 (338 규칙)

처방을 따르기 전에 `tools/probe834.js` 를 신설해 **주인이 본 그림**부터 찍었다. 소스 grep 이 아니라
두 팝업을 실제로 열어 칩 문자열을 읽는다 — 그래야 «갱신 경로가 있는데 안 도는» 경우까지 갈린다.

절차: 칭호 셋을 보유시키고(계급은 브론즈로 둔 채) 19 에서 «골드» 를 장착 → 하단 토글로 20 으로 갈아탄다.

```
[1a] 19 칩 = «골드»                                  ✓
[R1] 20 칩이 19 와 같은 문자열이다   19 «골드» ↔ 20 «칭호 없음»   ✗
[R2] 20 칩이 손 문자열 «칭호 없음» 이 아니다                      ✗
[3b] 칭호를 «실버» 로 바꾼 뒤 20 칩                «칭호 없음»    ✗
[4b] 폴백(고른 적 없음) 에서도 20 칩              «칭호 없음»    ✗
                                              PROBE834 7/11 FAIL
```

**등재문의 가설 ⓐⓑ 가 둘 다 그대로 확인됐다** — 기각된 갈래는 없다. 20 의 칩은 어떤 상태에서도
움직이지 않는다: 이 자리는 «틀린 값을 그린다» 가 아니라 **아무도 그리지 않는다**.

## §2. 처방 — 값을 복사하지 않는다

등재문이 못 박은 대로 **19 가 이미 쓰는 갱신 경로를 20 도 읽게** 했다(705 ② «그림 출처가 둘이 되지 않게»).
값을 20 쪽에 한 줄 더 적는 길은 **방금 고친 사고를 한 번 더 만드는 것**이라 처음부터 배제했다.

706 이 세운 축 셋 — 읽기(`titleIdx`) · 표시(`titleOf`) · 쓰기(`titleEquip`) — 옆에 **네 번째로 «그리기»** 를 붙였다:

```js
function paintTitleChips(){
  const n = titleOf().n;
  ['pfTtl', 'spcTtl'].forEach(id => { const el = $(id); if(el) el.textContent = n; });
}
```

- `renderProfile()` — `$('pfTtl').textContent = titleOf().n;` → `paintTitleChips();`
- `renderSpec()` — 한 줄 추가(닉네임 바로 아래, 같은 «머리 정보» 묶음)
- 마크업 — `.spc-rib > b > i` 에 `id="spcTtl"`. **문자열 «칭호 없음» 은 지우지 않았다** —
  스크립트가 죽었을 때 빈 칩이 되지 않게 하는 폴백 초기값이다(292·333 «죽은 표시를 지우면 무엇이 있었는지 사라진다»).

⚠ **HUD `#rankN`(drawHud)은 이 목록에 안 넣었다.** 매 프레임 도는 자리라 팝업 두 개를 같이 훑게 되고,
그 값은 이미 같은 `titleOf()` 에서 나온다 — **축은 하나이고 호출 시점만 다르다.**
