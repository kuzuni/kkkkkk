## 1. 그런데 그 자리는 «초록» 이 아니라 «뜨고 지는» 상태였다

등재문 2건이 끝났다고 게이트가 건강한 것은 아니다. 종결 근거를 1회 실행으로 삼지 않고
**연속 실행으로 확인**하다가 **뜨고 지는 FAIL** 을 잡았다:

```
run 1 PASS 68/68 ┐
run 2 FAIL  1/68 ├ ✗ #dgdw 열림 (04 규격 재사용) — got "800×1203"
run 3 PASS 68/68 ┘
```

`.dgd-box` 규격 단언(`796×1197`)이 **간헐로** 800×1203 · 806×1212 를 집었다.
800/796 = 1203/1197 = **정확히 1.005** — 세로·가로가 같은 비율이므로 레이아웃 결함이 아니라
**등장 애니메이션의 한 프레임**이다. 타임라인을 떠서 확정했다(`probe244.js`):

| t | `.dgd-box` | `el.getAnimations()` |
|---|---|---|
| 0~100ms | 732×1101 | `jzBoxIn` |
| 150ms | 782×1176 | `jzBoxIn` |
| **200ms** | **810×1218** ← 오버슛 정점 | `jzBoxIn` |
| 250ms | 806×1212 | `jzBoxIn` |
| **300ms** | **796×1197** ← 최종 | `[]` |

60 쥬시의 팝업 등장 `jzBoxIn` 은 **오버슛**(732 → 810 → 796)이고 **정확히 300ms** 에 끝난다.
게이트는 `waitForTimeout(300)` **바로 뒤에** 쟀다 — **대기값이 애니메이션 길이와 같은 값**이라
러너가 조금만 밀리면 감속 구간(800×1203 · 806×1212)을 집는다. 제품은 처음부터 옳았다.

## 2. 고친 것 — 「시간」 이 아니라 「멈췄는가」 를 기다린다

`waitForTimeout` 을 400·500 으로 **늘리는 것은 처방이 아니다**(같은 병을 뒤로 미룰 뿐이다).
잰 대상이 **실제로 멈춘 것**을 확인하고 넘어가도록 `settleBox()` 를 세웠다. 두 번 틀리고 세 번째에 맞췄다:

| 시도 | 방식 | 부하 12회 결과 |
|---|---|---|
| ① | `waitForTimeout(300)` (원본) | 4회 중 1회 FAIL — 감속 구간 800×1203 |
| ② | bbox 서명이 연속 3회 같으면 정지 (cap120 방식) | 4회 중 1회 FAIL — **got 732×1101 · «정지»** |
| ③ | **자기 애니메이션 종료 → 그 다음 bbox 연속 3회** | **12/12 PASS** |

**② 가 왜 틀렸는지가 이 작업의 핵심**이다. `jzBoxIn` 은 **시작 키프레임이 평평하다**(0·50·100ms 가 전부
732×1101). 러너가 밀리면 그 **시작 고원**에서 «연속 3회 같음» 이 먼저 차 버려서, 등장이 시작도 하기 전에
«정지» 로 속고 **시작 프레임을 규격으로 잰다.** 부하를 걸어 실제로 재현했다(`got "732×1101 (… · 정지)"`).
기하 안정성만으로는 «아직 안 움직였다» 와 «다 움직였다» 를 구분할 수 없다.

전역 `document.getAnimations()` 로도 못 기다린다 — `thBob`·`jzDotPulse`·`bgmA` 같은 **상시 아이들
애니메이션이 영원히 끝나지 않아** 무한 대기한다(cap120 이 bbox 서명을 쓴 이유가 이것이다).
답은 **잰 대상 자신의** `el.getAnimations()` 다. 상시 아이들은 **다른 요소**에 붙어 있어 걸리지 않고,
`.dgd-box` 는 등장 중 `[jzBoxIn]` → 끝나면 `[]` 로 깨끗하게 떨어진다.

```js
const settleBox = (page, sel, cap = 3000) => page.evaluate(async ({ sel, cap }) => {
  const all = () => [...document.querySelectorAll(sel)];
  const running = () => all().reduce((n, e) => n + (e.getAnimations
    ? e.getAnimations().filter(a => a.playState !== 'finished' && a.playState !== 'idle').length : 0), 0);
  const sig = () => all().map(e => { const r = e.getBoundingClientRect();
    return `${r.width.toFixed(2)}×${r.height.toFixed(2)}`; }).join('|');
  let waited = 0;
  while (waited < cap) { if (!running()) break; await wait(50); waited += 50; }   /* ① 등장 종료 */
  let prev = '', same = 0;                                                        /* ② 그 다음 정지 */
  while (waited < cap) { await wait(50); waited += 50;
    const s = sig(); same = (s === prev && s !== '') ? same + 1 : 0; prev = s;
    if (same >= 3 && !running()) break; }
  return { waited, settled: same >= 3 && !running(), box: prev || sig() };
}, { sel, cap });
```

**«멈춘 뒤에 쟀다» 자체도 단언으로 남겼다**(신설 2건). 상한 3s 까지 못 멈추면 규격 단언이 우연히
맞아떨어져도 그건 잰 것이 아니라 걸린 것이므로, 헛초록이 되지 않게 못박는다(200 ③ 방식).

## 3. 같은 병을 앓던 두 번째 자리 — 카드 규격 980×350

`.dgd-box` 를 고치고 **부하 6회**를 돌리자 이번에는 다른 자리가 떴다:

```
✗ 카드 규격 = 03 던전과 동일 980×350 — got "974×348"
✗ 아레나 카드 규격 980×350        — got "974×348"
```

974/980 = 348/350 = **0.994** — 역시 균일 배율, **60 `jzStagger` 카드 등장**의 한 프레임이다.
**부하 없이 돌린 첫 타임라인 조사에서는 카드가 t=0 부터 980×350 로 «안정» 으로 보였다**(그래서 1차 편집 때
제외했다). 등장이 이미 끝난 뒤에 조사가 시작됐던 것이고, **동시 6개**를 돌려 러너를 밀자 드러났다.
`settleBox` 를 카드 목록에도 붙였다(셀렉터에 걸리는 **전부**를 대상으로 보도록 일반화).

> **교훈** — «부하 없이 한 번 떠 보고 안정이더라» 는 경합 부재의 근거가 못 된다.
> 뜨고 지는 게이트는 **동시 실행으로 러너를 밀어 놓고** 판정해야 한다.
