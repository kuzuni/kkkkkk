안 잡히므로**, 원본을 **아틀라스 rect 를 1:1 로 그려서 만든다** — 같은 프레임을 오프스크린에
그려 «원본 잉크 bbox» 를 얻고, 화면 캔버스의 «그려진 잉크 bbox» 와 종횡을 견준다.
상자가 아니라 **잉크**를 재는 것이 핵심이다: 97 «슬롯을 꽉 채운다» 는 상자 규칙이라

## §2 판단 지점 — 97 «꽉 채우기» vs 356 «원본 비율»

등재문이 남긴 판단을 그대로 받았다. 두 규칙은 **정면으로 부딪히고 둘 다 살릴 수 없다.**

- **97**(2026-08-26) — 「카드 아트 자리는 «씬에 세우기» 가 아니라 «자리 채우기» 이므로 잉크 rect 를
  슬롯에 **늘려** 넣는다」. `drawSpriteTo` 에 `fit` 을 안 주면 `dw = W · dh = H − padY*2` 로 그린다
  = **원본 종횡을 아예 안 본다.**
- **356**(2026-08-29, 주인 지시) — 「모든 아이콘들이나 그런거 안 찌그러지게 … **원본 비율로**」.
  397 에서 같은 말을 더 세게 반복했다 — 「**게임 내에 모든 아이콘 다** 안 찌그러지게해라」.

**356 이 이긴다.** 시점이 나중이고, 주인이 두 번 말했고, 범위가 «모든» 이다.
그리고 97 이 스스로 인정한 예외가 이 두 칸뿐이었다 — 같은 부품을 쓰는 던전 카드 8장은
72 가 이미 «액자» 로 돌려 놓았고(2026-08-26 주인 재지시), 레이드·아레나만 그 전 세계에 남아 있었다.

## §3 처방 — 새 장치 0개

**`drawSpriteTo` 의 «꽉 채우기» 분기를 걷어내고, 세로 여유는 인셋으로 준다.**

1. **`TH_RDINS = { t: TH_BOBPAD, r: 0, b: TH_BOBPAD, l: 0 }` 신설**(`TH_BOBPAD` 옆).
   72 16회차가 `o.fit` 에 이미 **비대칭 인셋 객체 `{t,r,b,l}`** 을 받게 해 뒀으므로
   **새 부품이 0개**다. 121 6회차가 `padY` 로 만들던 «들썩이 들어갈 상·하 16px» 이 그대로 남는다.
2. **`raidDraw` 두 호출부** — 아레나 분기 `padY: TH_BOBPAD` → `fit: TH_RDINS` ·
   레이드 분기 `fit: rd ? 0 : TH_INS, padY: rd ? TH_BOBPAD : 0` → `fit: rd ? TH_RDINS : TH_INS`.
3. **`drawSpriteTo` 의 `ct`(contain 인가) 분기와 `o.padY` 를 선언째 삭제.**
   호출부가 셋뿐이고(`petPaint` · `raidDraw` ×2) 셋 다 `fit` 을 주므로 **소비처가 0** 이 됐다
   (295-②·399·460 죽은 코드 금지). ⚑ **이게 «증상» 이 아니라 «재발 경로» 를 막는 부분이다** —
   남겨 두면 `fit` 을 빠뜨린 다음 호출부가 조용히 다시 늘린다.

## §4 게이트 — 지우지 않고 **방향을 뒤집었다**(333 처방)

⇒ 한 항을 **셋으로 갈라 방향을 뒤집었다**:

| | 묻는 것 | 왜 |
|---|---|---|
| ⓐ | 그려진 잉크 종횡 ÷ **원본 잉크** 종횡 = ×1.000 ± 0.5% | 356 정책(자는 `verify356 [S3]` 과 같은 0.5%) |
| ⓑ | **담기는 축**은 여전히 칸을 채운다(옛 허용치 그대로) | 97 의 살아 있는 절반 — 칸을 놀리지 않는다 |
| ⓒ | **남는 축**의 크기 = 원본 종횡이 정한 값 ±3px | 그림이 더 쪼그라들면 빨개진다 |

ⓒ 가 «무르게 푼 수리» 를 막는 항이다. ⓑ 만 있으면 등방이 아니어도 통과하고, ⓐ 만 있으면
