## 2. 뿌리 — 등재문의 두 처방 후보가 **둘 다 표본을 잘못 짚고 있었다**

등재문은 «566 이 553 행을 7칸으로 정리해서 **표본이 낡았다**» 로 진단하고
ⓐ(살아 있는 8칸 행으로 갈아 끼우기) · ⓑ(행 이름 대신 개수로 묻기)를 후보로 냈다.
**재현이 그 진단을 한 칸 정정한다** — 낡은 것은 표본이 아니라 **표본을 가리키는 손가락**이다.

`probe566.js` 156행(수리 전):

`origin/main` 은 **566 자신의 push 로 움직인다.** 566 이 수리를 올린 순간
«수리 전» 이라는 이름이 «수리 후» 를 가리키게 됐다. 그래서:

| 항 | 무엇을 읽나 | 566 push 전 | 지금 |
|---|---|---|---|
| [4-a] | `origin/main` 의 553 | 8 (초록) | **7 (빨강)** |
| [4-b] | `origin/main` 의 512 | 7 (초록) | 7 (초록 — 값이 안 변해 **우연히** 살아남았다) |

⚑ **빨간 한 항보다 나쁜 것은 남은 두 항이었다.** [4-a] 와 [4-c] 가 **같은 내용**을 읽게 되면서
«수리 전 8 ↔ 수리 후 7» 이라는 이 절의 **대조가 통째로 사라졌다** — [4-b]·[4-c] 는
자기 자신과 비교하는 **헛초록**이었다. 빨간 항 하나만 초록으로 되돌리는 수리는

## 3. 처방 — 등재문의 ⓐ·ⓑ 를 **둘 다 기각**하고 «손가락» 을 고정했다

- **ⓐ 기각** — «지금도 8칸인 살아 있는 행» 으로 갈아 끼우면 **572**(«칸 수 7 초과» 131행 정리)가
  그 행을 7칸으로 만드는 순간 **똑같은 방식으로 또 썩는다.** 573 등재문 자신이
  «572 와 같은 자리» 라고 적어 두었다 — 갈아 끼우기는 다음 세션에 부패를 물려주는 것이다.
- **ⓑ 기각** — «칸이 7을 넘는 행이 몇 건인가» 로 물으면 572 가 끝나는 순간 **0 건**이 되어
  항이 뜻을 잃는다(폐기될 값을 게이트로 굳히는 310·333 계열).
- **채택** — «수리 전» 을 **고정된 커밋**에서 꺼낸다. 저장소 안에 이미 선례가 있다:
  `probe360.js` 43행 `const BEFORE_REF = process.env.P360_BEFORE || 'dae7b97'`
  (`probe359`·`probe501` 도 같은 꼴). 566 만 이 관행 밖에 있었다.

### ⚠ SHA 를 손으로 박기만 하면 이 저장소에서는 또 썩는다

`ROUTINE.md` 서두가 «이력 정리(2026-08-30): 캡처 PNG 이력 제거» 를 적어 두었다 —
**이력이 재작성되면 SHA 가 통째로 갈린다.** 그래서 ref 를 **커밋 메시지로 찾고**
손으로 박은 SHA 는 폴백으로만 둔다:

```js
function pickBefore() {
  if (process.env.P566_BEFORE) return { ref: process.env.P566_BEFORE, how: '…' };
  for (const msg of ['wip(566)', 'done(566)']) {
    const sha = gitQ(['rev-list', '-1', '--fixed-strings', '--grep=' + msg, 'HEAD']);
    if (!sha) continue;
    const parent = gitQ(['rev-parse', '--short', sha + '^']);
    if (parent) return { ref: parent, how: '`' + msg + '` 의 부모' };
  }
  return { ref: BEFORE_FALLBACK, how: '폴백 SHA(…)' };
}
```

⚠ **ref 는 «정체» 로 고르고 값은 따로 단언한다.** «553 이 8칸으로 보이는 ref» 를 찾아 고르면
[4-a] 가 자기를 증명하는 **헛초록**이 된다(무르게 푼 수리). 고르는 기준은
«566 의 수리 커밋의 **부모**» 하나이고, 8칸이라는 값은 그렇게 고른 뒤에 묻는다.

## 8. 교훈

1. **«표본이 낡았다» 와 «표본을 가리키는 손가락이 움직인다» 는 다른 병이다.**
   앞의 것은 표본을 갈면 낫고, 뒤의 것은 갈아도 다음 수리에서 또 걸린다.
   재현기가 «수리 전» 을 말할 때 그 ref 가 **자기 수리로 움직이는지** 부터 본다.
2. **빨간 항보다 그 옆의 초록이 위험하다.** [4-a] 가 빨개진 그 변경이
   [4-b]·[4-c] 를 «자기 자신과 비교» 로 만들었다 — 빨간 하나만 되돌리는 수리는
   헛초록 둘을 굳힌다. 절이 통째로 뜻을 잃었는지부터 확인할 것.
3. **이력을 재작성하는 저장소에서는 SHA 도 «움직이는 ref» 다.** 커밋 메시지로 찾고
   SHA 는 폴백으로 둔다.
4. **고정 ref 는 «정체» 로 고르고 값은 따로 묻는다.** «기대값이 나오는 ref» 를 고르면
   단언이 자기를 증명한다.
5. **«수리 전 트리에서도 같다» 는 곁다리 등재의 충분조건이 아니다** — 환경 결손(여기서는
   `playwright` 부재)은 두 트리에서 똑같이 빨갛다. §7 참조.
