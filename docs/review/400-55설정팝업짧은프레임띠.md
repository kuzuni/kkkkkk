## 2. 처방 — 두 자리

### ① 띠 (390 과 같은 상수)

```css
#app.shortf #cfw{padding:142px 0 180px}
```

142 = `.pedge` 하변 · 180 = 탭바. `.shortf`(frameH < 1842) 안에서만 갈라 **2280·1920 은 선언이 안 붙는다**(351-③).
142+180 = 322 는 프레임과 무관한 상수라, 짧은 프레임에서 상자는 늘 `max-height:100%` 상한에 걸려
**상변이 정확히 142 · 하변이 정확히 탭바 상변**에 선다.

### ② 눌림의 배분 — `--sq` 지분

본문 아래쪽 9자리를 `top` → **`bottom` 앵커**로 바꿨다. 값은 전부 항등식
`bottom = 1228 − (top + height)` 라 **2280 은 원소별 Δ0px**(1228 = 2280 에서의 본문 패딩상자 높이).
그 위에 눌리는 양을 변수로 얹는다:

```css
.cf55{ --sq:clamp(0px, calc(1669px - var(--frameh, 2280px)), 69px) }
```

`1669 = 1347 + 322` 이므로 `--sq` = 상자가 실제로 눌리는 px 다(1600 에서 69 · 1669 이상에서 0).
각 자리는 자기 **지분**만큼 그 값을 뺀다 — `calc(534px - var(--sq) * 0.695652)` 꼴.

## 3. ⚑ 1회차가 기각된 이유 — «한 장이 다 받으면 안 된다»

1회차는 «`top`+`bottom` 을 둘 다 가진 리스트 한 장만 줄어든다»(LESSONS 22-④ · 54 랭킹 처방)로 끝냈다.
기하는 완벽했다 — `probe400` 9/9 · `probe351` D7 **0건** · 2280 원소별 Δ0px · SMOKE PASS.
**그런데 비평가 둘이 각각 6·5 를 줬고, 둘 다 최저 축이 ④ 조작성이었다.**

| | 2280 | 1회차 1600 | 판정 |
|---|---|---|---|
| 행 pitch | 84.8 | **73.3** (−13.5%) | |
| 토글 컨트롤 높이 | 69 | 69 (0%) | 안 줄었다 |
| 라벨 잉크 | 30 | 30 (0%) | 안 줄었다 |
| **이웃 토글 사이 데드존** | 15.8 | **4.3** (**−73%**) | ← 여기서 갈렸다 |

두 비평가가 **각자 다른 자로 같은 결론**에 왔다: 잘림 0 · 겹침 0 · 라벨 잉크 0% 변화 ·
행 구분도 또렷 — **오직 «표적 간격» 하나**가 점수를 정했다(CH: «시각적으로는 멀쩡하고 손가락에서만 무너지는 유형»).
그리고 둘 다 같은 뿌리를 짚었다: **버튼 1개에 198px 을 쓰는 계정 패널과 푸터는 그대로 둔 채,
화면에서 유일하게 표적이 조밀한 구역에서만 69px 을 뽑았다.**

⚑ **교훈**: 「눌림은 늘고 줄 수 있는 한 장이 받는다」는 이 저장소의 관용구(22-④)인데,
**그 한 장이 «터치 표적이 늘어선 리스트» 일 때는 관용구가 틀린다.** 자로는 안 보이고 비평가만 본다.
