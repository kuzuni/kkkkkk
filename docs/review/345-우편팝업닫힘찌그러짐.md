## 1. 재현 — 등재문의 가설이 **맞았고, 숫자는 예상보다 훨씬 크다**

`tools/probe345.js` 는 껍데기 5종을 열고 `closeModal()` 한 뒤 ~16ms 간격으로
**레이아웃 박스**(`offsetWidth/offsetHeight` — `scale` 애니의 영향을 안 받는다)와
**그려진 박스**(`getBoundingClientRect` — scale 포함)를 같이 찍는다.
닫힘 연출이 «균등 축소»(`jzBoxOut` scale .94)라면 **레이아웃 박스는 첫 프레임부터 끝까지 열림과 같아야 한다.**

수리 전 실측:

| 껍데기 | 화면 | 열림 `.mbox` | 닫힘 첫 프레임 | 딤 패딩 |
|---|---|---|---|---|
| `.ml69` | 69 우편함 | 898×**1303** | 898×**230** (Δ **−1073**) | 126/91 → 126/91 |
| `.q22` | 22 퀘스트 | 898×**1497** | 898×**230** (Δ **−1267**) | 126/91 → 126/91 |
| `.at70` | 70 출석 | **940**×1077 | **898**×**1098** (Δ −42×+21) | **159/70 → 126/91** |
| `.sk8` | 08 스킬 세부 | 898×**1002** | 898×**1076** (Δ +74) | **132/91 → 126/91** |
| `.rl16` | 16 룰렛 | 898×1199 | 898×1199 (Δ0) | 불변 |

우편이 **1303 → 230** 인 것은 «기본 규격으로 조금 돌아간» 정도가 아니다 —
본문이 `.ml69 .mbody{position:relative;height:1189px}` 로 **절대 높이를 갖는 자리**라, 껍데기 클래스가
떨어지는 순간 그 1189px 이 통째로 사라지고 **헤더 + 하단 버튼(230px)만 남는다**.
그 납작한 상자가 0.12초 동안 페이드하며 축소되는 것이 주인이 본 «찌그러짐» 이다.
퀘스트(1497 → 230)도 같은 병이고, 출석은 **딤 패딩까지 159/70 → 126/91 로 바뀌어** 상자가 위치까지 옮긴 채 닫힌다.

`rl16` 은 **대조군**이다 — 현행 `openRoulette()` 은 껍데기 클래스를 안 붙이고 A5 기본 규격 그대로 쓰므로
되살릴 것이 없고 수리 전에도 균등 축소였다(§5 ⓐ).

## 2. 뿌리 — «가시성 스위치» 와 «치수 override» 를 한 번에 뗀다

```js
function closeModal(){ $('modal').classList.remove('on', 'sk8', 'rl16', 'q22', 'ml69', 'at70'); }
```

`on` 은 **가시성 스위치**(`#modal{display:none}` / `#modal.on{display:flex}`)이고
나머지 다섯은 **치수 override(껍데기)** 다. 이 한 줄이 둘을 같은 순간에 뗀다.

60 쥬시는 이 클래스 변화를 `MutationObserver` 로 보고 **그 뒤에** `jzClose()` 로 들어가
`el.style.display = disp` 로 화면을 되살려 `.12s` 역재생을 돌린다 —
즉 **연출이 도는 0.12초 내내 껍데기는 이미 없다.** 상자는 A5 기본 규격으로 리플로우된 채 축소된다.

「우편이 유독 심한」 이유도 여기서 나온다: 껍데기가 «조금 다른 치수» 가 아니라 **본문의 높이 전부**를 쥐고 있어서다.

## 3. 처방 — 닫는 순간의 클래스를 스냅샷해 **연출 동안만** 되살린다

지시서 처방 두 가지 중 **«jzClose 가 닫는 순간의 클래스 목록을 스냅샷해 `.jz-c` 동안 유지»** 를 골랐다.
다른 쪽(«껍데기 클래스를 offC 시점에 떼기»)은 `closeModal()` 을 고쳐야 하는데, 그 함수는 **호출부가 30곳 가까이**고
그중 상당수가 병렬 세션의 구간이다. 스냅샷 쪽은 60 쥬시 모듈 **한 곳**만 만지고 껍데기 5종 전부를 한 번에 닫는다.

`index.html` 변경(순증 4줄 + 손질 3줄, 나머지는 주석):

1. **MO 에 `attributeOldValue:true`** — 닫기 직전의 클래스 목록을 알아야 «무엇이 떨어졌는지» 를 안다.
   한 배치 안에서 **가장 앞선 `oldValue`** 를 쓴다(`closeModal` 은 레코드 1장이지만,
   여는 쪽처럼 `remove(...)` → `add(...)` 로 두 번 만지는 경로가 있다).
2. **`jzShellBack(el, prevCls)` 신설** — 떨어진 클래스 중 **껍데기만** 되살리고 그 목록을 돌려준다.
3. **`offC`** — 연출이 끝나면 되살린 것을 뗀다.

### ★ 가리는 기준을 하드코딩 목록으로 두지 않았다

되살리면 안 되는 것이 딱 하나 있다 — **가시성 스위치 `on`**. 그것까지 되살리면 `offC` 가 inline display 를
되돌려도 클래스로 계속 떠 있어 **안 닫히는 팝업**이 된다.

그런데 `['sk8','rl16','q22','ml69','at70']` 같은 목록을 여기에 또 적으면 **그 목록이 여섯 번째가 된다** —
이미 `showModal`·`closeModal`·`openMail`·`openAttend`·`openQuest` 다섯 곳에 흩어져 있고,
LESSONS 265 가 «껍데기 클래스를 새로 만들면 다섯 곳을 같이 고쳐야 한다» 를 회피 사유로 적어 둔 그 목록이다.
새 껍데기가 생기는 날 여섯 곳 중 하나만 빠지면 그 팝업만 조용히 다시 찌그러진다.

그래서 목록 대신 **질문**을 적었다:

```js
el.classList.add(c);
const d = getComputedStyle(el).display;   /* 이 클래스 하나만 도로 붙이면 화면에 뜨는가? */
el.classList.remove(c);
if(d === 'none') back.push(c);            /* 안 뜬다 = 껍데기(치수 override) — 되살린다 */
```

뜨면 가시성 스위치이므로 제외, 안 뜨면 껍데기다. **새 껍데기가 생겨도 이 코드는 그대로 맞는다.**
판별은 `el.style.display` 를 되살리기 **전에** 해야 한다(되살린 뒤엔 무엇을 붙여도 «뜬다» 로 읽힌다) —
그래서 `jzShellBack` 이 `jzKind`/`jzDimBg`/`jzDimKids` 보다 **앞**에 있다. 부수 효과로 그 셋도
«열려 있던 그대로» 의 배경색·자식 기하를 읽게 됐다(우편 딤 `rgba(0,0,0,.56)` 이 닫힘 동안 유지된다).

### 경합 — 되살린 클래스를 «연 쪽» 에게서 뺏지 않는다

연출 도중(0.12초)에 다른 팝업이 열릴 수 있다. 그때 `offC` 가 무턱대고 되살린 클래스를 떼면
**방금 열린 팝업의 껍데기를 뜯는다**(같은 팝업을 다시 열었으면 `ml69` 를 떼 버린다).
그래서 `offC` 는 inline display 를 되돌린 **뒤** 한 번 더 묻는다 — 지금도 `display:none` 이면 «아직 닫힌 것» 이니
내가 되살린 것을 떼고, 떠 있으면 그 클래스 상태는 «연 쪽» 의 것이므로 **손대지 않는다**(게이트 §4).

## 4. 게이트 `tools/verify345.js` — **98/98 PASS**

| 절 | 재는 것 |
|---|---|
| §1 | 껍데기 5종 전수 × t40·t80ms — 레이아웃 폭·높이·**본문 높이**·`max-height`·**딤 패딩** 이 열림과 Δ0 · 그려진 박스의 **가로/세로 배율 차 ≤ 0.004**(찌그러짐 = 두 배율이 갈리는 것) · «정말 축소 중인 프레임 ≥ 1장» |
| §2 | 연출이 끝나면 `display:none` · `on` 없음 · **되살린 껍데기 잔여 없음**(안 굳는다) |

| §4 | 경합 ① 닫는 중 퀘스트로 전환 → `q22` 살아 있고 `ml69` 잔여 0 · 본문 1383 ② 닫는 중 **같은 팝업 재열기** → `ml69` 살아 있고 상자 1303 / 본문 1189 |
| §R | 되돌림 시험 — `jzShellBack` 을 «아무것도 안 되살리는» 것으로 갈아 끼우면 **1303 → 230 · 본문 1189 → 116** 으로 §1 이 빨개지고, 원복하면 초록 |

**헛초록을 막은 두 자리**:
- §1 의 «축소 중인 프레임 ≥ 1장» — 연출이 아예 안 돌면 «레이아웃 박스 불변» 은 **공짜로 참**이다.
  이 항이 없으면 `jzClose` 를 통째로 지워도 §1 이 초록이다.
- §1 이 «높이가 1303 이다» 가 아니라 «**열림 프레임과 같다**» 를 묻는다 — 상수를 박으면
  껍데기 치수가 바뀌는 날 이 게이트가 «틀린 값을 지키는» 자리가 된다.

`.mbox` 만이 아니라 **`.mbody` 높이**를 같이 묻는 것도 같은 이유다. 우편의 결손이 실제로 산 자리가 거기다.
