작업 단위 **02**. 대상 구역은 «② 스테이지 헤더 · 우상단 메뉴 버튼 · ④ 좌하단 유틸 · ④ 우하단 미션 배너 · 배속 버튼» 5개.

## 0. 좌표계 정정 (이 회차의 핵심 발견)

A2 측정표는 전투 캔버스 top 을 **229**(좌측 프로필 플레이트 하단)로 잡았지만,
**전체 폭 기준 상단 HUD 바 하단은 188** 이다(A3 측정표 §19 와 일치. 좌측 플레이트만 38px 더 돌출).

프레임(1080×1920)의 `#stagearea` 는 y=104 에서 시작하고 `#top` 높이가 104 이므로,

| | 레퍼런스(2340) | 프레임(1920) |
|---|---|---|
| 전투영역 top | 188 | 104 |
| 전투영역 bottom | 2160 | 1740 |

- 상단 고정 요소 → `stagearea 기준 top = ref_y − 188`
- 하단 고정 요소 → `stagearea 기준 bottom = 2160 − ref_bottom`

229 를 쓰면 상단 요소가 전부 **41px 아래로** 내려간다. 이후 세션은 **188** 을 쓸 것.

### ①번이 1~3점인 이유 = 비평 시점의 캡처 문제였다 (실제 결함 아님)

두 비평가 모두 «우상단 4분할 메뉴 버튼이 100% 부재» 를 최대 감점 사유로 들었다.
그러나 버튼은 구현돼 있었고, **`#sideR` 의 이벤트 아이콘이 같은 좌표(100×99px 완전 겹침)에
나중에 그려져 버튼을 덮고 있었다.** 비평 캡처를 찍은 뒤 겹침을 발견해 이미 고쳤으므로
(§ PROGRESS «02 비고» 4번) 이 감점은 2회차에서 사라진다.
→ **레퍼런스 우측 컬럼 1행은 이벤트가 아니라 메뉴 버튼**이라는 사실이 비평가 2인에게서 독립적으로 확인됐다.

### 두 비평가가 «공통으로» 지적한 실제 결함 → 2회차에서 전부 수정

| # | 지적 | 수치 | 조치 |
|---|---|---|---|
| 1 | 미션 문구가 초록 보상칸을 침범해 글자가 잘림 | 우측 거트 58px → 2px, 55px 오버플로 | 컨테이너 폭 265 → **217** (우측단 x897, 레퍼 x892) + `text-overflow:ellipsis` |
| 2 | `STAGE` 검정 외곽선이 너무 얇음 | 코어 바깥 5.5px → **2px** | `-webkit-text-stroke` 4 → **11** + `text-shadow:0 4px 0 #000`. 수정 후 실측 코어 바깥 **위 7 / 아래 6** |
| 3 | 배너 레드닷이 큼 + 우측으로 밀려 잘림 | Ø24~27 → Ø30, 중심 x +7 | **직접 재측정: Ø24 (x1045..1068, 중심 1056.5/1865)** — 비평가가 옳았다. Ø30 → **Ø24**, 위치 보정 |
| 4 | 채팅 말풍선 글리프 과대 | +14~16%, 버튼 점유율 56% → 64% | font-size 62 → **54** |
| 5 | 마을 아트가 라벨 축에서 우측 이탈 | 10.5~11.5px (레퍼는 1.5px) | `translateX(-11px)` |
| 6 | 해골 흰 글리프 폭 부족 | 51 → 41 (−20%) | font-size 46 → **53** + `scaleY(.88)` |
| 7 | 배너 1행/2행 폰트 위계 역전 | 1행 +6%, 2행 −9% | 1행 34 → **32**, 2행 30 → **32**(잉크 20 → 22), 상단 패딩 14 → **11** |
| 8 | 진행바 노랑 채움 0px | 레퍼 28% | **결함 아님** — 캡처 시점 킬수 0. 이후 캡처는 레퍼와 같은 28% 상태로 맞춰 찍는다 |

### 비평가 지적 중 **채택하지 않은** 것

| 지적 | 이유 |
|---|---|
| 진행바 채움 높이를 트랙과 같은 24px 로 | **오판.** 실측 채움은 `y364..375 = 12px`, 트랙 안쪽 6px inset (비평가 A 도 «두께 11px» 로 같은 값) |
| 캡슐 알파 0.40 → 0.31 | 우리 전투 배경이 레퍼런스의 물색이 아니라 어두운 씬이라 관측 알파가 다르게 계산된 것. CSS 값은 실측대로 `rgba(0,0,0,.30)` |
| 미션 문구 잉크 24.5px | 흰 잉크 직접 측정은 **22px** (`y1920..1941`). 비평가 B 도 22 로 봤다 |

| 해골 눈구멍 색 네이비로 | 이모지 글리프 내부라 CSS 로 못 바꾼다 |

## 최종 상태 (3회차 반영 후)

- 헤드리스 1080×1920: **콘솔 에러 0건, 요소 겹침 0건**
- 3회차 수정은 **비평가 재채점 없이** 직접 픽셀 실측으로 검증했다(각 항목 «검증» 열 참조).
  회차 예산·시간 초과로 3번째 비평 루프는 돌리지 않았다. **확정 점수는 2회차의 5/10 이다.**

### 남은 문제 (9점 미달 원인)

1. **아트 리소스 부재** — 해골·마을·채팅·보상상자·자물쇠가 전부 이모지 대체다.
   비평가 2인이 공통으로 «글리프 종횡비 10~20% 어긋남», «해골 눈구멍 명암비 4:1 → 1.3:1»,
   «이모지 내부 색을 CSS 로 못 바꿈» 을 지적했다. **A1·A3·A4 와 동일한 한계**이며 아트가 들어와야 회수된다.
2. **게임용 좁은 한글 서체 부재** — 미션 문구·마을 라벨을 `scaleX()` 로 압축해 폭만 맞추고 있다.
   A1 비고 2번과 같은 트레이드오프.
3. **배너 내부 정밀 좌표의 근거가 약함** — 금색 바탕 위 금색 글자라 마스크 분리가 안 돼
   1행 라벨·보상칸 내부는 서브에이전트 육안 실측에 의존했다(측정표 §7 참조).

| 단면 | 레퍼런스 | 뜻 |
|---|---|---|

> **교훈**: «틈이 보인다» 를 «이 레이어를 통째로 올려라» 로 옮기면 다른 축에서 반대 결함이 생긴다.
