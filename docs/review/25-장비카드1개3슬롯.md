## 0. 왜 비평 루프(3-나)를 돌리지 않았나

**레퍼런스 06 은 이 설계를 담고 있지 않다.** ref 는 캐릭터 카드 **2장**(햄지·매옹이) × 부위 슬롯 각 2칸 +
하단 잠금 슬롯 3개인데, 확정된 우리 설계는 카드 **1장** × 슬롯 **3칸** · 잠금 행 **폐기**다.
두 그림의 «요소 배치·상대 크기·여백» 을 대조하면 **의도된 설계 차이가 그대로 감점**으로 돌아와
점수가 무의미해진다(04 비고 1 «캡처 상태가 레퍼런스와 다르면 그 회차 비평은 통째로 무효다» 와 같은 함정).

그래서 지시서 [3]-(가) 에 준해 **채점 없이 실측 검증**으로 처리하되, 채점 대신
**«카드 내부 요소의 규격이 레퍼런스 카드 1개와 같은가» + «캡처 자체에 결함이 있는가»** 만
독립 검수자 1명에게 PIL 픽셀 스캔으로 확인시켰다(§4). 이 판단이 옳았다 — 검수는 설계 차이를
감점하지 않고도 **실제 결함 3건**을 잡아냈다.

## 5. 인수인계 (완료 — 기록용) — 코드가 main 에 없었다

**sess-1828 은 git push 자격증명이 없었다.** `git fetch` 는 익명으로 되지만 push 는 github.com 이
**401 `could not read Username`** 을 돌려준다(같은 시각 다른 워커들은 정상 push 했다 — 세션 개별 문제).
GitHub MCP `push_files` 는 파일 **전체 내용**을 실어야 하는데 `index.html` 이 **438KB** 라 그 경로로도
올릴 수 없었다. `create_session` 으로 자격증명 있는 형제 세션을 띄우는 것도 이 세션에선 막혀 있었다.

그래서 **코드 변경분만 패치로** 올려 둔다. 25 를 이어받는 워커는 이것만 하면 된다:

정하고 자물쇠 탭을 전부 없애라고 한다. 현재 3개 시트(`06 .eqtb` · `07 .sk-tab` · `26 .sk-tab`)의
**4번 칸은 아직 `기타`(🔒)** 다.

**넘기는 이유**: PROGRESS 50 행이 «영웅 서브탭 … 의 **코스튬 탭**» 을 자기 범위로 명시하고 있고,
50(코스튬 팝업)이 아직 없어 지금 탭만 `코스튬` 으로 바꾸면 **목적지가 없는 빈 탭**이 된다
(`HEROBODY` 에 `cos` 키가 없어 패널 본문이 통째로 비고, smoke 의 서브탭 검사가 그 상태를 통과시킨다).
**50 이 아바타 기능을 이관하면서 세 시트의 4번 칸을 한 번에 `코스튬` 으로 바꾸는 것이 맞다** —
그래야 세 바가 어긋나는 중간 상태가 생기지 않는다.
