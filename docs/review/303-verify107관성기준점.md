## 1. 원인 — 기준점이 «관성의 마지막 프레임» 이었다

236 이 세운 [I] 는 손 뗀 뒤 rAF 마다 `[t, scrollTop, dsGlide]` 를 적고,
**`dsGlide` 가 1 로 적힌 마지막 프레임**의 scrollTop 을 기준으로 그 뒤가 움직였는지 본다.

```js
const glideEndIdx = tr.map(r => r[2]).lastIndexOf(1);
const settleT = glideEndIdx < 0 ? 0 : tr[glideEndIdx][0];
const rest = tr.filter(r => r[0] >= settleT);      /* ← 관성 마지막 프레임이 rest[0] */
const moved = rest.filter(r => Math.abs(r[1] - rest[0][1]) > 0.5);
```

그런데 한 프레임 안에서 **제품이 기록기보다 먼저 돈다**(`dsFling` 의 rAF 가 기록기보다 먼저 등록된다):

```js
step:  box.scrollTop = r.acc + sp*dt;   /* 마지막 한 걸음을 여기서 밟고 */
       sp *= 0.95^(dt/16.67);
       if(|sp| < DS_VMIN(0.02) || !moved){ dsGlide = 0; return; }   /* 같은 프레임에 0 을 놓는다 */
rec :  [t, scrollTop, dsGlide] 를 적는다   /* 기록기는 그제서야 0 을 본다 */
```

⇒ **`dsGlide=1` 로 적힌 마지막 프레임은 «마지막 한 걸음을 아직 안 밟은» 값**이다.
그 한 걸음이 다음 프레임에 «멎은 뒤 움직였다» 로 잡힌다.

**왜 간헐인가** — 걸음 크기가 `sp*dt` 이고 종료 조건이 «감쇠 후 `|sp| < 0.02`» 라
**프레임 간격에 정비례**한다. `scrollTop` 은 정수 픽셀로 반올림되므로:

| 프레임 간격 dt | 마지막 걸음 `sp*dt` | 정수 반올림 | 옛 ⓒ |
|---|---|---|---|
| 16.7ms (한가함) | 0.02/0.95 × 16.7 = **0.35px** | 0 | 초록 |
| 25ms (이 러너 평상시) | 0.02/0.95^1.5 × 25 = **0.53px** | 0~1 | 초록(대개) |
| **34ms (붐빔 — dt 상한)** | 0.02/0.95^2.04 × 34 = **0.76px** | **1** | **빨강** |

문턱 `0.5px` 이 0.35 와 0.76 **사이에** 놓여 있었다. 등재문의 실측이 게이트 45개 일괄 재실행에서
갈라져 나온 것도 이 때문이다 — **러너가 붐빌 때만** 빨갛다.

**236 의 전제가 왜 죽었나**: 236 은 옛 «900ms 상수» 를 «관성이 실제로 멎을 때까지» 로 바꿔 옳게 닫았지만,
기준점을 관성의 **마지막** 프레임에 뒀다. 그 프레임에 최종 값이 적혀 있는 것은 한가한 기계에서
마지막 걸음이 **0px 로 반올림되던 덕분**이었다 — 900ms 상수가 «격자가 짧아 관성이 바닥에 걸리던
덕분» 에만 참이었던 것과 **같은 종류의 우연**이다(236 review §2).

## 4. 고친 것 — 문턱이 아니라 «자를 대는 자리»

`tools/verify107.js` [I] ⓑ·ⓒ 의 기준점 한 줄:

```js
- const rest = tr.filter(r => r[0] >= settleT);   /* 관성 마지막 프레임 */
+ const rest = tr.slice(glideEndIdx + 1);         /* 관성이 멎은 것을 «본» 첫 프레임 */
```

- **문턱(0.5px)도, «한 프레임 더 기다리기» 같은 상수도 만지지 않았다**(LESSONS 288-① — 문턱을
  정교하게 만들지 말고 방해 항을 끌 손잡이를 찾아라). 방해 항은 «마지막 한 걸음» 이고,
  그 손잡이는 자를 대는 **자리** 다.
- `glideEndIdx + 1` 은 rAF 안에서 기록기와 제품 중 **누가 먼저 돌든** «step 이 끝난 뒤» 가
  보장되는 첫 프레임이라 **콜백 순서에 기대지 않는다**(step→rec 이면 그 프레임이 최종값,
  rec→step 이면 그 다음 프레임이 최종값 — 어느 쪽이든 `glideEndIdx+1` 이후는 전부 최종값이다).
- ⓐ 가 «관성이 안 멎었다» 로 빨간 경우 `rest` 가 빈다 → `rest[0]` 을 그냥 읽으면 게이트가
  **크래시**한다(옛 코드는 우연히 안 비었다). `[I] 관성이 멎은 뒤 프레임이 0개다` 로 말하고 넘어가게 막았다.

**감시창(4200ms)·문턱·항목 수는 그대로다.** ⓐⓑⓒⓓ 넷 다 살아 있다.

## 5. 되돌림 시험 — «넓혀서 초록» 이 아님을 못 박는다

기준점을 한 칸 옮긴 것이 «1px 짜리 진짜 밀림» 까지 같이 눈감게 만들었다면 그건 고친 게 아니라
게이트를 눈멀게 한 것이다. 그래서 `tools/neg236.js` 에 **N7** 을 신설했다 —
관성이 멎은 뒤 1.5초에 **1px 밀리고 되돌아오지 않는다**(`want: [I]ⓒ` · `not: ⓐⓑⓓ[A]`).
아래로 민 것이라 ⓓ 는 초록이어야 하고, ⓒ 만 빨개져야 한다.
