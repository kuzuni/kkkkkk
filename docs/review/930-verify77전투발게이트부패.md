## 1. 재현 — 등재문 그대로였다

```
[D] 상점 열고 자동 전투 10초 — 새 fly/plus 는 전부 #fxlc 에
  ✓ 592 — 잡몹 킬만 도는 10초에는 재화 연출이 한 건도 안 난다 (#fxlc 0 · #fxl 0)
  ✗ 살아 있는 전투 발조차 #fxlc 에 0건 (보너스 +59 · 전투 발 라우팅이 죽었다)
  ✓ #fxl 은 0건 (팝업 위로 새는 연출 없음)
VERIFY77 FAIL (1)
```

보너스 **+59** 는 들어오는데 연출만 0 — 즉 **사건은 났고 그림만 없다**.

## 2. 갈래를 가른 것 — 등재문의 처방(«살아 있어야 하는 축을 먼저 세라») 그대로

`FX_COMBAT_FX`(index.html **25737**)는 넷 다 꺼져 있다:

```js
const FX_COMBAT_FX = { kill:false, stageClear:false, waveBonus:false, clearGold:false };
```

`fxAt(…, 'combat')` 이 찍히는 자리는 소스 전체에 **셋뿐**이고(25755 ⑴킬 · 27315 ⑵클리어 · 27343 ⑶파도)
셋 다 이 표의 뒤에 있다 ⇒ **기본 설정에서 전투 발 태그는 한 번도 안 찍힌다.**
이 사실은 이미 저장소 안에 적혀 있었다 — index.html **41689** 원장의 «654 정오표»가
«`FXFLY_MAX_C` · `fxOrigBurstT` · combat 롤링 분기 · `fxSrc` 의 combat 갈래는 **런타임 도달이 0**» 이라고
못박고 있다. ⇒ **갈래 ⓐ 게이트 부패**(ⓑ «층 라우팅을 잃었다» 는 기각 — §4 가 실측으로 못박는다).

⚠ **자가 한 절 안에서 서로 반대를 묻고 있었다** — [D-a]는 «592 가 껐다»(연출 0이면 초록),
[D-b]는 «전투 발이 `#fxlc` 에 있어야 한다»(연출 0이면 빨강). 592 는 ⑴만 껐으므로 552·592 시절엔
둘이 양립했지만, **654 가 ⑵⑶까지 끄면서 양립이 깨졌다.** 333-① 그대로 —
고칠 곳은 제품이 아니라 **나중에 옳아진 쪽(654)의 반대편**이다.

## 3. 처방 — 자리를 비우지 않고 축을 넷으로 갈랐다 (333-②)

표본(스테이지 클리어 보너스)은 **그대로 두고** 무엇을 묻는지를 갈랐다:

| 항 | 묻는 것 | 주인 |
|---|---|---|
| [D-a] | 잡몹 킬만 도는 10초엔 연출 0건 | 592 (무변경) |
| **[D-b]** | 클리어 보너스는 **지급은 그대로(gold>0), 연출만 0** | **654 이관(방향 반전)** |
| **[D-c]** | 그 축**만** 되살리면 코인이 **상점 팝업이 열린 채로도** `#fxlc` 로만 간다 | **77 본래의 규칙** |
| **[D-d]** | 시험이 제품 스위치를 원복했는가 | 위생([B-R] 과 같은 꼴) |

**[D-c] 가 이 수리의 본체다.** [D-b] 만 넣고 끝냈으면 654 를 되돌리는 날 이 절은
«비어서 초록» 이 된다(333-② «표본 수가 아니라 그 축이 무엇을 재는가»).
[D-c] 는 654 원장이 «되돌림은 이 표 한 줄» 이라고 못박은 그 한 낱말(`FX_COMBAT_FX.stageClear`)을
그대로 써서 **제품의 진짜 경로**로 77 의 규칙을 다시 묻는다 — [C] 는 `elementFromPoint` 합성 프로브라
«제품이 그 층을 실제로 고르는가» 는 안 본다.

⚑ **`verify654` [R1]·[R4] 와 겹치지 않는다** — 654 는 «코인이 다시 나는가/어느 층인가» 를
팝업 없는 장면에서 묻고, [D-c] 는 **상점 페이지가 열린 통합 장면**에서 묻는다(77 의 관할).

## 4. 무르게 푼 수리가 아님 — 되돌림 시험 2종(제품에 회귀를 주입해 실측, 둘 다 원복)

**① 654 의 무음을 되돌린다**(`stageClear:false` → `true`):

```
  ✓ 654 — 클리어 보너스 골드는 그대로 들어온다 (+59 …)
  ✗ 654 무음이 깨졌다: #fxlc 5 · #fxl 0        ← [D-b] 가 잡는다
```

**② 층 라우팅을 부순다**(`L = (combat || buried) ? fxLC() : fxL()` → `L = fxL()`):

```
  ✓ 77 — 되살린 전투 발(클리어 보너스 +68) 연출 1건이 전부 #fxlc(팝업 아래)로 간다
  ✗ #fxl 에 4건 — 팝업 위로 뚫는 연출이 남아 있다   ← [D-c] 의 **짝 항**이 잡는다
```

⚑ **②가 교훈을 하나 냈다 — [D-c] 의 두 항은 짝이고, 하나만으로는 파손을 반만 잡는다.**
`+n`(`fxPlus`)은 `fxFly` 와 **다른 줄**에서 층을 고르므로(42520) 라우팅이 부서져도
`#fxlc` 카운트가 1 로 남아 «fxlc > 0» 은 초록이었다. 잡은 것은 «#fxl 이 0인가» 쪽이다.
⇒ 층 검사는 **«왔는가» 와 «안 샜는가» 를 반드시 같이** 묻는다.

②는 갈래 ⓑ(«층 라우팅을 잃었다»)의 기각 증거이기도 하다 — 라우팅이 죽었다면 축을 켰을 때
`#fxlc` 5건이 나올 수 없다.
