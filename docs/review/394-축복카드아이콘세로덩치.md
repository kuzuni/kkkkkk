## §1 무엇이 결손이었나 — «자가 정확히 반대 축을 물고 있었다»

356 6회차가 주인 지시(«아이콘은 원본 비율 — 비균등 스케일 금지»)를 따라 34 축복 카드 3장의
`scaleX` 를 걷어내고 **등방 contain** 으로 갈았다:

```
s = min(refW / natW, refH / natH)
```

이 자는 «ref 상자를 절대 안 넘는다» 를 보장한다 — 그래서 잘림이 구조적으로 없고, 나중에
ref 종횡의 아트가 들어오면 같은 `s` 가 그대로 정답이 된다. **좋은 자다. 다만 이 화면에서는
그 자가 무는 축이 하필 틀린 축이었다.**

`min` 은 «넘치지 않는 축» 을 물고 다른 축을 놓아 준다. 우리 이모지 셋은 종횡이 제각각
(1.01 / 1.09 / 0.97)이라 **셋 다 폭이 물렸고**(`probe394` [B1]), 놓아 준 높이가 이렇게 갈렸다:

| | 자연 잉크 | contain s | 그려진 잉크 | ref |
|---|---|---|---|---|
| 카드1 ⚔️ | 158×157 | .9494 | **150×150** | 150×153 |
| 카드2 ❤️ | 157×144 | .9236 | **145×133** | 145×154 |
| 카드3 🌀 | 152×157 | .8684 | **132×137** | 132×156 |

**세로 덩치 최대÷최소 = 150 / 133 = 1.1278.** 폭은 세 장 다 ref 와 **Δ0**.
⇒ 어긋남이 **전적으로 높이 축에 몰려 있었다**(`probe394` [A3]).

## §2 뿌리 — 레퍼런스가 고정한 축은 «높이» 다

ref 잉크는 **150×153 / 145×154 / 132×156** 이다. 여기서 한 줄만 읽으면 된다:

```
폭   150 / 145 / 132  →  최대÷최소 1.136  (13.6% 갈린다)
높이 153 / 154 / 156  →  최대÷최소 1.020  ( 2.0% 안에 모인다)
```

**레퍼런스는 세 아이콘의 «세로 덩치» 를 눈금처럼 맞춰 두고 폭은 그림대로 놓아 두는 화면이다.**
contain 은 그 눈금을 **정확히 반대로** 뒤집는다 — 폭을 맞추고 높이를 놓는다.
결손은 «배율이 틀렸다» 가 아니라 **«눈금이 거꾸로다»** 였다(338 이 던전 체력바에서 잡은 것과 같은 꼴).

## §3 왜 지금 고르는가 — 등재문의 «주인 판단 대기» 는 그 뒤에 풀렸다

등재문(356 6회차)은 처방 셋(ⓐ 아트 교체 · ⓑ 높이 눈금 · ⓒ 현행 유지)을 놓고
«폭 넘침을 허용해도 되는가는 자기 몫이 아니다» 로 **주인 판단 대기**를 걸었다. 옳은 판단이었다.

**그 판단이 같은 날 주인 지시 411 로 내려왔다.** 411 은 통과 기준을 이렇게 못박는다 —

> ① 자 — `probe` 로 **그려진 잉크** bbox 를 재 «세로 덩치 최대÷최소 ≤ 1.05»
> (**근거: ref 아트 편차 0.7~2.0% · 우리 12.9% 가 결함으로 읽혔다**)

인용된 «우리 12.9%» 가 **바로 이 자리의 수**다. 즉 주인은 이 화면의 편차를 **결함으로 판정**하고
그 판정을 다른 화면의 눈금으로 삼았다. ⇒ **ⓒ(현행 유지)는 배제됐고**, 아트가 없는 지금
실행 가능한 것은 **ⓑ** 다.

## §4 처방 — 눈금만 바꾼다 (등방은 그대로)

```
s = refH / natH        (폭 넘침 허용)
```

| | s | 그려진 잉크 | ref | Δ높이 | Δ폭 |
|---|---|---|---|---|---|
| 카드1 ⚔️ | **.9745** | 154×154 | 150×153 | **+1** | +4 (+2.7%) |
| 카드2 ❤️ | **1.0694** | 167×154 | 145×154 | **0** | +22 (+15.2%) |
| 카드3 🌀 | **.9936** | 152×156 | 132×156 | **0** | +20 (+15.2%) |

**세로 덩치 1.1278 → 1.013** (ref 자신은 1.020). 값은 손으로 안 골랐다 — `probe394` [B] 가
자연 잉크를 찍힌 픽셀로 재서 `refH/natH` 로 **역산**한다(`verify394` [4] 가 그 항등식을 다시 묻는다).

**356 정책은 안 깨진다.** 주인 지시의 내용은 «찌그러뜨리지 마라»(비균등 금지)이고
«어느 축을 물 것인가» 는 그 지시가 정한 적이 없다. 세 값 전부 `scale(s)` 한 수 = 등방이고
`verify356` [A] 스코프(비등방 0건)도 89/89 그대로다.

⚑ **아트가 들어오면 두 눈금은 같은 값으로 만난다.** ref 종횡의 아트는 `refW/natW == refH/natH`
라 min 이든 높이든 결과가 같다 ⇒ 이 전환은 «이모지 대체물이 살아 있는 동안만» 의 값이고
**아트 교체 경로를 한 칸도 안 막는다**(측정표 §17-3 발주 bbox 는 한 줄도 안 바뀐다).

## §6 왜 비평가를 안 띄웠나 (지시서 [3]-(가))

이 작업은 «레퍼런스와 배치를 눈으로 맞추는» 일이 아니라 **정해진 눈금(≤1.05) 하나를 통과시키는**
일이다. 통과 기준이 주인 지시 411 에 수치로 못박혀 있고, 자는 찍힌 픽셀이며, ref 실측치는
측정표 §17-3 에 세 자(내 `noty` 마스크 · 비평가 AZ · BA)가 ±1px 로 수렴한 채로 이미 있다.
⇒ 비평 루프를 돌리면 **이미 답이 있는 질문에 회차를 태운다**(지시서 [3]-(가) 의 경고 그대로).
눈 채점이 필요한 축(«아이콘 그림이 ref 와 닮았는가»)은 아트 몫으로 §17-3 에 남아 있다.

## §10 교훈

1. **«눈금이 거꾸로다» 는 «배율이 틀렸다» 와 다른 결손이다.** contain 은 잘림을 막는 좋은 자지만
   무는 축을 고르지 않는다 — `min` 이 고른다. 형제 아이콘 집합에서는 **ref 가 무엇을 고정해
   뒀는지**(폭? 높이?)를 먼저 보고 자를 그 축에 걸어라. ref 의 축별 편차를 나란히 적어 보면
   1초에 보인다(여기서는 13.6% ↔ 2.0%).
2. **«주인 판단 대기» 는 영구 보류가 아니다.** 이 자리는 6회차가 옳게 대기를 걸었고, 그 판단이
   **다른 작업(411)의 지시문 안에서** 내려왔다 — 심지어 **이 자리의 수를 근거로 인용**하면서.
   대기 항목을 잡을 때는 **등재 이후에 들어온 주인 지시를 먼저 훑어라.**
3. **정책 전환처럼 보이는 것이 실은 «자리별 눈금» 인 경우가 있다.** 등재문은 이 수리를
   «356 전체에 소급되는 정책 전환» 으로 봤지만, 근거가 «ref 가 **이 세 장의** 높이를 고정했다» 는
   화면의 사실이라 소급 범위는 그 형제 집합뿐이다. 자에 **`axis` 를 자리마다 적는 것**이
   전환을 강요하지 않고 두 눈금을 공존시키는 방법이다.
4. **미래에 사라질 값인지 확인하면 결정이 싸진다.** 이 전환은 아트가 들어오는 순간 두 눈금이
   같은 값으로 수렴해 **자동으로 무의미해진다.** «되돌리기 비용이 0 인 결정» 을
   «정책 전환» 으로 무겁게 다루면 결손이 그대로 남는다.
