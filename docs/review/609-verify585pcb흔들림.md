## 2. 뿌리 — 무력화가 «결과» 를 눌렀고, 그 결과가 절반뿐이었다

`verify585` 152~159행은 이렇게 적혀 있었다.

```
.pcb-p.fx-punch{animation:none!important;transform:none!important}
```

이 선택자는 **클래스가 붙는 경로**만 덮는다. 그런데 58/93 «톡톡» 펄스는 입구가 **둘**이다.

| 경로 | 입구 | 무엇을 쓰는가 | 옛 무력화가 덮는가 |
|---|---|---|---|
| 전투 발 (`soft=false`) | `fxPunch()` → `classList.add('fx-punch')` | CSS `@keyframes fxPunch` | ✅ |
| **UI 발 (`soft=true`)** | `fxPunch()` → **`fxPzHit()`** → `fxPzTick()` | **`el.style.transform = 'scale(1+a)'`(인라인, 매 프레임)** | ❌ |

93 의 13회차가 UI 발 펄스를 «CSS 애니메이션» 에서 «JS 진폭 경로» 로 옮겼고(도착 리듬을
개수가 아니라 시간으로 잡기 위해), 그때부터 그 경로는 **클래스를 안 붙인다.**
`probe609` [2] 가 어긋난 프레임을 직접 찍었다 —

```
클래스 [pcb-p pcb-g] · 인라인 transform scale(1.0345) · fxPz a=0.0345 · fxPz.size=2
```

클래스에 `fx-punch` 가 **없다.** 무력화가 «샌» 것이 아니라 **애초에 그 자리를 겨눈 적이 없다.**

### 왜 03 던전만 빨갛고 10 상점은 늘 초록이었나
자는 03 을 먼저 재고, 그 뒤 `openDunDetail` 400ms · `openShopPage` 500ms 를 지나 10 을 잰다.
그 사이에 진폭이 `a < 0.004` 로 잦아들어 `fxPzTick` 이 인라인 transform 을 지운다 —
**상점 표본은 언제나 쉬는 상태**다. 그래서 셋째 항(«03 ↔ 10 이 같은 값»)은 늘 03 쪽 몫으로 빨개졌다.

### 「기다리면 된다」 가 왜 안 되는가
자동 전투가 골드를 계속 벌어 펄스가 **반복해서 다시 붙는다**(원래 주석이 이미 적어 둔 사실이다).
기다림이 잡는 것은 순간의 틈뿐이라 `probe609` [1] 6회 측정에서 2회가 그대로 어긋났다.

## 3. 처방 — 결과가 아니라 «만드는 쪽» 을 끈다

```js
window.fxPunch = () => false;      /* 전투 발 — fx-punch 클래스 경로 */
window.fxPzHit = () => false;      /* UI 발 — JS 진폭 경로(93/13회차) */
try { fxPz.clear(); } catch (e) {}
document.querySelectorAll('.pcb-p').forEach(e => {
  e.classList.remove('fx-punch', 'fx-punch2');
  e.style.transform = ''; e.style.transformOrigin = '';
});
```

**왜 `.pcb-p{transform:none!important}` 로 안 눌렀나** — 그러면 «제품이 이 알약에 정적 배율을
얹는 회귀» 까지 같이 안 보이게 된다. 자가 물어야 하는 것은 **쉬는 상태의 크기**이지
«transform 이 없는 상태의 크기» 가 아니다. 만드는 쪽을 끄면 정적 배율은 그대로 남는다.

## 4. 무르게 풀지 않았음 — 세 겹

1. **§5 [전제] 신설** — 잰 순간의 `#dunw .pcb-p` 두 칸에 «인라인 transform · `fx-punch` 클래스 ·
   `fxPz` 항» 이 **0건**임을 같은 프레임에 확인한다. 무력화가 다시 새는 날 자는 조용히 흔들리는
   대신 **그 항이 빨개져 이유를 말한다**(609 가 바로 그 «조용히 흔들리기» 였다).
2. **§R [R4] 신설** — `#dunw .pcb-p{transform:scale(1.05)}` 을 심은 사본에서 §5 골드·다이아가
   **둘 다 빨개진다**(실측 68.56 / 62.02). 껐어도 제품 회귀는 그대로 본다.
3. **허용 오차를 한 칸도 안 넓혔다** — 기대값 65.3 / 59.06 · ±0.5% 그대로. 실측은 오차가 아니라
