# 294 — «광고 보고 무료 소환이 가능한 상황인데 레드닷이 없다» (T1 버그)

- 접수: 저장소 주인 보고 2026-08-27
- 처리: 2026-08-28, `sess-0654-13142` 워커 H · **1회차**
- 지시서 판정: **[3]-(가) 기계적/기능 검증 — 비평가 없음.** 레퍼런스 대조가 아니라
  «상태 → DOM» 판정이고, 자리·좌표는 공용 부품(`.stab>.bdg` · `.updot`)을 그대로 재사용해
  새 좌표를 한 줄도 적지 않았다.

## 1. 착수 전 실측 — 등재문의 «두 경로» 는 **한 재고**였다

등재문은 «무료 10연(`freeLeft`)» 과 «광고 소환(190)» 을 두 경로로 적었지만, 소스를 따라가면
진입점 두 곳이 **같은 재고**를 태운다.

| 진입점 | 문 | 차감 |
|---|---|---|
| 10 상점 카드 `.cbtn.b1[data-shfree]` (`index.html` shop 클릭 핸들러) | `if(freeLeft(b) <= 0) …return` | `useFreeSum(b)` |
| 12 결과 팝업 `#sumBF` (`$('sumBF').onclick`) | `if(freeLeft(b) <= 0) return` | `useFreeSum(b)` |

`useFreeSum()` 은 **무광고분(`S.daily.noAdSum`)을 먼저 태우고** 그 다음 `S.daily.freeSum` 을 깎는다.
즉 190 의 `noAdSum` 은 «이번 판이 광고 없이 되나» 만 가르고 **횟수를 늘리지 않는다**.
124(광고 제거 이용권)·190 도 `#app.noads` · `.shp-card.nofad` 로 **▶AD 뱃지 표시**만 바꾼다.

> **결론 — 판정식은 하나면 된다: `freeLeft(b) > 0`.**
> «광고 보고 뽑을 수 있다» 와 «광고 없이 뽑을 수 있다» 는 둘 다 이 한 조건 안에 있다.

## 2. «없다» 는 것도 절반은 틀렸다 — 탭바 칸은 **이미 있었다**

등재문의 «어느 쪽도 레드닷 판정에 안 들어가 있다 — `sideAlert()` 호출 목록에 소환 계열이 없다» 는
2026-08-27 시점 기준이고, 그 뒤 **166 ③ 이 탭바 «상점» 칸을 이미 켜 놨다**
(`k === 'shop' ? SHOP_BOXES.some(x => freeLeft(x.b) > 0)`, `renderUI()`).
`sideAlert()` 는 ▦ 메뉴·좌측 사이드 아이콘용 함수라 애초에 탭바 칸이 들어갈 자리가 아니다.

**실제로 빠진 것은 «상점을 열고 난 다음» 이다.** 탭바 칸은 상점을 여는 순간 `.tab.close`(✕)로
바뀌고 `.tab.close .bdg{display:none}` 이라 **레드닷이 사라진다** — 상점 안에는 표시가 하나도
없으니 «다섯 상자 중 어느 것이 남았는지» 를 알 방법이 없었다. 주인 지시의 «10 소환 탭 +
그 상자 카드» 가 정확히 이 구멍이다.

## 3. 고친 것 (`index.html` — 코드 4곳 + CSS 1블록)

### ⓐ 판정식 이름 뽑기 (`freeLeft` 옆)

```js
function sumFreeReady(b){ return freeLeft(b) > 0; }
function sumAnyReady(){ return SHOP_BOXES.some(x => sumFreeReady(x.b)); }
```

탭바 칸(166)도 같은 함수를 쓰게 바꿨다 — **판정은 한 글자도 안 바뀌고**, 세 자리가 한 출처를 본다.
⚠ 166 규약 «누를 게 있을 때만»: 다이아를 내는 10연·30연(`.b2`·`.b3`)은 **점등 대상이 아니다**.
재화는 방치로 계속 차오르므로 그것까지 켜면 주인이 지적한 그 상시 점등으로 되돌아간다.

### ⓑ 10 소환 탭 배지 (마크업 1줄)

```html
<div class="shp-ct stab on" data-cat="summon"><i class="ol4">소환</i><s class="bdg"></s></div>
```

공용 `.stab>.bdg`(right:23 top:−6 · 27×27) 를 그대로 쓴다 — **좌표를 새로 적지 않았다.**
실측으로 03 던전 서브탭 배지와 `right/top/width/height` 가 전부 동일(PROBE294 ②).
재화·이용권 칸에는 달지 않는다 — «누를 게 있다» 판정이 없어서 달면 상시 점등이 된다.

### ⓒ 상자 카드 배지 (`renderShopPage()`)

부품은 283 이 쓴 `<s class="updot">` 그대로. **283 의 카드들과 달리 노드를 조건부로 찍지 않고
늘 둔다** — 자정 충전·12 결과 팝업의 [무료] 등 렌더 밖에서도 재고가 변하는 화면이라,
껐다 켜는 주체를 한 곳(매 틱 도는 `syncShopSumBtns()`)으로 모으는 편이 «켜진 채 굳는» 사고가 없다
(도감 탭 `.cltab` 과 같은 «정적 노드 + CSS 토글» 꼴).

### ⓓ 매 틱 토글 (`syncShopSumBtns()` 끝)

```js
document.querySelectorAll('#shopList .shp-card').forEach(c => {
  const f = c.querySelector('.cbtn[data-shfree][data-shsum]');
  c.classList.toggle('alert', !!f && sumFreeReady(f.dataset.shsum));
});
const ct = document.querySelector('#shopCats .stab[data-cat="summon"]');
if(ct) ct.classList.toggle('alert', sumAnyReady());
```

상자 키를 **순번이 아니라 카드가 스스로 들고 있는 무료 버튼**에서 읽는다(카드 수·순서가 바뀌어도
엉뚱한 상자에 안 켜진다). 소환 탭 배지는 리스트가 비는 재화·이용권 탭에서도 갱신된다 —
«소환 탭으로 가라» 가 그때 전달돼야 한다.

### ⓔ CSS — **함정 하나에 4줄**

```css
#shopw .updot{display:none}
#shopw .alert>.updot{display:block}
#shopw .stab>.bdg{display:none}
#shopw .stab.alert>.bdg{display:block}
.shp-card>.updot{right:-7px;top:-7px}
```

`#shopw` 는 `#shopw i,#shopw em,#shopw b,#shopw u,#shopw s{display:inline-block}` 라는
**ID 급(1,0,1) 태그 리셋**을 갖고 있어서, 클래스 급인 `.updot{display:none}`(0,1,0)·
`.stab>.bdg{…display:none}`(0,2,0) 이 **진다** → `.alert` 와 무관하게 상시 점등이 된다.
166 ⓔ(도감 탭 `#collw`) · 202 §3(07·26·50 시트) · 283(05 `#wpnw`) 과 **똑같은 병**이고 처방도 같다.
아래 되돌림 시험 N1 이 이걸 재현한다.

카드 배지 자리는 `.eqsl>.updot` 와 같은 **우상단 바깥 −7,−7**. 카드 안 우상단은 헤더 밴드
`.chd` 의 둥근 모서리이고, 바깥 29px 은 카드 사이 여백이라 위 카드와 겹치지 않는다(PROBE294 ③).
299(«레드닷 우상단 통일») 가 새로 손댈 것이 없도록 처음부터 우상단으로 잡았다.
