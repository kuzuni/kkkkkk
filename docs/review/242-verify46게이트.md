## 1. §1·§10 «던전 카드 5장» — 46 당시의 표 길이가 상수로 굳어 있었다

`chk('던전 카드 5장', … === 5)` 의 5 는 규격이 아니라 **«46 을 하던 날 `DUNGEONS` 가 5칸이었다» 는 기록**이다.
그 뒤 90(6장) · 194 각성의 동굴(7장) · 203 룬의 제단(8장)이 표를 늘릴 때마다 이 자리는 다시 빨개졌다
(LESSONS 236 «데이터가 늘어도 전제는 죽는다» · 「N종까지만」 계열).

처방은 상수를 **다시 고르는 것이 아니라 없애는 것**이다(236 ②). 근거 데이터인 `DUNGEONS` 에서 파생시켰다:

```js
const dunIds  = await page.evaluate(() => DUNGEONS.map(d => d.id));
const cardIds = await page.$$eval('#dunList [data-dcard]', e => e.map(x => x.dataset.dcard));
chk('던전 카드 = DUNGEONS 표 전부 (수·순서까지)', cardIds.join(',') === dunIds.join(','), …);
```

수만이 아니라 **id 순서까지** 묻는다 — 카드 8장이 나와도 표와 다른 것을 그리면 잡힌다.
그리고 파생만 남기면 «표가 0칸이 돼도 초록» 이 되므로(헛초록), **안 바뀌어야 하는 쪽**을 같이 못박았다(200 ③):

```js
chk('표가 46 당시(5칸) 아래로 줄지 않음 + gold·dia 상시', dunIds.length >= 5 && … );
```

§10 «던전 카드 5장 복귀» 도 같은 처방. 그 자리가 실제로 묻는 것은 «5장» 이 아니라
**«레이드 카드가 사라지고 던전 표가 통째로 돌아왔는가»** 라서 `back.cards === dunIds.length && back.raid === 0` 으로 적었다.

## 3. §9 «측정 중 재도전» — 149 가 팝업을 토스트로 옮겨 **직전 결과 팝업의 제목을 읽고 있었다**

## 교훈

1. **«N장/N종» 단언은 대개 «그날 N개였다» 는 기록이다.** 늘어나는 표(던전·스킬·상점 진열)를 세는 자리는
   전부 표 파생으로 바꾸고, 대신 **하한과 «항상 있어야 하는 항목»** 을 같이 못박아 헛초록을 막는다.
2. **모달 제목·토스트처럼 «수명이 있는 UI» 를 읽는 단언은, 그 UI 가 안 떴을 때 «직전 것» 을 읽는다.**
   빨간 이유가 «없다» 인데 got 은 «다른 값» 으로 보여서 원인이 한 겹 가려진다.
   읽기 전에 «이 노드가 이번 동작으로 새로 생긴 것인가» 를 물어야 한다(관찰자 또는 이전 값 대조).
3. 게이트가 낡은 원인은 세 갈래인데 이 파일에는 **세 갈래가 다 있었다** — ① 데이터 증가(던전 5→8) ·
   ② 주인 지시로 규칙 변경(205 하루 3회) · ③ 주인 지시로 표현 변경(149 팝업→토스트).
   게이트를 고칠 때는 «어느 갈래인가» 를 먼저 갈라야 처방이 갈린다(파생 / 근거 상수 / 새 UI 채널).
