## §2 뿌리 — 자가 «값» 이 아니라 «틱 운» 을 재고 있었다

빨간 것은 허용치를 만드는 줄이었다(수리 전 `tools/verify69.js`):

```js
const dg0 = await page.evaluate(() => S.gold);
await page.waitForTimeout(600);
const drift = Math.max(4, (await page.evaluate(() => S.gold) - dg0) * 3);
```

이 자는 **«오염원이 연속 수입이다»** 라는 전제 위에 서 있다 — 600ms 를 표본으로 떠서 ×3 하면
1.8초치 예산이 나온다는 셈이다. 오염원이 이산이면 그 셈이 통째로 무너진다:

* 틱 간격이 최대 7.6초라 **600ms 창은 대개 한 틱도 못 잡는다** → `(0) * 3 = 0` → 허용치가 **바닥값 `Math.max(4, …)` = ±4** 로 떨어진다.
* 그런데 실제 표본 창(클릭 → 1,020ms 뒤 읽기)에는 틱이 **하나 얹힐 수 있다**. 한 틱은 **4.08**.
* **4.08 > 4** — 초과분이 **0.08**. 그래서 «4회 중 1회» 가 아니라 관측상 **6회 중 3회**까지 빨갰다.

즉 바닥값 ±4 는 **한 틱 바로 아래**에 놓여 있었다. 자가 재고 있던 것은 「우편 보상이 정확한가」가 아니라
**「표본 창에 킬이 들어왔는가」** 였다.

수리 전 6회 실행(같은 커밋):

```
run1 PASS 99/99   드리프트 600ms 당 4 → ±12
run2 FAIL 98/99   드리프트 600ms 당 1 → ±4    ✗ 골드 증가분 3004.08 ≠ 3000 (허용 ±4)
run3 PASS 99/99   드리프트 600ms 당 1 → ±4
run4 FAIL 98/99   드리프트 600ms 당 1 → ±4    ✗ 골드 증가분 3004.08 ≠ 3000 (허용 ±4)
run5 PASS 99/99   드리프트 600ms 당 4 → ±12
run6 FAIL 98/99   드리프트 600ms 당 1 → ±4    ✗ 골드 증가분 3004.08 ≠ 3000 (허용 ±4)
```

⚑ 출력의 «600ms 당 **1**» 은 «1 골드 벌었다» 가 아니라 **«한 틱도 못 봤다»** 는 뜻이다
(`Math.round(Math.max(4, 0) / 3)` = 1). 자가 자기 실패를 «작은 수입» 처럼 찍고 있었던 것이라
로그만 봐서는 «드리프트가 있긴 있네» 로 읽힌다 — 실제로는 **표본이 비어 있었다.**

## §3 처방 — 허용치를 벌리지 않고 **오염원을 끊었다**

등재문의 ⚠ 를 그대로 지켰다: **허용치를 ±8 로 벌리면 「연타 3회인데 골드는 1회분만」 이라는 본 단언이
통째로 무뎌진다**(그 자리가 재는 양과 한 틱은 자리수가 같다). 그래서 등재문 처방 **ⓐ**(표본 구간 동안 방치 틱을 멈춘다)를
택하되, 재현이 이름을 바꿔 준 만큼 **손잡이도 바꿨다** — 멈출 것은 방치가 아니라 **전투 수입**이다.

전투 골드는 예외 없이 `stat.goldMul` 을 탄다(세 자리 전부):

## §4 «기다리지 않는» 전제 — 내가 고치려던 플레이키를 새로 만들지 않기

동결이 실제로 들었는지를 «표본 창에 킬이 왔나» 로 확인하면 **틱 간격 7.6초짜리 플레이키를 그대로 새로 만든다.**
그래서 전제는 킬을 **기다리지 않고 직접 친다** — `killEnemy(enemies[0])` 는 결정적이고 즉시다
(`probe395` [D] 가 «적은 늘 화면에 있다 — 남은 적 33» 을 못박았다).

| 시점 | 강제 킬 골드 | 뜻 |
|---|---|---|
| 동결 **전** | **+4.08** | 오염원이 실재하고, 자가 그것을 부를 수 있다(전제가 공허하지 않다) |
| 동결 **중** | **+0** | 표본 구간에 전투 골드가 안 섞인다 — 허용치를 좁힐 근거 |
| 동결 **해제 뒤** | **+4.08** | 동결은 표본 구간에만 걸렸다 — 자가 게임을 영구히 껐고 초록인 게 아니다 |

셋째 줄이 없으면 «전투 수입을 꺼 놓고 초록» 과 구별이 안 된다 — **공허한 초록의 다른 얼굴**이다.

## §5 허용치 — ±drift → **IEEE754 잡음 폭**(0 이 아니다)

동결을 걸고 허용치를 **0** 으로 좁히자 8회 중 3회가 다시 빨갰는데, **이번 빨강은 다른 종류**였다:

```
✗ 전체 수령 골드 32000.000000000004 ≠ 32000 (허용 ±0)
```

틱이 아니라 **부동소수점 누적 오차**다(`S.gold` 가 4.08 씩 쌓인 뒤의 차분 — 4e-12).
⇒ 허용치를 **`EPS = 1e-6`** 으로 뒀다. 이것은 «오차 예산» 이 아니라 **잡음 폭**이다:
한 틱(4.08)의 **약 4백만분의 1**이라 틱은 물론 0.001 의 어긋남도 그대로 잡는다.

바뀐 자리 셋 — 전부 `±drift` → `±EPS`:

| 항 | 수리 전 | 수리 후 |
|---|---|---|
| `골드 증가분` | ±drift(4~12, 틱 운) | **±1e-6** |
| `연타 3회 — 골드는 1회분만` | ±drift | **±1e-6** |
| `전체 수령 골드` | ±drift | **±1e-6** |

곁다리로 **항을 하나 늘렸다**: [4-b] 삭제 절은 원래 다이아·유물석만 물었다(골드는 드리프트 때문에 **물어볼 수가 없었다**).
동결 구간이 되면서 **«삭제는 골드도 안 건드린다»** 를 ±0 으로 물을 수 있게 돼 신설했다 —
플레이키를 닫은 것이 게이트를 **넓히기까지** 한 자리다.

## §6 §R 되돌림 시험 — 무르게 풀지 않았음의 증명

좁힌 자가 «정말 좁은지», 그리고 동결이 «오염을 못 보게 눈을 가린 것» 이 아니라 «오염을 없앤 것» 인지를 못박는다.
방법은 **틱 하나를 일부러 창 안에 떨어뜨리는 것**이다(동결을 잠깐 풀고 강제 킬 → 다시 동결).

| 항 | 결과 |
|---|---|
| `[R-1]` 창 안에 틱을 하나 떨어뜨렸다 | **+4.08** |
| `[R-2]` 우편 보상은 그대로 들어온다 | 증가분 **3004.08** — 동결이 «보상까지 0» 으로 만든 게 아니다 |
| `[R-3]` 좁힌 자가 그 틱을 **빨갛게** 본다 | 3004.08 ≠ 3000 · 초과 **4.08** |
| `[R-4]` 한 틱 > 옛 허용치 바닥 ±4 | 4.08 > 4 — 옛 자가 빨갰던 이유 그 자체 |

`[R-2]` 가 핵심이다 — 이것이 없으면 «±1e-6 이라 적어 놓고 실은 동결이 우편 보상까지 0 으로 만든» 무른 수리와
구별이 안 된다(그 경우 증가분이 0 이 되어 `[R-2]` 가 빨개진다).

## §8 다음 세션이 볼 것

⚑ **재화 전후 비교를 하는 게이트를 새로 쓰는 세션에게** — 이 저장소의 «유휴 오염» 은 **연속이 아니라 이산**이다.
짧은 창을 떠서 ×N 하는 «드리프트 예산» 방식은 **틱 간격보다 창이 짧으면 구조적으로 0 을 돌려주고**,
그 바닥값이 한 틱보다 조금이라도 작으면 **영원히 아슬아슬한 자**가 된다(382 가 «±5% 에 여유 0.2pp» 로 만난 것과 같은 병).
예산을 재지 말고 **오염원을 끊어라** — `stat.goldMul` 하나가 전투 골드 세 자리를 전부 지난다.

⚑ **끊었으면 «끊겼다» 를 기다리지 말고 직접 쳐서 물어라** — `killEnemy(enemies[0])` 는 결정적이다.
«창 안에 킬이 오나» 로 전제를 세우면 고치려던 플레이키를 전제 쪽에 그대로 옮겨 심는 것이다.

⚑ **틱을 없앤 뒤에도 «0» 은 못 쓴다** — `S.gold` 는 4.08 씩 쌓이는 float 라 차분에 1e-11 급 잡음이 남는다.
`0` 이 아니라 **한 틱보다 6자리 작은 EPS** 가 정답이고, 그 둘의 차이를 주석에 적어 두지 않으면
다음 세션이 «가끔 빨개서» 를 이유로 EPS 를 틱만 하게 키운다.
