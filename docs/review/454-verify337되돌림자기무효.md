## 1. 재현 — 등재문 그대로였다

착수 직후 그대로 돌렸다.

```
[R] 되돌림 시험 — 옛 값을 주입하면 빨개져야 한다
  FAIL R1  셸을 100 로 되돌리면 §2(노출 0px)가 깨진다 — 노출 0.00px
  FAIL R1b 한 칸(99)만 되돌려도 노출이 생긴다      — 노출 0.00px
VERIFY337 90/92  FAIL 2
```

등재문의 «무엇을 주입해도 못 빨개진다» 가 그대로 확인됐다 — 주입값을 100 에서 99 로
한 칸 낮춰도 **노출은 0.00 으로 똑같다**. 값 싸움이 아니라 **축이 죽은 것**이다.

## 2. 뿌리 — §2 는 이제 CSS 항등식 위에 서 있다

437 이 칸 높이를 리터럴(85)에서 **패딩 상자 파생**으로 바꿨다:

```css
.stabs{--sb:7px;height:98px;border:var(--sb) solid #000;box-sizing:border-box}
.stabs>*{position:absolute;top:0;height:100%}      /* 437 2-4 */
```

절대배치 자식의 `height:100%` 는 담는 상자의 **패딩 상자**다. 그래서

* 패딩박스 하변 = 바 하변 − 테두리
* 칸 하변 = 바 상변 + 테두리 + (바깥 − 테두리×2) = 같은 값

이 **선언에서 항상 참**이다. §2 가 재는 `innerBottom − max(cell.bottom)` 은 그 두 값의 차이라
**셸 높이를 무엇으로 주입하든 0.00 이다**. R1·R1b 는 셸 높이 한 줄만 되돌리므로 원리적으로 못 빨개진다.

⚠ **파생 자체는 옳은 개선이다** — «바깥 − 칸 = 테두리×2» 가 CSS 안의 항등식이 되어
«셋 중 하나만 옮기는 사고» 가 원리적으로 안 난다(`verify437` [G]★·[S]).
그러니 처방은 **파생을 되돌리는 것이 아니라 되돌림 축을 다시 고르는 것**이다.

## 3. §2 자체는 헛초록이 아니다 — 제품에 직접 물어 확인했다

축이 죽었다고 §2 까지 공허한 것은 아니다. **제품 트리에 파생을 깨는 한 줄을 실제로 얹고** 돌렸다
(`<style>.stabs>*{height:85px}</style>` 를 `index.html` 끝에 붙였다가 원복):

```
[2] ③⑤ 알약 하변 ↔ 바 패딩박스 하변 = 0
  FAIL 07 스킬 노출 0px — -1.00px      FAIL 10 상점 — -1.00px
  FAIL 06 장비 노출 0px — -1.00px      FAIL 13 재화 — -1.00px
  FAIL 03 던전 노출 0px — -1.00px      FAIL 23 훈련 — -1.00px
                                        FAIL 47 룬  — -1.00px
```

**호스트 7곳 전부 빨강.** ⇒ §2 는 «칸 높이 리터럴이 되살아나는» 방향으로는 살아 있고,
죽어 있던 것은 «셸 한 줄» 이라는 **되돌림의 자리 선택** 하나다. 그래서 333 처방대로
**§2 를 갈아 끼우지 않고 그대로 뒀다** — 자리를 비울 이유가 없다.

## 4. 처방 — 등재문 ⓑ (`verify437` 의 자를 빌린다), 축을 셋으로 가른다

등재문의 세 후보 중 **ⓑ** 를 골랐다. 437 은 자기 [R] 절에서 이미 같은 함정을 만나
«따라오는가» 를 **양성으로** 묻고([R-b]·[R-c]) 결속을 깰 수 있는 **유일한 길**(칸 높이 리터럴 부활)만
음성으로 물었다([R-d]). 그 배분을 337 §2 축에 그대로 옮겼다.

| 항 | 주입 | 기대 | 실측 |
|---|---|---|---|
| **R1** | 337 **이전** 그림 통째 — `--sb:6` + `height:99` + `.stabs>*{height:85}` | 패딩 87 − 알약 85 = **노출 2** ⇒ §2 빨강 | **2.00px** |
| **R1-i** | (위 주입의 실제 상태를 되묻는다 — 435) | 셸 99 · 테두리 6 · 칸 85 | **99.0 / 6.0 / 85.0** |
| **R1b** | 파생을 **한 칸만** 깬다 — `.stabs>*{height:calc(100% - 1px)}` | 노출 **1** ⇒ §2 문턱 0.6 이 무르지 않다 | **1.00px** |
| **R1b-i** | (셸·테두리는 안 건드렸는가) | 98 / 7 / 83 | **98.0 / 7.0 / 83.0** |
| **R1c** ★ | 셸만 `height:99` | 칸이 **따라와** 노출 **0** — 파생이 살아 있다 | **0.00px · 셸 99 · 칸 85** |

* **R1** 이 «셋 통째» 인 이유: 437 이후의 테두리 7 에서는 셸 99 만으로는 칸이 85 로 따라와 노출 0 이다.
  노출 2 라는 **337 이 실제로 닫은 그림**을 재현하려면 테두리 6 과 칸 리터럴 85 가 같이 있어야 한다.
* **R1b** 가 «옛 값» 이 아닌 이유: 파생 아래에서 §2 를 깨는 길은 **리터럴 부활 하나뿐**이고,
  그 길의 **가장 얕은 한 칸**이 문턱을 문다. 값이 옛 값이어야 되돌림인 것이 아니라
  **단언이 실제로 빨개져야** 되돌림이다.
* **R1c 가 이 수리의 핵심이다.** 없으면 다음 워커가 R1 을 다시 «셸 한 줄» 로 줄여
  **똑같은 자기무효**를 만든다 — 이 항이 그 자리에 «셸만으로는 안 깨지는 것이 정상» 이라고 못을 박는다.
  ⚠ 이 항을 «빨개져야 한다» 로 두면 게이트가 **제 개선을 결함으로 읽는다**(437 [R] 머리말과 같은 경고).

**435 교훈을 두 곳에 박았다** — `R1-i`·`R1b-i` 는 «주입이 실제로 그 상태를 만들었는가» 를 되묻는다.
주입이 무음 실패한 날 되돌림 시험이 통째로 자기무효가 되는 것이 435 가 겪은 일이다.
