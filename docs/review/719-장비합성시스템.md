## 1. 착수 시점의 사실 — «합성은 이미 있었고, 산식이 달랐다»

등재문은 «합성 시스템 **신설**» 이라고 적었지만 저장소에는 **85 ⑤(주인 지시)가 만든 합성이 이미 돌고
있었다**. 달랐던 것은 셋이다.

| 축 | 착수 시점(85 ⑤) | 주인 지시(719) |
|---|---|---|
| 산출 | **다음 등급 5종 중 랜덤**(`nextGradeItem`) | **다음 티어 1칸**(등급 끝이면 다음 등급 최저 티어) |
| 진입점 | 08 세부 팝업의 **개별 [합성] 버튼**(`mCraft`) | 05 무기 팝업의 **[일괄합성] 하나** |
| 실행 단위 | 1회 1건 | **가능한 조합 전부 · 연쇄 · 소진까지** |

그래서 이 작업은 «없던 것을 만든 것» 이 아니라 **산식·진입점·실행 단위 셋을 갈아 끼운 것**이다.
같은 조건(«Lv100 만렙분만» · «5개 소모» · «최고 등급 없음»)은 85 ⑤ 가 이미 지키고 있어 한 글자도 안 건드렸다
(`CRAFT_NEED = 5` 도 그대로 — 주인이 확정한 5:1 비율이다).

## 2. 산식 — 표를 손으로 적지 않는다(402 규약)

```js
const nextTierItem = it => {
  const up = EQUIPS.filter(e => e.slot === it.slot && e.g === it.g && e.j === it.j + 1);
  if(up.length) return up[0];                       // ① 같은 등급 다음 티어
  const ng = EQUIPS.filter(e => e.slot === it.slot && e.g === it.g + 1);
  if(!ng.length) return null;                       // ③ 최고 등급은 합성 없음
  return ng.reduce((m, e) => (e.j < m.j ? e : m));  // ② 다음 등급의 최저 티어
};
```

⚑ **«티어» 는 새 데이터가 아니다** — 260 이 각 등급 배열을 «약→강» 으로 재배치해 둬서 `EQUIPS[].j` 가
곧 티어이고, 472 의 장착 효과표(`EQ_BASE(g, t)`)도 같은 j 를 읽는다. 즉 **합성이 올려 주는 칸은 장착 효과가
정확히 한 칸 오르는 칸**이다 — 산식과 값이 같은 축 위에 있다(표를 새로 적었으면 그 정합이 우연이 됐다).

⚑ **랜덤이 사라진 것이 부수 효과가 아니라 이득이다.** 85 ⑤ 는 «판정(`canCraft`)은 존재 여부만 보고
지급은 `nextGradeItem` 한 번이 정한다» 로 판정↔지급 어긋남을 피하고 있었는데, 이제 **같은 함수가 같은
칸을 돌려준다**(`verify719` A4 — 100회 물어도 한 칸). 그래서 게이트도 «풀 전체 보유 수가 늘었는가» 같은
우회를 버리고 **산출 id 를 직접** 집는다(`verify268` §6 이관).

## 4. 일괄 실행 — 연쇄·소진·장착분

`craftAll(list)` 는 **낮은 것부터**(등급 → 티어) 돌고, 한 바퀴에 한 건이라도 했으면 다시 훑는다.
낮은 티어가 만든 산출이 다시 5개를 채우면 그 칸도 이어서 합성된다(**연쇄**. 위임 규약으로 채택 —
되돌리려면 `do/while` 을 한 바퀴로 줄이면 된다).

⚑ **연쇄는 «이미 만렙이던 칸» 에서만 일어난다** — 산출은 항상 `{n:0, l:1}`(밑동 1개) 또는 `n++`(여분 +1)
이라 새로 생긴 칸은 Lv1 이고 `canCraft` 를 통과하지 못한다. 그래서 «한 번 눌렀더니 불멸까지 올라갔다» 는
구조적으로 불가능하다.

⚑ **장착분은 재료가 아니다 — 분기를 새로 만들지 않고 그렇게 된다.** 소모하는 것은 `S.own[id].n`(여분)
뿐이고 «그 장비 자신»(밑동 1개 + 강화 Lv)은 건드리지 않는다. 그래서 장착 중인 칸도 `S.eqSlot`·`has`·`oLv`
가 전부 그대로다(`verify719` [E4]). 위임 규약이 권고한 «장착분 제외» 를 **코드 한 줄도 안 쓰고** 만족한다.

⚠ **«1개» 의 자리가 밑동이냐 여분이냐** — 처음 얻는 칸은 조각 0(밑동)이고 이미 있는 칸은 조각 +1 이다.
1회차에 게이트가 이것을 모르고 `frag(weapon0_3) === 1` 을 기대해 빨갰다(실제 `has === true · n === 0`).
`craft()` 원본이 처음부터 그렇게 세고 있었고 — **게이트가 제품을 안 읽고 기대를 적은 것**이었다.

## 7. 199 통지

- 5:1 비율·«Lv100 만렙분만» 은 **주인 확정**이라 산식은 불변이다. 199 가 볼 것은 **티어 가치 등가성** 하나다:
  합성은 «같은 부위 만렙 5개 → 다음 티어 1개» 이므로 **한 티어 오르는 데 5배**가 든다. 장착 효과는 티어당
  ×1.5(`EQ_TIER`)이고 등급 경계는 ×3(`EQ_GRADE = 1.5⁴×3`)이므로, **비용 ×5 ↔ 효과 ×1.5** 는 티어 안에서
  적자, 등급 경계(5단계 누적 비용 ×3,125 ↔ 효과 ×15.19)에서는 더 큰 적자다 — 즉 **합성은 «남는 조각의
  출구» 이지 성장 주선이 아니다**(소환이 주선). 199 가 이 비율을 손잡이로 쓰려면 `CRAFT_NEED` 한 줄이다.
- 부수 효과 하나: 합성은 **보유 종수를 늘린다**(도감 91·118 · 보유 효과 `ownVal` 합산). 조각이 남아돌던
  세이브에서 cp 가 오르는 방향이고, 줄어드는 경로는 없다(밑동을 안 먹는다).
