## 1. 무엇을 만들었나

64(23 훈련 카드 홀드)의 규칙을 **#trw 전용 부품 한 벌**(`rtHoldStart`)로 뽑아 세 버튼에 붙였다.

```
pointerdown 즉시 1회 → TR_HOLD_DELAY(350ms) 뒤 반복 시작
                     → TR_HOLD_IV0(160ms)에서 ×TR_HOLD_ACCEL(0.86) 가속, 최소 TR_HOLD_IVMIN(60ms)
뗌 · pointercancel · 버튼 밖 이탈 · 팝업(#trw) 닫힘 → 즉시 정지
재화·포인트 부족 → 조용히 정지 + shake 1회 (119 G4)
```

**상수는 64·262 와 공유한다** — 세 자리가 같은 상수를 봐야 «같은 손맛» 이 된다(89 유물 `rwHold`
가 이미 «64 규칙 재사용» 선례를 만들어 뒀다).

### 262 의 `bindUpHold` 를 그대로 쓰지 않은 이유

262 가 만든 부품은 **껍데기가 `#modal`** 이다(`upHoldTick` 이 `$('modal').classList.contains('on')`
으로 멈추고, `mdLive` 가 08 팝업의 `.sk-*` 셀렉터를 안다). 23 훈련 팝업은 `#trw` 라 그 두 가지가
전부 어긋난다. 그래서 **부품은 따로, 상수는 공유**로 갈랐다. 두 부품이 섞이면 «팝업 닫힘» 판정이
서로를 죽인다 — 그 경계를 `verify262` §10 이 지킨다(내용이 «룬은 click 경로» → «부품이 안 섞였나»

## 2. 64 교훈 1 / 262 ⓑ — «누른 노드를 날리면 포인터 캡처가 끊긴다»

이게 이 작업의 진짜 몸통이었다. `renderRunes()`·`renderTemper()` 는

* 성공할 때마다 `renderTrain()` 이 부르고,
* 그와 별개로 `renderTrainLive()` 를 타고 **0.35초마다** 도는데,
* 서명(`dataset.sig`)이 달라지면 **본문 innerHTML 을 통째로 갈아끼운다.**

레벨·재화가 움직이면 서명이 반드시 달라지므로, 홀드 중에는 **누르고 있는 그 버튼이 매번
사라진다**. 터치의 암묵적 포인터 캡처가 그 순간 끊긴다.

처방은 262 와 같다 — 홀드 중에는 통짜 렌더를 멈추고 **숫자만** 고쳐 쓴다:

```js
if(rtHoldOn('rune')){ liveRunes(curId); return; }   // renderRunes 머리
if(rtHoldOn('temper')){ liveTemper(); return; }     // renderTemper 머리
```

`dataset.sig` 를 **갱신하지 않는 것**이 여기서 요령이다 — 손을 뗀 «뒤» 첫 렌더가 서명 불일치로
저절로 통짜가 된다. 홀드 종료(`end`)가 부르는 `renderTrain()` 한 번이 정합을 맞춘다.

### 표기층이 두 벌이 되는 문제 → 문자열을 한 벌에서 만든다 (262 교훈 2ⓐ)

«숫자만 갱신» 경로를 깔면 같은 숫자를 만드는 식이 두 군데가 된다(LESSONS 194 «두 식이 갈라지면
표기가 거짓이 된다»). 그래서 레벨·재화를 타는 문자열을 전부 함수 한 벌로 뽑았다:

* `runeCardTxt(r)` → `{ lv, bar, rate, rateS, eff, step, mat, dia, okM, okD, max, seg }`
* `runeSumTxt()` → 총효과 요약줄
* `temperRowTxt(t)` → `{ lv, eff, cost, seg, btn, ok }` · `temperHeadTxt()` · `temperFootTxt()`

통짜 렌더와 `liveRunes`/`liveTemper` 가 **같은 함수**를 부른다. 그 동일성을 게이트가 한 글자
단위로 잠근다(§3 아래 ★ 두 줄).

만렙은 예외다 — 룬이 만렙에 닿으면 버튼 2개가 `.rmax` 한 칸으로 **구조가 바뀐다.** `liveRunes` 는
그때 `sig` 를 비우고 통짜 렌더에 넘긴다(그 시점엔 `runeTryOk` 가 false 라 홀드도 다음 틱에 스스로
멈춘다). 단련은 맥스가 없어서(주인 지시 ⓑ) 구조가 안 바뀐다.

## 3. 반복분의 «조용함» — 토스트·연출을 죽인다

`runeBuy` 는 시도마다 토스트를 띄우고 `fxReward()` 를 쏜다. 60ms 간격으로 반복하면 토스트가
쌓여 화면이 잠기고 `#fxl` 이 FXMAX 로 막힌다(58 이 64 에서 이미 겪은 자리). 그래서
`runeBuy(id, pay, quiet)` · `temperUpBtn(k, quiet)` · `temperChargeBtn(quiet)` 에 조용한 경로를
넣고, 반복분은 전부 그 경로로 보냈다. 실패음(`sfx('err')`)도 반복분에서는 안 낸다 — 룬은 확률상
대부분 실패라 초당 16회 «삑» 이 된다.

정산은 손을 뗀 뒤 **요약 한 줄**이 한다:

* 룬 1회 → 기존 문구 그대로(«강화 성공! Lv. n» / «강화 실패 — 레벨은 그대로입니다»)
* 룬 n회 → «일반룬 — 23회 시도 · 성공 **2**회 (Lv. 30 → **32**)»
* 단련 n회 → «공격력 단련 **Lv. 8** (투자 8회)»

첫 누름부터 막힌 경우(잠금·만렙·부족)의 안내 문구는 **기존 경로 그대로** 나간다 — 조용해지는
것은 «반복분» 뿐이다.

## 4. ⓓ 다이아 결제 — 홀드에서 뺐고, 한 줄로 켤 수 있게 남겼다

등재문이 «주인 확인» 으로 남긴 항목이다. 이번 실행에는 주인이 없어(스케줄 실행) **가정을 명시하고
진행**했다:

* 주인 지시문은 «**룬 강화 버튼**» 이고, 등재문 스스로 «재료 시도 기준으로 읽었다» 고 적었다.
* 룬 다이아는 **50 다이아/1회**다. 홀드 1.2초면 최대 16회 ≒ 800 다이아가 되돌릴 수 없이 나간다.
* 262 도 같은 이유로 프리미엄 재화 경로를 뺐다.

→ `const RUNE_HOLD_DIA = false;` **한 줄**로 스위치를 남겼다. `true` 로 바꾸면 다이아 칸도 같은
홀드를 탄다(경로는 이미 `pay` 를 그대로 받는다). 게이트가 «지금은 false» 와 «1.2초를 눌러도
50 다이아 1회분만» 을 둘 다 잰다.

**주인 확인 필요**: 다이아 칸도 홀드를 원하는가.

## 7. 이번에 밟은 함정 2개 (다음 세션도 밟는다)

### ① 열자마자 재는 bbox 는 **애니메이션 한복판**이다

`openTrain(); renderTrain();` 직후 `boundingBox()` 를 재니 버튼이 **y 2345**(뷰포트 2280 **바깥**)로
나왔고, 마우스가 허공을 눌러 «단발 탭 = 0회» 가 됐다. 420ms 뒤 다시 재면 y 1667 이다.
164 가 «애니메이션 종료 대기 후 마우스 클릭» 으로 지난 자리와 같다.

고정 대기는 «가끔 통과» 로 굳으므로 결국 **Playwright 액셔너빌리티**로 옮겼다 —
`locator.scrollIntoViewIfNeeded()` → `locator.hover()` 는 «보이고 · 안정되고 · **그 좌표에서
이벤트를 실제로 받는**» 상태가 될 때까지 기다린다.

### ② 앞 절이 남긴 팝업이 버튼을 덮는다

`verify210` 은 [I] 직전에 절망의 탑을 실제로 클리어한다 → **`#dclw`(던전 클리어 팝업)** 가 열린 채
남는다. `hover()` 가 «`<div id="dclw" class="on">` intercepts pointer events» 로 30초 뒤 타임아웃해서야
드러났다(그전에는 «0회» 라는 조용한 오답이었다).
→ 포인터 절 앞에서 **닫개를 전부 부른다**: `closeDunClear` · `closeDefeat` · `closeModal` ·
`closeDungeon` · `closeSummonResult`. 그리고 «누른 좌표의 최상단 노드가 정말 그 버튼이었나» 를
**양성항**으로 따로 세워 뒀다(LESSONS 263-①) — 이게 없으면 다음에도 «0회» 만 보고 원인을 못 찾는다.
