## §1 등재문과 재현이 갈린 곳 — «결정적» 이 아니라 **플레이키**였다

등재문(509 회귀 곁다리 관측)은 이렇게 적혀 있었다:

> 출력은 «수리 후 289×166 ↔ 드레인 없음 **289×166**» 으로 두 읽기가 같다.
> `git stash` 로 수리 전 트리를 만들어 같은 자를 돌려도 같은 숫자로 32/33.
> **흔들리는 값이 아니라 결정적이다.**

338 규칙대로 처방 전에 재현했고, **그 한 줄이 틀렸다.**

착수 시점의 `main`(32aed18)에서 `verify471` 을 그냥 돌리니 **33/33 PASS** 였다.
그래서 [R] 이 재는 한 쌍만 떼어 반복하는 자(`tools/probe560.js`)를 신설해 세었다:

| 회차 묶음 | [R] 판정식 결과 |
|---|---|
| 1차 6회 | 5 PASS / **1 FAIL** |
| 2차 8회 | 8 PASS / 0 FAIL |
| **합계 14회** | **13 PASS / 1 FAIL (7.1%)** |

FAIL 회차의 값은 등재문과 정확히 같은 «289×166 ↔ 289×166» 이다.
즉 등재문이 본 것은 실재하지만 **재현율이 낮은 자리**였고, «결정적» 이라는 판단이 뒤집혔다.
⚠ 이 구별은 미용이 아니다 — «결정적으로 죽었다» 면 표본이 옮겨진 것(갈래 ⓐ)이고,
«가끔 죽는다» 면 자의 경합(갈래 밖)이다. **처방이 정반대다.**

## §2 뿌리 — 갈래 ⓐ·ⓑ 둘 다 기각. 범인은 **얼리는 손잡이 자신의 경합**이다

등재문이 세운 두 갈래는 이렇다.

- **ⓐ 표본이 옮겨졌다** — `P471_NODRAIN=1` 이 겨누는 호스트(35 패스 패널)가 `jzPgIn` 을 안 타게 됐거나
  애니 길이가 짧아져 «한복판» 이 없어졌다(514 가 룰렛 팝업을 32.2px 옮긴 자리부터 보라).
- **ⓑ 드레인이 이제 두 경로 모두에 걸린다** — `NODRAIN` 갈래도 멎은 뒤에 읽게 됐다.

**둘 다 기각됐다.** 되돌림 사본(`P471_NODRAIN=1 P471_FORCEANIM=1`) 쪽만 14회 돌리면서
«그 순간 얼릴 애니가 남아 있었는가»(`froze`)를 같이 찍으니 답이 한 줄로 나왔다:

```
  1/14  289×166  얼린 애니 0 []                                  ← [R] 죽음
  2/14  285×164  얼린 애니 1 [jzPgIn]
  3/14  285×164  얼린 애니 3 [jzPgIn,jzPgIn,jzPgIn]
  …
 14/14  285×164  얼린 애니 2 [jzPgIn,jzPgIn]
                                              froze=0 인 회차: 1/14
```

**«289×166 으로 죽은 회차» 와 «얼린 애니 0개인 회차» 가 정확히 같은 한 회차다.**
호스트는 그대로 `jzPgIn` 을 타고 있고(ⓐ 기각), 드레인을 껐을 때 애니가 실제로 잡히기도 한다(ⓑ 기각).
빠진 것은 하나 — **그 회차에는 얼릴 것이 이미 없었다.**

이유는 `jzOpen`(index.html 36651)에 있다. 등장 애니가 끝나면 `jzDoneThen` 이 `jz-o`·`jz-pg` 를 **뗀다**.
그런데 550 이 신설한 `P471_FORCEANIM` 은 **장면을 연 뒤에** `.jz-pg` 를 찾아 얼리는 꼴이었다:

```js
for (let i = 0; i < 16 && !document.querySelector('.jz-pg'); i++) await wait(50);
document.querySelectorAll('.jz-pg').forEach(e => e.getAnimations().forEach(a => { a.pause(); a.currentTime = 0; }));
```

`openPass('stage'); await wait(250)` 이 끝날 무렵 `jzPgIn .12s` 가 이미 끝나 클래스가 떨어져 있으면
이 블록은 **아무것도 안 얼린다**. 그러면 드레인이 있으나 없으나 «멎은 상자» 를 읽어
[R] 은 «두 읽기가 같다» = 죽은 것처럼 보인다.
얼린 애니 수가 회차마다 **0~4개로 흔들리는 것**이 곧 이 경합의 눈금이다.

⚑ **550 은 «자연 경합에 기대지 말고 얼려라» 로 한 겹을 닫았는데, 얼리는 행위 자체가 두 번째 경합이었다.**
그리고 550-② 가 적어 둔 대로 **여기서도 «더 기다린다» 는 처방은 방향이 반대다** — 기다릴수록 애니는 더 확실히 끝나 있다.

## §3 처방 — 시간이 아니라 **순서**로 닫는다 (허용 오차·항 삭제 0)

`tools/probe471.js` — 얼리기를 «찾아서» 가 아니라 «붙는 순간» 에 한다.
장면을 열기 **전에** `MutationObserver` 를 걸어 `jz-pg` 가 붙는 그 순간 애니를 0프레임에 세운다.

```js
if (FORCEANIM) await page.evaluate(() => {
  window.__p471froze = 0;
  const grab = (el) => el.getAnimations().forEach(a => { a.pause(); a.currentTime = 0; window.__p471froze++; });
  const mo = new MutationObserver(recs => { for (const r of recs) {
    const el = r.target; if (el && el.classList && el.classList.contains('jz-pg')) grab(el);
  } });
  mo.observe(document.documentElement, { subtree: true, attributes: true, attributeFilter: ['class'] });
  document.querySelectorAll('.jz-pg').forEach(grab);
});
```

왜 이 순서가 이기는가 — `MutationObserver` 콜백은 클래스를 붙인 스크립트가 스택을 비우는 즉시(마이크로태스크) 돌고,
`jzDoneThen` 이 클래스를 떼는 `finish`/`animationend` 는 **그보다 뒤 태스크**다.
그리고 한 번 얼린 애니는 영영 안 끝나므로 `offO` 의 2.5초 타임아웃까지 상태가 고정된다 = **읽는 동안 안 움직인다.**
`froze` 는 **장면마다** 0으로 되돌려 세므로 «PT 장면이 실제로 얼려졌는가» 를 그대로 물을 수 있다.

**허용 오차는 한 칸도 안 넓혔고, 항도 하나도 안 지웠다.** 판정식(`Δ > 1.5`)은 그대로다.
