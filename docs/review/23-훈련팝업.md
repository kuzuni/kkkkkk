## 3회차 — E 9 (통과) / F 7 (최저 **7**)

**E**: ①10 ②10 ③10 ④10 ⑤9 ⑥10 → **9 «통과»**. «최종 9점의 감점은 오직 이모지 대체 하나뿐이고
배치·크기·간격·정렬·폰트비율은 픽셀 단위로 일치»로 분류.
**F**(색·명암 집중): ①9 ②9 ③9 ④9 ⑤**7** ⑥9 → 7. 색 19종 ΔRGB 표를 떠서 대부분 ΔE<10 임을 확인했으나
**↑ 버튼 한 곳**에서 두 가지를 잡았다.

### F 가 잡은 것 (E 는 못 본 것)

1. **베벨이 반전됐다.** ref 는 «바깥 밝은 림(189) > 면(170)» 인데 우리는 림(172) < 면(179).
   1회차에 림을 넣긴 했지만 면 그라데이션이 아래로 갈수록 밝아져(#CFCFCF) 림보다 밝아진 것.
2. **화살표 상단에 검정 톱니(스파이크)** — 2회차에 넣은 `drop-shadow` 4방향 체인이 삼각형 꼭짓점에서 어긋난다.

### 반영

- **화살표를 인라인 SVG 로 교체** — `paint-order:stroke fill` + `stroke-linejoin:round`.
  세 번째 시도 만에 해결했다: ① 글리프 + `-webkit-text-stroke` → 스트로크가 초록을 먹어 **코어 4px**
  ② CSS 도형 + `drop-shadow` 체인 → 꼭짓점 **톱니** ③ **SVG path** → 초록 1800px / 검정 3821px (ref 1671 / 3250).
- **버튼 은색 재보정** — 림 `#A0A0A0` · 면 `#767676→#8E8E8E`. 실측 **림 Δ0 · 면 Δ2**, 베벨 순서 복원.
- 색 4건: 진행바 초록 `#97EB2A` · 카드 배경 `#FFFDF2` · 서브탭 비선택 `#635340` · 헤더 본체 `#8A5D3E` (전부 Δ3).

> **교훈**: «두께가 있는 외곽선이 필요한 도형»은 글리프도 CSS 도형도 아니고 **인라인 SVG + paint-order** 다.
> 글리프는 스트로크가 안쪽을 먹고, CSS 도형은 `drop-shadow` 가 꼭짓점에서 톱니를 만든다.
> 또 하나 — **베벨은 «색»이 아니라 «순서»다.** 림과 면의 밝기 대소가 뒤집히면 색이 맞아도 입체가 죽는다.

## 4회차 — H 7 (G 는 API 오류로 중단, 대체 G2 는 4회차 캡처 기준으로 별도 진행)

1. **카드 3장의 «바깥 갈색 링 + 하단 그림자»가 통째로 없었다.**

   → 실측 크림 구간 **x366..371 = ref 와 완전 일치**.
2. **하단 비용 바가 좌로 12px 밀려 카드 검정 왼쪽 테두리를 106px 구간 덮고 있었다.**
   2회차에 D 의 «그룹 중심 8px 좌측» 지적을 `left:0;right:16px` 로 반영한 것이 과했다.

3. **진행바 초록 채움이 완전 알약(r≈20)** 이었다. ref 는 거의 직사각(r≈4, 우단 x423).
   → 트랙 클립 `border-radius:8px` + 채움 `4px`, 채움 폭 공식 `16 + ratio×632`
   → 모서리 행까지 실측 ref (205,421)/(203,423)/(204,423) vs 우리 (206,422)/(203,423)/(202,423).
4. 크림박스 어두운 패널이 **28px 페더링**돼 있었고(ref 는 하드 엣지) 하단 밝은 립 6px 이 없었다. 상단 경계도 44px 어긋남.
