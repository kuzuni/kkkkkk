## 1. 결손의 정체 — 318·321·322 와 같은 «경로가 한 칸 짧다»

판정식은 **이미 있었다**. `blessTick()` 이 1초마다
`sideAlert('bless', blessAny())` 로 좌측 사이드 «축복» 아이콘을 켠다(index.html 26150,
`blessAny() = BLESS.some(x => !blessOn(x.k))`). 없던 것은 **부품**이다 —
카드 안 «받기» 알약 `.tm` 에는 배지 노드가 한 개도 없었다.

그래서 팝업(`#blsw` z41)을 여는 순간 사이드 아이콘이 가려지고,
**«받을 게 있다» 는 것까지는 알겠는데 세 칸 중 어느 칸인지가 화면에서 사라진다.**
293(우편) · 318(출석) · 321(룰렛) · 322(퀘스트)와 **같은 병·같은 처방**이다.

판정식은 새로 만들지 않았다. `blessAny()` 의 **칸별 항**이 그대로 `!blessOn(k)` 이고,
`renderBless()` 가 이미 그 값(`on`)을 손에 들고 있다 — 한 줄만 더 쓰면 된다.

## 2. 자리 — 322 의 교훈대로 «이 알약에서 다시 쟀다»

322 가 남긴 교훈은 «버튼 안쪽 우상단이 빈다는 전제를 베끼지 말고 버튼마다 다시 재라» 였다.
`tools/probe325.js` 실측:

| 국면 | 알약 `.tm` | 글자 `<i>` 잉크 | 알약 안 «글자 오른쪽 남는 폭» |
|---|---|---|---|
| 받을 수 있음("받기") | 219×98 | 56.55 | **65.83px** |
| 활성 중("00:00:00") | 219×98 | 136.97 | 25.62px |

닷은 27 + 바깥 링 7.5×2 = **42px** 를 먹는다.
**받기 국면의 65.83px 안에는 들어간다** — 그리고 활성 국면의 25.62px 은 문제가 되지 않는다.
그 국면은 «받을 수 없음» 이라 **닷이 애초에 안 켜지기 때문**이다(`.alert` 조건 = `!blessOn(k)`).
자리 싸움은 «닷이 켜지는 국면» 에서만 성립한다.

그래서 `.qs-b` 처럼 바깥으로 내보낼 이유가 없다. **오히려 바깥은 못 쓴다** —
`.bls-c{overflow:hidden}`(11187) 이라 318·322 가 쓴 «바깥 우상단 코너(−9,−9)» 는 **잘린다**.

```css

```

`.sk-btn`·`.ifbtn.pbtn`(321) 과 **같은 값**이라 자리 규약이 갈리지 않는다.
`.tm` 은 `.bls-c>.b>*{position:absolute}` 로 절대배치라 기준 상자가 되고,
테두리가 아니라 `inset` box-shadow 라 오프셋 12 는 알약 변에서 그대로 12px 이다.

## 3. 초록 — `.off` 는 «꺼진 카드» 가 아니라 «받을 수 있는 카드» 다

여기가 이 작업에서 유일하게 헷갈릴 자리다. `renderBless()` 는

```js
c.classList.toggle('off', !on);        // on = blessOn(x.k)
```

즉 **`.off` 국면이 바로 «지금 받을 수 있다»** 이고, 알약 글자가 "받기" 인 것도 그때뿐이다.
그래서 주인이 말한 «받기 버튼 초록색» 은 **`.bls-c.off .tm` 한 줄**에서 갈리면 되고,
활성(시간 표시) 알약 `#926A24` 는 손댈 이유가 없다.

```css
.bls-c.off .tm{background:#4CBA2E;box-shadow:inset 0 0 0 3px #2F8F1E}   /* 325 */
```

색은 새로 만들지 않고 **202 «가능=초록» 규약의 `.ifbtn` 팔레트**에서 가져왔다
(`--gb-mid:#4CBA2E` 본체 · `--gb-dk:#2F8F1E` 테두리). 구조는 기존과 같은
«플랫 채움 + inset 3px 어두운 링» 이라 **알약 bbox·글자 자리가 한 픽셀도 안 움직인다**
(34 는 이미 통과한 화면이다 — verify325 [H] 가 12항목으로 감시한다).

## 4. ⚠ 특이성 함정 — `#blsw` 도 «ID 급으로 `<s>` 를 켜 두는 화면» 이었다

166 ⓔ · 202 §3 · 283 · 294 와 **똑같은 모양**이 34 에도 있다:

```css
#blsw i,#blsw em,#blsw b,#blsw s{display:inline-block; …}    /* (1,0,1) — 11081 */
```

클래스 급인 `.updot{display:none}`(0,1,0) 은 여기에 **진다**.
추측이 아니라 실측이다 — 착수 전에 `.tm` 안에 `.updot` 을 하나 심어 보니
`.alert` 도 없이 `display:block` · rect 27×27 로 **상시 점등**이었다.

처방도 같다. 같은 급의 스코프 짝을 반드시 같이 적는다:

```css
#blsw .updot{display:none}
#blsw .alert>.updot{display:block}
```

**이 두 줄을 지우면 «축복 걸린 칸에도 레드닷이 상시 점등» 으로 돌아간다.**
verify325 [F] 가 이 두 줄을 무력화해 보고 실제로 되살아나는지까지 감시한다
(`display:block` 으로 되돌아오는 것을 확인 — 죽은 감시가 아니다).

### ⚑ `tools/verify117.js` C3 게이트 부패 (→ PROGRESS **334** 로 등재)

`VERIFY117 39/40` — `C3 카드 클릭 → 축복 경험치 +1 · 타이머 표시` 1건이 빨갛다.

원인은 **34 의 13회차 변경을 게이트가 못 따라간 것**이다. 13회차가 알약 내용을
«시계 `<b class="ck">⏱</b>» 와 «숫자 `<i>`» 로 **분리**했는데(11239 주석),
verify117 은 아직 한 노드였던 시절의 형식을 단언한다:

```js
/^\u23F1 \d\d:\d\d:\d\d$/.test(document.querySelector('#blsC_atk .tm>i').textContent)
```

`.tm>i` 에는 이제 `"00:30:00"` 만 들어 있고 `"⏱ "` 접두어는 형제 `<b class="ck">` 에 있다.
**제품이 아니라 게이트가 옛 DOM 을 보고 있다** — 319·333 과 같은 계열(게이트 부패)이라

## 9. 남기는 교훈

**«바깥 코너» 는 322·318 의 기본값이 아니다 — 호스트의 `overflow` 를 먼저 봐라.**
322 는 «안쪽이 좁아서» 바깥으로 나갔고, 318 도 카드 바깥이 그리드 gap 이라 나갈 수 있었다.
34 는 `.bls-c{overflow:hidden}` 이라 **바깥으로 나가면 잘린다** — 자리 규약을 베낄 때
«남는 폭» 만 재고 «잘리는가» 를 안 재면 화면에서 사라지는 배지를 만든다.

**그리고 «남는 폭» 은 «닷이 켜지는 국면» 에서만 재라.** 이 알약은 활성 국면에서
남는 폭이 25.62px 로 줄어 42px 를 못 받는다 — 그것만 보면 «안 들어간다» 로 잘못 결론난다.
그 국면은 닷이 안 켜지므로 애초에 자리를 다투지 않는다. 자리 계산의 정의역은 **점등 조건과 같다**.
