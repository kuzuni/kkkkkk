## §1 재현 — 338 대로 «처방 전에 재현»

착수 직후 `node tools/verify891.js`:

```
FAIL [2] 우리 1600 — 띠 13행 · D1 0/0/0 · D2 0/0/0 · max|Δ| 0.4 (z 3)
PASS [2] 우리 1841/1920/2280/2600 — 띠 293행 · D1 29/28/21
VERIFY891 15/16 FAIL
```

등재문의 값과 한 자도 안 틀렸다. 여기서 등재문은 갈래 둘을 적어 두었다 —
ⓐ 띠가 굶은 것이 **제품의 결함**(813·879·926 의 축) · ⓑ **문턱(`OUR_MIN`)을 창 길이에 비례**시킨다.

**둘 다 아니었다.** `node tools/probe891.js` 가 같은 표에서 이미 답을 들고 있었다:

| 프레임 | 화소로 찾은 띠 | **DOM 이 아는 띠**(격자 상변 − 패널 상변) |
|---|---|---|
| 1600 | **13행**(top 7 → bot **20**) | **212.8px** |
| 1841~2600 | 293행(top 7 → bot 300) | 317.3px |

⇒ 1600 의 띠는 굶지 않았다. **자의 창**이 격자 상변 213 대신 **20** 을 짚은 것이다
(1841 도 17행 일찍 짚고 있었다 — 같은 병의 약한 얼굴).
LESSONS 932-③ «갈림이 «창» 의 것인지 «그림» 의 것인지부터 가른다» 가 그대로 걸린 자리다.

## §3 처방 — 가르는 축은 «두께» 가 아니라 «밝기의 층»

카드 **면**은 계조 90 에서도 넓게 밝고, 몰딩 규칙선은 그 문턱에서 사실상 0 이다:

|---|---|---|
| ref 격자 상변(y144) | 0.538 | **0.532** |
| 우리 격자 상변(1600 y213) | 0.509 | **0.468** |
| 몰딩(1600 y20) | 0.994 | **0.002** |
| 몰딩(1600 y37 · y84) | 0.973 · 0.573 | **0.000** |

⇒ 트리거를 `brightFrac(y, 90) ≥ 0.30` 으로 올리고, 두께도 **같은 축**에서 묻는다 —
«뒤 40행 중 면 행(계조 90 비율 ≥ 0.10)이 25% 이상».
실측 여유: ref **20/40 = 0.50** · 우리 **40/40 = 1.00** ↔ 몰딩 자리 **0/40**.
새 상수는 넷(90 · 0.30 · 0.10 · 0.25)이고 전부 **한 축(면 비율)** 위의 수다.
