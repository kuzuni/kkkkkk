## 함정 2건 (LESSONS 등재)

### ① 122 의 «흔들림» 이 도는 요소는 `getBoundingClientRect()` 로 판을 못 잰다

첫 게이트가 A4 에서 **122.9×54.3**(기대 120×46)으로 빨갰다. 뱃지 `.cn-cd>.cp` 는 122 가 넣은
±4° 흔들림이 걸려 있어 rect 가 **회전 외접 사각형**이다. `document.getAnimations()` 를 전부
`currentTime = 0` 으로 고정해도 소용없었다 — 이 뱃지는 `--jz-d:-1.5s` 로 **음수 딜레이**를 걸어
칸마다 반주기씩 어긋내므로(122 5회차 처방) t=0 이 곧 «회전 0°» 가 아니다.
→ 판·겹침은 전부 **`offsetWidth`/`offsetLeft`**(레이아웃 박스, transform 무관)로 재도록 고쳤다.
`.cn-ml>.ex` 도 펄스(scale)가 걸려 있어 같은 이유로 `offsetLeft` 를 쓴다.

### ② «글자가 길어지면 넘친다» 는 눈대중이 틀렸다 — 재고 나서 판을 안 건드렸다

«쿠폰 +1»(5자) → «마일리지 +1»(7자)이라 fs 25 · 안쪽 112 면 넘칠 것으로 보고 `scaleX` 를 줄일
생각이었다. 실측은 **58.3 → 92.4px(여유 22.6)** 로 여유가 남았다 — 게임 서체(126 GameKR)의
한글 advance 가 fs 의 0.8 배 남짓이라 손으로 센 «fs × 글자수» 추정이 +30% 과대였다.
줄였으면 **레퍼런스 실측 판(120×46) 안의 글자만 혼자 작아져** 13 의 ②(상대 크기 비율)를 깎을 뻔했다.
LESSONS A1 «advance 보다 좁은 박스 + `text-align:center` → 좌측 정렬» 함정의 **반대 방향 오판**이다.
→ 문구를 늘릴 때는 **먼저 Range bbox 로 재고**, 넘칠 때만 판이 아니라 글자를 손댄다.
