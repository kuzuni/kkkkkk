## 1. 증상과 원인

`SKILLS` 의 5종이 **한 객체 리터럴 안에서 `n` 을 두 번** 썼다 — 앞은 이름, 뒤는 발사 수/연쇄 대상 수다.

```js
{ id:'stone', n:'돌팔매', … ,
  t:'proj', k:'shuri', n:1, sp:470, … }     // ← 뒤 n 이 이름을 덮는다
```

JS 는 중복 키를 **문법 오류로 잡지 않고 뒤 값이 조용히 이긴다.** 그래서:

| 스킬 | 이름이어야 할 `n` | 실제 런타임 `n` |
|---|---|---|
| `stone` | 돌팔매 | **1** |
| `arrow` | 꿰뚫는 화살 | **2** |
| `frost` | 서리 연쇄 | **4** |
| `gale` | 폭풍의 칼날 | **12** |
| `lance` | 천벌의 창 | **3** |

귀결 두 가지 — 버그 없는 빌드에서 게이트를 돌려 **양쪽 다 실측 재현**했다(§4):

- ⓐ **53 가방 «재화» 탭 크래시.** 5종 중 하나라도 재료를 보유하면 `bagCur()` 가 `n:it.n`(숫자)을 담고,
  `renderBag()`(~13183)이 `r.n.replace(/"/g,'')` 를 불러 **`TypeError: r.n.replace is not a function`**.
  탭이 통째로 안 그려진다.
- ⓑ **이름이 숫자로 표시.** 08 스킬 세부 팝업 제목이 «1 / 2 / 4 / 12 / 3», 11 확률 정보 표의 이름 칸도 같다.

## 2. 수정

지시서(PROGRESS 109 행 ①) 그대로 — **뒤쪽 `n` 을 `cnt` 로 바꾸고 이름 `n` 은 그대로 둔다.**
다른 화면이 전부 `it.n` 을 이름으로 읽으므로 이름 쪽을 바꾸면 파급이 훨씬 크다.

| 자리 | 전 | 후 |
|---|---|---|
| `SKILLS` stone·arrow·frost·gale·lance | `n:1 / 2 / 4 / 12 / 3` | `cnt:1 / 2 / 4 / 12 / 3` |
| `castGeneric()` `case 'proj'` (~9132) | `const n = s.n \|\| 1` | `const n = s.cnt \|\| 1` |
| `castGeneric()` `case 'chain'` (~9154) | `i < (s.n \|\| 3)` | `i < (s.cnt \|\| 3)` |

읽는 쪽은 이 **두 곳뿐**이다(`grep 's\.n\b'` — 나머지 2건은 `SLOTS` 의 부위 이름이라 무관).
저장 구조는 건드리지 않았다(세이브 마이그레이션 불필요 — `S.own` 은 id 로만 색인한다).

## 3. 기능 체크 표 (헤드리스 실측 — 「눌렀을 때 무엇이 바뀌는가」)

| 확인 | 방법 | 결과 |
|---|---|---|
| 5종 이름이 문자열 | `SKILLS/EQUIPS/PETS/RELICS` 전 항목 `typeof n` | 비문자열 **0건** |
| 53 «재화» 탭 | 5종 재료 7개씩 보유 → `openBag()` | 크래시 **없음** · 칸 ≥ 5 · 5종 이름 전부 표시 |

| 08 스킬 세부 | `showSkillDetail()` × 5 → `#mtitle` | 돌팔매 / 꿰뚫는 화살 / 서리 연쇄 / 폭풍의 칼날 / 천벌의 창 |
| 11 확률 정보 | `openProbInfo('skill',999)` → `.prb-row .nm i` | 24행 훑음 · 숫자 이름 **0건** · 5종 전부 보임 |
| **전투 회귀** — 발사 수 | 적 8기 배치 후 `castGeneric()` 직접 호출, `shots`/`bolts` 증가분 | stone **1** · arrow **2** · frost **4** · gale **12** · lance **3** = 설계값 · `hits` 와도 일치 |

전투 거동은 **한 발도 바뀌지 않았다** — 버그 빌드에서 `s.n`(숫자)으로 나오던 값이 이제 `s.cnt` 로 나올 뿐이라,
음성 테스트(§4)에서도 «실사격 · 생성 수» 7항목만은 양쪽 다 통과했다. 이 항목들이 갈리지 **않는** 것이 곧 무회귀의 증거다.

## 5. 게이트 구성 (`tools/verify109.js`, 42항목)

- **① 소스 스캔 (9항목)** — `SKILLS·PETS·RELICS·SLOTS·SHOP_BOXES·DUNGEONS·EQ_NAMES` 의 객체 리터럴을
  문자열·주석을 건너뛰며 훑어 **중복 키 0건**을 단언한다. 지시서 ②가 요구한 핵심이다:
  **중복 키는 런타임으로는 영영 못 본다**(이미 덮인 뒤다). 소스를 직접 보는 수밖에 없다.
  덤으로 `SKILLS` 구간에 `n:<숫자>` 리터럴이 없는지도 본다.
- **② 런타임 이름 타입 (2항목)** — 4개 테이블 전 항목 `typeof n === 'string'`.
- **③ 발수 회귀 (18항목)** — `cnt` 값 5개 + `hits` 일치 + **실사격**(적 8기를 놓고 `castGeneric()` 을 직접 불러
  `shots`/`bolts` 생성 수를 센다). 상수만 읽지 않고 실제로 쏜다.
- **④ 53 가방 (6항목)** — 5종 보유 상태에서 두 탭 렌더 + 칸 이름이 문자열 + 캡처.
- **⑤ 이름 표시 (7항목)** — 08 `#mtitle` · 11 `.prb-row .nm i`.
