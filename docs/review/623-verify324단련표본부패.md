## 1. 재현 — 등재문 가설이 그대로 확인됐다 (338 규칙)

수리 전 `node tools/verify324.js` = **33/34**, 빨간 항은 정확히 하나다.

```
FAIL  [5] 단련 temperUp — 전투력이 안 올랐다 (재료 준비 실패) — 786367098721633 → 786367098721633
```

등재문이 지목한 **613**(단련석 직접 지불 · 전환·포인트 폐지)이 뿌리였다. 하네스의 재료 준비가

```js
['단련 temperUp', "temperObj().pts = 99999; temperUp(TEMPERS[0].k);"],
```

인데, 613 이후 제품에서 «단련이 쓰는 재화 잔액은 `S.tstone` 하나»(index.html 19814 주석)이고
`temperUpOk = k => tstoneHave() >= temperCost(k)` 다. ⇒ `temperObj().pts = 99999` 는
**살아 있는 어떤 판정도 읽지 않는 죽은 필드에 값을 쓰는 한 줄**이 됐고, `S.tstone` 이 0 인 채
`temperUp()` 이 **첫 줄 `if(… || !temperUpOk(k)) return false;` 에서 되돌아갔다.**
cp 가 안 움직였으니 토스트도 0장 — 즉 **제품은 한 줄도 안 상했고 표본만 굳었다.**

## 2. 처방 — 자리를 비우지 않고 «지금의 준비 절차» 로 갈아 끼웠다 (333 규약)

```js
['단련 temperUp', "temperUp(TEMPERS[0].k);",
                 "S.tstone = temperCost(TEMPERS[0].k) * 1e3; markDirty();",
                 "({ ok: temperUpOk(TEMPERS[0].k), d: … })"],
```

- 액션(`temperUp`)과 준비(`S.tstone`)를 **갈랐다** — `act()` 는 `prep` 를 스냅샷 밖에서 돌리므로
  준비의 상태 변화가 Δ 에 안 섞인다(주석이 이미 그 이유를 적어 두고 있었다).
- ⚑ **액수를 상수로 다시 적지 않았다** — `temperCost(TEMPERS[0].k)`, 곧 «지금 서 있는 구간의 값»
  을 **제품에게 물어서** 1,000배로 깐다. 336 이 [6]·[7] 지갑에서 이미 겪은 것과 같은 함정이다:
  여기 `99999` 같은 수를 다시 박으면 `TEMPER_SEG`·`temperSegCost` 곡선이 바뀌는 날 이 자리가
  똑같이 다시 썩는다.
- «전투력이 실제로 오른다» 는 **뜻은 그대로**다 — 단언문도, 재는 축(cp 실측차 = 토스트 문자열)도
  한 칸도 안 넓혔다.

## 3. 곁들여 닫은 구멍 — Δ=0 이 두 가지 뜻을 한 항에 뭉치고 있었다

이 부패가 **표에 «제품이 안 올렸다» 로 찍혔다**는 것이 본체의 절반이다. [5] 의 루프는
`r.after <= r.before` 하나로 «준비가 안 먹었다» 와 «제품이 안 올린다» 를 같은 문장에 적는다.
[6] 은 **336 이 이미 같은 사고를 겪고** `pre6.ok`(«하네스가 살 수 있는 자리를 만들었다»)를
세워 뒀는데, [5] 에는 그 자가 없었다.

⇒ `act()` 에 선택 인자 `pre` 를 붙여 **준비가 실제로 재료를 깔았는지를 제품에게 묻고 따로 적는다**
(`{ ok, d }`). 기존 여섯 표본은 `pre` 를 안 넘기므로 **항 수도 동작도 그대로**다.

```
  ok  [5] 단련 temperUp — 준비가 실제로 재료를 깔았다 (아니면 아래 Δ=0 은 제품 탓이 아니다) — 단련석 1000 ≥ 비용 1
  ok  [5] 단련 temperUp → 1장 · 값 = 실측차 — 1장 «⚔️ 전투력 +15.7D» 기대 «⚔️ 전투력 +15.7D»
```

## 4. 무르게 푼 수리가 아님 — §R 되돌림 시험 2항 신설

허용 오차는 한 칸도 안 넓혔고, 두 방향으로 못박았다.

| 항 | 무엇을 재나 | 결과 |
|---|---|---|
| `[R]` 613 이전 문법 | `S.tstone=0` + `temperObj().pts=99999` 로 되돌리면 `temperUpOk` 가 **거짓** | `단련석 0 < 비용 1` ⇒ 빨갛던 것이 실재였다 |
| `[R]` 제품 무력화 | 새 준비를 깐 채 `temperUp` 을 no-op 으로 바꾸면 Δ=0 · **0장** | 이 항은 «전제» 가 아니라 **제품**을 본다 |

두 번째가 핵심이다 — 준비만 초록으로 만들어 놓고 본 단언이 헐거워졌다면 여기가 빨개진다.

## 7. 교훈

1. **«재료 준비 실패» 라고 적힌 빨강은 제품이 아니라 자를 가리킬 때가 많다** — 재화 축이 바뀐
   직후(613·614)라면 특히. 제품을 열기 전에 준비 한 줄이 아직 살아 있는 판정을 지나는지부터 본다.
2. **하네스가 액수를 상수로 적으면 곡선이 바뀌는 날 같이 썩는다**(336 이 지갑에서, 623 이 단련석에서
   두 번째로 겪었다). 준비값은 **제품의 비용 함수에게 묻는다.**
3. **Δ=0 하나에 두 뜻을 담지 마라** — «준비가 안 먹었다» 와 «제품이 안 올린다» 는 다른 사건이고,
   뭉쳐 두면 표가 엉뚱한 곳을 가리킨다. [6] 은 그 자를 갖고 있었고 [5] 는 없었다.
