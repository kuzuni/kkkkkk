## 2. 고른 처방 — «값은 그대로, 자리만 옮기고, id 는 못으로 박는다»

등재문의 처방 후보는 ⓐ v 배열을 오름차순 재배치 · ⓑ v 를 자리(j)에서 파생, 두 가지였다.
그리고 **«id 를 다시 매기지 말 것»** 이라는 못이 박혀 있었다 — `weapon0`·`weapon0_1`… 처럼 id 에
자리가 들어 있고 구 세이브가 그 id 로 보유·장착·강화 Lv 를 저장하기 때문이다.

ⓑ(자리에서 파생)를 **버렸다**. 자리에서 파생하면 1번째 칸의 v 가 1.00 → 0.90 으로 바뀌어
**이미 그 장비를 갖고 키운 사용자의 수치가 통째로 내려간다**(21티어 × 1종씩 = 21종). 밸런스를 안 건드리고
순서만 고치는 길이 있는데 굳이 값을 흔들 이유가 없었다.

ⓐ 를 택하되 **id 파생식을 폐기하고 항목마다 id 를 명시로 박았다**:

```
/* 전 — 자리에서 파생. 자리를 옮기면 id 가 따라 바뀐다 */
EQUIPS.push({ id:s.k + g + (j ? '_' + j : ''), ... })

/* 후 — 명시 id 우선, 없을 때만 옛 파생식 */
EQUIPS.push({ id:x.id || (s.k + g + (j ? '_' + j : '')), ... })
```

그 결과 **자리만 바뀌고 «id ↔ 이름 · v · 아이콘 · m · cd» 짝은 144종 전부 한 글자도 안 바뀌었다.**
HEAD~1 과 현재 트리에서 id→속성 맵을 떠서 비교한 결과 **차이 0건 / id 집합 완전 일치(144)**.
구 세이브(`S.own`·`S.eqSlot`·`S.eqPet`·강화 Lv)는 손상 경로 자체가 없다 — 게이트 [F] 가 옛 id 로
보유·장착·Lv 를 박은 세이브를 실제로 `load()` 시켜 확인한다.

## 3. 등급 경계 — «5번째 < 다음 등급 1번째»

주인 규칙의 후반부다. 재배치는 등급 **안** 순서만 고치므로 경계는 따로 봐야 한다.

- 장비: `gWear(g) × max(v_g) < gWear(g+1) × min(v_{g+1})`. 등급 배수 최소 비 **1.500**(1.0→1.5) 이
  개체차 폭 **1.250**(1.15/0.92) 보다 크므로 21개 경계 전부 성립. 게이트 [A4]·[A6].
- 펫: g0 최대 0.388 < g1 최소 0.464 … g6 최대 7.708 < g7 11.638. 7개 경계 전부 성립. 게이트 [B3].

**⚠ 다음 세션에게** — `v` 폭을 지금(1.250)보다 넓히면 그 순간 경계가 뒤집힌다. 상한은 1.500 이고
게이트 [A6] 이 «개체차 폭 < 등급 배수 최소 비» 로 그 여유를 상시 감시한다.

## 4. 스킬 — 주인이 완화한 쪽

주인 추가 지시: «같은 등급이면 효과 비슷해도 될 듯». → **오름차순을 강제하지 않는다.**
요구는 «등급 안에서 세기가 크게 벌어지지 않을 것» 하나다.

척도는 지어내지 않고 **게임이 전투력에 쓰는 식 그대로**(`stat.dps`) 썼다 — `m × hits / cd`
(cd 0 인 지속형은 `m × 3`). 기준선은 **등급 안 최대/최소 ≤ 3.0**(이미 기준선 안이던 일반 1.93 ·
고급 2.69 · 희귀 2.24 를 그대로 둘 수 있는 선).

| 등급 | 전 | 후 | 손댄 것 |
|---|---|---|---|
| 일반 | 1.93 | 1.93 | — (무변경) |
| 고급 | 2.69 | 2.69 | — (무변경) |
| 희귀 | 2.24 | 2.24 | — (무변경) |
| 영웅 | **12.73** | **2.83** | poison `hits` 5 신설 · drain m 2.00→2.40 · frost m 1.45→1.25 · bounce m 1.40→1.15 |
| 전설 | **6.00** | **2.91** | boomer `hits` 2 신설 · gale m 1.05→0.85 |
| 신화 | 3.13 | **2.93** | lance m 3.20→3.00 |

**`hits` 두 건은 밸런스 변경이 아니라 «선언 정정» 이다** — `hits` 는 `stat.dps` 합산에만 쓰이고
실피해에는 안 들어간다.

- `poison`(맹독 안개): 장판 `life 5.0s` × 틱 `0.4s` 마다 `dmg × 0.4` → 한 적이 받는 총 타격량은 **5.0**.
  선언이 1 이라 **전투력이 실제의 1/5** 로 세고 있었다. 같은 계열 `flask`(화염병)는 `zlife 4.5 → hits 4.5`
  로 **이미 이 규약을 쓰고 있었다** — poison 만 빠져 있던 것이다.
- `boomer`(부메랑): `pierce 99` 로 나갈 때·돌아올 때 두 번 지나간다 → 최소 **2**. 선언이 1 이라
  «전설 등급 최약» 으로 잘못 보였다.

즉 영웅·전설의 «최약» 두 자리는 **절반이 계산 착시였고**, 착시를 걷어낸 뒤 남은 편차만 `m` 으로 조였다.
27종 전면 재조정이 아니라 **튀는 세 등급만** 손댔다.

### verify86 의 «기존 13종 불변» 표를 한 칸 고쳤다 — 왜 정당한가

`verify86` 은 `OLD` 표로 기존 13종의 `[g, cd, m]` 을 못 박고 있었고, 260 의 `drain` m 2.00→2.40 이
거기 걸렸다(36/37 FAIL). 표를 **drain 만** 2.40 으로 갱신하고 근거 주석을 달았다.

- 그 표가 지키는 것은 «**86 의 리팩터가 기존 스킬을 건드리지 않았다**» 이지 «m 을 영원히 못 고친다» 가 아니다.
- 세이브는 **id 로만** 보유·장착을 저장한다 — `m`·`cd` 는 세이브 호환이 아니라 **밸런스 값**이다.
- 갱신하지 않으면 260 의 «등급 안 편차 ≤ 3.0» 과 이 표가 **서로를 부순다**(둘 다 통과할 수 없다).
- 나머지 12종은 260 이 손대지 않았다 — `poison`·`boomer` 는 `hits` 선언만 붙었고 `id·g·cd·m` 은 그대로다.
