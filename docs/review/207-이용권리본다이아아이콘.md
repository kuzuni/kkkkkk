## 1. 실측 — 밀린 것은 «리본 6줄 전부» 이고, 밀린 양이 소수점까지 같다

| 리본 | `--gx` | 판 중심 대비 **아이콘 중심 Δ** | 판 안쪽 여백(slack) | 수량 Δx |

수량(`u`)은 Δx 0 으로 멀쩡했다 — **어긋난 것은 판 안의 아이콘 하나뿐**이다.

## 2. 원인 — `display:flex` 가 **ID 특이도 태그 리셋에 조용히 졌다**

`tools/probe207b.js`(CDP `CSS.getMatchedStylesForNode`)로 판(`b`)에 걸린 규칙을 전부 뽑았다:

```
.pvc > .rb > b                                    display:flex  align-items:center  justify-content:center
#shopw i, #shopw em, #shopw b, #shopw u, #shopw s  display:inline-block          ← 이긴다
```

- `.pvc>.rb>b` 특이도 **(0,3,1)** · `#shopw b` 특이도 **(1,0,1)** → **ID 가 이긴다.**
- 그래서 판의 computed `display` 는 `flex` 가 아니라 **`block`**(`position:absolute` 라 inline-block 이 블록화)이었다.
- 그런데 `align-items` / `justify-content` 는 **그대로 남는다**(다른 속성이라 안 진다) —
  선언은 멀쩡히 보이는데 **아무 일도 하지 않는다.** 이게 «CSS 만 읽어서는 안 보이는» 이유다.
- flex 가 아니니 안의 `.cic` 은 그냥 줄 상자 시작점 = **좌상단**에 앉았다.

이 리셋(4356행)은 10 상점 페이지 전체에 걸린 것이라, **`#shopw` 안에서 i·em·b·u·s 에
`display` 를 새로 주는 규칙은 전부 이 리셋을 이겨야 한다.** 151 이 판을 `<b>` 로 잡은 순간부터
심어져 있던 결함이고, 화면에는 «아이콘만 왼쪽 위로 밀린» 모습으로 나온다(= 주인 보고 그대로).

### 191 과 같은 계열인가 → **아니다**

등재문이 «191 유물 아이콘 밀림과 같은 이미지 아이콘 전환(125) 후유증 계열» 을 후보로 걸어 뒀는데,

여기는 여백이 **+19 로 넉넉**하고(191 식 음수 여백 아님), `.cic` 은 이모지가 아니라 `<img>` 라

등재문의 다른 후보(`cic` 의 기본 크기·`vertical-align` 이 줄높이와 안 맞음)도 아니었다:
`vertical-align:-3.2px` 은 flex 컨테이너 안에서는 애초에 무시된다.
