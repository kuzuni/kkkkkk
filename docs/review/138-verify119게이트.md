## 2. A5 — «게이트가 자기 것이 아닌 성질을 물었다»

옛 판정식(`tools/verify119.js:66`):

```js
ok(/id="rwCost"><i>🔮<\/i><b>100<\/b>/.test(SRC), 'A5 정적 HTML `#rwCost` 기본 표기 «822» → «100»');
```

119 가 지키려는 성질은 **«정적 기본 표기가 822 가 아니라 100 인가»** 하나뿐인데, 정규식이 그 옆의 **아이콘 마크업까지 통째로** 물고 있었다. 그래서 125(화폐 아이콘 통일, `50fbbdd`)가

```html
<i>🔮</i>            →    <i data-cur-slot="relic"></i>
```

로 바꾸자, **비용 표기는 «100» 그대로인데** A5 만 깨졌다. 119 의 회귀가 아니라 **게이트의 오탐**이다(나머지 항목 전부 PASS 인 것이 그 증거다).

### 고친 것

`#rwCost` 엘리먼트 내용을 먼저 떼어 낸 뒤, **성질별로 두 항목으로 쪼갰다.**

```js
const rw = SRC.match(/id="rwCost"[^>]*>([\s\S]*?)<\/div>/);
ok(!!rw && /<b>\s*100\s*<\/b>/.test(rw[1]) && !/822/.test(rw[1]), 'A5 …기본 표기 «822» → «100»');
ok(!!rw && /data-cur-slot="relic"/.test(rw[1]),                   'A7 …아이콘은 125 의 화폐 슬롯');
```

- **A5 = 119 의 성질** — `b` 의 기본 숫자가 100 이고 «822» 가 없다. 아이콘 모양은 안 본다.
- **A7 = 125 의 성질** — 화폐 슬롯 자리가 살아 있다. 아이콘 **모양**은 125 의 게이트가 볼 일이고 여기선 **자리만** 본다.

### 판정식 대조표 (음성 검사 — 고친 게이트가 여전히 회귀를 잡는가)

| 마크업 | A5 | A7 | 기대 |
|---|---|---|---|
| `<i data-cur-slot="relic"></i><b>100</b>` (현재) | ✅ | ✅ | 둘 다 통과 |
| `<i>🔮</i><b>822</b>` (119 이전 = 회귀) | ❌ | ❌ | **A5 가 잡는다** |
| `<i>🔮</i><b>100</b>` (125 이전) | ✅ | ❌ | **A5 는 통과**(125 는 119 의 성질이 아니다) · A7 만 반응 |
| `<b>100</b>` (슬롯 소실 = 125 회귀) | ✅ | ❌ | **A7 이 잡는다** |

3·4행이 이번 수정의 요점이다 — **아이콘이 바뀌어도 A5 는 안 깨지고, 아이콘이 사라지면 A7 이 대신 잡는다.**

## 3. 곁가지로 같이 나온 F1~F5 — 벽시계 가정

등재 시점(34/35)에는 없던 실패다. 원인은 게임이 아니라 **게이트의 대기 방식**이었다.

```js
await page.dispatchEvent('#rwBasin', 'pointerdown');
await page.waitForTimeout(1600);        // ← «1600ms 면 3회 다 돈다» 는 벽시계 가정
```

선언 수치로는 `TR_HOLD_DELAY 350` + `iv 160 × 0.86^n` 이라 3회차가 **t≈670ms** 에 끝나야 하고 1600ms 는 2배 여유다. 그런데 이 기기에서 `summonRelic` 호출 시각을 직접 찍어 보니

| 회차 | 실측 t | 선언 간격 | 실측 간격 |
|---|---|---|---|
| 1 (pointerdown) | 1231ms | — | — |
| 2 | 2001ms | 350 | **770** |
| 3 | 2156ms | 160 | 155 |
| 4 (실패 → 홀드 중단) | 2822ms | 138 | 666 |

**1→2 가 770ms** 로 밀렸다. `setTimeout` 이 메인 스레드 혼잡으로 지연된 것이고, 그 한 번의 지연이 3회차를 1600ms 창 밖으로 밀어내 **F1~F5 가 통째로 거짓 FAIL**(sum 2 / 잔액 152 / 비용 102)이 났다. 게임 로직은 정상이다 — 실제로 홀드는 3회를 돌고 4회차에서 스스로 멈췄다(`sum 3 · relic 50 · rwHoldStop(true)`).

이것도 A5 와 **같은 계열**이다: F 가 지키려는 성질은 «잔액이 다음 1회분에 못 미치면 홀드가 스스로 멈춘다» 이지 «몇 ms 안에 멈춘다» 가 아니다.

### 고친 것

```js
let fStopped = true;
try {
  await page.waitForFunction(() => S.cnt.sumRelic >= 1, null, { timeout: 20000 });          // 홀드 시작
  await page.waitForFunction(() => typeof rwHold === 'undefined' || !rwHold, null, { timeout: 20000 });  // 홀드 종료
} catch (e) { fStopped = false; }
```

**시간이 아니라 홀드 종료 자체**를 기다린다. 안 멈추면 20초 타임아웃으로 `fStopped = false` 가 되고 **F6 이 그걸 잡는다**(`F.holding === false && fStopped`) — 대기를 조건부로 바꾸면서 F6 이 자명해지지 않게 못박은 것이다. 즉 판정력은 그대로고 기기 속도 의존만 사라졌다.

## 5. 교훈 (LESSONS 반영)

> **게이트는 자기가 지키려는 성질만 물어야 한다 — «옆에 붙은 마크업» 도 «벽시계» 도 그 성질이 아니다.**
>
> 정규식에 이웃 요소를 끼워 넣으면 남의 작업이 내 게이트를 깨고(A5 ← 125), 벽시계로 비동기를 재면 기기 속도가 내 게이트를 깬다(F ← setTimeout 지연). 둘 다 **«거짓 FAIL» 이라 더 나쁘다** — 진짜 회귀와 구분이 안 돼서, 다음 세션이 멀쩡한 코드를 뒤지느라 회차를 태운다.
> 처방은 같다: ① 판정 대상을 **엘리먼트 단위로 먼저 떼어 내고** 성질별로 항목을 **쪼갠다**(A5/A7). ② 비동기는 **시간이 아니라 상태 전이**를 기다리고, 안 오면 그것을 **별도 항목이 잡게** 남겨 둔다(F6).
>
> 같은 계열의 등재가 이미 110·127·130·132·133·134 에 있다. 새 게이트를 쓸 때 «이 정규식/대기가 깨지는 이유가 내 성질 말고 또 뭐가 있나» 를 한 번 물어라.
