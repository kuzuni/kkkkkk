## 3. 처방 — 숫자를 바꾸지 않고 **제품에서 파생**시켰다

등재문의 경고(«그냥 숫자만 바꾸면 다음에 또 어긋나면 그대로 굳는다»)를 따라 316·443 선례대로 했다.
이 절이 실제로 묻는 것은 «초가 몇인가» 가 아니라 **«눌린 카드의 세부가 열렸는가»** 이므로,
기대값을 **[3] 에서 클릭 전에 읽어 둔 카드 id** 로 제품 표 `RAIDS` 에서 파생시킨다.

```js
/* [3] — 눌린 카드의 id 를 같이 들고 나온다 */
return { tag: …, hitCard: !!card, rcard: c.dataset.rcard || null };

/* [4] — 기대값이 그 id 에서 온다 */
const r = (typeof RAIDS !== 'undefined' && RAIDS.find(x => x.id === id)) || null;
… { en: r ? r.n : null, ef: r ? r.sec + '초' : null }
```

**⚠ 파생이 «그린 것 = 선언» 이 되지 않게 두 겹으로 막았다:**

- **ⓐ id 는 클릭 «전» 에 읽은 것**이다. 팝업이 다른 카드를 열면 제목이 그 자리에서 어긋난다
  (제품 렌더러는 `dgdRaid` 를 읽고, 자는 «내가 누른 카드» 를 읽는다 — 두 경로가 갈라져 있어야 비교가 성립한다).
- **ⓑ 표에서 못 찾거나 모양이 깨지면 그 자체가 실패**다 — 항을 하나 더 세워
  `!!dg.en && /^[0-9]+초$/.test(dg.ef)` 를 먼저 묻는다. 표본이 사라져도 조용히 초록이 되는
  공허한 항(422 «음성항이 공허하다» 계열)이 되지 않게.

## 7. 교훈

- **리터럴로 박은 «제품의 값» 은 지시가 한 번 바뀌면 그 자리에서 부패한다.**
  같은 값을 묻는 자가 넷이었는데 **표에서 파생한 셋은 264 를 그대로 통과했고 리터럴 하나만 빨개졌다** —
  파생이 관행이 아니라 **부패 면역**이라는 것이 한 화면에서 대조로 보인다.
- **부패한 항을 «지우거나 숫자만 갈아 끼우면» 뜻이 준다.** 이 항의 뜻은 «초 = 30» 이 아니라
  «**눌린** 카드의 세부가 열렸는가» 다. 파생으로 바꾸면서 그 뜻이 오히려 **세졌다**(R2 가 그 증거 —
  리터럴 시절에는 «아레나가 열려도 초가 60 이면» 통과할 수 있는 모양이었다).
- **파생은 공허해질 수 있다.** 기대값을 제품에서 읽는 순간 «표본이 사라지면 조용히 초록» 이 되는 길이 열린다 —
  파생 항 옆에는 **«기대값을 정말 읽었는가» 항을 반드시 한 줄 세운다**(R3 이 그 자리를 지킨다).
