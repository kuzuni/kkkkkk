## 2. 처방 — 새 상수 0개, 좌표 재계산 0줄

등재문 처방 ① 대로 묶음을 한 컨테이너(`.dcl-grp`)로 쌌다. 다만 컨테이너를 «상자» 가 아니라
**좌표계 원점**으로 썼다:

```css
.dcl-grp{position:absolute;left:0;right:0;top:calc(50% - 1114px);height:0}
```

자식 top `T` 는 `(VH/2 − 1114) + T` 에 그려지고, 묶음 중심 1114 는 어떤 프레임에서도 정확히 `VH/2` 에 앉는다.

**왜 «묶음 안 좌표를 다시 적기» 가 아니라 이 꼴인가:**

1. 묶음 안 15자리의 top 은 전부 측정표 31 의 «frame y = ref y − 84» 실측값이다. 이걸 −718 해서
   다시 적으면 **측정표와 CSS 가 서로 다른 숫자를 말하게 된다** — 다음 세션이 대조할 근거가 사라진다.
   원점만 옮기면 측정표 값이 글자 그대로 남는다(`verify426` [C] 가 그 값들을 직접 단언한다).
2. **높이를 주면 안 되는 이유가 따로 있다.** 이 화면은 «딤 빈 면을 누르면 닫힌다» 가 규약인데
   (`$('dclw').addEventListener('click', e => { if(e.target === $('dclw')) closeDunClear(); })`),
   높이 있는 상자로 싸면 묶음 안 빈 면 클릭이 **그 상자에 먹혀** `e.target` 이 `#dclw` 가 아니게 되고
   닫힘이 죽는다. 높이 0 이면 상자는 hit-test 대상이 아니고, 자식들은 그대로 잡힌다.
   `pointer-events:none` + `>*{auto}` 로도 되지만 `.upr-grp` 같은 중첩 자식까지 규칙이 늘어난다.
3. **z-index 를 안 줬다.** 주면 새 쌓임 맥락이 생겨 자식 z 1~5 가 `#dclw` 맥락에서 빠진다
   (밴드 1 ↔ 타일 2 ↔ 코인 3 ↔ 수량 4 ↔ 339 줄 5 의 순서가 통째로 바뀐다).
