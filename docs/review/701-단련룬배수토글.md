## 2. ⚑ 등가성은 «검사» 가 아니라 **구조**다 — 700 의 처방을 그대로 썼다

«×100 한 번 ↔ ×1 백 번» 을 자로 지키려 들면 축이 하나 늘 때마다 두 경로가 갈라진다.
700 이 `relicDrawOne` 으로 푼 그 자리를 여기서도 그대로 판다 — **«한 번» 코어를 하나 두고
×1 도 ×N 도 그 함수만 지나게** 한다:

```js
function temperUpOne(k){ … S.tstone -= temperCost(k); alloc[k]++; return c; }   /* 장부만 */
function temperUpBatch(k, n){ for(i<n){ if(!temperUpOk(k)) break; spent += temperUpOne(k); } … }
function temperUp(k){ return temperUpBatch(k, 1).done === 1; }                  /* ×1 = n 1 인 배치 */

function runeTryOne(id){ … S.rstone -= runeCost(r, l); const up = Math.random() < rate; … }
function runeTryBatch(id, n){ for(i<n){ if(!runeTryOk(id)) break; … runeTryOne(id) … } … }
function runeTry(id){ … return { ok:true, up, lv, rate, cost } }                /* 반환 꼴 불변 */
```

**룬이 확률 판정이라 이 표본이 700 보다 가혹하다** — 수열이 한 걸음이라도 어긋나면 곧바로 갈린다.

| 자 | 값 |
|---|---|
| `probe701` [4] ×1 200회 — **수리 전/후** | 룬·단련 장부 **한 글자도 안 달라졌다**(코어를 갈랐어도 ×1 은 불변) |
| `verify701` [D1] 씨앗 고정 ×1000 한 번 ↔ ×1 을 1000번 | 잔액·레벨·시도·성공·지출 **완전 일치**(룬 Lv.63 · 지출 15,733 / 단련 Lv.1000 · 지출 22,000) |
| `verify701` [D2] 같은 항등식 ×100 | 일치 |

⚠ **재화·만렙 검사를 코어에 안 넣었다** — 넣으면 «되는지» 와 «했는지» 가 한 함수에 섞여
부분 실행의 회계가 흐려진다. 검사는 배치가 **걸음마다** 한다(그것이 곧 클램프다).

## 3. ⚑ 주인 보강의 정체 — «총비용 = 단가 × N» 을 **적을 자리 자체를 없앴다**

단련 비용은 100레벨 구간마다 계단이다(`temperSegCost(⌊lv/100⌋)` = 1 · 3 · 6 · 10 …).
그래서 «단가 × N» 은 구간을 넘는 배치에서 **틀린 수**다 — `probe701` [5-a] 가 그것을 찍는다:

> Lv.95 에서 10회: **단가×10 = 10** ↔ **걸음 합 = 20** (구간 0 에서 5걸음 ×1 + 구간 1 에서 5걸음 ×3)

한 걸음씩 도는 코어에서는 그 곱셈을 적을 자리가 없다 — 비용이 매 걸음 «그 걸음의 레벨» 에서
읽히기 때문이다. 라벨도 같은 식(`temperPlan`)을 쓴다:

| 자 | 값 |
|---|---|
| `verify701` [F1] | 실제 차감 = 걸음 합(20) ≠ 단가×N(10) |
| `verify701` [F2] | **버튼이 그 값을 적는다** — 라벨 «20» = `temperPlan` 20 |

⚠ 룬은 계단이 아니라 지수(`base × r^lv`)이고 **성공해야 레벨이 오른다** — 그래서 «×N 의 총액» 이
사전에 확정되지 않는다(전부 실패면 하한, 성공이 섞이면 그보다 크다). 아래 위임 규약 ⓒ 참조.

## 9. 199 통지

**밸런스 계수는 0줄**이다. 다만 199 가 알아야 할 것이 하나 있다 —
**단련·룬의 «시간당 투입 상한» 이 ×1000 만큼 올라갔다.** 종전에는 홀드 틱(≈60ms)당 1회라
1초에 약 16회가 상한이었는데, 이제 1초에 약 16,000회다. 재화가 곧 상한이므로 **총량은 안 바뀌지만**
«재화를 쌓아 두고 한 번에 태우는» 곡선이 가능해졌다(199 의 소비 속도 가정이 그 축을 쓰면 재확인 필요).
`temperCapAt` 같은 상한은 원래 없다(주인 지시 ⓑ «맥스 없음») · 룬은 500 상한 그대로.
