그래서 시간축에서 떼어 놨다 — `#fxl` 에 `MutationObserver` 를 걸어 **`.fx-toast` 가 태어난 순간을 기록**한다

|---|---|---|---|
| **N1** | 통보를 통째로 제거 | 승리 통보 · 상대 전투력 · 패배 통보 **3건** | 팝업 아님 2건 · 중단 · 전적 · 보상 |

| **N3** | 문구에서 상대 전투력만 제거 | 상대 전투력 **1건만** | 나머지 7건 |
| **N4** | 적는 수만 ×2 | 상대 전투력 **1건만** | 나머지 7건 |
| **N5** | 중단에서도 승리 통보 | 중단 **1건만** | 나머지 7건 |

N2 만 «팝업 아님» 을 때리고, N3·N4 는 «떴는가» 를 건드리지 않으며, N5 는 승/패 절을 건드리지 않는다.
⇒ 새 단언들이 **서로를 대신하고 있지 않다**는 증명이다.

### ⚠ 만들 수 없었던 시험 하나 — 「fmtB → fmt 표기 규약」

188 계열이면 «표기 규약만 흔드는» N 을 넣는 것이 관례인데, **이 화면에서는 성립하지 않는다**:
`fmtB = n => fmtG(n)`(index.html 13372) 이고 아레나 상대 전투력은 실측 **400~600 대**라
`fmtG(461) === fmt(461) === '461'` 로 두 규약이 **같은 글자**를 낸다(첫 N4 가 «전부 초록» 으로 나와 드러났다).
`verify116` E4-1 이 «단언이 유효한 크기» 를 따로 물어 둔 것과 같은 사정인데, 여기서는 그 크기가 안 나온다.
그래서 N4 를 **«적힌 수가 진짜 그 상대의 수인가»**(×2 부풀리기)로 바꿨다 — 표기가 아니라 **결속**이
이 단언의 값어치다. `fmtB(cp*2)` 가 `1.11A` 를 내는 것이 곧 «1000 위였으면 표기 시험이 됐다» 는 증거다.
(그 사정을 `neg247.js` 주석에 남겼다 — 다음 세션이 같은 N 을 또 만들지 않도록.)
