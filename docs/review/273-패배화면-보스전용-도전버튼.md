# 273 — 패배 화면은 «보스한테 졌을 때만» · 죽으면 [스테이지 재도전] 을 눌러야 보스 도전

> 저장소 주인 지시(2026-08-27, 원문)
> «그 보스한테 졋을때만 패배 화면 뜨게 하고 그냥 잡몹한테질때는 안뜨게좀 해줘.
>  그리고 아까 스테이지마다 보스 잇으라햇는데. 쨋든 죽게되면 그 스테이지에서 보스 도전 버튼 누르기 전까지는
>  계속 그 스테이지 잡몹만 잡는 식으로 하고 스테이지 도전 버튼 누르면 스테이지 보스 도전하게 되기.
>  그리고 클리어시 또 평소대로 자동도전 계속 되는식으로하기»

> **이 기록의 유래(2026-08-28, sess-0053-27599 워커 H)**: PROGRESS 등재 273 이 «동작하는 구현이 이미 있다»고 지목한
> 브랜치 `claude/skill-equip-lock-issue-xghw5z` 의 커밋 `130afbd`(그 브랜치 번호로는 223)를 현 `main` 에 이식했다.
> `index.html` 의 세 자리(사망 경로 · `playerDied()` 신설 · step ③)는 그 브랜치 이후 main 이 손대지 않은 구간이라
> 그대로 얹혔고, 게이트는 `verify223.js` → **`verify273.js`** 로 번호만 바꿔 신설했다. 결과 수치는 이 문서의

## 1. 무엇이 문제였나

| # | 증상 | 원인(구 코드) |
|---|---|---|
| ① | 잡몹에게 죽어도 전 화면 **패배 화면(18)** 이 뜬다 | 사망 경로가 조건 없이 `openDefeat()` 를 불렀다(index.html ~16268). 아레나만 예외였다(123). |
| ② | 죽어도 50킬을 채우면 **보스가 저절로 다시 선다** | step ③ 분기가 `S.bossFarm` 이면 «파도 보너스 → `startBoss()`» 로 이어졌다. [재도전] 버튼은 그 자동 도전을 앞당기는 단축키일 뿐이었다. |
| ③ | 잡몹에게 죽는 것은 아무 상태도 만들지 않았다 | `S.bossFarm` 은 **보스전 실패**에서만 켜졌다(`failBoss()` 는 `inBossFight()` 가 아니면 즉시 리턴). |

«스테이지마다 보스» 자체는 **162 에서 이미 구현**돼 있다(몹 50킬 → 보스 도전 → 보스 격파 = 클리어).
273 은 그 위에 «사망» 과 «패배 화면» 규칙만 얹는다.

## 2. 고친 내용

### ① 사망 한 곳에서 갈린다 — `playerDied()` 신설

```js
function playerDied(){
  if(inBossFight()){ openDefeat(); failBoss('패배'); return; }   // 보스한테 졌다 → 패배 화면 + 28 파밍 전환
  if(arena || raidOn || dunRun || promo) return;                 // 각자 결과 화면·규칙이 받는다
  if(S.bossFarm) return;                                          // 이미 대기면 그대로(재충전·되감기 없음)
  S.bossFarm = true;                                              // 잡몹 사망 → 보스 도전 «대기»
  uiDirty = true; save();
}
```

- 사망 지점(`index.html` 접촉 피해 처리)은 `playerDied()` **한 줄 호출**로 바뀌었다. 자동 부활 연출·타이밍은 1도 안 건드렸다.
- 던전 런·레이드·아레나·승급전 사망은 이 규칙 밖이다 — 던전은 제한 시간, 아레나는 결과 화면(123), 승급전은 `endPromo()` 팝업이 이미 받는다.

### ② 대기 중에는 보스가 «자동으로» 서지 않는다

step 의 ③ 분기(`killed >= ENEMY_COUNT`):

```js
if(S.bossFarm){ /* 파도 보너스 골드 */ killed = 0; queueMobs(); }   // 273 — 자동 도전 폐지
else startBoss();                                                   // 평소대로 자동 도전
```

- 그래서 죽은 뒤에는 **그 스테이지 잡몹만 계속** 잡는다(파도 전멸마다 28 의 보너스 골드는 그대로).
- 보스는 헤더 아래 **[스테이지 재도전]**(`#bossRt` → `retryBoss()`)으로만 선다. 50킬을 다시 요구하지 않는 것도 그대로다.
- **클리어하면** `S.bossFarm = false`(구 코드 그대로) → 다음 스테이지는 다시 «50킬 → 자동 보스 도전» 이다.

### ③ 상태 이름의 의미가 넓어졌다

`S.bossFarm` = 구 «보스전 실패 후 파밍» → 신 **«보스 도전 대기»**(실패·사망 어느 쪽으로든 들어온다).
세이브 키·HUD 클래스(`.bfarm`)·버튼 id 는 그대로라 구 세이브·측정표(28 §39/§40)는 영향이 없다.

## 5. 곁가지

- 74/142 «탭 유실» 의 원인 중 하나가 «사망 중에 뜬 `#defw` 가 탭을 삼킨다» 였다(verify74 주석). 잡몹 사망에서
  패배 화면이 안 뜨게 되어 **그 창이 크게 줄었다** — 142 를 잡을 때 이 변화를 전제로 다시 재는 것이 좋다.
- 죽은 뒤 대기 상태에서는 HUD 가 28 §40(«재도전 대기»)이라 **진행바가 숨는다.** 대기 중 50킬은 보상만 주고
  보스를 부르지 않으므로 표시할 진행이 없다 — 의도된 상태다. 대기가 길어지는 게 답답하다는 판단이 서면
  그 자리에 «파도 n회» 같은 표기를 넣는 것이 후속 후보다(레퍼런스에는 없다).
