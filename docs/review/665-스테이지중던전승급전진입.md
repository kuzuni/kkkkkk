## 2. 등재문 가설이 **반만** 맞았다

주인이 든 두 예 중

- ✅ **«승급전 도중에 던전 도전하면 승급전 클리어»** — 그대로 재현됐다. Δrank +1 · 첫 승급 다이아
  **100,000 이중 지급** · «🏅 승급 성공!» 팝업까지 난다.
- ❌ **«스테이지 보스전하다가 던전 도전하면 갑자기 스테이지 클리어»** — **지금 트리에서는 재현되지
  않는다.** 그 사이에 162(`stageWin` 예약제)와 475(격파 시퀀스)가 자리를 고쳐 놓았고,
  `startDunRun` 이 `bossOn`·`stageWin`·`bossT`·`bossClear` 를 전부 비우고 들어가기 때문이다.
  주인이 본 그림은 실재했지만 **그 자리는 이미 다른 작업이 지나갔다.**

  그런데 **바로 옆 칸에 진짜가 있었다** — «격파 시퀀스(475)가 도는 2초» 안에 갈아타면 스테이지가
  **안 오른다**(Δstage 0). 방향만 반대일 뿐(«없는 클리어가 생긴다» 가 아니라 «있는 클리어가
  사라진다») 같은 급의 결손이고, 이건 **보상 손실**이다. 338·341 이 «등재문 가설 기각» 을 한
  자리에서, 665 는 «기각 + 옆 칸에서 실재 발견» 이 됐다.

## 3. 뿌리 — 승급전의 승리 판정이 «필드 파생» 이었다

```js
/* 수리 전 (step) */
if(!enemies.some(e => e.tk === 'promo')) endPromo(true);
```

이것은 «수호자를 **잡았다**» 가 아니라 «필드에 수호자가 **없다**» 다. 그래서 **어떤 이유로든 전장을
비우는 코드가 그대로 «승급 성공»** 이 된다. 던전 입장(`startDunRun` 의 `enemies.length = 0`)이
정확히 그 코드였다.

같은 자리의 다른 모드는 이미 런 소속이었다 — 스테이지는 `stageWin`(162, `killEnemy` 가 예약),
던전·탑은 `dunRun.bossDown`(255, 같은 자리), 아레나는 `arena.foe` 참조. **승급전 하나만** 필드에서
읽고 있었다.

처방은 332 규약 그대로 «판정 축을 런 소속으로»:

```js
promo = { t:BOSS_SEC, max:BOSS_SEC, rank:r, down:false };          // startPromo
if(promo && !enemies.some(x => x.tk === 'promo')){ promo.down = true; bossClearStart('promo', e); }  // killEnemy
if(promo.down) endPromo(true);                                      // step
```

깃발이 서는 자리는 **`killEnemy` 한 곳**이다. `enemies` 는 그 함수 맨 위에서 이미 splice 됐으므로
«죽은 뒤 남은 수» 를 세는 것이고, 그 조건이 참인 순간이 곧 «마지막 수호자를 잡았다» 다
(208 이 수호자 수를 늘려도 안 갈라진다).

⚑ **이 한 줄이 단독으로 유효하다는 것을 게이트가 못박는다** — `verify665` **[R2]** 는 락을 통째로
열되 깃발만 남긴 사본에서 `promo → 던전` 이 **들어가되 승급하지 않는다**(Δrank 0)를 단언한다.
반대로 **[R1]** 은 깃발을 옛 필드 파생으로 되돌린 사본에서 다시 Δrank +1 · Δ다이아 +100,000 이
난다는 것을 단언한다. 둘이 짝이라 «이미 참인 것을 굳힌 게이트»(338 이 잡은 모양)가 아니다.

## 4. 차단 해제 — 자를 «전투 중» 에서 «갈아탈 수 없는가» 로 갈랐다

453 은 `battleBusy()` 한 자로 **표시와 입장을 둘 다** 물었다. 665 가 그 둘을 가른다.

```js
const battleLocked = () => { const md = bossMode(); return (md !== '' && md !== 'stage') || !!bossClear; };
```

- ⓐ **스테이지가 아닌 모드**(던전·탑·레이드·아레나·승급전)는 그대로 잠근다 — 입장권·도전 횟수를
  이미 치른 판이라 갈아타면 그 값이 조용히 사라진다. **주인이 연 것은 «스테이지 도전 중» 뿐이다.**
- ⓑ **격파 시퀀스(475) 창**도 잠근다 — §1 표의 «클리어 증발» 이 그 근거다. 2초 남짓이라
  «못 누르는 버튼» 이 아니다.
- ⚠ **등장 국면(`bossIntro`)은 축에서 뺐다.** 처음엔 넣었는데 두 가지가 걸렸다: ① 갈아타도 잃는
  것이 없다(`startDunRun` 은 `bossIntro = null`, `startPromo` 는 `bossIntroStart` 로 덮어쓴다 —
  `probe665` 의 `stageIntro → *` 두 칸이 전부 초록) ② 국면은 `bossIntroEnd()` 하나로만 닫히므로
  **어떤 경로로든 남으면 모든 입장이 영영 잠긴다.** `verify453` [D] 가 정확히 그 모양으로 빨개져서
  잡혔다(앞 절이 남긴 `bossIntro` 를 [D] 의 setup 이 안 지운다 — 대가를 치를 이유가 없는 항이다).

### 전환할 때 이전 런은 «명시 종료»

```js
function leaveStageRun(){ if(bossOn) failBoss('모드 전환'); }
```

458 원칙 그대로 **새 종료 경로를 만들지 않고** 스테이지 보스전이 이미 쓰는 실패 경로를 부른다
(스테이지 유지 + 파밍 전환 + [재도전] 노출 + 보스 BGM 복귀). 네 입장 함수(`startDunRun`·
`startPromo`·`startRaid`·`startArena`)가 전부 부른다.

### 범위 — 레이드·아레나도 같이 열었다 (⚑ 위임 규약 채택)

주인 문장은 «던전, 승급전» 이지만 그 둘과 **같은 03 던전 페이지 카드**에 레이드·아레나가 나란히
있고 넷이 `battleBusy()` 한 자를 공유한다. 던전만 열면 같은 페이지에서 카드 절반은 눌리고 절반은
회색인 그림이 된다. ⇒ **자 하나를 갈아 넷이 같이 열리게 했다.**
**되돌리는 법**: `startRaid`·`startArena` 의 `battleLockBlock` 을 `battleBlock` 으로 되돌리고
`raidCardOk`·`arenaCardOk` 의 `!battleLocked()` 를 `!battleBusy()` 로 되돌리면 그 둘만 다시 잠긴다
(다른 자리는 한 줄도 안 건드린다).

## 8. 교훈 (LESSONS 665)

1. **«필드에서 읽는 판정» 은 그 필드를 비우는 모든 코드에 문을 열어 준다.** 승급전 하나가
   그랬고, 형제 셋(스테이지·던전·아레나)은 이미 런 소속이었다 — **한 벌에서 하나만 다르면
   그 하나가 버그다**(LESSONS 58-① 의 다른 얼굴).
2. **차단을 여는 작업은 «열면 무엇이 터지는가» 를 먼저 찍는다.** 가드를 걷어낸 사본을 만들어
   재현하는 것이 «옛 커밋을 뒤져 옛 거동을 추측» 하는 것보다 정확하고 빠르다.
3. **주인이 든 예가 지금도 참인지 확인하라.** 두 예 중 하나는 그 사이의 다른 작업(162·475)이
   이미 고쳐 놓았고, 진짜는 **바로 옆 칸에 방향이 반대로** 있었다(클리어가 생기는 게 아니라 사라진다).
4. **가드에 «닫는 자리가 하나뿐인 상태» 를 넣지 마라.** `bossIntro` 는 `bossIntroEnd()` 로만
   닫혀서, 어떤 경로로든 남으면 **모든 입장이 영영 잠긴다.** 얻는 것이 0 인 항이었다.
5. **표시의 자와 입장의 자는 다르다.** 453 이 둘을 한 자로 물어 두었기 때문에 «입장을 연다» 는
   지시 하나가 레드닷·딤·카드 점등까지 같이 뒤집었다. 갈라 두면 다음 지시는 한쪽만 만진다.
