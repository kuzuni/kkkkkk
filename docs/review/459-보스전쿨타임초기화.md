## §2 처방의 갈림길 — «전투 시작» 이 언제인가 (이 작업의 본체)

등재문 ②는 «국면이 없는 모드(아레나)는 start 함수 안» 이라고 적어 두었다.
**그 자리에 두면 안 된다는 것을 재현이 보여 줬다.**

`probe459` ④ — 스테이지 보스에서 `startBoss()` **안**에서 쿨을 0 으로 두고 굴린 결과:

| | 빈 바닥으로 나간 시전 | 보스가 «선» 프레임의 쿨 |
|---|---|---|
| start 함수 안에서 0 | **2건 (`poison`·`meteor`)** | slash 0.2 · **poison 1.8** · **meteor 2.6** · holy 0.2 |

뿌리는 `castSkillRaw` 의 **폴백**이다 — 대부분의 스킬은 `nearest()` 가 없으면 `return false`(→ 쿨 0.25 로 재시도)지만
`poison`(`nearest() || {x:px,y:py}`)·`meteor`(`nearest(600) || 무작위 근처`) **둘은 대상이 없어도 성공한다.**
그래서 «필드가 빈 창» 에서 0 으로 두면 그 둘이 나가 버리고, 보스가 설 때는 **4종 중 2종이 쿨을 물고 있다** =
「초기화」가 절반은 거짓말이 된다.

그 «빈 창» 은 모든 모드에 있다:

| 모드 | 빈 창의 정체 | 길이 |
|---|---|---|
| 스테이지·던전·탑 | `spawnQ` 보스 스폰 딜레이(`DUN_BOSS_DLY` 1.4s) | 1.4s |
| 승급전·레이드·아레나 | 상대는 그 자리에 서지만 `nearest()` 가 **`born < 0.3` 을 건너뛴다** | 0.3s |

⇒ **«전투 시작» 은 start 함수가 도는 프레임이 아니라 보스가 «실제로 표적이 되는» 프레임이다.**

### 채택한 구조 — 예약(arm) 하나 · 푸는 자리(fire) 하나

```
다섯 진입점 (startBoss · startDunRun · startPromo · startRaid · startArena)
        └── cdArm = true            ← 예약만 건다
step()  [스폰 큐] → **여기** → [적 갱신] → [스킬 틱]
        └── if(cdArm) 보스급이 표적이면 → cdArm = false; resetSkillCd();
```

* `resetSkillCd()` 는 값이 **0** 이다 — 23418(장착)이 이미 쓰는 값과 같다.
  스킬 틱의 `rnd(0, 0.4)`(20753)는 «**처음 보는** 스킬» 을 어긋나게 하는 규약이지 «초기화» 가 아니다.
  0 으로 둬도 `guard` 는 스킬마다 따로 도는 while 이라 «4종이 같은 프레임에 나간다» 가 전부다(실측 확인).
* 푸는 자리를 **스폰 큐 뒤 · 스킬 틱 앞**에 둔 것이 핵심이다 — 보스가 서는 그 프레임 안에서 초기화가 먹고
  같은 프레임에 첫 시전이 나간다(`verify459` [n-h] 첫 시전 **0.00s**).
* 425 등장 국면은 `step()` 맨 위에서 return 하므로 이 자리에 **오지 않는다** ⇒ 국면 동안에는 0회,
  국면이 닫힌 다음 프레임에 1회다(`verify459` [9]). 지시의 «전투 시작부터» 와 같은 뜻이 자동으로 성립한다.
* **페이즈 2·3번째 보스에서는 안 걸린다** — 예약을 거는 자리가 다섯 start 함수뿐이라
  런 도중에는 다시 걸릴 길이 없다(등재문 ②: 페이즈마다 초기화하면 연출이 아니라 밸런스가 된다).
* 예약이 남은 채 판이 끝나도 안전하다 — 예약을 푸는 것은 «보스급이 표적이 되는 프레임» 뿐이고
  그 프레임은 정의상 다음 보스전의 시작이다. 잡몹은 `cdFoeUp()` 판별식이 걸러낸다(`verify459` [8] 음성항).

## §3 범위 — 왜 펫 쿨(`p.cd`)은 안 건드렸나 (지시 ③)

## §6 교훈 (LESSONS 459)

1. **«시작» 은 함수가 도는 프레임이 아니다.** 지시가 말하는 «시작» 은 사람이 보는 사건(보스가 서고 때릴 수 있게 됨)이고,
   코드의 `start*()` 는 그보다 0.3~1.4초 앞이다. 그 사이에 «대상이 없어도 성공하는» 동작이 하나라도 있으면
   지시가 절반만 이뤄진다. — `poison`·`meteor` 의 `nearest()` 폴백.
2. **등재문의 처방도 재현으로 검산한다.** 등재문 ②는 «아레나는 start 함수 안» 이라고 적었는데,
   `born < 0.3` 창 때문에 아레나에도 같은 결손이 있었다(338 규칙이 세 번째로 값을 했다).
3. **예약(arm)과 실행(fire)을 가르면 «언제» 를 한 곳에서 정의할 수 있다.**
   진입점 다섯이 각자 «자기 시작 시점» 을 판단하지 않으므로 457(등장 국면 확대)이 시작 시점을 옮겨도
   이 수리는 따라간다 — 국면이 끝난 뒤 첫 프레임에 저절로 풀린다.
4. **게이트의 «프레임 번호» 는 무르게 잡되 «사실» 은 조인다.** 초기화 프레임과 `born ≥ 0.3` 프레임은
   한두 프레임 어긋난다(순서: 스폰 큐 → 예약 풀기 → 적 갱신). 프레임을 정수로 못박으면 헛빨강이 되므로
   ±3프레임으로 두고, 대신 «그 순간 전부 0» · «시작 전 시전 0건» · «첫 시전 0.5초 안» 을 같이 물었다.
5. **시나리오가 제품을 이기면 못 잰다.** [7](페이즈 2번째 보스)은 쿨이 0 으로 풀린 4종이 7초 만에
   던전을 통째로 클리어해 세 번 빨갰다 — `areaDamage` 는 `born` 을 안 보므로 장판은 «등장 창» 에서도 닿는다.
   자를 굴리는 동안에는 보스를 불사로 두고, 죽일 때만 손으로 죽였다.
