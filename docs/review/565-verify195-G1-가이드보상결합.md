## §1 등재문과 재현

등재문(PROGRESS 565): G1 「함수형 보상 = 그 소환의 10연(1,000) · 하드코딩 유입 0」이
`13000,19000,21000` 을 잡는다. 세 값이 «10연 정가 1,000» 과 자릿수가 다르므로 갈래는 둘 —
**ⓐ 보상 표가 함수형에서 하드코딩으로 되돌아갔다** / **ⓑ 자가 다른 표를 읽고 있다**.

338 규칙대로 처방 전에 제품에게 먼저 물었다 — `tools/probe565.js` **13/13 신설**.

```
· [1] 함수형 칸 idx  : 1, 4, 5
· [1] 그 칸의 보상   : 13000, 19000, 21000
· [1] 498 곡선 값    : 13000, 19000, 21000   (GM_DIA0 11000 + 2000·i)
· [1] 상자 10연 정가 : skill:1000 weapon:1000 shield:1000 amulet:1000 pet:1000
· [3] 상자를 900,000 로 올렸을 때 따라온 칸: skill→[] weapon→[1] shield→[4] amulet→[5] pet→[]
· [4] 상수 사본에서 따라온 칸: skill→[] weapon→[] shield→[] amulet→[] pet→[]
```

**⚑ 갈래 ⓐ 는 기각됐다.** 세 칸은 **여전히 함수**(`typeof m.dia === 'function'`)이고, 찍힌 세 값은
498 곡선 `gmDiaAt(i)` 와 **1원 단위로 같다**(13000=13000 · 19000=19000 · 21000=21000).
하드코딩이 들어온 것이 아니라 **곡선이 하한을 이긴 것**이다.

**ⓑ 도 절반만 맞다.** 자는 옳은 표(`GUIDE`)를 읽고 있었다 — 낡은 것은 표가 아니라 **기대값**이다.

### 뿌리 — 498 이 결합을 «값» 에서 «하한» 으로 옮겼다

`index.html` 18813 근방(498, 주인 위임 «첫날 100만»):

```js
const GM_DIA0 = 11000, GM_DIA_D = 2000;
const gmDiaAt = i => GM_DIA0 + GM_DIA_D * i;
GUIDE.forEach((m, i) => {
  const base = gmDiaAt(i), old = m.dia;
  m.dia = typeof old === 'function' ? () => Math.max(base, old()) : base;
});
```

73 ② 는 세 미션(idx 1·4·5)의 보상을 «다음 미션이 소환이면 그 10연을 감당한다» 며
`dia:() => summonCost(다음 상자, 10)` 로 걸어 뒀다. 498 은 그 결합을 **버리지 않고 하한(`max`)으로**
남겼고, 지금은 곡선(13,000·19,000·21,000)이 10연 정가(1,000)보다 훨씬 커서 **곡선이 이긴다**.
소환 가격이 곡선 위로 오르면 결합이 자동으로 이긴다 — `probe565` [3] 이 그것을 행동으로 확인했다.

옛 G1(`fnVals.every(v => v === 1000)`)은 73 ② 시절의 **값**에 굳어 있었다. 결합은 살아 있는데
자만 «1,000 이어야 한다» 고 우기던 자리다. ⇒ **게이트 부패, 제품 0줄.**

## §2 처방 — 자리를 비우지 않고 «살아 있는 증언» 으로 갈아 끼웠다 (333)

**⚠ 값만 다시 적는 길(1,000 → 13,000)은 헛초록이다.** 그러면 게이트가 498 곡선 상수를 손으로
베낀 사본이 되고, `dia:() => summonCost(...)` 결합이 **통째로 사라져도 초록**이다 — G1 이 지키려던
«하드코딩 유입 0» 이라는 뜻이 그 순간 사라진다(402 «표 두 벌» · 328~330 «항을 눌러 초록으로
만들지 마라» 와 같은 자리).

그래서 **«값이 얼마인가» 를 묻지 않고 «그 값이 상자 가격을 실제로 따라오는가» 를 묻는다.**
`verify195.js` [G] 를 다섯 항으로 갈아 끼웠다(제품 0줄):

| 항 | 무엇을 묻는가 | 실측 |
|---|---|---|
| **G1** | 함수형 3칸 = `max(498 곡선, 다음 상자 10연)` — 하한 결합 그대로 | `idx1 13000=max(13000,1000)` · `idx4 19000=max(19000,1000)` · `idx5 21000=max(21000,1000)` |
| **G1-b ★** | **결합이 살아 있다** — 상자 10연을 곡선 위로 올리면 세 칸이 그 값을 그대로 따라간다 | `[1,4,5]` / 함수형 `[1,4,5]` |
| **G1-c** | 73 ② — 각 칸이 반응하는 상자 = **다음 미션의 상자**(칸↔상자 1:1) | `idx1→weapon(다음 weapon)` · `idx4→shield` · `idx5→amulet` |
| **G1-d ☆** | **되돌림 시험** — 세 칸을 상수로 굳힌 사본에서는 어느 상자도 칸을 못 움직인다 | `0칸` |
| **G1-e** | 상자 값을 되돌리면 다시 곡선값 — `max` 는 «대체» 가 아니라 «하한» | `13000,19000,21000` |

`G2`(가이드에 «펫 소환» 미션 없음 → 73 ② 체인 영향 0)는 손대지 않았다.

**측정 손잡이**: 상자 `cost` 를 90,000 으로 올려 10연 = **900,000** 을 만든다 — 곡선 최대
(idx19 = 49,000)보다 확실히 크다. 올린 값은 **같은 `evaluate` 안에서 즉시 복원**하므로
뒤 절([H][I])을 오염시키지 않는다(G1-e 가 복원 자체를 단언한다).
