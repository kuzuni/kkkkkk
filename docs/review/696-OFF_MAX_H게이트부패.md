## 2. 전수 스윕 — 등재문이 센 셋 밖에서 **하나 더** 나왔다

「못 찾으면 `process.exit(1)`」 꼴(`num(/const X…/)`·`pick(/const X…/)`)로 제품 선언을 읽는
도구를 저장소 전체에서 훑었다: **표본 62건**.

| 도구 | 상태 |
|---|---|
| `sim177.js` · `sim249.js` | 등재문이 센 둘 — 즉사 |

⇒ 셋을 같이 고쳤다. 하나를 남기면 이 작업이 존재하는 이유(「199 가 손잡이를 돌릴 때마다
자가 죽어 있으면 밸런스 회귀를 못 본다」)가 그대로 남는다.

곁다리 **1건은 고치지 않고 등재**했다(§6) — 기계가 다르고 값이 199·498 의 결정이다.

## 3. 처방 — 「이름만 갈아 끼우기」가 아니었다

```js
- const OFF_H = num(/const OFF_MAX_H\s*=\s*(\d+)/,          'OFF_MAX_H');
+ const OFF_H = num(/const OFF_DAY_CAP_MIN\s*=\s*(\d+)/, 'OFF_DAY_CAP_MIN') / 60;
```

`sim112`·`sim131` 이 21회차에 받은 것과 **같은 줄**이다(자리를 비우지 않는다 — 333).
⚠ 그런데 **뜻이 다른 만큼 값도 다르다**: 6h → **24h**. 21회차가 sim112 에 적어 둔
「이 이관으로 산출 수치는 한 칸도 안 움직인다」는 **그 자에서만 참**이다.

## 5. `verify177` 위생 — 자식의 죽음을 「한 항의 빨강」으로

```js
try { simOut = execFileSync(…, 'sim177.js'); }
catch (e) { simOut = e.stdout || ''; yes('⑤ sim177 이 끝까지 돌았다 [죽음: …]', false); }
```

653 의 **반대 방향** 사고였다(그쪽은 FAIL 을 내고도 종료 코드 0 = 「초록으로 읽히는 빨강」,
이쪽은 스택 트레이스 = 「읽을 수 없는 빨강」). 이제 자식이 죽어도 자는 **집계까지 가고**
무엇이 몇 개 빨간지 보인다. `verify696` [D] 가 죽은 sim177 을 물린 **verify177 사본**으로
그것을 매 실행 되돌림 시험한다([D4] 는 멀쩡한 자에서 그 항이 **없다**는 짝 — 「항상 참」이 아님).
