# 814 — 14회차 비평 브리핑 (50 코스튬 [강화] 성공 연출) · **890 이 든 뒤 재채점**

## 0. 무엇을 채점하는가

50 코스튬 시트에서 카드 하나를 고르고 **[강화]** 를 눌렀을 때의 **성공 연출**이다.
지시서 [3]-**(다)**(연출) 축으로 채점한다 — ①타이밍(길이·이징) ②크기 비율 ③위치·경로
④가독성·일관성. 각 10점, **네 항의 최저가 당신의 점수**다. 통과선은 8.
색·아트 «내용»·서체 «모양» 은 감점 사유가 아니다 — **크기·위치·대비**만 본다.

## 0-1. ⚑ 이 회차는 왜 다시 찍었는가 — **감쇠 이징이 바뀌었다(890)**

11·12회차 채점 넷(EA·EB·EC·ED)이 ① 의 최저 사유로 각자 **«워시 감쇠 절벽»** 을 냈다.
그 곡선은 공용 `@keyframes fxFlash` 라 **이 작업 단위 밖**이었고 **890** 으로 등재됐다.
**890 이 그 뒤 들었다** — `animation:fxFlash .34s <이징> forwards` 의 이징 토큰 하나가
`cubic-bezier(.2,.8,.3,1)` → **`linear`** 로 바뀌었다.
**키프레임 opacity 값(.97/.80/.45/.22) · `FXFLASH_MS`(340) · `FXFLASH_PEAK`(1.06) 은 전부 불변**이다.

⇒ **이 캡처가 890 이 든 첫 판이다.** 12회차 대비 달라진 것은 그 토큰 하나뿐이고,
이 작업 단위의 제품은 **12·13회차에 각각 0줄**이다(13회차는 자만 신설했다 — 아래 0-2).

## 0-2. ⚠⚠ 13회차가 **기각한 처방** — 다시 적지 마라

12회차 채점자 ED 가 «`fxCvLit` 앰버 `#FFC02E` → `#FFE496`» 를 처방했다. 근거는
«Lv. n» 열창 대비 **3.09:1** 이었다. 13회차가 **세 번째 자**(`tools/probe814d.js` · 소속을
DOM 으로 읽어 열창을 안 고른다)로 그 숫자를 갈랐다:

| 자 | «Lv. n» | 분자(상위1% L) | 분모(중앙값 L) |
|---|---|---|---|
| A — `probe814c`(Range bbox) | **5.08** | 1.000 | 0.157 |
| B — ED 열창(카드기준 x53..116 · y19..39) | **5.10** | 1.000 | 0.156 |
| C — 세 번째 자(소속 마스크) | **5.03** | 1.000 | 0.159 |
| ED 가 보고한 값 | *3.09* | (순백을 뺐다) | — |

ED 열창 안 L≥0.99 픽셀 **53/53(100.0%)** 이 «그 값 줄만 지우면 사라지는» **글자**였다 —
순백 keep-out 판때기가 아니다. 빼는 순간 글리프 채움을 지우고 그 글자의 대비를 재게 되어
분자가 무너진다. ⇒ **3.09 는 거짓 경보이고 그 위에 선 처방은 근거가 없다.**
되살리려면 `probe814d` [D5] 를 먼저 뒤집어라(그냥 다시 처방하지 마라).

## 2. 유령 방지 — 이 넷은 감점 사유가 아니다

* ⓐ `step` 벌의 «실제 경과 시간·수거» 는 채점 대상이 아니다. CSS 애니를 정지시키고 진행도를
  직접 준 것이라 시간축이 정확한 대신 **파티클은 JS 틱이라 정지**다.
* ⓑ 그래서 `step` 벌에서 «알이 안 움직인다» 는 **하네스의 성질**이지 제품이 아니다.
  입자 흩어짐은 4절의 **자 출력**이 답한다.
* ⓒ 크롭 경계·이웃 카드는 채점 대상이 아니다.
* ⓓ ⚑⚑ **«정지 상태» 는 `-rest.png` 에서만 읽어라.** 실측(`probe814c` [P9]~[P11] · **이번 실행**) —
  플래시와 패치가 **같은 프레임(489ms)에 같이 사라지고**, `#fxl` 자식이 **0개**로 완전히 비고,
  정지 «Lv. n» 은 `rgb(255,255,255)` 로 이웃 카드와 **같은 색**이다.
  ⇒ 400ms 이후를 «정지» 로 읽은 «keep 사본 영구 잔존» 지적은 감점 사유가 아니다
  (9·10회차를 두 번 뒤집은 유령이 그것이다). 대신 `-rest` 에서 A ↔ P ↔ 이웃 카드가 다르면
  **그것은 진짜다 — 반드시 잡아라.**
* ⓔ `live-2..6` 이 서로 byte 동일한 것도 하네스다 — 스크린샷 한 장이 200~480ms 라
  수명 620ms 를 지난 프레임들이다(`probe814b` [3-a]: live 벌은 판정에 못 쓴다).

## 3. ① 타이밍 — **890 전후의 결정적 자 출력**(`node tools/probe890.js` · 14/14 PASS)

이 자는 픽셀에서 opacity 를 «추정» 하지 않는다 — `getComputedStyle(el).opacity` 로
**애니가 굴리는 값 자체**를 읽는다(열창이 없으니 «어디를 봤는가» 로 갈릴 자리가 없다).
산수 모형 ↔ 브라우저 실측 **최대 오차 0.00000**.

| 축 | 채점자가 본 판 `cubic-bezier(.2,.8,.3,1)` | **지금 제품 `linear`** |
|---|---|---|
| 60fps 한 프레임 최대 낙폭 | Δ**0.2360** @177ms | Δ**0.0917** (2.6배 완화) |
| 20ms 격자 낙폭(EC 의 자) | Δ0.2605 | Δ0.1078 |
| 감쇠율 최대/최소 | **98,103배** | **13.4배** |
| ∫opacity·dt | 211.0ms | **231.1ms** |
| opacity ≥0.5 노출 | 204.8ms | **241.0ms** |
| 봉우리 opacity | 1.000 | **1.000 (Δ0)** |

* **완화를 봉우리를 깎아서 얻은 것이 아니다** — 노출은 오히려 늘었고 봉우리는 한 칸도 안 줄었다.
* 절벽의 자리는 **꼬리가 아니라 한복판(177ms = 52% 키프레임 경계)** 이었다.

### 3-1. ⚠ **그 개선은 8장 캡처로는 거의 안 보인다 — 나이퀴스트다**

`step` 8장은 80ms 격자다. 같은 두 곡선을 그 격자로 표본하면:

| 격자 | 0ms | 80ms | 160ms | 240ms | 320ms | 400ms |
|---|---|---|---|---|---|---|
| 옛 `cubic-bezier` | 1.000 | 0.936 | 0.801 | 0.451 | 0.015 | 0 |
| **지금 `linear`** | 1.000 | 0.961 | 0.828 | 0.504 | **0.108** | 0 |

177ms 사건(16.7ms 폭)은 80ms 한 칸 [160,240] **안쪽에 숨는다.** 캡처에서 실제로 달라 보이는
자리는 **step-5(320ms)** 한 장뿐이다(꼬리가 0.015 → 0.108 로 «중간 알파 프레임» 이 생겼다).
찍힌 픽셀로도 그렇다 — `probe814b` [3-f] 테 Δ휘도 여덟 칸 = **41 → 134 → 126 → 55 → 5 → 0 → 0 → 0**.

⇒ **① 을 «8장에서 계단이 보인다» 로 깎을 거면 그 계단이 80ms 표본의 것인지 CSS 의 것인지
먼저 갈라라.** 갈랐다면 그것은 살아 있는 지적이다 — 위 표가 «CSS 쪽» 의 값을 다 준다.

## 4. 자 출력 — ③ 을 «미관측» 으로 깎지 말라고 같이 준다

`step` 벌이 파티클을 정지시키므로 흩어짐은 캡처로 못 본다. DOM 좌표 자(손잡이 불변이라 r10~r14 동일):
* 버스트 알이 **누른 카드 상자 안**에서 뜬다 — 밖 0알 / 잰 10알
* 입자가 **값 줄 두 곳 위에 안 앉는다** — 0알
* 알 최대 지름 17px · 이동 벡터 평균 8.6px
* 가로 링 — rx 54.0px · 최악 끝점 63.7px(지터 상한 포함) · 가둠 벽 71.5px · 잉크 끝 72.2px ≤ 카드 반폭 84.0px ⇒ **눌림 0 · 액자 절단 0**

## 5-1. ⚠⚠ 처방을 적기 전에 반드시 읽을 것 — **이미 스윕으로 기각된 값**

11회차 두 채점자(EA·EB)가 각자 «`--flash-k` .70 → .40 / .50» 을 처방했는데 **둘 다 채택되지
않았다.** 7회차 채점자 CX 가 이 손잡이를 스윕해 .70 을 고른 근거가 코드 옆에 적혀 있다
(index.html ~43431):

> «0.80 은 3.09 로 걸치고 **0.60 은 플래시가 눈에 띄게 죽는다**»

⇒ .40·.50 은 이미 기각된 .60 **아래**다. 워시 세기를 내리는 처방은 ④ 를 사는 대신 ①② 를 판다.
그 교환을 하겠다면 «플래시가 죽지 않는다» 를 **당신 자로 보여라**(그냥 숫자만 적지 마라).
같은 이유로 **흰 테 9px · 하드 림 · 안쪽 글로우도 손잡이가 아니다**(619 16·18·19회차 «0 도 답이 아니다»).

## 6. 당신이 답할 것

1. **①~④ 각 점수와 최저 점수**(정수). 후하게 주지 마라.
2. 지적은 **수치로만** — «몇 px 어긋남 / 몇 % 큼 / 대비 몇 :1». 두루뭉술한 총평 금지.
   가능하면 `node` + `pngjs` 로 픽셀을 직접 재라(리포 루트에 설치돼 있다).
   **어떤 마스크·열창으로 쟀는지 지적마다 밝혀라**(A1 10회차 교훈 — 계측 정의가 다르면
   일치해도 틀린다).
3. **8점을 막는 «단 하나»** 를 하나만 고르고, 그것을 **판 P 와 대조해** 이 회차가 만든 것인지
   원래 있던 것인지, 아니면 이 작업 밖(공용 곡선·바 색 등)인지 밝혀라.
4. 그 «단 하나» 의 처방을 **숫자까지** 적어라. 0-2 와 5-1 을 읽고 적어라.
5. ① 을 깎았다면 3-1 의 갈래(80ms 표본 ↔ CSS)를 **먼저 갈라서** 적어라.
