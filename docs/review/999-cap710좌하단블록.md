## §2 사다리 — 네 번 갈라 뿌리에 닿았다

등재문은 «뿌리 미상» 이었다. 갈래를 좁힌 순서를 그대로 적는다(다음에 같은 얼굴이 오면 이 사다리를 다시 탄다).

| 물음 | 잰 것 | 답 |
|---|---|---|
| ① 판 «안» 인가 «간» 인가 | 한 판에서 `draw()` 6회(120ms 간격) 해시 | **1종** — 살아있는 시계가 아니다. 판을 가로질러서만 2종 |
| ② 자원인가 그린 것인가 | `floorCv` 전 화소 해시 · 바닥만 따로 블릿 | **16판 전부 동일** — 바닥 그림도, 래스터·리샘플링도 아니다 |
| ③ 어느 명령이 칠하는가 | 캔버스 2D 를 감싸 «칠하는 명령마다 블록 해시 전후» | 블록을 건드린 명령 **6개**, 범인은 `fillText('44.2A', 988.28, 958)` |
| ④ 왜 갈리는가 | `nums` 원소를 통째로 견줌 | `v`·`raw`·`mg` **한 필드 묶음만** 갈린다(나머지 전 필드 바이트 동일) |

⚑ **③ 이 이 작업의 실체다.** ①② 로 «그림도 자원도 아니다» 까지는 좁혀지지만 거기서 더 못 간다 —
캔버스를 감싸 **«블록을 실제로 칠한 명령»** 을 세고서야 범인이 나왔다. 그때 나온 여섯 줄:

```
0   fillRect(0,0,540,998)              @ctm[2,0,0,2,0,0]        ← 바탕
3   drawImage(<HTMLCanvasElement>,0,0) @ctm[2,0,0,2,-1920,0]    ← floorCv
22  fill()                             @ctm[2,0,0,2,-1920,0]
23  strokeText(44.2A,988.28,958)       @ctm[2,0,0,2,-1920,0]    ← ★ 범인
24  fillText(44.2A,988.28,958)         @ctm[2,0,0,2,-1920,0]    ← ★ 범인
27  fillRect(0,0,540,998)              @ctm[2,0,0,2,0,0]
```

## §3 뿌리 — «그림» 이 아니라 **부스러기**였고, 그 값을 흔든 것은 «용사 자리» 다

`cap710` 은 규격(`spec`)을 뽑으려고 17종을 **두 자리에서 두 번씩 실제로 시전**한다.
그 타격이 남긴 **떠오르는 피해 숫자**(`nums`)는 `clearFx` 의 여덟 배열
(`shots`·`ghosts`·`bolts`·`zones`·`booms`·`drones`·`parts`·`rings`)에 **안 들어 있어** 한 번도 안 치워졌다.
그 한 장이 마지막 줄 `rico` 칸 상자 안(월드 988.28, 958 = 화면 게임 28.3, 958)에 찍힌다 —
`probe996` 이 «rico 86» 으로 세던 화소가 **정확히 이 글자**다.

값이 갈리는 이유는 하네스의 **마지막 안 잡힌 자유도** 하나다:

```
run 0  v "44.2A"  raw 44234.055  mg 16
run 2  v "34.7A"  raw 34690.937  mg 15      ← 나머지 전 필드(x·y·crit·ox·src…)는 바이트 동일
```

996 이 씨앗·`orbitAng`·시계 셋을 핀으로 박았지만 **용사 자리**는 그대로 흔들린다 —
부팅 `waitForTimeout(1200)` 동안 제품의 rAF 가 몇 프레임 도는지가 판마다 달라
용사가 매 판 다른 자리에 선다(실측 boot x **857 / 1032 / 1077 / 961**).
그 자리에서 시전한 피해값이 갈리고, **자릿수가 바뀌면 잉크가 바뀐다.**

⚑ **같은 뿌리의 다른 얼굴이 등재 `1000`** 이다(«`orbitAng` 이 아니라 용사 자리가 흔들린다»).
996 §6 이 둘을 따로 등재한 것은 옳았다 — 얼굴이 다르고 자도 다르다.

## §4 처방 — 값을 얼리지 않고 **부스러기를 치웠다**

두 길이 있었고, 갈림은 «무엇이 이 시트의 채점 대상인가» 하나로 닫힌다.

| | 대가 | 판정 |
|---|---|---|
| **ⓐ `clearFx` 에 `nums` 편입 (채택)** | 없음 — 지울 것을 지운다 | 시트의 채점 대상은 **투사체 실루엣 17종**이고 피해 숫자는 하네스가 규격을 뽑다 흘린 부스러기다. 애초에 `clearFx` 가 치웠어야 할 것이라 **목록에 넣는 것이 수리**다 |
| ⓑ 용사 자리를 핀으로 박아 값을 얼린다 | 부스러기가 **남는다** — 채점자가 `rico` 칸에서 «44.2A» 를 계속 본다 | **부스러기를 남긴 채 예쁘게 만드는 길**이다. 값만 얼리면 다음에 표적·피해가 바뀌는 날 같은 자리가 다시 갈린다 |

**ⓐ 를 골랐다**(위임 규약 2026-09-01 — 상신 없이 그 회차에서 채택).
`corpses` 도 같은 부류라 같이 넣었다 — 지금 표본에서는 늘 비어 있어(표적 hp 1e12 라 안 죽는다)
**그림이 한 화소도 안 바뀌지만**, 표적이 죽는 날 똑같은 얼굴로 재발할 자리다.

⚠ **문턱은 한 칸도 안 넓혔다**(334·796). 등재문이 «`verify996` [2-d] 래칫을 키우는 것은 수리가 아니다» 라고

## §5 손잡이 하나 — `CAP710_HERO` (기본 «안 건드림»)

되돌림 시험을 **운에 안 맡기기 위해** 심었다. 원 증상이 «다섯 판에 한 판» 이라, 사본을 두 판 찍어
«안 갈렸다» 를 얻는 것은 수리의 증거가 못 된다(338 이 경고한 «이미 참인 것을 굳힌 게이트» 의 사촌이다).

```
CAP710_HERO="<x>,<y>"      규격 시전 «앞» 에 용사를 그 자리에 세운다
기본(미설정) = null        → 용사를 손대지 않는다 = 시트 기본 동작 한 화소도 불변
```

기본값이 «안 건드림» 이라는 것은 자가 직접 잰다 — `verify999` **[3-b]** 가 핀 없이 찍은 판과
핀을 켠 판을 화소로 견줘 **Δ0** 을 단언한다. 선례는 996 의 `CAP710_ORBIT`(695 `freeze`·rul504 `immortal`).

⚑ **[3-a] 가 덤으로 하나를 못박는다** — 용사를 860,1380 과 1080,1640 두 자리에 세워도 **시트는 화소 동일**이다.
