## 1. 판정 — «조건이 안 켜진 것» 이 아니라 **부품이 없던 것**

착수 전 실측(`node tools/verify202.js` 41/41 PASS)이 먼저 말해 준다: 202 가 만든 ① 탭 계열은
**멀쩡히 돌고 있었다.** 탭바 «영웅» · `#eqTabs` 3칸 · `subTabs()` 생성 바 전부 조건대로 켜지고 꺼졌다.

빠진 것은 **나머지 두 자리의 배지 노드 자체**였다. 202 는 «켜는 자리 = 탭바 «영웅» 칸 + 그 서브탭»
이라고 스스로 범위를 그었고(202 §4 표), 카드·버튼에는 `<s class="bdg">` 를 아예 달지 않았다.
그러니 «장비 탭 한 곳에만 뜬다» 는 주인 표현은 정확했다 — 서브탭 칸 말고는 **찍힐 노드가 없었다.**

| 자리 | 착수 전 | 이번 |
|---|---|---|
| ① 탭바 «영웅» + 서브탭 «장비·스킬·펫» | **있음**(202) | 그대로 — 회귀만 확인 |
| ② 06 부위 슬롯(무기·방패·목걸이) = 05 로 가는 유일한 진입 버튼 | 없음 | **신설** |
| ② 05 무기 격자 카드 · 07 스킬 카드 · 26 펫 카드 | 없음 | **신설** |
| ③ 05 `#wpnBtnUp` · 07 `[data-skup]` · 26 `[data-ptup]` [일괄 강화] 버튼 자체 | 없음 | **신설** |

판정식은 새로 만들지 않았다 — 카드는 `canLevel(it)` 한 자, 06 진입 슬롯은
`EQUIPS.some(e => e.slot === 부위 && canLevel(e))`, 버튼은 그 시트의 `some(canLevel)` 로
**202·171 이 이미 쓰던 식 그대로**다(등재문의 «판정은 새로 만들지 말고 `upAnyReady()` 계열을 그대로 쓴다»).

## 3. ★ 함정 ① — **166 ⓔ · 202 §3 과 «똑같은» 특이성 함정이 두 화면에 또 있었다**

새 부품을 `.updot{display:none}` + `.alert>.updot{display:block}`(클래스 급)으로 두면
**두 화면에서 상시 점등**이 된다:

```
#wpnw i,#wpnw em,#wpnw b,#wpnw u,#wpnw s{display:inline-block; …}   /* 05 — ID 급 */
:is(#bSk,#bPet,#bCos) i,…,s,em{display:block; …}                    /* 07·26·50 — ID 급 */
```

`<s class="updot">` 가 그 `s` 에 걸린다. 166 이 도감 탭(`#collw s` vs `.cltab>s.dot`)에서,
202 가 영웅 서브탭(`:is(#bSk,#bPet,#bCos) s` vs `.stab>.bdg`)에서 잡은 것과 **글자 그대로 같은 모양**이다.
처방도 같다 — 같은 급의 스코프 짝을 붙인다:

```
:is(#bSk,#bPet,#bCos) .updot{display:none}
:is(#bSk,#bPet,#bCos) .alert>.updot{display:block}
#wpnw .updot{display:none}
#wpnw .alert>.updot{display:block}
```

**이번에는 «호스트가 두 개» 였다는 것이 새로 배운 점이다.** 202 는 시트 세 개(`#bSk,#bPet,#bCos`)만
막으면 됐지만, 이번 부품은 05 무기 팝업(`#wpnw`)에도 들어간다. 그래서 음성항도 **두 갈래로 갈라**
잰다(§6 N1·N2) — 한 짝만 지우면 그 화면만 새는 것이 확인된다. 한 덩어리로 재면
«둘 다 새고 둘 다 초록» 인 항등식과 구별이 안 된다.

## 4. ★ 함정 ② — **배지를 다는 순간 «매 틱 innerHTML 교체» 가 눈에 보이는 결함이 됐다**

06 부위 슬롯에 배지를 달자 프로브가 폭을 **36px** 로 집었다(정의는 27px). 원인은 CSS 가 아니라
`renderEqPage()` 였다 — `$('eqCards').innerHTML = h` 를 **조건 없이** 하고 있었고, 이 함수는
`renderUI()` 가 **0.35초마다** 부른다. 노드가 매 틱 새로 생기니 60 쥬시의 `jzDotIn`
(`.3s`, `scale 0 → 1.3 → 1`)이 **끝나기 전에 계속 다시 시작**했다. 36 = 27 × 1.33 = 그 중간 프레임이다.

07·26 시트는 이미 `setBody()` 가 «내용이 같으면 갈아끼우지 않는다» 로 막고 있었다 — **06 만 빠져 있었다.**
같은 규약을 `#eqCards` 에도 걸었다(`ec.__bh !== h` 일 때만 교체).

> 교훈: **«매 틱 통짜 재렌더» 는 정적인 화면에서는 안 보이지만, 등장 연출이 붙은 요소를 하나 얹는 순간
> 무한 재시작으로 드러난다.** 새 배지·연출 요소를 붙이기 전에 그 호스트의 재렌더 주기를 먼저 본다.

측정 후: 1.5초(틱 4회) 동안 **같은 노드가 살아 있고** 폭이 27~28 로 머문다(남는 흔들림은
공용 맥박 `jzDotPulse` 1.14 뿐 — 다른 레드닷과 동일).

## 4b. ★ 함정 ③ — **«우상단에 붙인다» 가 세 자리 전부에서 부딪혔다**

레드닷의 관례 자리는 우상단이다(`.stab>.bdg` · `.tab .bdg` · `.dnc .dot` 전부). 그대로 붙였더니

| 자리 | 부딪힌 것 | 옮긴 자리 |
|---|---|---|
| 07·26 `.sk-card` | **272 의 해제 뱃지 `.sk-eq`**(카드기준 123,10~172,30) 와 픽셀이 겹친다 | **좌상단 «바깥» −14**. −5 로 옮겼더니 이번엔 `Lv.n`(`.sk-clv` 18,14~70,46) 의 좌상단 모서리를 **4×8px 물었다**(게이트가 잡았다). −14 면 배지 우변 13 < 18 이고, 맥박 1.14 에서 14.9 · 등장 1.3 에서 17.1 로도 안 닿는다 |
| 05 `.wgc` | 카드 자신이 **`overflow:hidden`** — 바깥에 두면 **잘린다** | **안쪽**. 그 안에서도 우상단은 `.lv`(right:13 top:9) 자리라 **좌상단 안쪽**(`left:5 top:5`) |
| 06 `.eqsl` | 좌상단 바깥은 부위 뱃지 `.eqbd`(left:704, 슬롯 left:724) 자리 | 우상단 «바깥»(`right:-7 top:-7`) — 슬롯 자신은 `overflow:visible` 이라 안 잘린다 |

`.sk-card` 는 `overflow:visible` 이고 첫 «잘리는 조상» 이 `.sk-gp`(격자 스크롤러)다 — 격자는 카드보다

**«잘리는 첫 조상 안에 배지 상자가 온전히 들어가는가» + «기존 요소와 0 겹침»**.

## 5. ★ 함정 ④ — 게이트를 넓히다 **자기가 만든 연출에 자기가 속을 뻔했다**

`verify166` 의 전수 감사는 호스트마다 `.alert` 를 **뗐다 붙였다** 하며 잰다. 그 조작이
`jzDotIn` 을 **다시 시작시킨다** — 감사 직후 곧바로 «세 자리 동시 점등» 을 재니
`getBoundingClientRect().width` 가 **0** 으로 잡혀 `card=0 btn=0`, 즉 «안 켜졌다» 로 빨개졌다.
클래스는 멀쩡히 붙어 있었다(`nAlert=36`). 202 §3 이 이미 적어 둔 함정(«painted 를 따로 낸다»)과 같은 것이고,
**감사가 스스로 만든 상태** 때문에 재발했다. 처방: 감사와 측정 사이에 `wait(700)`.
