## §1 재현 — **등재문의 뿌리 진단이 기각됐다(338·341 계열)**

등재문: «`node tools/neg202.js` → 마지막 줄 `NEG202 12/13 ← FAIL 1건` · **종료 코드 0** ·
자리는 그 자의 마감부 — 실패를 세어 찍기만 하고 `process.exit(1)`/`exitCode` 를 안 세운다».

**앞 절반은 맞고 뒤 절반은 틀렸다.** 12/13 은 그대로 재현됐지만, 마감부는 처음부터 이렇게 적혀 있었다
(`tools/neg202.js` 102행 · 수리 전 커밋에도 같다):

```js
process.exit(fail ? 1 : 0);
```

**종료 코드는 내내 옳게 세워져 있었다.** 직접 재면 1 이 나온다:

```
$ node tools/neg202.js >/dev/null 2>&1 ; echo $?
1
```

### 그럼 등재자는 왜 0 을 봤는가 — **파이프**다

`$?` 는 **파이프라인의 마지막 명령**의 코드다. 자를 `| tail` 로 묶어 재면 `tail` 의 0 이 잡힌다.
수리 전 사본으로 나란히 못박았다:

```
$ git show HEAD:tools/neg202.js > tools/.neg202-prefix-$$.js
--- 수리 전 사본 · 파이프로 ---   NEG202 12/13  ← FAIL 1건      파이프 뒤 $?=0     ← 등재문이 본 값
--- 수리 전 사본 · 직접   ---                                   직접   $?=1     ← 자의 진짜 답
```

⚑ **이 함정은 이 세션이 직접 밟았다.** 첫 명령을 `node tools/neg219.js 2>&1 | tail -25; echo "EXIT=$?"`
로 적어 **EXIT=0** 을 받았다 — 그때 neg219 는 실제로 빨간(코드 1) 상태였다. 등재자와 같은 자리에서
같은 값을 본 것이고, 이것이 이 작업의 가장 값싼 교훈이다.

## §2 그렇다면 진짜 결함은 무엇인가 — **N1 표본이 굳었다**

종료 코드는 멀쩡했지만 **`FAIL 1건` 은 진짜였다.** 등재문 지시(«먼저 그 1건이 진짜 결함인지를 재고»)대로
그 한 항을 팠다:

```
FAIL [N1] ⓐ `.alert` 가 없는데도 시트 배지가 켜져 있다 ← 이 짝이 없으면 상시 점등
```

N1 은 202 가 깐 특이성 복구 짝을 **떼면** 166 ⓔ 함정(«`.alert` 와 무관하게 상시 점등»)이 부활한다고
단언한다. 그런데 떼도 안 샌다.

**제품은 멀쩡하다** — 기준선 ⓐ(«`.alert` 를 떼면 배지가 사라진다»)가 초록이다. 뿌리는 **531(2026-08-31)** 이다.
531 은 «상시 점등» 함정의 **재료**를 미리 덮는 더 넓은 짝을 깔았고(`index.html` 11524~11527),
그 셀렉터가 `s.bdg` 를 포함한다:

```
:is(#bSk,#bPet,#bCos, … ,#svw) :is(s.updot,s.bdg,s.dot){display:none}
:is(#bSk,#bPet,#bCos, … ,#svw) .alert>:is(s.updot,s.bdg,s.dot){display:block}
```

`.stab` 의 배지는 마크업이 예외 없이 **`<s class="bdg">`** 다(`index.html` 15954·16076·16111~16114 …).
⇒ 531 짝이 202 짝과 **같은 시트·같은 노드**를 덮는다. 특이성도 함정을 이긴다:

| 규칙 | 특이성 | 이기는가 |
|---|---|---|
| 함정 `:is(#bSk,#bPet,#bCos) s{display:block}` | (1,0,1) | — |
| 202 짝 `:is(…) .stab>.bdg{display:none}` | (1,2,0) | ✅ |
| **531 짝 `:is(…) :is(s.updot,s.bdg,s.dot){display:none}`** | **(1,1,1)** | ✅ |

**막는 겹이 둘이 된 것이다.** 202 짝만 떼도 531 이 받아 준다 — 그래서 N1 이 빨개졌다.

## §3 처방 — 항을 지우지 않고 **진리표 셋**으로 갈랐다 (333 처방)

«202 짝은 이제 필요 없다» 도, «시험이 틀렸다» 도 아니다. 한 줄짜리 단언으로는 «겹이 둘» 이라는
사실을 적을 자리가 없었던 것이라, 갈라 적었다:

| 항 | 갈아 끼움 | 기대 | 뜻 |
|---|---|---|---|
| **N1-a** | 202 짝만 제거 | 안 샌다 | 531 이 덮는다 |
| **N1-b** | 531 짝만 제거 | 안 샌다 | 202 가 덮는다 |
| **N1-c** | **둘 다** 제거 | **샌다** | 함정은 진짜고, 두 겹이 «합쳐서» 짐을 진다 |

**N1-c 가 이 시험의 본체다** — 그것이 없으면 «무엇을 지워도 초록» 인 항등식이 되고(214-④ · 215-② · 217-②),
N1-a·N1-b 가 없으면 겹이 둘이라는 사실을 다시 놓친다. `[N1-c] ⓑⓒ 는 초록 그대로` 항(절 분리)도 살렸다.

⚠ **제품 CSS 는 한 줄도 안 지웠다.** 202 짝이 531 과 겹친다고 «죽은 코드» 로 걷어내는 것은
이 작업 단위가 아니고(둘의 스코프·특이성이 다르다 — 202 짝은 `<s>` 가 아닌 배지 노드도 덮는다),
두 짝의 주석이 모두 «이 짝을 지우면 상시 점등으로 돌아간다» 고 못박아 둔 자리다.
**N1-a·N1-b 가 그 겹침 사실을 기록으로 남기므로**, 정리할지는 근거를 갖고 나중에 판단할 수 있다.

⚑ 앵커는 **652 와 같은 처방으로 파생**시켰다 — 531 짝의 id 목록은 주석이 «새 화면을 만들면 그 id 를
목록에 더한다» 고 적어 둔, **자라도록 설계된 목록**이다. 손으로 베끼면 652 와 똑같이 썩는다.

## §6 다음 세션에게

⚑ **자의 종료 코드를 `| tail` 뒤에서 재지 마라.** `$?` 는 파이프라인의 **마지막** 명령 코드다.
빨간 자가 조용히 초록으로 읽히고, 그 착시가 **실재하지 않는 결함을 T1 으로 등재하게 만든다**.
재려면 `node tools/X.js >/dev/null 2>&1; echo $?` 처럼 **직접** 재거나, 출력이 필요하면
파일로 받아서(`> out.txt 2>&1`) 코드를 먼저 읽어라.

⚑ **음성항이 빨개졌을 때 «제품이 깨졌다» 로 먼저 읽지 마라.** 이번처럼 **보호가 한 겹 늘어서**
빨개지는 경우가 있다. 기준선 항이 초록인지부터 보고(제품은 멀쩡하다는 뜻), 그 다음
«무엇이 이 짐을 대신 지고 있는가» 를 찾아라 — 답은 대개 나중에 깔린 더 넓은 스코프다.
