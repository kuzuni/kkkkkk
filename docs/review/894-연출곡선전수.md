## §2 재현 — 등재문의 머리가 **기각됐다** (`tools/probe894.js`)

⚑⚑ **이 회차의 본체는 처방이 아니라 «세는 방법» 이었다.**

890 의 스윕은 `animation:` **약칭**의 timing-function 하나를 전 구간에 걸어 opacity(t) 를 풀었다.
CSS 는 그 위에 **키프레임 안의 `animation-timing-function`** 을 얹고, 그 선언이 있는 구간은
약칭이 아니라 **그 함수**로 굴러간다. 그 우선순위를 지켜 다시 재면:

```
── fxSpark  (380ms · 약칭 `ease-out` · 정지점 9 · 키프레임 안 timing 선언 8건)
   실효 구간 이징: 0%→linear · 5%→linear · 12%→linear · 18%→linear
                 · 29%→linear · 46%→linear · 66%→linear · 84%→linear
   [α] 한 프레임 최대 낙폭 Δ0.1154 @319ms   (전 구간 linear 면 Δ0.1154)
```

**`fxSpark` 는 여덟 정지점 전부가 `animation-timing-function:linear` 를 스스로 적고 있다.**
약칭의 `ease-out` 은 **한 구간도 굴리지 않는다.** 실물 낙폭은 **Δ0.1154**(브라우저 실측 **Δ0.1174**)로
890 문턱 **아래**다 — 등재문의 Δ0.1725 는 «있지도 않은 이징» 의 값이었고, 등재문이 괄호로 적어 둔
«같은 곡선을 linear 로 두면 Δ0.1151» 이 **실은 지금 제품의 값**이다.

⇒ **등재문이 이 행에 준 유일한 «문턱 초과» 는 소멸했다.** 8건 전수에서 890 의 알파 축을 넘는
자리는 **0건**이다(최대는 `jzSlam` 의 Δ0.1364 < 0.15).

## §4 처방 — 한 토큰 + 사본 한 줄

```
  @keyframes fxPay{0%{scale(1)} 20%{scale(.925)} 56%{scale(.962);animation-timing-function:ease-out} 100%{scale(1)}}
  .fx-pay{animation:fxPay .3s ease-out both}
                                 ↓
  @keyframes fxPay{0%{scale(1)} 20%{scale(.925)} 56%{scale(.962)} 100%{scale(1)}}
  .fx-pay{animation:fxPay .3s linear both}
```

  그 한 줄만 되살린 사본으로 실제로 그것을 확인한다(재가속 1.00 → 1.32배).

## §5 안 건드린 일곱 — **자리마다 이유가 다르다**(다음 세션이 다시 세지 않게)

1. **`fxSpark`** — 실효 전 구간 linear. **890 이 이미 원하는 상태**다. 681·838·881 이 도는 구간이라

4. **`fxHandTap`** — 같은 이유(ease-in-out ×5, 경계 속도 0↔0 연속). «톡 · 톡» 은 손가락이 극점마다

5. **`fxPunch`** — 93 **39회차가 자로 이미 손본 자리**다. 복귀 구간(42→90%)은 그때 `ease-out` 을

6. **`fxPunch2`** — 이징 몫은 **가장 작다(×1.21)**. 다만 **절대값이 가장 나쁘다**(한 프레임이 진폭의

7. **`jzSlam`** — 알파 Δ0.1364 로 문턱 아래. ⚠ **여기서 `linear` 는 오답이다** — `translate` 채널의

   «등속으로 내려와 딱 멈추는» 그림이 된다. §6 의 판별식이 그것을 갈라 준다.

## §6 규약을 넓히지 않고 **날카롭게** 했다 (UI-REFERENCE 58)

890 이 올린 규약은 「여러 정지점 `@keyframes` 에 이즈아웃을 걸지 마라」였다. 그대로 읽으면
`jzSlam` 의 도착 감속과 `fxHandRing` 의 숨까지 금지된다(둘 다 그 이징이 **곡선 자체**다).
이 회차의 산출로 두 줄을 덧댔다 — **세기 전에 읽을 것**과 **갈라 볼 것**:

* **① 세기 전에 키프레임 «안» 을 읽어라.** 키프레임 안의 `animation-timing-function` 이 약칭을
  이긴다. 약칭만 세면 `fxSpark` 처럼 **이미 고쳐진 자리를 결함으로** 센다(890 이 894 로 넘긴 8건의 머리).
* **② 이즈아웃이 계단이 되는 조건 = «그 채널의 정지점이 곡선을 이미 표본할 때».**
  정지점이 **둘뿐인 채널**은 이징이 곧 곡선이라 `linear` 로 만들면 감속이 사라진다.
  판별은 값으로 한다 — **같은 키프레임 값을 `linear` 로 굴린 것과 나눠**, 이징이 «자기 몫으로»
  만든 계단만 센다(`probe894` 의 **이징 몫**).

## §7 곁다리 등재 — **896**

## §11 교훈

1. **«8건» 같은 목록을 물려받으면 목록을 만든 자의 모형부터 재현해라.** 890 의 스윕은 약칭만
   읽었고, 그 목록의 **머리가 이미 고쳐진 자리**였다. 처방을 먼저 했으면 «이미 linear 인 것을
   linear 로 바꾸는» 회차가 됐을 것이다(338 규칙).
2. **CSS 이징은 세 겹이다** — 약칭 · 키프레임 안 `animation-timing-function` · 구간마다 다시 걸림.
   890 은 셋째 겹을 밝혔고 894 는 **둘째 겹이 첫째를 이긴다**를 더한다.
3. **«이징이 나쁘다» 가 아니라 «이징이 자기 몫으로 만든 계단» 을 세라.** 같은 값을 linear 로
   굴린 것과 나누면 설계(고원·정지)와 결함(톱니)이 갈린다 — 안 가르면 `fxHandRing` 의 숨과
   `fxPay` 의 톱니가 같은 표에 나란히 빨갛게 선다.
4. **정지점이 둘뿐인 채널에 `linear` 를 주면 곡선을 지우는 것이다.** 규약을 «전부 linear» 로
   넓히면 `jzSlam` 의 슬램 도착이 등속이 된다 — 규약은 **넓히는 게 아니라 날카롭게** 해야 한다.
