# 263 — 새로 뽑은 것이 «자동으로 장착돼 있다» → 장착은 플레이어가 한 것만

> 저장소 주인 지시(2026-08-27): «새로 뽑은 것이 자동으로 장착돼 있다 — 장착은 플레이어가 한 것만
> (장비·스킬·펫 전부).»
> 완료 (2026-08-27, sess-2324-2334 워커 F · **T2 주인 지시 · 1회차**).
> 지시서 [3]-**(가)** — 레퍼런스 스크린샷과 대조할 레이아웃이 없다(장착 규칙). 비평가 없음.
> 대신 ROUTINE «기능 완성 규칙» 에 따라 **재현 프로브 · 기능 체크 표 · 되돌림 시험**을 남긴다.

## 1. 무엇이 문제였나 — 재현부터

등재문의 «범인» 지목(`equipFillNew` 하나)이 가설인지부터 확인했다(LESSONS ②
«등재문의 «원인» 은 가설이다 — 재현 프로브가 다른 이야기를 하면 프로브가 맞다»).
`tools/probe263.js` 로 다섯 획득 경로를 각각 돌려 **장착 목록 3축**(`S.eqSkill`·`S.eqPet`·`S.eqSlot`)의
전후를 찍었다.

| 경로 | 수정 전 | 수정 후 |
|---|---|---|
| 유료 소환 — 스킬 10연 | ★ `[] → ice,whirl,slash,stone,curve,shuri` (6칸) | 불변 |
| 유료 소환 — 펫 10연 | ★ `[] → pet1_2,pet1_4,pet0_2` (3칸) | 불변 |
| 유료 소환 — 무기/방패/목걸이 10연 | ★ 빈 부위가 채워짐 | 불변 |
| 무료 소환(광고·보상) | ★ `shield:null → shield1` | 불변 |
| 합성 `craft` | ★ `amulet:null → amulet1_2` | 불변 |

가설은 맞았다 — 세 호출부(`doSummon`·`doSummonFree`·`craft`) 전부 같은 함수 하나를 부르고 있었다.

> **첫 프로브가 «무기만 불변» 이라고 거짓말을 했다.** 유료 무기 소환만 «자동 장착 안 됨» 으로 나와
> 잠깐 «범인이 하나가 아닌가» 싶었는데, 원인은 코드가 아니라 **프로브의 상태 세팅**이었다 —
> `DEF()` 로 초기화하면 `S.guide.idx = 0` 이라 가이드 미션(첫 미션 = «스킬 1회 소환»)이
> `gmBlocked('weapon')` 으로 **다른 배너 소환을 통째로 조기 return** 시킨다. 소환이 아예 안 일어난 것을
> «자동 장착이 안 된다» 로 읽을 뻔했다. → `S.guide.idx = 99` 를 넣고 다시 쟀다.
> **이것이 이 작업 내내 따라다닌 함정이다 — «안 바뀌었다» 는 «아무 일도 안 일어났을 때도» 참이다.**
> 그래서 게이트의 모든 «불변» 항목에 «신규 획득이 실제로 n종 발생» 을 **한 쌍으로** 붙였다(§4).

## 2. 처방 — 등재문의 «확인 필요(주인)» ⓐ/ⓑ 중 **ⓐ**

등재문은 ⓐ **완전 폐지**(빈 칸이어도 절대 자동으로 안 낌 — 지시문 그대로) / ⓑ «게임을 처음 켰을 때
전투력 0» 만 피하는 최소 예외 중 하나를 주인에게 물어야 한다고 적어 뒀다. 주인이 부재중이므로
**지시문 그대로인 ⓐ 로 확정**했다 — 근거는 등재문 자신이 적어 둔 사실이다:

> «시작 지급은 별개 경로라 이 함수를 지워도 남는다 — `if(!has('slash')){ S.own.slash = …; S.eqSkill = ['slash'] }`»

즉 **ⓑ 가 막으려는 사고(전투력 0 으로 시작)는 ⓐ 에서도 일어나지 않는다.** 실측으로 확인했다 —
새 세이브로 부팅하면 `eqSkill = ['slash']` · 펫 0 · 부위 0(게이트 §7). ⓑ 를 택할 이유가 남지 않았다.

### 바꾼 것 (index.html — 순증 −25줄)

1. **`equipFillNew(ids)` 함수 삭제** (스킬·펫·부위 3계열의 «처음 얻은 것 + 빈 칸 → 1회 채움»).
2. **호출 3곳 삭제** — `craft()`(~19904) · `doSummon()`(~20040) · `doSummonFree()`(~20058).
3. **105 주석 재작성** — «유일한 예외가 이 함수» 라고 적혀 있던 자리를 «263 이 그 예외까지 없앴다 ·
   되살리지 마라 · 회귀는 verify263» 로 바꿨다. 등재문 ③ 이 «안 고치면 다음 세션이 되살린다» 고
   경고한 자리다.
4. **`power()` 는 남긴다.** 유일한 호출자가 `equipFillNew` 였지만, `verify86`·`verify197`·`verify260` 세
   게이트가 «등급 안 세기 순서»(260)의 **자**로 이 함수를 쓴다. 죽은 코드처럼 보여 지우면 게이트 3개가
   같이 죽는다 — 꼬리 주석을 그 사실로 바꿔 놨다.

### 안 바꾼 것

- **시작 지급**(`S.eqSkill = ['slash']`) — 획득 경로가 아니라 첫 실행 초기화다. 게이트 §1·§7 이 못 박는다.
- **`toggleEquip`** — 플레이어가 누르는 유일한 장착 경로. 그대로다.
- **자동 사냥·자동 시전·스테이지 자동 진행·자동 저장·유물 자동 강화** — 105 [L] 감사표대로 유지.

## 6. 다음 세션에 남기는 것

- **«자동으로 채워 주면 친절하다» 는 유혹이 우편·퀘스트 지급·이벤트 보상 경로에서 그대로 재발한다.**
  105 는 그것을 «신규만 채운다» 로 좁혀서 남겼고, 263 이 그 남은 하나까지 지웠다.
  **이제 허용선은 «신규만» 이 아니라 «없음» 이다.** 새 획득 경로를 만들 때 채움을 붙이지 마라.
- **삭제 작업의 게이트는 「없다」만 물으면 안 된다.** 「없다」는 기능이 통째로 죽어도 초록이다.
  263 의 모든 절이 «신규 획득 n종 발생» 이라는 양성항과 «플레이어가 누르면 장착» 이라는 대조군을
  같이 들고 있는 이유다.
