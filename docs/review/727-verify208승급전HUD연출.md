## §3 뿌리 — 게이트가 **332/475/665 보다 먼저 쓰인 코드**다

옛 §6 은 «등장 순간» 을 재려고 이렇게 했다:

```js
promo = null; enemies.length = 0;   /* ← 상태를 손수 지운다 */
startPromo();
```

그 사이에 세 작업이 지나갔다:

* **332 / 475** — 격파 시퀀스가 «타이머 체인» 이 아니라 **상태 하나**(`bossClear`)가 됐다.
  §5 의 `killEnemy(e)` 가 `bossClearStart('promo', e)` 로 그 상태를 연다(index.html 22517).
* **665** — 재진입 가드가 `battleBusy()` 에서 **`battleLocked()`** 로 갈렸다:
  `const battleLocked = () => { const md = bossMode(); return (md !== '' && md !== 'stage') || !!bossClear; };`
  (25252) — **격파 시퀀스 창은 못 갈아탄다**가 명시 규약이고, `startPromo()` 의 두 번째 줄이
  `if(battleLocked()) return;` (27645) 이다.

⇒ §6 의 «손수 지우기» 는 `promo` 만 지우고 **`bossClear` 는 그대로 둔다.** 그래서
`startPromo()` 는 첫 줄에서 되돌아가고, 게이트는 «열지도 않은 승급전» 에게 «켜졌느냐» 를 물었다.
**세 항은 제품이 아니라 그 빈 자리를 읽고 있었다.**

`probe727` 이 범인을 하나로 못박는다 — [B] 와 [C] 는 `bossClear` 를 닫았는가만 다르고
(`bossClearDone()` 한 줄) 나머지 상태는 같은데, 세 항이 통째로 되살아난다.

## §4 처방 — 333 «자리를 비우지 말고 살아 있는 표본으로 갈아 끼운다»

## §8 교훈

1. **«상태를 손수 지우고 다시 연다» 는 게이트는 반드시 늙는다.** 제품이 «닫는 방법» 을 새로
   만들 때마다(332 `bossClear` · 665 `battleLocked`) 손으로 지운 목록에서 한 칸씩 빠진다.
   닫을 때는 **제품이 스스로 닫는 그 경로**(여기서는 `bossClearDone()`)를 부르는 것이
   사본을 안 만드는 유일한 길이다.
2. **«막힌다» 는 결손이 아니라 규약일 수 있다.** 재진입이 막혀서 0 이 나온 자리를 «제품이 안
   켠다» 로 읽으면 멀쩡한 코드를 고치게 된다 — 막는 판정(`battleLocked()`)을 **먼저 물어보고**,
   막혔으면 그것을 [전제] 로 단언한 뒤 창을 정당하게 빠져나와서 재라.
3. **마크업 초깃값이 정답과 같은 문자열이면 그 항은 값만으로 못 닫는다.** `#bossTmN` 의 문서
   기본값 `15.0` 이 `BOSS_SEC` 와 같아서 «갱신 안 됨» 과 «정확히 15.0» 이 구별되지 않았다 —
   **켜짐 토글을 같이 보거나 되돌림 시험을 붙여야** 한다.
4. **한 창에 갇힌 게이트는 그 창 안의 다른 절도 같이 헛초록으로 만든다.** §6 을 고치다가 §7 이

   물려받는지**까지 보라.
