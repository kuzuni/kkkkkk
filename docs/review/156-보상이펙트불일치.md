# 156 — 보상 이펙트가 실수령 표기와 불일치 (다이아만 받는데 골드 흡수 연출도 뜸) 「버그」

- 세션 `sess-2159-20684` (워커 D) · 2026-08-26 · **1회차 · T1 버그**
- 지시서 [3]-**(가)** 판정 — 레퍼런스 대조가 필요 없는 «지급 로직» 버그라 **비평가를 띄우지 않았다.**
  검증은 신설 게이트 `node tools/verify156.js` 와 기존 `verify22` · `smoke` 로 한다.
- 관련: 58(연출 공용 모듈 — «연출은 실지급을 따른다») · 22(퀘스트 팝업)

## 1. 증상과 원인

주인 보고: «퀘스트에서나 뭐나 보상을 다이아로만 받았는데 골드도 흡수되는 것 같은 이펙트가 뜸 —
다이아만 받았으면 다이아만 이펙트 떠야지».

원인은 **연출이 아니라 지급**이었다. 세 층이 서로 다른 말을 하고 있었다:

| 층 | 코드 | 무엇을 말하나 |
|---|---|---|
| 표기 | `qrow()` (index.html ~18328) | `curIc('dia') + fmt(rw.c)` — **다이아 배지 하나뿐** |
| 지급 | `claimQuest()` (~17025) · `claimAllQuests()` (~17046) | `S.gold += rw.g; S.dia += rw.c;` — **골드도 준다** |
| 이펙트 | `fxWatch()` (~23527) → `fxAcc` → `fxFly` | `S.gold` 가 실제로 늘었으니 **정직하게 골드를 쏜다** |

즉 **58 연출은 결백하다.** 연출은 실지급을 그대로 반영했을 뿐이고, 거짓말을 한 것은
«다이아만 적어 놓고 골드를 같이 주는» 보상표다. 그래서 처방도 «골드 이펙트를 숨긴다» 가 아니라
**«골드 지급 자체를 없앤다»** 다(주인 지시 + 58 규칙).

일일 퀘스트(`DQUESTS` → `claimDQuest`)는 처음부터 다이아 전용이라 손댈 것이 없었다 —
**반복 탭에만** 있던 결함이다.

## 2. 고친 것 (index.html 3자리, 16줄)

1. `QUESTS[]`(~13330) — 5종 전부 `rw:s => ({ g:…, c:… })` → **`({ c:… })`**. 다이아 값은 한 푼도 안 바꿨다.
2. `claimQuest()`(~17025) — `S.gold += rw.g; S.dia += rw.c;` → `S.dia += rw.c;`
3. `claimAllQuests()`(~17046) — 같은 처리.

`rw.g` 를 읽던 자리는 이 둘뿐이다(`grep 'rw\.g'` 로 확인 — 나머지 `rw.gold` 는 던전 `d.rw` 계열로 별개).
주석에 **«되살릴 일이 있으면 행 표기(qrow)에 골드 배지를 같이 그리는 것까지가 한 벌»** 이라고 못 박아 뒀다 —
한쪽만 되돌리면 같은 버그가 그대로 재발한다.

### 전 수령 경로 훑기 (지시서 «다른 수령 경로도 같은 기준»)

`S.gold +=` · `S.dia +=` 전 호출부를 훑어 «표기에 없는 재화를 주는» 경로를 찾았다. **반복 퀘스트 하나뿐이었다.**

| 경로 | 표기 | 지급 | 판정 |
|---|---|---|---|
| 22 반복 퀘스트 `claimQuest`/`claimAllQuests` | 다이아 1종 | 골드+다이아 | ❌ **이 작업에서 수정** |
| 22 일일 퀘스트 `claimDQuest` | 다이아 1종 | 다이아 | ✅ 일치 |
| 70 출석 `claimAttend` → `giveReward` | `atRewards()` 가 dia·rel·goldMul·gold 를 **전부** 칸으로 그림(최대 3, 실제 최대 3) | 같은 객체 | ✅ 일치 |
| 룰렛 `spinRoulette` → `giveReward` | `roulLabel()` 이 goldMul·dia·rel 전부 표기(🎁대박 = 다이아+유물 2줄) | 같은 객체 | ✅ 일치 |
| 던전/소탕 `d.rw(f)` | 던전마다 **단일 재화**(골드/다이아/유물) | 같은 객체 | ✅ 일치 |
| 69 우편 `claimMail`/`claimAllMail` | 토스트가 골드·다이아·유물 전부 표기 | 같은 값 | ✅ 일치 |
| 36 패스 `passClaim` | 칸마다 단일 재화 `r.k` | 같은 값 | ✅ 일치 |
| 61 가이드 미션 `gmDia` | 다이아 1종 | 다이아 | ✅ 일치 |
| 13 광고 보상 `COIN_ADS` | 상품마다 단일 재화 | 같은 값 | ✅ 일치 |

※ 던전 04 세부·31 클리어 화면의 «대표 재화 1종» 표기는 그 던전이 **실제로 1종만 주기** 때문에 일치한다
(여러 종을 주는데 1종만 그리는 구조가 아니다).

## 3. 게이트 — `node tools/verify156.js` → **VERIFY156 21/21 PASS**

세 겹으로 본다. 「이 게이트가 진짜 이 버그를 잡는가」를 **수정 전 코드로 되돌려 직접 확인**했다
(`git stash` 후 실행 → **13/21 FAIL**, 아래 표의 «수정 전» 열이 그 실측이다).

| 층 | 단언 | 수정 전 | 수정 후 |
|---|---|---|---|
| [A] 표(정적) | `QUESTS[].rw` 에 골드 키(`g`/`gold`/`goldMul`) 없음 · `rw().c` 가 유한수 | **FAIL ×5** (`["g"]` 잔존) | ok ×10 |
| [B] 지급(동기) | `claimQuest` ΔS.gold | **900** | **0** |
| | `claimQuest` ΔS.dia | 100 | 100 (행 배지와 동일) |
| | `claimAllQuests` ΔS.gold | **1700** | **0** |
| | `claimAllQuests` ΔS.dia | 310 | 310 |
| | `claimDQuest` ΔS.gold | 0 | 0 |
| [C] 이펙트(클릭 경로) | 탭 후 1.8초간 `fxFly` 가 쏜 재화 종류 | **`["dia","gold"]`** | **`["dia"]`** |
| | 날아간 다이아 총량 = 행 배지 숫자 | 100 = 100 | 100 = 100 |
| [D] 과교정 방지 | 출석 7일차 카드 표기 칸 수 | 3 | 3 |
| | 출석 7일차 ΔS.gold > 0(표기대로 골드도 준다) | ok | ok |
| | 출석 7일차 `fxFly` 재화 | `["dia","gold"]` | `["dia","gold"]` |
| | 콘솔 에러 | 0 | 0 |

**[B] 를 «동기»로 재는 것이 이 게이트의 핵심이다.** 자동 전투가 매 프레임 `S.gold` 를 올리므로
`await` 를 하나라도 끼우면 ΔS.gold 는 절대 0 이 안 된다. `fn()` 호출 «직전/직후» 를 같은 tick 에서 찍는다.

**[C] 는 전투를 `window.step = () => {}` 로 얼려** UI 발 연출만 남긴 뒤 **진짜 버튼 클릭**으로 잰다
(연출을 끄는 것이 아니라 노이즈원을 끄는 것 — `fxFly` 는 원본을 그대로 호출한다).

**[D] 는 과교정 잠금장치다.** «골드가 뜨면 무조건 버그» 로 굳으면 다음 세션이 출석 7일차·룰렛 골드 칸까지
죽인다. 표기가 3종인 보상은 이펙트도 3종(= `FXCUR` 에 있는 dia·gold 2종 + 유물은 알약이 없어 비행 대상 아님)
이어야 PASS 다.

## 6. 남은 것 / 다음 세션에 넘기는 메모

- **경제 밸런스**: 반복 퀘스트가 주던 골드(`400~900 × 2^s`)가 사라졌다. 다이아 값은 그대로 뒀다 —
  주인 지시가 «다이아만 받는 보상이면 골드 지급 자체를 없앤다» 였고, 표기를 바꾸라는 말은 없었다.
  골드 수급을 보전해야 한다면 **다이아를 올리는 게 아니라 행 표기에 골드 배지를 되살리는 쪽**이 맞다(§2 주석).
- 158(팝업·네비 탭에서 전투 골드가 튀는 «버그»)은 **다른 작업 단위**다. 증상이 비슷해 보이지만
  원인이 다르다 — 156 은 «주지 말아야 할 골드를 줬다», 158 은 «준 골드의 **발원지**가 틀렸다»(`fxSrc`).
  156 을 고쳐도 158 은 그대로 남아 있다. 손대지 않았다.
