## 1. 등재문이 말한 것

> `tools/verify358.js` [3-ⓑ] 1건 실패(67/68) — 725 «% → ×N배» 전환 뒤에도 자가 «값은 0% 로 고정» 을 요구한다.
> 358 이 지키려던 뜻(«이동 속도 줄은 남기고 값은 영구히 증가 0»)은 **여전히 지켜지고 있다** —
> 725 가 표기 한 벌을 배수로 갈면서 «증가 0» 의 **표기**가 `0%` → `×1배` 로 바뀐 것뿐이다(둘은 같은 값이다).
> ⚑ 처방은 «×1배 도 통과» 로 무르게 푸는 것이 **아니라** 표기 부품(`fmtMul`)에서 파생된 «증가 0» 문자열을
> 자가 같이 읽게 하는 것 — 무르게 풀면 «축이 되살아나 값이 커져도 초록» 이 된다(334 교훈).
> 725 의 이관 16종 목록에 358 이 빠져 있었다.

## 2. 재현부터 했다 (338 규칙) — **등재문이 그대로 맞았다**

착수 트리(`b38fd0f` + claim)에서 `node tools/verify358.js` 를 그대로 돌렸다:

```
FAIL 3-ⓑ 그리고 값은 0% 로 고정이다 — ×1배
VERIFY358 67/68 FAIL
```

빨간 항은 **하나**이고, 그 항이 부르는 값은 «축이 되살아났다» 가 아니라 **«표기가 달라졌다»** 다.
제품 쪽을 그대로 읽어 확인했다 — `index.html` 35405·35425:

```js
const pc = fmtMul;                 /* 725 — «증가율 %» 세 행이 배율 그 자체를 말한다 */
...
['이동 속도',   pc(stat.speed / PLAYER_SPEED)]
```

`stat.speed / PLAYER_SPEED` 는 **정확히 1**(증가 0)이고, `fmtMul(1)` 이 `×1배` 다.
즉 **제품은 358 의 뜻을 한 글자도 안 어겼고**, 어긋난 것은 자의 **기대 문자열**뿐이다 ⇒ 게이트 부패.

## 3. 처방 — 「무르게 풀기」를 고르지 않았다

| 안 | 내용 | 대가 |
|---|---|---|
| ⓐ | 기대값을 `'×1배'` 로 바꿔 적는다 | **같은 부패가 다음 표기 개정에서 그대로 재발**한다(지금 이 행이 그 증거다) |
| ⓑ | `0%` **또는** `×1배` 면 통과 | ⚠ **축이 되살아나 값이 커져도 초록**이 될 위험 — 334 가 못박은 «무르게 푼 수리» |
| **ⓒ 채택** | 기대값을 **제품 표기 부품에서 파생**(`fmtMul(1)`) + 판별력 항 + 비=1 항 + 되돌림 시험 | 자가 표기 개정을 자동으로 따라오고, 값이 변하면 즉시 빨개진다 |

⚑ **ⓒ 의 위험은 «파생 기대값이 무엇과도 같아지는 것»** 이다 — 예컨대 누가 `fmtMul` 을 상수로 만들면
«기대 = 실제» 가 항상 참이 된다. 그래서 파생 한 항만 두지 않고 **셋으로 갈랐다**(326 교훈 «한 항이
두 자리를 겸하면 한쪽이 사라져도 초록이다»):

| 항 | 묻는 것 |
|---|---|
| `3-ⓑ-전제` | 표기 부품이 «증가 0»(`fmtMul(1)`)과 «증가 있음»(`fmtMul(1.5)`)을 **실제로 가르는가** — 눈금이 상수로 뭉개지지 않았다 |
| `3-ⓑ` | 화면에 찍힌 값이 그 «증가 0» 문자열과 같은가 (손 상수 아님) |
| `3-ⓑ` | 그 표기의 **뿌리인 비 자체가 정확히 1** 인가 — «표기만 맞고 값이 다른 것» 을 막는다 |
