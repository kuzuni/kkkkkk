# 581 — «받기·강화» 주 행동 버튼 공용 `.ifbtn` 통일 (저장소 주인 지시 2026-08-31)

주인 원문 두 줄이 같은 처방이다.
· «도감의 강화버튼도 초록색으로 하기»
· «축복의 받기 버튼도 다른 팝업 버튼에서 쓰는 버튼으로 하기. **일괄 받기 버튼 같은 디자인**»

주인이 지목한 «일괄 받기 버튼» 이 공용 베벨 부품 `.ifbtn`(2374)이고 그 기본 팔레트가 곧 초록이다
(`--gb-mid:#4CBA2E`). 그래서 **초록은 지시가 아니라 결과**다 — 색을 새로 칠하는 것은 반려(등재문 처방 ①).

### 무엇을 바꿨나 (제품 `index.html` 4자리)
1. `.clb-btn` — 자기 배경·바닥 베벨·`border`·`.rdy` 금색을 **통째로 삭제**하고 `--gb-bw:6px` + 좌표·239×90·radius 45 만 남겼다. 마크업에 `ifbtn` 추가 + 라벨을 `<i>` → `<b>`(부품 규약, `.qs-all`·`.cl-all` 과 같다).
2. `.bls-c .tm` — 면·테두리를 기하에서 갈라 `.bls-c:not(.off) .tm`(상태 칩, 34 실측 갈색 Δ0)로 옮기고, `.bls-c.off .tm`(= «받기» 국면)의 플랫 채움 두 줄을 **지웠다**.
3. `renderBless()` — `.alert` 를 켜는 그 한 줄에서 `ifbtn` 도 같이 토글한다(**판정식 0개 신설** — 같은 `!on`).
4. `.clb-btn>b` / `.bls-c.off .tm>i`·`>b.ck` — 부품이 얹히며 생긴 세로 1~6px 만 되받는다.

옛 `border:6px solid #000` 과 같은 값이라 padding 상자가 애초에 같다.

### 함정 셋 (LESSONS 등재)
① **`color:inherit` 한 마디가 부품의 색을 이긴다.** `.clb-btn>b`(0,2,0)는 `.ifbtn>b`(0,2,0)보다 파일에서
   뒤에 있다 — 부품에 맡기려고 적은 `color:inherit` 이 오히려 흰색을 덮어 **흰 잉크가 0px** 이 됐다.
   부품에 맡긴다는 것은 «그 속성을 **아예 안 적는** 것» 이다.
② **아웃라인까지 통일하면 라벨이 죽는다.** 두 상태의 스트로크를 base 의 10px #000 하나로 합쳤더니
   준비 상태 흰 코어가 **64×32 → 22×10** 으로 무너졌다. `-webkit-text-stroke` 는 윤곽선 «가운데»
   정렬이라 절반이 글자 안쪽을 먹는다(10px = fs40 획을 5px 씩). ref 63×32 를 맞춘 것은 **준비 상태의
   5px 반투명** 쪽이고, 부품이 바꾸는 것은 **버튼 면**이지 라벨 잉크가 아니다(등재문 처방 ④).
③ **등장 연출이 끝나기 전에 재면 자가 흔들린다.** 60 쥬시가 카드를 1.00~1.01x 로 올리는 동안 재면
   같은 CSS 로 잉크 중심이 37.5·38.5·39.5 로 번갈아 나온다. 그 노이즈를 보고 +2 를 +1 로 잘못
   내렸다가, 1500ms 를 기다리고 다시 재서 **+2 가 Δ0** 임을 확인했다.
