## 2. 고른 수정 — ① 스케일 (지시서 대안 ② 는 **쓸 수 없다**)

PROGRESS 행은 «① `transform:scale(min(1, avail/1527))` 로 줄이거나, 레이아웃 점수를 깎으면
② `#relw{overflow:hidden}` + 안내문 재배치» 두 갈래를 줬다. **② 는 불가능하다:**

> 41 팝업 내장 재화 바 `.pcb` 는 `top:-104px; height:108px` 로 **`#relw` 바깥(HUD 자리)** 에 얹혀 있다
> (`index.html` line ~2033). `#relw{overflow:hidden}` 을 걸면 골드·다이아·유물조각 알약 3개가 **통째로 잘린다.**
> `#relw` 의 원래 값이 `overflow:visible` 인 이유가 바로 이것이다 — 지우면 안 되는 값이었다.

→ **①** 을 쓰되, 걱정거리였던 «레이아웃 점수» 는 발생하지 않는다:
**기준 해상도 2280 에서 가용 = 2280 − 104 − 180 − 266 = 1730 > 1527 이므로 스케일이 정확히 1** 이다.
즉 89 가 7회차에 통과시킨 측정 규격은 **기준 해상도에서 전혀 건드려지지 않고**, 축소는 오직
«원래 잘려 나가던» 짧은 프레임에서만 일어난다. (ROUTINE [2] 의 «scale 래퍼 금지» 는 레퍼런스 대조 기하를
스케일로 때우지 말라는 뜻이고, 여기서는 대조 해상도의 기하가 불변이라 그 금지에 걸리지 않는다.)

### 바꾼 것 (3곳, 전부 100 구간)

1. **CSS `.rw-panel`** (~line 2401) — `transform-origin:50% 0; transform:scale(var(--rws,1))` 추가.
   origin 을 «top center» 로 잡아 **상변 y266(프레임 y370)과 가로 중심 540 이 고정**된다(게이트가 검사).
2. **JS `rwFit()`** (`fit()` 바로 아래 신설) — `avail = frameH − 104 − 180 − 266`,
   `--rws = min(1, avail/1527)`. 상수는 CSS 값과 같은 이름(`RW_TOP/RW_BOT/RW_PANEL_TOP/RW_PANEL_H`)으로 박아
   나중에 CSS 를 고치면 같이 고치도록 했다.
3. **호출부 2곳** — `fit()` 끝(리사이즈·회전·`visualViewport` 경로 전부 여기를 지난다) + `openRelw()`
   (리사이즈 없이 바로 여는 경로 대비).

> ⚠ **여기서 하마터면 오진할 뻔했다 — 다음 세션이 반복하지 않도록 적어 둔다.**

> `#relw` 가 진짜였던 건 넘친 `.rw-panel` 자신을 클리핑하는 조상이 **없었기** 때문이다.
> **«bbox 가 겹친다» 와 «가린다» 는 다른 말이다.** 조상 클리핑을 반영하는 히트테스트로 확정할 것.

한 가지 기록해 둘 것: **같은 종류의 버그가 다른 곳에 남아 있을 수 있다.** «내용물 높이가 절대값으로 박히고
클리핑 조상이 없는» 구조가 조건이다. 작업 51 이 바닥 시트 계열에 대해 같은 문제를 `max-height` 로 처리한
전례가 있다. 전체화면 페이지 계열을 통째로 훑는 작업은 **100 범위 밖**이라 손대지 않았다 —
필요하면 별도 작업 단위로 뗄 것(위 히트테스트 스니펫을 그대로 쓰면 된다).
