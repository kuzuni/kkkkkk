## 2. 등재문의 의심 셋을 각각 재서 둘을 기각했다

등재문(PROGRESS 357 행)은 ⓐ `#slots{padding-left:3px}` · ⓑ 슬롯 안 아이콘 잉크 오프셋 ·
ⓒ 스프라이트/이모지 잉크 자체의 중심 어긋남 셋을 의심했다. 338·341·350 규칙대로
**처방을 따르기 전에 `tools/probe357.js` 로 재현**했고, 결과는:

### ⓐ `padding-left:3px` — **기각(고치면 안 되는 자리다)**
행 전체가 앱 기하 중심에서 **+1.5px** 오른쪽인 것은 맞다. 그러나 이 값은 **A4 2차 라운드가
레퍼런스를 재서 박은 값**이다 — `docs/review/A4-스킬슬롯.md` 에 «REF 슬롯1 중심 **86.34 / 86.36 / 86.4**»
가 세 번 나오고 `padding-left` 를 4 → 2.7 → **3** 으로 두 번 조정한 기록이 남아 있다.
우리 칸1 중심은 **86.5** 로 REF 와 Δ0.1~0.16 이다. **레퍼런스 자신이 앱 중심에서 그만큼 오른쪽**이므로
여기서 «중앙 = 앱 중심» 으로 되돌리면 `verifyA4` 가 빨개지고 주인이 못 박은 레퍼런스 일치가 깨진다.
⇒ 357 은 이 줄을 **한 글자도 안 건드렸다.** (`verify357` §5 가 이 불변을 지킨다.)

### ⓑ advance 박스 오프셋 — **기각**
`.slot2` → `.cdw` → `.si3` 사슬의 **상자** 중심은 여덟 칸 전부 슬롯 중심과 **Δ0.00** 이었다.
즉 상자는 처음부터 정확히 가운데 있었다 — 어긋난 것은 **상자 안에서의 줄** 이다.

### ⓒ 글리프 side bearing — **부분적으로만 참(주범 아님)**
bearing 은 실재하지만 글리프마다 다르고(🪨 −1.68px, 나머지 0~−0.42px) **평균 0 근처**다.
여덟 칸이 **똑같이 +4.24** 인 것은 bearing 으로 설명이 안 된다. 진짜 축은 아래 §3 이다.

## 3. 진짜 원인 — 대조군으로 못 박았다

`.si3` 는 `width:100%`(= well 폭 **87.63px**)인데, Noto Color Emoji 의 advance 는 **1.2478em 고정**이라
fs 78.3 에서 **97.71px** 다. 줄이 상자보다 넓으면 크로미움은 그 줄을 **line-left 에 박는다**.

**검산(`probe357` 대조군 · `mech` 실험):**

| `.si3` 에 준 값 | 줄 중심 − well 중심 (변환 전) |
|---|---|
| `text-align:left` | **+5.04px** |
| `text-align:center` (현행이었던 값) | **+5.04px** |
| `text-align:right` | **+5.04px** |
| 상자를 넓힘(`width:auto;margin:0 -20px`) | **−0.01px** |

**세 값이 완전히 같다** — `text-align` 이 죽어 있었다는 뜻이다. 그리고
`(97.71 − 87.63) / 2 = 5.035` 가 실측 **5.04** 와 소수점까지 맞는다. `× 0.842 = 4.24` = 화면 실측값.

## 4. 수리 — 제품 2줄

```css
.slot2 .si3{display:block;font-size:78.3px;line-height:87.6px;text-align:center;
  width:auto;margin:0 -20px;                    /* ← 357: width:100% 에서 */
  position:relative;top:-1.5px;transform:scaleX(.842)}
```

* 상자가 87.63 → **127.63px** 이 되어 advance 97.71 을 담고도 남는다 ⇒ `text-align:center` 가 **되살아난다**.
* 마진이 **좌우 대칭**이라 상자 중심 = well 중심 **불변** → `transform-origin`(43.81px)도 그대로.
* 삐져나온 폭은 `.cdw{overflow:hidden}` 원형 클립이 그대로 먹는다 ⇒ **보이는 그림의 크기·세로는 Δ0**.
* ⚠ **`width:100%` 를 남긴 채 마진만 주면 상자가 넓어지지 않고 왼쪽으로 20px 밀린다** — `width:auto` 가 짝이다.

**안 한 것**: `padding-left`(§2 ⓐ) · fs 78.3 · scaleX .842 · line-height 87.6 · `top:-1.5px` ·
칸 pitch 130 — 전부 그대로. 칸마다 다른 값을 손으로 밀어 넣는 «비균등 보정» 도 하지 않았다(357 지시).

## 5. 남은 잔차는 «우리 배치» 가 아니라 «폰트» 다 (probe357 ⓓ)

수리 후에도 칸마다 0 ~ −1.5px 이 남는다. 이것이 배치 잔차면 더 고쳐야 하므로 **분해했다** —
같은 규격으로 오프스크린에 그려 펜 중심 대비 잉크 중심(= 순수 side bearing)을 따로 재고 뺐다.

| 칸 | 글리프 | 폰트 bearing 예상 | 화면 실측 | 설명 안 되는 잔차 |
|---|---|---|---|---|
| 0 | 🗡️ | +0 | +0 | **+0** |
| 2 | 🪨 | **−1.68** | −1.5 | **+0.18** |
| 3 | 🌙 | +0 | −0.5 | −0.5 |
| 5 | 💫 | −0.42 | +0 | +0.42 |
| 7 | 🌀 | −0.42 | +0 | +0.42 |

**폰트를 뺀 «배치» 잔차 최악 = 0.50px** (서브픽셀 반올림). 그래서 게이트는 §2 를 **±0.5px**(배치)로
조이고 §3 잉크만 **±2px**(bearing 포함)로 둔다 — 등재문의 «±1px» 을 칸별로 그대로 쓰면
**폰트 몫을 CSS 로 때우라는 지시**가 되어 357 이 금지한 비균등 보정으로 간다.

## 8. 측정이 네 번 틀렸다 — 그 과정이 이 작업의 절반이다

«아이콘이 어디 있나» 를 픽셀로 재는 데만 다섯 번을 고쳤다. 전부 `tools/probe357.js` 머리말에 남겼다.

1. **창을 쟀다.** «well 배경색에서 먼 픽셀 = 잉크» 로 재는데 측정창(Ø69.6)이 잉크(68×85)보다 **작아서**
   여덟 칸이 전부 «70×70» 으로 나왔다 — 창의 크기였다.
2. **전투 캔버스가 움직였다.** 차분 두 장 사이에 화면이 흘러 잉크가 «128×104» 로 부풀었다
   → 메인 루프가 스스로 재예약하는 구조라 **rAF 를 눕히면** 언다.
3. **well 의 원형 클립.** 프레임을 세웠는데도 bbox 가 여덟 칸 전부 «well 폭» 이었다 —
   `overflow:hidden` 이 글리프를 잘라 bbox 가 well 에 물린 것. 클립은 중심 대칭이므로
   **측정 동안만** `overflow:visible`(제품 CSS 는 안 건드림, 343 §R 처방).
4. **CSS 전이·60 쥬시 팝은 rAF 와 무관하게 산다.** 스킬이 터진 칸 언저리만 달라져 칸 4·5·6 이
   «112·122·111» 로 부풀었다 → `transition`·`animation` 을 눕히고 **대조군 한 장**을 도입.
5. **대조군을 잘못 뒀다.** ON·CTL 을 연달아 찍으면 **그 뒤**(가리는 동안)의 변화를 못 본다 →
   **ON → OFF → ON2** 로 창 전체를 두르고, 장마다 스타일시트를 덧붙이던 것도
   **`html` 클래스 한 개 토글**로 바꿔 세 장의 스타일 환경을 완전히 같게 만들었다.

⚑ 그러고도 **대조군이 더러운 회차가 절반쯤** 남는다(칸 4개 언저리). 그 회차의 숫자는 못 쓰는 숫자이므로
**깨끗해질 때까지 다시 찍는다** — 재시도의 판정은 **값이 아니라 «전제»(대조군)** 이고, 6회 안에 못 얻으면
그대로 빨개진다. 이것이 «빨간 걸 초록 될 때까지 돌리기» 와 다른 점이다(플레이키 게이트 **344** 의 교훈).
게이트 5연속·프로브 3연속 PASS 로 확인했고, 다시 찍은 회차는 **로그에 그대로 찍힌다.**

## 9. 다음 세션에게

* **이 결함은 «이모지를 고정폭 상자에 `text-align:center` 로 담는» 모든 자리에서 재발한다.**
  판정법은 한 줄이다 — `Range.getBoundingClientRect()` 로 **줄 폭**을 재서 **상자 폭보다 크면** 이미 밀려 있다.
  `text-align` 을 left/center/right 로 흔들어 **값이 안 바뀌면** 그것이 증거다.
* **356**(아이콘 원본 비율 전수)을 잡는 세션에게: 이 스윕(§6)이 «비율» 이 아니라 «중심» 축으로
  이미 56개를 훑어 뒀다. 356 은 «찌그러짐»(scaleX) 축이라 겹치지 않지만, `.si3` 는
  **의도된 `scaleX(.842)`**(잉크 68×85 정규화, 측정표 §3)이므로 **356 의 «비균등 금지» 대상이 아니다** —
  건드리면 A4 가 10회차에 걸쳐 맞춘 잉크 규격이 통째로 무너진다.
