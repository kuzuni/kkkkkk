## 1. 결론 한 줄

**바는 «덜 찬» 것이 아니라 «거꾸로» 였다.** 격파 프레임의 폭은 전 조합에서 예외 없이 **574px = 가득**이었고,
결손은 «눈금이 안 따라온다» 가 아니라 **«눈금의 방향이 반대다»** 였다. 폭·수치를 **«남은 보스 체력»** 으로 뒤집었다.

## 3. 그럼 무엇이 결손인가 — «같은 부품이 두 자리에서 반대로 움직인다»

주인의 낱말이 이미 답이었다: **«hp바»** · **«다 깎여있지를 않음»**(찬다가 아니라 **깎인다**).

| 근거 | 내용 |
|---|---|
| 측정표 30 §1 | 이 바의 레퍼런스 대응물은 **39 보스전의 «보스 체력바»** 다 |
| 측정표 30 §4-4 | 바 우측 두개골이 «39 의 체력바 끝 두개골과 **1px 이내로 같은 에셋**» |
| 측정표 30 §4-3 | 레퍼런스 바 안 수치 `9.61C` = **남은 체력**. 우리는 그 자리에 «누적 피해» 를 넣었다고 §4-3 이 명시 |
| 제품 `#bossHp` | 같은 부품의 다른 자리는 `clamp(hp/max)×671` = **줄어든다** (`drawBossHud`) |
| 제품 `#dunBar` (수리 전) | `dunRunProg()×574` = **차오른다** · 수치는 `fmtB(dunRun.dmg)` = **커진다** |

즉 **한 부품이 스테이지에서는 줄고 던전에서는 차오르고 있었다.** 보스가 죽는 순간 스테이지 바는 0,
던전 바는 574 — 주인이 본 «죽었는데 다 안 깎임» 이 정확히 이 그림이다.

수치 쪽 뿌리는 더 오래됐다: `dunRun.dmg` 는 **255 이전** «누적 피해 ≥ 요구 피해 = 클리어» 시절의 눈금이다.
255 가 판정을 보스 격파로 옮기고 331 이 앞 국면을 지운 뒤에도 **바 안 글자만 그 시절 값을 계속 쓰고 있었다**
(LESSONS 295-② — 폐지된 조건의 눈금이 화면에 남으면 그건 거짓말이다). 그래서 **차오르는 바 위에 커지는 숫자**였다.

## 4. 처방 — 축을 새로 만들지 않는다

`dunRunProg()` 는 **한 줄도 안 건드렸다.** 그것은 «클리어 접근도» 로서 264 탑 진행·284 등이 읽는 값이고,
등가식 `left`(남은 보스 체력 합) `= tot × (1 − prog)` 가 **정확히** 성립하므로 사본을 만들 필요가 없다(LESSONS 90-①).

```js
const dunBossHpR   = () => (dunRun ? clamp(1 - dunRunProg(), 0, 1) : 1);
const dunBossHpVal = () => (dunRun ? dunRun.need * DUN_BOSS_HPK * dunBossHpR() : 0);
...
$('dunBarF').style.width = (dunBossHpR() * 574) + 'px';
$('dunBarN').textContent = fmtB(dunBossHpVal());
```

- **등장 딜레이(1.4초) = 만피 574px.** `dunRunProg()` 가 그 구간에 0 이라 자동으로 그렇게 된다 —
  `drawBossHud` 가 스테이지 보스 스폰 딜레이에 쓰는 «아직 보스가 없을 때는 만피» 와 **같은 규약**이다.
- **격파 = 0px, 332 홀드 내내 유지.** `bossDown` 이 prog 1 을 굳히므로 시퀀스 90~132프레임 내내 0 이다.
- **`dunRun.dmg` 는 계속 센다.** 화면에는 안 나오지만 `verify255 [D]`·`verify257 [4]` 가 이 칸을 크게 밀어
  «누적 피해는 바를 못 민다» 를 재는 자리라, 칸을 지우면 그 회귀 잠금을 못 건다.

### 안 바뀐 것 (밸런스·판정 0줄)

클리어 판정은 `killEnemy → bossDown` 하나뿐이고 계수(`DUN_DMG_K`·`DUN_BOSS_HPK`)는 한 줄도 안 건드렸다.
`dunRunProg()` 를 읽는 쪽(264 탑·284)이 **그대로 초록**인 것이 그 증거다.
