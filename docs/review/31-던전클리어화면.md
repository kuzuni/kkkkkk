## 회차 기록

### 1회차 — 비평가 A **8** / B **7** → 불합격(B<8)

두 비평가가 **공통으로** 잡은 것(= 실제 결함):

1. **밴드 안·딤 위에 코인 스프라이트가 떠 있다.** 원인은 레이아웃이 아니라 **z-index** 였다 —
   `#fxl`(58 재화 비행 연출 레이어)이 **z-index 60** 인데 `#dclw` 를 40 으로 뒀다.
   `giveReward()` 가 쏜 코인들이 결과 화면 **위를** 가로질러 밴드 안에 그려졌다.
   실측: 딤 위 최대 휘도 **255**(ref 108), >200 픽셀 **4,925개**.
2. 버튼 라벨 3개가 전부 **6~8px 아래**로 처짐(ref 는 몸통 중심보다 광학적으로 4.5~6px 위).
3. 버튼 라벨 잉크 **폭만** 10~14% 넓음(높이는 일치).
4. 보상 타일 외곽 **116 → 120**, 측면 버튼 몸통 **236 → 234**, 티켓 아이콘 색면 **40×29 → 44×33**.

두 비평가가 **엇갈린** 것(→ 측정표를 신뢰하고 그대로 둠, 아래 «남은 문제» 참조):
코인 bbox(A: ref 63×65, 우리와 일치 / B: ref 60×60), 코스트 알약 폭(A: ref 157, 일치 / B: ref 173).

- 버튼 세로 그라디언트가 ref 보다 약함((248,241,47)→(255,184,20) vs 우리 (249,240,45)→(248,201,25)).

### 남은 문제 (통과 무관 · 비평가 간 엇갈림 포함)

- 버튼 3개 **하단 림 코너 반경** 12px vs ref 24~26px (D 만 지적).
- 보상 타일 밴드 내 상하 여백 100/106 vs ref 102/102 (C 만 지적, 6px 불균형).
- **코인 코어 지름** — C·D 는 Ø60(+링), 1회차 A 와 측정표는 **63×65 로 «우리와 일치»** 판정.

## 교훈 (다음 세션 주의)

> **1. `line-height` 만 줄여선 글자가 안 올라간다.**
> 이 프로젝트는 `#XXw i{display:inline-block}` 을 전역으로 깐다. 그러면 버튼 안의 `<i>` 가
> **부모와 같은 `line-height` 를 물려받아** 자기 line box 도 같이 커지고 줄어서, 부모의
> `line-height` 를 96→84 로 줄여도 **잉크 중심이 1px 도 안 움직인다**(1회차→2회차 실측으로 확인).
> 광학 보정은 `<i>` 의 `position:relative; top:-Npx` 로 줘라.
>
> **2. «화면 위에 이상한 게 떠 있다» 는 레이아웃 문제가 아니라 z-index 문제일 수 있다.**
> 58 재화 비행 연출 레이어 `#fxl` 은 **z-index 60** 이다. 기존 결과 연출 오버레이(09 36 · 17 38 ·
> 18 39)는 전부 그 아래라, 새 결과 화면을 그 관례대로 40 에 두면 `giveReward()` 직후 쏜 코인이
> 화면을 가로지른다. **보상을 즉시 지급하면서 동시에 결과 화면을 띄우는 화면은 `#fxl` 위(61)에 둬라.**
>
> **3. 비평가는 «색면» 을 잰다 — `box-sizing` 을 의심해라.**
> ref 의 «44×33, 검정 2px» 을 `border-box; width:44; border:2px` 로 쓰면 색면이 40×29 가 되어
> 두 비평가가 독립적으로 «−9%w / −12%h» 를 잡았다. bbox 가 색면 기준인지 외곽선 포함인지 먼저 정해라.
>
> **4. 비평가 2명이 엇갈리면 측정표를 믿어라.** 코인 bbox(63×65 vs 60×60)·알약 폭(157 vs 173)에서
> A 와 B 가 정반대로 쟀다. 측정표는 PIL 행/열 색전이 스캔 + 코너 반경 피팅으로 만든 것이라
> 비평가의 단발 스캔보다 근거가 두껍다. **엇갈린 지적을 둘 다 반영하려 하면 값이 요동친다.**
