## 1. 어떻게 잡혔나 — «게이트도 초록이고 비평가도 옳았다»

72(03 던전 카드 썸네일)의 **비평가 6명이 13·15·16·17 네 회차에 걸쳐 같은 줄을 지적**했다:

| 회차 | 지적 |
|---|---|
| 13 | 헤더 재화 아이콘 **−14~21%** |
| 15 | 헤더 재화 아이콘 **−14~18%** |
| 16·17 | 헤더 재화 아이콘 **−9px(−14~20%)** · 4인 일치 |

72 는 매번 «내 구간이 아니다(A3)» 로 넘겼고(맞는 판단이다), 17회차 결론은
**«①~④ 를 8 로 올리려면 47(서브탭)·A3(헤더 아이콘)가 먼저 움직여야 한다»** 였다.
47 은 335 로 등재돼 다른 워커가 잡았고, **남은 하나가 이것**이다.

그런데 게이트(`verify125` D3 «41 재화 바 아이콘 57×57»)는 내내 **초록**이었다.
착수 직후 `getBoundingClientRect` 로 재 봐도 상자는 측정표 그대로 57×57 이었다.

**둘 다 맞았다.** 게이트는 `<i>` 의 **레이아웃 박스**를 쟀고, 사람이 보는 것은 박스가 아니라
**아트의 색 잉크**다. `assets/ui/cur-*.svg` 가 viewBox 안에서 덜 차기 때문에 박스가 맞아도 잉크는 모자란다.
`tools/probe340.js` 로 ref JPEG 와 캡처를 **같은 자**(색 마스크 bbox)로 재니 지적이 그대로 재현됐다:

| 자리 | ref | cap(수리 전) | Δ |
|---|---|---|---|
| 코인 실루엣(검정 아웃라인 포함) | 64×65 | 57×57 | −10.9% / −12.3% |
| **코인 노란 원판** | 57×57 | **49×50** | **−14.0%** / −12.3% |
| 젬 실루엣 | 64×65 | 54×55 | −15.6% / −15.4% |
| **젬 시안 몸통** | 56×57 | **45×51** | **−19.6%** / −10.5% |

비평가들이 말한 «−14~21%» 는 **색 잉크 숫자와 소수점까지 같다**. 유령이 아니었다.

## 2. 뿌리 — 측정표의 «57» 은 실루엣이 아니라 색 잉크였다

측정표 `docs/measure/41-팝업내장재화바.md` §3 은 아이콘을
**«bbox(검정 아웃라인 포함) x500~556 / y111~167 = 57×57»** 로 적어 두었다. 41 은 그 값을 믿고
상자를 57 로 만들었다. 그런데 ref 를 다시 스캔하면

- 배경(바 본체·알약)이 아닌 화소 전체 = **64×65**
- 노란/시안 마스크 = **57×57 / 56×57**

즉 §3 의 57 은 **아웃라인 포함 실루엣이 아니라 노란 원판·시안 몸통**이다. 아웃라인 몫 7~8px 이 빠져 있었다.

**A3 가 HUD 에서 똑같은 것을 이미 겪었다.** A3 9회차 주석이 그대로 남아 있다 —
«‹실루엣 63 을 지켜야 한다›던 7회차 판단은 ref 외곽을 63 으로 본 측정표 값만 믿은 것이고,
X 가 ‹ref 외곽 64×65› 를 재면서 뒤집혔다». **64×65 — 이 문서가 방금 잰 값과 같다.**
HUD 는 그때 보정을 얻었다(코인 상자 63 → **65.3** · 젬 이미지 **scaleX(1.16)**).
`.pcb` 는 그 보정을 **못 받았다**.

> 이것은 93 이 `.fx-fly`·`.fx-lit` 에서 잡은 것과 **같은 계열의 결손**이다 —
> «재화별 보정을 `#top .curs` 안에서만 걸어 두었다». 93 은 비행·딤복제 두 자리를 편입시켰고,
> 여기서 **네 번째 자리(.pcb, 03·10·89 공용)** 가 나왔다.

## 3. 처방 — 새 상수를 만들지 않고 HUD 와 «같은 손잡이»를 건다

```css
.pcb-g>i>.cic{width:65.3px;height:65.3px}                        /* 코인: 상자(이미지) 키우기 */
.pcb-d>i>.cic{width:63px;height:63px;transform:scaleX(1.16)}     /* 젬: 이미지 자신에 scaleX */
```

- **같은 아트 · 같은 목표 잉크 = 같은 손잡이여야 한다.** 여기서 새 값을 지어내면 자리마다 또 갈린다
  (93 이 고친 병이 정확히 그것이다). 그래서 HUD(A3 6·9회차)의 두 값을 그대로 쓴다.
- **상자(`<i>` 57×57)는 안 건드린다.** 이미지는 절대배치 상자 안에서 flex 중앙정렬이라
  고르게 넘치고 잉크 중심은 상자 중심에 그대로 남는다. 알약(254×49)·숫자 그릇(235 의 186.5)이
  한 픽셀도 안 움직인다 — `verify340` [3] 이 그것을 단언한다.
- 넘친 잉크의 중심을 ref 중심(코인 528,139 · 젬 828.5,139)에 되돌리느라
  `.pcb-g>i` top −2.5 → **−4.5** · left −5 → **−5.5**, `.pcb-d>i` top −3 → **−4.5** · left −4 → **−5**.

### 수리 후 실측 (`node tools/probe340.js`)

| 자리 | ref | cap(수리 후) | Δ |
|---|---|---|---|
| 코인 노란 원판 | 57×57 | **56×58** | −1.8% / +1.8% |
| 젬 시안 몸통 | 56×57 | **57×57** | +1.8% / 0.0% |
| 코인 실루엣 | 64×65 | 66×66 | +2 / +1 |
| 젬 실루엣 | 64×65 | 67~69 × 60 | +3~5 / **−5** |
| 잉크 중심 | (529.5,140) / (828.5,140) | (527.5,138.5) / (828,139) | ≤2px |

**대가는 알고 받았다** — 젬 실루엣 세로가 ref −5px 다. 우리 자산의 검정 아웃라인이
가로로 두껍고 세로로 얇은데 `scaleX` 는 아웃라인까지 늘리기 때문이고, A3 6회차가 HUD 에서
받아들인 것과 **같은 대가**다. 보이는 것은 몸통(시안)이고 그쪽이 Δ≤1 이다.
자산(`cur-dia.svg` 의 마름모가 viewBox 를 꽉 차게)이 고쳐지면 두 override 가 함께 내려가고
실루엣도 같이 붙는다 — 측정표 «아트 필요» 표에 등재했다.

## 4. 게이트 — 이관 + 신설

- **이관** `verify125` **D3**: «41 재화 바 아이콘 57×57(measure/41)» → **«HUD 와 같은 재화별 확정값
  (gold 65.3×65.3 · dia 73.1×63)»**, 그리고 **D3b 신설**(기전까지 잰다 — gold=상자 크기 · dia=이미지 scaleX).
  D1/D1b 가 HUD 에 대해 하는 일을 `.pcb` 에도 그대로 시킨 것이다.
  **왜 «완화» 가 아닌가**: 옛 D3 은 57 이라는 **틀린 상수**를 지키고 있었다(그 상수를 지키는 한
  잉크는 영원히 −14~20% 다). 새 D3 은 더 좁게 잰다 — 값이 재화별로 갈리고, 기전(D3b)까지 본다.
- **신설** `tools/verify340.js` **39/39**:
  - `[1]` **ref 를 직접 다시 잰다** — 실루엣 64×65 · 색 잉크 57×57/56×57, 그리고
    «실루엣이 색 잉크보다 7~9px 크다(⇒ 57 은 실루엣일 수 없다)». 측정표가 다시 57 로 되돌려지면 빨개진다.
  - `[2]` 캡처 색 잉크가 ref 에 붙는가(폭 오차 ≤6% · 중심 ≤2.5px).
  - `[3]` 기전 — 알약 254×49 · 상자 57×57 · 패딩 53/14.5 불변(235 그릇), 보정은 **이미지**에만.
  - `[4]` 같은 컴포넌트를 쓰는 **10 상점 · 89 유물** 바도 같이 움직였다(81 «두 바 Δ0» 규약).
  - `[R]` **되돌림 시험**(LESSONS 334-③) — 보정을 걷어내면 코인 −14.0% · 젬 −19.6% 로 **다시 빨개지고**,
    걷어낸 것을 원복하면 초록. «무르게 푼 수리» 가 아님을 못박는다.
