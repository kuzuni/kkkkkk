## 1. 결함

저장소 주인 스크린샷: **일반 등급 장비 3종을 낀 상태인데 세 칸이 전부 초록.**

원인은 두 줄이다.

```css
.eqsl>.rim{... background:#C7E746}                              /* 상수 */
.eqsl>.rim>.fi{... background:linear-gradient(180deg,#9CC638,#97BD36)}   /* 상수 */
```

그리고 `renderEqPage()` → `eqpSlot(y, badge, ic, lv, attr)` 가 슬롯에 넘기는 것은
**부위 아이콘 · 아이템 아이콘 · Lv 뿐**이었다 — `it.g`(등급)를 아예 안 넘긴다.
색이 CSS 상수인데 등급이 도달조차 못 하니, 일반을 껴도 신화를 껴도 결과가 같을 수밖에 없다.

## 3. 팔레트 선택 — `SK_FILL` 이 아니라 `WGRADE`

등재문 처방은 «07 선례대로 `--f:SK_FILL[g]` · `--r:SK_RIM[g]`» 였다. **바꿔 잡았다.**

06 슬롯을 누르면 열리는 것은 **05 팝업**이다(`$('eqCards')` 리스너 → `openWeapon(null, part)`).
05 는 같은 아이템을 `WGRADE[g]` 로 칠한다. 여기서 `SK_FILL`(스킬 팔레트)을 끌어오면
**같은 장비 한 개가 슬롯에서와 팝업에서 다른 색**이 된다 — 주인이 지적한 «통일감» 의 정반대다.
두 팔레트는 실제로 다르다(예 g2 희귀: `SK_FILL` `#347DC1` 밝은 파랑 vs `WGRADE` `#1F5281` 짙은 파랑).

`SK_FILL`/`WGRADE` 의 g1(고급)만 우연히 거의 같아서(`#94BC35` vs `#94BC35`) 등재문이
어느 쪽을 써도 같아 보였을 뿐이다.

## 4. ⚠ 레퍼런스 이탈을 0 으로 만든 방법 — g1 만 실측값을 박았다

등재문의 경고 그대로, **이 초록은 레퍼런스 색일 수 있다**(06 측정표 §2-6 · §2-6-1 에 실측으로 등재).
그런데 레퍼런스 스크린샷은 **고급 장비를 낀 상태**다 — 즉 그 초록은 «슬롯 색» 이 아니라 **«고급 색»** 이다.

그래서 팔레트의 **g=1 칸만 측정표 실측 6색을 그대로 박았다.**

| 요소 | 측정표 실측 | `EQSL_G[1]` | 렌더 실측(게이트 [A]) |
|---|---|---|---|
| 슬롯 밝은 림 | `#C7E746` | `#C7E746` | `#c7e746` Δ0 |
| 슬롯 면 위 | `#99C136`(§2-6) / CSS `#9CC638` | `#9CC638` | `#9cc638` Δ0 |
| 슬롯 면 아래 | `#95BD34`(§2-6) / CSS `#97BD36` | `#97BD36` | `#97bd36` Δ0 |
| 뱃지 밝은 링 | `#ACC640` | `#ACC640` | `#acc640` Δ0 |
| 뱃지 중간 링 | `#9EBA3C` | `#9EBA3C` | `#9eba3c` Δ0 |
| 뱃지 채움 | `#7C9A38` | `#7C9A38` | `#7c9a38` Δ0 |

**결과: 레퍼런스 상태(고급 장착)에서 이 화면은 1px 도 안 바뀐다.** 07 이 등급색을 넣을 때 감수한
«레퍼런스 이탈» 이 여기서는 **필요 없었다** — 이탈 없이 버그만 뺄 수 있다. 측정표 §2-6 에 정오표로 남겼다.

나머지 7등급은 레퍼런스에 표본이 없다. g1 에서 잰 «슬롯 → 뱃지» 명암비로 파생했다:

```
뱃지 밝은 링 = 슬롯 림 ×0.87 · 뱃지 중간 링 = 슬롯 면 ×0.97 · 뱃지 채움 = 슬롯 면 ×0.80
슬롯 면 아래 = 슬롯 면 위 ×0.96   (측정표 «거의 평면, 매우 약한 세로 그라디언트»)
```

파생식이 적용되는 것은 **레퍼런스가 없는 등급뿐**이라, 이 비율이 몇이든 반증할 근거가 없다 —
그래서 «맞다/틀리다» 를 다투는 대신 게이트 [E] 로 **명암 순서(림 > 면 > 뱃지채움)만** 못 박았다.

## 5. 고친 것 3곳

1. **CSS** — `.eqsl>.rim` 의 배경을 `var(--r,#C7E746)`, `.eqsl>.rim>.fi` 를
   `linear-gradient(180deg,var(--f,#9CC638),var(--fb,#97BD36))`, `.eqbd` 의 채움·링 2개를
   `var(--bf/--br/--bm, …)` 로. **폴백값 6개는 전부 옛 상수 그대로**다 — 그래서
   변수를 안 싣는 경로(빈 칸)는 CSS 한 줄도 안 바뀐 것과 같다.
2. **`EQSL_G`** 신설(`WGRADE.map`) + `eqTone(h,k)` 파생 헬퍼. `skDim()`(07 구간)은 **안 건드렸다** —
   ×0.65 로 하드코딩돼 있어 인자를 열면 남의 작업 구간을 고치게 된다.
3. **`eqpSlot(y, badge, ic, lv, attr, col)`** — 6번째 인자로 팔레트를 받아 슬롯과 뱃지 두
   `style` 에 변수를 싣는다. 호출부는 `renderEqPage()` **한 곳뿐**이라(grep 전수) 다른 거동 변화 없음.

**빈 칸은 처방대로 지금 색을 유지한다** — `col=null` 이면 변수를 아예 안 싣고 CSS 폴백
(림 `#C7E746` · 면 `.eqsl.empty` 의 어두운 초록 `#7E9C2C→#7A982A` · 뱃지 `#7C9A38`)이 그대로 남는다.
게이트 [D5] 가 «빈 칸의 인라인 style 에 `--r/--f/--bf` 가 없다» 를 못 박는다.
