## 1. 재현이 등재문을 두 군데 고쳤다 (338·344·372 규칙)

처방을 따르기 전에 `tools/probe452.js` 로 제품에게 직접 물었다. 등재문의 주장은 **참**이었지만
**두 가지가 틀렸거나 모자랐다.**

### ① 「10.1px」은 «획을 뺀» 값이다 — 찍히는 잉크는 **14.6px**

| 재는 공간 | 목걸이 최악 겹침(단계 0) |
|---|---|
| Range bbox (레이아웃 잉크) | **10.1px** ← 등재문이 적은 값 |
| Range bbox + `-webkit-text-stroke` 절반(4.5px) = **찍히는 잉크** | **14.6px** |

`.clb-eff` 는 `-webkit-text-stroke:9px` 이라 획이 Range bbox **밖으로 4.5px 더** 나간다.
`14.6 − 10.1 = 4.5` 가 정확히 그 몫이고, 게이트 `verify452` 는 이 항등식을 그대로 단언한다
(`probe452` ⓐ 3항). **340 교훈의 재발**이다 — «게이트가 초록이던 이유는 그것이 레이아웃 박스를
쟀기 때문이다». 비평가 셋이 읽은 «4~5px» 은 둘 중 **어느 쪽도 아니다**(눈은 획을 반만 센다).

### ② 그 10.1px 은 **부팅값**이다 — 워스트에서는 «목걸이만» 이 아니다

등재문은 부팅 세이브(단계 0 ⇒ «+0.0%»)만 봤다. 단계는 10 까지 오르고 세트 등급 배율은
**26 배**(`GRADE[7].mul`)까지 가므로 자릿수가 늘어난다. 단계 10 · 세트 전원 만렙에서 재면:

| 탭 | 항 수 | 워스트 문자열 | raw 겹침 |
|---|---|---|---|
| 스킬 | 2 | 공격력 +120.0% · 공격 속도 +40.0% | **+1.3px** |
| 무기 | 1 | 공격력 +200.0% | −297.5px |
| 방패 | 1 | 최대 체력 +200.0% | −253.1px |
| **목걸이** | 2 | 치명타 피해 +130.0% · 골드 획득 +260.0% | **+96.9px** |
| **펫** | 2 | 펫 피해 +520.0% · 골드 획득 +260.0% | **+43.1px** |
| 유물 | 1 | 공격력 +116.7% | −311.8px |

⇒ **2항 탭 셋 다** 물린다. 등재문이 «표(어느 탭이 2항인가)로 막지 말고 상자를 버튼 앞에서
끊어라» 고 적은 것이 정확히 옳았고, 그 근거가 이 표다. 표로 막았으면 «목걸이만» 을 고치고
**펫·스킬은 단계가 오르는 순간 같은 버그로 되돌아왔을 것**이다.

### ③ 2280 ↔ 1600 은 완전히 같다 (등재문 ⓑ 확인)

가로는 1080 공통이고 팝업은 세로만 준다 — 두 프레임에서 **같은 14.6px / 96.9px** 이 나왔다.
⇒ 351(9:13.3 가독성) 감점 대상이 아니라 별개 번호가 맞다.

### ④ 뿌리 (등재문 ⓒ 확인)

효과 바 상자 **130.5..948.5** · 버튼 **716.5..955.5** — 바가 **블록 전폭**을 잡고 버튼이 그 위에

## 2. 처방 — 상자를 «버튼에게 물어서» 끊는다 (새 상수 0개)

```js
function collFitEff(){
  document.querySelectorAll('#collList .clb').forEach(b => {
    const eff = b.querySelector('.clb-eff'), btn = b.querySelector('.clb-btn');
    if(!eff || !btn || !b.offsetWidth) return;
    const bw = b.getBoundingClientRect().width;
    if(!bw) return;                                          /* 팝업이 안 떠 있으면 잴 것이 없다 */
    const sc = bw / b.offsetWidth;                            /* 프레임 → 화면 배율(fit()) */
    const cs = getComputedStyle(eff);
    const gap = parseFloat(cs.paddingLeft) || 0;              /* 좌측 여백을 거울로 */
    const sw  = parseFloat(cs.webkitTextStrokeWidth) || 0;    /* 획 절반이 Range 밖으로 나간다 */
    const rg = document.createRange(); rg.selectNodeContents(eff);
    const room = btn.getBoundingClientRect().left - (gap + sw / 2) * sc - rg.getBoundingClientRect().left;
    if(room > 0) fitNum(eff, room);
  });
}
```

- **부품을 안 만들었다.** 213 이 같은 문제(«기록 자릿수가 썸네일 슬롯을 침범»)에 쓴
  `fitNum(el, maxW)` 그대로이고, 공간 맞춤(양변을 «화면 px» 로 통일)도 `raidFitNums()` 를 그대로 따랐다.
- **자리를 상수에서 뺐다(368 처방).** 버튼 좌변을 **버튼에게 묻는다** — `left:586px` 을 복사해 두면
  버튼이 움직이는 날 조용히 갈라진다.
- **여백도 새 상수를 안 만들었다.** 버튼 앞 여백 = **바 자신의 `padding-left`(32px)** 를 거울로 쓴다
  («효과문은 바 안쪽에서 좌우 같은 값만큼 떨어진다»). 213 의 `RD_SPGAP = 16` 을 빌려 오지 않은 이유는
  그것이 **03 던전 카드 규격**이라 21 도감과 묶이면 한쪽을 고칠 때 다른 쪽이 따라 움직이기 때문이다.
- **호출은 두 자리다.** `renderColl21()` 끝(탭 전환·강화·일괄 강화의 재렌더가 전부 여기를 지난다) ·
  `openColl21()` 의 `.classList.add('on')` **뒤**. 후자가 없으면 **첫 열기가 안 잡힌다** —
  `openColl21` 은 `display:none` 인 채로 그린 뒤 `.on` 을 붙이므로 그 시점에는 잴 것이 0 이다.

## 4. 자를 짜면서 걸린 함정 — 60 쥬시의 «등장 스케일»

`renderColl21()` 직후에 재면 같은 블록(`.clb`, 선언 폭 818)의 **그려진 폭이 760.7 ~ 832.55px 로 흔들린다.**
60 쥬시가 블록에 등장 스케일을 걸기 때문이다. 1회차 자는 프레임 좌표를 `#app` 배율로만 환산해
바 상자를 **125.79..953.2**(정답 130.5..948.5)로 읽었고 E1·E2·E3 세 항이 통째로 빨갰다 —
**제품이 아니라 자가 틀린 것**이었다. ⇒ `settle()`(그려진 폭이 선언 폭으로 돌아올 때까지 대기)을
자에 넣었다.

⚑ **제품 쪽은 이 흔들림에 구조적으로 안전하다** — `collFitEff` 는 방과 잉크를 **둘 다 화면 px** 로
재고 그 **비**만 쓰므로 등장 스케일이 얼마든 같은 `font-size` 로 수렴한다(`fitNum` 도 같은 공간).
`sc` 를 `#app` 이 아니라 **블록 자신**(`bw / b.offsetWidth`)에서 뽑은 것이 그 이유다.
