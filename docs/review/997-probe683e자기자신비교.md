## 1. 재현 — 등재문 그대로였다(338 규칙)

등재문(sess-1358-25920)이 적은 **6/11** 과 빨간 항이 하나 다르다 — [4-c]가 9.18 ↔ 9.26 으로
**노이즈 폭 안에서** 초록으로 넘어왔다. 이것 자체가 진단이다: **BASE 와 FLIP 이 같은 그림**이라
둘의 차가 매 실행 부호를 바꾼다.

뿌리는 등재문 그대로다 — `VARIANT.BASE = ''`(아무것도 안 덮음)로 «수리 전 그림» 을 잡았는데,
**14회차가 FLIP 을 제품에 심으면서 BASE ≡ FLIP** 이 됐다. 자가 죽은 게 아니라 **견줄 상대가 사라졌다**.

## 2. 처방 — 사본을 «13회차 상태» 로 **주입**하고, 값은 제품에서 파생시킨다

되돌릴 자리는 둘뿐이다(14회차 §14-4 의 그 두 줄):

```
filter: brightness(0) invert(1)        →  brightness(0)              (채움 흰색 → 검정)
        drop-shadow(… #140D04) ×8      →  drop-shadow(… #FFF) ×8     (테 어두움 → 흰색)
```

**손으로 안 적었다**(402 «표 두 벌» 금지 · `verify753` [B2c] 가 쓰는 것과 같은 파생):
실행 시각에 `getComputedStyle(#fxl .fx-rlic).filter` 를 읽어 ① `invert(1)` 을 빼고
② `lastIndexOf('drop-shadow(')` **앞의 테 구간**에서만 색을 흰색으로 바꾼다.
글로우(마지막 겹)는 14회차가 한 값도 안 건드렸으므로 **그대로 둔다** — 전부 치환하면 글로우까지 희어진다.

⚑ **SCREEN 도 같이 옮겼다.** 처방문의 물음은 «13회차 알에 screen 을 걸면 낫는가» 다.
제품(FLIP) 위에 blend 한 줄만 얹으면 **극성이 이미 고쳐진 뒤**라 [5-c]가 «screen 도 정상» 으로
헛빨강이 된다. ⇒ SCREEN = **13회차 사슬 + `mix-blend-mode:screen`**.
