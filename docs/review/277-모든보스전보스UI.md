# 277 — 모든 보스전에 보스 UI (HP 바 + 남은 시간)

> T1 버그 · 저장소 주인 보고 2026-08-27 · **1회차 완료** (2026-08-28, sess-0023-30593 워커 F)
> 지시서 [3]-**(가)/기능 완성 규칙** — 레퍼런스 대조가 아니라 «실제로 동작하나» 를 재는 작업이라
> **비평가를 띄우지 않았다.** 판정은 전부 헤드리스 게이트다.

## 주인 보고

> «스테이지 보스 하다가 승급전으로 넘어갔더니 UI가 스테이지 보스 하던 UI였다.
> 승급전이나 던전, 쨋든 모든 보스전은 다 보스 UI 제대로 떠야 함 — 해당 HP 바랑 시간 얼마 남았는지»

## 1. 진단 — 실측으로 확인한 것

등재문의 전제(«`drawBossHud()` 에 promo 분기가 없다»)는 맞았다. 그 위에 **원인 두 개**가 더 있었다.

| # | 증상 | 원인 (실측) |
|---|---|---|
| ⓐ | 승급전에 들어가도 스테이지 보스 ⏱·체력바가 그대로 | `drawBossHud()` 가 `raidOn` → `inBossFight()` 두 갈래뿐. **`inBossFight()` = `bossOn` 은 스테이지 보스 전용 플래그**이고 `startPromo()` 는 그것을 안 끈다 → 승급전 중에도 `bf === true` 로 읽혀 `#stinfo.bfight` 가 켜진 채 남고, ⏱ 는 `bossT`(직전 보스전 시계), 체력바는 «보스가 없으니 만피» 폴백을 그렸다. |
| ⓑ | 승급전에 **남은 시간이 아예 안 보인다** | 승급전 시계는 `#prT`(진행바 안 글자)에만 있었는데 ⓐ 로 켜진 `.bfight` 가 `#stinfo .kbar` 를 `display:none` 으로 덮는다 → 시계가 통째로 사라진다. 즉 «스테이지 보스 UI 가 남는다» 와 «승급전 시계가 없다» 는 **같은 한 줄의 두 얼굴**이었다. |
| ⓒ | 승급전 위에 **[스테이지 재도전] 버튼이 남는다** | 파밍 조건이 `S.bossFarm && !bf` 였다. 보스에게 지고(파밍) 승급전에 들어가면 `bf` 가 false 인 경로에서 `fm` 이 true → `#bossRt` 노출. `#bossRt` 는 `pointer-events` 가 살아 있는 **버튼**이라 눌리기까지 한다. 던전·레이드·아레나는 진입 함수가 `S.bossFarm = false` 를 해 우연히 이 구멍을 피해 갔을 뿐이다(같은 식이 남아 있는 한 언제든 재발). |

던전(30/178/257)·아레나(123)는 **이미 자기 HUD 에 ⏱ + 체력/진행바가 있었다** — 257 이 던전 진행바를
보스 국면에서 «보스 체력 합» 으로 갈라 놓은 그대로다(§5 로 실측 확인). 그래서 이번 수정 대상은
**승급전 + 모드 전환 잔존** 이다.

## 2. 처방 — 등재문의 «한 곳에서 정한다» 그대로

```js
function bossMode(){          /* 'arena' | 'dun' | 'raid' | 'promo' | 'stage' | '' */
  if(arena)  return 'arena';  /* 123 — 자기 HUD */
  if(dunRun) return 'dun';    /* 30/257 — 자기 HUD(보스 국면 = 보스 체력 합) */
  if(raidOn) return 'raid';   /* 46 — 28 규격 재사용 */
  if(promo)  return 'promo';  /* 277 신설 — 28 규격 재사용 */
  if(inBossFight()) return 'stage';
  return '';
}
const BOSS_HUD28 = { raid:1, promo:1, stage:1 };
```

- 우선순위는 «자기 HUD 를 가진 모드 → 28 규격을 빌려 쓰는 모드 → 스테이지». **승급전이 'stage' 보다 위**인
  것이 ⓐ 의 수리다 — 승급전은 스테이지 보스전 **도중에도** 끼어들 수 있다(`step` 의 `bossT > 0 && !promo`).
- `drawBossHud()` 는 이제 «모드마다 제 HUD 를 켠다» 가 아니라 **매 프레임 다섯 요소를 전부 다시 토글**한다
  (`.bfight` · `.bfarm` · `#bossTm` · `#bossHp` · `#bossGv` · `#bossRt`). 「이전 모드 HUD 초기화」가
  별도 절차가 아니라 **그리기 자체**라서, 어떤 순서로 전환해도 잔존이 구조적으로 불가능하다.
- 파밍 조건은 `S.bossFarm && !bf` → **`S.bossFarm && md === ''`**(ⓒ 수리).
- 승급전 분기: ⏱ = `promo.t`, 체력바 = 승급 수호자(`tk 'promo'`, 208 이 `ETYPE.promo` 를 갈아 끼운 그것)의
  `hp/max`. 수호자가 없는 프레임(첫 프레임·막 쓰러진 프레임)은 0 으로 그린다 — NaN 폭 방지.
- **[포기하기]는 `stage`·`raid` 만.** 승급전은 중간에 그만두는 경로가 원래 없다 — 없는 버튼을 새로 만드는 것은
  이번 지시(«HP 바랑 시간») 밖이라 안 만들었다.

### 곁가지 한 줄 — 60 보스 훅 중복

`.bfight` 를 켜면 60 의 관찰자가 «BOSS» 슬램을 띄운다. 승급전은 `startPromo()` 가 «승급전» 슬램을
직접 부르므로 두 장이 겹친다 → 관찰자가 **승급전일 때 스스로 물러난다**. (관찰자에 넘기지 않은 이유:
스테이지 보스전 도중에 승급전이 오면 `.bfight` 가 이미 켜져 있어 «변화» 가 없고, 그러면 등장 연출이
통째로 빠진다.)

## 5. 안 건드린 것 (근거)

- **`startPromo()` 의 `bossOn`·`bossT`.** 끄고 싶었지만 `step` 의 `bossT > 0 && !promo` 가 «승급전이
  끼어들면 보스전 시계는 멈춘다» 를 그 값으로 표현하고 있다. 모드 판정이 승급전을 위에 두므로
  HUD 는 이미 옳고, 승급전이 끝나면 `endPromo → spawnStage()` 가 네 플래그를 전부 비운다.
  **플래그를 안 건드리고 표시만 바로잡은 것**이 이번 수정의 범위다.
- **`#prT` 의 승급전 문구.** 화면에는 안 나오지만 같은 `prR` 을 161 의 중간 노드 점등이 쓰므로
  계산은 그대로 뒀다(VERIFY161 §5 가 그것을 잰다).
- **278(제한 시간 15초 통일).** 등재문이 «277 과 묶으면 효율적» 이라 적었지만 지시서 [1]
  «잡은 작업 단위 딱 1개만» 이 우선이라 상수는 한 줄도 안 건드렸다(`BOSS_SEC 30` · `DUN_SEC 30` 그대로).
  이번 구조 덕에 278 은 «상수만 갈면» 되는 상태다 — HUD 는 어느 모드든 자기 시계를 읽는다.
- **승급전 [포기하기].** 위 2절 참조 — 지시 밖.
- `verify257` 이 첫 실행에서 83/84(런 [6] «보스끼리 겹치지 않는다» 는 무작위 스폰 좌표를 본다),
  이어진 두 번 연속 실행에서 **84/84 PASS**. HUD 토글과 스폰 기하는 접점이 없다.
