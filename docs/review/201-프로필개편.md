## ② 칭호는 승급 성공 시에만 1개씩

**원인 실측 — 겉보기 결과는 이미 맞았지만 «규칙» 이 코드에 없었다.**
구 구현은 `renderProfile()` 이 `own = i <= S.rank` 로 보유를 **파생**시켰다. 화면에 뜨는 칸 수는
«기본 1 + 승급 횟수» 라 지시와 우연히 일치하지만, 파생에는 두 결함이 있다:

1. **지급이라는 사건이 없다.** 승급 성공 팝업은 «칭호 **브론즈** 획득!» 이라고 적는데
   그 문장을 뒷받침하는 코드가 어디에도 없었다 — 표기만 있고 지급이 없는 상태
   (ROUTINE «기능 완성 규칙» 이 금지하는 바로 그 모양. 179 가 «보여 주고 안 주면 거짓» 이라고 적은 자리와 같다).
2. **계급이 내려가면 칭호가 회수된다.** 파생이므로 `S.rank` 가 줄면 이미 «획득!» 이라고 알린 칸이 도로 잠긴다.
   주인 지시의 «회수 금지» 를 만족한다고 말할 근거가 없다.

**고친 것 — 182 코스튬과 «같은 훅·같은 규칙»**(등재문이 지시한 대로):

| | 코스튬(182) | 칭호(201) |
|---|---|---|
| 저장 키 | `S.avatars` | **`S.titles`**(계급 index → 1) |
| 지급 함수 | `grantPromoCos(ri)` | **`grantRankTitle(ri)`** |
| 부르는 자 | `endPromo(true)` · `load()` 소급 | 같음 |
| 멱등 | 이미 있으면 건너뜀 | 같음 |
| 회수 | 금지 | 금지 |
| KEY | 안 올림(44 교훈 2) | 안 올림 |

- 칭호 목록은 **별도 표를 만들지 않고 `RANKS` 자체**로 뒀다(계급 수 = 칭호 수 8 — 등재문의 «계급명 연동»).
- **기본 칭호 1개(브론즈)는 포함**한다. 코스튬 `av0` 이 «기본 지급» 인 것과 같은 자리이고,
  0개로 시작하면 신규 유저의 `#pfTtl`(현재 칭호)과 02 헤더 `.ptitle` 이 «보유하지 않은 칭호» 를 달게 된다.
- 팝업 문구도 지급 결과를 따라간다: 새로 받으면 «칭호 **실버** 획득!», 재도전이면 «칭호 **실버** (이미 보유)».

**구세이브 소급(회수 금지의 실체)** — `load()` 에서 `titles` 키가 없으면 `0..S.rank` 를 지급한다.
이 한 줄이 없으면 **구 파생 구현에서 이미 열려 있던 칸이 reload 한 번에 잠긴다.**
게이트 §4 가 `titles` 를 지운 rank 3 세이브를 `addInitScript` 로 심고 reload 해서 4칸이 그대로 열리는지 본다.

> ⚠ **게이트를 짜다 만난 함정** — localStorage 를 `page.evaluate` 로 써 놓고 reload 하면
> 그 사이 게임 루프의 자동 저장이 메모리의 `S` 로 덮어쓴다(실측: rank 3 을 심었는데 reload 후 **1**).
> `addInitScript` 는 페이지 스크립트보다 먼저 도므로 그 경주가 아예 없다.
