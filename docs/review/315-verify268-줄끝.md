## 2. 원인

`tools/verify268.js` §3 은 showItem 본문을 **소스 리터럴**로 잘라낸다.

```js
const fn   = SRC.slice(SRC.indexOf('function showItem(id){'));
const body = fn.slice(0, fn.indexOf('\n}\n') + 3);
```

- 시작 앵커에는 줄바꿈이 없어 CRLF 에서도 맞는다.
- **끝 앵커 `'\n}\n'` 만 빗나간다** — CRLF 소스에서는 그 자리가 `\r\n}\r\n` 이라 `indexOf` 가 `-1`.
- `-1 + 3 = 2` → `body` 가 **2글자**(`"fu"`)로 잘린다.

그 결과 딱 2건이 빨개진다:
- `showItem 본문을 소스에서 찾았다`(`body.length > 200`)
- `showItem 이 .skd 를 쓴다`(`/class="skd"/`)

그리고 **더 나쁜 쪽** — 같은 body 를 쓰는 **부정 단언 4건**
(`#0e1428` 없음 · `.gbtn` 없음 · `#mClose` 없음 · `showModal()` 안 씀)은
빈 문자열이라 **전부 헛통과**한다. 145/147 의 «2건» 은 실은 «6건이 무의미해진» 상태의 그림자였다.

313(`verify283`)이 «`\n` 리터럴 치환이 조용히 0건» 이던 것과 같은 병이고, 이쪽은 치환이 아니라 **슬라이스**라는 점만 다르다.

## 3. 수정 (2곳, 게이트만 — 제품 무변경)

1. `SRC` 를 읽을 때 줄끝을 정규화한다(브라우저는 원본 파일을 그대로 연다 — 캡처·측정에 영향 없음).
   ```js
   const SRC = fs.readFileSync(..., 'utf8').replace(/\r\n/g, '\n');
   ```
2. **헛통과를 막는다(212-①).** 시작·끝 앵커를 각각 소리 나게 센다 — 앵커가 다시 부패하면
   부정 단언이 조용히 초록으로 가는 대신 여기가 먼저 빨개진다.
   ```js
   ok(fnAt  >= 0, 'showItem 시작 앵커를 소스에서 찾았다');
   ok(endAt >  0, 'showItem 끝 앵커(`\n}\n`)를 찾았다 — 줄끝 정규화 확인');
   ```
   단언 2건이 늘어 총계는 147 → **149** 가 된다.
