## 3. 원인 — 「나이」를 **벽시계**로 재면, 프레임이 멈춘 시간까지 나이에 들어간다

`fxSrc(now)`(index.html ~24238)의 두 창은 길이가 다르다:

```js
const a = (now - fxOrigT < 600  && fxOrig)   ? fxOrigT : -1e9;   /* 전투·명시 힌트 */
const b = (now - fxTapT  < 1200 && fxTapEl)  ? fxTapT  : -1e9;   /* 마지막 탭 */

```

같은 프레임에서 재는 한 이 식은 옳다 — 더 최근에 찍힌 쪽이 이긴다.
문제는 **재는 시점이 밀릴 때**다. 하단 네비를 누르면 패널 렌더가 메인 스레드를 통째로 잡아먹는다:

```

```

정지가 **645~803ms** 라 두 창이 **서로 다른 배수로** 만료된다:

- 전투 힌트(600ms) — 정지 하나에 **만료된다**
- 탭 힌트(1200ms) — 같은 정지를 **살아남는다**

그래서 프레임이 풀리는 순간의 `fxWatch` 는 «더 오래된 탭» 만 유효한 후보로 보고 그것을 스냅샷한다.
**순서가 뒤집힌 것이 아니라, 더 최근인 쪽이 먼저 실격당한 것이다.**

표본으로 검산(run 6): 탭 T−897 → 킬 T−769 → 정지 T−734~T(734ms).
`a` 는 769 > 600 이라 `-1e9`, `b` 는 897 < 1200 이라 살아 → 탭 승. combat 태그가 사라져 `fxFly` 가 `#fxl`(팝업 위)을 고른다.

> 158 이 «스냅샷을 발사 시점이 아니라 **누적 시점**으로 옮긴다» 로 막은 것은 «누적 뒤에 누른 탭» 이었다.
> 여기서 이기는 탭은 **누적 전에 눌린** 탭이고, 밀린 것은 스냅샷을 **뜨는 시점**(정지 뒤 첫 프레임)이다.

## 4. 처방 — 힌트의 나이는 «프레임이 실제로 돌아간 시간» 으로 잰다

프레임이 멈춰 있는 동안에는 **새 힌트가 들어올 수 없다.** 그러니 정지 구간은 한 프레임 몫만 세면 된다.

```js
const FX_STEP = 120;                       /* 한 프레임이 흡수하는 진행량 상한(ms) */
let fxClock = 0, fxClockAt = performance.now();
function fxClk(){ return fxClock + Math.min(performance.now() - fxClockAt, FX_STEP); }
function fxClockTick(now){ fxClock += Math.min(now - fxClockAt, FX_STEP); fxClockAt = now; }
```

- `fxAt()` · `pointerdown` 리스너 — 도장을 `performance.now()` → **`fxClk()`**
- `fxSrc(now)` — 유효 창 판정을 **`fxClk()`** 기준으로(인자 `now` 는 호출부 호환으로만 남긴다)
- 메인 루프 — `fxClockTick(performance.now())` 를 **절전 분기 «앞»** 에서 한 번

**⚠ 시계를 `fxTick` 안에 두면 안 된다.** 56 절전 모드는 `fxTick` 을 통째로 건너뛴다(index.html ~25812) —
거기 두면 절전 중에 시계가 얼어 힌트가 **영원히 신선**해지고, 절전이 풀리는 순간 그동안 쌓인 방치 골드가
«절전 직전에 누른 버튼» 에서 튀어나온다. 158 이 없앤 그림이 정확히 되돌아온다.
루프가 도는 한 시계도 돌아야 한다 → `saverOn` 분기 **앞**.

순서 판정(`a >= b`)은 **손대지 않았다.** 고친 것은 «누가 아직 유효한가» 하나다 —
세 표본 모두 전투 힌트가 더 최근이었으므로, 실격만 없애면 원래 식이 알아서 맞는다.

## 7. 다음 세션에 남기는 주의

- `fxClk()` 는 **프레임 시계**다. 새 연출이 «몇 ms 전인가» 로 무엇을 판정한다면 `performance.now()` 가 아니라
  이 시계를 써라 — 벽시계로 재는 순간 «패널 여는 프레임» 이 그 판정을 조용히 뒤집는다.
- 반대로 **길이(duration)** 는 벽시계 그대로다(비행 0.28s·롤링 0.32s 등). 시계를 바꾼 것은 **나이(age)** 뿐이다.
- `FX_STEP = 120` 은 «한 프레임이 흡수하는 진행량» 이다. 이보다 짧은 공백(정상 프레임 드랍)은 그대로 흐르고,
  이보다 긴 공백만 «멈춰 있었다» 로 접힌다. 실측 정상 프레임은 16~47ms 라 여유가 2.5배 이상이다.
