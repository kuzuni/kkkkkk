## §2 흔들림의 뿌리는 **둘**이다 (`probe408` [1]·[2])

### ⓐ 레드닷 자신의 애니메이션 — **영원히 안 앉는다**

`.updot` 규칙(`index.html` **10451**)에 `transform:none` 이 있는 것은 사실이다. 그런데 60 쥬시가
**11822~11826행**에서 이렇게 건다:

```css
.ibtn.on .bdg, … ,.alert>.updot, … {
  animation: jzDotIn .3s var(--jzs) both, jzDotPulse 2s ease-in-out .3s infinite}
@keyframes jzDotIn   {0%{scale:0} 62%{scale:1.3} 100%{scale:1}}
@keyframes jzDotPulse{0%,72%,100%{scale:1} 84%{scale:1.14}}
:root{--jzs:cubic-bezier(.34,1.56,.64,1)}          /* 오버슈트 */
```

⚑ **`transform` 이 아니라 `scale` 속성이라 `transform:none` 에 안 걸린다.** 등재문이 걸려 넘어진 자리다.
그리고 `jzDotPulse` 는 **infinite** — 닷의 `getBoundingClientRect()` 는 **정착하는 시점이 없다.**

실측(`probe408` [1], 한 번 여는 동안 20ms × 130 표본):

```
우 인셋(.updot) : 13.55 ~ 29.90   폭 16.35   σ 1.67      ← 허용 오차 1.2 의 열 배가 넘는다
닷 폭            : 0 ~ 39.05 (CSS 27)
|좌−우| (=[G4]) : 0 ~ 12.42       허용 1.2 를 넘는 표본 17/130
```

등재문이 적은 빨간 값 **16.9** 와 초록 값 **19** 는 **같은 곡선 위의 두 점**이다(`probe408` [1-b] —
스윕 범위 13.55~29.90 이 16.9 를 낀다). 산수도 맞는다: 16.9 는 `scale = (13.5+2.1)/13.5 = 1.156`,
즉 `jzDotIn` 의 62%→100% 구간을 내려오는 도중이거나 `jzDotPulse` 봉우리(1.14) 언저리다.
게이트가 `waitForTimeout(250)` 한 자리에서 재므로 **몇 ms 의 지연이 곧 43/44 다.**

### ⓑ 팝업 열림 연출 — 조상을 통째로 스케일한다 (**앉는다**)

`.ad` 뱃지 자신에는 애니메이션이 없다(`index.html` 1867~1877 — 정적 규칙뿐). 그런데도 좌 인셋이
초반에 17.48~19.35 를 훑는다. 뿌리는 **팝업 열림 연출이 조상(다이얼로그)을 통째로 스케일**하는 것이다.

```
t ≥ 1000ms (팝업이 앉은 뒤)
  좌 인셋 : 19 ~ 19  (폭 0)      ← 조상 배율만 탄다 = 앉는다
  우 인셋 : 17.11 ~ 19 (폭 1.89) ← jzDotPulse 가 infinite = 안 앉는다
```

⚑ **ⓑ 는 좌·우에 «같은 배율» 로 걸리므로 [G4] 의 «차» 에서는 상쇄된다** — 그것을 `probe408` [3] 이
못박는다(닷만 얼리면 **여는 순간부터** `|좌−우| = 0`, 그 표본들이 «팝업이 앉기 전» 을 실제로 포함한다는
것은 [3-b] 가 좌 인셋 절대값이 여전히 1.9px 폭으로 훑는 것으로 보인다 = 헛초록이 아니다).
그래서 **[G4] 만 놓고 보면 ⓐ 하나만 끄면 되지만**, [G1]·[G2]·[G3]·[G5]·[G6] 이 찍는 절대 px 은
그동안 배율에 실려 있다(250ms 에서 우 인셋 절대값 18.28~19.22 — `probe408` [5-b]).

## §3 처방 — 두 벌, 그리고 **허용 오차는 한 칸도 안 넓혔다**

등재문이 «⚠ 허용 오차 1.2 를 넓혀서 풀지 마라» 라고 못박아 둔 자리다. 넓히지 않았다.

1. **`__rou(true)` — 재는 동안만 닷의 애니메이션을 끈다.**
   `verify299`(59행) · `verify321`(**151행 — 같은 `#rouBtn > s.updot` 을 잰다**) ·
   `probe322`(48) · `probe325`(53) · `probe328`(148) · `probe364`(45) 가 **전부 쓰는 집안 처방**이고
   **367 만 안 쓰고 있었다.** 새 규칙이 아니라 이미 있는 규칙이 한 자리에 안 닿아 있던 것이다.
   인자 없이 부르면 종전 그대로라 표기·상태 항([B]·[C]·[D]·[H])은 제품을 안 건드린다.
2. **`settle(page)` — «250ms 뒤» 가 아니라 «앉은 뒤» 에 잰다.**
   ⓑ 를 «몇 ms» 라는 새 상수로 때우지 않고 **버튼 상자가 두 프레임 연속 같아질 때까지** 기다린다
   (`polling:'raf'`). 368 처방 그대로 — **자리를 상수에서 빼고 제품에게 묻는다.**
   닷은 영원히 안 앉으므로 여기서 안 본다(보면 영원히 안 끝난다).
3. **네 상자를 같은 순간에 잡는다** — `btn`·`adRect`·`dotRect`·`labInk` 를 한 블록에서 읽는다.
   종전에는 `btn` 만 함수 머리에서 먼저 읽고 있었다(같은 프레임이라 값은 같았지만, 얼리기가 끼면
   «무엇이 얼린 상태의 값인지» 가 코드에서 안 읽힌다).

## §5 다음 세션이 볼 것

⚑ **레드닷(`.updot`)의 `getBoundingClientRect()` 를 재는 자는 예외 없이 애니메이션을 끄고 재라.**
`jzDotPulse` 가 **infinite** 라 «조금 더 기다리면 앉는다» 가 성립하지 않는다 — 기다림으로는 절대 못 푼다.
그리고 `.updot` 규칙의 `transform:none` 을 «애니메이션 없음» 의 근거로 쓰지 마라: 쥬시는 `transform` 이
아니라 **`scale` 속성**을 쓴다(11824~11826). 이 한 줄이 등재문을 잘못된 첫 갈래로 보냈다.

⚑ **팝업 안 기하를 «열고 n ms 뒤» 에 재는 자는 전부 같은 함정 위에 있다.**
열림 연출이 조상을 스케일하는 동안 **절대 px 이 전부 배율에 실린다**. «차»(인셋·간격·중심)를 묻는 항은
상쇄되어 살아남지만, 절대값을 찍는 항은 그동안 뜻이 없다. 상수 ms 대신 «상자가 두 프레임 연속 같아질
때까지» 를 쓰면 새 상수 없이 닫힌다(368 처방과 같은 꼴).

⚑ **재현기가 자기 자신을 플레이키하게 만들 뻔한 자리** — 1·2회차 초안은 «250ms 언저리 어느 ms 가
빨갛다» 를 단언했다가 회차마다 뒤집혔다(`reopen()` 이 끝난 시점과 애니메이션 시작이 매번 몇 ms 어긋난다).
플레이키를 잡는 자가 플레이키면 아무것도 못 잡는다 — 그래서 «어느 점» 이 아니라 **위상 스윕이 그 값을
끼는지**로 바꿨다(344 교훈). 지금 [4] 는 그 창을 **진단 출력으로만** 찍고 판정하지 않는다.
