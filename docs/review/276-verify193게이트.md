## 2. 고친 것 — `tools/verify193.js` 만, `index.html` 0줄

### ★ 표를 제품에 맞춰 덮어쓰지 않았다

가장 쉬운 «고침» 은 `KEEP` 의 네 수를 2.40/1.25/0.85/3.00 으로 바꾸는 것이다. 그러면 초록은 되지만
**그 순간 이 항목은 «아무것도 안 보는 표»** 가 된다 — 다음에 누가 몰래 `m` 을 조여도, 260 이 되돌려져도
게이트는 계속 초록이다. 211~215·275 가 빠졌던 자리가 정확히 이것이다.

그래서 **축을 갈랐다.** 어긋난 것이 `m` 하나뿐이었다는 §1 실측이 그대로 설계가 됐다.

| | 무엇을 지키나 | 밸런스 작업이 지나가면 |
|---|---|---|
| **[1-a]** 기존 19종 **id·등급·cd** 불변 | 구 세이브 **호환** — 세이브가 실제로 의존하는 축 | 안 움직인다 (260 도 안 건드렸다) |
| **[1-b]** 기존 19종 **`m`** 이동은 **등재분뿐** | 밸런스 **이력** — 누가 무엇을 왜 옮겼나 | 등재하면 통과, 몰래 옮기면 빨개진다 |

`KEEP` 은 **193 기준선 그대로 두고**, 이동분을 새 표 `M_MOVED` 에 «옮긴 값 + 누가·왜» 로 따로 등재했다.

```js
const M_MOVED = {
  drain: [2.40, '260 — 영웅 등급 최약이라 올림'],
  frost: [1.25, '260 — 영웅 등급 최강이라 내림(hits 4)'],
  gale:  [0.85, '260 — 전설 등급 최강이라 내림(hits 12)'],
  lance: [3.00, '260 — 신화 등급 최강이라 내림(hits 3)']
};
```

[1-b] 의 판정은 **집합이 정확히 같은가**다 — 기준선에서 벗어난 id 집합 == `M_MOVED` 의 키 집합.
그래서 **양방향**으로 문다:

- **미등재 이동** (등재 없이 움직임) → 빨개진다
- **등재값 불일치** (등재해 놓고 제품이 안 따라옴 = 260 이 되돌려짐) → 빨개진다

통과 메시지가 이동 내역을 그대로 출력하므로, 게이트 로그 자체가 밸런스 이력이 된다.

```
✓ 기존 19종 id·등급·cd 불변 = 구 세이브 호환 (어긋남 0건)
✓ 기존 19종 `m` 이동은 등재분 4건뿐 — 260(등급 안 편차 ≤ 3.0)이 옮긴
  drain 2.00→2.40 · frost 1.45→1.25 · gale 1.05→0.85 · lance 3.20→3.00
  · 나머지 15종은 193 기준선 그대로
```

항목이 1 → 2 로 갈라져 **73 → 74** 가 됐다. 헤더 주석 [1] 절도 같이 고쳤다.
