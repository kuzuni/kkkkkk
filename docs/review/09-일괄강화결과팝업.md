## 3회차 조치 — 꼬리를 «하나의 실루엣»으로 재작화

2회차 지적이 전부 꼬리에 몰린 원인은 **구조**였다. 꼬리를 몸통 **뒤**에 두고 몸통을
«테두리 있는 라운드렉트» 로 얹으면, 몸통 테두리가 꼬리 위에 이음선으로 남는 것이 필연이다.
1·2회차에 이걸 «패치 요소로 덮는» 방식으로 두 번 땜질했지만 좌우 비대칭·가로 이음선이 계속 남았다.

→ **꼬리를 몸통 앞(z-index 3)으로 올리고, 클립 경로를 «ㄴ 자» 한 덩어리로 다시 그렸다.**

```
몸통 왼쪽 기둥(local x 0~42, 전 높이) + 드룹(local y 70~96, 전 폭)
clip-path: polygon(15 0, 42 0, 42 70, 91 70, 91 82, 80 90, 64 95, 18 95, 2 88, 0 80, 14 45, 2 16)
```

`x>42 · y<70` 을 비워 두면 그 구간은 몸통이 그대로 보이고, 꼬리가 걸치는 구간에서는
꼬리가 몸통 테두리를 덮어 **검정 이음선이 구조적으로 생길 수 없다.** 패치 요소는 전부 제거했다.

## 4회차 — **G 9/10 · H 9.5/10 → 최저 9 · 통과**

3회차 조치가 전부 반영돼 두 비평가 모두 «배치·크기·간격·정렬·폰트비율» 을 9.5~10 으로 봤다.
남은 감점은 **색·명암 단일 항목**이었고, 원인도 하나로 수렴했다 —
리본 상단 하이라이트 3px 밴드가 `#FDF08A`(253,240,138)로 들어가 ref `#FEF7A4`(254,247,164)보다
**ΔB −26 만큼 노랬다.** 측정표 §2.1.3 실측값(`#FEF7A4`→`#FEEA84`)대로 되돌려 회수했다.

두 비평가가 «남은 오차는 전부 JPEG 번짐·아트/폰트 리소스 한계» 로 분류했다:
꼬리 주황 하단 +3px, 화살표 폭 −1px, 몸통 주황 +2px — 전부 3px 이하로 ref 의 JPEG 경계 번짐 범위 안.
**아이콘 그림 차이(이모지 대체)와 서체 획 굵기는 채점 규칙상 미채점** — 실제 아트/게임 서체가 들어오면 회수된다.
A5(9)와 더불어 09 도 **색·폰트 리소스 한계를 감안한 채점에서 9점에 도달**했다.

## 이 화면에서 얻은 교훈 — **다른 화면에도 그대로 재발한다**

### 1. 숫자 텍스트에 `÷0.93` 을 쓰면 안 된다 (한글 규칙과 다르다)

`PROGRESS.md` 의 «01 교훈» 은 `font-size = 잉크높이 ÷ 0.93` 인데, 이건 **한글** 기준이다.
숫자·라틴은 잉크가 **캡하이트**라 같은 식을 쓰면 크게 나온다.

- 잉크 23px 을 노리고 `÷0.93` → **25px** 을 넣었더니 실측 잉크가 **17~18px** 이었다(−26%).
- 실제 캡비는 **0.70** 이었고 **33px** 이 맞았다. 두 비평가가 1회차에 나란히 이걸 지적했다.

> **숫자는 `font-size = 잉크높이 ÷ 0.70`, 한글은 `÷ 0.93`.** 한 문자열에 섞여 있으면 숫자 기준으로 잡고
> 한글은 `<i>` 의 `scaleX` 로 맞춘다.

### 2. 비평가 수치는 «레퍼런스를 직접 스캔해» 확인한 뒤 반영한다

1회차에 B 만 «꼬리↔몸통 검정선» 을 지적했고, **측정표에는 «몸통 검정 외곽선 6px 좌 x278–283»** 라고
적혀 있어 서로 어긋났다. `PROGRESS.md` §05 교훈 ③ 대로 반영 전에 ref 를 직접 훑었다.

```
ref y1060 · x272~291  →  전부 주황, 검정 0
ref y1020 (꼬리 y범위 밖) →  전부 검정
```

**둘 다 맞았다.** 몸통 검정 외곽선은 실재하지만 **꼬리가 겹치는 y구간에서만 없다.**
측정표의 «6px 외곽선» 은 꼬리 밖 구간을 잰 값이었다. 어느 한쪽을 그대로 믿었으면 틀렸다.

### 3. 같은 결함이 2회 연속 남으면 «값» 이 아니라 «구조» 를 고쳐야 한다

꼬리 이음선을 1회차엔 패치 요소로, 2회차엔 패치 폭 조정으로 땜질했는데
2회차 비평가 2명이 **또** 꼬리에서 5건을 찾아냈다(가로 이음선·우측 1px 이물·좌우 비대칭 등).
3회차에 z-order 와 클립 경로를 바꾸자 5건이 **한 번에** 사라졌다.
→ **같은 부위 지적이 반복되면 CSS 값을 더 만지지 말고 겹침 구조부터 다시 볼 것.**

### 4. 그늘 밴드는 방향이 있다

꼬리 그늘을 «안쪽(몸통 쪽) `#DD8433` / 바깥끝 `#A45119`» 인데 반대로 넣었더니
드룹 우측이 밝아져 **주황이 ref 보다 20px 더 뻗은 것처럼** 읽혔다(2회차 C·D 둘 다 «주황 과다» 로 지적).
색 자체는 둘 다 팔레트에 있었기 때문에 «색 Δ» 검사로는 안 걸린다. **밴드는 순서까지 실측대로.**

### 5. 인라인 SVG 는 `fill` 을 명시해야 한다

화살표를 이모지 «➡» 로 넣으면 이모지 폰트가 CSS `color` 를 무시해 레퍼런스의 연두(`#B4EC2C`)가 안 나온다.
그래서 인라인 SVG 로 그렸는데, `fill` 을 안 주면 **검정**이 되어 1회차에 «화살표 없음» 으로 채점됐다.
`fill:#B4EC2C; stroke:#000; stroke-width:8; paint-order:stroke fill` + `overflow:visible` 이 정답.
(SVG `stroke` 도 `-webkit-text-stroke` 와 똑같이 **윤곽 중심**에 그려져 실측 4px 을 내려면 8 이 필요하다)

## 진입점

`levelUpAll()` 이 `{n, lvs, ups}` 를 돌려주도록 확장했다(`ups = [{it, from, to}]`, 기존 `n`·`lvs` 는 그대로).
일괄 강화 3개 경로가 전부 `openUpAll(r.ups)` 로 09 를 띄운다. 강화된 게 **없을 때만** 기존 안내 모달을 쓴다.

- 07 스킬 팝업 «일괄 강화» (**레퍼런스 09 가 바로 이 경로다**)
- 05 무기 팝업 «일괄 강화»
- 배너 패널 «일괄 강화» (`data-upall`)

레퍼런스는 카드 3칸이지만 실제 결과는 개수가 가변이라 **한 줄에 들어가는 6칸까지**만 보여 준다
(151×6 − 14 = 892 < 1080). 화면 아무 데나 탭하면 닫힌다 — 레퍼런스에 ✕ 버튼이 없다.
