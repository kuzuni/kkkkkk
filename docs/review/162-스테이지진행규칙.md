  현재는 10스테이지마다 보스 뜸, 수정». 작업 28(보스전 개편)의 후속.
- 지시서 [3]-**(가)** 적용 — 레퍼런스 스크린샷과 대조할 레이아웃이 아니라 **진행 규칙**이라
  **비평가를 띄우지 않았다.** 대신 게이트 `tools/verify162.js` 를 신설해 «게임을 굴렸을 때
  그렇게 되나» 를 87항목으로 재고, 수정 전 트리로 되돌려 **빨간지 확인**했다.

## 1. 무엇이 바뀌었나

| | 구 규칙 (28) | 새 규칙 (162) |
|---|---|---|
| 보스가 뜨는 스테이지 | `S.stage % 10 === 0` — 10의 배수만 | **전부** |
| 일반 스테이지 클리어 | 몹 파도(50마리) 전멸 | **폐지** |
| 스테이지 클리어 조건 | (보스 스테이지만) 보스 격파 | **보스 격파 — 전 스테이지 공통** |
| 한 스테이지의 구성 | 몹 50 **또는** 보스 1 | 몹 50 **그리고** 보스 1 |
| 실패 처리 | 파밍 + [재도전] (10의 배수에서만) | 그대로 — 매 스테이지에 재사용 |

## 2. 구조 — 상태를 «스테이지 번호» 에서 «단계 플래그» 로 옮겼다

구 코드의 판정은 전부 스테이지 번호에서 나왔다.

```js
const isBossStage = () => S.stage % 10 === 0;
const inBossFight = () => isBossStage() && !S.bossFarm;
const stageTotal  = () => inBossFight() ? 1 : ENEMY_COUNT;
```

새 규칙에서는 `isBossStage()` 가 **항상 참**이 되어 아무것도 가르지 않는다. 대신 필요한 정보는
«이 스테이지에 보스가 있나» 가 아니라 **«지금 보스와 싸우는 중인가»** 다 — 같은 스테이지 안에서
몹 구간과 보스 구간이 시간순으로 갈리기 때문이다. 그래서 런타임 플래그 두 개를 세웠다.

```js
let bossOn   = false;   /* 보스 도전 중 — 스테이지는 «몹 50킬(false) → 보스(true)» 2단계 */
let stageWin = false;   /* 보스를 잡은 프레임에 서는 «클리어 예약» */

const inBossFight = () => bossOn;
const stageTotal  = () => bossOn ? 1 : ENEMY_COUNT;
```

- **`bossT > 0` 로 대신하지 않은 이유**: 보스 스폰 딜레이(1.4초)와 시간 초과 직전 프레임에서
  값이 흔들린다. «단계» 는 시계와 별개의 사실이라 별도 플래그가 맞다.
- **세이브에 넣지 않은 이유**: 28 의 `S.bossFarm` 은 «졌다» 는 사실이라 남겨야 하지만,
  `bossOn` 은 진행 중인 한 판이다. 새로고침하면 그 스테이지를 50킬부터 다시 채우는 쪽이
  «보스 앞에서 새로고침해 30초를 리셋하는» 구멍보다 안전하다.
- **`stageWin` 이 필요한 이유**: `killEnemy()` 는 전투 처리 한복판이다. 거기서 곧장
  `S.stage++ · spawnStage()` 를 하면 **호출자가 순회 중인 `enemies`/`spawnQ` 를 갈아엎는다.**
  그래서 예약만 하고, 실제 클리어는 `step()` 끝의 클리어 분기가 (승급전·사망 연출 게이트를
  통과한 뒤) 집는다.

## 3. 고친 것 (전부 `index.html`)

### ① 상수부 — `isBossStage` 폐기 (~13687)

`S.stage % 10` 은 코드에서 한 글자도 남지 않았다(게이트 §1 이 주석을 뺀 소스로 확인).

### ② `spawnStage()` — 스테이지 시작은 언제나 몹 구간 (~14185)

```js
S.bossFarm = false; bossOn = false; stageWin = false;
bossT = 0; queueMobs();
showMsg('STAGE ' + s);
```

구 코드의 «보스 스테이지면 보스 단독 스폰» 분기가 여기서 빠져 **`startBoss()` 로 옮겨 갔다.**
«BOSS n» 토스트도 같이 옮겼다 — 스테이지 시작에 뜰 일이 없어졌다.

### ③ `startBoss()` 신설 (~14205) — 28 의 보스전 프레임을 그대로 재사용

```js
function startBoss(){
  if(bossOn) return;
  S.bossFarm = false; bossOn = true; stageWin = false;
  enemies.length = 0; spawnQ.length = 0; killed = 0;   /* 28 — 보스는 «단독» 스폰 */
  spawnQ.push({ t:'boss', delay:1.4 });
  bossT = BOSS_SEC;
  showMsg('BOSS ' + S.stage);
  uiDirty = true;
}
```

들어오는 길은 둘 — **① 몹 50킬**(step 의 클리어 분기) **② [재도전] 버튼**.

### ④ `step()` 클리어 분기 — 배타적 4갈래로 재작성 (~15760)

구 코드는 «전장이 비었나» 하나로 두 갈래(파밍 재충전 / 스테이지 클리어)를 갈랐다.
새 규칙은 같은 «전장이 비었다» 가 세 가지 뜻이라(50킬 달성 · 보스 잡음 · 그 외) 단계로 가른다.

```js
else if(!promo && player.dead <= 0){
  if(stageWin){ … S.stage++ · 보너스 골드 · 최고 기록 다이아 · spawnStage() · 'STAGE CLEAR!' }
  else if(bossOn){ /* 보스전 진행 중 — 결판이 날 때까지 아무것도 하지 않는다 */ }
  else if(killed >= ENEMY_COUNT){ (파밍 중이면 보너스 골드) · startBoss(); }
  else if(enemies.length === 0 && spawnQ.length === 0){ queueMobs(); }   /* 안전망 */
}
```

- 마지막 갈래는 **진행바가 멈춘 채 방치되는 상태를 만들지 않기 위한 안전망**이다. 킬 이외의
  경로로 전장이 비면(현재는 없다) 다시 채운다. 30 던전의 «몹이 떨어지면 리필» 과 같은 취지.
- 28 의 «파밍 파도 전멸 = 보너스 골드»(`eGold(S.stage) * 12`) 자리는 세 번째 갈래로 옮겼다.
  **파밍 중일 때만** 준다 — 첫 도전은 그 뒤 클리어 보너스(`eGold(S.stage-1) * 12`)를 받으므로
  여기서 또 주면 스테이지당 이중 지급이 된다(골드 곡선 +100%).

### ⑤ `failBoss()` / `retryBoss()` / `killEnemy()` / HUD

- `failBoss()` — `bossOn = false; stageWin = false` 를 추가. 나머지(파밍 전환·몹 재충전·
  BGM 복귀)는 28 그대로.
- `retryBoss()` — **`spawnStage()` → `startBoss()`.** 구 코드는 스테이지를 다시 깔았는데,
  새 규칙에서 그건 «재도전» 이 아니라 «50킬부터 다시» 다. 50킬은 이미 한 번 채웠으므로
  보스만 다시 세운다.
- `killEnemy()` — 보스 처치 분기에 `if(bossOn){ bossOn = false; stageWin = true; }`.
  **46 레이드 샌드백도 `tk === 'boss'`** 라서 `bossOn` 으로 «진짜 스테이지 보스» 만 거른다
  (게이트 §6 이 샌드백 처치가 스테이지를 안 올리는지 확인한다).
- `drawBossHud()` — `fm = S.bossFarm && isBossStage()` → `S.bossFarm && !bf`.
  파밍은 이제 «보스전에 한 번 졌다» 뿐이라 스테이지 번호 조건이 없다.
- 30 던전 · 46 레이드 · 123 아레나 **진입 3곳** — 기존 `S.bossFarm = false; bossT = 0;`
  줄에 `bossOn = false; stageWin = false;` 를 붙였다. 보스전 한복판에 다른 모드로 들어가면
  단계 플래그가 남아 돌아왔을 때 «보이지 않는 보스전» 이 된다.

**되돌려 빨간지 확인**: `git stash push -- index.html` → 게이트가 `page.waitForFunction`
(=`startBoss` 가 없다)에서 즉사한다. 구 트리에서 통과할 수 없는 게이트임을 확인했다.

게이트를 짜다 두 번 스스로 오탐했고, 둘 다 **게이트 쪽 결함**이라 게이트를 고쳤다(코드가 아니라).
다음 세션을 위해 남긴다.

1. **`S.best` 를 `Math.max` 로 올려 두면 «최고 기록 다이아» 경로가 안 탄다.** 앞 §에서
   스테이지 23 을 재고 온 뒤 12 를 재면 `S.best` 가 23 이라 `first = S.stage >= S.best` 가 거짓이 된다.
   테스트가 스테이지를 오가면 `S.best` 는 **덮어써야** 한다.
2. **§5 시간 초과 루프(30초)를 돌리면 플레이어가 보스에게 맞아 죽어 있다.** 클리어 분기는
   `player.dead <= 0` 게이트를 타므로, 되살려 놓지 않으면 «규칙이 안 돈다» 가 아니라
   «사망 중» 을 재게 된다. **step 을 길게 굴린 다음의 측정은 부활을 먼저 확인할 것.**
