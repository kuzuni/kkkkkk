## §3 처방 — 자를 «제품이 실제로 산 것» 만 묻게 갈아 끼웠다

등재문 ⓐⓑ 그대로다. **`F` 를 530 으로 갈아 끼우는 길은 안 갔다** — 그러면 다음 813·866·879
회차에 똑같이 조용히 빨개진다.

- **§2** — 「여백 = 30」(= 「버튼 상변 = H − 566」 의 다른 얼굴)을 걷어내고 셋으로 갈랐다:
  ① 팝업 하변이 **클램프 산식**이 정하는 자리에 있는가 — `y2 = H − (X/2 − 369.5)`,
     X = 1931 ⇒ H − 596. 상수 596 을 손으로 적지 않고 `CROSS` 에서 푼다(407 은 X = 1801 ⇒ H − 531).
  ② 여백이 음수가 아닌가(전 구간 · §1 과 같은 축) · 최솟값 ≥ 2px.
  ③ 바닥 구간에서 **여백 ≥ 30** — 「=」 가 아니라 **하한**이다. `여백 = 596 − F` 라
     **버튼이 위로 올라와 420 이 확보한 30 을 도로 파고들 때만** 빨개지고, 멀어지는 이동에는 안 흔들린다.
  + 단언이 아닌 **관측 한 줄**(`· 관측 F = H − 버튼 상변 : 1600:530 · …`)을 찍는다 — 다음에 스택이
    걸으면 게이트가 빨개지기 전에 이 줄이 먼저 말한다.
- **§R** — 되돌림의 **대상**을 옮겼다. 「407 값으로 되돌리면 35px 겹친다」 는 스택 파생이라
  이미 안 물었다 ⇒ 「스코프 규칙을 지우면 ⓐ `#ciw` 하단 여백이 **407 식(234 + 1801 − H)** 으로
  떨어지고 ⓑ 팝업이 **정확히 (1931 − 1801)/2 = 65px** 내려온다」 로 갈았다(1600·1800 두 프레임).
  둘 다 **제품 CSS 를 직접 묻는 항등식**이라 세로 스택이 어디로 걷든 안 흔들린다.
  「가로 겹침 400(버튼 전폭)」 과 「라벨 잉크는 되돌려도 0%」 는 남겼다.
- **§N 신설(음성 시험)** — 완화가 **무르게 푼 수리가 아님**을 자기 자신으로 증명한다(334).
  `#rwBasin{position:relative;top:-40px}` 을 주입하면 여백이 66 → **26** 으로 떨어져 §2 ③ 이 물고,
  `-80px` 이면 §1 의 「겹침 없음」(세로 겹침 **14**)과 「부품 덮임 0%」(최댓값 **6.2%**)가 같이 깨진다.
  ⇒ 하한을 「≥ 30」 으로 푼 뒤에도 **진짜 결함 방향은 그대로 빨개진다.**
