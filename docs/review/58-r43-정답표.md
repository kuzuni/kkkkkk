# 58 r43 캡처 정답표 (cap58b.js — 강제 합성)

표본마다 페이지를 새로 열고 목표 시각까지 rAF 로 진행시킨 뒤 **rAF + CSS 애니메이션을 둘 다 얼리고** 찍었다.
«실제» 는 얼린 시각이며 목표와의 차이가 그 프레임 라벨의 오차다.

36회차 — 얼리기가 **세 겹**(rAF · CSS 애니메이션 · **타이머**)이 됐다. 종전 두 겹은 `setTimeout` 으로 도는
연출 노드 제거를 못 막아, 얼린 뒤 스크린샷까지의 300~600ms 동안 불꽃·코인이 계속 사라졌다(그림 < 표).
«얼림» 열은 얼린 뒤 40ms·160ms 두 번 읽은 census 가 같았는지다 — «고정» 이어야 표와 그림이 같은 순간이다.

**41회차 — 이 표의 개수는 «DOM 에 있는 노드» 가 아니라 «보이는 노드»(불투명도 ≥ 0.06 · 화면 안) 다.**
40차 두 비평가가 «표에는 있는데 그림에 없다» 를 2인 공통으로 낸 자리를 닫은 것이다 — 퇴장 페이드의
마지막 한 뼘과 타이머 지연이 종전 표에서는 «있다» 로 찍혔다. «유령» 열이 그 차이(= 안 보이는데 DOM 에
있는 노드 수)이며, 0 이 아니어도 **그림이 맞다** — 표를 그림에 맞춘 것이지 결함을 감춘 것이 아니다.

**42회차 — 여기에 «렌더 크기 하한»(bbox 최소변 ≥ 12px)이 더해졌다.** 41차 BG 가 잡은 자리다:
착지 직후 `scale(.18)` 로 오므린 코인은 **불투명도가 1 인데 화면에 자국이 없다**(≈8px 이 목적지
알약 아이콘 밑에 깔린다). 그렇게 걸러진 개수는 «축소» 열에 남는다 — 유령 열과 같은 원칙이다.
