## §1 재현 — 등재문이 그대로 확인됐다 (338 규칙)

`tools/probe522.js` 를 신설해 **제품에게 직접 물었다**(`PROBE522 PASS — 6/6`).

- **ⓐ** `openProbInfo('weapon', 75)` 는 만렙 50 아래에서 **MAX 로 튕긴다.**

  영영 거짓. 실측 `단계=MAX · 불멸행=true`.

⇒ **뿌리는 «기대값이 틀렸다» 가 아니라 «만렙을 손으로 적었다»** 다. 115 당시 만렙은 100 이었고,

## §2 처방 — 숫자를 제품의 표에서 역산한다

LESSONS 106-1 «만렙을 손으로 적지 마라» · 496 이 `verify106` F5 에 쓴 것과 같은 처방.

### ② «불멸 해금 단계»

두 항이 **정말 묻던 것**은 «불멸이 열리는 그 레벨에서는 아직 `t=0` 이라 행이 없고, 초월은 이미
나와 있다» 다. 그 레벨을 제품의 표(`rollOf('weapon')` = `GRADE_ROLL_EQ`)에서 읽는다.

```js
const R = rollOf('weapon');
const immU = R[R.length - 1].unlock;   /* 불멸(최고 등급) 해금 = 49 */
const trU  = R[R.length - 2].unlock;   /* 초월 해금 = 40 */
openProbInfo('weapon', immU);
```

판정에 **496 이 규칙으로 못박은 조항**을 한 항 더 얹었다 — `immU === SUM_MAXLV − 1`
(«불멸은 만렙 직전 1레벨 램프» — 18014 주석·18048 선언). 이유는 §3 ⓓ 에 있다.

### ⑩ 세이브 왕복

`S.sum.weapon.lv = SUM_MAXLV` 로 **합법 값**을 저장하고 `lv === SUM_MAXLV` 를 기대한다.

### 같은 병의 나머지 두 자리 — 같이 고쳤다

`fnchk115.js` 안에는 만렙 100 이 **네 자리**에 박혀 있었다. ②⑩ 만 고치면 나머지 둘은
«다음에 만렙이 100 을 넘는 날» 조용히 뜻을 잃는다.

| 자리 | 옛 값 | 새 값 |
|---|---|---|
| 상태 주입 | `S.sum[b].lv = 100` | `SUM_MAXLV` |
| ② 단계 이동 | `openProbInfo('weapon', 75)` | `rollOf` 에서 역산한 `immU` |
| ③ MAX 이동 | `openProbInfo('weapon', 100)` | `SUM_MAXLV` |
| ⑧ 펫 MAX | `openProbInfo('pet', 100)` | `SUM_MAXLV` |
| ⑩ 왕복 | `lv = 100` · 기대 100 | `SUM_MAXLV` · 기대 `SUM_MAXLV` |

파일 머리말에 «만렙을 이 파일에 손으로 적지 마라 — 522 가 그래서 썩었다» 를 남겼다.

## §3 무르게 푼 수리가 아니다 — `probe522` 6/6

등재문의 경고(«숫자만 갈아 끼우지 마라»)에 더해, 새 판정이 **성질을 깨면 실제로 빨개지는지**를
직접 물었다. 제품은 한 줄도 안 고치고 페이지 안 임시 변조로만 흔들었다(ⓔ 에서 원복).

| 항 | 무엇을 물었나 | 실측 |
|---|---|---|
| ⓐ | 옛 ② 의 «Lv75» 가 만렙 50 아래에서 무엇으로 읽히나 | `단계=MAX · 불멸행=true` (옛 기대 «75»·false) |
| ⓑ | 옛 ⑩ 의 «lv=100» 이 어디서 깎이나 | `live=100 → 재로드 50` |
| **ⓒ** | 불멸 해금을 만렙−1 → **만렙−3** 으로 밀면 새 ② 는? | **빨강**(`새 판정=false`) |
| **ⓓ** | 램프 조항을 뺀 **무른** 판정은 같은 변조에서? | **초록**(`무른 판정=true`) |
| ⓔ | 원복하면 새 ② 는? | **초록**(양성항) |
| ⓕ | 만렙 아닌 Lv43 왕복(양성) · «만렙으로 올림» 상태(음성) | `재로드 43` · `고장 모사 50` |

⚑ **ⓓ 가 이 작업의 교훈이다.** «불멸 행 없음 · 초월 행 있음» 만 보는 판정은 해금 레벨을
어디로 옮겨도 **항상 초록**이다 — `p0 = 0` 이라 해금 시점 `t = 0` 은 어떤 레벨에서든 0 이기
때문이다. 그 판정만 남겼으면 **«② 가 통째로 사라져도 초록인 게이트»** 가 됐다(328·329 가
`verify166` 에서 겪은 것과 같은 꼴). 램프 조항(`immU === SUM_MAXLV − 1`)이 그것을 막는다.

⚑ **⑪ 을 신설한 이유도 같다.** ⑩ 이 **만렙만** 왕복하면 «`load()` 가 무조건 만렙으로 올린다»
는 고장과 구별되지 않는다 — 실제로 옛 ⑩ 은 100 을 넣어도 만렙이 나왔고, 그 상태에서
«만렙 유지» 로 기대를 바꿨으면 그 고장이 통째로 숨는다. 만렙이 아닌 합법 레벨(만렙−7 = 43)을
넣어 **그 값 그대로** 돌아오는지 묻는 항을 짝지었다.

## §6 다음 세션이 볼 것

- **`S.sum[b]` 는 496 이후 «별칭 뷰» 다**(19174~19191). `S.sum.weapon.lv = X` 는 곧 `S.sumLv = X`
