# 1003 — `verify989` [R2] 가 «구운 사본» 때문에 축을 못 가른다 (T1 게이트 부패)

> 1회차 · 2026-09-06 · sess-1713-18688 루틴 워커 A · **제품 `index.html` 0줄** · 자 2파일

## 0. 한 줄

«989 직전 사본» 을 **오늘 트리 + 한 줄 되돌림**으로 굽던 것을 **고정 SHA(`534fce3`)에서 꺼내는 것**으로
바꿨다. 그러면 두 눈금이 **한 트리**를 재므로 축이 정확히 하나다(376-④). `verify989` **9/10 FAIL → 11/11 PASS**.

## 1. 재현 (공짜다 — 한 줄)

```
node tools/verify989.js      →  9/10 FAIL   ([R2] 하나)
```

```
FAIL [R2] … 989 직전 트리에서 옛 눈금(본체만)은 «밖 1종» 으로 초록인데 …
```

등재문이 적은 그대로다 — [R2] 는 `b.bad.length === 0 && o.bad.length >= 3` 을 묻는데
**옛 눈금 쪽도 밖 1종**(`bounce:218.7` · 중앙값 145)이라 «초록↔빨강» 대조가 성립하지 않는다.

**내 변경 몫이 아님은 착수 전에 확인했다** — 등재자(sess-1643-4006)가 `git stash` 대조로 이미 못박아
뒀고, `verify989` 는 `path`·`fs`·`pwlaunch` 셋만 `require` 한다.

## 2. 뿌리 — 사본이 갈라졌다 (실측)

1회차의 사본은 이랬다:

```js
const NEG_SC = …;                       // 오늘 트리를
fs.writeFileSync(NEG_SC, killLine(src, TAG_SC, PRE989));   // SHOT_SC 한 줄만 되돌려 굽는다
```

**등재 당시엔 그것이 정확히 989 직전 트리였다.** 실측으로 확인했다 — `534fce3:index.html` 의
`SHOT_SC` 는 `PRE989` 상수와 **글자까지 같다**:

```
534fce3  const SHOT_SC = { arc: 1.18, rock: 1.15, moon: 1.27, arrow: 0.89, ball: 0.89,   rockfall: 0.93 };
PRE989   const SHOT_SC = { arc: 1.18, rock: 1.15, moon: 1.27, arrow: 0.89, ball: 0.89,   rockfall: 0.93 };
HEAD     const SHOT_SC = { arc: 1.18, rock: 1.15, moon: 1.27, arrow: 0.89, ball: 0.647, rockfall: 0.683, fire: 0.733, bottle: 0.734 };
```

**갈라진 것은 배율표가 아니라 그림이다.** 989 이후 `index.html` 이 +347/−61 줄 바뀌었고,
그중 **981 5회차(«도약탄 두 마디 → 세 마디 지그재그»)** 가 `bounce` 의 형상을 갈았다.
그래서 «오늘 그림 + 옛 배율» 이라는, **어느 시점에도 존재한 적 없는 트리**가 구워진다:

| 종 | 진짜 989 직전(534fce3) 본체 대각 | 구운 사본 본체 대각 |
|---|---|---|
| `bounce` | 168.4 | **218.7** |
| `whirl` | 172.5 | 157.7 |
| `curve` | 116.8 | 134.7 |

`bounce` 하나가 밴드(중앙값 145 ±25% = 108.8~181.3) 밖으로 나가면서 [R2] 의 «옛 눈금은 초록» 이
깨졌다. 다른 둘은 아직 밴드 안이지만 **다음 그림 변경이면 같은 자리에서 또 깨진다** — 이 사본은
구조적으로 썩는다.

## 3. 처방 — 굽지 말고 꺼낸다 (등재문 후보 ⓐ)

등재문이 준 두 후보 중 **ⓐ(고정 SHA 사본 · `gitrev756` 사다리)** 를 골랐다.
ⓑ(«옛 눈금이 새 눈금보다 무르다» = 밖 종 수 견줌)를 안 고른 이유는 등재문 자신의 ⚠ 다 —
이 항이 지키는 것은 «[E1] 의 초록이 **눈금이 만든 것**이었다» 는 989 의 근거 자체이고,
개수 견줌은 «초록↔빨강» 을 «많고 적음» 으로 무르게 바꾼다.

⚑ **ⓐ 는 «축 하나» 를 오히려 더 정확히 지킨다.** 지금 [R2] 는 **한 트리(534fce3)** 를
두 눈금으로 잰다 — 트리는 고정, 눈금만 바뀐다. 구운 사본 쪽은 트리도 눈금도 같이 움직이고 있었다.

```js
const PRE_SHA   = '534fce3dec0874b7a7624f56b84cffa80cbad5b5';   // claim(989) 의 부모
const PRE_SINCE = '2026-09-05';                                  // 사다리 첫 칸(날짜)
const pre = G.show(PRE_SHA, 'index.html', { since: PRE_SINCE });
```

**얕은 클론에서도 판다** — 실측: `git clone --depth=1` 한 새 클론에서
`--shallow-since=2026-09-05` 한 칸으로 **5.8초 · 이력 385커밋**을 받아 표본을 꺼냈다.
못 팠을 때는 756 규약 ② 대로 갈린다 — **얕으면 ⏸ 보류(세지 않는다)** · 안 얕은데 없으면 **빨강**.

## 4. «무르게 푼 수리가 아니다» — [R2b] 신설 (되돌림 시험)

수리의 근거를 말로만 두지 않았다. **[R2b] 가 옛 사본을 매 실행 다시 굽고, 그것으로는 축이 안
갈린다는 것을 스스로 증명한다**:

```
ok [R2b] 1003 — 구운 사본(오늘 트리 + SHOT_SC 한 줄 되돌림)으로는 축이 안 갈린다:
   그 사본은 옛 눈금(본체만)으로도 밖 1종 (bounce:218.7 · 중앙값 145) 이라 [R2] 의 «초록↔빨강» 이 없다
   · 진짜 989 직전 트리와 본체 대각이 어긋난 종 3종 (curve 116.8→134.7 · whirl 172.5→157.7 · bounce 168.4→218.7)
   ⇒ 사본은 굽지 말고 고정 SHA 에서 꺼낸다
```

즉 **되돌리면(고정 SHA 를 버리고 사본을 도로 구우면) [R2] 가 그 자리에서 다시 빨개진다.**
그 사실이 자 안에 수치로 남아 있으므로, 다음 워커가 «왜 SHA 를 박았나» 를 다시 물을 필요가 없다.

## 5. 이관 — 접는 산수 사본과 `verify1001` [C1] 인구조사

등재문의 마지막 ⚠(«995 뒤 이 자만 아직 옛 이름 `DIAG_TOL`·옛 눈금(대각)을 쓴다 — 같이 볼 것»)도 닫았다.

**둘로 갈라서 답이 다르다:**

1. **접는 산수(사본)는 걷어냈다.** `verify989` 의 인라인 `outBand` 를 998 부품
   `B998.band(rows, DIAG_TOL, key)` 로 넘겼다 — 989·995·998·1001 이 네 번 고친 그 사본의 마지막 자리다(402).
   그 결과 `verify1001` [C1] 인구조사가 «사라진 자 verify989.js» 로 빨개져
   **ALLOW 목록에서 989 를 뺐다**(이관 · [C1] 5자 → 4자 · [R2] 도 같이 초록으로 복귀).
   허용 목록은 «있어도 된다» 가 아니라 **«있다» 를 세는 자**라, 안 접는 자가 목록에 남으면 그것이 곧 거짓이다.

2. **열쇠(대각)는 안 바꿨다 — 바꾸면 이 항이 죽는다.** 실측이 그것을 결정했다.
   진짜 989 직전 트리를 995 의 눈금(**최대 변**)으로 접으면:

   | 접는 법 | 989 직전 트리 본체 밖 | 989 직전 트리 제손 밖 | (참고) 오늘 트리 제손 밖 |
   |---|---|---|---|
   | 대각 (989 의 열쇠) | **0종** | **3종**(boom·meteor·flask) | 0종 |
   | 최대 변 (995 의 열쇠) | 5종 | 7종 | 5종 |

   최대 변 밴드는 792 가 `SHOT_SC` 로 **아직 닫는 중인 절대 밴드**라(오늘 트리도 밖 5종 = `verify792` [E1] 31/32)
   그 눈금에서는 «초록↔빨강» 대조가 **어느 트리에도 없다**. 989 의 축은 «본체만 ↔ 본체+제 손 부품»
   **한 가지**이고, 그 축이 서는 접는 법이 대각이다. ⇒ 열쇠는 대각, 산수는 부품.

## 8. 곁다리 등재 1건 — 1004

`probe989` 가 **4/7 FAIL** 이다([2]·[4]·[5]). 989 리뷰는 완료 줄에 «`probe989` 7/7 신설» 로
적혀 있는데, 그 7/7 은 **수리 전 트리에서 재현하던 값**이고 이 자는 «지금 트리» 만 잰다
(`require` 는 `path`·`pwlaunch` 둘뿐 · 사본을 안 굽는다). 989 가 결함을 고친 뒤로는
[2]«R60 이 자른다» · [4]«상자를 키우면 판정이 뒤집힌다» · [5]«제손 눈금이면 밖 0종이 아니다» 가
**구조적으로 서지 않는다** — 즉 영원히 빨강이다(573 «`probe566` [4-a] 영원히 빨강» 과 같은 꼴).

**내 변경 몫이 아님을 확인했다** — 내가 만진 두 파일(`verify989.js`·`verify1001.js`)을
`probe989` 는 한 줄도 안 읽는다(`require` 둘 다 아님) · `index.html` **0줄**.

처방은 이 행이 방금 쓴 것과 같다 — **재현 대상을 고정 SHA(`534fce3`)로 박거나**, 아니면
«수리 전↔수리 후» 두 판을 한 실행에서 재서 «뒤집힌다» 를 묻는 꼴로 바꾼다. 지시서 [1]
«잡은 작업 단위 딱 1개» 라 손대지 않고 등재만 했다.

## 9. 교훈 (LESSONS 1003)

① **«한 줄 되돌림» 사본은 등재한 날에만 맞다.** 그 한 줄 말고 다른 것이 안 변한다는 보장이
   어디에도 없으므로, «수리 전 트리» 가 필요하면 **커밋을 박아라**(756 사다리가 얕은 클론을 판다).
② **되돌림은 «한 트리 · 두 눈금» 이어야 축이 하나다**(376-④). 사본을 구우면 트리도 같이 움직여
   축이 둘이 되고, 그 둘째 축은 **남이** 움직인다(여기서는 981 의 그림 변경).
③ **눈금을 최신으로 맞추는 것이 늘 옳지는 않다.** 995 가 [E1] 을 최대 변으로 갈았지만, 989 의 축은
   최대 변에서 **초록↔빨강이 아예 없다**(둘 다 빨강). 열쇠는 «최신» 이 아니라 «그 축이 서는 것» 으로 고른다.
④ **접는 산수와 열쇠는 다른 물음이다.** 산수는 부품 한 벌(998)로 모으고, 열쇠는 자마다 자기 축으로 고른다 —
   그 둘을 한 덩어리로 보면 «부품을 쓰려면 열쇠도 남을 따라야 한다» 는 잘못된 결론이 나온다.
⑤ **허용 목록은 «있다» 를 센다.** 사본을 걷어내면 그 자를 **목록에서도 빼야** 한다 —
   안 빼면 [C1] 이 «사라진 자» 로 빨개진다(정리가 게이트를 깨는 자리 · 286 선례와 같은 꼴).
