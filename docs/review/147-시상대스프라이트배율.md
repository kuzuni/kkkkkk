이번에 같은 방식(`tools/scan147.py`)을 다시 돌려 보니 **재현되지 않는다** — 2위만 165 가 나오고
**1위·3위는 스캔 시작행(40)이 그대로 나온다.** 원인은 씬 배경이 균일한 남색(22,22,32)인데도
단상 x 구간 안에 **어두운 기둥·홀 배경·방패 워터마크** 같은 «배경 아닌 배경» 이 있어 행이 통째로 임계를 넘기 때문이다

## 7. 남은 문제 — 다음에 54 를 잡는 세션이 볼 것

1. **1위 ref 높이가 11회차 값과 31px 어긋난다.** 11회차 «ref ≈275»(→ sc6, Δ−2%) vs 이번 A·B 실측
   **244±2**(→ sc6 은 Δ+11%). 이번엔 **단상 사이 비율**(§5-2)을 근거로 sc6 을 유지했다.
   54 를 다시 잡는 세션에서 비평가 두 명이 «1위가 크다» 로 갈리면, `tools/verify147.js` 의 `SPEC`
   1위 행(`sc:6, ink:178, body:202`)을 sc5(`ink:223, body:248`)로 바꾸고 c1 상자를 288×230 으로 줄이면 된다.
   **그 경우 2·3위도 같이 내려야 비율이 유지된다** — 한쪽만 움직이지 마라.
2. **가로.** 우리 스프라이트는 단독 기사(폭:높이 ≈ 0.98:1)고 ref 는 탈것을 낀 가로 덩어리(1.21~1.42:1)다.
   같은 높이에서 폭이 ref 의 70~85% 수준이라 «면적이 작다» 는 지적은 **배율로는 회수 불가**다 —
   아트 리소스(탈것 포함 일러스트)가 들어와야 닫힌다. **«보류(아트 대기)» 축이지 배율 축이 아니다.**
   ref 의 «사람» 3명은 셋 다 **발이 탈것에 가려 안 보이는 2~3등신 치비**(A·B 일치)라, 우리 단독 기사와는
   실루엣 자체가 다르다. 이 차이를 CSS 로 좁히려 하지 마라.
3. 3위 ref 는 접지가 단상 윗면 앞모서리(ref 576)가 아니라 **먼 모서리(ref 551.8, 프레임 468)** 다 —
   잠수함 바닥이 거기에 0px 로 맞물린다(B 실측이 측정표 §3-1b 와 일치). 우리는 491 에 붙어 있다.
   ~23px 차이라 이번엔 손대지 않았다(발밑 앵커를 바꾸면 `verify80` B2·`verify147` B1 이 같이 움직이고,
   80 의 «발밑 = 단상 윗면» 규칙 자체를 3위만 예외로 두는 설계 변경이 된다).

## 8. 곁가지 — `verify95` 의 간헐 FAIL 은 147 탓이 아니다

최종 게이트 회차에서 `node tools/verify95.js` 가 한 번 **FAIL 1건**(«관성 없음 — 뗀 직후 360 → 360»)을 냈다.
147 의 변경(`.rk-ch` 기하 + `rkPodDraw` 배율)은 스크롤과 무관하지만, 짐작으로 넘기지 않고 **대조 실험**을 했다 —
`index.html` 을 147 이전 커밋(`5a067d3`)으로 되돌려 4회 돌렸더니 **2회 FAIL / 2회 PASS**,
147 적용본은 4회 중 **1회 FAIL / 3회 PASS**. **147 이전부터 있던 간헐 결함**이다(비율도 더 나쁘지 않다).

이 파일 범위 밖이라 고치지 않았다. 95 를 잡는 세션이 «관성» 항목의 시간 기준을 볼 것 —
`뗀 직후` 표본이 관성 첫 프레임보다 먼저 찍히면 360 → 360 이 나온다(135·142 와 같은 «시간을 잘못 재는» 계열).
