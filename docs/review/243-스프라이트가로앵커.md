## 2. 고친 것 — `index.html` 한 곳(공용 `drawFrame`·`drawFrameC`)

등재문의 처방(「잉크 중심 오프셋을 그리기 전용 `xo` 로 뺀다」·「`e.x`·판정 반경·AI 는 절대 건드리지
마라」)을 그대로 따랐다. 178 의 `yo` 규약과 같은 모양이다.

```
const xo = frameXo(key, A)[frameName] || 0;
… ctx.drawImage(src, …, (-fr[6]/2 + fr[4] + xo)*scale, …)
```

**설계 결정 3개** (전부 실측으로 갈랐다):

### ① 기준은 «캐릭터마다 하나» — 아틀라스 통짜도, 애니마다도 아니다

- **통짜(아틀라스당 상수 1개)로 잡으면** elves 한 장에 든 blue/green 두 캐릭터 중 한쪽이 밀린다
  (blue `xo` +63.0 vs green −72.5 → **135.5 논리px** 차이).
- **애니마다 잡으면** 애니 «사이» 의 진짜 움직임이 지워진다. 기사 `attack_B` 0프레임은 `idle` 보다
  5 논리px 앞으로 내밀고 시작하는데, 애니 기준이면 그 내지름이 0 으로 깎인다.
  더 나쁜 예: elves `die` 는 «옆으로 쓰러지는» 애니라 0프레임(서 있음, +71.5)에서
  마지막 프레임(누움, −0.5)까지 잉크 중심이 72px 움직인다. 애니 기준이면 **쓰러지는 순간 몸이
  통째로 옆으로 순간이동**했다가 눕는다 — 실제로 애니 기준 시안을 돌려 보고 잡았다(green_die_4 가
  −0.544 로 튀었다).

→ **논리 칸(`fr[6]×fr[7]`)이 같은 애니 = 같은 캐릭터**로 묶는다. 원본 시트가 다르면 칸이 다르다:

| 아틀라스 | 논리 칸 | 상수 `xo` | 애니 |
|---|---|---|---|
| knight | 79×63 | **+12.5** | attack_A/B/C · die · fall_loop · get_hit · guard · guard_end · guard_start · **idle** · jump_loop · jump_start · run |
| elves | 235×138 | **+63** | blue_attack · blue_die · **blue_idle** |
| elves | 265×134 | **−72.5** | green_attack · green_die · **green_idle** |
| elves | 32×32 / 60×11 | 0 / 0 | blue-missile / green-missile |
| zombie | 256×251 | **−14.5** | **walk** |
| zombie | 352×466 | 0 | Death |
| bird | 108×103 | +3 | **anim** |
| robo | 300×256 | **−20** | **Running** |
| dragon 96×64 · boom 64×64 | | 0 | fly / boom |

묶음의 기준 애니는 «서 있는 자세»(`idle` → `walk` → `run` → `fly` → `anim` 순, 없으면 첫 애니).
좀비 `walk` 와 `Death` 가 정확히 갈리는 것이 이 규칙이 맞다는 증거다 — 좌표계가 아예 다른
(256×251 vs 352×466) 서로 다른 원본 시트라 묶으면 안 된다.

### ② 보정은 `ctx.scale(-1,1)` **뒤** 좌표에 더한다 — flip 부호가 저절로 맞는다

등재문은 «`flip` 일 때 부호를 뒤집는다» 고 적었는데, 그것은 보정을 **앵커 `x` 쪽**(translate 전)에
걸 때의 이야기다. `drawImage` 의 dx 에 넣으면 뒤집힌 공간의 0 이 월드에서도 0 이라 부호 분기가
아예 필요 없다. 79·80 `drawHeroTo`(index.html ~13742)와 163 로딩 씬(`ldDraw`, ~13103)이 이미
같은 자리에서 같은 식(`c0`)을 쓰고 있었다 — **그 두 곳이 이 병을 각자 혼자 고치고 있던 선례**라,
식을 공용으로 올린 것이 이 작업이다. (두 곳은 `drawFrame` 을 안 지나므로 손대지 않았다.)

### ③ «그림자를 그림에 맞출지, 그림을 그림자에 맞출지» — 등재문의 주인 판단 항목

등재문의 처방(「그리기 전용 `xo` 로 빼되 `e.x`·판정 반경·AI 는 절대 건드리지 마라」)대로
**그림을 그림자에 맞췄다.** 바뀌는 것은 «그려지는 자리» 하나뿐이라 접지·히트박스·깊이 정렬·AI 는
한 줄도 안 바뀐다(게이트 §3·§5 가 이것을 잰다). 반대 선택(그림자를 그림 쪽으로 옮기기)은
`e.x` 를 기준으로 도는 발밑 접지·HP바·재화 연출 발원까지 전부 따라 옮겨야 해서 훨씬 넓다.

## 4. 남긴 것

- 잔차가 남는 아트 3종(**dragon ±0.008 · boom ±0.015 · 미사일 2종 ±0.005**)은 앵커 문제가 아니라
  **PNG 자체에 비대칭 투명 여백이 구워져 있는 것**이다(트림이 `ox=0`·논리 칸 = 잉크 칸). 배율을
  키워도 비율이 안 커지므로 아트 교체 때 같이 정리할 항목이지, CSS·코드로 밀 자리가 아니다.
- **새 아틀라스를 넣을 때**: 애니 이름에 `idle`/`walk`/`run`/`fly`/`anim` 중 하나가 들어가면
  그것이 «서 있는 자세» 기준이 된다. 안 들어가면 그 묶음의 첫 애니가 기준이므로, 공격·사망만
  있는 아트를 넣으면 기준이 엉뚱해질 수 있다 — `node tools/verify243.js` §0 표를 보고 확인할 것.
