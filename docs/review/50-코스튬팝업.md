## 1. 무엇을 만들었나

**기존 «아바타» 기능(다이아 구매 · 보유 효과 영구 합산 · 외형 변경)을 영웅 서브탭 «코스튬» 으로 이관**했다.
게임 로직·저장 구조(`AVATARS` · `S.avatar` · `S.avatars` · `bonus()` 의 아바타 합산 · `buyAvatar()`)는
**한 줄도 바꾸지 않았고**, 표시 위치와 껍데기만 07 스킬 바닥 시트 구조로 옮겼다.

| 구간 | 내용 |
|---|---|
| `#bCos` (신규 `.body`) | 07·26 과 같은 바닥 시트. CSS 는 기존 `:is(#bSk,#bPet)` 규칙 셀렉터에 **`#bCos` 를 추가**해 공유(신규 CSS 규칙은 `.sk-card.sel` **한 줄**뿐) |
| `renderCos()` | 헤더 «코스튬» + 착용 슬롯 1칸 + 그리드 5×3 + 총 보유 효과 + [착용]/[구매] + 서브탭 바 |
| `showCosDetail(id)` | 08 스킬 세부 팝업 껍데기(`.sk8`) 재사용 — 등급·가격·보유 효과 + [착용]/[구매] |
| `wearAvatar(id)` | 외형 변경(구매는 기존 `buyAvatar()` 그대로) |
| `subTabs(cur, attr)` | 07·26·50 이 픽셀 동일한 서브탭 바를 만들던 3벌 복붙을 **한 곳으로 합쳤다** |
| 서브탭 4칸 | 잠금 «기타»(🔒) 폐기 → **`장비 · 스킬 · 코스튬 · 동료`**. `06 .eqtb` · `07 .sk-tab` · `26 .sk-tab` **세 곳을 한 번에** 교체(인계 메모대로) |
| 구버전 폐기 | 상점 패널 `renderShop()` 의 «👤 아바타» 섹션 + `[data-av]` 핸들러 **제거**(LESSONS 57-①) |
| 레드닷 이관 | «살 수 있는 코스튬 있음» 레드닷을 **상점 탭 → 영웅 탭**으로 옮김 |

### 서브탭 «순서» 판단 (기록)

인계 메모(PROGRESS 50 · UI-REFERENCE 설계 확정 16)는 «**4번 칸**(기타 🔒)을 코스튬으로 바꿔라» 인데,
같은 지시서가 세 곳(설계 확정 16 · §6 · §7)에서 순서를 **`장비 · 스킬 · 코스튬 · 동료`** 로 못박았다.
둘이 충돌하므로 **명시된 순서 쪽을 따랐다** — 코스튬을 3번 칸, 동료를 4번 칸으로. 결과적으로
«4번 칸의 잠금 기타 폐기» 도 같이 만족한다. 바 기하(셀 경계 71/291/552/780, 폭 224/261/223/229,
구분선 `.sk-tsep` x704)는 **1px도 안 바꿨다** — 라벨과 `data-*` 만 이동했다.

## 5. 다음 세션에 넘기는 것

   들어오면 `.sk-si`(115×115) · `.sk-ci`(168×171 카드 안 96 높이) 자리에 그대로 얹으면 된다. 표는 `docs/measure/50-코스튬.md`.
2. **`#herosub`(구버전 파란 서브탭)** 은 세 시트 전부에서 `display:none` 이라 화면에 안 나오지만 DOM 에는 남아 있고,
   라벨이 아직 `장비·스킬·동료` 3개다. 폐기 대상이지만 **50 구간이 아니라 손대지 않았다**(LESSONS 57-② 참고 — 렌더 여부는 실측 필요).
3. **`.eqtc.on` 선택 알약(폭 260)이 4번 칸에서는 바 밖으로 23px 나간다** — 실측(4칸에 차례로 `.on` 을 붙여 측정):
   1번 −700 · 2번 −451 · 3번 −214 · **4번 +23**(바 오른쪽 기준). 1번은 `left:-12` 로 왼쪽으로 나가도록 설계된 것이고
   오른쪽 끝 칸에는 그 대칭 보정이 없다. **지금은 드러나지 않는다** — `.eqtb` 는 `#eqw`(장비 화면)에서만 보이고
   그때 `.on` 은 항상 1번 칸이라, 4번 칸이 `.on` 인 상태가 렌더되지 않는다. 06 서브탭 바를 다시 손대는 세션이 처리할 것.
