## 처방 — 규칙을 «지키기 쉽게» 가 아니라 **어길 수 없게**

### ⓐ `tools/claim.js` — 선점 절차를 코드로

```
node tools/claim.js <ID> <SID>              선점(또는 90분 죽은 lock 회수)
node tools/claim.js --beat    <ID> <SID>    heartbeat(파일만 — 회차 커밋에 같이 담는다)
node tools/claim.js --release <ID> <SID>    해제(삭제 + 커밋 + push)
node tools/claim.js --check   <ID> <SID>    판정만(파일·커밋 없음)
```

종료 코드로 답한다 — **0 = 내 것** · **2 = 남이 잡았다(포기하고 다음 작업으로)** · 1 = 오류.

핵심은 **덮어쓸 경로를 아예 없앤 것**이다:

- push 거부 → `pull --rebase` → **충돌 파일이 내 `<ID>.lock` 이면 그 순간 경쟁 패배**로 확정하고
  `rebase --abort` + `reset --hard origin/main` 후 코드 2 로 나간다. 워커가 «내 쪽으로 풀지» 를 고를 수 없다.
- rebase 가 **깨끗이** 끝났어도 lock 내용이 내 SID 가 아니면 같은 처리(ROUTINE [-1] 4 후단).
- 죽음 판정은 **lock 시각과 마지막 `wip(<ID>)` 커밋이 둘 다 90분 초과**일 때만(lock 갱신을 빼먹었지만
  커밋은 계속 올리는 세션은 살아 있다). `--grep 'wip(<ID>)'` 로 본다.
- `--release` 는 **내 SID 의 lock 만** 지운다. 남의 lock 은 코드 2 로 거절한다.


C4 를 같이 재는 이유: 90분 회수는 **살아 있어야 하는 기능**이다. «못 덮게» 만 조이면 죽은 세션의 lock 이
