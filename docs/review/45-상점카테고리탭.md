## 2. 좌표 근거

- 패딩박스 = 990 − 테두리 2×7 = **976** → 칸 **488**. 재화 탭은 테두리 5라 980 → 칸 **490**.
- ✦ `left:485` 는 **레퍼런스 4탭 바의 «가운데 ✦» 실측치**다. 4칸의 가운데 경계 = 2칸의 유일한 경계이므로
  좌표를 새로 만들 필요 없이 그대로 쓴다(실측 유지 = 지시의 «✦ 구분선 규격 유지»). 기하 중심(488)과는 4.5px 차인데,
  이는 레퍼런스 3개 ✦(251/485/741)가 전부 기하 경계보다 ~3.5px 우측인 것과 일관된다 — 실측을 따랐다.
- 알약은 **크기만 실측 유지**(250×79 / 256×76)하고 위치는 칸 중앙으로 새로 잡았다. 지시가 «균등 배치»이고,
  옛 `left:-8` / `left:1` 은 칸 폭 244 를 전제한 값이라 488 칸에서는 의미가 없다.

> **13 측정표 §8 «알약이 바 우측으로 7px 돌출» 은 이제 성립하지 않는다.**
> 4칸일 때 칸 폭 244 에 알약 256 이라 넘쳤던 것이고, 2칸(490)에서는 넘칠 이유가 없다.
> 13 을 다시 채점할 일이 있으면 이 항목을 감점 사유로 쓰면 안 된다(우리 설계 변경의 결과다).

## 3. 겸사로 고친 잔존 상태 버그

활성 알약은 **활성 탭 칸 안에 사는 DOM 노드**이고 클릭 핸들러가 `insertBefore` 로 노드째 옮긴다(13 이 도입).
그런데 `openShopPage()` 는 `shopCat='summon'` + `.on` 클래스만 리셋하고 **알약은 옮기지 않았다** —
재화 탭에서 상점을 닫고 다시 열면 «활성 라벨은 소환인데 노랑 알약은 재화 칸» 인 상태가 남았다.
탭 바가 45 의 작업 구간이라 같이 고쳤다(`openShopPage` 에 알약 복귀 3줄). verify45 [5] 가 이 경로를 잡는다.
