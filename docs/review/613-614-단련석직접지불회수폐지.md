## §1 경로도(착수 실측 — 등재 ①)

수리 전 단련 재화 경로는 **3단**이었다:

```
절망의 탑 rw(tstone) ──▶ S.tstone ──[temperCharge 1:1]──▶ S.temper.pts ──[temperUp]──▶ alloc(Lv)
                                                              ▲ [temperReset: 1000 dia 로 전액 환급] ┘
표시: 헤더 .pv «단련 포인트 n» + [충전 .cg] · 행 «n pt» · 회수 줄 .tp-ft [💎1000 회수]
기타 소비처: 13 광고 상품(a8, +50) · 53 가방 표기 · CURINFO — 전부 «잔액» 층이라 무관
```

수리 후 **1단**: `S.tstone ──[temperUp: 직접 차감]──▶ alloc(Lv)`. 죽은 자리 = 전환(temperCharge ·
TEMPER_PT_COST · .cg · data-tpchg · rtChargeHold) · 잔액(S.temper.pts) · 회수(temperReset(Ok/Btn) ·
TEMPER_RESET_DIA · temperSpent(All) · temperFootTxt · .tp-ft · data-tpreset). 산 자리(불변) = 비용 계단
(temperSegCost) · TEMPERS/TEMPER_EFF · temperVal/bonus() 합류 · 절망의 탑 수급 · 홀드(rtTemperHold).

- 등재문의 «주인 확인 대기 1건»(문장 끝 «강화» 의 범위)은 권장대로 **좁게** 잡았다 — 단련 탭의
  «강화 절차 = 전환 단계» 제거로 읽었고, 장비/일괄 강화는 손대지 않았다. 넓히는 쪽은 주인 확인 후.
