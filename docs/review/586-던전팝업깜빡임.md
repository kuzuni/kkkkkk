## 0. 한 줄

**«깜빡임» 이 아니라 «얼어 있음» 이었다.** 던전 탭을 눌러 페이지를 `display:block` 으로 켠 뒤에도
화면은 **아래 화면 그대로** 0.6~0.8초 멈춰 있다가 툭 바뀐다. 뿌리는 «켜지는 그 한 프레임이 너무
비싼 것» 이고, 두 조각을 걷어내 **얼어 있는 시간을 723ms → 272ms(계측 바닥 112ms 위로 611 → 160ms,
3.8배)** 로 줄였다. 제품 `index.html` **3자리**(CSS 2 + JS 1) · 레이아웃 Δ0px · 밸런스·판정 0줄.

## 1. 재현이 먼저 (338 규칙) — `tools/probe586.js` 신설

등재문은 후보를 여섯(ⓐ~ⓕ) 남기고 «갈래를 정하기 전에 고치지 마라» 고 못박았다. 그래서 먼저 쟀다.

### 1-1. 재는 자를 세우는 데만 두 번 헛디뎠다 — 그 자체가 이 작업의 교훈이다

| 시도 | 무엇을 봤나 | 왜 틀렸나 |
|---|---|---|
| `requestAnimationFrame` 로그 | 열기 직후 `jzPgIn` 의 `currentTime` 이 0 에 붙어 있다 | **스톨 구간이 통째로 «없는 시간»** 이 된다. rAF 가 안 도는 동안이 정확히 문제 구간이다 |
| `page.screenshot()` 폴링 | — | 이 화면에서 **한 장에 4,414ms** 가 걸린다(실측). 전환을 통째로 놓친다 |
| **CDP `Page.startScreencast`** | 합성기가 실제로 내보낸 프레임 | 이것만이 «화면에 무엇이 찍혔나» 를 본다 |

받은 jpeg 는 node 에 디코더가 없어 **다른 페이지의 캔버스로 되돌려** 읽는다(368 처방).
⚠ 그 페이지가 **배경 탭이면 `img.decode()` 가 EncodingError 로 즉사한다** — 전 프레임이 조용히
버려져 «프레임 0장» 이 나왔다. `onload` 로 받으면 같은 데이터가 그대로 읽힌다.

### 1-2. 축을 무엇으로 삼는가 — 여기서 처방이 갈렸다

탭 페이지는 딤이 없는 **불투명한 면**이라 열리는 동안 찍히는 것은 `F = α·page + (1−α)·old` 다.
그래서 α 를 최소제곱으로 역산한다: `α = <F−old, page−old> / |page−old|²`.

축은 **둘이어야 한다**. 하나로는 증상을 못 짚는다:

* **T_hold** = 켠 시각 → α ≥ 0.10 인 첫 프레임 = **화면이 아래 것 그대로 얼어 있는 시간**.
  주인이 «깜빡인다» 고 한 것이 이 구간이다.
* **T_show** = 켠 시각 → α ≥ 0.9 = 카드까지 다 칠해져 정착하기까지.

⚠ **T_show 만 보면 처방을 잘못 고른다.** 카드가 기준 프레임의 대부분이라 껍데기가 먼저 떠도
T_show 는 거의 안 움직인다(실측: 껍데기 249ms · 정착 546ms). 실제로 1차 처방을 T_show 로만 재고
«16% 개선» 이라 읽어 하마터면 «작은 개선» 으로 닫을 뻔했다.

⚠ **«α<0.9 인 프레임 «장수»» 를 축으로 쓰면 안 된다** — 페이드를 빼면 그 구간에 프레임이 아예
안 나온다(합성기가 새로 보여 줄 것이 없다). **장수는 줄고 화면은 그대로 멈춰 있다.**

### 1-3. 계측 바닥 — 0 을 요구하는 게이트는 못 짠다

등재문 게이트 ⑴ 은 «아래 화면이 비치는 프레임 **0**» 을 요구했다. **그 수는 달성 불가다.**
내용이 **없는** 불투명 면을 같은 사각(`0,104,1080,1996`)에 켜기만 해도 이 러너에서
**T_hold 112~138ms** 다. ⇒ 게이트는 절대 ms 가 아니라 **같은 실행에서 잰 바닥의 배수**로 묻는다.

## 3. 처방 — 제품 3자리

### ⓐ 여는 프레임을 «투명하게 붙들지» 않는다 (CSS 2줄)

```
- @keyframes jzPgIn{0%{opacity:0;scale:.985}35%{opacity:1}100%{opacity:1;scale:1}}
+ @keyframes jzPgIn{0%{scale:.985}100%{scale:1}}
+ @keyframes jzPgFade{0%{opacity:1}100%{opacity:0}}
- .jz-c.jz-pg{animation:jzPgIn .12s ease-in reverse both}
+ .jz-c.jz-pg{animation:jzPgIn .12s ease-in reverse both,jzPgFade .12s linear both}
```

12회차가 남긴 주석이 이미 «전체화면 페이지는 아래 화면을 **대체하는 면**이라 반투명 구간이 길면
안 된다» 고 적어 두고 불투명도를 앞 35%(**42ms**)에 몰아 놨다. **그 42ms 예산이 실측 최대 734ms
였다** — 예산은 «애니메이션이 제때 돈다» 를 전제하는데, 페이지가 켜지는 프레임은 그 인터랙션에서
가장 비싼 프레임이라 애니메이션 자체가 그때 못 돈다. ⇒ 여는 쪽은 **scale 만** 준다.

⚠ **닫는 쪽 페이드는 살렸다.** 닫기의 페이드는 «아래 화면을 되돌려 주는» 연출이라 뜻이 반대다.
`reverse` 로 얻어 쓰던 것을 자기 애니메이션으로 갈랐다 — `jzBoxOut`/`jzBoxFade` 가 **같은 이유로
이미 갈라져 있다**(한 곡선으로 두 속성을 못 낸다, 12회차 주석).

⚠ **이름을 `jzPgIn` 그대로 뒀다.** `tools/settle291.js` 가 `/^jz(Pg|Sheet)/` 로, `tools/neg221.js`
N5 가 선언 문자열 `  .jz-o.jz-pg{animation:jzPgIn .12s ease-out both}` 로 이 자리를 찾는다.
이름을 바꿨으면 게이트 44개의 정착 장치가 조용히 죽었을 것이다(`jzPgFade` 도 같은 정규식에 걸린다).

### ⓑ 여는 프레임에는 카드를 «칠하지» 않는다 (CSS 1줄 + JS 1자리)

```
#dunw.on:not(.warm) .dnc{visibility:hidden}
```
```
openDungeon()  … syncDunNav(true); pgWarm('dunw');
closeDungeon() … w.classList.remove('on', 'warm');
function pgWarm(id){ … requestAnimationFrame(() => requestAnimationFrame(() => …add('warm'))); }
```

⚑ **이것은 «빈 상자 한 프레임»(등재문 ⓑ 가 경계한 것)을 새로 만드는 게 아니다.**
카드는 어차피 60 쥬시의 스태거 `jz-st` 가 `0%{opacity:0}` + `--jzd` **60ms** 로 붙들고 있어
**처음 60ms 는 원래 안 보인다**(13226·37613). 여기서는 그 «안 보이는 구간» 을 **칠하지도 않게**
할 뿐이고 `.warm` 은 다음 프레임에 붙는다. 즉 화면에 나가는 그림은 한 장도 안 바뀐다.

⚠ **rAF 를 두 번 건다.** 한 번짜리 콜백은 «이번 프레임을 그리기 직전» 에 돌아서 클래스가 같은
프레임에 반영된다 — 미루는 효과가 **0** 이다. 두 번째 rAF 라야 «첫 커밋 다음» 이다.
⚠ **닫을 때 `.warm` 을 같이 떼야** 두 번째 열기부터도 효과가 난다(`verify586` [B5] 가 못박는다).
⚠ `content-visibility:hidden`(184ms)이 아니라 `visibility:hidden`(152ms)을 쓴다 — 전자는 크기
억제까지 같이 걸려 그 한 프레임에 리스트의 스크롤 높이가 접힌다.

## 7. 다음 세션이 볼 것

1. **탭 페이지가 «열리는 데 걸리는 시간» 을 재려면 T_hold 와 T_show 를 둘 다 찍어라.** 하나만
   보면 처방이 뒤집힌다(§1-2).
2. **«비치는 프레임 0장» 같은 게이트를 쓰지 마라.** 내용 없는 불투명 면조차 이 러너에서
   112~138ms 다. **바닥을 같은 실행에서 재고 배수로** 물어야 한다.
3. **캡처를 되돌려 읽는 페이지는 앞으로 내라**(`bringToFront`) — 그리고 `img.decode()` 대신
   `onload` 를 써라. 배경 탭에서 decode 는 EncodingError 로 전 프레임을 조용히 버린다.
4. **무거운 목록을 새로 다는 탭 페이지**는 CSS 의 586 블록에 한 줄 더할 수 있지만 **재고 나서**
   더해라 — 10 상점이 그렇게 해서 «더 나빠짐» 이 나왔다(§5).
