### ④ `data-why` → DOM 캡션 (지시서 ④)

비활성 버튼 사유(74 ④)는 **캔버스가 아니라** `jzWhy(el, txt)` 가 만드는 `.jz-why` 캡션으로 옮겼다.

- `#fxl`(z-index **60**) 안에 붙는다 → 모달(z **30**)·시트 위에 뜬다. 캔버스에 그리면 딤 뒤에 깔려 안 보였다.
- 흔들리는 버튼 **바로 위 12px**. 위가 좁으면(프레임 상단) **아래로 뒤집는다** — top 6px 버튼에서 캡션 top 123 실측.
- 좌우도 프레임 안으로 민다: 버튼 `left 0` → 캡션 x 24..512, `left 980` → x 958..1036. 둘 다 0..1080 안.
- `max-width:520px` + 줄바꿈이라 사유 문구가 길어도 안 넘친다.
- 버튼 흔들림(`jz-sh`)과 `sfx('err')` 는 그대로 둔다 — 60 쥬시 구간을 건드리지 않았다.

### ⑤ 연출 (지시서 ⑤)

페이드 인 **0.15s** → 유지 **1.0s** → 페이드 아웃 **0.3s** (총 1.45초. 옛 값은 «1.7초, 페이드 인 없음»).

## 3. 게이트 `tools/verify94.js` — 무엇을 어떻게 재는가

**98항목. 핵심은 «픽셀 차분»이다.** `measureText` 추정이 아니라 실제로 그려진 잉크를 잰다
(LESSONS 74-⑤ «잉크는 rect 가 아니다» · 100-① «bbox 는 히트테스트가 아니다» 의 같은 계열).

```
step = () => {}            ← 월드 정지
camUpdate = () => {}       ← 카메라도 정지 (loop 본문에 있어 step 스텁만으론 안 선다)
① msgT = 0 로 한 프레임 → base = getImageData
② showMsg(txt); msgT = <원하는 알파 지점> → 한 프레임 → cur = getImageData
③ |base − cur| > 20 인 픽셀의 bbox = **문구 잉크**
```

`getImageData` 는 `file://` 아틀라스에 오염되므로 `--allow-file-access-from-files` 로 띄운다(verify79·80 과 같은 이유).
**자기 검사** 항목을 하나 넣었다 — «문구 없음» 프레임 2장의 차분 픽셀이 **0** 이어야 한다.
같은 차분의 최대 |Δ| 로 알파 램프도 잰다(등장 직후 16 → 등장 중 90 → 유지 200 → 퇴장 중 90(45%) → 퇴장 끝 6).

## 4. 이 게이트를 만들며 두 번 고쳐 쓴 것 (다음 세션이 같은 데서 안 넘어지게)

1. **첫 음성 테스트에서 게이트가 FAIL 대신 통째로 죽었다** — `waitForFunction` 조건에
   **신설 심볼 `msgFit`** 을 넣은 탓에 옛 빌드에서 15초 타임아웃으로 종료됐다.
   109-③ 이 경고한 «깨진 빌드에서 죽는 게이트는 게이트가 아니다» 가 **대기 조건**에서도 그대로 재발한다.
   → 대기 조건은 «구·신 양쪽에 다 있는» 심볼(`showMsg`) 하나로 두고, 신설 심볼은
   `ev()` 래퍼가 «없으면 FAIL 한 줄» 로 바꾼다. 본문 전체를 `try/finally` 로 감싸 보고는 항상 찍히게 했다.
   덤: 폴백 객체를 돌려줄 때 **하류 접근자도 안전해야 한다**(`fit['200자'].t` 가 `{}` 에서 다시 죽었다).
2. **픽셀 하네스도 «옛 빌드에서 돌아야» 증거가 된다.** `MSG_DUR` 을 직접 쓰다가 음성 테스트에서
   `ReferenceError` 로 스킵됐고, 그러면 «옛 빌드는 글자가 밖으로 나간다» 를 픽셀로 못 보여 준다.
   구 빌드 값(1.7 · 페이드 인 0)으로 폴백을 두자 비로소 `L=0 R=0` 이라는 **직접 증거**가 나왔다.

## 5. 교훈 (LESSONS 로 옮길 것)

> **1. 캔버스 차분으로 «실제 잉크» 를 재려면 월드만 멈춰서는 안 된다 — `step` 밖에서 도는 것부터 찾아라.**
> `step` 을 스텁했는데도 짧은 문구의 차분 bbox 가 캔버스 전체(1080×1996 · 16.7만 px)로 나왔다.
> 범인은 `camUpdate(dt)` — `loop()` 본문에서 **`step` 과 나란히** 불린다. 카메라가 목표로 수렴하는 동안
> 배경이 통째로 흐르니 «문구 없음/있음» 두 프레임이 문구 말고도 달랐던 것이다.
> 긴 문구(80자)만 우연히 통과해서 «클램프는 되는데 짧은 것만 이상하다» 로 오독하기 딱 좋았다.
> → 차분 하네스에는 **«두 빈 프레임의 차분 = 0» 자기 검사**를 반드시 넣어라. 이 한 줄이 오독을 막는다.
> 그리고 시간 의존 그리기(오라 반경 `Math.sin(performance.now()/220)`)가 켜져 있으면 애초에 차분이 안 된다 —
> 게이트가 그 상태(`skillEquipped('aura')`)를 **먼저 단언**하게 해 둘 것.
>
> **2. 「없어도 되는 말」을 지울 때는 «그 정보를 이미 누가 보여 주는지» 를 코드로 확인하고 지워라.**
> 파밍·클리어 문구의 `+NG` 를 그냥 지우면 «골드가 들어온 걸 모르게 되는 것 아닌가» 가 걸린다.
> 실제로는 58 `fxWatch()` 가 `S.gold` **증가 자체를 감시**해 코드 한 줄 없이 코인 비행을 쏘고 있었다
> (46 교훈 3 «모든 경로가 지나는 한 지점» 의 연출 판). 확인하고 나니 지울 근거가 생겼고,
> 게이트에도 «3웨이브 모두 골드는 들어온다» 를 항목으로 박았다 — 다음 세션이 «문구를 지워서 골드가
> 안 보인다» 고 되살리는 것을 막는다.
>
> **3. 폭 클램프는 «그릴 때» 가 아니라 «값이 정해질 때» 한 번만 해라.**
> `draw()` 안에서 `measureText` + 이진 탐색을 돌면 문구가 떠 있는 1.45초 동안 매 프레임 반복된다.
> `showMsg()` 는 문구가 바뀔 때만 불리므로 거기서 (문자열, font-size) 한 쌍을 확정해 두면 된다.
> 짝으로: **축소하면 `lineWidth` 도 같은 비율로 줄여라.** 6px 외곽선을 18px 폰트에 그대로 두면
> 획이 서로 먹어 글자가 뭉치고, miter 가 삐쳐 잉크 bbox 가 계산보다 넓어진다(`lineJoin:'round'`).
>
> **4. 「팝업 위에 떠야 하는 안내」를 캔버스에 그리면 영영 안 보인다 — 층위부터 정하고 자리를 정해라.**
> `data-why`(비활성 버튼 사유)는 팝업 안의 버튼에서 가장 자주 난다. 전투 캔버스는 `#stagearea`(z 낮음)라
> 모달 딤(z30) 뒤에 깔린다 — 즉 **정작 필요한 상황에서 100% 안 보이는 안내**였다.
> `#fxl`(z60)에 붙이는 것이 답이고, 게이트도 «캡션이 뜬다» 가 아니라 **«#fxl z60 > 모달 z30»** 을
> 항목으로 단언한다. 앵커형 캡션은 **가장자리 3방향(좌·우·상단)** 을 반드시 같이 재라 —
> 화면 끝 버튼에서 캡션이 프레임을 넘거나 위로 잘리는 것은 기본값으로는 안 잡힌다.
