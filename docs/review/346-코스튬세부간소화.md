## 1. 처방 전에 재현했다 — 결손은 «두 줄» 이 아니라 «세 벌»

338·341·350 규칙대로 등재문의 처방을 따르기 **전에** `tools/probe346.js` 를 신설해 실측했다
(보유 칸 · Lv.38 · 순번 1 — 주인 스크린샷과 같은 자리):

| 자리 | 수리 전에 적혀 있던 것 |
|---|---|
| 라벨 `.sk-sl` | «강화 효과» |
| 상자 `.sk-db` 1줄째 | «강화 효과 **Lv. 38** — 공격 +15% · 체력 +11% · 골드 +7.6%» |
| 상자 `.sk-db` 2줄째 | «**Lv. 500** 까지 강화하면 — 공격 +200% · 체력 +150% · 골드 +100%» |
| 알약 `.sk-ow` | «보유 1번째» ｜ «공격 +4.0% 체력 +3.2% 골드 +2.0%» |

⚑ **등재문은 «두 줄을 지워라» 였지만, 재현이 보여 준 것은 더 간단한 사실이다** — 같은 세 축
(공격·체력·골드)이 **한 화면에 세 벌**(지금 강화분 · 만렙 예고 · 보유 계단) 적혀 있고,
정작 **플레이어에게 지금 실제로 걸려 있는 값(계단 + 강화)은 어디에도 없었다**.
주인이 말한 «괜히 복잡하기만함» 의 정체가 이것이다 — 합이 아니라 **조각만** 늘어놓은 화면.

그래서 이 작업은 «두 줄 삭제» 가 아니라 **«세 벌 → 한 벌»** 이다. 지시의 «더해서 보여줘» 가
그대로 처방이었다.

부품 bbox(mbox 기준, 수리 전) — 넷 다 08 스킬 세부와 **픽셀 동일**:
`.sk-ct` 59,232,750,132 · `.sk-sl` 284,391,300,58 · `.sk-db` 59,420,750,290 · `.sk-ow` 94,628,680,63.
`.sk-db` 안에서 알약은 **위 여백 208px · 아래 여백 19px** 자리다(등재문 ⓐ «264px 구멍» 의 실체 —
상자와 알약은 겹쳐 있다).

## 2. 무엇을 어디에 뒀나 (자리 결정 근거)

수치를 들 수 있는 자리는 상자(`.sk-db`)와 알약(`.sk-ow`) **둘**인데, 둘 다 들면
주인이 지적한 «두 번 적기» 가 그대로 남는다. 한 자리만 들어야 한다.

| 자리 | 수리 후 | 왜 |
|---|---|---|
| `.sk-sl` 라벨 | 보유 «**보유 효과**» / 미보유 «획득 방법»(불변) | 지시 «강화 효과라는 설명도 삭제» |
| `.sk-db` 본문 | 보유 = **합산 한 줄** «공격 +19% · 체력 +15% · 골드 +9.6%» / 미보유 = 획득 방법(불변) | 수치를 **여기** 둔 이유는 아래 ⚑ |
| `.sk-ow` 알약 | 보유 «보유 순번»｜«**1**번째 코스튬» / 미보유 «다음 획득»｜«2번째 코스튬» | 197 이 넣은 **순번**만 남긴다(수치 0) |

⚑ **«상자를 비우고 알약만 수치» 를 안 고른 이유는 실측이다.** 그 배치도 기하는 같지만
(`.sk-db` 는 고정 크기 상자라 내용이 비어도 bbox 가 안 변한다) 보유 칸에서 상자 위쪽
**208px 이 통째로 빈 면**이 된다(§1 실측). 수치를 상자에 실으면 그 자리가 글자로 차고,
알약은 원래 자기 것이던 순번을 든다 — **빈 면 145px** 로 미보유 칸과 같은 모양이 된다
(미보유 칸은 194 이후 줄곧 «한 줄 + 알약» 이었다. 즉 새로 생긴 모양이 아니다).

⚠ **미보유 알약 왼쪽을 «다음 획득» 으로 바꾼 것은 197 의 미완을 닫은 것이다** —
197 주석이 «미보유 칸의 순번은 «지금 얻으면 받을 다음 칸» 이라 라벨을 «다음 획득» 으로 바꾼다»
라고 적어 두고 **코드는 안 바꿔** 미보유 칸도 «보유 n번째» 라고 말하고 있었다(아직 보유가 아닌데).
알약 문구를 손대는 김에 주석이 원래 말한 대로 맞췄다.

## 3. 숫자 — 한 식, 두 갈래 없음

```js
const cosEffNow = k => cosOwnStep(k, cosOwnIdx(id)) + cosLvOf(id) * COS_LV[k];
```

- 출처는 등재문 ⓒ 대로 **`COS_OWN`/`COS_LV` 상수 그대로**(`bonus()` 와 한 벌 — 표기·실효 불일치 금지, 156 규약).
- **미보유 분기를 새로 만들지 않았다** — 미보유 칸은 `cosLvOf` 가 0 이라 같은 식이 «계단만» 으로
  자연히 떨어진다. 분기가 늘면 두 갈래가 서로 어긋날 자리가 생긴다.
- 라이브 갱신은 이미 있던 경로를 탄다 — `liveCos()` → `mdLive({desc})` → `put('.sk-db p', …)`.
  262 가 뚫어 둔 자리라 **새 배선 0줄**이다.

⚠ **합은 «곱» 이 아니라 «합» 이다 — 지시·등재문 처방이 둘 다 «더해서» 다.**
실제 `bonus()` 는 `(1+계단) × (1+총레벨×COS_LV)` 로 **곱**하므로 표시값은 곱항 `계단×강화` 만큼
살짝 낮다(Lv.38 에서 공격 19% vs 곱 19.8% = **0.6%p**, 만렙 Lv.500 에서 204% vs 212% = **8%p**).
게다가 강화 배수는 **보유 코스튬 전체 레벨 합**에 한 번 걸리므로(194) 한 칸의 몫을 곱으로
정확히 떼어내는 것은 애초에 불가능하다 — 그래서 «이 칸이 얹는 몫» 을 합으로 적는 지금이
읽는 사람에게 **덜 틀린** 쪽이다. 곱 표기로 가려면 194 의 풀링 규약부터 바꿔야 한다.
**밸런스·판정은 0줄** — `bonus()` 는 한 글자도 안 건드렸다(표시층만).
