## §2 재현 — `tools/probe562.js` 신설 (338 규칙: 처방 전에 제품에게 묻는다)

74 의 «네이티브 click 삼키기»(`index.html` 37342)는 이렇게 생겼다:

```js
addEventListener('click', e => {
  if(!e.isTrusted || e.__tap) return;
  if(tapRec && performance.now() - tapRec.t < 3000){ e.stopImmediatePropagation(); e.preventDefault(); }
}, true);
```

`tapRec.t` 는 **pointerdown 시각**이다. 즉 삼키기는 «down 으로부터 3초» 짜리 창이다.
`verify95` 의 드래그는 12스텝 × hold 12ms 라 **한가한 기계에서는 1.2~1.6초**에 끝나지만,
기계가 밀리면 스텝마다의 CDP 왕복이 늘어 **3초를 넘긴다** — 넘긴 순간 삼키기가 안 걸리고
네이티브 click 이 그대로 샌다.

`probe562` 는 그래서 «빨강인가» 가 아니라 **시간축**을 찍는다. 궤적·거리·속도를 고정하고
**떼기 전에 머무는 시간만** 갈랐다(스텝 수로 갈면 거리·속도가 같이 변해 축이 둘이 된다).

| 항 | 제스처 | 길이 | scrollTop | `dsDragged` | click |
|---|---|---|---|---|---|
| [A] 빠른 드래그 260px (verify95 [B] 와 같은 값) | 12×12ms | 1,590ms | 305 | true | **0건** |
| [B] 느린 드래그 260px (떼기 전 3.2초 머묾) | 12×12ms + 3,200 | 4,993ms | 264 | true | **1건(네이티브)** |

| [C] 길게 머묾 (2,600ms) | 같음 | 3,948ms | 264 | true | **1건(네이티브)** |

**거리·속도가 같은데 머문 시간만으로 갈린다** = 축은 하나, 시간이다.

[D] 샌 click 은 **전부 `isTrusted` 네이티브**였다(`__tap` 0건) — 합성기(74)는 `dsDragged` 를 읽어
**이미 접고 있었다**(37326). 즉 결손은 합성기 억제가 아니라 **네이티브 삼키기의 창**이다.
등재문이 적어 둔 용의자 ⓐ(74 억제 임계 8px 이 밀렸는가)·ⓑ(10 상점이 얹은 새 핸들러)·ⓒ(자의 좌표)
셋은 이 계측으로 **전부 기각**된다 — 임계도 핸들러도 좌표도 안 건드리고 **머문 시간만** 바꿔서 갈렸다.

[E] 실제 피해의 크기도 같이 쟀다: 상점 [구매] 버튼(200×98) 위에서 40px·12px 만 끌고 3.2초 머물다 떼면
click 은 **새지만** 표적은 `.cbtn` 이 아니라 **클래스 없는 조상 `DIV`** 였다(`closest('.cbtn')` 0건).
click 의 표적은 down·up 두 노드의 공통 조상인데, 10 상점 목록은 `renderUI` 0.35초 주기가 본문을
통째로 다시 그려(작업 107 주석) down 노드가 detached 가 되므로 조상이 카드 밖으로 올라간다.
⇒ **지금 이 화면에서의 피해는 한 칸 얕다.** 그래도 결손은 결손이다 — 규칙(«드래그는 탭이 아니다»)이
깨진 것이고, 같은 규칙을 쓰는 다른 화면은 재렌더 주기가 달라 조상이 카드 안에 남을 수 있다.

## §3 처방 — 창을 늘리지 않고 «드래그로 끝났다» 를 up 에서 찍는다

세 갈래를 놓고 골랐다.

| 갈래 | 무엇 | 왜 안 골랐나 / 골랐나 |
|---|---|---|
| ⓐ `3000` 을 키운다 | 삼키기 창을 30초 등으로 | 그 상수의 뜻은 «낡은 기록은 안 믿는다» 인데, 늘리면 그 뜻이 죽는다. 드래그가 얼마나 길지는 상한이 없다 |
| ⓑ 삼키기에 `dsDragged` 를 OR 로 | 한 줄 | `dsDragged` 는 **다음 pointerdown 까지 참**으로 남는다 → 드래그 뒤 키보드(Enter)로 누른 버튼의 trusted click 까지 삼킨다 |
| **ⓒ up 시각을 찍고 그 직후 하나만 접는다** | 3자리 | **골랐다.** 네이티브 click 은 pointerup 에 이어 오므로 창이 좁아도 된다(400ms). 기존 3초 창보다 **더 좁다** |

```js
const DS_CLK_MS = 400;
let dsClkT = -1e9;                       /* 드래그로 끝난 제스처의 up 시각 */
...
const end = e => { ...
  if(!r || !dsDragged) return;
  dsClkT = performance.now();            /* 562 — 이 제스처는 드래그였다 */
...
addEventListener('click', e => {
  if(!e.isTrusted || e.__tap) return;
  if(performance.now() - dsClkT < DS_CLK_MS){ e.stopImmediatePropagation(); e.preventDefault(); return; }
  if(tapRec && performance.now() - tapRec.t < 3000){ ... }
}, true);
```

**허용 오차를 넓히지 않았다** — 새로 연 창(400ms · 드래그 끝에서만 열린다)은 기존 창(3,000ms ·
모든 down 에서 열린다)보다 좁고, 여는 조건도 «드래그로 확정된 제스처» 하나다.

## §7 남은 것 · 다음 세션에게

⚑ **«연속 n회 빨강» 은 «굳은 실패» 의 증거가 아니다.** 305 가 닫은 «4회 중 1회» 와 이번 «4회 중 4회» 는
같은 종류다 — 둘 다 **기계 속도라는 숨은 축**이 정했다. 곁다리 관측을 등재할 때 «몇 회 빨강» 만 세지 말고
**그 실행의 벽시계 값**(제스처 길이·소요 시간)을 같이 적어야 다음 세션이 축을 찾는다.

⚑ **시간 창(`performance.now() - t < N`)으로 제스처를 묶는 자리를 새로 만드는 세션에게**: 그 창의 기준점이
**down 인지 up 인지**를 먼저 적어라. 여기서 샌 이유는 창이 짧아서가 아니라 **기준점이 down 이라
제스처가 길어질수록 남은 예산이 줄기 때문**이다.
