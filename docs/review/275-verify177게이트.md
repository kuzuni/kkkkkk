## 1. 재현 — 등재문 그대로였다

착수 첫 실행에서 등재문(249 작업 중 발견)이 적은 그 1건이 그대로 재현됐다.


같은 절의 **값 단언**(«승급 수호자 체력 = eHp(s)×60», `near`)은 초록이다. 즉 제품의 성질은 살아 있고
**소스 정규식만** 빨갛다 — 회귀가 아니라 오탐이라는 증거다.

판정식과 실제 소스:

```js
/* tools/verify177.js:174 (부패) */
/const T2 = ETYPE\.promo, s = S\.stage, hp = eHp\(s\)\*60;/

/* index.html:20918 (208 이후 · 현재) */
```

**`hp = eHp(s)*60` 은 한 글자도 안 바뀌었다.** 208(승급 보스 아틀라스 교체)이 같은 문장의 앞부분을

물고 있어서 함께 깨졌다.

## 2. 처방 — 등재문의 «괄호로 넓히기» 대신 **문장을 떼고 성질별로 쪼갰다**

등재문의 처방은 `(?: = promoType\(ri\))?` 로 208 표기까지 받게 넓히는 것이었다. 그렇게 하면 이번 FAIL 은
사라지지만 **같은 병이 다음 표기 변경에서 그대로 재발한다** — 정규식이 여전히 «남의 성질»(승급 보스 타입을
어떻게 고르는가)을 물고 있기 때문이다. LESSONS 138-1(«정규식에 이웃 요소를 끼워 넣으면 남의 작업이 내
게이트를 깬다»)의 처방을 그대로 따랐다: **판정 대상을 문장 단위로 먼저 떼어 내고, 성질별로 항목을 쪼갠다.**

```js
const promoStmt = (src.match(/^[^\n]*const T2 = ETYPE\.promo[^\n]*$/m) || [''])[0];
yes('⑥ 승급 수호자 스폰 문장이 살아 있다 (const T2 = ETYPE.promo …)', promoStmt !== '');
yes('⑥ 승급 수호자 스테이지가 S.stage 다', /\bs = S\.stage\b/.test(promoStmt));
yes('⑥ 승급 수호자 hp 식이 eHp(s)*60 그대로다', /\bhp = eHp\(s\)\*60;/.test(promoStmt));
```

**177 이 지키려는 성질만 남았다** — 스폰 자리가 살아 있는가(⑥a) · 스테이지 축이 `S.stage` 인가(⑥b) ·
hp 가 새 곡선 `eHp(s)×60` 을 타는가(⑥c). `= promoType(ri)` 는 이제 **어느 항목도 안 본다.**
항목 수는 1 → 3 으로 늘어 총계가 **94 → 96** 이 됐다(판정력이 준 게 아니라 쪼갠 만큼 늘었다).
