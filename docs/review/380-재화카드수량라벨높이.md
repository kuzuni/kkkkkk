## 2. 처방 — 세로 축 하나를 ref 에서 역산하고, 폭은 계열마다 되돌린다

세로를 정하는 것은 `.cn-cd>.qt{font-size}` **하나**다. 값은 지어내지 않고 이 파일이 이미 쓰는 규약
(«ref_h/cap_h 만큼 fs 를 줄이고 폭 보존은 가로 배율에 역수» — 6회차 주석)대로 **ref 잉크에서 역산**했다:

```
×100 : 39.3 × (31−8)/(37−8) = 31.17
×50  : 39.3 × (30−8)/(36−8) = 30.88     ⇒ font-size **31px**
```

(−8 은 `-webkit-text-stroke:8px` 이 잉크 위·아래로 4px 씩 더한 몫.)
스윕 실측이 이 역산을 그대로 확인한다 — **fs 31 에서 잉크가 정확히 31·30 = ref** 다.

### 광고 칸의 `qx` 는 377 과 **같은 방법으로** 다시 역산했다

등재문의 ⚠ 대로 «크기를 먼저 확정하고 폭 보정을 다시 잰다». fs 31·qx 1.08 에서 실측 잉크는
×100 **81** · ×50 **66** 이므로

```
×50  : 1.08 × 81   / 66 = 1.3255      ×100 : 1.08 × 97.5 / 81 = 1.300
```

377 이 고른 쪽과 같은 쪽 — **칸 3개를 차지하는 «×50» 을 ref Δ0 으로 두는 값**으로 **1.33** 을 썼다.
결과는 ×100 **99×31**(ref 97.5×31) · ×50 **80×30**(ref 81×30) 으로 **가로도 수리 전보다 ref 에 가깝다**
(수리 전 101/82). 잉크 우변이 1px 더 안쪽이라 377 이 세운 «검정 테까지 여유 ≥6px» 은 더 넉넉해진다.

### 남의 계열(dia·rel·dtk)은 «세로만» 바뀌게 `--qk` 로 폭을 되돌렸다

등재문이 남긴 판단(«칸별 손잡이를 만들지, 계열별로 갈지»)의 답이다.

- 광고 칸만 줄이는 손잡이(⓵)는 **버렸다** — 같은 화면·같은 부품인데 광고 칸 라벨만 31, 이웃
  다이아·유물조각·입장권 칸은 37~39 가 되어 **레퍼런스에 없는 불일치**를 새로 만든다
  (377 이 «한 칸만 줄이면 이웃과 19% 어긋난다» 로 기각한 것과 같은 이유).
- 그래서 세로는 **부품에서 한 번에** 내리고, ref 가 없는 세 계열(측정표 §11 «레퍼런스 없음 ·
  우리 게임 설계»)은 목표를 «**수리 전 폭 그대로**» 로 두고 `--qk`(폭 보존 배수)로 되돌렸다.
  ⇒ 이 회차가 바꾼 것은 **세로 한 축**이고, 남의 칸에서 바뀐 것도 세로뿐이다.

| 계열 | `--qk` | 근거(실측 배수) | 수리 후 폭 Δ |
|---|---:|---|---|
| dia 5칸 | **1.255** | 1.24 · 1.24 · 1.25 · 1.27 · 1.25 | +1 / +1 / −1 / −1 / −1 |
| rel 3칸 | **1.235** | 1.22 · 1.24 · 1.25 | −1 / −2 / −2 |
| dtk 8칸 | **1.19** | 1.19 (문자열이 «×1» 로 짧다) | −1 |

⚑ **배수를 «fs 역수 1.268» 로 지어내면 안 된다.** 외곽선 8px 은 `font-size` 를 안 따라가므로
폭은 fs 에 **선형이 아니고**, 짧은 문자열일수록 덜 준다(«×1» 1.19 ↔ «×450,000» 1.27).
선형으로 지어냈으면 dtk 8칸이 **+3px 씩** 넓어졌을 것이다.

## 4. 다음 세션이 볼 것

1. **`.cn-cd>.qt` 의 세로 축은 이제 `font-size:31px` 하나이고, 계열별 폭은 `--qk` 가 받는다.**
   문자열이 바뀌는 칸(수량 표기 규약 150·111 계열)을 손대면 `--qk` 의 실측 배수도 같이 다시 재라 —
   배수는 문자열 길이에 따라 다르다(외곽선이 fs 를 안 따라가기 때문).
2. **잉크 높이를 fs 로 역산할 때 외곽선 몫(위·아래 4px씩)을 먼저 빼라.** 안 빼면 39.3 × 31/37 = 32.9 가
   나오고, 그 값은 잉크를 33 으로 만들어 ref 를 2px 넘긴다(스윕표의 fs 33 행이 그 자리다).
3. **되돌림 시험은 «수리 전 상태» 를 되돌려야 한다 — 축이 둘이면 둘 다.** 377 의 [R] 은 380 이
   세로를 내린 순간 «한 축만 되돌린 사본» 이 되어 헛초록이 될 뻔했다. 그래서 사본 편집이 먹었는지를
   묻는 [R-0] 을 같이 넣었다.
4. **377 이 남긴 함정 둘은 그대로 유효하다** — ⓐ 잉크는 rect·`scrollWidth` 로 안 보인다(사본을 단색
   판 위에 띄워 찍어라) · ⓑ 옛 커밋 사본은 **저장소 폴더 안**에서 열어라(/tmp 는 웹폰트가 안 붙는다).
   여기에 이번 회차가 둘을 더한다 — ⓒ **사본 판이 뷰포트를 넘으면** 잘린 자리가 통째로 «잉크» 로 읽히고
   (높이 1000px 짜리 유령), ⓓ **행 창이 pitch 보다 넓으면** 이웃 행이 섞여 **높이가 두 배**로 읽힌다
   (1회차에 37 이 62 로 나왔다).
