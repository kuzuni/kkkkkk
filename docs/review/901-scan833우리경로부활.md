## 1. 재현 — 등재문 그대로, 그리고 한 겹 더

등재문의 즉사를 먼저 재현했다(338 규칙 — 처방 전에 재현).

```
node tools/cap151.js scratch/901-r1.png --geo --crop
python3 tools/scan833.py --cap scratch/901-r1 --geo scratch/901-r1.geo.json
```

→ **ref 절은 정상으로 다 찍고**(배너형 열 13 · 위 검정 테 10.15 · 채움 96.12 …) 우리 절 첫 카드에서

```
File "tools/scan833.py", line 261, in main
    kind = '배너형(파랑)' if 'ban1' in c['cls'] else '불릿형(초록)'
KeyError: 'cls'
```

⚑ **재현이 등재문에 결손을 하나 더 붙였다.** `cls` 를 채우면 **바로 다음 줄**에서 또 죽는다 —
`c['card']['x']`(크롭-로컬 카드 상자)도 `cap151.js` 의 덤프에 없다. 첫 키가 둘째를 가리고 있었을 뿐,
이 경로는 **두 군데**가 비어 있었다.

## 2. 뿌리 — 자가 썩은 게 아니라 **기하를 만드는 자가 둘**이었다

`scan833.py` 가 묻는 `cls`·`card` 는 `probe667b.js` 가 **이미 싣고 있다**:

```js
const ox = Math.max(0, cr.left - 40), oy = cr.top - 80;   // 크롭 원점 — cap151 --crop 과 같은 식
const o = { id: c.dataset.pv, cls: c.className, card: B(c) };
```

즉 세 스캐너(`scan833`·`scan667b`·`scan667c`)는 **`probe667b` 의 덤프 모양**에 맞춰 쓰였는데,
docstring·등재문은 `cap151.js --geo` 를 먹이라고 적고 있었다. 두 생산자의 모양이 갈린 채 굳었고,
`cap151` 쪽으로 먹인 경로는 **한 번도 안 돌았다**(등재문의 관측 그대로).

⚑ **그래서 이 자리는 `scan833` 하나가 아니다** — `scan667c.py`(254행)·`scan667b.py`(149행)도
같은 두 키를 같은 방식으로 묻는다. 뿌리를 `cap151` 에서 고치면 **셋이 같이 산다**.

## 3. 처방 — 등재문의 ⓐ 채택, 그리고 ⓑ 를 기각한 실측 근거

등재문의 두 후보: ⓐ `cap151.js` 가 `cls` 를 싣는다 · ⓑ `scan833.py` 가 `id` 로 형을 가른다.

**ⓐ 를 골랐고, ⓑ 는 실측으로 기각된다** — 배너형 카드의 id 는 `ban1` 이 아니라 **`noads`** 다
(불릿형은 `abless`·`offplus`). id 문자열에는 형을 읽을 축이 아예 없다. 형을 정하는 것은 CSS 의
`.pvc.ban1` 이므로 그 클래스를 그대로 넘긴다 — 카드가 늘어도 자를 안 고친다.
게이트 `B6` 이 이 기각을 못박는다(«배너형 id 가 `ban*` 이 아니다»).

### 3-1. `cap151.js` — 두 키를 싣는다

- `o.cls = [...c.classList]` — 실제 클래스 목록.
- 크롭 루프에서 **크롭 원점을 한 곳에서 계산**해 클립과 덤프가 같은 수를 쓰게 했다:

```js
const ox = Math.max(0, c.x - 40), oy = Math.max(0, c.y - 80);
const cw = Math.min(1080 - ox, c.w + 80), ch = c.h + 110;
c0.card = { x: c.x - ox, y: c.y - oy, w: c.w, h: c.h };   // 크롭-로컬
c0.crop = { x: ox, y: oy, w: cw, h: ch };
```

⚠ **상수를 베끼게 두지 않은 것이 요점이다.** 형제 자 `scan833b.py` 는 같은 자리를
`CROP_DX, CROP_DY = 40, 80` 이라는 **상수 사본**으로 때우고 있었다(37행). 그 둘은 `cap151` 의
클립 줄에서 정해지는 값이라, 클립이 바뀌면 사본은 **조용히** 어긋난다(402 «사본을 지운다» 와 같은 꼴).
이제 실제 원점이 덤프에 실려 나온다 — 실측으로 `card = (40, 80)` · `crop = (11, 220)` 이 확인됐다.

### 3-2. `scan833.py` — 죽을 거면 무엇을 다시 뽑을지 말한다

두 키의 부재를 루프 **앞에서** 확인하고, 벌거벗은 `KeyError` 대신 처방을 말하고 끝낸다.
(«자가 부패했다» 처럼 보이던 얼굴의 절반은 이 역추적이었다.)

### 3-3. 곁다리로 닫은 함정 — 부분일치

`has_cls()` 를 세워 **낱말 단위**로 가른다. 옛 `'ban1' in c['cls']` 는 두 생산자의 두 모양
(목록 ↔ 문자열)에서 **둘 다 도는 것처럼 보이지만**, 문자열 쪽은 부분일치라
이웃 클래스 `ban10` 이 생기면 조용히 참이 된다. 게이트 `D4` 가 그 함정을 음성항으로 잡는다.

## 7. 교훈

1. **«자가 부패했다» 의 절반은 «먹이가 다른 자의 것이었다» 다.** 이 자리는 자가 썩은 게 아니라
   기하 생산자가 둘(`cap151` ↔ `probe667b`)인데 소비자가 한쪽 모양만 알고 있었다.
   자를 새로 세우기 전에 **«이 자는 누가 만든 기하를 먹는가»** 를 먼저 본다.
2. **833·885 가 3·4·5회차에 `scan885`~`scan885d` 를 새로 세운 이유가 이것으로 설명된다** —
   자가 죽어 있으니 매번 새 자를 세웠다(등재문의 관측). 죽은 자를 살리는 값이 새 자를 세우는 값보다 싸다.
3. **첫 `KeyError` 는 둘째를 가린다.** 사전 키 하나가 없어 죽으면 그 줄만 고치고 «끝났다» 하기 쉽다 —
   같은 절이 묻는 키를 **전부** 세어 보고 고쳐야 한 회차에 끝난다.
4. **상수 사본은 조용히 늙는다.** `scan833b.py` 의 `CROP_DX,CROP_DY = 40,80` 은 맞는 값이지만
   그 값을 정하는 줄과 끊겨 있었다. 값을 베끼지 말고 **만든 자리에서 실어 보낸다**(402 계열).
