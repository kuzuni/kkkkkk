### 무슨 일이 있었나

`index.html` 의 지급표는 282 로 이렇게 바뀌었다:


182/194 시절에는 «1계급 승급 = 묶음 21종» 이라 `av45` 도 어느 묶음엔가 들어 있었고,
따라서 `cosRankOf('av45') >= 1` 이었다. 282 가 지급을 **묶음 → 대표 1종**으로 줄이면서
지급표(`PROMO_COS`)는 7칸 7종이 됐고, 남은 **42종은 미출시**(`COS_OFF`)로 갈렸다.
`av45` 가 바로 그 42종 중 하나다 → `cosRankOf` 가 **0**, `cosReqText` 가 «추후 공개».

제품은 이 갈림을 정확히 처리하고 있다(`cosOff` 조기 반환이 «잠기지도 않은 채 영영 못 얻는 칸»
버그를 막는다 — LESSONS 282-② 가 적어 둔 자리다):

```js
function cosReqOk(a){
  if(!a) return true;
  if(cosOff(a.id)) return cosOwn(a.id);          /* 미출시 칸은 계급 조건이 아예 없다 */
  return cosOwn(a.id) || (S.rank|0) >= cosRankOf(a.id);
}
```

그런데 `verify91` 은 표본 id 를 **`'av45'` 로 소스에 박아 두고** 있었다(4곳).
지급표가 바뀌자 «계급으로 열린다» 단언이 통째로 빨개졌다.

**LESSONS 91-4 의 재발이다** — «자동 생성은 코드가 안 바뀐다는 뜻이지 게이트가 안 바뀐다는
뜻이 아니다». 실제로 106(펫 8등급) 때 같은 파일이 «세트 37개» 상수로 5건 FAIL 했고,
282 때도 verify182 §6 의 «칸 수 8» 6곳이 같은 이유로 깨져 `PROMO_COS` 파생으로 바뀌었다.
91 만 이번 물결에서 빠져 있었다.
