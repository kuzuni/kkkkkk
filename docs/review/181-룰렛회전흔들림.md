## 1. 65 는 «옳게» 고쳤는데 왜 증상이 남았나

65 는 `#modal` 에 `rou-spin` 을 붙이고 CSS 3줄로 **`#modal` 안**(딤·박스·박스의 모든 자손)의
`animation-name`·`scale`·`translate`·`rotate` 를 껐다. 지금도 정확히 동작한다 — 인계 시점에
`node tools/verify65.js` 는 **손대기 전부터 PASS** 였고, 내 전수 조사도 같은 결론이었다:

| 대상 | 회전 중 변화 | 자 |
|---|---|---|
| `.mbox`·`#modal` 딤·`.rlt`·`#rouBtn`·`#rouClose`·`#app` | **Δ0** | `probe181.js` (rect + computed style) |
| `#app` **안 모든 요소**(147개) 중 모달 서브트리 | **Δ0** | `probe181.js` (전수 walk) |
| 모달 서브트리 `animationstart`/`transitionstart`/style·class 변이 | 회전 구간 **0건** | `probe181b.js` (이벤트) |

**그런데 `rou-spin` 셀렉터는 `#modal` 을 벗어나지 못한다.** 이 게임에서 팝업 «위» 에 그리는 층은
`#fxl`(z60)이고, 그건 `#modal`(z30)의 형제다. 즉 **연출 레이어는 65 의 사정권 밖**이었다.

`probe181b.js` 로 실제 손가락(pointerdown 120ms 유지 → up)을 태워 보니 회전 3.9초 동안
**`#fxl` 에 연출 노드 30개**가 들어왔다. 픽셀로도 잡힌다 — 모달 박스 사각만 잘라
연속 프레임을 비교하면(`pix181.js` + `diff181.py`, 원판 마스크) 회전 시작 직후
**2724 → 28 → 0 화소**가 바뀐다. 박스는 안 움직이는데 **박스 위를 무언가 가로지른 것**이다.

### 움직이던 것 2가지

**① 보상 연출이 «돌리는 순간» 터진다.**
`spinRoulette()` 이 결과 칸을 뽑자마자 `giveReward()` 를 불렀다. 그 함수는 첫 줄이 `fxReward()` 라
58 이 **누른 버튼 자리에서 스파크 14개**를 터뜨리고, 이어 `S.dia` 증가를 93 의 감시자(`fxWatch`)가
잡아 **다이아 비행 + HUD 알약 복제판(`fx-lit`)** 까지 쏜다. 출발점은 `fxSrc()` = 방금 누른 **[돌리기] 버튼**,
도착점은 화면 맨 위 HUD 알약 — **경로가 팝업을 세로로 관통한다.** 원판이 도는 내내 그 위로
재화가 날아다니니 «회전 중 흔들리는 연출» 로 보인다.

**② 조바심에 다시 누르면 팝업 위에 캡션이 튄다.**
회전 중 두 버튼은 `disabled` 다. 60 의 전역 위임(`jzInit`)은 죽은 버튼을 누르면 3가지를 한다 —
`jz-sh`(좌우 흔들림) · `sfx('err')` · `jzWhy()`(«아직 사용할 수 없습니다» 캡션).
65 가 죽인 것은 **첫 번째뿐**이다. 캡션은 `#fxl` 에 붙으므로 `rou-spin` 이 닿지 않아
**누를 때마다 팝업 위에서 튀어나왔다.**

> **오답 후보 2개도 실측으로 지웠다.** ⓐ «60 누름 스프링(`jz-dn`/`jz-up`)이 회전 첫 290ms 를 먹는다»
> — `probe181b` 타임라인은 `jz-dn` 206ms · `jz-up` 338ms · **`rou-spin` 345ms** 로, 스프링은
> 회전이 **시작되기 전**에 끝나거나 7ms 만에 눌린다. 65 가 이미 닫은 문이다.
> ⓑ «전투 카메라 흔들림(`cam.shake`)이 딤 너머로 비친다» — 룰렛을 연 채 6초(261프레임) 재니
> `cam.shake>0` 이 **10프레임(3.8%) · 최대 3.03**(화면 이동 ±1.4 게임px)뿐이라 이 증상을 못 설명한다.
> 55 의 `shakeOn()` 게이트를 룰렛이 건드리지 않은 이유다.

## 2. 수정 — 4곳

### (가) 지급을 «돌리는 순간» → «멈춘 뒤» 로 옮겼다 (`spinRoulette` → `roulFinish`)

연출을 **끄는** 게 아니라 **제자리로 옮기는** 것이다. 등재문도 «끝나고 당첨 연출은 무방 —
지시는 «회전 중 흔들림» 금지» 라고 못 박았다. 이제 원판이 서는 순간 당첨 칸이 켜지고,
그 자리에서 다이아가 날아오른다 — 인과가 바로 선다.

출발점은 **원판 허브(`.rlt-hub`)로 못 박았다.** 그냥 두면 `fxSrc()` 가 null 을 돌려준다:
마지막 탭(`fxTapT`) 유효 시간은 **1200ms** 인데 회전이 **3.9초**라 이미 만료다. 그러면
`fxFly` 가 `{x:FRAME_W/2, y:frameH*0.5}` 폴백으로 떨어져 다이아가 «화면 한가운데» 에서 솟는다
(158 이 잡은 «엉뚱한 곳에서 튀는 재화» 와 같은 함정, 부호만 반대). `fxAt(hub)` 힌트는 600ms
유효이고 바로 다음 줄이 `giveReward()` 라 넉넉하다.

### (나) «보상 손실 없음» 을 세 갈래로 다시 보증했다

지급이 뒤로 갔으니 **회전 도중 빠져나가는 모든 길**에서 지급을 보장해야 한다.
`roulSpinTo` 안에 `fin()` 하나를 두고 모든 이탈 경로를 그리로 모았다(`paid` 플래그로 **1회 보장**):

| 이탈 | 종전 | 지금 |
|---|---|---|
| 팝업이 애초에 없음 (`!disc`) | `roulFinish` | `fin()` → 지급 |
| 다른 팝업이 덮어 원판이 detach | **그냥 return**(지급은 앞단에서 이미 됨) | `fin()` → 지급 |
| 딤을 눌러 팝업을 닫음 | 원판은 살아 있어 3.9초 더 돎 | **`gone()` 감지 → 즉시 결판**(지급 + 연출) |
| 앱 종료·새로고침 | (앞단 지급이라 무관) | **`pagehide` 안전망** → 지급 + `save()` |
| 정상 정지 | `roulFinish` | `fin()` → 지급 |

`pagehide` 를 쓴 이유: `beforeunload` 는 모바일에서 안 오는 경우가 있고, 여기서는 «지급 + 저장» 만
하면 된다 — `roulFinish` 를 부르면 사라지는 화면에 소리·DOM 갱신을 얹게 된다. 미지급 칸은
`rouPend`(−1 = 없음)에 들고, 지급하는 모든 경로가 이 값을 비우므로 **두 번 오면 두 번 주지 않는다.**

### (다) 세대 토큰 `rouGen` — 묵은 rAF 루프가 새 회전을 덮던 구멍

팝업을 닫았다 다시 열고 3.9초 안에 또 돌리면 **앞 회전의 rAF 루프가 아직 살아 있다.** 그 루프가
뒤늦게 «원판이 사라졌다» 를 알아채고 `roulFinish` 를 부르면 **새 회전의 `rouSpinning`·버튼·`rou-spin`
표식까지 같이 꺼진다.** 65 때부터 있던 구멍인데 그때는 지급이 앞단이라 «보상» 은 안 걸렸을 뿐이다.
지금은 지급까지 얽히므로 세대를 센다 — **주인이 아닌 세대는 지급만 하고 UI 는 안 건드린다.**

> 이 구멍은 **게이트를 짜다가 드러났다.** [F](강제 닫힘 3회)를 넣자 바로 뒤 [G](8칸 전수)가
> «원판이 안 돈다 · 역산 7/8 불일치» 로 무너졌는데, 원인은 [F] 가 남긴 세 개의 좀비 루프였다.
> 게이트가 «내가 안 짠 시나리오» 를 만들어 준 셈이다.

### (라) 회전 중에는 두 버튼을 포인터 대상에서 뺀다 (CSS 1줄)

```css
#modal.rou-spin .gbtn{pointer-events:none}
```

«죽은 버튼 누름» 자체가 성립하지 않게 해서 `jz-sh`·`sfx('err')`·`jzWhy` 를 **한꺼번에** 없앴다.
60 모듈을 안 건드리고 룰렛 쪽에서만 끄는 방법이고, 어차피 두 버튼은 `disabled` 라 기능 손실이 없다.
**딤 클릭 닫기는 그대로다** — `#modal` 의 핸들러는 `e.target === #modal` 만 보는데, 버튼을 통과한
탭은 딤이 아니라 `.mbox` 에 맞는다(실측 확인).

## 5. 교훈 (다른 화면에도 그대로 재발한다)

1. **«상태 클래스 + 특이도» 로 끄는 방식(65)은 그 클래스가 붙은 서브트리 밖을 못 끈다.**
   이 저장소의 연출은 절반이 `#fxl`(z60, 팝업 «위») 에 그려진다 — **오버레이 층은 항상 사정권 밖**이다.
   «회전/진행 중에는 조용해야 한다» 를 CSS 로만 풀려 하지 말고, **연출을 쏘는 시점을 옮겨라.**
2. **«무엇이 움직이나» 는 rect 만 보면 놓친다.** 계산 스타일·bbox 전수 조사가 «모달 안 Δ0» 이라고
   말할 때도 픽셀은 2724개가 바뀌고 있었다 — **위를 지나가는 것**은 bbox 를 안 건드린다.
   자를 두 개 대라(DOM 이벤트 + 픽셀 차분). 그리고 정지 상태 기준선을 먼저 재라
   (여기서는 회전 없이 6프레임 Δ0 을 확인하고서야 «회전이 원인» 이라고 말할 수 있었다).
3. **크로미움 스크린샷 PNG 는 컬러타입 2(RGB, 3바이트/화소)다.** RGBA(4)로 가정하면 스트라이드가
   어긋나 필터 복원이 무너지고 `[4,255,0]` 같은 **순색 잡음이 화면 전체에 깔린다** — 그걸
   «회전 중 흔들림 21399화소» 로 읽고 한 회차를 태울 뻔했다. **헤더에서 읽어라.**
4. **지급 시점을 뒤로 옮기면 «중간에 빠져나가는 길» 을 전부 다시 세어야 한다.** 앞단 지급은
   이탈 경로를 신경 쓸 필요가 없어서 코드가 그렇게 쓰여 있었다 — 옮기는 순간 그 이탈 경로들이
   전부 «보상 증발» 후보가 된다. 여기서는 5갈래였고, `paid` 플래그 한 개로 «1회 보장» 을 묶었다.
5. **rAF 루프는 화면이 사라져도 안 죽는다.** 같은 UI 를 다시 열어 새 루프를 띄우면 묵은 루프가
   새 상태를 덮는다. 수명이 긴 rAF 애니에는 **세대 토큰**을 붙이고, 주인이 아닌 세대는
   «자기 뒤처리만» 하게 하라.
