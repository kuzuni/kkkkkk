## 2. 뿌리 — 가설 ⓐ 가 맞았다(제품은 내내 옳았다)

등재문의 두 갈래 중 **ⓐ(주입문이 낡았다)** 다. ⓑ(«기대 0건» 이 애초에 틀렸다)는 기각된다 —
N9 는 «칸 수가 늘어도 게이트가 따라오는가» 를 묻는 **양성 대조**라 초록이 정답이고,
실제로 주입문을 고치자 **빨간 항 0개**가 됐다.

낡은 것은 `neg279.js` 가 손으로 적어 둔 `.sp4` **아홉 줄**이다. 그 값들은 서브탭 셸 테두리
**b = 6px** 시절의 전사본이다:

```
.stabs.sp4>.stab{width:calc(25% + 3px)}          /* = 25% + b/2, b=6 */
.stabs.sp4>.stab:nth-of-type(1){left:-6px}       /* = -b,        b=6 */
```

그런데 **437(2026-08-30)** 이 그 b 를 `--sb` 한 손잡이로 빼면서 **6 → 7** 로 올렸다
(`index.html` 10727 `.stabs{--sb:7px;…}`). 그래서 주입된 바의 바깥 좌끝이 −6, 오른끝이 100%+6 으로 그려지고,
게이트가 제품의 참값(−7 / 100%+7)과 대 보아 **1px = 7 − 6** 씩 세 항이 빨개졌다.

**검산**: 세 항의 Δ 가 전부 1.0 이고, 그것이 `--sb` 의 증분과 정확히 같다. 다른 축(칸 폭·칸 2·3 경계·알약)은
`b/2` 나 `−11.75` 로 들어가 반올림 안에 들어 빨개지지 않았다 — **끝 칸의 바깥 끝 둘만** 온전히 b 를 먹는다.

## 3. 처방 — 값을 갱신하지 않고 «자리를 제품에게 물었다»

⚠ **`3px → 3.5px` · `-6px → -7px` 로 고치는 길은 안 갔다.** 그 길은 이 파일이 §[A] 주석에
스스로 적어 둔 것 — «리터럴을 새 값으로 갱신하는 것은 같은 죽음을 다음 폴리시까지 미루는 것뿐이다» —
바로 그 길이고, `--sb` 가 다시 움직이면 여기는 똑같이 다시 죽는다.

⇒ 제품에 **이미 살아 있는 4분할 선언**이 있다. 437 이 07 스킬 시트 4칸 바를 위해 `--sb` 로 다시 적은
`.stab-c1`~`.stab-c4` 아홉 줄(`index.html` 11313~11321)이다. 그 줄들에서 **선언부(첫 `{` 뒤)를 통째로
물려받고 선택자만** `.stabs.sp4>.stab…` 으로 갈아 낀다.

```
.stabs.sp4>.stab{width:calc(25% + var(--sb) / 2)}
.stabs.sp4>.stab:nth-of-type(1){left:calc(-1 * var(--sb))}
… (9규칙, 전부 index.html 에서 읽어 온 것)
```

**이 파일에 새로 적힌 숫자는 0개다.** 그리고 저 아홉 줄이 사라지거나 모호해지면
§[A] 앵커가 «0줄 / n줄» 로 **빨개진다** — 387 이 만든 «조용히 죽는» 길이 없다.

⚠ 379 규약(칸 = 바깥/4 · 활성 알약 11.75/면 · 셸에 닿는 면은 패딩 변에 붙는다)을 **여기서 다시 적지 않는 것**이
처방의 핵심이다. 제품의 그 아홉 줄이 이미 그 규약이고, 여기 다시 적는 순간 또 낡는다.
