## 2. 고친 것 — 예외를 «보스» 가 아니라 «1:1 단독 개체» 로

`index.html` 2곳, 판정 한 줄이 전부다.

```js
/* ~14178 */
const SOLO_CHASER = { boss:1, promo:1, arena:1 };
/* ~15957 (적 이동 루프) */
const isBoss = !!SOLO_CHASER[e.tk];      // ← 이전: e.tk === 'boss'
```

- 무리 몹(`zombie`/`goblin`/`dark`)은 **그대로 둔다** — 스월과 적 간 분리(×2.9)는 «떼» 의 거동이고,
  단독 개체에서만 «주위를 도는» 역효과가 난다.
- `tk === 'boss'` 를 쓰는 **다른 8곳**(처치 보상 `S.dia` · 파티클 수·색 · HUD 보스 HP 바 ·
  `bossInSfx` 등)은 **한 곳도 건드리지 않았다.** 바꾼 것은 «이동 규칙 판정» 하나뿐이다.

## 3. 게이트 — `tools/verify172.js` (신설) · **V172 PASS**

66 의 게이트는 스테이지 보스 한 종만 잰다. 172 가 요구한 «전수» 를 게이트로 굳혔다 —
보스·승급 수호자·아레나 도전자 3종을 같은 축으로 잰다.

- **세 개체 전부**: ⑥ 진행 방향 정렬 ≥ **0.98**(스월이 꺼졌나) · ⑦ 실측 속도 ≥ 플레이어 × **0.92**
  (속도 바닥이 걸렸나) · pageerror 0 · 표본 충분
- **보스·승급 수호자만**: ① 접촉 · ② 수렴 평균 거리 ≤ 사거리+50 · ③ 멀어짐 < 10% · ④ 공격 ≥ 1회
- 문턱은 **눈대중이 아니라 before/after 실측 사이**에서 골랐다 —
  정렬 before 최대 **0.949** ↔ after 최소 **0.999** 사이의 0.98,
  속도 before 최대 **0.75×** ↔ after 최소 **0.97×** 사이의 0.92.

**«되돌려서 빨간지» 확인(LESSONS 규칙)**: `git stash push -- index.html` → 승급 5항목 · 아레나 2항목
**FAIL**(정렬 0.949/0.945 · 속도 61/86px/s) → `git stash pop` → **PASS**. 게이트가 실제로 이 버그를 문다.

## 4. 남긴 것 — 아레나(123)는 «추격» 이 아니라 «스폰 배치» 가 남았다

아레나 도전자는 이제 **플레이어 속도로 똑바로 쫓아온다**(속도 77 → 114px/s · 정렬 1.000).
그런데도 30초 안에 못 붙는다. 원인은 172 의 추격 규칙이 **아니고**, 작업 123 자신의 스폰 배치다:

- `startArena()` 가 `makeEnemy('arena')` 를 그대로 써서 **플레이어 반경 300~700px 링**
  (67 `SPAWN_RMIN`/`SPAWN_RMAX`)에 놓는다. 보스는 `BOSS_RMAX 340` 으로 링을 좁혀 뒀는데 아레나는 안 좁혔다.
- 같은 함수가 `e.nopop = true` 에 «팝인 없이 **마주 선 채** 시작» 이라는 주석을 달아 놓았다 —
  **코드가 자기 주석과 어긋나 있다.**
- 게다가 아레나 상대는 플레이어 스프라이트 규격(`r 16`)이라 사거리가 **38px**(보스 76px)뿐이고,
  추격 상한이 플레이어 속도 ×1.08 이라 30초 동안 벌 수 있는 거리가 **45px 남짓**이다.

→ 30초 대전 내내 **상대가 한 대도 못 때린다** = 플레이어가 카이팅만 하면 무조건 이긴다.
**스폰 배치는 123 의 구간이므로 손대지 않았다.** `verify172` 도 아레나에는 ①~④(접촉·공격)를
걸지 않고 ⑥⑦(추격 규칙)만 건다 — «항상 빨간 게이트»(130·133·134·138 계열)를 새로 만들지 않기 위해서다.
PROGRESS 172 비고에 같은 내용을 남겼다.
