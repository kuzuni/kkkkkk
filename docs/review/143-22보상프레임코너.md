## 3. 신설 도구 `tools/rr143.js` — ref 와 캡처를 **같은 자로** 잰다

`node tools/rr143.js [--json a.json] [--dsf N]`

23 의 `inkcmp23.js` 방식이다 — 회차마다 반복되던 «기준 불일치» 를 구조적으로 없앤다.
ref JPEG 와 우리 캡처를 **같은 마스크·같은 피팅**에 넣는다(npm 의존성 0, 크로미움 canvas 디코드).

- **무엇을 재나** — 프레임 **상단 두 코너의 «열별 최상단 inset 프로파일»**.
  라운드 사각형은 좌단에서 `d` 떨어진 열의 상단이 `y0 + r − √(r² − (r−d)²)` 에서 시작한다.
  좌·우 코너를 `d` 로 접어 한 표본으로 합치고 `(y0, r)` 을 격자 탐색으로 피팅한다.
- **왜 상단만** — 하단은 수량 배지(`.ifq`)가 프레임 밖으로 20px 걸쳐 있어(141) 실루엣이 오염된다.
  상단 두 코너는 행 크림(#F7ECDA) 위에 깨끗하게 떠 있다.
- **왜 «반경» 을 프로파일로 재나** — LESSONS 20-2·22-2. 코너를 눈으로 읽거나 한쪽 원호만
  피팅하면 **실제의 절반 근처로 과소/과대** 읽는다. 여러 단면으로 재는 것이 유일하게 재현된다.

### 3-1. 추정기 두 개를 돌리고 «자가검증» 으로 하나를 골랐다

이 도구의 핵심은 추정기 자체가 아니라 **고르는 근거**다. 지정값을 이미 아는 **우리 렌더**에
같은 추정기를 걸면 그 지정값이 그대로 되돌아와야 한다 — 그 오차가 곧 추정기의 신뢰도다.

| 추정기 | ref r | 우리 렌더 자가검증 오차 | 채택 |
|---|---|---|---|
| ① **AA 램프 50% 교차**(서브픽셀·임계 무관) | **31.40** (MSE 0.221) | **0.05px** | ✅ |
| ② 단일 임계 + 부풀림 δ 보정 | 28.45 (임계 3단 산포 1.00) | 0.28px | ❌ |

②는 «ref 폭이 마스크에서 110 = 실제 106 + 2/side» 라는 관측(22 비고의 «JPEG 쪽만 +2» 와 일치)에서
δ 를 반경에서 빼는 방식인데, **JPEG 번짐이 균일 팽창이 아니라 과잉 보정**된다.
①은 램프의 절반을 선형보간으로 찍어 대칭 번짐이 스스로 상쇄되고, 실제로 우리 렌더를 0.05px 로 되짚는다.

**비평가 X 의 «29» 도 ② 계열**(단발 dark row 폭 역산)이라 같은 이유로 낮게 갈린 것이다.
→ ①의 31.40 은 **측정표 §12(30.9)·104 주석(31.0)과 독립적으로 같은 값**이다. 세 출처가 모인다.

## 4. 결정 — 등재된 선택지 중 ①

등재 시 적힌 선택지는 ① 화면별로 열기 · ② 공용값을 올리고 나머지 5화면 재측정 · ③ 그대로 두기.

- **③ 기각** — ref 와 −21% 다. 141 이 같은 자리에서 이미 «회수한다» 로 결론냈다.
- **② 기각** — 나머지 다섯은 `.233` 이 **자기 레퍼런스와 맞는 값**이다(05 .2365 · 53 .2297 에서 뽑았고
  여섯 중 다섯이 .213~.246 안에 있다). 22 하나 때문에 올리면 다섯을 동시에 틀리게 만든다.
- **① 채택** — `--if-ic`(104 가 아이콘 잉크에 이미 낸 예외) · `--ifq-k`(141) 과 **같은 원리**다:
  프레임의 «두께·합성» 은 통일 대상이고, «레퍼런스가 잰 치수» 는 화면이 주는 입력이다.

**값은 `.2925`(= 106 × .2925 = 31.005)** 로 정했다. ①의 31.40 이 아니라 31.0 인 이유:
측정표 §12 가 «radius **31** 을 쓸 것» 으로 못 박아 둔 값이고, 세 출처(30.9 · 31.0 · 31.4)의
한가운데다. 남은 0.4px 는 LESSONS 16-④ «Δ≤2px 는 JPEG 노이즈» 구간이라 쫓으면
**코드가 측정표와 어긋나는 대가만** 치른다.

## 5. 게이트 — `verify104` ④ 를 화면별 기대값으로 바꿨다 (등재 시 ⚠ 로 예고된 것)

`④ 코너비율 산포 ≤ .004` 는 «전 프레임이 한 값» 을 요구해서 ①과 정면충돌한다.
**141 이 ⑥ 에서 한 것과 똑같이** 화면별 기대표로 바꿨다:

```js
const IFRR = { '22 .qs-i': 0.2925 };   // 나머지 여섯은 BASE .233
...
const base = rr.filter(x => IFRR[x.label] == null).map(x => x.v);
ck('코너비율 산포 ≤ .004 (기본값 ' + base.length + '프레임)', spread <= 0.004, ...);
```

불변식이 **약해진 것이 아니다** — «전부 한 값» 이 «화면별 기대값을 뺀 나머지가 전부 0» 으로
바뀌었을 뿐이고, 나머지 여섯의 산포는 여전히 **0.0000** 으로 잠겨 있다.
143 이 통일을 깬 것이 아니라 «레퍼런스가 잰 치수만» 연 것임을 이 게이트가 지킨다.
