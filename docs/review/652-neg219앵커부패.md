## §2 뿌리 — 규칙은 한 글자도 안 변했다. **앵커를 적는 방식**이 썩었다

N3·N4 가 찾던 앵커는 손으로 베껴 둔 공용 규칙 두 줄이다:

```
:is(#bSk,#bPet,#bCos,.stabs) .ol3{text-shadow: …}      ← neg219 가 들고 있던 문자열
:is(#bSk,#bPet,#bCos,.stabs) .ol4{text-shadow: …}
```

현행 `index.html` **12335·12337**:

```
:is(#bSk,#bPet,#bCos,.stabs,.rl-help,.pr182) .ol3{text-shadow: …}   ← `.rl-help`·`.pr182` 두 개가 붙었다
:is(#bSk,#bPet,#bCos,.stabs,.rl-help,.pr182) .ol4{text-shadow: …}
```

**셀렉터 목록이 자란 것뿐이고 `text-shadow` 본문은 한 글자도 안 바뀌었다.** 그런데 앵커가
목록째 베낀 문자열이라 **조용히 어긋나** 시험만 죽었다. 게이트가 지키던 뜻(«덧칠을 공용 유틸로
확산시키면 빨개진다»)은 내내 멀쩡했고, 그것을 **확인할 방법**이 사라져 있었다.

⚑ 이 목록은 **자라도록 설계된 목록**이다 — 화면이 늘면 항이 붙는다. 즉 이 부패는 우연이 아니라
**시간이 지나면 반드시 재발하는 종류**다.

## §3 처방 — 402 와 같은 «파생»

402 가 `dunTk()` 의 손으로 적은 표를 **id 파생**(`'tk' + Id`)으로 갈아 끼운 것과 같은 처방을 썼다.
앵커를 «손으로 적은 문자열» 에서 **«제품에서 찾아 오는 자리»** 로 바꾼다:

```js
const find = (re, name) => { const m = SRC.match(re); if (!m) { console.error('[!] 앵커 없음(' + name + ')'); return null; } return m[0]; };
const COMMON_OL3 = find(/^ *:is\([^)]*\.stabs[^)]*\) \.ol3\{text-shadow:[^}]*\}/m, 'COMMON_OL3');
```

정규식은 **셀렉터 목록이 아니라 «무엇을 고르는 규칙인가»** 로 잡는다(`.stabs` 를 포함하는 `:is(…)` 의
`.ol3` 규칙). 목록이 더 자라도 따라온다.

여섯 앵커를 전부 같은 방식으로 옮겼다 — N3·N4 만 고치면 나머지 넷은 **다음에 목록이 자랄 때 똑같이 죽는다**:

| 앵커 | 쓰는 시험 | 잡는 규칙 |
|---|---|---|
| `SHOP_OL3` · `SHOP_OL4` | N1 · N2 | `#shopCats .stab>i.ol3/.ol4` 덧칠 규칙 |
| `COMMON_OL3` · `COMMON_OL4` | N3 · N4 | `.stabs` 를 포함하는 `:is(…)` 공용 링 |
| `STAB_I` | N5 | `.stab>i{display:inline-block; …}` |
| `TOKEN_DROP` | N6 | `--sh-drop:<값>;` (값만 갈아 끼운다) |

## §4 무르게 풀지 않았음 — «시끄럽게 죽는 성질» 은 그대로다

«없어졌으니 뺀다» 로 풀면 N3·N4 가 지키던 뜻이 통째로 사라진다(등재문 ⓑ 경고). 그렇게 풀지 않았다:

- 정규식이 **못 찾으면 `null`** 을 돌려주고, 루프 앞의 `if (!t.from || SRC.indexOf(t.from) < 0)` 가
  그대로 **`갈아 끼울 자리를 찾았다` 를 빨갛게** 만든다. 규칙 자체가 사라지면 여전히 시끄럽게 죽는다.
- 단언은 **한 항도 안 지웠고 허용 오차도 한 칸 안 넓혔다.** N3·N4 의 `want`/`not` 은 그대로다.
- 수리 뒤 N3·N4 가 **실제로 «빨개져야 할 것이 빨개지고 초록이어야 할 것이 초록»** 임을 처음으로 확인했다
  (부패 이후 한 번도 안 돌던 6항이다).
