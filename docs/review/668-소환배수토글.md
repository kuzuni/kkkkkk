## 1. ⚑ 본체는 토글이 아니라 «등가성» 이었다 — 그리고 그것은 **이미 깨져 있었다**

등재문은 «대량 소환은 1회 소환 N번과 동일해야 한다» 를 **새로 지켜야 할 규약**으로 적었다.
착수해서 `doSummon` 을 열어 보니 그 규약은 지금도 필요한 것이었는데 **10·30연이 이미 그것을 어기고 있었다**:

```js
/* 668 이전 */
const lvUp = sumAddExp(b, times);          // ← 묶음 경험치를 통째로 **먼저**
const res = [];
for(let i=0;i<times;i++) res.push(summonOne(b));   // ← 그 뒤에 times 번
```

`sumAddExp` 는 그 자리에서 레벨을 올린다. 그러니 배치가 레벨을 올리면 **첫 장부터** 오른 레벨의
확률표(`gradeProbs`)로 뽑혔다. 즉 결손은 «×1000 을 만들면 생길 위험» 이 아니라 **이미 있는 것**이었고,
배수가 커질수록 커지기만 한다.

**처방은 순서 하나다** — «그 장의 경험치 → 그 장의 추첨» 을 한 장씩 지킨다:

```js
function summonBatch(b, times){
  const res = []; let lvUp = 0;
  for(let i=0;i<times;i++){ lvUp += sumAddExp(b, 1); res.push(summonOne(b)); }
  return { res, lvUp };
}
```

1회 소환의 순서(`sumAddExp(b,1)` → `summonOne(b)`)와 **글자 그대로 같으므로** 등가성이
«검사로 지켜지는 성질» 이 아니라 **구조로 보장되는 항등식**이 된다. 등재문이 금지한
«확률표 고정 후 N회 샘플» 은 애초에 쓸 자리가 없다.

### 재현 — 등재문 가설의 확인 (338 규칙)

`tools/probe668.js` 가 씨앗 고정 RNG 로 셋을 굴려 비교한다:
ⓐ «×N 한 번» · ⓑ «×1 을 N 번» · ⓒ **668 이전 알고리즘**(자 안에만 남긴 사본).

| 항 | 결과 |
|---|---|
| ⓐ vs ⓑ (100회, 배치 중 Lv 1→2) | 시퀀스 **100/100 일치** · lv 2/2 · exp 95/95 · dia·summons 동일 |
| ⓒ vs ⓑ (100회) | **어긋난 칸 1/100** (첫 불일치 i=1) — 결손 재현 |
| ⓒ vs ⓑ (3,000회, Lv 1→5) | 확률표 총변동거리 **1.259e-2** · 어긋난 칸 9/3,000 · 종별 도수차 합 18 |
