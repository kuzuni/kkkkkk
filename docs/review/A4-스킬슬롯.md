# 비평 로그 — A4 스킬 슬롯 원형화

대상: `#slots` / `.slot2` (전투 화면 최하단 원형 8칸)
레퍼런스: `docs/ref/02-기본-메인-화면.jpg` · 측정표: `docs/measure/A4-스킬슬롯.md`
캡처: 헤드리스 1080×1920, 패널 닫힘, 상태 분포를 레퍼런스와 동일하게 고정(1번 활성 / 2·3번 대기 / 4~8번 잠금)

## 1회차 — 최저 3/10

| 비평가 | ① 배치 | ② 크기비 | ③ 여백 | ④ 정렬 | ⑤ 색 | ⑥ 폰트 | 최종 |
|---|---|---|---|---|---|---|---|
| 1 | 7 | 7 | 9 | 9 | **4** | 6 | **4** |
| 2 | 8 | 5 | 7 | 9 | **3** | 5 | **3** |

두 명 모두 **⑤ 색·명암**이 최저였고 사유가 같았다 — **링이 전부 단색 플랫**.

### 코어 치수는 1회차에 이미 통과

비평가 1 실측: 「외곽 Ø120(0px 오차), pitch 130(0px), gap 10(0px), well Ø88,
컬러 링 8px(r48.5~55.5), 어두운 밴드 4px 2겹 — **전부 1:1 일치**」
→ 지름·피치·간격·링 두께는 손대지 않았다.

### 지적과 처리

| # | 지적 | 판정 | 처리 |
|---|---|---|---|
| 1 | 컬러 링이 단색 플랫. 레퍼런스는 세로 그라디언트(루마차 22~55) | **타당** | `inset box-shadow` 는 그라디언트가 안 되므로 **링 4겹을 레이어로 재구성**(`.slot2` / `::before` / `::after` / `.cdw`) 후 `linear-gradient` 적용 |
| 2 | 활성 슬롯에 원 바깥 노란 링(r60~66, 외곽 Ø133) 누락 | **타당** | `.slot2.ready{box-shadow:0 0 0 7px #fffe03}` 추가 |
| 3 | 장착 슬롯 하단 Ø40 뱃지가 14px 돌출하는데 없음 | **타당** | `.lvv2` 를 Ø40 원형 뱃지로 바꿔 `bottom:-14px` 에 배치 (원본은 동료 머리 아트, 우리는 아트가 없어 레벨 뱃지로 대체) |
| 4 | 자물쇠가 63px 로 +17% 크고 종횡비 -20%, 색이 흰색 아님(213) | **타당** | `font-size 58px + scaleY(.83)` 로 잉크 47×54 (레퍼런스 46×54), 필터를 `brightness(2.6) drop-shadow` 로 바꿔 249 (레퍼런스 245) |
| 5 | (비평가 2) 4·5번 슬롯만 어둡다 — 8칸 중 2칸이 다른 색 | **캡처 하네스 버그** | 내가 캡처 스크립트에서 **잠금 슬롯에 쿨타임 오버레이를 강제**한 탓. 게임 코드는 `sk` 가 없으면 `r=0` 이라 빈 슬롯에 오버레이가 걸리지 않는다. 하네스를 레퍼런스와 같은 상태 분포로 수정 |
| 6 | (비평가 2) 외경 119→117, gap 11→13 으로 | **불채택** | 세 측정(내 픽셀분석 118~120 / 측정 서브에이전트 118 / 비평가 117)이 갈리지만 **well 88 은 두 측정이 일치**한다. 링대 16(4+8+4)을 더하면 Ø120 이라야 well 88 이 나온다. 117 이면 well 85 로 어긋난다. pitch 130 은 전원 일치라 gap 차이는 2px 뿐 |
| 7 | (비평가 2) 활성의 노란 안쪽 링은 원 **바깥**이다 | **불채택** | 내 반지름 프로파일과 측정 서브에이전트 둘 다 **r36~43(well 안쪽)** 으로 일치. 비평가 2 의 육안 오독. 단, 바깥 링(r60~66)도 **별도로** 존재하는 것은 맞아 그건 반영(#2) |

### 1회차에서 바로잡은 내 오류

레퍼런스 1번 슬롯을 처음에 «well 전체가 노랑»으로 구현했다가, 측정 서브에이전트의 독립 실측으로
**well 은 다른 장착 슬롯과 똑같은 파랑(`#367cc0`)이고 노랑은 well 가장자리의 링(r36~43)일 뿐**임이
확인되어 되돌렸다. (커밋 `172b028`)

| 5 | 행 전체가 레퍼런스 대비 −2px 좌측 | **타당** | `#slots{padding-left:4px}` → 좌 27 / 우 23 (레퍼런스 27.5 / 24.5) |
| 6 | **3번 슬롯이 «시안 링 + 흰 자물쇠 + 뱃지 없음»** — 대기 슬롯에 잠금 표시가 겹침 | **캡처 하네스 버그(2번째)** | 하네스가 `.empty` 클래스만 벗기고 자물쇠 DOM 은 그대로 뒀다. 게임 코드는 `buildSlots()` 에서 둘을 항상 같이 만든다. 하네스가 아이콘·뱃지까지 교체하도록 수정 |

| 8 | 컬러 링 두께 8px → 6.5px 로 줄일 것 (비평가 A) | **불채택** | 1회차 비평가 1 실측 8px, 측정 서브에이전트 8px, 내 반지름 프로파일 8px(r48~55) — 3:1 로 8px |

### 그라디언트 형태 재실측 (비평가 A·B 가 서로 달라 내가 직접 쟀다)

레퍼런스 링(r=51.5)을 시계 방향 8지점에서 ±6° 평균으로 샘플한 결과:

| 지점 | 잠금 | 대기 | 활성 |
|---|---|---|---|
| 12시 | `#b9bccb` L192 | `#25d7ff` L170 | `#ffad2a` L157 |
| 3시 | `#b8bccb` L192 | `#25d8fe` L170 | **`#ffe52c` L176** |
| 9시 | `#b8bcca` L192 | `#25d8fe` L170 | **`#fee42b` L176** |
| 4:30 | `#9fa3ba` L170 | `#06bef5` L147 | `#fd9722` L146 |
| 7:30 | `#9fa3ba` L170 | `#05bff7` L148 | `#ffc620` L162 |

→ **잠금·대기는 12시~3/9시가 완전히 평탄하고 하단만 −22 감쇠.**
→ **활성만 3·9시(세로 중앙)가 최고조**인 볼록형. 1회차 비평가 1 의 «상단이 가장 밝다» 는 오독이었다.
   (6시 지점은 하단 뱃지가 겹쳐 오염되므로 4:30·7:30 으로 판정한다)

적용한 CSS:
```css
.slot2::before      { background:linear-gradient(180deg,#25d8fe 0 50%,#04bef6 93%) }              /* 대기 */
.slot2.ready::before{ background:linear-gradient(180deg,#ffad2a 7%,#ffe52c 50%,#f89a24 93%) }     /* 활성 */
.slot2.empty::before{ background:linear-gradient(180deg,#b9bccb 0 50%,#9fa4ba 93%) }              /* 잠금 */
```
(원 위의 각도 → 세로 위치 대응: 12시 = 7%, 3·9시 = 50%, 4:30·7:30 = 93%)

### 그라디언트 각도 보정

### 불채택 — 링 두께 8px → 6px, 외곽 Ø120 → Ø117 (비평가 B)

B 는 「컬러 링 6px, 어두운 선 3/2px, 외곽 Ø116~117」이라 했으나 **자체 모순**이다.
B 자신이 `well Ø88 일치 ✓` 라고 적었는데, B 의 링 두께를 그대로 쓰면
`88 + 2×(3+6+2) = 110` 이라 자기가 말한 Ø117 이 나오지 않는다.

내 모델은 닫힌다: `88 + 2×(4+8+4) = 120`.
지지 근거도 3:2 로 우세하다 — 내 반지름 프로파일 / 측정 서브에이전트 / 1회차 비평가 1
(「외곽 Ø120, 컬러 링 8px(r48.5~55.5), 어두운 밴드 4px 2겹 — **전부 1:1 일치**」) 대 2·3회차 B.
3회차 비평가 A 도 `외곽 Ø119(+1) / well 87(+1) / gap 0 / ④ 정렬 10점` 으로 내 값을 지지했다.
→ **Ø120 / 4-8-4 유지.**

### 감점되었으나 CSS 로 고칠 수 없는 것 (아트 한계)

B 의 ⑥ 감점 근거는 **이모지 글리프 내부 형상**이었다 — 자물쇠 열쇠구멍 `8×11` vs 레퍼런스 `12×19`,
shackle 두께 `+10%/+25%`. 이는 `🔒` 글리프 자체의 모양이라 CSS 로 바꿀 수 없다.
(글리프 **바깥 치수**는 46×53 vs 46×54 로 이미 일치)
**실제 게임 아트를 넣는 시점에 자동 해소되는 항목**이라 5회차에서는 손대지 않았다.

### 노란 링 두께 — 비평가 3인이 전부 다른 값을 댔다

| 출처 | 바깥 노란 링 | 안쪽 노란 링 |
|---|---|---|
| 4회차 A | 3.5px (더 얇게) | 5.5px |
| 5회차 B | **6.5px (더 두껍게)** | 7px |
| 내 반지름 프로파일 | ? | ? |

→ 서로 정반대라 **내가 직접 밴드 패턴으로 재판정**했다.
반지름 34~69 를 «노랑 / 어두움 / 기타» 로 문자열화해 레퍼런스와 나란히 놓으니 결론이 명확했다:

```
REF: oooooYYYYY....oYYYYYYYo....YYYYYoooo
OUR: oooooYYYYY....YYYYYYYY....YYYYY.....
      34   39-43  44-47  48-55  56-60 61-65
```

**둘 다 5px** (안쪽 r39~43, 바깥 r61~65) — A 의 3.5 와 B 의 6.5 사이였다.
4회차에 A 의 지적을 따라 7px→4px 로 줄인 것은 **내 실측을 버리고 비평가를 따른 오판**이었고,
5회차에서 바로잡았다. (말단의 `oooo` vs `.....` 는 레퍼런스 배경이 물색, 우리는 어두운 게임 배경이라 생기는 차이)

### 남은 문제 (5회 안에 9점 미달 — 인계 사항)

| # | 문제 | 성격 |
|---|---|---|
| 1 | 자물쇠 열쇠구멍 `8×11` (레퍼런스 `12×19`), shackle 두께 `+10%/+25%` | **아트 한계.** `🔒` 이모지 글리프 내부 형상이라 CSS 로 불가. 글리프 **바깥** 치수는 46×53 vs 46×54 로 이미 일치. **실제 게임 아트 투입 시 자동 해소** |
| 2 | 원주 12% 구간(주로 전환 각도 부근)에서 Δ6~20 | conic 전환폭을 더 잘게 쪼개면 줄지만, 레퍼런스가 JPEG 라 경계 자체가 ±1px 번져 있어 **측정 노이즈 바닥**에 근접 |
| 3 | 슬롯 하단 «동료 머리 뱃지»(레퍼런스 Ø40~44 아트) | 캐릭터 2명 구조 미결(PROGRESS «미결» 참고). 현재는 같은 자리·지름의 레벨 뱃지로 실루엣만 맞춤 |
| 4 | 쿨타임 오버레이는 레퍼런스에 없어 대조 불가 | UI-REFERENCE ⑤ «쿨타임은 슬롯 위에 오버레이» 규정만 따름. well(88) 안쪽만 덮어 링을 가리지 않게 구현, `cap/cooldown.png` 로 동작 확인 |

> **비평가 편차 경고 (다음 워커에게).** 이 화면은 비평가 3명이 같은 항목에 서로 **모순되는** 수치를 냈다
> (외경 117 vs 119 vs 120, 노란 링 3.5 vs 6.5, 뱃지 Ø40 vs Ø51, 뱃지 중심 +47 vs +50).
> 지적이 갈리면 **비평가를 따르지 말고 직접 실측해 판정하라.** 특히 **닫히는지 검산하라** —
> `well + 2×링대 = 외경` 이 맞아야 한다. 4회차에 이 원칙을 어겨 노란 링을 잘못 줄였다.

**conic-gradient 로 바꾼 이유**: 레퍼런스 활성 링은 좌우 대칭이 아니다 —
10:30 이 `#fead2a`(어두움)인데 1:30 은 `#fee42b`(밝음)로, 빛이 **우상단에서 오는 방향성 하이라이트**다.
세로 `linear-gradient` 는 높이가 같은 두 지점을 반드시 같은 색으로 칠하므로 이 구조를 만들 수 없다.
`conic-gradient` 로 각도별 색을 직접 지정해 7개 시계 지점 전부 Δ≤5 로 맞췄다(직전 회차 최대 Δ14).
