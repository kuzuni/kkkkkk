## 2. 등가성 — 유물에는 «668 의 결손» 이 애초에 없었다. 그래도 코어를 하나로 뒀다

668 은 «묶음 경험치를 통째로 먼저» 라는 **이미 있던 결손**을 고치는 것이 본체였다.
유물 소환에는 소환 레벨·천장 축이 없고 가격도 274 로 고정 100 이라, «배치 중 레벨이 올라
확률표가 바뀐다» 는 문제가 **생길 자리가 없다**(`probe700` [4] — 수리 전에는 배치 경로 자체가 없다).

그래도 처방은 668 과 같다 — **한 장을 뽑는 코어 하나**(`relicDrawOne`)를 두고
`summonRelic`(×1)도 `summonRelicBatch`(×N)도 그 함수만 지난다:

```js
function relicDrawOne(){ S.relic -= relicCost(); … return it; }   /* 지불 + 추첨만 */
function summonRelicBatch(n, quiet){ … for(i<n) it = relicDrawOne(); markDirty/save/renderRelw; }
function summonRelic(quiet){ return summonRelicBatch(1, quiet); } /* ×1 = n 1 인 배치 */
```

등가성이 «검사로 지켜지는 성질» 이 아니라 **구조로 보장되는 항등식**이 된다. 축이 나중에
생겨도(예: 유물 소환 레벨) 두 경로가 갈라질 자리가 없다.

| 자 | 값 |
|---|---|
| `probe700` [5] ×1 100회 — **수리 전/후** | 어긋난 칸 **0/100** · 잔액 동일 (코어를 갈랐어도 ×1 은 한 글자도 안 변했다) |
| `probe700` [6][7] ×100 한 번 ↔ ×1 100번 | 잔액·소환수·레벨 **일치** · 지불 정확히 10,000 |
| `verify700` [F][F2] ×1000 한 번 ↔ ×1 1000번 | 장부 **완전 일치** · 지불 100,000 |

⚠ 재화 검사를 코어에 넣지 않았다 — 넣으면 «중간에 떨어져 절반만 뽑힌» 상태가 생겨
등가성이 조용히 깨진다. 검사는 부르는 쪽이 **한 번에**(모 아니면 도) 한다.

## 4. 경계 하나 — **탭바 레드닷은 배수를 안 탄다**

`relicSummonReady()`(×1 기준)는 탭바 «보물상자» 칸(`k === 'box'`)과 미션이 읽는 자다.
여기에 배수를 먹이면 «페이지를 열어 ×1000 을 골랐다» 는 이유로 탭바 닷이 꺼진다 —
**«화면 밖에서 배수가 보이는»** 713 [4] 와 같은 결함이다.
⇒ 화면 안 두 자리(버튼 닷 · 코스트 알약)만 실제로 낼 값(`relicMulCost()`)을 본다.
330 이 세운 «닷 ↔ `.lack` 은 같은 자의 앞뒤» 는 그대로다 — 이제 그 «같은 자» 가 배수를 탄 값일 뿐이다
(321 규약 «레드닷 = 지금 누를 수 있다» — ×1000 을 골라 놓고 못 내면 눌러도 반려되므로 닷도 꺼져야 한다).
`verify700` [I] 가 그 갈림을 한 항으로 못박는다(조각 5,000 · ×1000 → 버튼 닷 false · ×1 축 true).

## 7. 199 통지

- **뽑기 한 장당 기대값은 완전히 불변**이다(등급 확률·가격 100 모두 그대로 · `RELICS` 균등).
