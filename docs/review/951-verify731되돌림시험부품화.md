## 1. 뿌리 — `String.replace` 는 못 찾아도 조용하다

§R 은 «차단기 배선을 뺀 `pwlaunch` 사본» 을 만들어 [C] 를 다시 돌린다. 그 «빼기» 가 **문자열 상수**였다:

```js
psrc.replace(/const arm = b => evguard\.armBrowser\(armBrowser\(b\)\);/, …)
```

731 당시의 `pwlaunch.js` 는 정확히 그 한 줄이었다. 그런데 **918**(껍데기 걷개)이 같은 자리에 한 겹을 더 감쌌다:

```js
const arm = b => shell918.armBrowser(evguard.armBrowser(armBrowser(b)));   // tools/pwlaunch.js:97 (현행)
```

정규식이 안 맞고, `String.replace` 는 **못 찾아도 예외를 안 낸다** — 사본은 원본 그대로 복사되고 §R 은
«배선을 뺐다» 고 믿은 채 배선이 살아 있는 세상을 잰다. **931 과 무관**함은 등재문이 이미 대조로 못박아 두었다
(`308d4da^` 트리에서도 33/36 동일).

## 2. 처방 — 상수를 갱신하지 않았다

가장 짧은 길은 정규식을 새 줄(`shell918.armBrowser(evguard.armBrowser(...))`)로 갱신하는 것이다. **안 골랐다.**
그 길은 **다음에 또 누가 감싸면 똑같은 얼굴로 조용해진다**(918 이 이미 한 번 그랬다 — 726·902 계열의 «상한이 아니라 열 수» 와 같은 꼴).
등재문의 처방 그대로 두 갈래로 갈랐다.

### ① 배선 제거를 «정규식» 이 아니라 «부품» 으로

사본은 이제 `pwlaunch` 의 소스를 만지지 않는다. `evguard731` 을 **require 캐시에서 가짜로 갈아 끼운 뒤** `pwlaunch` 를 부른다:

```js
const real = require('./evguard731');
require.cache[require.resolve('./evguard731')].exports = Object.assign({}, real, {
  armBrowser: b => { fs.appendFileSync(MARK, 'armed\n'); return b; },
});
module.exports = require('./pwlaunch');
```

`arm` 이 몇 겹으로 감싸이든 배선은 걷힌다 — `armBrowser` 가 `install()`(마감 훅)까지 혼자 쥐고 있어서
**부품 하나를 갈면 차단기가 통째로 꺼진다**(`tools/evguard731.js` 146~163행).

### ② «치환이 실제로 일어났는가» 를 먼저 단언한다

- **[R1] 이 표식으로 바뀌었다** — 가짜 `armBrowser` 가 불릴 때만 `.v731-armed-<pid>.txt` 가 생긴다.
  «갈아 끼운 부품이 **그 자리에서** 불렸다» 는 것이 곧 «배선이 실제로 걷혔다» 다. 배선이 통째로 사라지면 표식이 안 생겨 **[R1] 이 빨개진다.**
- **남은 치환 한 자리에는 문(`sub()`)을 세웠다** — 사본 자의 `require('./pwlaunch')` 를 바꾸는 자리다.
  못 찾으면 조용한 no-op 대신 그 자리에서 죽는다: `Error: [951] 치환 실패 — 찾는 문자열이 없다: …`.
- 덤으로 **사본 청소를 종료 훅으로 옮겼다** — `sub()` 이 도중에 죽는 길이 생겼는데 청소가 본문 끝에만 있으면
  `tools/.v731-*` 가 남는다(실제로 사보타주 C 실행이 6개를 남겼다).
