### ★ 핵심: A2-① 부채가 A1 에서 그대로 재발했다

A1 은 1차 라운드에서 **칸마다 다른 `font-size`** 로 아이콘 bbox 를 레퍼런스 스프라이트에 맞춰 놨다.
그런데 그 뒤 **24**(모험 → «던전» ⚔️)·**88/89**(성장 → «훈련», 보물상자 → «유물» 🔮)가
**칸 내용을 갈아 끼우면서 역산값을 그대로 뒀다.** r6 실측(측정표 §4 대비):

| 칸 | ref bbox | r6 실측 | 오차 |
|---|---|---|---|
| 영웅 🐾 | 121×121 | 117×109 | −3.3% / −9.9% |
| 훈련 ⚒️ | 150×100 | 128×127 | −14.7% / **+27.0%** |
| 던전 ⚔️ | 109×120 | 112×112 | +2.8% / −6.7% |
| 유물 🔮 | 125×96 | 94×115 | **−24.8%** / +19.8% |
| 상점 🏪 | 165×115 | 130×133 | **−21.2%** / +15.7% |

비평가 2인이 독립적으로 같은 자리를 짚었다 — G 는 «3칸 아이콘 폭 −24% · 5칸 상점 −15% ·
1칸 잉크 매스 높이 −36%», H 는 ② 5 점.

**1차 라운드 A1 이 «이모지는 가로세로가 같이 커져 가로로 넓은 아트(상점 165×115)를 재현할 수 없다»
며 아트 대기로 남긴 것은 틀렸다.** A2 가 쓴 방법 — **높이는 `--sf`(font-size), 폭은 `--sx`(scaleX)로
가르는 것** — 이 그대로 통한다. ROUTINE [3]-(나) «아트 자리 규칙»(레퍼런스 bbox 를 정확히 차지하게
만들어 두면 나중에 이미지로 교체만 하면 된다)이 요구하는 형태이기도 하다.

역산식: `--sf = 지금 fs × ref높이 / 실측높이` · `--sx = ref폭 / (실측폭 × ref높이 / 실측높이)`

## 이번 라운드에 «측정표가 틀렸다» 고 판정한 것 2건

### (1) §7 NEW 리본 bbox — **주황 아이콘을 물었다**

원 측정 «x864–1027 (w164) · y2163–2253 (h91)» 의 빨강 마스크가 느슨해
(`r>90 · r−g>40 · r−b>30`) **주황 (248,147,33) 도 통과**시켰고, `x1009..1025` 의 **상점 가게 아트**가
리본 오른쪽 끝으로 잡혔다. 초록을 묶은 마스크(`r>80 · g<95 · r−g>55`)로 다시 재면
**x864–980 (w117) · y2163–2241 (h79)**. 측정표 §7-1 에 정오표로 남겼다.

### (2) 레드닷 ⌀ — «화면 전체 Ø24~25 통일» 은 탭바에 해당하지 않는다

`LESSONS 02-4` 는 **메뉴·배너** 레드닷을 재고 «화면 전체에서 Ø24~25 로 통일» 이라고 적었는데,
탭바 레드닷은 그렇지 않다. `docs/ref/02` 에서 칸 중심을 지나는 **세로 단면**으로 3칸을 다시 재니
**전부 외곽 41 (y2161..2201) · 빨강 코어 31~32 (y2164..2195)** 로 측정표 §6 과 정확히 일치했다.
비평가 2인도 독립적으로 «ref 코어 29~32 / 외경 41~42, 우리는 −20~27%» 로 봤다.
→ LESSONS 의 «게이트의 상수는 «레퍼런스 실측» 과 «통일 상수» 를 갈라서 다뤄라» 에 해당하는 자리다.

## 이번 라운드에 «비평가가 틀렸다» 고 판정한 것

- **«라벨 잉크 높이가 +44%»** — 내 첫 스캔이 낸 허수다. 차분은 **검정 외곽선(6px)까지** 잡는데
  측정표 §3 의 «잉크 높이 32» 는 **흰 코어** 값이다. 코어로 환산하면 33~34 vs 32 = **+3~6%** 로
  사실상 일치한다(비평가 H 도 «흰 코어 높이 ref 32 vs 우리 32/33 — 일치» 로 독립 확인).
  `scanA1.py` 가 이제 코어로 환산해 찍는다.
- **«유물 라벨 폭 −50%»** — ref 는 «보물상자»(4자 121px), 우리는 «유물»(2자)이다. **대조 자체가
  성립하지 않는다.** 폭을 비교할 수 있는 칸은 ref 와 같은 단어인 **영웅·상점 둘뿐**이다
  (영웅 +10.7% / 상점 +1.7%). 스캐너가 나머지 칸에 «개칭 — 대조 불가» 를 찍게 했다.
- **«✕ 칸 폭 296 → 301»**(H ④) — ref 3장 실측이 296/299/297 이고 측정표 설계값이
  «296 + 196×4 = 1080» 으로 딱 떨어진다. 301 로 올리면 합이 1085 가 되어 그리드가 깨진다. 유지.

`node tools/smoke.js | tail -2 && git push ...` 로 묶었더니 **파이프가 smoke 의 종료 코드를 가려**
`SMOKE FAIL` 인 채로 push 가 나갔다(커밋 `3730eac`, 다음 커밋에서 복구). **게이트는 출력이 아니라
종료 코드로 확인한다** — `node tools/smoke.js > 파일; echo $?` 형태로 돌릴 것.

실패 내용 자체도 남길 만하다: CSS 주석 안에 «210/211/211/211/» 뒤에 마크다운 강조 별표 두 개를
붙였더니 **슬래시+별표가 여는 주석 기호로 세어져** smoke [0] 의 주석 균형 검사가
«여는 1695 vs 닫는 1694» 로 FAIL 했다. 렌더링은 멀쩡하지만(주석은 첫 닫는 기호에서 끝난다)
게이트가 «규칙이 조용히 사라지는» 사고를 잡으려고 세는 값이라 실제 결함으로 취급하는 게 맞다.
