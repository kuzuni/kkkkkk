## 1. 재현이 먼저다 (338 규칙)

등재문의 가설을 **그대로 확인**했다(338·341 처럼 기각되지 않았다). 다만 등재문이
«확정하지 않았다» 고 남긴 축 — «갈린 것은 부하·머신 속도로 보인다» — 은 **재현이 정정했다**(§2).

| 조건 | C8 결과 |
|---|---|
| 단독 실행 (수리 전) | `VERIFY169 62/62 PASS` · 40.0초 |
| **5병렬 × 5판 (수리 전)** | **13/25 FAIL (52%)** |
| 5병렬 × 5판 (수리 후) | (§4 표) |

실패 로그는 **예외 없이 같은 모양**이었다 — 그리고 이것이 진단의 전부다:

```
FAIL C8 … — «36.9A» → «36.9A» (S 36.9A)     ← 실패 판 13건 전부
PASS C8 … — «24.6A» → «36.9A» (S 36.9A)     ← 통과 판은 12.3A · 18.4A · 24.6A · 30.7A
```

**값은 내내 옳다**(`S` 도 36.9A, C2 가 같은 판에서 지급액을 정확히 확인한다). 통과한 판이 집은
«시작값» 은 0 이 아니라 **12.3A·18.4A·24.6A·30.7A** — 즉 **롤 한복판**이다. 옛 축은
«HUD 가 굴러가는 것을 봤는가» 를 묻는다고 적혀 있었지만 실제로는
**«내 샘플이 롤보다 빨랐는가»** 를 물었다. 그건 제품의 성질이 아니라 **자의 운**이다.

## 2. 뿌리 — «부하가 롤을 빠르게 한다» 가 아니다. 부하가 **샘플을 늦춘다**

등재문은 갈린 축을 «부하·머신 속도» 로 짐작하고 확정을 미뤘다. `probe649` **§3**(단독·결정론적)이
그 자리를 정확히 메운다.

```
롤 자취 — 1ms«0» → 545ms«6.14A» → 682ms«12.3A» → 819ms«18.4A»
          → 967ms«24.6A» → 1125ms«30.7A» → 1272ms«36.9A»
```

- 롤(58 재화 흡수 `fxVal`)은 **약 1.27초** 만에 정착한다. 옛 자의 **명목** 대기는 클릭 + **500ms** 다.
- ⇒ **부하가 없으면 500ms 시점의 표기는 아직 «0»** 이고, 그 뒤 `waitForFunction` 이 정착을 기다리는
  동안 값이 굴러 올라 `txt !== hudStart` 가 참이 된다. **단독 실행이 늘 통과하는 이유가 이것이다.**
- 부하에서 빨라지는 것은 롤이 아니라 **자의 시계**다. 옛 자는 클릭 뒤 `evaluate`(`after` 7필드) →
  `waitForTimeout(500)` → `evaluate`(hudStart) 를 거치는데, 5병렬에서는 CDP 왕복 하나하나가 늘어져
  **«500ms» 가 벽시계로 1.3초를 넘긴다.** 그 순간 시작값 = 정착값이 되고 축은 거짓이 된다.

`probe649` **3-c** 가 이 메커니즘을 **부하 없이 결정론적으로** 못박는다 — 롤이 끝난 뒤에 «시작값» 을
읽으면 «36.9A» = «36.9A» 로 옛 축이 **제품이 완벽한데도** 거짓이 된다.

⚑ **638·645 와 같은 계열이다** — «부하에서만 죽는 자». 638 은 `verify102` 의 고정 대기 900ms 였고,
645 는 `verify69` 가 «닫혔나» 대신 «퇴장 연출이 끝났나» 를 재고 있었다. 셋 다 **자가 벽시계를
가정**했고, 병렬이 그 가정을 깼다.

## 3. 처방 — 항을 빼지 않는다. **읽는 시점**을 옮긴다

무른 수리 두 가지를 먼저 반려했다(334·643 규약).

| 반려안 | 왜 반려인가 |
|---|---|
| `hud.txt !== hudStart` 항을 뺀다 | **HUD 가 아예 안 움직여도 초록**이 된다 — «다른 화면에 반영» 이라는 C8 의 뜻이 통째로 사라진다 |
| 대기(500ms)를 늘린다 | 638 이 이미 겪은 길이다. 부하가 더 세지면 같은 자가 같은 자리에서 다시 죽는다 — 상수를 키우는 것은 진단이 아니다 |

**고친 것은 한 줄의 자리다.** `hudStart` 를 지급(클릭) **앞**에서 읽는다.

```js
const hudStart = await p.evaluate(() => …'goldN'.textContent); /* 649-ANCHOR-PRE */
const paid = await p.evaluate(() => { const g0 = S.gold; …click(); return S.gold - g0; });
```

두 가지가 같이 좋아진다.

- ⓐ **롤이 언제 끝나든 축이 산다.** 기준선이 롤 밖에 있으므로 부하와 무관하다.
- ⓑ **뜻이 또렷해진다.** 로그가 «24.6A → 36.9A»(우연히 집은 중간값)에서 **«0» → «36.9A»** 로 바뀐다.
  읽는 사람이 «지급 전 → 지급 후» 를 그대로 본다.

643 이 C2 에서 한 것과 **같은 처방**이다(«기대값을 고쳐 적는 재기준은 반려 — 고칠 것은 자의 측정 방식»).
같은 블록에서 한 칸 아래 자리만 그 규약을 못 받고 있었다.
