## 1. [B2] — 치환문이 «리터럴» 이라 809 가 지나가자 조용히 no-op 이 됐다

`verify566` [B2] 는 **되돌림 시험**이다: 축 ⓒ 를 걷어낸 `verifyProgress` 사본이 같은 합성 표에서
초록이어야 [B] 의 빨강이 «ⓒ 의 것» 임이 증명된다. 566 은 그 «걷어내기» 를 한 줄 리터럴로 적었다:

```js
src.replace('  const cells = cellsOf(line);', '  continue;   /* … */\n  const cells = cellsOf(line);')
```

**809 가 축 ⓓ 범위를 넓히면서 그 줄을 `const impl = cellsOf(line)[3];` 로 갈아 끼웠다.**
`String.replace` 는 못 찾으면 **예외도 경고도 없이 원본을 그대로 돌려준다** — 그래서

* 사본 = 본체 ⇒ [B2-0] «사본이 실제로 달라졌다» 빨강
* 사본이 축 ⓒ 를 그대로 지닌 채 [B] 와 **같은 표**를 도니 code 1 ⇒ [B2-a] 빨강
* [B2-b] 는 앞의 둘의 논리곱이라 같이 빨강

셋이 **한 덩어리로** 빨간 것이 등재문이 짚은 «축 ⓒ 를 걷어내는 치환문이 본체와 안 맞는다» 다 — 정확했다.

### 처방 — 앵커를 **본체에서 파생**시킨다 (861·960 [R] 선례)

축 ⓒ 자신의 이름(`kind: 'mute'` 를 미는 줄)으로 찾고, **정확히 한 줄일 때만** 믿는다.

```js
const MUTE_PUSH = /^[ \t]*contra\.push\(\{[^\n]*kind: 'mute'[^\n]*\);[ \t]*$/gm;
const anchors = src.match(MUTE_PUSH) || [];
const cut = anchors.length === 1 ? src.replace(MUTE_PUSH, '  continue;   /* … */') : src;
ok('[B2-0] … «정확히 한 줄» 찾아 걷어냈다', anchors.length === 1 && cut !== src, '앵커 ' + anchors.length + '줄');
```

⚑ **«한 줄일 때만» 이 이 수리의 핵심이다.** 0줄이면 다시 no-op 이고 2줄 이상이면 축을 덤으로 더 걷어낸다 —
둘 다 [B2-0] 이 «앵커 n줄» 이라는 **이름을 달고** 빨개진다. 다음 번 809 가 와도 이 절은
«조용한 초록» 이 아니라 «앵커가 썩었다» 로 말한다.

### 잠복 2호 — 648 이 이름을 반만 고쳤다

같은 절에 **앵커가 멀쩡해도 터질 자리**가 하나 더 있었다. 648(«고정 이름 임시 사본 전수 수리»)이

+  const cutPath = path.join(ROOT, 'tools', `.v566-cut-${process.pid}.js`);

치환문 수리에 가려 안 보이던 자리라 같이 고쳤다(`cutName` 한 곳에서 짓고 둘이 읽는다).

## 2. [P-a] — `probe566` [4-e]. 갈래가 둘이고 하나는 **상수가 틀렸다**

`probe566` 은 «수리 전» 사본을 **커밋 메시지 그물**로 고른다(573 이 «움직이는 ref» 를 고정 커밋으로 바꾼 자리).
[4-e] 는 그 그물의 건강을 묻는다 — «고른 ref 의 **바로 다음** 커밋이 `wip(566)` 인가».

### ⓐ 폴백 SHA 가 `wip(566)` 의 부모가 아니었다 (진짜 결함)

566 이 적어 둔 폴백은 `842dc2f` = **`claim(566)`** 이고 주석도 «566 의 수리(wip) 직전» 이라고 적혀 있다.
실측하면 **그 커밋의 다음은 `wip(491)`** 이다. 진짜 부모는 **`9104a067`(`wip(567): 문서 …`)** 이다.

⚑ **번호는 시간 순서가 아니다** — 워커 넷이 병렬로 도니 566 의 이웃 커밋이 566 의 것일 이유가 없다.
«같은 번호가 붙은 커밋이니 이웃일 것» 이라는 눈대중이 상수를 만들었다.

그런데도 이 상수는 **[4-a]~[4-d] 를 전부 통과했다** — `claim(566)` 도 수리 **전**이라 553 이 아직 8칸이었기 때문이다.
**[4-e] 만 그 어긋남을 짚는다.** 이것이 [4-e] 가 존재하는 이유이고, 등재문이 «별개 갈래일 수 있다» 고 한 그 갈래다.

### ⓑ 얕은 클론에서는 그 폴백이 **HEAD 의 조상조차 아니다** (환경)

루틴 컨테이너의 클론은 얕다 — **착수 실측 211커밋(≈ 2026-09-02 이후)** 이라 566(08-31)이 창 밖이다. 그러면

1. 그물(`rev-list --grep`)이 **창 안**만 훑으므로 조용히 미끄러져 폴백으로 내려앉고,
2. 폴백 SHA 는 `gitrev756` 이 **객체만** 데려오므로 `git show` 는 되지만 HEAD 의 조상이 아니다(이식된 뿌리),
3. `rev-list --ancestry-path <ref>..HEAD` 가 **0줄** ⇒ 다음 커밋이 `?` ⇒ [4-e] 빨강.

실측으로 갈랐다 — `git fetch --shallow-since=2026-08-30 origin main`(24초 · 이력 211 → **3,310커밋**) 뒤
그물이 `wip(566)` 을 물고 [4-e] 가 곧바로 초록이 됐다. **자의 결함이 아니라 환경이다.**

### 처방 — 파지 않는다. 갈라서 말한다 (756 규약 ②)

756 규약 ①(«판는 것이 먼저다»)을 여기서 **일부러 안 따랐다.** 값이 비싸기 때문이다:

> 566 시대까지 넓히면 이력이 **211 → 3,310커밋**이 되고, `verifyProgress` §1 은 **done() 커밋마다**
> `git show <sha>:docs/PROGRESS.md`(220KB)를 돈다. 그 커밋 수가 **102 → 500(약 5배)** 로 늘어
> 실측 `verifyProgress` 한 번이 **6.2초 → 88초(약 14배)** 가 됐다. 이 자는 **모든 워커의 push 전 게이트**라
> (지시서 [4]) 재현기 하나가 저장소 전체의 push 를 14배 느리게 만드는 것은 값이 안 맞는다.
>
> ⚑ **이것은 추측이 아니라 이 회차가 실제로 밟은 자리다** — 넓힌 채로 돌린 `verify566` 은
> **[P-c] 회귀 `verify388` 이 `code null`**(= `execFileSync` 의 600초 timeout 이 SIGTERM 으로 죽였다)로

> `git fetch --depth=211 origin main` 으로 창을 **되돌리고** 그 상태에서 최종 점수를 냈다
> (되돌린 뒤 이력 196커밋 · 객체는 남아 있고 조상 관계만 없다 = **착수 시점과 같은 조건**).

⇒ [4-e] 는 **이력이 닿을 때만** 재고, 안 닿으면 갈린다:

| 상태 | 판정 |
|---|---|
| `ancestry-path` 가 있다 | 지금까지처럼 **다음 커밋 제목**을 본다(그물이 본문 인용을 안 물었는지) |
| 길이 없다 · **얕은 클론** | **⏸ 보류(환경) — 세지 않는다.** 줄에 처방 한 줄(`git fetch --shallow-since=<날짜> origin main`)을 **날짜까지 파생해서** 찍는다 (938 «적힌 명령 한 줄이 곧 처방») |
| 길이 없다 · 얕지 않다 | **빨강** — 고른 ref 가 진짜로 HEAD 의 조상이 아니다 |

### [4-f] 신설 — 안 쓰이는 동안 상수가 썩는 것을 막는다

ⓐ 가 오래 숨어 있던 이유는 **그물이 도는 환경에서는 아무도 폴백을 안 쓰기 때문**이다(그 침묵이 964 의 뿌리다).
⇒ 이력이 닿는 환경에서는 **폴백 상수 자신**을 그물의 답과 대조한다:

```js

```

이 항이 있었으면 566 의 잘못된 상수는 **등재 당일에** 빨갰다.
