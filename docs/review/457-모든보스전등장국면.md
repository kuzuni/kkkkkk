## §2 처방 — «모드마다 국면» 이 아니라 **국면 하나에 모드가 넷**

### 2-1 상수·상태를 승격했다 (`DUN_` → `BOSS_`)

```
BOSS_INTRO_PAN  = 0.35   플레이어 → 보스 편도 팬      (425 값 그대로)
BOSS_INTRO_STAY = 0.70   보스에 머묾
BOSS_INTRO_BACK = 0.35   보스 → 플레이어 편도 팬
bossIntroLen() = 1.40s
let bossIntro = null     { md, t, e, p, c } — md = 'dun'|'stage'|'promo'|'raid'
```

⚑ **모드별 값을 두지 않았다.** 주인 원문이 «던전 **지금 보스 전 하듯이**» 라 길이·이징이 갈리면 그 자체가
지시 위반이고, 값이 넷이 되면 «어느 하나가 반드시 어긋난다»(LESSONS 58-①). `verify457` **[G-d]** 가
`STAGE_INTRO_*`·`PROMO_INTRO_*`·`RAID_INTRO_*` 를 **이름째** 0건으로 못박고, **[C-b]** 가 세 모드의 국면
프레임 수를 던전과 **±1프레임**으로 묶는다.

### 2-2 **시계를 모드마다 멈추지 않았다** — 이것이 이 작업의 본체다

등재문 ③ 은 «국면 동안 타이머 정지(`bossT`·`promo.t`·레이드 시계)» 였다. 그대로 적으면 **다섯 자리**가 되고
그 중 하나는 반드시 빠진다. 실제로는 **한 자리도 안 적었다** — 425 가 만든 배타적 상태 블록이 `step()` **맨 위**에
있고 네 시계의 감소가 전부 그 아래에 있기 때문이다:

```
step(dt){
  if(bossIntro && bossIntro.md !== bossMode()) bossIntroEnd();   // 안전망(아래 2-4)
  if(bossIntro && !(dunRun && dunRun.bossDown)){ … return; }     // ← 여기서 프레임을 통째로 가져간다
  …  bossT -= dt  /  raidT -= dt  /  promo.t -= dt  /  dunRun.t -= dt  는 전부 이 아래
}
```

425 가 «타이머 체인이 아니라 상태 하나» 로 지은 덕에 **모드를 늘리는 비용이 0줄**이었다. `verify457` §A 가
세 모드 각각 «국면 동안 Δ0 · 국면 끝 **다음** 프레임부터 감소» 를 따로 묻는다.

### 2-3 스테이지만 **한 자리 더** 필요했다 — 스폰 딜레이 1.4초

던전은 `dunRun.fight` 가 서야 `t` 가 깎이지만 28 에는 그런 깃발이 없어서 예약과 동시에 시계가 돌았다.
새 깃발을 만들지 않고 **전장에서 읽는다**:

```
if(bossT > 0 && !promo && !bossIntro && (bossT < BOSS_SEC || enemies.some(e => e.tk === 'boss')))
```

* `!bossIntro` — ⚠ **한 프레임 때문에 필요하다.** 국면이 열리는 프레임은 이미 스폰 큐(위)를 지나
  여기까지 내려오므로, 이 항이 없으면 «보스가 선 프레임의 시계 14.983» 이 된다(1회차 `verify457` [A-a] 실측).
* `bossT < BOSS_SEC ||` — ⚠ **«지금 필드에 있는가» 로만 두면 안 된다.** 보스가 격파가 아닌 경로로 사라진 판에서
  시계가 영영 멈추고 `bossOn` 이 안 풀려 **다른 전투 입장이 453 가드에 영원히 막힌다**. «이미 한 프레임이라도
  흘렀다» 는 시작값이 정확히 `BOSS_SEC` 라는 사실에서 그냥 나온다(새 상태 0개).

승급전·레이드는 스폰 딜레이가 없어(둘 다 그 자리에서 `enemies.push`/`makeEnemy`) 가드가 필요 없다.

### 2-4 국면이 «자기 전투보다 오래» 못 산다 — 안전망 한 줄

`if(bossIntro && bossIntro.md !== bossMode()) bossIntroEnd();`

런이 포기·실패·클리어로 사라지거나 모드가 갈리면 국면도 그 프레임에 닫힌다. **새 상태를 안 만들고**
453 이 세운 단일 판정 `bossMode()` 에 물어본다. 이 한 줄이 없으면 국면이 남은 채 블록이 매 프레임
`return` 해 **게임이 통째로 멈춘다** — 배타적 상태를 모드 공용으로 올릴 때 가장 값비싼 실패 모드다.
`camUpdate` 는 언제나 `step` **다음**에 돌므로(loop 34262 → 34282) 카메라가 한 프레임도 뒤처지지 않는다.

### 2-5 425 의 이름을 **얇은 접근자로 남겼다** (등재문 ①의 두 갈래 중 이쪽)

`dunRun.introOn`·`introT` 를 `Object.defineProperties` 로 `bossIntro` 에 이어 붙였다. 이유는 하나다 —
**던전 계열 게이트·재현기 아홉**(`verify255`·`verify273`·`verify425`·`verify442`·`verify458`·`probe425`·
`probe442`·`probe458`·`cap425`)이 이 이름으로 «지금 국면인가» 를 읽고, 그 이름을 지우면 아홉이 국면을
**0프레임으로 읽고 조용히 초록**이 된다(헛초록 — 425 의 보장이 통째로 증발한다). 쓰기(`introOn = false`)는
«국면을 닫는다» 는 뜻이라 `bossIntroEnd()` 한 곳으로 모았다. `verify457` [G-f] 가 그 접근자를 지킨다.

### 2-6 안 한 것

* **아레나(123) 제외** — 상대가 보스가 아니라 «같은 급 대전자» 다(지시 ⑥). 실측은 §1 마지막 줄.
* **108 폐기 연출 부활 0줄** — 늘어난 것은 «목표 좌표를 섞는 팬» 하나뿐이고 `cam` 필드는 {x,y,z,shake} 그대로다
  (`verify425` §G · `verify457` [B-f]).
* **밸런스 계수 0줄** — 값을 바꾸지 않았다. 다만 §6 의 이관 한 줄을 199 에 남긴다.
* **스테이지 «파밍»(`S.bossFarm`)에는 국면 없음** — 잡몹 파도라 `tk === 'boss'` 가 아니다. [재도전]은
  `startBoss()` 를 다시 타므로 **새 보스전 = 새 국면**이 맞다(주인 원문 «모든 보스전»).

### 5-1 이관을 «항을 눌러» 하지 않았다 (LESSONS 328)

두 게이트가 빨개진 이유는 하나다 — **«등장 국면은 던전만의 것» 이라는 전제**가 457 로 깨졌다.

* `verify425` **§C** 는 «28·46·승급전은 국면 0회 · 카메라 108 그대로» 를 물었다. 0 → 1 로 고치기만 하면
  «457 이 통째로 사라져도 초록인 게이트» 가 된다. 그래서 같은 자리에서 **새 질문 셋**을 한다:
  ① 세 모드에서 국면이 실제로 돈다 ② **아레나는 0회**(425 가 지키던 «범위가 있다» 는 성질이 여기로 옮겨 왔다)
  ③ 국면 **밖** 에서는 카메라가 108 그대로다. ⚠ 종전 §C 는 모드를 갈아탈 때 전장을 안 되돌려
  **`battleBusy()`(453)에 막힌 채로도 초록**이었다(승급전 표본이 그랬다) — 하네스에 `reset()` 을 세워 그것도 닫았다.
* `verify108` 은 «클램프 밖에서 카메라–플레이어 60px 초과 프레임 0» 이다. 상한을 올리는 것은 108 을 무르게
  푸는 것이라 **국면 창을 세어서 따로 묻는다**: `[457]` 두 항이 «그 창이 실제로 있고(0이면 빨강)» ·
  «상수 길이를 안 넘는다» 를 각각 묻는다 ⇒ 이탈을 핑계로 게이트를 넓힌 것이 아님이 매 실행 확인된다.
* `verify425` **[D-d]** 는 값이 아니라 **재는 법**을 고쳤다. «2번째 보스 구간에 시간이 흐른다» 를 루프가
  끝난 뒤 `dunRun.t` 로 재고 있었는데, 그 값은 «런이 그때까지 살아 있었나» 에 걸린다 — 2번째 보스는
  145~180프레임에 죽는 판이 흔해서(재현 12/12) 런이 먼저 사라지면 «0초» 로 읽혔다. 질문은 그대로 두고
  매 프레임 최솟값으로 낙차를 누적하게 바꿨다(2회 연속 초록).

## §6 199 이관 (밸런스)

계수는 **한 줄도 안 건드렸다.** 다만 세 모드의 «실제로 때릴 수 있는 시간» 이 늘었다:

| 모드 | 수리 전 유효 시간 | 수리 후 | 차이 |
|---|---|---|---|
| 28 스테이지 보스 | 15.0 − 1.400(스폰 딜레이) = **13.60s** | **15.00s** | **+10.3%** |
| 승급전 | 15.0 − 0.017 = 14.98s | 15.00s | +0.1% |
| 46 레이드(측정장) | 30.0 − 0.017 = 29.98s | 30.00s | +0.1% |

· **28 이 +10.3% 쉬워진다** — 425 가 던전에서 만든 것과 **같은 크기·같은 방향**이다(던전 13.6 → 15.0).
  되돌릴 지렛대는 `BOSS_SEC` 가 아니라 보스 체력 배수 쪽이다(28 은 `eHp(s)*22`, 승급전은 `eHp(s)*BOSS_SEC`).
· **레이드는 «측정» 이라 이 방향이 특히 맞다** — 264 가 «1.4초 스폰 딜레이는 안 쓴다» 고 적은 이유
  («30초 만에 넣은 피해» 를 재는 판)가 그대로 국면에도 적용된다. 국면이 시계를 멈추므로 기록이 안 흔들린다.
