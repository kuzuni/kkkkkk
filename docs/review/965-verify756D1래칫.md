## 2. 두 자가 **서로 다른 이유로** 진다 — 그래서 처방도 갈린다

756 교훈 ② 의 반복이다. 같은 부품 뒤로 옮기되 «못 꺼냈을 때» 의 답이 다르다.

  얕은 클론이든 **오타든 지워진 커밋이든 똑같이 조용히 넘어간다**. 756 교훈 ③ 이 금지한 반쪽 처방이다.
* **`probe888`** — SHA 가 argv 라 **오타가 정상 입력만큼 흔하다**. 옛 코드는 `execFileSync` 가 던지면

  (756 머리말이 말한 «게이트 부패와 똑같은 얼굴» 이 여기선 자기 자신에게 일어난다).

## 3. 처방 — 부품 뒤로 옮기고, **갈림을 짝으로 넣는다**

`tools/gitrev756.js` 의 `show()` 는 «판는 것이 먼저 · 못 팠을 때만 갈린다» 를 이미 갖고 있다.
호출부는 그 갈림을 **버리지 않고 그대로 쓴다**.

```js
const g = G756.show(BASE, 'tools/verify188.js', { … });
if (g.how) …                       // 조용히 성공하지 않는다(어떻게 팠는지 남긴다)
if (!old && g.env)  skip++;        // ⏸ 보류 — 세지 않는다
else if (!old)      ok(false, …);  // 얕지 않은데 없다 = 진짜 빨강 (안전핀)
```

* `probe760` — `skip` 은 남기되 **`env` 일 때만**. 아니면 `[1-0]` 으로 **빨개진다**.
  합계 줄 문구도 «건너뜀(얕은 클론)» → «⏸ 보류 n건(환경/얕은 클론)» 으로 756 규약 문구에 맞췄다.
* `probe888` — 대상마다 갈린다: 환경이면 그 대상만 ⏸ 보류하고 계속, 진짜 없으면 `✗` 로 세고
  **종료 코드 1**. 합계 줄 `PROBE888 대상 n건 · ⏸ 보류 k건 · ✗ m건` 을 신설했다.
  (`git log -1 --format=…` 은 `git show` 가 아니라 그대로 뒀다.)

## 4. 래칫을 **조인** 것이 이 회차의 나머지 절반

D1 은 «직행이 있으면 빨강, 단 부품을 `require` 하면 면제» 다. 그 면제에 구멍이 둘 있었다.

* **구멍 ①: `require` 만 얹고 직행을 남기면 초록이다.** ⇒ **[D2b] 신설** — 부품에 위임한 다섯 자
  (`probe708`·`539`·`716`·`760`·`888`)는 `git show` **직행이 한 자리도 없어야** 한다.
  ⚠ `probe356r23` 은 **일부러 뺐다** — 그 자는 `digPre()` 로 **판 뒤에** 직접 꺼내는 것이 설계이고
  `verify631` A7 이 그 위임을 지킨다. 직행이 남아 있는 것이 정상이다.
* **구멍 ②: 스캐너 자신이 헛초록일 수 있다.** 「부품 밖 0개」는 **아무것도 안 잡아도** 초록이다.
  ⇒ **[D3] 신설** — 스캐너 세 줄을 그대로 떼어 네 표본에 물린다: 문자열 꼴 직행을 잡는가 ·
  **배열 꼴** 직행을 잡는가(756 교훈 ① 이 통째로 놓쳤던 꼴) · 부품을 문 자는 안 잡는가 ·
  **주석뿐인 인용**은 안 잡는가(`codeOf` 가 살아 있는가).
  ⚠ 파일을 안 쓰고 **문자열로** 되돌린다 — 951 «되돌림 배선을 문자열로 들면 조용히 no-op» 의 반대쪽이라,
  여기서는 수술 대상이 옮겨 가도 표본이 자기 안에 있어 no-op 이 안 된다(756 교훈 ④).
* **[D2] · [E] 목록 이관** — D2 에 `probe760`·`probe888` 두 줄, E(보류가 조용하지 않다)에 `probe760` 을 넣었다.
  ⚠ `probe888` 은 E 에 **안 넣었다** — 점수를 안 내는 «표 찍는 자» 라 보류가 초록에 섞일 자리가 없다.
