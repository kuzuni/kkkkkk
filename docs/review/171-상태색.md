## 2. 고친 곳

### ① 원인 (실측)

`.sk-b2`(`index.html` ~8889)는 `color:#DFDFDF;--hl:#D3D3D3` + 회색 그라디언트로 **하드코딩**돼 있었고,
`renderCos()` 의 버튼 마크업(~22102)은 상태 클래스를 **아예 안 붙였다.** 즉 상태 분기가 없었다 —
다이아가 넘쳐도, 조건을 다 채워도, 이미 사 놨어도 **똑같은 회색** 이었다.

### ② 처방 — 자리와 색을 분리

`.sk-b1/.sk-b2` 는 이제 **자리(left)와 기본 배색**만 정하고, «지금 되는가» 는 `.ok`(초록) / `.no`(회색)가 덮는다.
같은 `.sk-btn` 부품을 쓰는 **07 스킬 · 26 동료 · 50 코스튬** 세 시트가 한 벌로 움직인다.

| 화면 | 버튼 | 초록(가능) 조건 | 회색 |
|---|---|---|---|
| 50 코스튬 시트 | **[구매]** | 미보유 + `cosReqOk` + `S.dia >= cost` | 부족 · 조건 미달 · 이미 보유 |
| 50 코스튬 시트 | **[착용]** | 보유 + 착용 중 아님 | 미보유 · 이미 착용 중 |

### ③ 레이아웃은 한 값도 안 건드렸다

색조만 얹었다. 그라디언트 **정지 위치**(9/11/101/103/109 · 11/101/107/115), 링 7px, 굽 6px,
버튼 좌표·크기는 그대로다. 게이트가 매 실행 확인한다:

* 50 시트 — `240 / 551`, `275×131`, `top 1158`
* 05 팝업 — `137 / 447`, `274×131`, `top 1184`

`.sk-act .sk-u` 주석의 «레퍼런스도 재료가 모자란데 강화는 회색 원색 그대로» 는 여전히 맞다 —
**레퍼런스가 찍힌 그 상태(부족)** 에서는 지금도 회색이다. 초록은 «가능» 일 때만 새로 뜬다.
