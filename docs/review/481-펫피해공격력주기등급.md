## 2. 무엇을 고쳤나 (제품 6자리)

1. **`petDmg`** — `stat.dmg * p.m * gWear(p.g) * lvWear(oLv(p.id)) * bonus().pet` → **`stat.dmg * bonus().pet`**
2. **`PET_M` 표 삭제** · `PET_NAMES` 36칸의 `m`·`cd`·`v` 필드 **전부 삭제**(구 9종 오버라이드 포함)
3. **`PET_CD` 를 식으로** — `1.30 × (0.40/1.30)^(g/7)` = `[1.30 1.10 0.93 0.78 0.66 0.56 0.47 0.40]`
   (상수 `PET_CD_TOP`·`PET_CD_END` 둘) — 한 등급당 **×0.845 = 15.5% 빨라진다**(요구 ≥ 8%의 두 배)
4. **개체차 `v` 를 자리에서 파생** — `1 + (j − (n−1)/2) × PET_V_STEP`(0.03) ⇒ 5종 등급 0.94~1.06 · 1종뿐인 불멸 1.00.
   402 의 교훈대로 «손으로 적는 목록» 을 안 만들었다 — 종이 늘어도 이 줄만 읽으면 된다.
   `cd = PET_CD[g] / v` (자리가 뒤로 갈수록 빠르다 = 260 규약이 주기 축에서 성립)
5. **`tierScore(pet)`** — `it.m / it.cd` → **`1 / it.cd`**(11 확률표 티어 가중이 죽은 필드를 읽고 있을 뻔했다)
6. **08 세부 설명문** — «따라다니며 <em>n초</em>마다 **플레이어 공격력으로** 공격합니다» ·
   «장착 효과 — 공격력 +n% · **전투 피해** N»(485 의 «전투 참여 피해» 에서 라벨 단축)

### 왜 개체차 폭을 0.90~1.15 → 0.94~1.06 으로 좁혔나 (기하가 정한다, 취향이 아니다)

주기 축에서 «등급 경계 비역전»(260) 이 성립하려면 **등급 한 칸의 비 < 개체차의 최저/최고 비** 여야 한다.
구 폭이면 0.90/1.15 = **0.783** 이라 등급 한 칸을 **21.7% 이상** 내려야 하고, 7칸이면 불멸이 **0.23초**(3마리 초당 13발)가 된다.
새 폭 0.94/1.06 = **0.887 > 0.845** 이라 여유를 두고 성립한다. `verify481` **B8** 이 이 부등식 자체를 단언하고
**§R3** 이 «구 폭으로 벌리면 6경계가 뒤집힌다» 로 되돌림을 못박는다.

## 7. 교훈 (LESSONS 481 로 등재)

1. **등재문의 «이유» 가 틀려도 «결론» 은 맞을 수 있다 — 둘을 따로 검산하라.** 481 은
   `bonus().pet` 을 «보유 효과» 라고 잘못 적었지만, 그것을 빼야 한다는 결론은 다른 이유로도 참일 수 있었다.
   재현이 **무엇이 그 값을 올리는지**를 직접 흔들어 보여 준 뒤에야 «남긴다» 는 답이 나왔다.
2. **축을 옮길 때는 «옮긴 축이 감당할 수 있는 크기인가» 를 먼저 재라.** 도감 축(×14.28)을 주기로 옮기면
   DPS 는 같지만 발사체가 초당 108발이 된다. 같은 곱셈이라도 **피해와 주기는 다른 물건**이다.
3. **개체차 폭과 등급 계단은 한 부등식으로 묶여 있다.** 주기 축에서 «등급 경계 비역전» 은
   `등급비 < v_min/v_max` 다 — 폭을 안 좁히면 불멸이 0.23초가 되고, 계단을 안 세우면 경계가 뒤집힌다.
   둘 중 하나만 정하면 반드시 다른 하나가 깨진다.
4. **«전 펫 같은 값» 을 절대값으로 재면 못 잰다.** 펫을 보유·장착하는 것만으로 `b.atk` 가 움직여
   `stat.dmg` 가 바뀐다(ownVal · 485 petEquipVal). 재는 것이 «펫 자신의 축» 이면 **비율**로 재거나
   **스킬 칸을 비워 항등식**으로 확인해야 한다. 이 함정에 게이트 두 곳(`verify485` D5 · `verify481` D1)이
   연달아 걸렸다.
