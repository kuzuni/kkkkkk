## 2. 처방 — 333: 자리를 비우지 않고 방향만 356 축으로

빨간 항을 지우면 그만큼 자가 **안 보는 자리**가 된다. 다섯 항을 전부 **살아 있는 축으로 갈아 끼웠다.**

### §1 — 전제를 «356 이후의 부등호» 로 다시 적고, 넓힌 상자는 «안전핀» 으로 따로 못박는다

```

ok §1 [안전핀]      상자가 well 보다 40.00px 넓다(margin −20/−20) — 356 뒤에도 떼지 않는다
```

두 항으로 가른 이유: index.html 1141~1142 가 «357 의 `width:auto;margin:0 -20px` 는 그대로 둔다 —
advance 가 well 안에 들어왔지만 그 짝은 «넘치면 line-left» 함정을 막는 **안전핀**이라 떼지 않는다» 고
**선언**해 놓았다. 선언이 둘이면 항도 둘이어야 한다 — 한 항으로 뭉치면 핀을 떼도 초록이 나온다.

### §4 — 주입하는 «옛 CSS» 를 356 **이전** 값으로 되돌려 되돌림 시험을 살린다

옛 주입은 `width:100%; margin:0` 하나뿐이었다. 356 뒤에는 상자가 87.63 으로 좁아져도 advance 82.23 이
그 안에 들어와 **text-align 이 살아남는다** — 그래서 이 절이 통째로 죽어 있었다.
주입을 **356 이전 규격 전부**(`fs 78.3` + `scaleX(.842)` + `width:100%` + `margin:0`)로 되돌리자
곧바로 되살아났다:

```
356 이전 CSS 주입 후 8칸 Δ = +4.24 · +4.24 · +4.24 · +4.24 · +4.24 · +4.24 · +4.24 · +4.24
ok §4 356 이전 CSS 에서는 §2 기준(±0.5)이 실제로 깨진다 (최악 4.24)
ok §4 그리고 8칸이 **전부 오른쪽으로** 밀린다 — 주인 보고(«다 오른쪽») 재현
ok §4 원복하면 다시 ±0.5px (최악 0.01)
```

**8칸이 전부 +4.24px 오른쪽** — 357 을 낳은 주인 원문(«아이콘이 다 오른쪽에 밀려있더라») 그대로다.

⚑ **[음성항]을 같이 세웠다** — 이 절이 죽었던 이유 자체를 기록으로 남긴다.

```
[음성항] width:100% 만 주입 → 8칸 Δ = −0.01 (전부)
ok §4 [음성항] 현행 fs 에서는 `width:100%` 만으로는 안 깨진다 — 356 이 넘침을 없앴다 = 넓힌 상자는 안전핀
```

이 항이 언젠가 «깨진다» 로 뒤집히면 그것은 fs 가 356 이전으로 돌아갔다는 신호다.

### §5 — 상수 대신 **regime 을 넘어 살아남는 불변량**

`fs 78.3` 도 `scaleX .842` 도 356 이 폐기했으니 그 숫자를 다시 적으면 다음 지시에 또 부패한다.
그래서 **가로 시각 크기 = `fs × scaleX`** 를 묻는다:

| | fs | scaleX | fs × scaleX |
|---|---|---|---|
| 356 **전** | 78.3 | .842 | **65.93** |
| 356 **후** | 65.9 | 1 | **65.90** |

356 은 «어떻게» 를 바꿨지 «가로로 얼마나» 를 바꾸지 않았다(측정표 §3 «잉크 폭 68 정규화» · 폭 Δ0).
그래서 이 값은 **두 regime 에서 같다** — 상수가 아니라 불변량이다.

```
ok §5 등방이다 — 비균등 scaleX 없음 (scaleX 1.000) · 356 «아이콘은 원본 비율»
ok §5 가로 잉크 정규화 불변 — fs × scaleX = 65.90 (356 전 78.3×.842 와 같은 값)
```

세로는 356 이 −15.8%(잉크 85 → 71.6) 로 **줄인 것이 정답**이라 이 절이 묻지 않는다 — 묻는 것은 `lh 87.6` 뿐이고
그 항은 손대지 않았다(계속 초록).

## 3. 무르게 풀지 않았다 — §R 신설

갈아 끼운 항이 «항상 참» 이면 게이트가 아니라 장식이다. **§R** 을 신설해 네 항이 실제로 뒤집히는지 직접 돌린다.

```
356 이전 주입 → advance 97.7 · well 87.63 · 상자 87.62 · fs 78.3 · scaleX 0.842 · fs×sx 65.93
ok §R §1 [전제·356 이후]가 뒤집힌다 — advance(97.7) > well(87.63)
ok §R §1 [안전핀]이 뒤집힌다 — 상자−well = −0.01px
ok §R §5 «등방» 이 뒤집힌다 — scaleX 0.842
ok §R §5 «fs×scaleX = 65.9» 는 356 이전 규격에서도 그대로 (65.93) — regime 을 넘는 불변량
ok §R 크기를 실제로 바꾸면(fs 80 등방) §5 불변량이 뒤집힌다 — fs×scaleX 80.00
```

⚑ 넷째 항은 **일부러 «안 뒤집힌다» 를 단언**한다 — 그것이 이 불변량을 고른 이유다.
그러면 «아무것도 못 잡는 항» 아닌가? 그래서 다섯째 항이 **크기를 실제로 바꾸는 주입**(fs 80 등방)을
하나 더 돌려 65.90 → 80.00 으로 뒤집히는 것을 확인한다. **불변량이 무엇에 둔감하고 무엇에 민감한지를 자가 직접 적는다.**

⚑ §R 이 덤으로 등재문의 산수도 검산했다 — 356 이전 advance 는 **97.7px** 이고 well 87.63 을 **10.07px 넘는다**.
등재문이 «82.23 이 이미 well 안» 이라고만 적고 옛 값을 안 적었던 자리다.
