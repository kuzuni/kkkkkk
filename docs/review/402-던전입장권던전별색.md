## 2. 뿌리 — 그림이 아니라 «폴백 한 문자열»

입장권 SVG 5장은 **처음부터 색이 달랐다**. 빨간 것은 매핑이다:

```js
const dunTk = id => id === 'gold' ? 'tkGold' : id === 'dia' ? 'tkDia'
                  : id === 'stone' ? 'tkStone' : id === 'rstone' ? 'tkRstone' : 'tkRelic';
                                                                              // ↑ 여기
```

이 **마지막 폴백 한 문자열**이 「위 넷에 안 걸린 던전」을 전부 같은 보라로 접었다.
`relic1`·`relic2`·`relic3`·`relic4` 가 거기 걸렸고, `DUN_UI[].tk` 에도 `curIc('tkRelic')` 이
**손으로 네 번 똑같이** 적혀 있었다(그래서 선언만 읽는 자에게는 «네 값이 다 있다» 로 보였다).

⚑ **측정표가 이미 답을 적어 두고 있었다** — `docs/measure/03-던전팝업.md` §3-5-3 의
«입장권 아이콘 bbox» 줄에 실측 주석 «**기울어진 티켓, 카드마다 다른 아트**» 가 있다.
레퍼런스는 처음부터 카드마다 다른 권종을 그리고 있었고 우리 매핑만 접혀 있었다.

## 3. 게이트와 정면으로 부딪힌 것이 본체다

`tools/verify125.js` **H2** 가 «입장권 종류는 **5종뿐**» 을 단언하고 있었다. 그 5종은
125(주인 지시 2026-08-26)가 «입장권은 던전 **계열** 로만 갈린다» 로 세우고 194·203 이 계열마다
한 장씩 더한 규약이다. **이번 주인 지시는 그 «계열» 단위를 «던전» 단위로 바꾸라는 것**이므로
규약을 갱신하고 자를 갈아 끼웠다(356 이 «비균등 스케일 금지» 로 관행을 뒤집은 것과 같은 꼴 —
주인 지시가 이전 규약보다 우선이다).

⚠ **넓히지 않았다.** 125 의 다른 절(«재화 하나에 이미지 하나» · 소스에 화폐 이모지 0건)은
한 항도 안 건드렸다. 오히려 유물 4단이 그림 하나를 나눠 쓰던 것이 **그 규칙에서 벗어나 있었다.**

| verify125 [H] | 수리 전 | 수리 후 |
|---|---|---|
| H1 | 던전 8개의 입장권이 **계열 5종과 일치** | 던전 8개의 **권종 키가 CUR_ICON 에 전부 있다** |
| H2 | 입장권 종류는 **5종뿐** | 입장권 **그림이 던전마다 다르다(중복 0건)** |
| H3 | — | **03 카드가 그린 그림 = 선언**(손으로 적은 사본 금지) — 신설 |

⚑ **숫자를 손으로 안 적었다.** 옛 H2 의 «5종» 은 194 에서 4종을, 203 에서 5종을 뒤따라간
상수였고 이번이 **네 번째 부패였을 자리**다. 새 H2 가 세는 것은 어떤 상수가 아니라
**던전 수와의 일치**다 — 던전이 늘어도 안 뒤처진다.
`[C] C0~C2`(아이콘 종수)는 이미 `CUR_ICON` 블록 **전수 추출**이라(289 처방) 4장이 늘어도
손댈 곳이 **0줄**이었다. 등재문이 걱정한 «네 번째 부패» 는 그쪽에서는 안 일어났다.

### ③ 폴백을 없앤 방법 — 표도 안 만들었다

```js
const dunTk = id => 'tk' + String(id).charAt(0).toUpperCase() + String(id).slice(1);
```

등재문 처방은 «폴백 문자열 하드코딩 금지 — **던전 id → 권종 표**로 바꾼다» 였다.
표는 **안 만들었다**. 표도 손으로 적는 목록이라 던전이 늘면 뒤처지는 것은 폴백과 같기 때문이다.
id 에서 이름을 만들면 gold→`tkGold` · dia→`tkDia` · relic1→`tkRelic1` · stone→`tkStone` ·
rstone→`tkRstone` 로 **기존 5개 이름이 한 글자도 안 바뀌면서** 새 던전도 자동으로 자기 권종을 갖는다.

⚠ **그 대신 «그림이 없는 새 던전» 이 생긴다** — `curKey()` 는 모르는 키를 **조용히 골드로**
떨어뜨린다. 그 조용함에 안 기대려고 `verify402` [A1] 이 «8던전의 권종 키가 CUR_ICON 에 전부
있다» 를 못 박는다. 던전을 늘리면서 SVG 를 빼먹으면 그 자리에서 빨개진다.

### ④ 사본을 지운 것이 이 수리의 핵심이다

`DUN_UI[].tk` 는 **입장권 그림을 두 번째로 적어 두던 자리**였다. 지시대로 `dunTk()` 만 고치고
그 필드를 뒀으면 03 카드는 여전히 **옛 사본을 그렸을 것**이다(카드만 `u.tk` 를 읽는다).
지우면서 **등재문이 «같이 정리하라» 고 한 죽은 필드 둘도 함께 사라졌다** —
`tower.tk`(유물권)와 `despair.tk` — 후자는 입장권이 아니라 **단련석 재화 아이콘**
(`cur-ticket-tstone.svg` 라는 파일은 없다)이 들어가 있었다. 탑 카드는 `.sp.tk` 에
«♾️ 없음» 을 그리므로(209) 둘 다 처음부터 화면에 안 나오던 값이다.

### 자산 — 색만 다르고 기하는 픽셀 동일

새 4장(`assets/ui/cur-ticket-relic{1..4}.svg`)은 껍데기 `path d` 한 줄이 기존 장들과
**바이트 단위로 같다**(`verify402` B2 가 8장을 한 값으로 묶어 잰다). 색은 그 던전
**카드의 두 톤 그대로** — 껍데기 = `DUN_UI[id].s` · 속띠 = `DUN_UI[id].r`:

| 던전 | 껍데기(`.s`) | 속띠(`.r`) |
|---|---|---|
| relic1 | `#394256` | `#5A678A` |
| relic2 | `#092A5C` | `#1750A6` |
| relic3 | `#1D53CE` | `#4A85F5` |
| relic4 | `#3A1E52` | `#6E3897` |

⚑ **`.i`/`.r` 이 아니라 `.s`/`.r` 을 골랐다.** 등재문은 `.i`/`.r` 을 예시로 들었는데
relic1 은 그 둘이 `#4A5570` / `#5A678A` 로 **명도가 거의 같아** 속띠가 껍데기에 묻힌다.
기존 5장의 구조는 예외 없이 «어두운 껍데기 / 밝은 속띠» 라(relic `#3E2A6B`/`#9E7BE0`) 그
구조를 지키는 쌍이 `.s`/`.r` 이다. 그리고 `.r` 은 PROGRESS 등재문 자신이 «카드 배경색» 으로
지목한 값이라 **카드와 권종이 같은 색으로 묶인다** — 지시의 목적 그대로다.

기존 4종(gold·dia·stone·rstone)은 **색·파일 그대로 = 회귀 0.**
옛 공용 `cur-ticket-relic.svg` 한 장만 사라졌다(4장이 갈라 가졌다).

## 5. 세이브 이관 «없음» 이 정답 — 실물로 못 박았다

`S.dunTk` 는 처음부터 **던전 id 별**이다(`DUNGEONS.reduce((o,d)=>(o[d.id]=DUN_TRY,o),{})`).
**수량은 이미 던전마다 따로 세고 있었고 아이콘만 접혀 있었다.** 계열을 쪼개도 저장 구조·수량·
잔고가 한 값도 안 바뀐다 ⇒ **KEY 안 올렸다.**

말로 두지 않고 `verify402` **[F]** 가 구 세이브를 실제로 만들어 `save()` → `load()` 를 돌린다:

```
F1 구 세이브를 실로드해도 8칸 수량이 한 값도 안 바뀐다(KEY 안 올렸다)
   — {"gold":3,"dia":4,"relic1":5,"relic2":6,"relic3":7,"relic4":8,"stone":9,"rstone":10}
F2 S.dunTk 는 던전 id 별로 저장돼 있다(수량은 애초에 접혀 있지 않았다)
```
