# 431 — `tools/verify374.js` 가 얕은 클론에서 3항 즉사 (게이트 부패)

**완료 2026-08-29 · sess-1938-23403 워커 A · 1회차**
**제품 `index.html` 0줄 · 레이아웃 Δ0px · 판정·밸런스 0줄.** 고친 것은 `tools/verify374.js` 한 파일이다.

---

## 1. 재현 — 등재문 그대로였다

등재문의 진단이 한 줄도 틀리지 않았다. 루틴 컨테이너의 클론은 **shallow** 다:

```
$ wc -l < .git/shallow      → 1
$ git rev-list --count HEAD → 55
$ git cat-file -t 5fe9d37   → fatal: Not a valid object name 5fe9d37
$ git cat-file -t 16d96a4   → fatal: Not a valid object name 16d96a4
```

`verify374.js` §R 은 그 두 SHA 를 **상수로 박아** `verifyProgress.js --rev <SHA>` 를 부른다.
객체가 없으니 본체는 «PROGRESS 를 읽지 못했다» 로 **종료 코드 2**(도구 오류)를 돌려준다.

```
[R] 되돌림 시험 — 실제 사고 커밋에 자를 대면 빨개진다
  ✗   R1 5fe9d37 종료 코드 1 = 2
  ✗   R2 §1 빨간 행이 정확히 368·369 두 건 = 없음
  ✗   R3 진단이 «정확 되돌림» = ok
  ✓   R4 사고 직전 16d96a4 는 §1 초록 = §1 조용
  ✓   R5 그 시점 §1 빨강 0건 = 0

VERIFY374 19/22 FAIL
```

본체(`verifyProgress.js`)는 등재문 말대로 **exit 0** 이다 — 워커의 push 게이트 자체는 멀쩡했고,
깨진 것은 **그 게이트의 되돌림 시험**뿐이다.

### ⚑ 등재문이 못 본 것 하나 — R4·R5 는 «헛초록» 이었다

빨간 셋만 문제가 아니다. **R4·R5 는 같은 도구 오류 위에서 초록이었다.**
자가 `s1Ids(out)`(빨간 행 목록)으로 «§1 조용» 을 묻는데, 도구 오류로 아무 행도 안 나오면
그 물음은 **«잰 결과 깨끗하다» 와 «재지 못했다» 를 구별하지 못한다.**
`verifyProgress.js` 자신은 그 규약을 지킨다(«부분검사» 로 세어 요약에 찍는다 · «못 보는 것을
초록으로 부르지 않는다») — **자기 자를 재는 자가 그 규약을 안 지키고 있었다.**

## 2. 뿌리 — 388 은 피했는데 374 는 안 피했다

`verify388.js` 헤더에 이미 적혀 있다:

> §R 은 이력에서 옛 판본을 꺼내 오지 않는다. 커밋 하나를 상수로 박으면
> 그 게이트는 얕은 창에서 즉사한다(388 §5 곁다리 관측).

374 는 388 보다 **먼저** 쓰였고, 그래서 그 교훈이 없었다. 새 결정이 아니라 **규칙이 안 따라온 것**이다
(350·378 과 같은 모양).

## 3. 처방 — 등재문의 ⓐ 를 본선, ⓑ 를 보강 절로

등재문이 가설 둘을 냈고 «ⓐ 를 본선, ⓑ 는 깊은 클론에서만 도는 보강 절» 을 유력하다고 적었다.
**그대로 갔다.**

### ⓐ §R — 사고를 «이력에서 꺼내지 말고 합성한다»

자가 재는 것은 원래부터 특정 SHA 가 아니라 **«행이 직전 판본으로 바이트까지 되돌아갔을 때
자가 빨개지는가»** 다. 그 모양은 **창 안의 아무 done 행으로도** 만들 수 있다.

표본은 **실행할 때 이력에서 고른다**(하드코딩 금지 — shallow 창은 실행마다 다르다):
«done 커밋이 완료로 적었고 · 직전 판본이 창 안에 있고 · 둘이 다르고 · 지금 표에 그 행이 있는» 행.
이 창에서는 7건이 걸렸고 앞의 둘(**421 · 422**)을 써서 **사고와 같은 «2행» 모양**을 만든다.

```
[R] 되돌림 시험 — 사고의 «모양» 을 합성해서 자에 물린다(SHA 를 안 박는다)
  ✓   R0  되돌릴 표본을 이력에서 골랐다(하드코딩 아님) = 421 422
  ✓   R0b 합성본이 옛 판본을 바이트까지 담았다 = 421 422
  ✓   R1  되돌린 사본 종료 코드 1 = 1
  ✓   R2  §1 빨간 행이 정확히 되돌린 그 행뿐 = 421 422
  ✓   R3  진단이 «정확 되돌림» = 421 422
  ✓   R4  되돌리기 전 사본은 §1 초록(사고 전후를 가른다) = §1 조용
  ✓   R5  그 사본 §1 빨강 0건 = 0
```

⚠ **`String.replace` 의 치환문 함정을 R0b 가 못박는다.** 옛 판본 본문에 `$&`·`$1` 이 살아 있으면
치환문으로 해석돼 **바이트까지 같게 안 들어가고**, 그러면 «정확 되돌림» 이 아니라 «완료 표지 상실» 로
잡혀 R3 이 조용히 뜻을 잃는다. 그래서 치환을 **함수형**(`() => line`)으로 넣고, 들어간 바이트를 R0b 가 되묻는다.

### ⓑ §H — 실물 사고 커밋은 «깊은 클론 전용 보강 절» 로

원래의 R1~R5(실제 `5fe9d37`·`16d96a4`)를 **§H 로 옮기고**, 객체가 있을 때만 돌린다.
없으면 **`⊘ 건너뜀` 으로 찍고 pass 도 fail 도 안 센다.**

```
[H] 실물 — 실제 사고 커밋에 자를 대면 빨개진다(깊은 클론 전용 보강 절)
  ⊘   H1~H4 — 건너뜀: 얕은 클론 — 5fe9d37/16d96a4 가 이력 창 밖이다(§R 이 같은 모양을 합성으로 건다)

VERIFY374 24/24 · 건너뜀 4항(깊은 클론 전용) PASS
```

**왜 빨강이 아니라 건너뜀인가**: 얕은 창에서 빨갛게 부르면 «고칠 수 없는 빨강» 이 되고,
고칠 수 없는 빨강을 단 게이트는 **통째로 무시된다**(431 이 정확히 그 상태였다 — 19/22 가 계속 빨간 채로
아무도 안 고쳤다). 대신 **초록으로도 안 부른다** — 요약줄이 건너뛴 항 수를 밝힌다.

⚠ **`git fetch --deepen` 을 자 안에서 부르지 않았다**(등재문 경고). 네트워크를 게이트의 전제로 삼으면
오프라인에서 다시 즉사한다. 깊은 클론이면 §H 가 **저절로** 켜진다(`has()` 실측: `HEAD`·`196387c` → true ·
`5fe9d37`·`deadbeef1` → false).

⚠ **`has()` 는 stderr 를 삼킨다.** `git cat-file` 이 뱉는 `fatal: Not a valid object name` 이 자의 출력에
섞이면 «자가 깨졌다» 로 읽힌다 — 있음/없음만 조용히 묻는다(`stdio:'ignore'`).

## 4. 무르게 풀지 않았음 — 되돌림 시험 2개

합성으로 바꾼 자가 **진짜로 잡는지**를 본체를 부러뜨려 확인했다(수리 후 원복 · `git diff --quiet` 로 확인).

| # | 부러뜨린 것 | 기대 | 실측 |
|---|---|---|---|
| ① | `verifyProgress.js` 의 **«정확 되돌림» 자를 통째로 들어냄** | §R 빨강 | **R1·R2·R3 빨강 · 21/24 FAIL** |
| ② | 자는 남기고 **진단 낱말만** `정확 되돌림` → `되돌아감` | R3 만 빨강 | **R3 만 빨강 · 23/24 FAIL** |

②가 중요하다 — **R3 이 R1·R2 의 중복이 아님**을 못박는다. «빨갛기만 하면 통과» 로 두면
표지 자(«완료 표지가 사라졌다»)가 되돌림 자를 가려도 초록이 되고, 그것이 바로 본체 첫 판의 실패였다
(368·369 를 «표지 없음» 으로만 부르고 병합 사고라는 이름을 못 붙였다 — `verifyProgress.js` 34~35행 주석).

**⚑ 그리고 이 두 시험은 얕은 클론에서 돌았다** — 옛 §R 은 같은 자리에서 **아무것도 못 잡았다**(도구 오류로 즉사).
바뀐 것은 «빨강을 초록으로 만든 것» 이 아니라 **한 번도 안 돌던 절이 처음 돈 것**이다(319 와 같은 꼴).

## 6. 다음 세션에게

- **§R 은 이제 SHA 를 안 박는다.** 표본은 실행할 때 이력에서 고르므로 창이 바뀌어도 따라온다.
  창 안에 «직전 판본이 있는 done 행» 이 **0건**이면 R0 이 빨개진다 — 그때는 조용히 넘기지 말고
  창을 넓히거나(`git fetch --deepen=200 origin main`) 표본 조건을 다시 보라.
- **자를 쓰는 자에도 «못 보는 것을 초록으로 부르지 않는다» 를 적용하라.** 431 의 진짜 결손은
  빨간 셋이 아니라 **초록이던 R4·R5** 였다. «빨간 행 0건» 은 «깨끗하다» 와 «재지 못했다» 를 구별하지 못한다.
- **이력 SHA 를 게이트 상수로 박지 마라**(388 헤더 · 이제 374 헤더에도 적었다). 루틴 컨테이너는 얕다.
