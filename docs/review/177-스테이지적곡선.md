## 1. 문제 — 168 이 남긴 벽

168 이 훈련 효과값을 **선형**(`b + k·l`)으로 바꿨는데 적은 **순수 지수**(eHp ×1.25 · eDmg ×1.14 /스테이지)
그대로였다. 선형은 지수를 이길 수 없으므로 훈련 축은 어딘가에서 반드시 벽에 부딪히고,
`sim168` [D] 가 그 벽을 **스테이지 18**(보스 30초 초과는 19)로 실측했다.
168 은 그것을 «설계» 로 남기고 «완화 여부는 177 의 몫» 이라 못 박았고, 주인이 «재조정» 을 지시했다.

## 2. 고친 것 — 곡선 한 줄

```js
/* before */
const eHp   = s => 55 * Math.pow(1.25, s-1);
const eDmg  = s => 6  * Math.pow(1.14, s-1);

/* after (177) */
const ES_K    = 0.888;   const ES_KNEE = 80;
const ES_M1   = 1.010;   const ES_M2   = 1.127;   const ES_A = 0.5872;
const eScale = s => (1 + ES_K*(s-1))
                  * Math.pow(ES_M1, Math.min(s, ES_KNEE) - 1)
                  * Math.pow(ES_M2, Math.max(0, s - ES_KNEE));
const eHp   = s => 55 * eScale(s);
const eDmg  = s => 6  * Math.pow(eScale(s), ES_A);
```

`eGold` 는 **한 글자도 안 바꿨다**(아래 §5).

## 3. 왜 이 형태인가 — 등재문이 준 두 선택지의 결론

등재문은 «적도 선형~저지수 / 구간별 기울기» 를 선택지로 주고 근거를 요구했다. **둘 다 필요했다.**

- **선형 항이 있어야 하는 이유.** 훈련 축이 선형이면 «훈련만 공격력» TP(s) 는 스테이지에 대해
  거의 선형으로 자란다(sim177 [B] 실측: TP(1) 78 → TP(80) 8,031, 비 102.97).
  적을 순수 지수로 두면 그 비가 지수적으로 벌어진다 — 이것이 벽의 정체다.
  적 곡선에 **훈련 축과 같은 선형 항**을 넣으면 그 부분이 정확히 상쇄된다.
- **구간별이어야 하는 이유.** 선형 항만 남기면(M=1) 훈련 축이 영원히 평탄해져 **배수 축(장비·유물·
  도감·펫·축복)이 진행에서 할 일이 없어진다.** 168 이 세운 구조(«훈련은 바닥, 지수 성장은 획득물»)를
  지키려면 무릎 위에 지수가 살아 있어야 한다.

## 4. 자유도 넷 — **전부 역산이다** (LESSONS 106-1 «발명이 아니라 역산» · 112-① «따로 푼다»)

| 상수 | 값 | 무엇 하나로 풀렸나 |
|---|---|---|
| `ES_KNEE` | **80** | 112 주인 지시(«스테이지 80 까지 훈련 4단계»)의 지평. **동시에 RANKS 의 플래티넘 계급 스테이지가 정확히 80** 이다 — 서로 다른 두 근거가 같은 수에서 만난다(sim177 이 매 실행 «RANKS 에 stage 80 계급이 있는가» 로 확인) |
| `ES_K` | **0.888** | 설치된 112 비용 곡선 + 168 선형 val + **162 페이싱**으로 도달 Lv 을 실측해 K = (TP(80)/TP(1) − 1)/79. 유휴 가정 밴드(0.5~6h)에서 나오는 네 기울기 중 **최소** |
| `ES_M1` | **1.010** | «훈련만으로 s ≤ 80 전 구간 몹 ≤ 1초 · 보스 ≤ 30초»(168 이 쓴 «게임이 실제로 되는가» 기준)를 **유휴 밴드 전체**에서 만족하는 상한 **1.01081** 이내의 값 |
| `ES_M2` | **1.127** | RANKS s80(2e9) → s300(2e21) 요구 전투력 성장률 **1.1338** ÷ 그 구간 선형 항 성장률 **1.0060** |
| `ES_A` | **0.5872** | = ln(1.14)/ln(1.25). 구 곡선이 `eDmg/6 = (eHp/55)^A` 였으므로 **적의 «맷집 대 화력» 비례를 한 글자도 안 바꾼다** — 곡선의 «속도» 만 바꾼 것이다 |

### ★ K 의 부호 함정 — «많이 방치할수록 기울기가 작다»

밴드별 역산 K 는 **1.422(0.5h) · 1.490(1h) · 1.291(3h) · 0.888(6h)** 로 단조가 아니다.
많이 방치할수록 **s1 도달 Lv 자체가 높아져**(2 → 5) 분모 TP(1) 이 커지고, 그래서 s1→s80 의 «상대»
기울기는 오히려 **작아진다.** 직관대로 «가장 적게 방치하는 0.5h 를 쓰자» 로 갔으면 K 를 1.422 로
잡아 **적을 60% 더 세게** 만들 뻔했다.
채택 규칙은 «밴드 하한» 이 아니라 **«밴드 최소 기울기»** 다 — 적 곡선이 가장 완만해지는 선택이고,
그 결과가 밴드 안 어느 가정에서도 성립하는지는 **게이트 ⑧ 이 밴드 전체를 훑어** 확인한다
(최악은 0.5h 쪽에서 나온다: 몹 0.985초 ≤ 1 · 보스 20.91초 ≤ 30).

## 5. eGold 는 왜 안 건드렸나 (등재문이 «경제 축» 으로 지목한 자리)

112 의 `TRAIN_COST_R` 은 눈대중이 아니라 **eGold 배율 1.175 에서 역산**된 값이다
(`dL/ds = ln(1.175)/ln(1.05) = 3.33`, index.html «112 훈련 비용 곡선» 주석).
그러므로 eGold 를 건드리면 «스테이지 80 까지 훈련 4단계» 라는 **주인 지시가 그 자리에서 깨진다.**
반대로 난이도 축만 낮추면 골드 수입은 그대로인데 스테이지를 더 빨리 지나가므로 «골드 수지가 훈련을
따라간다» 는 요구는 **저절로 좋아진다.** 그래서 177 은 난이도 축(eHp/eDmg)만 바꾸고,
경제 축이 그대로임을 게이트 ⑪(eGold 배율 1.175)·⑫(s80 도달 Lv 308 = 4단계)로 못 박았다.

## 9. 남의 게이트 처리 (LESSONS 168-③ «표기를 바꾸면 남의 시뮬이 먼저 죽는다»)

착수 전에 `grep -rl 'const eHp' tools/` 를 돌려 **sim112 · sim131 · sim168** 셋을 먼저 찾았다.

  — 다음에 곡선을 또 갈아 끼우는 사람은 이 파일 하나만 넓히면 된다.
- `sim112`·`sim168` 은 상수 추출 4줄을 `require('./ecurve')` 한 줄로 바꿨다. **판정 로직은 안 건드렸다.**

### ★ `sim168` ⑧ — **전제가 죽은 게이트를 «완화» 하지 않고 «재정의» 했다** (LESSONS 168-② 의 재발판)

sim168 ⑧ 은 «지수 적 곡선 앞에서 선형 훈련은 반드시 벽에 부딪힌다 — 그 위치를 177 에 넘긴다» 였고,
177 이 그 입력을 받아 곡선을 갈아 끼우자 **s ≤ 80 에 벽이 없어져 빨개졌다.**
여기서 조건을 넓히면(«벽이 있거나 없거나») 게이트가 통과하면서 죽는다. 대신 **곡선 표기에 따라
서로 반대 방향으로 단언**하도록 재정의했다:

```js
const g8 = EC.form === '177' ? (W_BOSS === null && W_MOB1 === null)   /* 177 곡선 → s≤80 무벽이 정상 */
                             : (W_BOSS !== null && W_MOB1 !== null);  /* 구 지수 곡선 → 벽이 반드시 있다 */
```

어느 쪽이든 «집어낸 수치» 가 있어야 통과다. 구 곡선으로 되돌리면 ⑧ 이 다시 옛 물음을 판정한다.
(같은 이유로 `verify168` ⑦ «s80 은 훈련만으로 못 넘는다(비 < 1)» 는 **그대로 살아 있다** — 새 곡선의
s80 비가 0.935 라 여전히 1 미만이다. 이는 우연이 아니라 M1 상한 조건이 «몹 ≤ 1초» 였던 결과다.)
