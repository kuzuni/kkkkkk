## 2. 원인 — «조건부 회귀» 가 아니었다. 상수 하나다

127 은 «깨끗한 페이지에서 같은 조작은 통과한다(프로브: 1.5초 뒤 확인)» 를 근거로
«게이트가 만든 상태에서만 죽는 조건부 회귀» 로 봤다. **아니다.** 프로브가 1.5초, 게이트가 0.9초를
기다린 것이 차이의 전부였다.

| | 값 | 출처 |
|---|---|---|
| 게이트 대기 | **900ms** | `verify69.js` — 주석에 «FXHOLD(620ms)» 라고 적혀 있었다 |
| 실제 `FXHOLD` | **1330ms** | `index.html:15316` `const FXSOLO = 1250, FXHOLD = 1330` |

`FXHOLD` 는 작업 **93**(«58 재화 흡수 연출 — 너무 빨라 «찰진 느낌» 이 없다», 커밋 `117878f`)이
**620 → 1330** 으로 늘렸다. 행 수령의 재렌더 경로는

```js
fxThen(() => { claimMail(id); fxRenderLater(() => { if(fxStillOpen('ml69')) openMail(); }); });
```

이고 `fxRenderLater` 는 `fxHoldList()` 가 미룬 시각(`fxReT = now + FXHOLD`)까지 기다린다.
즉 **수령 후 1.33초 동안 행이 옛 상태로 남는다.**

## 3. 이건 게이트만의 문제가 아니다 — 사용자에게 «죽은 버튼» 이다

게이트 대기를 1400ms 로 늘리면 숫자는 초록이 된다. 하지만 그건 증상만 가린다:
실제 플레이에서 **보상을 받은 뒤 1.33초 동안 버튼이 «받기» 인 채 활성**으로 남는다. 눌러도
`claimMail` 의 `S.mail[id]` 가드에 막혀 아무 일도 일어나지 않는다 — 사용자가 보기엔 **눌리는데
반응이 없는 버튼**이다. PROGRESS 129 제목이 말하는 «버튼이 «받기» 로 남고 활성» 이 정확히 이것이다.

## 4. 고친 방법 — 재렌더는 그대로 미루고, 표식만 즉시

`FXHOLD` 를 되돌리거나 재렌더를 앞당기는 것은 **금지**다. 두 가지 이유:

1. **93·58 은 남의 작업 구간이다**(`docs/claims/93.lock` 살아 있음. 지시서 [4] «내 작업 구간이 아닌 곳은 남의 버전 그대로»).
2. 앞당기면 58·77 회귀가 실제로 난다 — 93 주석: «3박자로 늘린 뒤에도 620ms 에 목록을 갈면 연출
   중간에 재렌더가 끼어… 코인이 아직 형제 행 위를 지나는데 딤이 풀려 «저 퀘스트도 완료됐나» 오독이 돌아온다».

그래서 **통재렌더는 손대지 않고**, 그 행의 완료 표식만 클릭 즉시 DOM 에 입힌다.

```js
/* mailRowHtml 아래 신설 */
function mailRowDone(row, btn){
  if(btn){ btn.disabled = true; (btn.querySelector('b') || btn).textContent = '완료'; }
  if(!row) return;
  row.classList.add('done');
  const d = row.querySelector('.ml-d i'); if(d) d.textContent = '수령 완료';
}

/* openMail() 행 클릭 핸들러 */
if(b.disabled || S.mail[b.dataset.ml]) return;      /* 129 — 이미 받은 행은 여기서 끝 */
fxMail(b, …);
mailRowDone(row, b);                                /* 129 — 재렌더는 미루되 «받았다» 는 지금 */
fxThen(() => { claimMail(…); fxRenderLater(() => { … openMail(); }); });   /* 58 계약 그대로 */
```

핵심 제약: **`mailRowDone` 이 입히는 결과 = `mailRowHtml` 의 `done` 분기 결과**여야 한다
(`disabled` · 라벨 «완료» · 행 `.done` · `.ml-d` «수령 완료» 4개). 어긋나면 1.33초 뒤 통재렌더에서
표식이 «되돌아» 보인다. 그래서 문구·클래스를 `mailRowDone` 한곳에 모으고, 게이트에
**재렌더 전/후 두 시점 비교**를 넣었다(§5).

부수 효과 — **연타 가드가 구조적으로 선다.** 비활성 버튼은 `click` 을 발화하지 않으므로
`claimMail` 의 `S.mail[id]` 가드에 도달할 일 자체가 없어진다(가드는 이중 안전으로 남겨 뒀다).

### 4-1. 연출이 «탁» 튀지 않게 (CSS, 69 구간)

표식을 즉시 입히면 `.ml-r.done{background:#E3D3BC}` 와 `.ml-r.done .ml-i{filter:grayscale(.75)}` 가
**코인이 썸네일을 떠나기도 전에** 스냅한다. 93 의 도착 타이밍(첫 도착 0.56s)을 피해 지연을 준다:

```css
.ml-r,.ml-ac{transition:background .30s ease .16s}
.ml-i{transition:filter .34s ease .18s}
```

라벨·`disabled` 는 **지연 없이 즉시**다 — 그게 이 버그의 본체다.
`.out`(92 삭제 연출)은 `animation` 이라 같은 속성을 잡아도 트랜지션보다 우선한다(간섭 없음).

## 5. 게이트 보강 — 상수가 또 바뀌어도 잡히게

`verify69.js` 의 대기 시간을 늘리는 «땜질» 대신, **재렌더에 의존하지 않는다는 것 자체**를 잰다.
`FXHOLD` 가 앞으로 또 바뀌어도(93 이 아직 진행 중이다) 이 세 항목은 그대로 유효하다.

| 신설 항목 | 재는 것 |
|---|---|
| `클릭 120ms 뒤 — 이미 «완료» · 비활성 · .done` | 표식이 **재렌더를 안 기다린다** (FXHOLD 무관) |
| `재렌더 뒤에도 수령 n행이 «완료» 유지(즉시 표식 ≡ mailRowHtml)` | 통재렌더가 표식을 **되돌리지 않는다** |
| `미수령 행은 그대로 [받기] 활성` | 즉시 표식이 **엉뚱한 행**에 번지지 않는다 |

옛 «FXHOLD(620ms)» 주석도 실제 값(1330, 93 이 올림)과 그 함의로 고쳐 적었다 — 이 주석이 틀린 채로

## 7. 남긴 것 / 손대지 않은 것

- **`FXSOLO`/`FXHOLD` 는 건드리지 않았다** — 93 구간. 값이 옳은지는 93 이 판단할 몫이다.
- **`mailBtn`(일괄 읽기&수령) 경로**는 `fxThen(() => { claimAllMail(); openMail(); })` 로 **즉시** 통재렌더한다

- 교훈 후보(LESSONS 로 승격 대상): **«게이트 주석에 박아 둔 상수는 코드가 바뀌면 거짓말이 된다.»**
