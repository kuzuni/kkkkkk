## §2 처방 — 자리마다 베끼지 않고 «칠하는 법» 을 한 함수로 모았다

701 이 단련·룬에서 쓴 처방(«칸은 처음 한 번만 만들고 그 뒤로는 클래스만 뒤집는다»)을 상점·유물에
**복사**하면 같은 코드가 넷이 되고, 다섯 번째 바가 생기는 날 똑같이 뒤처진다. 668·700 이 «칸을
그리는 말»만 `mulBarHTML()` 로 모으고 **칠하는 법은 자리마다** 적어 둔 것이 이 결함의 구조적 원인이다.

⇒ **`paintMulBar(bar, cur)`** 하나를 세우고 네 자리가 그것을 읽는다.

```js
function paintMulBar(bar, cur){
  if(!bar) return;
  if(bar.children.length !== SUM_MULS.length) bar.innerHTML = mulBarHTML(cur);   /* 만드는 것은 여기 한 번뿐 */
  [...bar.children].forEach(c => {
    const on = +c.dataset.mul === cur;
    c.classList.toggle('on', on);
    const i = c.querySelector('i');
    if(i){ i.classList.toggle('ol4', on); i.classList.toggle('ol3', !on); }
  });
}
```

* `renderSumMulBar()` · `renderRwMulBar()` — 한 줄 위임으로 축약
* `renderTrMulBars()` — 701 이 자기 몸에 적어 뒀던 같은 로직을 걷고 공용 함수를 읽는다

⇒ **`innerHTML = mulBarHTML(...)` 대입이 저장소 전체에서 한 곳뿐**이 됐다(`verify797` [1-c] 가 그 수를
직접 센다). 네 자리가 갈라질 자리 자체가 없다 — 700 §2 의 «칸 모양이 갈라질 방법이 원리적으로 없다» 를
**칸 수명** 축으로 넓힌 것이다.
