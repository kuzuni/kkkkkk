## 3. 고친 것 (`tools/verify114.js` [8] 한 절만)

`index.html` 은 **한 줄도 건드리지 않았다**(제품이 아니라 자의 문제).

1. **주 판정 — 작업량 예산** `프레임당 캔버스 명령 ≤ 460`
   `CanvasRenderingContext2D.prototype` 의 그리기 13종을 래핑해 세고 절이 끝나면 되돌린다(다음 절 무영향).
   자는 실측 중앙값 373 · 최대 386 위에 **+19%**.
2. **주 판정 — 비싼 상태** `프레임당 filter·shadowBlur ≤ 0.5`
   «명령 수는 적은데 시간만 폭발하는» 부류(LESSONS 121-③)를 명령 수 축이 놓치므로 setter 를 세서 따로 막는다.
   현재 이 씬에서 **0건**이다.
3. **보조 판정 — 같은 실행 안의 시간 비율** `부하/기준선 중앙값 ≤ 2.4`
   기준선(스킬 0칸)과 부하(8칸)를 **번갈아 3쌍 × 800프레임**. 한쪽을 다 재고 나중에 다른 쪽을 재면
   그 사이의 부하 변화가 통째로 비율에 실린다(LESSONS 121-④ ⚠). 자를 좁히지 않은 이유는 [4] 참고.
4. **절대 fps 는 옵트인** — `V114_PERF=1` 을 준 전용 러너에서만 `≥55fps` 를 판정하고, 기본 실행에서는
   «참고(판정 아님)» 로 값만 찍는다. 등재문의 ⓒ 를 단독으로 쓰지 말라는 조건대로 **ⓐ·ⓑ 와 묶여 있다**.
