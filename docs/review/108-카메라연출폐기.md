## 1. 기준으로 삼은 «맨 처음» 코드

67 이전(`0c9acce^`)의 카메라 블록은 `step()` 안 다섯 줄이 전부였다:

```js
const tx = clamp(player.x, VW/2, WORLD.w-VW/2);
const ty = clamp(player.y, VH/2, WORLD.h-VH/2);
cam.x += (tx-cam.x) * Math.min(1, dt*6);
cam.y += (ty-cam.y) * Math.min(1, dt*6);
if(cam.shake > 0) cam.shake = Math.max(0, cam.shake - dt*28);
```

`cam` 은 `{x, y, shake}` 뿐이고 `draw()` 에는 `ctx.scale` 이 없다(`ox = -(cam.x - VW/2) + sx`).

**`CAM_K = 0.10` 으로 정한 근거**: 옛 계수 `Math.min(1, dt*6)` 은 60fps 한 프레임에 정확히 **0.10** 이다.
67 이 쓰던 0.12 를 그대로 두면 «맨 처음 느낌» 보다 20% 빠른 추적이 된다. 다만 `dt*6` 같은 **선형 계수는 그대로 두지 않았다** —
`loop()` 의 dt 캡이 0.1초라 프레임이 튀면 계수가 0.6(=60% 점프)이 되어 그 자체가 저크다.
프레임률 독립 감쇠 `1-(1-k)^(dt*60)` 로 감싸 **60fps 에서는 옛 값과 같고**, 프레임이 튀어도 곡선이 유지되게 했다.

### 남긴 것과 그 이유

- **월드 경계 클램프** — 맵이 2배(1920×3072)라 두 축 모두 실제로 산다. 없으면 가장자리에서 검은 띠가 보인다.
  `camClamp` 는 줌이 없어져 `hw = VW/2` 고정으로 단순해졌다. 짧은 기기(9:16)에서 월드가 화면보다 좁은 축은 중앙 고정.
- **`draw()` 의 ox/oy 2차 클램프** — 셰이크는 «화면» 이 흔들리는 것이라 카메라를 가둔 «뒤» 에도 경계에서 월드 밖을 드러낸다. 67 이 넣은 이 두 줄은 줌과 무관한 버그 수정이라 남겼다.
- **`cam.shake`** — 55 설정 «화면 흔들림» 게이트(`shakeOn()`) 포함 그대로. 피격·보스 등장 셰이크는 «연출» 이 아니라 기존 피드백이다.
- **78/98 오디오** — `sfx('bossin')/bgmSet('boss')` · `sfx('bosskill')/bgmSet('main')` 은 남의 작업 구간이라 **카메라에서 떼어내 오디오 훅 2개로 분리**했다. 카메라는 이 둘을 한 픽셀도 보지 않는다.
- **맵 2배 · 스폰 링(`SPAWN_RMIN/RMAX`) · 28 보스전 30초·재도전** — 지시 ③④ 대로 손대지 않았다.

### 5-1. 왜 VERIFY59 를 같이 도는가
59 의 «구석·벽 체류율» 은 **맵 크기·스폰 링에 물려 있다.** 카메라만 바꿨어도 `step(dt*camTimeScale())` → `step(dt)` 로
게임 시간 흐름이 바뀌므로(처치 슬로모가 사라져 같은 실시간의 실제 진행량이 늘어난다) 이동 AI 지표가 흔들릴 수 있다.
실제로는 흔들리지 않았다 — 구석 0.0% · 벽 2.6% 로 상한(10 / 25)에서 멀다.

### 5-2. 병합 뒤 다시 돌렸다
