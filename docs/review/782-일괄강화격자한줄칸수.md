## 1. 등재문과 실제로 어긋난 곳

등재문(782)은 [D4]«가려진 행이 있으므로 격자가 스크롤된다»가 `894/894` 로 빨간 것을
**«표본이 모자라다»**(펫 35종이라 안 넘친다)로 읽고, 처방 ⓐ(더 많은 종수·더 짧은 프레임으로
표본을 올린다) + ⓑ(헤더를 «넘칠 때만»)를 권했다.

338 규칙대로 처방 전에 재현했고(`tools/probe782.js`), **갈래가 한 칸 앞에서 갈렸다** —
표본은 모자라지 않았다. 그려진 격자가 이랬다:

```
n=14 @2280   그려진 행별 칸 수  [6,6,2]  ← 를 기대했는데
             실측 좌변 18.5 / 169.5 / 320.5 / 471.5 / 622.5 / 773.5 / 924.5  = **7칸**
펫 35 @1600  그려진 행 5 · sh/ch 894/894 (안 넘친다)
             그런데 헤더는 "총35건 강화 **밀어서 더 보기**"
```

**뿌리는 표본이 아니라 «같은 수를 두 곳에 따로 적은 것»이다.**
726 은 한 줄 칸수를 **JS 에만** 적고(`const UPR_COLS = 6`, 주석까지 «137·6 + 14·5 = 892 < 1080»),
격자는 **전폭 1080** 으로 두었다(`.upr-cards{left:0;right:0}`). 전폭에는 **7칸이 들어간다** —

    137·7 + 14·6 = 1043 ≤ 1080

그래서 CSS 는 7칸으로 줄바꿈하고 JS 는 `rows = ceil(n/6)` 으로 6칸을 세었다. 어긋난 값이
**세 군데로 동시에 샜다**:

| 새어 나온 자리 | 증상 |
|---|---|
| `rows > vis` 헤더 조건 | 펫 35: 센 행 6 vs 그려진 행 5 ⇒ **안 넘치는데 «밀어서 더 보기»** |
| `--upr-gh` 묶음 높이 | 없는 행 하나만큼 묶음이 더 높다(중앙 정렬이라 자리도 따라 밀린다) |
| `verify726` [D4] | 넘침을 전제로 선 항이 영영 빨갛다 |

⚠ **[D5] 가 초록이던 것이 더 나빴다** — 자가 «밀어서» 라는 **낱말만** 찾았으므로,
자와 제품이 *같은 거짓을 나눠 들고* 서로를 통과시키고 있었다.

## 2. 처방 — ⓐ·ⓑ 를 같이 (등재문 권고 그대로, 단 ⓐ 의 뜻이 바뀌었다)

등재문의 ⓐ 는 «표본을 올려라» 였지만 재현이 «표본은 충분했다»를 보였으므로,
ⓐ 를 **«선언을 한 곳으로 모아라»** 로 바꿔 잡았다.

- **ⓐ 줄 폭을 `UPR_COLS` 에서 판다** — `openUpAll` 이 `--upr-cw = UPR_COLS·137 + (UPR_COLS−1)·14`
  를 `#upw` 에 걸고, `#upw.many .upr-cards` 가 `width:var(--upr-cw,892px);margin:0 auto` 로 받는다.
  이제 CSS 가 «한 줄 칸수» 를 혼자 정할 방법이 없다. 칸 폭 137 도 `UPR_CEL_W` 로 이름을 얻었다.
- **ⓑ 헤더는 계산이 아니라 «그려진 격자» 에게 묻는다** — `rows > vis` 를 버리고
  `upCards.scrollHeight > clientHeight + 1` 실측으로 붙인다. `#upw{display:none}` 이라
  **`.on` 을 붙인 뒤**라야 값이 나오므로 그리기·`petPaint` 뒤로 순서를 옮겼다.
  `.upr-cnt` 는 `position:absolute` 라 격자 기하는 **Δ0px** 이다.

ⓑ 만 했으면 헤더는 참말이 되지만 **묶음 높이는 계속 한 행씩 거짓**이고 [D4] 는 영영 조용해진다
(«넘침 없음» 으로 통과). ⓐ 만 했으면 다음에 폭·칸 규격이 바뀌는 날 같은 병이 재발한다.

## 3. 게이트 — 이관 1항 · 신설 2절

- **[D5] 이관** — ««밀어서» 라는 낱말이 있는가» → **«말함 ≡ 실제 넘침»** 등호. 한쪽만은 못 선다.
- **[G] 신설(782)** — «상수가 몇인가» 가 아니라 **«그려진 줄이 그 상수와 같은가»** 를 묻는다.
  - G1 첫 줄에 선 칸 수 = `UPR_COLS` · G2 그려진 행 수 = `ceil(n/UPR_COLS)`
  - G3·G4 **음성항** — 안 넘치는 판(7칸 @2280)에서 «밀어서» 가 **없다**
- **[G-R] 되돌림 시험** — 줄 폭 제약만 뺀 사본에서 GR1(한 줄 7칸) · GR2(그려진 행 5 ≠ 센 행 6) ·
  **GR3([D4] 가 894/894 로 다시 빨개진다)** 가 전부 성립한다. 무르게 푼 수리가 아님을 이 셋이 못박는다.

⚠ **`getBoundingClientRect` 로 «같은 줄» 을 세면 안 된다** — 60 쥬시 등장 연출이 칸마다 다른
위상으로 `scale` 을 걸어 같은 줄이 `[1,6,1,1,1,1,1,2]` 처럼 갈라진다(1회차에 실제로 그랬다).
`offsetTop` 은 레이아웃 값이라 transform 과 무관하다 — `probe782`·`verify726` 둘 다 이것을 쓴다.
