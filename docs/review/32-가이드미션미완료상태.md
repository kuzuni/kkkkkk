## 0. 세로 변환 상수 — **이 화면은 «ref y − 60» 이다** ★

지시서 [3]-(나) 2 는 비평가에게 «ref y − 84» 를 알려 주라고 하지만, **그건 화면 위쪽 기준 요소에만 맞는다.**
이 배너는 **탭바 위에 붙은 하단 앵커 요소**다.

| | ref | 프레임 | 변환 |
|---|---|---|---|
| 상단 기준 요소 | y | y − 84 | 상태바 84 제거 |
| **하단 앵커 요소** | y | **y − 60** | ref 2340 ↔ 프레임 2280. 잔차 **24** 는 전투 캔버스가 흡수 |

**실측 근거**: 탭바 상단이 ref **2160**(A1 측정표 §12) ↔ 구현 **프레임 2100** → 차 **60**.
`#tuto` 는 `#stagearea`(bottom 2100) 기준 `bottom:171` 이므로 프레임 1929 = ref **1989** 로 정확히 맞는다.

> **처음에 −84 로 대조했더니 배너가 «24px 아래로 밀렸다» 는 가짜 감점이 나왔다.**
> PROGRESS «확정(18)» 의 교훈(«비평가에게 주는 세로 변환 상수를 먼저 실측하라»)이 그대로 재발한 것이다.
> `tools/crop32.js` 는 이 −60 을 크롭 단계에서 이미 보정하므로, 두 크롭은 **같은 픽셀 = 같은 논리 위치**다.

## 1. 1회차 — 자체 픽셀 실측 (`node tools/probe32.js docs/review/32-r1.png`)

캡처 `docs/review/32-r1.png`. 레퍼런스와 같은 문자열(`[미션-227]` / `아무거나 소환 10회` / `(0/10)` / `200`)을
`tools/cap32.js` 가 주입한다 — 세 줄이 **중심 정렬**이라 문자열 길이가 다르면 잉크 bbox 대조 자체가 불가능하다.

| 요소 | 기대(ref) | 1회차 실측 | Δ |
|---|---|---|---|
| 배너 좌단 x | 620 | **620** | **0** |
| 배너 상단 / 하단 (ref y) | 1840 / 1989 | 1838 / 1988 | −2 / −1 (높이 151→150 이면 해소) |
| L1 `[미션-227]` 잉크 | x714 · 160×27 | x718 · **132×28** | **폭 −28 (−17%)** · 중심 783.5 vs ref 793.5 |
| L2 `아무거나 소환 10회` 잉크 | x677 · 217×24 | x673 · **220×24** | +3 / 0 (일치) |
| L3 `(0/10)` 잉크 | x741 · 89×23 | x750 · **68×26** | **폭 −21 (−24%) · 높이 +3** |
| 보상칸 외곽 | x948 · 118×119 | x948 · **117×117** | −1 / −2 |
| 젬 시안 잉크 | x978 · 58×60 | x969 · **75×60** | **폭 +17 (+29%)** |
| 수량 `200` 잉크 | x969 · 75×26 | x978 · **57×26** | **폭 −18 (−24%)** |
| 레드닷 붉은 픽셀 | 0 | **0** | ✅ |

**진단** — 껍데기(배너 상자·보상칸 위치)는 이미 맞고, 병목은 **글자·아이콘의 잉크 «폭»** 하나다.
레퍼런스 게임 서체는 **숫자·괄호가 거의 정사각**(`(0/10)` 의 `0` 이 17×17)인데 우리 기본 서체는 세로로 길다.
→ ②·⑥ 비율 항목이므로 `transform:scaleX()` 로 잉크 폭을 레퍼런스 bbox 에 맞춘다
(A2 마을 라벨 `scaleX(.86)` · 23 훈련 팝업과 같은 처방).
