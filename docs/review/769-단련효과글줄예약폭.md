## §1 — 등재문의 처방 셋과 고른 것

등재문은 ⓐ(최악 문구를 실제로 만들어 재고 예약을 다시 정한다) · ⓑ(남는 만큼 버튼을 왼쪽으로
넓힌다) · ⓒ(그대로 둔다) 를 적고 **«먼저 ⓐ 를 재고 결정할 것»** 이라고 못박았다.
⇒ `tools/probe769.js` 를 신설해 ⓐ 를 재고, 그 수치로 **ⓑ 를 채택**했다(위임 규약 — 결정을
상신하지 않고 그 회차에서 진행. 되돌림은 CSS 두 값뿐이다: 236 → 392 · 496 → 340).

**ⓒ 를 기각한 근거는 재현 두 줄이다:**

| 잰 것 | 값 |
|---|---|
| `.td` 예약 폭 | **392** (612 가 정한 값) |
| 두 줄 최악 잉크 — 레벨 스윕 Lv 0 ~ 99,999,999 | **226.0** |
| 두 줄 최악 잉크 — 전역(`mulNum` 접기 직전 봉우리 «체력회복 ×999,999배») | **228.4** |
| 둘째 줄(상수 «다음 1레벨 +0.02배») | **199.0** |
| ⇒ **과예약** | **163.6px** (예약이 최악의 **1.71배**) |
| 잉크 우변 ↔ 버튼 좌변 빈 띠 | **209px** (세 행 동일 — 등재문 실측 190~227 재현) |

⚑ **392 의 근거가 725 에 이미 무너져 있었다.** 612 는 «한 줄 잉크 최악 **411** > 남는 폭 392»
로 두 줄 분할을 골랐는데, 그 411 은 **«%» 표기 시절의 문자열**에서 나온 수다. 725(효과 표기
«×N배» 전환)가 문자열을 통째로 갈아엎었으므로 예약의 근거는 그때 재산정됐어야 했다.
(612 의 «두 줄» 판단 자체는 지금도 옳다 — 한 줄로 펴면 **419px** 로 남는 폭 408 을 여전히 넘는다.
`probe769` [2-c] 가 그 항을 유지한다.)

⚑ **최악에 상한이 있다는 것이 이 재고의 핵심이다.** 단련은 만렙이 없어(주인 지시 ⓑ) 레벨이
무한이지만, `mulNum` 의 `MUL_FOLD`(1e6)가 «×1.00B배»(191.3px)로 **접어 버려** 잉크가 되레
좁아진다 ⇒ 봉우리는 접기 직전의 «×999,999배» 이고 그 값이 228.4 다. 축 이름 최장은
«체력회복»(4자 · k2 행)이라 최악 표본은 **k2 × 접기 직전**의 조합 하나로 정해진다.

## §2 — ⓐ 만으로는 그림이 한 픽셀도 안 바뀐다 (이 작업의 함정)

`.td` 상자는 **눈에 안 보인다.** 폭을 392 → 236 으로 줄여도 잉크는 좌변 224 에 그대로 있고,
비평가 4인이 지적한 «빈 띠» 는 **잉크 우변과 버튼 좌변 사이**에 있다. 즉 ⓐ 는 «장부를 맞추는»
일이고, **그림을 바꾸는 것은 ⓑ**(그 폭을 실제로 쓰는 것) 다. 지시서 [1]«레이아웃을 실제로
바꾸는 것이 목적이다 — 기계적 상수 정리로 회차를 태우지 마라» 가 여기서 갈린다.
