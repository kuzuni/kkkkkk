## §2. 뿌리 — 자가 **456 이전**에 굳어 있었다 (제품은 옳다)

`verify124.js` 는 오프라인 자동 축복 정산을 **게임과 독립으로 다시 시뮬**한다(자기 자신과 비교하지
않으려는 설계다 — 파일 머리말 5~9행). 그 시뮬이 지속 시간을 이렇게 적고 있었다:

```js
const B_BASE = 30 * 60 * 1000, B_PERLV = 5 * 60 * 1000, …
const durAt = lv => B_BASE + B_PERLV * (Math.min(B_MAXLV, Math.max(1, lv)) - 1);
```

이것은 **456 이전 곡선**이다. 주인 지시 **456**(«축복은 늘 30분으로 해줘 렙업되도», 2026-08-30 완료)이
`blessDur()` 에서 레벨 항을 **이름째** 걷어냈고, 제품은 지금 `blessDur(){ return BLESS_BASE; }`(index.html
29150) 하나다. 둘이 **정면으로 반대를 단언**하던 자리이고 **나중 지시(456)가 이긴다** — 333 이 149↔295 에서
쓴 판정 그대로다.

만료 차가 하필 **5분·20분·35분**(= 레벨당 5분의 1·4·7배)이었던 것이 그 증거다 — 3종이 라운드로빈으로
도는 동안 레벨이 오르면 지속이 서로 벌어진다.

**6항은 한 뿌리다.** `durAt` 한 줄을 고치자 6항이 같이 초록이 됐고, §R1 이 옛 곡선을 다시 깔았을 때
**Lv11 · 42회** — 등재문에 적힌 그 «기대값» 이 그대로 재현된다.

## §3. 처방 — 자리를 비우지 않았다 (334 처방)

① **모델을 456 쪽으로** — `B_PERLV` 는 **이름째** 지웠고 `durAt` 은 인자도 분기도 없다(`() => B_DUR`).
   제품이 «레벨을 읽는 지속시간» 의 자리를 안 남긴 것과 같은 꼴로, 이 자에도 안 남긴다.
② **30분이라는 값을 따로 단언** — 시뮬 대조만으로는 «둘이 같이 틀리면 초록» 이다. 게임이 낸 만료 시각에서
   직접 읽는 항 둘을 신설했다:
   - `[6-e]` 만료 = **마지막 발동 + 30분** (3종 전부 «30분» 으로 찍힌다)
   - `[6-f]` 3종 만료 시각이 **서로 같다** (레벨당 가산이면 벌어진다)

## §7. 교훈

1. **«독립 시뮬» 은 게이트를 강하게 만들지만 부패에는 더 약하다.** 제품에서 값을 읽는 자는 지시가 바뀌면

   그 상수를 정한 **작업 번호를 주석에 박아 두라**(이 파일은 이제 456 을 이름으로 적고 있다).

   «레벨당 가산이 한쪽에만 남았다» 를 처음부터 말하고 있었다.
3. **되돌림 시험은 옛 모델을 그대로 재현해 보이는 것이 가장 싸다.** §R1 이 낸 «Lv11 · 42회» 는
   등재문이 적어 둔 자의 옛 기대값과 정확히 같아서, **한 뿌리였다는 증명과 되돌림 시험을 한 번에** 준다.
