## 0. 어떻게 잡았나 (등재 경위)

티어 스캔에 **미선점 작업이 하나도 없었다**(표 608행 전부 ✅/⏹/⏸/✖, 남은 `199`·`356` 은 둘 다
살아 있는 lock). ROUTINE 의 «티어 스캔에 미착수가 없어도 종료하지 마라»(2026-08-31 13:55 ③)와
605·607·608·609·617·618 의 선례대로 **게이트 스윕**을 돌렸다 — `tools/verify*.js` 최근 70종을
4병렬로 굴려 빨간 자를 찾았고, 그중 이탈이 가장 큰 `verify504`(**9/12**)를 잡았다.

> 스윕에서 같이 나온 빨강은 `verify488` 75/76 · `verify491` 67/72 · `verify509` 43/44 ·

> 병렬 실행 중 타임아웃(code 124)으로 빨개진 `verify494`·`verify501`·`verify502` 는
> 부하 때문일 수 있어 **빨강으로 세지 않았다**.

## 1. 재현 — 등재문 가설 둘이 기각됐다 (338·341 규칙)

`tools/probe620.js` 신설. 504 의 하네스를 그대로 복제해 **판마다 22708 의 가드 세 항을 찍는다**.

```
[1] 옛 초기화 목록(504 원본)
   판    id      시전   닫힌프레임   판 시작 상태
   1~6   slash   29~30  0            intro=0 clear=0 cdArm=0 busy=0 mode=""
   7     bolt    17     0            → 판 끝: intro=1 cdArm=1 busy=1 mode="stage"
   8     bolt    0      1500         intro=1 clear=0 cdArm=1 busy=1 mode="stage"
   9~30  …       0      1500         intro=0 clear=0 cdArm=1 busy=1 mode="stage"
```

- **[1-a]** 8번째 판부터 «시전 0» 으로 굳는다.
- **[1-b]** 그 뒤로는 **종을 바꿔도** 한 번도 안 나간다 — **23판 연속 0**.
  ⇒ «그 종이 약하다» 가 아니라 **«앞 판이 남긴 상태»** 다.
- **[1-c]** 닫은 항은 **473 `cdArm && battleBusy()`** 다.
  기각된 가설 둘: 475 **`bossClear`**(`clear=0` — 한 번도 안 켜졌다) · `bossClear.die` 가 NaN.

## 2. 뿌리 — 손으로 적은 초기화 목록이 세계보다 낡았다

`verify504` 의 `one()` 은 판을 «통째로 되돌린다» 면서 **504 를 쓸 당시의 목록**을 손으로 적어
뒀다(`S.stage`·`killed`·`player`·`enemies`·`shots`·`zones`·`drones`·`skillCd`). 그 뒤 들어온
보스전 상태 — **162 `bossOn`/`bossT` · 457 `bossIntro` · 459 `cdArm` · 475 `bossClear`** — 는
목록에 **하나도 없다.**

굳는 경로는 정확히 이렇다:

1. 7번째 판에서 `killed` 가 `ENEMY_COUNT` 에 차 **162 의 50킬 자동 진입**으로 스테이지 보스가 선다.
2. **425·457 등장 국면(`bossIntro`)이 열린 채** 25초가 끝난다.
3. 8번째 판 입구의 `enemies.length = 0` 이 **국면 중인 보스를 «격파가 아닌 경로로» 지운다.**
4. 그러면 `index.html` **23372** 의 자기치유 항
   `(bossT < BOSS_SEC || enemies.some(e => e.tk === 'boss'))` 이 **둘 다 거짓**이다 —
   국면이 `!bossIntro` 로 시계를 **한 프레임도 안 흘려** `bossT === BOSS_SEC` 그대로고,
   보스는 이미 지워졌다. ⇒ 보스 시계가 **영영 안 흐른다.**
5. `bossOn` 이 안 풀리니 `bossMode()` 가 `'stage'` 로 굳고 `battleBusy()` 가 참,
   `cdArm` 은 «상대가 표적이 되는 프레임»(22606 `cdFoeUp`)이 영영 안 와서 참 —
   **473 가드가 22708 의 스킬 루프를 그 뒤 모든 판에서 막는다.**

⚑ **23372 의 주석이 약속한 자기치유가 «국면 창» 에서는 성립하지 않는다.** 그 주석은
«보스가 격파가 아닌 경로로 사라진 판에서 시계가 영영 멈춰 `bossOn` 이 안 풀린다» 를 막으려고
`bossT < BOSS_SEC`(= «한 프레임 이상 흘렀다»)를 세웠는데, **등장 국면 동안은 시계가 아직 한
프레임도 안 흘렀다.** 게임 안에서 그 창에 보스가 사라지는 경로가 실제로 있는지는 이 작업 단위
밖이라 **손대지 않았고**, 아래 §5 에 남긴다.

## 3. 처방 — 목록을 없애고 제품에게 묻는다 (368 규약)

**«보스전 상태를 끄는 줄» 을 목록에 더 적지 않았다** — 같은 목록이 또 뒤처진다(이 결함의 뿌리가
바로 그것이다). 대신 제품의 **«새 판» 입구 `spawnStage()`**(21209) 를 부른다:

```js
S.stage = 20;
spawnStage();                        /* 제품이 bossOn·bossT·stageWin·S.bossFarm 을 스스로 끈다 */
enemies.length = 0; spawnQ.length = 0;   /* 눈금 쪽 조건 — 개체수·종은 아래 채움 루프가 정한다 */
player.vx = 0; player.vy = 0;
```

`bossIntro`·`bossClear` 는 `bossMode()` 가 빈 문자열이 되는 순간 **22542·23339 가 자기 자리에서**
닫는다(새 줄 0개).

그리고 **판 안에서 `killed` 를 0 으로 눌러 둔다.** 눈금의 이름이 «자유 전투» 인데 개체수를
POP 으로 고정해 두면 25초 안에 처치가 `ENEMY_COUNT` 를 넘어 **판이 도중에 보스전으로 바뀐다** —
그때 473 가드가 재는 창을 종마다 다른 길이로 자른다. `killed` 를 누르는 것은 개체수를 POP 으로
누르는 것과 **같은 종류의 눈금 조건**이고, 초기화 주석이 이미 `killed` 를 «보스 소환 눈금» 이라고
부른 그 자리다.

⚠ `spawnStage()` 가 깐 50마리 파도(`queueMobs`)는 **비운다** — 안 비우면 스테이지 20 의
고블린·다크가 섞여 «몇 번째 판인가» 가 다시 값을 바꾼다(초기화 주석의 ⚠ 두 줄과 같은 이유).

### 자리를 안 비웠다 — [C0] 전제 신설

[C1] 보다 **먼저** 묻는다: **«재는 동안 22708 가드가 한 프레임도 안 닫혔다»**.
이 항이 없으면 굳은 판이 다시 생겨도 표에는 «미발동» 으로만 남아 **원인이 스킬을 가리킨다**
(315·333·341 이 «자리를 비우지 말고 전제를 세워라» 로 남긴 자리와 같은 꼴).
지금 값 **0 / 99,000 프레임**.

## 5. 남은 빨강 1건 — poison 은 **선언 쪽이 낡았다**(622 로 등재, 199 몫)

수리한 자로 재니 [C2] 에 **poison 하나**가 남는다 — 선언 **29.36** vs 실측 **15.48**(이탈 47%,
허용 ±40%). 6판 값이 14.25~16.63 으로 **조여 있어** 흔들림이 아니다.

**338·344 규칙대로 «내 변경이 만든 값이 아님» 을 대조로 못박았다** — `probe620` [3] 이
poison 을 **첫 종으로** 놓아 «굳기 전 창» 에서 옛 초기화로도 재고, 새 초기화와 나란히 놓는다:

```
[3] poison — 선언 29.36 / 옛 초기화 16.28 / 새 초기화 15.46  (차이 −5.0%)
```

⇒ 47% 이탈은 **620 의 수리가 만든 값이 아니라 원래 그 자리에 있던 값**이고, 굳은 판이
그것을 **가리고 있었을 뿐**이다. 유력 뿌리는 502·580(잡몹 이속)·541(잡몹 크기 ×1.2) —
장판은 «적이 장판 위에 머무는 시간» 으로 타격수가 정해지므로 이속이 오르면 그대로 준다.

⚠ **`hits` 를 여기서 고치면 안 된다** — 그 값은 484 의 «등급 안 DPS 동일»(`m × hits / cd`)이
서 있는 축이라 `m` 과 **한 벌로 재역산**해야 하고, 그것은 밸런스 계수다(326·331·541 과 같은 처리).
**622 로 등재하고 199 에 넘겼다.**

## 6. 교훈

1. **«판을 통째로 되돌린다» 는 손목록은 반드시 낡는다.** 되돌릴 것을 목록으로 적지 말고
   제품의 «새 판» 입구를 부르면, 그 뒤 늘어난 상태가 자동으로 따라온다(368 «자리를 상수에서
   빼고 제품에게 묻는다» 의 하네스판).
2. **«0» 은 두 가지 뜻이다** — «그 종이 아무것도 안 한다» 와 «잴 기회가 없었다». 자에 전제
   한 항([C0])을 세워 두 뜻을 갈라 놓지 않으면, 하네스 고장이 **제품 결함으로 읽힌다**.
   실제로 이 자는 11종 중 9종을 «미발동» 으로 신고하고 있었다.
3. **자기치유 항의 «한 프레임 이상 흘렀다» 전제는 연출 국면을 안 센다.** 23372 의
   `bossT < BOSS_SEC` 는 국면 창(시계가 아직 0프레임)에서 성립하지 않는다.
4. **굳은 자는 다음 결함을 가린다.** 이 자가 굳어 있는 동안 502·580·541 이 장판의 실제
   타격수를 절반으로 내렸는데 아무도 못 봤다 — 자를 고치자 그 자리(621)가 곧바로 드러났다.
