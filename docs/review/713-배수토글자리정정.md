## 2. 자리 — 15px 을 어디서 가져왔는가

패널은 `padding:106 0 98` 이고 하단 크롬(`.sm-panel::after`)이 15px 이라 쓸 수 있는 띠가
**[15, 98] = 83px**. 셸 98 을 받으려면 아래 여백이 **113**(= 15 + 98) 이어야 하고, 그 15px 을
어디서 빼는가가 실제 결정이었다:

| 후보 | 대가 |
|---|---|
| ⓐ 패널을 키운다 | 327 주인 지시 «세로 2배»(패널 1080 = ref 539 × 2.00)가 깨진다 |
| ⓑ 위 여백 106 에서 뺀다 | 106(크롬 14 + 본문위 92)은 **레퍼런스 실측값**이다 |
| **ⓒ 그리드에서 뺀다(주 채택)** | 876 은 ref 값이 아니라 327 이 «최악 판을 담는다» 는 목적으로 고른 수다 |

**결론은 ⓒ + ⓑ 를 8:7 로 나눠 낸 것**이고, 그 비율은 취향이 아니라 산수가 정했다.

### ⚑ 327 의 산수 하나가 여기서 정정됐다

327 은 «최악 판 = 5행 846»(170×5 − 4) 이라고 적었다. **아니다.**
개수 배지(`.ifq`)는 절대배치라 **스크롤 넘침에 그대로 들고** 카드 바닥 아래로 **18.69px** 나오며,
줄들은 `align-content:safe center` 라 그리드를 줄여도 **절반만 따라 올라온다**:

```
배지 하단 = (H − 846)/2 + 838 + 18.69 ≤ H   ⇔   H ≥ 867.4   ⇒ 하한 868
```

876 은 그것을 담고 있었고 **846·862·865·866 은 못 담는다** — `verify327` [E5] 가 그 넷에서
연달아 빨개져 이 식을 드러냈다(1회차에 세 번 되잡았다). 그래서 그리드는 **−8**(876 → 868)만
가져가고 나머지 **7px 은 위 여백**(106 → 99)에서 냈다.

⚑ **[E5] 를 «참/거짓» 에서 «수치» 로 바꾼 것이 그 세 번을 가능하게 했다** — `got=false` 만
보였을 때는 얼마나 모자란지 알 수 없었다. 지금은 `got=867 want=866` 처럼 찍힌다.

### 최종 값 (전부 `#sumw`·`.sm-panel` 두 줄에 있다)

```
--sm-gh   876 → 868     (−8)
padding   106 0 98 → 99 0 113
--sm-ph   204 + gh → 212 + gh      ⇒ 패널 1080 **불변**

## 3. ⚑ 카드가 11px 위로 간다 — 피할 수 없다(의도적 이탈)

`verify12`(레퍼런스 대조 게이트)가 그것을 잡았다: 배지·카드 행 y 가 전부 **−11**.

```
카드 y = 패널상변 + 위여백 + (그리드 − 846)/2 ,  위여백 + 그리드 = 1080 − 113 = 967

패널을 키워도(ph + X) 상변이 같이 내려가 상쇄돼 **−11 이 하한**이다.
⇒ `verify12` 에 **`DY = −11` 한 상수**를 명시해 얹었다. 무르게 푼 것이 아니라 한 값으로 적어

## 8. 곁다리 관측 (등재만 · 내 작업 단위 아님)

**745 등재 — 668 의 ×배수는 «고유 종 ≤ 30» 이라는 327 의 전제를 넘어선다.**
327·713 의 «가려짐 0» 은 «버튼이 10·10·30 뿐이라 결과는 최대 30칸» 위에 서 있다.
그런데 668 의 ×1000 은 30,000장을 뽑아 **배너 종수(36)까지** 고유 칸이 나올 수 있고,
36칸은 6행 = 1016px 이라 그리드(868)를 넘어 **스크롤이 생긴다**. 지금도 그렇고(668 이후 내내)
713 이 만든 상태가 아니다 — `verify668` [H2] 가 «15칸 / 배너 종수 36» 으로 그 여지를 이미 찍어 두었다.
스크롤이 나는 것 자체는 187 의 원래 설계라 **버그는 아니고**, 327 이 약속한 «스크롤조차 안 쓴다» 가
배수 상황에서는 참이 아니라는 **문서·게이트의 어긋남**이다. 상세는 PROGRESS 745 행.

> **⚑ 745 마감(2026-09-02, sess-0014-32220 워커 A · 제품 0줄)** — 등재문의 기하는 맞았고(31칸부터
> 넘침 · scrollH 1027 vs 868 = 159px · 가려짐 6칸) **축이 틀렸다**: 닿는 조건은 «×1000 = 30,000장» 이
> 아니라 **«소환 레벨 × 장수»** 다(`gradeProbs` 가 `l < g.unlock` 으로 등급을 잠근다). Lv1 은
> 30,000장에도 15칸에서 멈추고 — `verify668` [H2] 가 찍고 있는 «15칸/36종» 이 그 상태다 —
> **Lv50(MAX)에서는 100장(10연 ×10)이 이미 32칸**이다. 그래서 «×1000 이면» 으로 적은 게이트는
> ×10·×100 에서 이미 깨진 것을 못 잡는다. 처방은 등재문이 권한 ⓐ 그대로(문서만): `verify327` 의
