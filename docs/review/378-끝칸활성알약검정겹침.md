## 0. 한 줄

활성 알약이 셸 **안쪽 변에 닿는 면**에서, 알약의 검정 7px 이 셸 테두리 6px 에 **겹치지 않고 더해져** 13px 이었다.
ref 는 그 자리에 검정을 겹치지 않는다 — **셸 테두리가 알약의 그 변을 겸한다.**
고친 것은 «닿는 면 하나» 이고, **안 닿는 면의 검정 7 은 그대로 두었다**(ref 에도 있다).

## 1. 재현이 먼저다 — `tools/probe378.js` 신설 (338·341·350·363·368 규칙)

등재문(352 §8)은 **10 상점 좌변 한 자리**에서 «검정 ×13» 을 한 번 쟀다. 그 한 자리가 부품 전체의
이야기인지, 그리고 «가운데 칸은 ref 에도 검정 7 이 있다» 는 음성 대조가 실제로 성립하는지를
**찍힌 픽셀**로 확인하는 것이 첫 일이었다(350 처방 — 선언만 보면 자식이 덮은 자리를 못 본다).

재는 법 — 호스트 5곳 × 칸 전부를 차례로 활성으로 만들고 **바 세로 한복판 행**에서 네 자리를 읽는다:
바 좌변 바깥→안 24px · 바 우변 바깥→안 24px · 알약 좌변 안쪽 20px · 알약 우변 안쪽 20px.

**등재문 가설이 그대로 확인됐다**(338·341 은 기각됐던 자리다). 수리 전:

| 자리 | 표본 | 결과 |
|---|---|---|
| 알약이 셸 변에 **닿는** 면 | **9면** | `#000000 ×13` → `#634F37 ×7` → 면 `#4B3E2D` — **9/9 전부** |
| 알약이 **안 닿는** 바 변 (음성 대조) | 21면 | `#000000 ×6` → 림 `#705F4B ×7` → 셸 면 `#61523D` — 21/21 정상 |
| 안 닿는 **알약** 면 (양성 대조) | 21면 | `#000000 ×7` → `#634F37 ×7` → 면 `#4B3E2D` — 21/21 정상 |

⇒ 한 자리의 이야기가 아니라 **부품 규칙 하나**였고, 동시에 **«지우기» 가 오답임**도 같은 실행이 말했다 —
안 닿는 면의 검정 7 은 ref 규격 그대로 살아 있다(측정표 07 §9 «좌우 테두리 7px #000000 (292~298 / 544~550)»).

### 1-1. 재현기가 두 번 거짓말할 뻔했다 — 둘 다 잡았다

- **ⓐ 입장 연출 중 프레임.** 10 상점 첫 판이 `#000000 ×3` 으로 찍혔다. 결함이 아니라 `jzPgIn` 이 바를
  아직 축소해 놓은 프레임이다(테두리 6 이 3 으로 줄어 보인다). ⇒ verify47 과 같은 `SETTLE` 을 붙였다.
- **ⓑ 캡처 네 장 사이에 `.on` 이 되돌려진다.** 23 훈련(`#trSubs`)은 `renderUI()` 가 매 틱 상태에서
  `.on` 을 다시 그려 클래스 주입이 지워진다. `readRow` 를 네 번 부르면 캡처도 네 장이라, 되읽기는
  통과했는데 **픽셀은 다른 칸 그림**을 재고 있었다(«칸2 를 쟀다» 면서 칸1 을 찍었다).
  ⇒ **캡처 한 장에서 네 자리를 다 읽고, 그 캡처 앞뒤로 되읽기를 한 번씩** 한다. 어긋나면 그 표본을 버린다.
  그래서 닿는 면 표본이 10 이 아니라 **9** 다(23 훈련 칸3 은 정직하게 «건너뜀» 으로 남는다).

⚑ **다음 세션에게** — `#trSubs` 에 클래스를 주입해 무언가를 재려는 도구는 전부 이 함정을 밟는다.
주입이 아니라 **실제 클릭**을 쓰거나, 캡처 앞뒤로 되읽기를 해서 표본을 버려라.

## 2. 뿌리 — 규칙이 좌·우로 안 따라온 것

측정표 07 §9 «활성 탭» 행이 이미 적어 두었다:

> 형태 — 바 **안쪽 높이 전체**를 채우는 세그먼트. **위/아래 테두리는 바 테두리와 공유**

그런데 07 ref 의 활성 탭은 **«스킬» = 가운데 칸**이라, 그 표는 «좌·우가 셸에 닿으면 어떻게 되는가» 를
말할 기회가 없었다. 그 자리를 ref 로 채운 것이 352 §8 의 03 실측이다(활성 = 오른쪽 끝 칸):

```
ref 03  바 우변 바깥 → 안 :  #000000 ×6(+AA) → #604F3D → #634F37 ×5 → 면 #4B3E2D
우리 10 바 좌변 바깥 → 안 :  #000000 ×13     → #634F37 ×7          → 면 #4B3E2D
```

⇒ «위·아래 테두리는 바 테두리와 공유» 는 **네 면의 규칙**이었고, 좌·우에서만 안 따라오고 있었다.
새 결정이 아니라 **있던 규약의 나머지 절반**이다(350 과 같은 모양의 결함 — «규칙이 안 따라온 것»).

## 3. 제품 변경 (`index.html` 2자리)

`box-shadow` 는 **면별 선언이 없다** — 네 겹을 통째로 다시 적어야 한다. 그래서 좌·우 밴드를
**변수 둘로 갈라** 놓고, 닿는 칸만 그 변수 **한 쪽**을 바꾼다. 이것이 «한 면만» 손잡이의 유일한 형태다.

```css
.stab.on{
  --pill-l:inset 7px 0 0 #000,inset 14px 0 0 #634F37;
  --pill-r:inset -7px 0 0 #000,inset -14px 0 0 #634F37;
  box-shadow:var(--pill-l),var(--pill-r)}

/* 셸 안쪽 변에 닿는 칸만 — 그 면의 검정을 셸 테두리에 넘긴다 */
.stabs.sp2>.stab.on:nth-of-type(1),
.stabs.sp3>.stab.on:nth-of-type(1),
.stab.on.stab-c1{--pill-l:inset 7px 0 0 #634F37}
.stabs.sp2>.stab.on:nth-of-type(2),
.stabs.sp3>.stab.on:nth-of-type(3),
.stab.on.stab-c4{--pill-r:inset -7px 0 0 #634F37}
```

**«닿는 칸» 은 배치 규칙이 이미 정해 둔 그 칸이다** — 새 판정을 만들지 않았다:
균등분할은 첫 칸(`left:0`)과 끝 칸(우변 = 콘텐츠 우변) · 4칸 격자는 `.stab-c1`·`.stab-c4`
(`c4` 는 `709+229 = 938 = 950−12` 로 콘텐츠 우변과 정확히 같다). 가운데 칸은 한 면도 안 바뀐다.

⚠ **`:last-of-type` 을 안 썼다** — `.stabs` 의 자식은 전부 `div` 이고 `#eqTabs` 는 `.stab-sep` 이
**마지막 div** 라 `:last-of-type` 이 구분선을 문다. 배치 규칙이 쓰는 선택자를 그대로 쓴 이유다.

**수리 후 같은 probe**: 닿는 면 **9/9 가 `#000000 ×6` → `#634F37 ×7`**(13px **0건**) ·
음성 대조 21/21 · 양성 대조 21/21 **전부 무변경**.

## 7. 교훈 (LESSONS 378)

1. **«위/아래 테두리는 바 테두리와 공유» 같은 규약은 네 면짜리다.** ref 의 활성 칸이 가운데라
   좌·우 사례가 표에 없었을 뿐이고, 없는 것을 «규칙이 없다» 로 읽으면 그 면만 규약 밖으로 남는다.
2. **`box-shadow` 에 «한 면만» 손잡이를 만들려면 변수로 가른다.** 면별 선언이 없어 네 겹을 통째로
   다시 적어야 하는데, 통째로 적는 override 는 다음 세션이 본체를 고칠 때 **조용히 안 따라온다**.
3. **`:last-of-type` 은 «마지막 칸» 이 아니다.** `.stabs` 의 마지막 `div` 는 `#eqTabs` 에서 `.stab-sep` 이다.
   자리를 묻고 싶으면 **배치 규칙이 이미 쓰는 선택자**를 그대로 쓰는 것이 가장 짧고 안 어긋난다.
4. **캡처를 여러 장 찍어 한 상태를 재는 도구는 그 사이에 상태가 바뀐다.** `renderUI()` 가 매 틱
   다시 그리는 바(`#trSubs`)에서 실제로 «다른 칸 그림» 을 쟀다. **한 장에서 다 읽고, 앞뒤로 되읽기**.
5. **섞인 트리로 대조하지 마라.** 제품만 되돌리고 게이트는 새것인 상태의 점수는 어느 쪽 이야기도 아니다.
