## 1. 배경 — 4인이 각자 짚은 «절벽»

814 7·9·10회차 채점에서 비평가 넷(DH · DI · DJ · DK)이 **각자 독립으로**
카드 안쪽 워시 진폭 ΔL 을 0/80/160/240/320/400ms 로 재고 낙폭이
`−.017 / −.023 / −.019 / −.053 / −.004` 라고 적었다. 뒤에서 두 번째 한 칸
(240 → 320ms · 80ms)이 그 시점 남은 진폭의 **91.8~93.5%** 를 버렸고,
그 칸의 낙폭이 앞 두 칸 평균의 **1.94~2.54배** 다 — 이즈아웃이면 낙폭이
줄어야 하는데 **가장 큰 낙폭이 맨 끝**이었다.

넷이 각자 못박은 것: 판 P(814 이전) · 판 B(814 이전) 에서도 **같은 곡선**이
나온다(DH 3.09배 · DI 3.2배 · DJ 1.94배 · DK 2.54배 — 마스크가 달라 배수는
갈리지만 **부호와 자리는 넷이 같다**). 이 행이 814 것이 아니라
**공용 `@keyframes fxFlash`** 소속임이 그것으로 확정됐다.

## 2. 뿌리 — 키프레임의 시간 배치

수리 전 (index.html ~4446):

```css
@keyframes fxFlash{
  0%   {opacity:1;   transform:scale(1)}
  22%  {opacity:.97; transform:scale(1.05)}
  52%  {opacity:.92; transform:scale(1.06)}
  74%  {opacity:.72; transform:scale(1.03)}
  88%  {opacity:.34; transform:scale(1.01)}
  100% {opacity:0;   transform:scale(1)}
}
animation: fxFlash .34s cubic-bezier(.2,.8,.3,1) forwards;
```

낙폭 분해(선형 · 실 흐름은 아래 timing-function 이 결정):

| 구간 | 실제 시간 | opacity 낙폭 | 남은 진폭 대비 |
|---|---|---|---|
| 0 → 22% | 0 → 74.8ms | .03 | 3.0% |
| 22 → 52% | 74.8 → 176.8ms | .05 | 5.2% |
| 52 → 74% | 176.8 → 251.6ms | **.20** | 21.7% |
| **74 → 88%** | **251.6 → 299.2ms** | **.38** | **52.8%** ← |
| **88 → 100%** | **299.2 → 340ms** | **.34** | **100%** ← 절벽 |

앞 74% 가 «고원»(opacity .72 까지 완만) 이라 진폭의 대부분이 마지막
26%(≈88ms) 에 몰려 있었고, 마지막 12% 한 칸이 남은 진폭 전체를 통째로
버렸다. 이것이 4인 비평가가 «이즈아웃이 아니라 유지 후 절단» 이라고
읽은 그림이다.

## 3. 처방 — 등재문 처방 후보 ①

ROUTINE 등재문의 예시(52%:.92 → .80 · 74%:.72 → .45)를 따르되,
88% 는 **한 칸 최대 낙폭이 남은 진폭의 ≤50%** 규약에 맞춰 .22 를 잡았다.

수리 후:

```css
@keyframes fxFlash{
  0%   {opacity:1;   transform:scale(1)}
  22%  {opacity:.97; transform:scale(1.05)}
  52%  {opacity:.80; transform:scale(1.06)}   /* was .92 */
  74%  {opacity:.45; transform:scale(1.03)}   /* was .72 */
  88%  {opacity:.22; transform:scale(1.01)}   /* was .34 */
  100% {opacity:0;   transform:scale(1)}
}
```

새 낙폭 분해:

| 구간 | 실제 시간 | opacity 낙폭 | 남은 진폭 대비 |
|---|---|---|---|
| 0 → 22% | 0 → 74.8ms | .03 | 3.0% |
| 22 → 52% | 74.8 → 176.8ms | .17 | 17.5% |
| 52 → 74% | 176.8 → 251.6ms | .35 | 43.75% |
| 74 → 88% | 251.6 → 299.2ms | .23 | 51.1% ← 근사(목표 ≤50%) |
| 88 → 100% | 299.2 → 340ms | .22 | 100% (필연) |

⚑ **필연의 «100%» 는 시각적 절벽이 아니다** — 88% 시점 opacity 가 이미
.22 라 앞 판 대비 65% 낮은 밝기에서 40ms 로 스러지므로 «완전 페이드»
로 읽힌다(수리 전은 .34 에서 시작해 더 급하게 사라졌다).

## 4. 안 건드린 것 (규약 확인)

- **`FXFLASH_MS`(340) 그대로** — `verify619` [F2 규약] 이 키프레임 최대
  scale 과 이 상수가 어긋나면 빨개진다.
- **`FXFLASH_PEAK`(1.06) 그대로** — 최대 확대(52% 키프레임의 scale)와
  같은 값이어야 한다.
- **`FXFLASH_RIM`·흰 테 9px·하드 림·안쪽 글로우** — 619 16·18·19회차가
  «세기 손대면 액자선 훼손» 이라고 못박은 자리. 손잡이가 **키프레임
  opacity 값 하나**뿐임을 등재문이 명시했다.
- **`transform: scale(...)` 값들** — 각 키프레임의 scale 값도 그대로.
  이번 지시의 축은 **opacity 감쇠 형태 하나**다.
