## 1. 착수 전에 재현했다 (338·341·350 규칙)

등재문의 처방을 따르기 **전에** `tools/probe348.js` 를 신설해 «찍힌 픽셀» 로 재현했다.
HP바는 `fillRect` 로 불투명 단색을 깔기 때문에(일반 적 `#ff6b8a` · 보스류 `#ffca5c`)
**그 색 픽셀의 개수와 bbox** 가 곧 «바가 그려졌는가 / 어디에» 다(350 교훈 — 상태값·rect 가 아니라 픽셀).

| 적 자리(화면 게임px, VW 540 · VH 998) | 수리 전 바 픽셀 | 바가 찍힌 x 범위 |
|---|---|---|
| 안-중앙 (270, 599) | 308 | 251.5..273.0 |
| 안-좌끝 (34, 599) | 308 | 24.0..45.5 |
| 걸침-좌 (4, 599) | 308 | 24.0..45.5 |
| **밖-좌 (−160, 599)** | **308** | **24.0..45.5** ← 몸통이 없는 왼쪽 가장자리 |
| **밖-우 (700, 599)** | **308** | **479.0..500.5** ← 오른쪽 가장자리 |
| 밖-위 (270, −160) | 0 | — |
| 밖-아래 (270, 1158) | 0 | — |
| **밖-우(보스)** | **987** | **397.5..467.5** |

**⚑ 등재문 가설이 확인됐다 — 단, 결손은 «가로 한 축» 이다.**
`fxClampX` 는 이름 그대로 **x 만** 민다. 그래서 위·아래로 벗어난 적의 바는 **수리 전에도 이미 0**이었고
(캔버스 밖으로 그냥 나간다), 주인이 본 «가장자리에 남는 바» 는 **좌·우 두 자리**다.
바가 찍힌 자리 `24.0`·`500.5` 는 `fxClampX` 의 상수와 정확히 맞는다(`lLim 24` · `VW − 24 − hw`) —
**클램프가 그린 것**이 맞고 다른 요소가 아니다.

## 2. 처방 — 클램프는 그대로 두고, 그리기 호출부만 가시성으로 가른다 (등재문 ①②)

```js
/* 348 — «몸통이 뷰포트 밖인 적» 인가. 오버헤드 HP바는 위 클램프로 **끌어오지 않고 아예 안 그린다** */
function eOnScreen(e){
  const sx = e.x + camOx, sy = e.y + camOy;
  return sx + e.r > 0 && sx - e.r < VW && sy > 0 && sy - e.r*2 < VH;
}
```
호출부는 한 항만 늘었다 — `if(e.hp < e.max && grow >= 1 && eOnScreen(e)){`.

- **`fxClampX` 는 한 줄도 안 건드렸다**(등재문 ②). 여진 바닥 타원 등 다른 연출이 같은 자를 계속 쓴다
  (게이트 §6-b 가 호출부 수를 세어 못박는다).
- **보일 때의 클램프 규약(13회차)은 그대로다** — 좌측 끝 적의 바는 여전히 사이드 아이콘 열 밖으로 밀린다
  (게이트 §3-b: 바 좌변 78.5 ≥ 사이드 열 우변 72.5). 이번 수리는 «미느냐 마느냐» 가 아니라
  **«애초에 그리느냐»** 한 겹을 앞에 세운 것이다.
- **판정 기준은 «몸통 bbox 가 뷰포트와 겹치는가»**(등재문 ④ — 워커가 정하고 기록할 몫):
  가로 `±e.r`, 세로 `발밑 e.y ~ 머리 e.y − 2·e.r`. **반쯤 걸친 적은 «보이는 것» 으로 친다**
  — 몸통이 1px 이라도 보이면 그 적의 체력은 알려 줘야 하고, 그 자리는 클램프가 원래 하던 일이다.
- **월드 좌표가 아니라 화면 좌표로 판정한다** — `camOx/camOy` 를 태워 «카메라가 밀려서 벗어난» 경우도
  같이 걸린다(게이트 §5 가 적을 한 px 도 안 움직이고 카메라만 밀어 이것을 직접 잰다).

### 등재문 ③ — «보스가 화면 밖인데 어디 있는지 모름» 은 생기지 않는다

스테이지 보스전 30초 실측에서 보스가 화면 밖인 프레임은 **0건 · 최장 연속 0.00초**다(위 표).
보스는 66/172 가 지키는 추격 AI 로 플레이어에게 붙어 있고 카메라는 플레이어를 따라간다.
게다가 던전·탑·승급 보스는 **전용 HUD 바**(`#dunBar`·`#bossHp` — 338)가 따로 있어
설령 한 프레임 벗어나도 체력 정보가 사라지지 않는다. ⇒ **방향 화살표 같은 대체물은 안 만들었다**(지시대로 과잉).

## 5. 다음 세션이 볼 것

- **가로만 클램프된다** — `fxClampX` 에 짝이 되는 `fxClampY` 는 **없다**. 「가장자리에 남는 오버레이」류를
  다시 만나면 좌·우부터 보면 된다(위·아래는 애초에 캔버스 밖으로 나간다).
- **적 오버헤드에 새 표시(상태 아이콘·이름표 등)를 얹는 세션은 `eOnScreen(e)` 를 같이 태워라.**
  이 함수는 HP바 전용이 아니라 «몸통이 보이는가» 한 축이고, 안 태우면 348 이 통째로 되살아난다.
- 데미지 라벨(`fxClampX` 를 쓰는 다른 자리)은 **이번 범위 밖**이다 — 그것은 «맞은 순간 그 자리에 뜨는»
  일회성 연출이라 오래 남지 않는다. 주인이 지적한 «계속 보이는» 것은 상시 표시인 HP바였다.
